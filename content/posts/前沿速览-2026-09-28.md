## 大模型 LLM

### [Disaggregated Quantization: Specializing LLM Prefill and Decode](https://arxiv.org/abs/2609.26333)
`评分3 · HF 44赞`

这篇论文要解决的是大模型推理中一个被长期忽视的结构性错配问题：prefill（提示处理）和 decode（逐 token 生成）这两个阶段的硬件瓶颈截然不同，但现有量化方法几乎都采用"一刀切"的策略。Prefill 阶段 token 数多，权重能被大量复用，属于计算受限，因此适合把权重和激活都量化成硬件原生支持的格式（如 NVFP4），用低精度矩阵乘加速；而 decode 阶段 batch 小、每步只生成一个 token，权重加载的显存带宽才是瓶颈，此时更该用紧凑的权重编码（如 2–3 bit 的 LUT 查表编码）来减少访存，而激活动态范围大、量化它反而会引入额外误差。之前的方法要么全局用同一种量化格式，要么只做 weight-only 量化而放弃 prefill 的算力加速，结果就是：在 decode 密集型任务上，单独量化 decode 带来的精度损失是单独量化 prefill 的 2–4 倍（Gemma3-1B 上甚至达 7 倍）；而在 prefill 密集型任务上，单独量化 prefill 的损失又是单独量化 decode 的 1.1–4.1 倍。这种"敏感性不对称"说明统一量化必然在某一侧吃亏，而 disaggregated serving（把 prefill 和 decode 部署在不同实例、通过 KV cache 交换）虽然已经是工业界常见做法，但现有系统只优化了通信和调度，没人去动量化格式本身。

论文的核心创新叫 disaggregated quantization（DQ），关键洞察是：既然 prefill 和 decode 本来就跑在不同硬件上、通过 KV cache 交互，那它们的权重和计算格式完全可以解耦，只要两者仍朝同一个响应目标联合优化即可。为此作者提出 QADD（quantization-aware distillation with disaggregation），复用 SFT 数据里本来就有的 label mask——原本用于损失掩码，现在同时充当"路径选择器"：用户 prompt 走 prefill 通路，assistant 回复走 decode 通路。虽然蒸馏损失只监督回复 token，但梯度会通过 prompt 产生的 key/value 反向传到 prefill 权重上，于是一次前向-反向就能让两条通路协同优化。在这个训练框架下，DQ 展开成三个层次：格式解耦（format disaggregation）只在 decode 阶段关掉激活量化，保留 NVFP4 的存储和 prefill 计算成本，却让 decode 精度显著回升，相当于零成本插拔替换；完全解耦（full disaggregation）则给 prefill 单独训练一套原生 NVFP4 权重，decode 保留紧凑的 weight-only 编码，两者从同一未量化模型出发联合训练，推理时 prefill 权重生成 KV cache、decode 权重去消费它，注意力结构完全不用改；而 offloaded disaggregated prefill（ODP）解决的是"多存一份 prefill 权重放不下"的问题——由于 prefill 权重只在处理 prompt 时用到、decode 阶段完全闲置，ODP 就从 SSD 按 transformer block 流式加载 prefill 权重，用两块设备缓冲区做双缓冲重叠加载与计算，缓冲区空间则从 decode 权重里临时"借"出来（decode 阶段再恢复），因此不额外占用设备显存。更实用的是，DQ 还能扩展到"prefiller"模式：面对已经量化好、算法不透明的现成 decode checkpoint（比如社区发布的 GGUF），只训练一个适配它的 NVFP4 prefill 模型，训练时冻结 decoder 的反量化权重、让梯度穿过它流回 prefill 通路，这样无需触碰原 decode checkpoint 就能获得硬件原生加速的 prefill。

实验在 Qwen 3（0.6B–8B）和 Gemma 3（1B–12B）上做了系统验证，用 Tülu 3 的 1 亿 token 做 KL 蒸馏，decode 侧测 GSM8K、MATH-500、MMLU-Pro，prefill 侧测 RULER 的 4K–32K 长上下文任务，并通过 vLLM 做真实的 disaggregated serving。格式解耦在 decode 密集型任务上比非解耦方案平均提升 1.9–4.5 个百分点（NVFP4/LUT3/LUT2 各有不同），prefill 侧影响不到 1.3 分，同时 prefill 相对 BF16 有 1.49–1.67 倍加速、decode 还快 2–3%。完全解耦更猛：LUT3 在 decode 和 prefill 上分别提升 6.3/4.1 和 5.2/4.3 分，LUT2 提升 10.7/5.3 和 7.4/10.5 分。最亮眼的是 prefiller 场景：给已发布的 Qwen3.8-27B 1-bit GGUF decoder 配一个 NVFP4 prefiller，MMLU-Pro 提升 32.5 分、MMMU-Pro 提升 35.3 分，且完全不动 decode checkpoint；ODP 在 8K 上下文下相对 weight-only 基线把首 token 延迟加速了 1.78 倍。局限也很明确：ODP 依赖"计算随上下文增长、加载成本固定"这一前提，对 MoE 模型不成立（激活参数比例越高，加载相对计算越贵），所以作者明确把它定位为稠密模型的本地部署工具；此外完全解耦需要多存一份 prefill 权重，训练也依赖有明确 prompt/response 区分的 SFT 数据。总体而言，这篇工作把"量化"从全局静态决策变成了随推理阶段动态特化的设计维度，为低比特（尤其 1–3 bit）部署在保持可交互性的同时大幅挽回精度提供了一条务实路径，也提示未来的量化研究应当按 workload 分别评估、分别优化，而不是追求单一格式通吃。

### [Block Sparse Attention with Log-Linear Complexity](https://arxiv.org/abs/2609.31093)
`评分3 · HF 20赞`

长上下文建模的核心瓶颈在于自注意力对序列长度的二次复杂度，而块稀疏注意力通过只保留部分键块来把计算量降下来，是一条被广泛看好的路线。但问题在于，选出该保留哪些块这一步本身就退化成二次复杂度：要判断某个查询该关注哪些键块，传统做法必须对全部查询-键块对打分，再取 Top-K，于是序列一长，路由开销就吃掉了稀疏化省下来的收益，甚至成为新的主导项。已有的稀疏注意力方案要么用固定模式（如滑动窗口、局部+全局）回避选择问题，但难以适配真实的长程依赖；要么用低秩或哈希近似来估计相关性，精度损失明显；要么直接做全量打分再裁剪，复杂度上并没有真正解决问题。因此，关键矛盾是：如何在亚二次甚至接近线性的代价下，仍然准确地找出最相关的键块。

PISA 的核心洞察是，找最相关键这件事本身不必在全部候选上一次性完成，而可以像金字塔一样逐层收窄。具体来说，它把键按由粗到细的方式组织成 O(log N) 个层级：最粗层是最大粒度的池化表示，最细层就是原始的键块。选择从最粗层开始，在该层对当前有界的候选集合用 LogSumExp 打分，挑出得分最高的若干候选，只把这些候选对应的子节点展开到下一更细的层级，再在更细层重复同样的打分与筛选，直到抵达最细层，最终确定真正参与注意力的键块。这里用 LogSumExp 而不是简单的平均或最大池化来打分，是因为它能在池化后的粗粒度表示上近似估计该组键中是否存在与查询高度匹配的项——它偏向于保留组内的最大值信息，从而避免因平均而把真正相关的键稀释掉。由于每一层参与打分的候选数都被上一层限制在一个较小的常数级规模，而层数只有对数级，整体选择代价就从 O(N²) 降到 O(N log N)。为了让这套层级路由真正跑得快，作者还写了硬件感知的 Triton 内核，把逐层路由和 LogSumExp 打分融合在一起，关键是不显式地物化完整的查询-键得分矩阵，从而避免了显存带宽和中间张量带来的开销，训练和推理都适用。相比之前的方法，它的优势不只是复杂度更低，更在于选择过程仍然保留了数据依赖性：不是靠固定模式或哈希碰撞碰运气，而是用粗层打分引导细层搜索，在近似精度和效率之间取得了更实际的平衡。

在语言建模任务上，PISA 与基线相比在常识推理等基准上取得了相当的表现，同时在检索类任务上结果更好，这说明它在需要精确长程定位的场景里没有因为稀疏化而丢掉关键信息。不过论文摘要没有给出具体的提升数字，也没有展开不同序列长度、不同稀疏预算下的消融细节，因此它在大规模预训练、超长上下文（如百万级 token）以及训练稳定性方面的表现仍有待更完整的验证；层级池化和 LogSumExp 近似打分在极端分布下是否会导致漏选关键块，也是需要进一步考察的局限。总体而言，这项工作把块稀疏注意力的瓶颈从“选哪些块”重新定义为“如何分层地选块”，用对数级的层级结构把路由代价压到 O(N log N)，并配以可落地的内核实现，为长上下文模型提供了一条不依赖近似哈希、也不牺牲选择精度的可行路径，后续很可能推动更多关于层次化路由与硬件协同设计的研究。

### [AgentWorld: Benchmarking Long-Horizon Collaboration of Multi-agent LLMs](https://arxiv.org/abs/2609.31590)
`评分3 · HF 7赞`

现有针对多智能体大模型的评测基准大多聚焦于竞争性场景、二十步以内的短程交互，或者仅仅把各个智能体的个体表现简单加总，因而无法真正隔离并凸显出「协作」这一能力本身。这篇论文要解决的核心痛点正在于此：当任务变长、角色变多、信息变得不透明时，智能体之间究竟能不能协调起来，此前缺乏一个干净、可量化的衡量手段。作者指出以往基准存在三个具体缺陷：其一，任务时域太短，普遍在十步以内，根本不足以考察持续性的协调；其二，很多基准把「低层动作控制」和「协作」混为一谈，智能体大量精力花在精确的 3D 导航、方块放置这类操作上，导致协作能力的好坏被动作控制的熟练度稀释，分数无法反映协作质量；其三，像 Project Sid 这类大规模社会模拟关注的是涌现出的社会行为，而不是有明确成功判据的具体任务。此外，现有评测要么是竞争性设定，要么不强制「黑盒」交互（即智能体彼此看不到对方的内部状态、观测和动作历史），而黑盒恰恰是真实协作中最关键的约束——你只能靠显式沟通来协调。正是这些缺口，使得「长时程、多角色、黑盒条件下的协作能力」一直没有被单独拎出来测量。

AgentWorld 的做法是在环境、任务和度量三个层面同时做设计。环境上，它基于开源 MMORPG 引擎 Kaetram 搭建沙盒，拥有 1056×768 的持久化 2D 世界、9 种生物群系、380 多种物品、144 种怪物、70 多个 NPC 和 1531 个可采集资源点，但关键在于它加了一层抽象：把复杂的多步游戏机制封装成 13 个高层 API 工具（移动、攻击、采集、制作、转移、聊天等），比如一次 attack_entity 调用就自动完成寻路、发起攻击、结算战斗、拾取战利品，harvest_resource 则包办了走到资源点、执行采集、收取结果的全过程。这样智能体的决策预算就花在「做什么」和「和谁协调」上，而不是「怎么执行低层动作」上，分数才能真正反映协作。为了让评测可复现，实时游戏被改造成回合制，每轮每个智能体依次拿到新观测、选一个工具调用、等动作结算后再轮到下一个，回合顺序确定；在黑盒设定下，智能体无法访问他人的内部状态、观测或动作历史，协调只能靠经由环境路由的显式聊天消息。任务上，100 个人工标注任务覆盖战斗、制作、采集、交易、探索、生存、建造、协调八大类，外加 100 个由 Claude Opus 生成、经人工校验的增强变体；每个任务包含一个必须多智能体协作才能完成的主目标、带非对称角色与技能与出生点与初始物品的智能体配置、25 到 55 轮不等的回合预算、每个智能体专属的任务上下文文档（配方、怪物属性、资源位置），以及一个用 Python 写的成功判定函数，直接检查最终游戏状态。任务被刻意设计成任何单个智能体都不具备全部技能或资源，例如「资源商队」需要 8 个智能体横跨三个生物群系，由队长协调两支伐木队、山地矿工和一个接收双方材料打造镐子的工匠，智能体必须协商谁采什么、跨区域通报资源数量、在约定地点完成转移。度量上，除了传统的任务成功率（SR）和基于检查点的部分成功率（PSR），论文提出了因果协作有效性（CCE）。SR 和 PSR 只衡量「做到了什么」，却不衡量「是怎么协作做到的」——一个智能体包揽全部工作、其他人闲着，任务照样能成功。已有的 LLM-as-judge 做法让模型整体打分（比如「协调性 1 到 5 分」），主观且随评判模型版本漂移，难以复现。CCE 改用图结构：在任务轨迹上构建「因果动作图」，先找出直接达成目标的成功动作，然后逐轮向后回溯，每一轮让 LLM 判断哪些动作因果性地促成了已被认定为有贡献的动作，这个类似广度优先搜索的过程累积出一个「贡献集」，CCE 就是贡献动作数与全部动作数之比，失败任务按定义 CCE 为零。它的巧妙之处在于，LLM 只做相对客观的二元因果判断（「捕虾是否促成了后来的虾转移」），而不做主观质量评分，因此跨评判模型版本的可复现性大大提升。这套设计让「协作质量」第一次有了一个可分解、可归因的量化口径，而不只是一个笼统的成败标签。

在 Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini 和 DeepSeek R1-70B 四个前沿模型上的实验显示，即便最好的模型也只拿到 52.0% 的任务成功率，CCE 仅为 0.320，也就是说不到三分之一的智能体动作真正因果性地推进了共同目标，绝大多数动作对任务完成没有贡献。分类型看，生存类任务最容易（成功率 67% 到 100%），而协调类（12%）和建造类（20%）最难，恰恰反映出紧密多智能体同步的困难。定性分析揭示出系统性的失败模式：沟通中断（智能体没能共享关键信息）、角色混淆（重复劳动或越出既定角色行事）、以及无法跨轮次维持共享计划。客观地说，这篇工作的局限也很明显：CCE 依赖 LLM 做因果判断，虽然比主观打分客观，但仍受评判模型能力影响；沙盒是 2D MMORPG，任务虽多样但仍是模拟环境，向真实软件工程、科研等场景的迁移性有待验证；回合制与黑盒设定简化了真实协作中的并发与部分可观测性；增强变体由 LLM 生成，即便经人工校验，其难度分布与多样性也可能与人工任务存在系统性差异。尽管如此，它的意义在于把「协作」从一个笼统的褒义词拆解成了可测量、可归因的对象：SR 告诉你团队有没有赢，CCE 告诉你这个赢（或输）有多少来自真正的协作，而 52.0% 与 0.320 这两个数字共同说明，当前基础模型在长时程、非对称、黑盒的多智能体协作上仍存在普遍且结构性的缺口，这为后续研究指明了明确的改进方向。

### [Learning to Stop without Learning to Stop: Self-Supervised Confidence Training Improves Reasoning Efficiency](https://arxiv.org/abs/2609.31619)
`评分3`

这篇论文要解决的是推理模型推理链过长导致推理成本过高的问题。当前主流思路分两类：一类是在推理阶段做早停，通过监控置信度、不确定性或答案稳定性等信号，在模型似乎“想够了”的时候强行终止生成；另一类是在训练阶段显式鼓励短推理，比如用带长度惩罚的强化学习目标，或者筛选出简洁的推理轨迹做微调。这两类方法虽然路径不同，但都把“效率”当作训练或推理时的显式优化目标——要么直接控制何时停止，要么直接教模型生成更短的推理。问题在于，这种显式优化往往需要额外的推理时干预机制，或者引入与正确性可能冲突的长度惩罚，调参复杂且容易损害推理质量。论文提出的疑问是：效率能不能不作为直接优化目标，而是作为学习某种更基础信号的“副产品”自然涌现出来？

核心洞察在于，置信度本身就是关于“当前推理状态是否可靠、继续推理是否还有价值”的自监督信号。作者提出 ConfSFT：用模型自己生成的推理轨迹，在轨迹中间的若干决策点（默认以“Wait”标记为界）截断，接上一个固定的答案引出提示，让模型贪心地生成一个当前试探性答案，再把这个答案的逐 token 概率取几何平均（即长度归一化似然）作为置信度标签。这个标签完全来自模型自身分布，不需要标准答案，也不需要外部评判。然后把置信度量化成 50 档百分比文本，构造训练样本：问题加推理前缀加一句固定引导语“从0%到100%，我目前对答案的置信度是”，后面接这个百分比标签。训练时只对标签对应的 token 位置算交叉熵，问题、推理前缀、引导语全部 mask 掉，损失函数里没有任何关于推理长度、停止或效率的项。由于推理轨迹和置信度标签都依赖当前策略，训练采用迭代式 on-policy 方式：每轮用当前策略在新一批训练题上采样轨迹、构造标签、微调，再进入下一轮。推理时完全不做任何改动——不要求模型输出置信度，不加早停判据，不用验证器，模型也不会自发在推理链里写出置信度。换句话说，效率提升只能来自微调后的策略本身改变了生成行为，而不是任何推理时的外部干预。

实验在 Gemma-4-E2B、Qwen3-4B、Nemotron-Nano-8B、GPT-OSS-20B 四个模型家族上展开，训练仅用 AIME2000–2023 的 600 道题，验证用 AIME2024，测试覆盖 AIME2025、GSM8K、GPQA-Diamond、HumanEval 和 LiveCodeBench。在匹配准确率的前提下，ConfSFT 把生成 token 数分别降低了 11.1%、10.3%、19.2% 和 11.1%，而且从数学训练题迁移到科学和代码任务上仍然有效。与显式优化效率的训练方法相比，比如带长度惩罚的 A&Z 和 On-Policy SFT，ConfSFT 在多个模型上取得了相当甚至更大的 token 缩减，例如在 Qwen 上 On-Policy SFT 降低 17.2% 而 ConfSFT 达到 19.2%，但它完全没有收到任何偏好短推理的监督。分析还显示，置信度预测能力随训练轮次提升的同时 token 数下降而准确率稳定；把推理轨迹分解成高层行为后，ConfSFT 基本保留了基模型的推理行为构成，并不是靠压制某类推理来换效率；把置信度标签随机打乱后效率增益消失或大幅减弱，说明监督信号本身的内容至关重要。局限方面，论文没有给出置信度标签量化粒度、决策点选择策略的系统消融，迭代训练轮数和每轮数据量的影响也只在附录中有限讨论；此外，方法依赖模型自身能生成有意义的试探性答案，对于基模型本身准确率很低的领域，置信度信号是否仍然可靠尚不清楚。总体而言，这项工作提示了一条新路径：让模型学习元认知信号（如置信度）本身，就可能作为下游结果自然带来更高效的推理，而不必把效率当作直接优化目标，这对未来推理模型的后训练设计有启发意义。

### [User Model Extraction via Belief Self-Distillation](https://arxiv.org/abs/2609.31603)
`评分3`

这篇论文要解决的核心问题是：大语言模型在对话中会隐式地推断用户的各种属性（比如性别、教育背景、是否具有寻求真相的意图、对AI的信任程度等），并据此调整自己的行为——包括个性化推荐、是否顺从请求，甚至是否拒绝回答。然而，这些“用户信念”深藏在模型的隐藏激活中，既难以被人类直接观察，也无法被因果性地操控。此前的方法大致分为两条线：一是线性探针，能从激活中解码出人口统计等属性，但这类方法通常只关心“读”，不关心“写”，而且往往依赖受控属性或合成线索；二是激活引导，能对某些表征进行因果干预，但通常从预定义的属性出发，干预方向未必对应模型自身真正使用的用户表征。更关键的是，模型对用户的“信念”并没有外部真值——重要的不是用户实际上是谁，而是模型认为用户是谁。这就导致传统的有监督探测方法在概念上就不完全匹配，因为标注数据反映的是真实属性，而非模型内部的主观推断。LatentQA等更 expressive 的方法虽然能提取开放式用户表征，但需要训练辅助解码器，且主要优化的是读出质量，并未显式保证学到的表征具有因果可写性。因此，之前的方法要么只能读不能写，要么读写分离，无法回答“模型对用户的信念到底是什么，以及这个信念能否被隔离并因果修改”这一机制性问题。

BSD的核心创新在于用一个“读写一体”的瓶颈结构，让模型自己教自己，把用户信念蒸馏成一个紧凑向量。具体来说，它初始化两个完全相同的冻结模型，一个当教师，一个当学生。教师只看到完整对话，在某一层的最后一个token位置取出隐藏状态，经过一个低秩投影矩阵A压缩成一个128维的用户向量v_user。学生则只看到属性探测问题（比如“这位用户的教育程度是什么？”），完全看不到对话内容。学生唯一的对话相关信息就是通过另一个投影矩阵B写入到它激活中的v_user。训练目标是最小化学生注入v_user后输出的属性答案分布与教师基于完整对话和探测问题所给出的信念分布之间的KL散度。这里的关键设计是信息不对称：学生没有对话，所以教师对用户的全部推断必须通过v_user这个瓶颈传递过去。这就迫使v_user必须编码模型自己用来刻画用户的信息，而不是任何外部标注的属性。同时，B被约束为正交列，保证写入操作不改变向量范数，使得后续的因果干预可以公平比较。训练完成后，A和B就构成了一个读写接口：读的时候，在v_user上训练线性探针，就能恢复模型推断的属性；写的时候，在用户空间中构造一个目标方向（比如从“男性”到“女性”的均值差），通过B注入回模型激活，就能因果地改变模型的信念。这种方法之所以比传统方法更好，是因为它学到的用户状态是显式优化为既能解码又能因果干预的——传统探针只优化解码，激活引导只优化干预，而BSD通过自蒸馏目标把两者统一在一个低维瓶颈中，并且由于学生看不到对话，这个瓶颈被迫只保留模型真正用于表征用户的信息，而不是激活中所有可解码的冗余信息。

在实验上，BSD在Llama-3.1-8B、Qwen3-8B和OLMo-3-7B三个模型上进行了验证，使用约5.8万条来自WildChat和WildJailbreak的对话，定义了13个属性，包括社会人口学属性和安全相关属性（如寻求真相的意图、交互风格、对AI的信任）。读出方面，128维的v_user将隐藏状态压缩了32倍，但线性探针的macro-F1与直接在原始隐藏状态上训练的探针差距在4%以内，说明压缩几乎没有损失可解码的用户信息。写入方面，用对比激活加法在v_user上计算引导向量，再通过B注入，翻转率显著高于直接在原始隐藏状态上引导：在Llama-3.1-8B上，v_user引导的翻转率达到78%，而原始状态只有21%，随机向量基线仅13%；在OLMo-3-7B和Qwen3-8B上，v_user分别比原始状态高出23%和13%的翻转率。更重要的是，论文发现拒绝行为不仅取决于请求本身，还取决于模型推断的用户意图：固定同一个有害请求，只改变模型对用户意图的信念，就能显著改变拒绝率。此外，独立训练的模型在用户表征的几何结构上表现出惊人的跨模型规律性，说明不同模型可能收敛到相似的“用户空间”几何。局限方面，BSD目前依赖预定义的属性集合和多项选择探测来获取信念监督，这限制了它捕捉更开放式用户表征的能力；干预虽然对目标属性有效，但仍有约37%的跨属性泄漏，说明选择性还有提升空间；此外，Qwen3-8B对一般激活扰动高度敏感，随机基线翻转率就达到27%，虽然v_user仍显著优于随机，但绝对性能受模型特性影响。总体而言，这项工作的意义在于把隐式用户模型从“可读但不可写”或“可写但不对应模型真实信念”的状态，推进到了可读且可因果写入的内部状态，并揭示了用户信念在安全决策中的直接因果作用，为AI安全中“模型根据它认为你是谁来决定如何行动”这一问题提供了可操作的分析工具。

### [Highlight-Then-Summarize: Learning to Compress Evidence for Long-Context Understanding](https://arxiv.org/abs/2609.31382)
`评分3 · 23 pages, 13 figures. Zhaoyuan Xia and Qinghongbing Xie cont · 有代码`

长上下文理解的核心矛盾在于，任务真正需要的证据往往稀疏地散布在数万 token 的文档中，而大量无关冗余内容会严重干扰模型的推理。现有方法大致沿两条路线应对：一是长上下文强化学习，通过构造检索-推理轨迹或直接奖励上下文定位来让模型更容易找到证据；二是检索增强生成与引用归因方法，侧重把生成内容对应回源文档。但这些方法的共同局限在于，它们只解决了“证据在哪里”的问题，却没有显式规定“多条证据该如何被整合”。证据的拼接与关系推断被隐含地留给了最终答案生成阶段，模型必须同时完成保留碎片化证据、推断证据间关系、组织语言作答三件事，这种纠缠导致证据难以被一致地使用，也容易诱发不必要的冗长推理。论文用一个 motivating study 佐证了这一判断：在 15.19K token 的文档上，仅额外加入 1.04K token 的、由模型自己生成的、以问题为条件的摘要，Qwen3.5-Flash 的准确率就从 72.6 提升到 85.9；若用 Claude 生成的 0.46K token 摘要，准确率甚至达到 93.0，与原文档结合后进一步升到 96.7。这说明把分散证据重组为紧凑的、面向问题的表示，本身就是提升长上下文推理的有效杠杆。

H2S 的核心设计是把“选证据”和“整合证据”从最终作答中剥离出来，显式外化为两个中间表示，再让答案以这两个表示为条件生成。具体来说，模型面对被切成带稳定标识符的源文档块，先执行 Highlight 阶段，输出一组可溯源到具体块和 span 的证据项，保留证据的出处；再执行 Summarize 阶段，把这些可能零散、跨远距离的证据映射成一个以问题为条件的摘要，这个摘要既不是泛泛的文档摘要，也不是检索片段的简单拼接，而是按问题所需推理组织起来的紧凑状态。关键在于，整个流程由同一个自回归模型一次性生成，条件分布被分解为“源定位—问题条件下的证据整合—任务完成”三个因子，前两个因子因此变得可观测、可监督、可做过程级评估。原文文档在生成全程保持可用，所以 H2S 是“组织上下文”而非“剪枝上下文”，既保留了回源能力，又让推理所需信息显式化。为了训练这种行为，作者构建了 H2S-Dataset，把已有的 (文档, 问题, 答案) 三元组增强为 (文档, 问题, 证据, 摘要, 答案) 五元组，共 6,647 条、来自 11 个 benchmark 家族，其中 4,228 条用于 SFT、2,419 条用于 RL；数据构造时先用混合词法与语义检索形成高召回候选池，再把问题拆成原子信息需求并抽取相关 claim，绑定到块标识与支撑 span，随后去重、按信息需求组织并合成摘要，最后通过忠实性、覆盖度、可答性三重质检。训练侧提出 H2S-RL，基于 GRPO，用确定性程序化奖励联合评估最终答案质量、证据质量（块标识与 span 能否在源文档中解析、span 级 F1）、摘要质量（去掉局部证据标识后的 ROUGE-L）以及结构门控（Evidence–Summary–Answer 结构是否完整），从而让证据选择和摘要构建两个阶段互为约束——任一阶段失败都会拉低过程奖励，避免某一强项掩盖另一弱项，也无需在线 LLM 裁判。

在统一的 128K 输入、4K 输出预算下，H2S-7B 和 H2S-14B 在自建的 H2S-Bench（覆盖检索、推理、聚合、引用、摘要等七类任务）上分别取得 28.56 和 32.60 的平均分，其中 H2S-14B 在开源模型中整体最强，比 QwenLong-L1-32B 高 5.01 分、比 Qwen3.8-27B 高 10.17 分；H2S-RL 在 7B 和 14B 的 SFT checkpoint 上又分别带来 4.88 和 3.44 分的提升。过程级分析进一步支撑了机制有效性：H2S-14B 取得最高的 Evidence–Summary Quality 分数，移除其生成的摘要会让平均性能下降 8.47 分，而把输出预算从 4K 扩到 16K 只多带来 0.96 分，说明性能增益主要来自证据组织质量而非更长的生成。局限方面，H2S 依赖高质量的证据与摘要监督数据，构造管线较重，且 H2S-Bench 与训练数据同源，跨领域泛化仍需验证；摘要作为中间瓶颈也可能在证据关系复杂时丢失细节。但总体而言，它把长上下文推理的改进方向从“找得更准”推进到“组织得更好”，为过程级监督和紧凑推理状态的设计提供了一个可复用的范式。

### [New LoRA Skills Should Read but Never Write](https://arxiv.org/abs/2609.31600)
`评分3`

这篇论文要解决的是大语言模型多任务适配中的一个核心痛点：如何把多个独立训练好的LoRA适配器组合进同一个模型，同时不破坏各自已经学会的技能。LoRA让每个任务都能以极低成本微调出一个小的低秩更新模块，实际系统里自然会积累一堆这样的适配器，但把它们合起来却非常棘手。已有的三条路线各有硬伤：在权重空间直接相加或合并更新会产生干扰，因为不同任务的更新方向可能冲突甚至相互抵消；在所有任务数据上联合重训代价高昂，而且容易把已经学好的技能带偏；用路由或门控在推理时选择不同适配器虽然保住了各自的能力，但系统始终没有真正变成一个单一模型，服务路径上永远挂着额外的调度机制。更早的合并方法如TIES、DARE、RegMean等试图改进合并算术，但它们把适配器当成已经完成的、内部形式无关紧要的对象，新适配器一到就要重新做全局合并，旧技能会被再次移动。论文指出，这些方法都隐含地做了两个从未被显式审视的选择，而正是这两个选择决定了组合后技能能否存活。

第一个选择是LoRA更新的因子分解坐标。一个更新矩阵可以写成两个低秩矩阵的乘积，但这对因子并不唯一——对任意可逆矩阵做变换，乘积完全不变。当适配器单独服务时，这个自由度不可见，因为模型只看到乘积；但一旦要学习适配器之间的耦合，耦合矩阵连接的是一个适配器的输入基和另一个适配器的输出基，而这些基并不是由技能功能决定的，而是初始化、数据顺序和随机种子留下的偶然产物。如果直接在原始因子上学耦合，学到的可能是训练过程的偶然性而非技能之间的真实关系。第二个选择是耦合的方向。旧技能和新技能之间的连接可以指向两个方向：让新技能把自己的输入方向写入旧技能的输出基，或者让新技能读取旧技能的输入方向进入自己的输出基。前者会改变旧技能对每个输入的计算结果，旧行为只能靠优化恰好没怎么移动它来保护；后者则对旧技能的输出不添加任何项，旧技能的功能在构造上就被完整保留。READ的核心设计就是同时固定这两个选择：它先用薄QR分解和奇异值分解把每个适配器重写成一种平衡的规范形式，这个变换精确保持更新矩阵不变，但让两个因子携带相同的度量，从而消除基的任意性；然后在每次追加新技能时，只训练耦合矩阵中新技能对应的那一行和对角块，旧技能之间的所有耦合块和旧因子全部冻结，新技能可以读取旧技能的输入子空间，但不能写入旧技能的输出子空间。这样每次追加只引入极少量可训练参数，组合后的更新可以预先折叠进基础权重，推理时就是一个普通的秩为kr的LoRA更新，不需要路由器、不需要任务标识、也不需要额外的服务开销。

实验在Llama-3.2-3B和Qwen3-4B两个模型家族、GLUE、SuperGLUE、Domain和BBH四个基准套件上进行，每次追加一个技能。在Llama-3.2-3B上，READ在GLUE、SuperGLUE和Domain三个套件的最终平均值上都超过了最强的可折叠替代方案，其中SuperGLUE从0.605提升到0.783，Domain从0.846提升到0.887；在Qwen3-4B上同样赢下这三个套件，GLUE从0.775提升到0.838。在全部32条谱系中，READ赢了24条，输掉的8条全部集中在BBH上，平均领先最强基线0.073，置信区间为0.047到0.101。这些结果说明，因子坐标和耦合方向这两个单独适配器从不暴露的选择，确实是决定组合技能能否存活的关键。局限也很明确：BBH上的全面失利表明这种方法在需要复杂推理链或多步组合的任务上可能不够，而且每次追加仍然需要在旧任务和新任务的联合数据上做一遍训练，虽然只优化极少量参数，但数据暴露并没有完全消除。此外耦合存储随技能数量二次增长，在测量范围内占比很小，但技能数量继续增大时可能成为新的瓶颈。总体而言，这篇工作把LoRA组合问题从“如何更好地合并权重”推进到了“在什么坐标系中、沿什么方向让技能交互”这一更根本的层面，为构建真正单一的多技能模型提供了一条无需路由、无需重训全部数据的可行路径。

### [EAServe: Encode-Aware Disaggregated Serving for Multimodal Large Language Models](https://arxiv.org/abs/2609.31551)
`评分3 · 13 pages, 12 figures, 7 tables. Accepted to PACT 2026`

多模态大模型在真实部署中面临的核心系统问题，是它比纯文本大模型多出了一条“编码”阶段，从而形成了编码—预填充—解码的三段式流水线。纯文本推理天然可以拆成计算密集的预填充和访存密集的解码两段，分别放到独立伸缩的GPU池上，这就是已经被工业界验证有效的PD分离。但多模态模型在最前面还要跑一个模态编码器，把图像、视频或音频转成语言模型能吃的嵌入向量，于是多出的编码阶段就成了整条流水线的入口。问题在于，这个入口阶段的计算和带宽需求随模态、输入尺寸、到达模式剧烈变化，而现有框架对它要么完全不管（纯文本PD系统根本没有编码概念），要么只是把它当成一个独立服务跑通，一次只处理一个请求，GPU分配靠人工设定，也不去调节下游请求的流入节奏。这种被动处理带来一个结构性失衡：每个请求都必须先过编码才能进入下游，可单次编码前向太小，根本喂不饱现代GPU，而想攒大batch又受制于等待延迟。结果就是编码GPU在高负载下依然大量空转，下游的预填充和解码工作节点却堵在越来越长的编码队列上，尾延迟被不断推高。作者用实测说明了这一点：基线部署下编码GPU的计算和HBM带宽利用率都很低；简单加一个batch size为8的微批处理虽然能提升吞吐、降低首token延迟，却会让平均每token延迟急剧上升，因为被加速的编码把下游冲垮了，而编码GPU本身依旧在短暂爆发和长时间空闲之间反复横跳。这三点观察——需要一个能随到达率自适应的调度策略、需要一个把编码GPU空闲算力导向同机预填充工作节点的卸载机制、需要一个在batch变化时仍能隔离两个共置工作节点的资源划分原语——构成了全文的设计动机，而这三者又彼此耦合，无法单独调优。

EAServe的核心洞察是把编码阶段重新定位为整条流水线的控制点，因为作为入口，它天然掌握三个耦合维度：工作何时进入下游、预填充在哪里执行、GPU如何被共享。系统分两层协同设计。上层是混合自动选择（HAS），负责离线搜索部署配置，配置由GPU分配方案、编码batch上界和预填充卸载比例三部分组成。HAS的关键在于发现配置空间存在内部不对称性：GPU分配的一阶效应是单调且可由各阶段单worker容量预测的，如果某个阶段被饿死，那无论batch和卸载比例怎么调，瓶颈都在那里，这类分配可以直接剪掉、无需真实部署；而batch与卸载比例之间的交互在可行分配集合内是非单调的，只能靠端到端实测来定位。于是HAS先用各阶段容量画像并行地在不同GPU子集上做profiling，剪掉不平衡的分配，再用基于TPE的贝叶斯优化在剩余空间里精调，从而比暴力搜索更快逼近近优配置。下层是三个编码感知的运行时机制，把HAS选出的配置真正落地并在线自适应：第一是负载自适应的微批处理，配合一个泊松间隔派发规则，让编码batch上界跟随当前到达率变化，而不是死等一个静态超时；第二是速率受控的部分卸载，把编码GPU的空闲算力以受控速率导向同机的本地预填充worker，既利用闲置资源又不会反过来拖慢编码本身；第三是动态的每微批SM划分，借助libsmctrl写每进程的TPC掩码，在亚微秒级重新配置SM分区，让编码和本地预填充按当前batch大小比例瓜分计算资源。这里有个重要的设计约束：软件级SM划分只能隔离SM、不能隔离HBM带宽，而解码阶段是逐token流式读取KV cache的访存密集型负载，一旦和编码共置就会无视SM划分把共享内存总线打满，所以解码必须留在专用GPU上，共置只发生在编码与预填充之间——这两者都是计算密集的transformer前向，按TPC掩码切分计算正好能保护编码延迟。也正因为SM划分比例取决于当前编码batch上界，而batch上界又影响本地预填充能接受多少卸载，三个机制被牢牢绑在一起，必须联合设计、联合搜索，这正是HAS存在的理由。

在评估上，作者在8卡服务器上覆盖了图像、视频、音频三种模态的代表性模型——LLaVA-v1.6-34B、Qwen2.5-VL-32B和Ultravox-v0.6-27B，在多种TTFT/TPOT延迟目标下与NVIDIA Dynamo和vLLM对比。在相同SLO约束下，EAServe的goodput（满足SLO的请求速率）最高比Dynamo提升4.3倍、比vLLM提升1.7倍，同时整条EPD流水线的GPU利用率更均衡也更高，并且比基线搜索方法更快找到近优的分离配置。这些数字的意义不只是加速比本身，而是说明把编码从被动的直通服务提升为流水线控制点、并把调度、卸载、SM划分三者联合优化，确实能解开多模态服务里那个“入口阶段卡住全局”的结构性死结。当然，论文也留下了明确的局限：软件SM划分无法隔离HBM带宽，这直接排除了把解码共置到编码GPU上的可能，也就意味着解码仍需独占GPU，GPU预算紧张时这种分离策略的收益会受限；HAS的搜索虽然经过剪枝，但仍需对每个模型、工作负载、GPU预算和目标到达率的组合离线跑一遍，部署组合爆炸时配置成本依然可观；此外实验集中在单机8卡，跨节点场景下嵌入向量和KV cache的传输开销、以及编码队列的跨节点调度是否仍能维持这种收益，还有待验证。总体来看，这篇工作为多模态服务系统指出了一个被长期忽视的方向：与其只盯着预填充和解码的分离，不如回头把编码这个入口阶段当作调度与资源分配的中枢来重新设计，而它给出的编码感知运行时三件套与容量画像加贝叶斯优化的混合搜索思路，很可能成为后续EPD服务框架的参考基线。

### [Game Arena: Strategic LLM Evaluation in Competitive Environments](https://arxiv.org/abs/2609.31473)
`评分3 · 31 pages, 15 figures. Technical report. Project page: https:`

静态基准测试的饱和与污染问题，是当前LLM评估面临的核心困境。MMLU、GSM8K这类固定测试集，随着前沿模型性能逼近上限，区分度急剧下降，而且测试数据可能泄露进训练语料，导致分数虚高。基于人类偏好或LLM裁判的动态评估虽然能生成新鲜样本，但主观性强、标准不一致，还存在冗长偏好和谄媚等偏差，评估信号噪声很大。游戏提供了一条更可靠的路径：胜负结果客观可验证，且随着模型变强，对局本身也在演化，不会饱和。但已有的游戏基准大多以固定数据集或孤立评估的形式发布，样本量小、统计功效不足，无法支撑持续性的纵向追踪。Game Arena正是针对这些缺陷设计的开放平台，首批覆盖国际象棋、扑克和狼人杀三个环境，分别对应完全信息、不完全信息和多人博弈三种信息结构。

三个环境共享一套统一的文本交互协议：模型在每个决策点收到自然语言描述的当前状态和历史，必须返回规定格式的单一动作，非法响应允许有限次重试但仅给出最少反馈。国际象棋采用标准FIDE规则，每对模型下40局并平衡黑白，模型只拿到FEN格式的棋盘和PGN走子历史，不提供合法走子列表，必须自行推断走子合法性，连续非法则判负，重试次数被记录为诊断指标。扑克采用单挑无限注德州扑克，每手100BB重置筹码，每对模型进行100手一组的独立对局，组内模型能看到之前所有手牌的完整文本历史，且每手结束后双方底牌强制亮出，加速对手建模的反馈循环。最关键的创新是引入了重复扑克格式：每100手序列预先洗牌后打两遍，交换座位和底牌，使得同一发牌序列下不同模型的决策可以直接对比，大幅降低方差。每个对局组合共20000手，十模型循环赛总计90万手，远超此前基准的几千手规模。狼人杀为8人局，两狼一预言家一医生四村民，环境通过事件总线和可见性权限严格实施信息不对称，模型采用ReAct框架生成推理和动作，解析失败时强制弃权。评估层面，国际象棋用Bradley-Terry模型拟合Elo等级分并锚定最低分为零，扑克以筹码盈亏为主指标，所有环境均报告bootstrap置信区间。

这一平台的核心贡献在于把游戏评估从一次性基准转变为可持续运营的竞技场。90万手的扑克对局规模使得统计显著性有了保障，重复扑克的设计让同牌对比成为可能，这在LLM扑克基准中尚属首次。国际象棋中不提供合法走子提示、隐藏诊断信息的设计，迫使模型真正理解棋盘状态而非模式匹配。狼人杀则同时提供了战略能力评估和agent安全研究的沙盒——模型既要生成欺骗也要检测欺骗，可以在受控环境中红队测试其操纵能力。局限方面，论文本身尚未给出完整的跨模型排名结果，外部校准仅通过Stockfish技能等级做近似插值，狼人杀的团队胜负归因也比双人零和博弈复杂得多。但方向是清晰的：以真实对局结果锚定评估、以大规模采样保证统计严谨、以可插拔的游戏协议支持持续扩展，这套思路如果被社区采纳，有望成为对抗基准污染和饱和的长期基础设施。

## 强化学习 RL

### [SLCA-GRPO: Resolving Cross-Segment Credit Misattribution in Tool-Calling RL](https://arxiv.org/abs/2609.29050)
`评分4 · HF 6赞`

工具调用智能体的输出天然是异质的：一段是穿插推理与结构化 API 调用的执行轨迹，另一段是面向用户的自然语言总结。标准 on-policy 强化学习算法（如 GRPO）会把整条轨迹压缩成一个标量优势，再原封不动地广播给所有 token，这就制造了一个结构性的失败模式。问题不在于奖励信号不够密，而在于信号在进入优势估计之前就已经被混在一起：总回报等于工具回报加总结回报，GRPO 直接对这个总量做组内归一化，于是总结部分的好坏会渗进工具决策 token 的梯度里。后果是双向的——一次失败的工具调用如果后面跟了一段漂亮的总结，反而可能被正向强化；一条正确的工具轨迹如果总结写得差，也会被连带惩罚。作者把这种现象称为跨段信用错配，并强调它和梯度方向冲突是两回事：诊断显示工具段与总结段的梯度方向近乎正交，真正的噪声来源是优势污染。已有的缓解手段都没堵住这条路：VinePPO、GiGPO、SPO 这类时序信用分配方法仍然在总回报上做文章；ToolPO 加了局部工具奖励，但总结相关的噪声依旧能到达工具 token；RLTR 干脆把规划器和总结器拆成两个模型，放弃了统一策略的简洁性。

SLCA-GRPO 的核心洞察是：信用分配的轴不只有时间轴，还有一条结构轴——执行与表达。方法先利用梯度掩码把可学习 token 与冻结的环境上下文区分开，再确定性地切出两个语义段：总结段是最后一段连续的可学习 token，工具段是此前所有可学习 token 的并集，包括工具调用之间的思考块。这样每个带梯度的 token 都被唯一归入一个语义角色，不需要训练额外的分段器。关键操作发生在优势估计阶段：工具回报和总结回报在同一个 rollout 组内分别做归一化，得到两个独立的段级优势，然后工具优势只路由给工具 token，总结优势只路由给总结 token。这等于在反向传播之前就把总结到工具的优势通路物理切断，而不是事后做梯度投影。它不增加任何额外 rollout，也不拆分模型，代价是引入了一个有意的偏差——方法明确假设密集的执行奖励对更新工具决策 token 而言是方差更低、信息量足够的信号，而不声称工具调用对最终答案没有因果影响。配套的基础设施有两个：Schema-Guided LLM Simulator 用确定性 schema 校验加跨家族冻结 LLM 模拟工具响应，既避免了真实 API 的高成本和不可复现，又通过跨家族设计减少隐式泄漏；Hierarchical Rewards 把回报拆成工具侧的过程奖励和总结侧的偏好奖励，分别对应执行正确性与表达质量。值得注意的是，SLCA 处理的结构轴与 VinePPO、GiGPO 处理的时序轴正交，因此理论上可以和时序信用分配方法叠加使用，只是这篇论文没有做组合实验。

在 Qwen2.5-7B-Instruct 为主干、相同训练预算下，SLCA-GRPO 在三个基准上都超过了标准 GRPO、ToolPO 和 RLTR：域内 Toucan 上高出 2.53 个百分点，BFCL 单轮原子泛化上高出 1.36 个百分点，τ²-Bench 的双控协作任务上高出 9.15 个百分点，同时在工具冗余和调用成本上都有下降。跨规模验证也一致：3B 和 8B 主干上 Toucan 的增益分别为 2.35 和 2.05 个百分点。消融实验覆盖了去掉 SLCA、去掉 SGLS、去掉 HierR 三种情况，用来分离各模块的贡献。局限也很明确：SLCA 只解决段间污染，不解决工具段内部多个动作之间的时序信用分配，论文没有评估与时序方法的组合效果；分段规则依赖轨迹以单一最终答案块收尾，边缘情况需要额外处理；理论保证是每次更新的条件性优势隔离，而非全局无偏优化。尽管如此，它指出的问题——异构输出下统一标量优势的结构性失效——对工具调用智能体的 RL 后训练具有普遍意义，而把信用分配从时间轴扩展到结构轴，也为后续同时沿两个轴做精细分配留下了清晰的空间。

### [Strategically Diverse Sampling for Self-Training](https://arxiv.org/abs/2609.31571)
`评分3`

这篇论文要解决的核心问题是：当前大语言模型的自训练流程在构造训练数据时，普遍采用独立同分布采样再按正确性过滤的做法，但这会导致模型反复强化自己本来就偏好的那套解题策略，采样出的回答往往只是表面措辞不同、底层思路高度雷同。这种模式坍缩在模型能力边界附近尤其致命——难题本来就极少被解出，IID采样在可行预算内可能一次都碰不到正确路径，于是RL的 rollout 组拿到完全相同的奖励、梯度信号消失，测试时聚合的候选池也缺乏可组合的差异。作者指出，真正有价值的不是词面或嵌入空间上的多样性，而是“策略多样性”，即针对同一问题在解题方法层面存在实质性分歧。他们想验证的假设是：与其在正确性上死磕，不如改变采样程序本身，让训练数据覆盖模型心目中合理的决策空间，这样即便样本是错的，也可能比正确但同质的样本更有训练价值。

方法上有两个关键设计。第一个是 Groot，它让模型针对一个问题先构造一棵关于可能解法的层次化决策树，然后从根到叶选出若干条互不重合的路径，每条路径代表一种在某个关键决策点上与其它路径分道扬镳的解题策略；由于两条根到叶路径必然在某处分歧，策略差异就被结构强制保证了。第二个是 Verbalized Sampling 的策略级改编：让模型一次性列出多种解题思路并附上估计概率，得到一个无结构的方法集合，差异程度完全由模型自己的枚举决定。两者都采用两阶段流程——先做一次规划调用拿到若干策略，再把每个策略作为隐藏指令单独喂给模型，要求它“假装是自己想到这个思路的”来生成完整推理链，并自动丢弃那些在回答中显式提到该指令的样本，从而保证训练数据仍是标准的“先推理后作答”格式。与 Tree-of-Thoughts 那种在推理时搜索和剪枝不同，Groot 的树只在造数据时建一次，测试时仍是普通解码。作者还特意把温度调到1.5作为额外的IID基线，发现单纯升温只能增加解出的问题数，并不能带来策略层面的分化，这反衬出 Groot 和 VS 的增益来自采样程序的结构性改变，而非随机性变大。

实验在竞赛编程和下一章预测两个领域展开，均以 Qwen3-4B-Instruct 为主模型并在 Nemotron3-Nano-4B 上复现。竞赛编程聚焦于“前沿”难题（64次IID采样中最多解出2次），结果显示 Groot 和 VS 训练后的模型在留出集上的 pass@8 达到基线的三倍以上，而 IID 训练即便用16倍采样预算也几乎不涨；更惊人的是，用策略多样但最终答案错误的轨迹做自训练，效果超过了从235B教师模型做IID蒸馏，说明策略集合的构成比正确性和教师规模都更重要。在下一章预测中，IID采样的高质量计划无法提升模型基础能力，而策略多样化训练显著提高了生成高质量计划的概率，并且为后续RL和递归自聚合提供了更强的初始化。局限方面，两种方法都额外增加了一次规划调用，论文在预算对比时未计入这笔开销，且策略多样性的收益在模型能力边界之外是否仍然成立、如何自动判断该用Groot还是VS，都还没有给出原则性答案。但这项工作的意义在于直接挑战了“正确性至上”和“大教师一定好”的默认假设，把自训练数据的构造从过滤问题重新定义为采样问题，为后续在RL预热和测试时扩展中系统性地利用策略多样性打开了空间。

### [Trust Guided Decision Transformer](https://arxiv.org/abs/2609.31586)
`评分3 · To appear in Neurips 2026`

Decision Transformer 在长程 rollout 中性能会显著退化，即使训练已经在离线数据上收敛。这篇论文指出，问题并不出在策略本身，而在于策略所依赖的条件上下文。DT 在训练时使用的上下文窗口来自离线轨迹，但在评估时，上下文是由模型自己一步步生成的。经过足够多自生成步骤后，rollout 上下文会逐渐偏离离线分布，策略被迫在训练中从未见过的历史上做决策，此时动作不再受训练目标的有效约束。作者把这种失败模式称为 rollout context mismatch。更关键的是，这种失配有一个可测量的前兆：一个冻结的外部下一状态预测探针的滚动预测误差会在 rollout 过程中升到离线范围之上，并且持续保持高位，而不是仅仅出现孤立尖峰。这意味着失败并非来自偶发的预测抖动，而是上下文已经离开了 DT 训练目标仍然有意义的区域。已有的修复方法大多在问“给定上下文，哪个动作最好”，比如加 critic 做价值引导、做行为正则化、或在线调整上下文长度，但它们都忽略了一个更优先的问题：这个上下文本身是否可信？如果上下文已经不可靠，critic 在这些动作之间排序，本质上只是在模型自己已经标记为可疑的选项里挑一个。

TGDT 的核心设计正是把上下文可靠性与动作价值在决策层面拆开，并且颠倒了两者的顺序。它在每一步查询多个不同长度的上下文后缀，为每个后缀维护一个滚动下一状态预测误差，并用离线数据校准出的阈值来过滤掉近期误差超限的后缀，然后才让冻结的 critic 在存活下来的可信后缀所生成的动作中挑选价值最高的那个。这里的阈值来自留出离线轨迹上的滚动预测误差的 95 分位数，形式上借用了 split conformal prediction 的次序统计量，但作者明确不声称在线覆盖保证，因为闭环 rollout 与 teacher forcing 验证轨迹并不可交换。为了让这个可靠性信号有意义，模型还做了两件事：一是动作头采用行为正则化的残差形式，基预测加上有界残差，并用类似 TD3+BC 和 ReBRAC 的损失把动作约束在离线数据附近，否则预测误差反映的可能是动作漂移而非上下文漂移；二是 DT 自身训练了一个内部可靠性头，从动作 token 的隐藏状态直接预测下一状态，这样运行时不需要外部探针。critic 用 IQL 训练后冻结，只在训练时提供微弱的价值偏置，在评估时仅用于对少量候选动作排序，绝不用于在连续动作空间中搜索。这个设计的关键洞察是：价值排序必须发生在可靠性过滤之后。在 Maze2D-medium 上的受控消融显示，同样的模型、同样的冻结 critic、同样的候选后缀集合，仅把 critic-only 选择改成先信任过滤再排序，最长超阈值连续段就缩短了约 8 倍，归一化回报也得到提升。

在 D4RL 的 Maze2D、AntMaze 和 MuJoCo locomotion 任务上，TGDT 相比同一个训练模型使用全上下文、硬重置上下文、以及仅用 critic 选择后缀这三种评估方式都有提升，同时减少了持续高误差的 rollout 段。论文还做了训练侧消融，表明仅靠辅助下一状态预测、冻结 IQL critic 引导、以及有界行为正则化残差动作头，虽然各自都能提高回报，但评估时仍然会出现长时间的超阈值高预测误差段，说明训练侧改进不足以解决可靠性问题。局限方面，TGDT 的阈值没有在线覆盖保证，非交换性来自滚动窗口的时间相关、rollout 状态分布依赖策略自身历史、以及评估动作分布与离线数据的差异；此外它依赖一个学到的下一状态预测器，预测器在随机性强的环境中的校准质量会影响信任过滤的效果。尽管如此，这篇论文的意义在于把 DT 长程退化从“策略不够好”重新定位为“上下文不可信”，并给出了一种决策层面的、可操作的顺序原则：先判断上下文是否可信，再在可信上下文产生的动作中做价值排序。这个视角可能影响后续对序列模型离线强化学习的评估协议和在线上下文选择机制的设计。

### [Online Learning via Learned Latent Bayesian Tracking](https://arxiv.org/abs/2609.31559)
`评分3 · Accepted at NeurIPS 2026`

现代机器学习系统越来越多地部署在数据分布随时间变化的环境中，例如自适应信号处理、无线通信以及面临分布偏移的视觉系统。在这类场景下，模型必须持续适应不断演化的数据分布，同时还要满足严格的计算和延迟约束，这就带来了一个核心挑战：如何从有限的流式数据中实现快速而可靠的在线适应。传统做法是基于在线梯度优化，用随机梯度方法随着新样本到来逐步更新参数。这类方法虽然通用，但缺乏对不确定性的原则性建模，通常需要多步梯度更新和精细的超参数调节才能保持稳定，因此在“必须在极少样本内完成适应”且计算资源紧张的场景下表现不佳。另一条更古老的思路是把在线学习看作贝叶斯状态估计问题，即把模型参数视为随时间演化的状态向量，用贝叶斯滤波器递归更新。卡尔曼类滤波器天然提供单步的预测-校正更新，并能传播不确定性，理论上非常适合快速在线适应。但问题在于，贝叶斯滤波的计算复杂度至少与状态维度成平方关系，有时甚至是立方关系，而这里的“状态维度”就是模型参数的数量。对于现代深度模型，参数量动辄百万千万，直接做贝叶斯滤波在计算上完全不可行。于是现有方法只能退而求其次，走两条近似路线：一是对协方差矩阵施加结构约束，比如假设它是对角矩阵或低秩矩阵；二是限制表示能力，比如只更新预先指定的参数子集，或者依赖人工设计的低维动态模型。这些近似虽然降低了复杂度，但严重损害了适应性能，而且对大规模实时学习来说往往仍然太贵。这篇论文的核心洞察正是：真正的瓶颈不在于贝叶斯滤波器本身，而在于缺乏一个合适的低维隐动态状态空间表示，使得滤波可以在不牺牲模型表达能力的前提下高效进行。

针对这个问题，作者提出了一个名为“基于学习隐贝叶斯跟踪的在线学习”框架，核心思想是把在线适应从原始高维参数空间搬到学到的低维隐空间里去做。具体来说，他们不再直接去估计当前分布下的最优高维参数，而是引入一个低维隐状态向量，再通过一个学到的“提升映射”把隐状态还原成完整的模型参数。隐状态的演化被建模成一个随机线性动态系统，状态转移矩阵取对角形式，过程噪声协方差为某矩阵，这实际上是一种常见的Ornstein-Uhlenbeck型动态。学习者只能通过流式带标签样本间接观测隐状态，观测模型把隐状态经提升映射后的预测类别概率与真实标签的one-hot编码联系起来，观测噪声被建模为零均值、协方差为某矩阵的高斯噪声，这个假设的合理性在于交叉熵训练下最优概率预测器的误差是零均值且与估计不相关的。有了这个隐状态空间模型后，在线适应就用扩展卡尔曼滤波来完成。扩展卡尔曼滤波之所以合适，一是它每步只需要一次局部线性化和一次更新，只计算一次雅可比矩阵；二是它的复杂度虽然与状态维度成平方关系，但这里的状态维度是低维隐向量维度而非完整参数维度，因此计算上可行；三是相比无迹卡尔曼滤波、容积卡尔曼滤波或粒子滤波，扩展卡尔曼滤波实现简单且对平滑非线性跟踪性能足够好。每一步，扩展卡尔曼滤波先根据动态模型预测隐状态的均值和协方差，然后用新来的带标签样本做校正，校正时用观测模型对隐状态的雅可比矩阵做局部线性化，计算出卡尔曼增益后更新隐状态均值和协方差，最后通过提升映射把更新后的隐状态还原成完整的模型参数。整个在线适应过程每个样本只做一次隐空间跟踪步加一次参数重建，非常高效。但关键在于，这个隐状态空间表示——包括提升映射和隐动态参数——并不是预先已知的，而是通过离线元学习从多条非平稳训练轨迹中学到的。作者把隐状态空间模型的各个组件当作在线适应过程的元可学习超参数，用离线轨迹端到端地优化它们，使得扩展卡尔曼滤波在线学习器在分布偏移下表现最好。这就相当于元学习了一个专门为快速在线适应而定制的参数空间几何结构，让结构化的贝叶斯更新与学到的低维表示相互配合，产生快速可靠的适应。

在实验验证方面，作者在两个非平稳场景下测试了该方法：一是时变信道下的神经无线接收机在线适应，这里快速适应至关重要；二是非平稳失真下的图像分类。与现有的在线学习方法和贝叶斯滤波基线相比，该方法在适应速度、准确率和计算效率上都有显著提升，而且每个样本只需要一次低复杂度的更新步就能完成适应。这证明了适应感知的隐几何结构对于高维模型中的有效贝叶斯在线学习确实是有益的。不过，该方法也有其局限性。首先，它依赖离线非平稳轨迹来元学习隐状态空间，如果部署环境与离线轨迹的分布偏移模式差异很大，学到的隐几何可能不够通用。其次，隐空间的维度选择、动态模型的具体形式以及观测噪声协方差的建模都是设计决策，可能影响最终性能。此外，虽然扩展卡尔曼滤波计算高效，但它仍然依赖局部线性化，对于高度非线性的适应动态可能不够精确。尽管如此，这篇论文的意义在于它重新定位了贝叶斯在线学习的瓶颈，从“如何设计更好的滤波器”转向“如何学习一个适合滤波的低维动态表示”，为高维模型在非平稳环境下的快速在线适应开辟了一条新路径。
