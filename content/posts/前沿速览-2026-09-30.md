## 大模型 LLM

### [Raven: The Harness of Harnesses for Composable Agentic Intelligence](https://arxiv.org/abs/2609.33439)
`评分4 · HF 452赞`

Raven 要解决的核心问题是：当 LLM 智能体从单一领域任务走向长周期、跨领域工作流时，单个 harness（即围绕模型构建的工具接口、上下文管理、技能、执行策略与恢复机制的总和）既难以手工扩展，又因深度绑定特定领域而缺乏通用性。过去的方法要么为每个领域单独打磨一个更强的 harness，要么用固定的多智能体角色分工来拼凑能力，但前者无法跨模型和跨领域规模化，后者则受限于任务结构、局部能力与协调开销——多智能体失败分析反复指出，智能体之间的语义错位和任务验证不足是常见病根。更根本的是，在共享资源预算下，单个智能体或简单路由都无法保证覆盖需要多种局部契约协同才能完成的任务族，因为路由只按整个请求选一个执行者，而真实工作流往往需要在一次请求内部调用多个互补的局部能力。Raven 的动机就是把这个中心问题从“如何为某个领域造一个更强的 harness”扭转为“如何自动构建、通过经验改进、并跨领域编排多个专用 harness”。

Raven 的关键洞察是把每一个可执行的“模型–harness 对”当作智能的组合单元，而不是把模型本身当作单元。它设计了一个 Host Agent 作为编排中枢：先把用户目标分解成子任务，再根据 agent registry 中登记的能力把子任务匹配到具体执行者，并用有向无环图（DAG）显式表示子任务之间的依赖——节点是一次 worker 调用，边是产物交接，运行时先检查计划再调度就绪节点，记录产物用于交接和复用，并处理异常、整合交付物。每个执行者通过 execution adapter 接入共享编排接口，但保留自己的工具和内部执行策略，因此 Claude Code、Codex 等第三方智能体也能作为组合单元加入。在 harness 层面，Raven 采用模块化设计，把执行策略暴露给外部 evolver，在既定边界内修改；进化过程由诊断驱动，先分析失败，再提出候选 harness，并用冻结的任务模型评估其行为，候选 harness 还会进入 Harness Gene Bank 进行重组和门控筛选。经验复用则由三层机制支撑：host archive 保留用户上下文，EverOS 提供对过去经验的语义访问，Skill Forge 从本地技能、记忆衍生技能和 SkillHub 中检索任务相关流程，并让技能随经验自进化。理论上，Raven 把能力定义为共享资源预算下的可靠任务覆盖，并给出充分条件：当局部能力互补、交接兼容、规划与执行错误有界时，组合系统能在同一预算下解决单个可用智能体无法可靠解决的任务，且成本核算涵盖规划、协调、worker 执行、交接、运行时验证和重试。它之所以比之前的方法更好，是因为它不依赖某个万能 harness，也不把多智能体协作简化为角色对话，而是把 harness 的自动构建、经验驱动的进化、跨域编排和可复用技能统一在一个可组合的架构里，并用理论刻画了组合何时真正扩展能力边界。

在评估上，Raven 在 Multi-Agent Orchestration Benchmark（MAOB）上比较各系统在 worker 执行前提出的 DAG 与参考图，用四个图指标衡量专家选择和依赖预测，在两种测试 backbone 下均排名第一，Exact Match 分别比最强基线高 10.4 和 10.5 个百分点。领域评估覆盖 Raven-Research、Raven-Code、Raven-Design、Raven-Oncall 四个原生专家，HarnessBank 实验用冻结 backbone 验证进化方法，SkillCorpus 实验显示 curated skill library 在三个 benchmark 上提升 Raven，其中两个提升幅度大于 OpenClaw。局限也很明确：理论给出的是充分条件，实际适用性取决于实现的 agent 和 host 是否满足这些条件；组合的收益仍受任务结构、局部能力与协调成本约束；评估虽然覆盖编排、专家执行、harness 适应和技能复用，但每个维度相对独立，长期跨域工作流中的累积可靠性和真实部署成本仍需更多验证。对方向的影响在于，Raven 把“harness 工程”从手工活变成了可进化、可组合、可编排的系统问题，并给出了一个可检验的理论框架，后续工作可以围绕更紧的可靠性边界、更低协调开销的编排策略以及跨组织 agent 生态的互操作标准展开。

### [LLMs are General Asynchronous Agents](https://arxiv.org/abs/2609.35427)
`评分4 · HF 59赞`

这篇论文要解决的核心问题是：当前的大语言模型智能体虽然能力越来越强，但它们本质上都遵循“读取—思考—回复或调用工具—重复”这种串行交互循环，而现实世界中大量场景并非串行——语音助手需要边听边想并处理打断、具身智能体要在执行动作时对突发状况做出反应、监控系统要在持续接收日志流的同时进行分析。现有做法是把每种并发场景当作独立的研究问题分别处理：全双工语音助手专门设计双工架构，流式视频理解训练轻量级“探针”来决定跳帧，VLA模型采用双 actor-thinker 结构来兼顾反应与思考，编程助手则通过异步函数调用或并行子智能体来支持中途干预。这些方案各自有效，但都需要针对特定任务设计专门的推理软件、通信机制，甚至需要昂贵的微调，无法泛化到新的并发场景。作者提出的假设是：现代大语言模型在训练中已经学会了模仿人类推理，而人类天然具备异步处理连续信息流的能力，因此只要给出合适的框架，LLM或许也能在没有任务特定训练的情况下表现出通用的异步性。

核心方法叫 AsyncLLM，它把 Python asyncio 的 async/await 编程模型扩展到了 LLM 推理上。开发者（或智能体自身）可以定义多个异步协程，每个协程独立执行 LLM 前向推理，并通过“缓存块”（CacheBlock）进行通信。每个缓存块存储一段连续 token 的模型内部记忆状态，对现代混合 Transformer 来说包括注意力层的 KV 缓存和 Gated Delta Network 的循环状态。关键在于“缓存视图”（cache view）机制：一次前向推理虽然只写入一个缓存块，但可以同时“看到”任意多个其他缓存块，数学上等价于按顺序编码这些块中的所有 token 后做注意力，但不需要真正重新排列或重新编码。比如论文中的例子，一个“思考者”协程把推理过程写入自己的块，一个“写作者”协程通过缓存视图同时看到问题块和思考块，实时总结进展——两者之间不传递 token，只通过共享记忆状态通信，因此同步是瞬时的。为了让这种多块注意力在 GPU 上高效执行，作者扩展了 Rodionov 等人关于 RoPE 注意力缓存操作的工作：不旋转历史 KV 块，而是只旋转当前查询向量，使其相对于每个缓存块的位置正确，从而避免每次前向传播都重排全部历史 KV。推理引擎会自动把不同协程的并发请求分组到同一批次做 GPU 推理，每个协程对相同的底层缓存块持有自己的视图。此外，框架还支持用 asyncio 的 Event、Lock、Queue 等原语来表达对外部信号的响应，比如视频流中的事件探针触发后台思考协程、多个事件描述协程用锁来安全地合并报告。

实验方面，作者用同一家族 Qwen 3.x 视觉语言模型，在不做任何任务特定微调的情况下，构建了三个异步智能体：流式视频理解、电子游戏环境和系统监控。结果表明这些模型能够利用 AsyncLLM 的编程模型运行异步协程，甚至能在同一个推理循环中定义和修改自己的协程——也就是说，模型不仅能被动执行预设的异步逻辑，还展现出一定的自我编排能力。不过作者也坦承这种自我修改能力目前还不够可靠，尚不能稳定使用。局限方面，框架依赖模型本身具备足够的指令遵循和推理能力来正确使用异步原语，对较弱模型可能不适用；缓存视图的并发更新虽然对 LLM 可读，但不等价于任何串行推理，其语义一致性的边界条件还需进一步研究；GPU 批处理的效率在协程数量很多、缓存块组合复杂时可能下降。总体而言，这篇工作的意义在于把“异步智能体”从一个需要逐任务定制的研究领域，推进到了可以用通用编程模型表达和执行的层面，为未来 LLM 从环境描述中自主生成自适应异步智能体提供了初步证据。

### [Omni-IO Skills: Harnessing Your Agent Omni-Native](https://arxiv.org/abs/2609.31847)
`评分3 · HF 156赞`

这篇论文要解决的是通用智能体在“生产端”能力碎片化的问题。像 Codex、Claude Code 这类智能体已经具备很强的指令遵循、长程规划、代码执行和迭代修正能力，但它们的产出面基本局限在软件与知识工作，一旦任务涉及音频、视频、3D 资产、专业文档或需要多种媒介协同交付的完整工作流，就不得不依赖外部能力并手工编排。已有的两条路线各有硬伤：一条是扩展基础模型本身，把更多模态纳入统一的自回归或混合离散-连续建模，但这会把能力增长绑定在昂贵的模型更新上，每加一种模态都要重新协调表示、目标函数、编解码器和对齐阶段；另一条是拼装专家模型和工具，虽然不用重训主模型，却留下一个更棘手的协调问题——如何选择正确的能力、表达控制与数据依赖、在工具之间搬运中间产物、隔离局部失败，并在后续轮次中复用先前输出。模型协调系统证明了智能体可以委派给模态专家而不重训底层模型，Agent Skills 也提供了可复用的过程性知识，但两者简单相加并不等于一个 Omni 工作流。真正缺失的是一层位于智能体推理核心与异构执行后端之间的“Omni 智能体 harness”，它要把散落的模型、工具和流程变成可选择、可组合、可执行、可追踪的能力。

Omni-IO Skills 的核心设计正是这层 harness，它不改动宿主智能体的推理核心，而是通过分层 Skills、标准化多模态执行接口、依赖感知编排和持久化 Asset Registry 让现有智能体变得“omni-native”。Skills 按任务粒度和组合范围分为三层：Atomic Skill 是单个可独立调用的操作，比如生成一张图；Expert Skill 面向一个具体交付物，把多个原子操作组织成完整流程，比如做一张海报需要协调素材生成和版面组装；Scenario Skill 则面向应用场景，从用户请求中判断需要哪些交付物，再协调相应的 Expert 或 Atomic Skill。所有 Skill 共享一套声明式表示，描述适用条件、所需输入、执行过程、预期输出以及与其他 Skill 的关系，输入输出按语义描述而不绑定具体提供商，这样宿主智能体无需加载底层实现细节就能检查、选择和组合。选择从任务上下文和请求交付物开始，命中应用场景就激活 Scenario Skill，请求单一专业产物可直接选 Expert Skill，自包含操作则绕过上层直接调用 Atomic Skill；随后高层 Skill 被递归展开，直到所有步骤可执行，共享输入和中间结果只表示一次而不在多个交付物间重复，终端任务成为执行图节点。关键机制是 Declare Execution Graph，它把多资产工作流表达为带依赖关系的图，独立操作可以并发调度，成功输出被注册到 Asset Registry 供下游和跨轮次复用，而执行后端可替换。底层四层架构把任务知识、工具接口、服务实现和持久化输出分开：Skill Entry 层暴露统一任务接口并展开为可执行规格，MCP Tool Service 层提供标准化的多模态理解、生成和工具操作接口，Provider and Configuration 层把能力绑定到具体提供商、模型、凭证、默认参数和回退策略，Asset Registry 层则归一化并记录中间与最终输出，使其可以脱离物理路径被引用和复用。这样一来，工作流不再绑定于某个服务或文件路径，宿主智能体只需负责它最擅长的规划和推理，多模态生产中的依赖、搬运、失败隔离和跨轮修订都由 harness 承担。

在 UniM-90 这个受控的 90 实例子集上，以 GPT-5.6 Sol 和 Claude Sonnet 5 作为两个不同的宿主智能体，Omni-IO Skills 把输入支持率从 40.00% 和 38.89% 都提升到 100%，相对 Semantic–Quality Coupled Score 分别从 26.99 和 27.82 提升到 74.94 和 77.78，提升幅度为 47.95 和 49.96 个百分点，Strict Structure Score 达到 100.00 和 99.78，两个宿主的 Lenient Structure Score 均为 100.00。更值得注意的是，加载 harness 后的绝对 SQCS 是在全部 90 个实例上测得的 74.94 和 77.78，已经超过了 Base Agents 仅在其较窄支持子集上取得的 67.49 和 71.53，这说明共享 harness 能在不同宿主上同时补齐模态与工作流缺口，并在全部实例上给出高质量响应。当前实现的 27 个 Skills 覆盖七种产物模态和 38 个代表性任务，横跨理解、生成、推理、检索四类能力族，应用领域从教育、研究延伸到营销、创意生产和软件工程。局限在于，这套系统目前仍依赖人工整理的 Skill 库和任务到 Skill 的映射，覆盖范围虽然广但并非无限，面对全新模态或高度定制化的生产流程仍需扩展 Skill；此外，Asset Registry 的跨轮复用和依赖感知编排在更复杂、更长程的工作流中的鲁棒性还有待进一步验证。不过其意义已经比较清楚：它把“能力组合”从模型内部转移到 harness 层面，证明了一条不改变宿主推理核心、通过可插拔系统层实现广泛且可演化 Omni 能力的实用路径，这对那些不想被单一模型栈锁死、又希望快速获得多模态生产能力的应用来说，提供了一种成本更低、迭代更快的选择。

### [Periodic Weak Spots: Phase Sensitivity from Chunked KV-Cache Compression](https://arxiv.org/abs/2609.36322)
`评分3 · HF 79赞`

这篇论文关注的是长上下文推理中一个被长期忽视的失效模式。随着上下文窗口不断变长，KV cache 的显存和注意力开销成为瓶颈，分块压缩（chunked KV-cache compression）因此成为主流方案：它按固定步长把连续若干 token 的 KV 条目压缩成更少的缓存项，从而降低内存与计算成本。但作者指出，这种压缩在带来效率的同时，也悄悄引入了一个新的位置坐标——phase，即某个 token 相对于压缩窗口边界的位置。问题在于，同一个信息在某个 phase 下可能很容易被检索到，在另一个 phase 下却很难，而且这种差异不是随机的，而是随 phase 周期性波动。作者把这种现象称为 phase sensitivity（相位敏感性）。在最强的开源大模型上，长上下文检索准确率在不同 phase 之间可以相差高达 40 个百分点，这意味着平均 benchmark 分数完全可能掩盖掉系统性的“周期性弱点”。换句话说，模型在某些相位上存在稳定的检索盲区，而传统评测只看平均值，根本发现不了。

为了搞清楚这个现象从何而来，作者没有停留在对现成模型的观察上，而是从头预训练了一族 transformer，覆盖多种不同的 KV 压缩设计，结果在多个变体上都复现了 phase sensitivity，说明这不是某个实现细节的偶然产物，而是分块压缩这一机制本身带来的结构性效应。接着，他们用因果干预做机制分析，发现了一种 phase specialization（相位特化）现象：不同的注意力组件在检索不同源相位的信息时，贡献是不对称的。也就是说，模型内部并没有均匀地处理所有相位，而是让某些注意力头或通道专门负责某些相位的信息。作者还进一步分析了理想化的检索模型，从梯度流动力学的角度解释了为什么训练过程会倾向于产生这种尖锐的相位特化——简单说，梯度更新会奖励那些在特定相位上专精的组件，而不是让所有组件平均分担所有相位。这就解释了为什么平均准确率可以很高，但某些相位上却系统性失败：模型把资源集中到了部分相位上，牺牲了另一些相位。

在结果层面，作者的核心贡献不只是报告了 40 个百分点的相位间差距，而是证明了这种差距在多种压缩方案和从头训练的模型中稳定存在，并且通过因果干预把现象追溯到了具体的注意力组件和训练动力学。这带来一个直接的评测含义：对于使用分块 KV 压缩的模型，必须按压缩相位分别测量检索性能，否则高平均分可能掩盖系统性的位置失效。当然，论文也有局限：它主要基于从头预训练的小规模模型和理想化分析，尚未在大规模生产模型上完整验证相位特化的具体回路；同时，如何设计一种既保持压缩效率又消除相位敏感性的压缩方案，仍然是一个开放问题。但无论如何，这项工作把“相位”从一个被忽略的实现细节提升为长上下文压缩评测中必须正视的一维，对后续的 KV 压缩设计、注意力机制分析和长上下文 benchmark 构建都有直接的方法论影响。

### [Follow the Entities: A Corpus Map for Agentic Search](https://arxiv.org/abs/2609.37226)
`评分3 · HF 68赞`

这篇论文要解决的是大语言模型智能体在大型文档集合上做问答和任务执行时的一个真实痛点：答案所需的证据往往分散在多个文档里，比如一个项目的审批记录在邮件里、需求在运维文档里、最新状态在项目追踪系统里、最终决策在会议纪要里，单看任何一份都不够，而且这些文档之间的关联通常不会在任何一份文档里被显式写出来。传统的检索增强生成只做一次性的 top-k 检索，把文档当成彼此独立的条目打分，丢弃了文档间的结构信息；GraphRAG、HippoRAG 这类图方法虽然构建了实体关系图，但这个图只服务于检索器，生成答案的模型拿到的仍是一次性选定的固定上下文，检索漏掉的文档它永远够不着。近年来的 agentic search 让智能体用 shell 命令直接多轮搜索整个语料，不再受限于初始检索，但语料本身仍是一堆扁平的文件，一份相关文档不会告诉你它和其他文档是什么关系，于是智能体每遇到一个新问题都得重新搜索、重新阅读、重新推理出这些关系，既容易漏掉互补证据，又反复消耗大量 token。作者的关键观察是：不同查询需要的关系子集不同，但关系本身——比如哪些文档在谈论同一个项目——是跨查询稳定的，完全可以提前识别并复用。于是他们把问题重新定义为"语料导航"，需要一个持久的导航层，既暴露可复用的跨文档结构，又保留对完整语料的访问。

CorpusMap 的核心设计是把语料组织成一张以实体为中心的二分图。它先离线地从语料本身归纳出一个实体类型目录，因为哪些类型的实体值得抽取是因语料而异的，没法预先穷举，所以用 LLM 从若干小规模采样文档中提出候选目录，再综合、验证、修订成最终目录，固定下来供后续阶段使用。接着做实体抽取，依据目录和文档上下文识别实体提及，并把同一文档内指代同一对象的提及归并成文档局部实体。然后是关键的实体消解阶段：先把每个抽取出的名字在其源文本中出现的位置做 grounding，再逐个文档地把局部实体对一个初始为空的共享注册表做解析，对每个局部实体检索可能的注册表条目，权衡当前文档与候选证据，决定是链接到已有条目、新增一个实体、还是标记为未解决；只有链接和新增会记录实体-文档的连边，未解决的不产生任何边。最后是渲染阶段，只保留至少链接了两份文档的跨文档实体，因为只有这些才提供可复用的导航路径，把每个保留实体的文档邻域渲染成一个 Entity Page，页面里包含简要概述、每条都标注来源文档的关键事实、该实体的各种别名、以及指向邻域内所有文档的链接。这些页面和原始文档一起以文件形式存放，Entity Page 里列出所链接文档的文件路径，于是智能体可以用和搜原始语料完全相同的工具去读和搜这张地图。推理时，智能体除了收到问题，还会收到与问题相关的 Entity Page 所链接文档的路径作为候选，自行决定读哪些；它既可以从一个页面顺着链接去读列出的文件，也可以从一份文档反向搜出哪些页面列出了它。这个设计之所以比之前的方法好，在于它把关系的发现从推理时前移到了离线构建时，跨查询共享，而且 Entity Pages 是叠加在语料之上而非替换语料，原始文档始终可访问。相比 LLM 维护的 wiki 需要模型自行决定什么成为页面、内容如何合并且随语料增长会退化，相比把文档分到少数主题分支的层级技能树会把同一主题跨来源的证据拆散，实体作为锚点天然允许一份文档同时属于多个邻域，从而把原本被割裂的互补证据重新连起来。值得一提的是，抽取、消解、渲染三个阶段既可以用 LLM 实例化，也可以用现成的确定性替代方案，甚至不用 LLM 也能构建，并且能随语料增长增量更新。

实验在三个需要跨文档证据的基准上验证：EnterpriseRAG-Bench 的 80 个纯多文档问题、WixQA 的 79 个多文档问题、HERB 的 238 个基于内容的问题，语料分别是 2819、6365 和 6221 篇文档，且都包含全部金标文档。评估沿三个轴：答案质量（正确性、完整性、事实性、内容）、检索质量（文档召回和上下文召回）、效率（每个问题整条智能体轨迹累计的输入 token）。对比对象包括 Raw Corpus 以及四种用不同单元组织同一语料的导航层——Document Page、Group Page、LLM Wiki 和 Corpus2Skill，所有方法下原始文档都对智能体可访问。用 7 个不同模型测试的结果显示，CorpusMap 在证据发现和答案质量上一致优于原始语料的 agentic search 和这些替代导航层，整体质量提升 6.4 到 11.7 分，同时平均少用 34% 到 57% 的输入 token。它的局限在于只保留至少出现在两份文档中的跨文档实体，那些只在一份文档里出现但对某个查询至关重要的实体不会进入地图，只能靠原始搜索兜底；实体消解的质量直接决定图的质量，消解错误会把不相关的文档连到一起或漏掉本该连上的边；此外实体类型目录的归纳依赖采样文档的代表性，语料分布偏移时可能需要重建。尽管如此，这项工作指出的方向是有启发性的：与其只优化智能体怎么搜，不如改进语料本身如何被组织，让跨查询稳定的结构被提前显式化并复用，这对在持续增长的大规模文档集合上运行的智能体来说，可能是一条比单纯改进搜索策略更有杠杆的路径。

### [Imagine3D-LLM: Teaching MLLMs to Imagine 3D Scenes Before Answering](https://arxiv.org/abs/2609.38177)
`评分3 · NeurIPS 2026; Project Page: https://cvlab-kaist.github.io/Im`

多视图三维推理一直是多模态大模型的一个软肋：单张图像的理解已经做得相当好，但一旦要求模型跨视角整合证据、形成一致的三维理解，性能就明显掉下来。现有两条主流补救路线各有问题。一条是往模型里塞像素级的三维信号，比如把点云坐标编码进 patch 特征、在图像上画显式标记、用精确对应关系做蒸馏、或者设计跨视角重建的预训练任务，逼模型对齐重叠内容；另一条是把 MLLM 的图像特征与 CUT3R、VGGT 这类三维重建基础模型的稠密几何特征融合。这两类方法本质上都在追求“细粒度、像素级精确”的三维线索，但实验表明它们带来的提升相当有限。作者由此提出一个反问：人类做三维推理时真的需要像素级精确的几何吗？认知研究给出的答案是否定的——人看几张图时，并不会在脑中维持逐像素对应或稠密深度图，而是先认出跨视角重复出现的物体，用这些物体当锚点推断视角之间的粗略相对关系，再在脑中拼出一个紧凑的、物体级的三维布局。也就是说，支撑人类下游推理的内部表示是近似的、抽象的、物体级的，而不是像素精确的。这篇论文的动机就是把这个洞察搬进 MLLM：与其告诉模型像素级的几何，不如让模型自己“想象”出一个紧凑的三维场景。

方法上的核心设计是一组可学习的 Gaussian summary token。具体来说，在多视角 MLLM 的标准流程里，视觉编码器先对每帧独立提 patch 特征，经投影器映射到语言模型嵌入空间，得到每帧的视觉 token，K 帧拼起来就是整段视觉 token 序列，后面接文本 token。Imagine3D-LLM 在这段视觉 token 之后、文本 token 之前，插入 M 个可学习的 summary token，它们通过标准的因果自注意力去“读取”全部图像 token，主动挑选出重建场景所需的信息。关键约束是 M 远小于图像 token 总数，这个信息瓶颈逼着模型不能给每个 patch 分配一个 token 去简单复制二维内容，而必须把跨视角重叠的内容合并到同一组 token 上，于是模型被迫去判断哪些物体在多视角中反复出现、它们如何拼进统一的三维布局，从而自发涌现出物体级的聚类分组。这些 summary token 在 LLM 中间层的隐状态被取出，经一个轻量 MLP 头解码成三维高斯泼溅（3DGS）基元，每个 token 解码 G 个高斯，每个高斯带三维中心、不透明度、协方差和球谐颜色系数，整组高斯可用可微光栅化渲染成新视角图像。训练时有两个损失：一是标准的下一 token 预测语言建模损失，二是把解码出的高斯在输入视角渲染出来、与真实帧做光度重建的损失，两者加权联合优化。这里有两个值得注意的细节：其一，高斯不是直接从图像特征预测的，而是从专门的 summary token 预测，防止模型走捷径把二维图像内容原样贴成与图像对齐的高斯；其二，纯光度监督收敛极慢，因为前馈 3DGS 估计器通常要训几十万步，于是作者引入 ZipSplat 这个预训练的紧凑高斯估计器做教师，把它的场景表示蒸馏进 LLM，大幅加速收敛。最反直觉也最有价值的发现是：虽然只有 summary token 直接接受重建监督，但 LLM 自身的图像特征也变得更“懂三维”了——对应位置的注意力更锐利，PCA 可视化显示图像特征在语义上更有组织，同一物体在不同视角下被一致地编码。这说明“要求模型推断场景底层结构”这件事会把三维感知信号反向传播到整个模型，重塑其内部表示为连贯的、以物体为中心的三维理解。

实验在七个空间推理与三维场景理解基准上展开，Imagine3D-LLM 一致超过此前方法，包括那些注入像素级三维信号或融合三维基础模型特征的方案，验证了“先想象场景再回答”比“被告知像素级几何”更有效。这个结果的意义不只是刷点，而是提出了一种新的归纳偏置：抽象的场景重建本身就能作为构建三维感知 MLLM 的有力手段，而且它不需要额外的三维输入模态、不需要逐场景优化，单个通用模型就能通过自然语言处理多种任务。局限方面，论文没有回避纯光度监督收敛慢的问题，必须依赖 ZipSplat 这样的教师蒸馏才能实用，这意味着方法对教师模型的质量和可用性有依赖；此外紧凑高斯表示毕竟是有损的，对需要极精细几何的任务（比如精确测量、薄结构重建）可能力不从心，而论文的评测集中在空间推理和场景理解，尚未充分覆盖这类场景。对方向的影响在于，它把“让 MLLM 自己生成三维表示并以此条件化回答”这条路线立了起来，后续工作可能会探索更强的重建监督、更优的 token 瓶颈设计，或者把这种“想象再回答”的范式推广到视频、具身等更动态的三维任务上。

### [Pretraining Latent Information Feedback Transformers with Teacher Supervision](https://arxiv.org/abs/2609.38149)
`评分3`

Transformer语言模型本质上是前馈的：深层表示永远不会回传到浅层，跨生成步骤向下流动信息的唯一通道就是解码出的token。这个通道极其狭窄，一个token最多携带log₂|V|比特的信息，对于十万词表大约只有17比特。这导致三个具体问题：模型必须在浅层重新计算本可以在深层完成的结果，否则就会失败——比如多跳查询中第一跳解决得太晚，后续层来不及完成第二跳，而把深层表示回传到浅层可以修正高达66%的这类失败；模型无法在生成时保留多个备选延续，只能被迫采样一个token，而在图可达性任务中，同时持有多个搜索路径的连续思维能让两层Transformer用与图直径相同的步数找到答案，而非沿单条路径走需要平方级更多的步数；计算深度无法随序列增长，这对于状态跟踪这类顺序步骤随输入增长的任务是致命的，固定深度的Transformer在理论上就无法解决。此前的工作试图在事后训练阶段缓解这个问题，教模型生成推理轨迹的压缩表示，推理时传播连续隐状态而非单个token，但这类方法需要昂贵的顺序隐状态展开，且可能不足以让模型适应这种新的连续表示输入分布。另一类工作用Jacobi式迭代近似全递归，通过多次前向传播并行更新位置，但存在固有的质量-效率权衡：更好的近似需要更多迭代和更多训练成本。核心问题于是变成：能否在预训练阶段就教会语言模型利用这种深层到浅层的反馈，同时避免顺序处理带来的不可行训练开销。

LIFT的核心洞察是把递归状态学习转化为一个教师强制的预测问题。具体来说，每个输入token都配对一个信息密集的状态，这个状态来自一个现成预训练语言模型的下一token分布，经过top-k截断和温度重归一化后得到，最多有k个非零项。模型被扩展一个融合层，接收token嵌入和状态的投影均值，通过SwiGLU块融合后送入标准Transformer堆栈，训练目标是同时预测下一个token和下一个状态。关键设计在于：状态来自外部教师的下一token分布而非隐层表示，因为分布在任何共享分词器的两个模型之间都处于同一空间，坐标对应token概率，预测它是一个成熟的目标，而隐层表示在不同模型间没有共享坐标，学生回归到另一个模型的内部表示既不对齐也更难预测。训练时教师冻结，所有状态预先并行计算，因此预训练保持完全并行，不传播梯度到教师。推理时模型用自己的预测状态反馈，计算开销很小且随模型规模增大而递减。为了缓解训练用教师状态、推理用自身状态之间的分布偏移，训练目标中加入了一个状态对齐项，用前向KL散度衡量学生状态与教师状态的差异，并在最后10%的训练中丢弃教师和对齐项，让模型适应自身状态。此外还采用前缀状态丢弃，以一定概率将训练序列的状态替换为学习到的偏置向量，使模型学会在有状态和无状态两种模式下运行，从而支持推理时的并行预填充。

在S₅置换组合这个NC¹完全的状态跟踪任务上，两层LIFT模型即使状态来自一个本身在该长度上失败的Transformer教师（仅3%准确率），也能在12步序列上达到100%准确率，而同样深度的普通Transformer在N≥12时完全失败。在135M到1B参数的预训练实验中，LIFT在token匹配预算下始终优于标准Transformer以及蒸馏和Jacobi迭代反馈基线，在计算匹配设置下也不落后或领先。最大的增益出现在程序性任务上，如多操作数算术和模式延续，LIFT在每个规模上都匹配或超过用2倍token训练的Transformer。1B模型在100B token上训练，约为Chinchilla预算的5倍。局限方面，推理时状态反馈使输入处理变为顺序，虽然开销小但确实存在；状态对齐和自身状态适应阶段增加了训练复杂度；教师状态的质量仍然影响最终性能上限。这项工作的意义在于首次证明了Transformer语言模型可以通过高效、完全并行的教师强制状态预训练来学会利用深层到浅层的反馈，为突破前馈架构的信息流瓶颈提供了一条可扩展的路径。

### [Learning Meta-Skills for Agent Harness Design in Test-Time AI4AI](https://arxiv.org/abs/2609.38143)

这篇论文要解决的核心问题是：在不更新任何模型权重的前提下，如何让一个作为“构建者”的AI学会为另一个作为“执行者”的AI搭建更好的工作环境，从而提升后者的任务表现。这个问题的现实动机来自一个类比——一个能力很强的博士生可能因为实验配置和结果散落在各种脚本和笔记里而浪费大量时间重复劳动，而一位好的导师能通过建立共享实验日志、可复现工具和清晰的验证流程来解除这个瓶颈，让学生把精力集中在科学判断上。论文把这种“导师”角色形式化为Builder，把“学生”角色形式化为Target，研究的是测试时的AI-for-AI场景。此前的方法要么直接给Target灌输任务技能（告诉它怎么做题），要么让Builder在没有任何经验积累的情况下凭空搭建环境，结果都不理想：直接给Target技能的效果有限，因为声明性的建议需要Target在推理时自行解读和落地，负担很重；而无技能的Builder虽然具备搭建能力，却不知道该搭什么、为什么搭，只能盲目尝试。论文的关键洞察是：Builder需要的不是任务技能，而是一套关于“何时需要支持、提供什么资源、Target该如何使用这些资源”的可复用原则，作者称之为元技能。

元技能被定义为一个三元组：when字段识别需要支持的可观察条件，provide字段指定环境应当提供的能力或资源，use字段说明Target应如何使用该支持以及哪些判断仍由Target自己负责。整个学习流程是一个“构建—执行—反思”的闭环：从一个空的元技能库开始，Builder针对每个开发任务用当前技能库搭建一个包含指令、资源与可执行机制的harness，Target在其中执行并产生公开的执行记录和基准原生分数，Builder随后审视自己生成的程序和Target的执行反馈，判断是否存在一个可被更好支持所解决的反复出现的错误或负担，然后决定是修订已有元技能、新增一条元技能、还是保持不变——每个批次最多只允许一次新增或修订，且必须引用该批次中的证据，以保证学到的原则扎根于实际观察到的行为。经过两轮开发集迭代后，技能库被冻结，用于测试时对每个未见任务重新搭建harness。测试时有两种技能供给模式：全量库把所有元技能放入Builder上下文，检索模式则用BM25从任务初始提示中选出最多两条正相关技能。Builder可操作的harness组件涵盖七大类：指令、记忆、上下文组织、组合工具、执行控制、验证与恢复、工作区准备。关键之处在于，Builder把一条声明性的元技能翻译成持久状态、可执行工具、验证逻辑或控制决策，例如当一条元技能指出“工件在验证后被编辑会导致先前检查过时”，Builder就会实现文件版本记忆和重新验证工具，而Target只需在提交前检查当前验证结果，内容判断仍由自己负责。这解释了为什么它比之前的方法更好：同样的元技能库直接交给Target时，Target必须在推理时自行解读并正确应用，而交给Builder时，Builder可以把它操作化为环境中的具体机制，大幅降低Target的认知负担。实验中也验证了这一点——全量库交给Builder比直接交给Target平均高出12.02个百分点，在六个设置中全部胜出，最大差距达到25.43个百分点。

在Harness-Bench和NewtonBench两个基准上，使用GPT-5.6-Sol作为Builder，分别以Gemini-3.6-Flash、Qwen3.8-Flash和GPT-OSS-120B作为Target，全量元技能库的Builder取得了65.31%的宏平均分，比无技能Builder高8.95个百分点，比独立学习并直接提供给Target的结构化任务技能高10.93个百分点。分基准看，NewtonBench上的平均增益为10.96个百分点，高于Harness-Bench的6.95个百分点，说明当失败模式在不同任务和Target之间反复出现时，积累的经验最有价值——NewtonBench需要协调实验、推理和符号提交，协调瓶颈突出，而Harness-Bench的工作流更异质，有效支持更依赖Target自身的规划和工具使用。全量库在六个设置中的五个优于BM25 top-2检索，NewtonBench上平均高出7.19个百分点，说明紧凑的元技能库中存在互补程序，词法检索可能遗漏它们的联合价值。分析还发现，教学行为可能延迟出现：在NewtonBench上第一轮开发集迭代对分数的影响不到1.1个百分点，而第二轮为Gemini和Qwen分别带来13.01和12.33个百分点的提升，两轮平均增益10.42个百分点。当Builder和Target是同一个模型时，元技能在三个设置中平均带来18.71个百分点的提升，暗示了一条系统级自我改进的路径——模型可以通过学习为自己搭建更好的支持来提升自身执行能力。局限方面，全量库并非在所有设置中都优于检索，有一个设置例外，说明更广泛的技能访问不一定普遍有益，需要能同时考虑技能互补性和Target对支持可能反应的检索方法；此外增益在不同Target和基准间波动，积累的指导必须适配具体Target和任务而非假设普遍有用。论文的意义在于把AI4AI的目标从“教Target解题”拓展到“教Builder成为更好的导师”，提出了一条通过改善环境构建来实现系统级自我改进的路径，对agent学习和测试时自适应方向都有启发。

### [AdviSD: Learning to Advise Frontier LLMs via Targeted Multi-Turn Self-Distillation](https://arxiv.org/abs/2609.38142)
`评分3`

这篇论文要解决的核心问题是：当一个小模型（advisor）通过自然语言建议去引导一个冻结的大模型（executor）完成任务时，如何训练这个 advisor 才能让它真正提升执行效果，而不是仅仅学会模仿反馈中的修正建议。之前的方法主要有两条路线：一是用任务奖励做强化学习（如 advisor-GRPO），但回合级别的奖励只告诉 advisor 整体做得好不好，并不指出具体哪个决策该改、该怎么改；二是反馈条件自蒸馏，让一个能看到完整交互反馈的教师模型去监督只能看到原始上下文的 student advisor。问题在于，advisor 输出的建议是通过另一个模型（executor）起作用的，一条看起来合理的修正建议未必能改变 executor 的行为。论文举了一个很具体的例子：executor 本身就会可靠地搜索航班，但有时会猜错乘客 ID 导致订票失败；反思可能同时提出“查一下乘客 ID 再订票”和“把航班搜索步骤写得更详细”两条修正，前者真正解决了错误，后者只是重复了 executor 已经会做的事。如果 advisor 从后者也学习，由于参数共享，这种冗余监督会污染 advisor 在其他场景下的决策。论文进一步用理论证明：在共享参数模型下，如果那些“无论怎么建议 executor 行为都一样”的失败案例所提供的教师目标对有用建议的偏好更弱，那么随着有用建议让可预防失败越来越少、这类无效失败占比越来越高，学习会被逐渐拖向一个次优的均衡点；只有对这类修正进行差异化降采样，才能提高最终性能上限。

AdviSD 的关键设计在于把“提出修正”和“选择在哪里学习”拆开。训练时，外部 reflector 根据 executor 的响应、工具返回结果和任务检查，在每个不完美回合中标记出最多若干个值得修正的建议决策点。然后，advisor 自己对同一条已记录的 executor 响应做两次打分：一次在包含它当时发出的建议的上下文里，一次在不包含该建议的上下文里，两次打分的差值幅度反映了这条建议对 executor 实际行为的预测影响有多大。这个配对打分完全由 pre-update advisor 完成，不需要 executor 的似然度，也不需要额外跑 executor rollout。选择规则就是用这个差值幅度来决定哪些决策点值得被监督——差值大说明建议确实改变了 advisor 对 executor 行为的预期，差值小则说明这条建议可能无关痛痒。被选中的决策点上，一个反馈条件化的 pre-update advisor 副本作为教师，去监督当前可训练 advisor 的下一 token 分布，而 GRPO 的回合级优势值保持不变。这样，AdviSD 既保留了结果奖励提供的全局信号，又通过自蒸馏在关键决策点上注入了更细粒度的反馈信息，同时避免了从无效修正中学习。部署时，reflector 和配对打分都不再需要，advisor 只需在每个 executor 回合前决定给建议还是弃权。

实验用 Qwen3-8B 作为 advisor，分别驱动 Gemini 和 Claude 作为 executor。在 BFCL-v3 上，AdviSD 比 advisor-GRPO 高出 4.2 到 6.4 个百分点；在 EnvScaler 上高出 3.9 到 5.1 分。更重要的是，它比“匹配数量的随机选择”还高出 2.5 到 4.9 分，这说明收益不只是来自减少了监督量，而是来自选对了监督的位置。AdviSD 训练出的 advisor 还能零样本泛化到域外任务，比单独执行 executor 的宏平均高出 2.7 到 3.6 分，并且能跨 executor 版本和模型家族迁移，跨家族双向迁移时比迁移后的 GRPO 还高 3.1 分。局限方面，论文的理论分析建立在简化模型上，假设教师偏好和 executor 行为在训练中固定，实际场景中这些可能漂移；配对打分依赖 advisor 自身对 executor 响应的预测能力，如果 advisor 对 executor 的行为建模很差，选择信号可能失真；此外 reflector 的质量也会影响可修正决策点的召回。总体而言，这篇工作把“从反馈中学习”从“拟合教师”推进到了“选择性地拟合教师”，为冻结大模型的外部适配提供了一个有理论支撑、可操作且迁移性强的训练范式。

### [LongHarness Bench: Stress-Testing Language Model Harnesses for Long-Context Reasoning](https://arxiv.org/abs/2609.38137)
`评分3`

这篇论文要解决的是长上下文推理评测中一个被长期忽视的盲区：现有的长上下文基准已经无法有效区分不同 LM harness（语言模型外层控制框架）的优劣。所谓 harness，指的是包裹在基座模型外面的控制层，负责管理上下文、工具调用和交互序列，比如 OpenCode、mini-swe-agent、RLM、ReAct 都属于此类。它们通过搜索、上下文切片、工具使用和额外模型调用来扩展模型处理长文本的能力，代价是消耗更多计算。问题在于，LongBench-v2、HELMET 这类基准的任务偏向"召回"——找到少量相关信息再做几步推理即可，harness 的策略适应性几乎用不上；而 LongProc 和 Oolong-Synth 虽然处理量很大，但前者给出了详细流程只需忠实执行，后者可以用通用的"分而治之"策略（逐条独立分类再聚合）解决，都不需要根据中间结论动态调整检索策略。结果是强模型加不同 harness 的准确率趋于饱和、彼此拉不开差距，同时准确率本身也完全无法反映计算成本的巨大差异——同一个基座模型在不同 harness 下可能准确率相近，实际消耗却相差一个数量级。这就使得"该选哪个 harness"这个问题既无法用准确率回答，也无法用成本回答，评测本身失去了指导意义。

LongHarness 的核心设计思路是：构造一批任务，让检索策略和推理过程深度耦合，同时天然存在多条计算代价不同的解法，从而把准确率和效率同时变成可区分的评测维度。它包含四个任务。约束求解搜索给出约 12 万 token、关于 160 个人的文档，要求找出同时满足三到五个条件的恰好五个人；关键在于条件有"选择性"之分——某个条件只有极少数人满足，先查这个条件就能把候选集大幅缩小，再逐一验证其余条件，而穷举式地对每个人检查每个条件虽然也能做对，检索和推理量却高得多，且题目故意不告诉你哪个条件更具选择性。等价程序对搜索给出约 10 万 token、200 个 Python 程序，要求找出所有行为等价的程序对，但函数语句和可见的输入输出样例被删去，每个正确实现周围环绕着行为不同却看似解决同类问题的变异体，因此"长得像"反而可能是错的；高效策略是先推断每个程序意图、分组候选，再用有区分力的输入剔除近邻，而非两两比较全部程序对。程序执行追踪要求从 320 条打乱的 Python 计算记录中复原一个八步查询程序的结果，每一步都要找到函数语义等价且调用输入匹配的记录，前一步的输出决定后一步的搜索键，因此检索是逐步依赖的；高效做法是把已恢复的输出当作下一步的搜索键并复用已有计算结果，而不是重新计算每一步，但一旦匹配错误，后续搜索键会被带偏，整条追踪链都会走错。离群备忘录检测给出 700 条备忘录、2500 条关于人物组织及其关系的陈述，其中恰好 15 条包含与别处关系相矛盾的断言，但矛盾在单条备忘录内部不可见，必须跨多条组合才能发现；高效策略是一次读完、把陈述组织成可复用的关系表或图，再对每个派生断言做组合检查，低效策略则对每条可疑断言单独检索证据，反复重读同样的备忘录，还可能漏掉只有组合后才显现的矛盾。这四个任务共同的技术要点是：检索必须混合词法搜索（靠实体名定位段落）和语义匹配（"喜欢水果"要能匹配到"对西瓜的偏爱"），中间发现必须能改变下一步检索什么，且存在选择性搜索与结果复用这类明显更省的替代路径。评测协议上，每个实例给 300 万 token 的累计输入输出预算，四个任务分别用精确匹配打分，成本按 API 费率估算。

实验结果给出了几个有分量的数字。最强配置 GPT-5.6-sol 加 mini-swe-agent 在四个任务上的宏平均准确率只有 68%，最强的非 GPT 配置 GLM-5.3 加 mini-swe-agent 是 42.5%，Kimi-K2.6 从未超过 1.5%，说明基准对当前模型-harness 组合仍有相当难度，且没有任何一个 harness 在四个任务上全面领先。效率差异非常刺眼：在程序执行追踪上，GPT-5.6-sol 直接推理和 OpenCode 分别达到 94% 和 96% 的准确率，但输入 token 是 0.121M 对 1.29M，单实例成本 0.648 美元对 1.37 美元；在约束求解搜索上，直接推理 58% 花费 0.690 美元，OpenCode 56% 却要 1.72 美元。更值得注意的是 harness 与模型的交互并不单调：对 GPT-5.6-sol，OpenCode 把程序执行追踪从 94% 提到 96%，却把离群备忘录检测从 44% 砸到 10%、等价程序对搜索从 44% 砸到 0%；mini-swe-agent 靠把离群备忘录检测从 44% 拉到 100% 拿到最高宏平均 68%，同时把约束求解搜索从 58% 降到 42%。论文还观察到基座模型越弱、harness 带来的增益通常越大，而失败模式集中在无法复用证据、无法验证候选、无法在预算内收敛到答案。局限方面，等价程序对的判定标准是"两者都通过原题测试"，这并不构成对所有输入的真正等价性证明，答案键本身带有近似性；成本是按特定 API 费率估算的，换供应商或换硬件结论可能偏移；四个任务虽然覆盖了检索与推理的不同组合，但仍是合成构造的，向真实长文档场景的迁移性有待验证。尽管如此，这项工作把"效率"正式确立为长上下文评测的一等维度，并提供了一个可以检验 harness 是否在"策略性地处理上下文而非穷举式地处理"的试验台，对后续设计能主动缩小搜索空间、复用中间结果、按需分配算力的 harness 有明确的指向意义。

### [How Local Mixing Encodes Relative Position in Global NoPE Attention](https://arxiv.org/abs/2609.38109)
`评分3`

这篇论文要解决的是一个在大模型架构演进中冒出来的真实困惑：既然自注意力本身对位置完全不敏感，为什么把滑动窗口注意力（SWA）或门控线性注意力这类局部混合层，与完全不做位置编码的全局注意力层（NoPE）交错堆叠起来，模型依然能正常工作、甚至还能更好地外推到长序列？过去大家默认位置编码是必需品，RoPE 这类显式相对位置编码几乎成了标配，但它有计算开销，而且一旦序列长度超出训练分布，性能就迅速崩塌。NoPE 虽然外推性更好，却在同分布内表现不如显式编码。后来 Kimi、Qwen 等大模型开始用「局部层 + 全局 NoPE」的混合架构，效果出奇地好，但没人真正说清楚位置信息到底藏在哪儿。此前唯一相关的研究只证明了这类混合模型不编码绝对位置，却留下一个关键空白：它们会不会其实在隐式地编码相对位置？这篇论文的核心动机就是填补这个空白，把「为什么能行」这件事从经验观察推进到机制层面的解释。

论文的关键洞察是：局部混合层会在残差流里注入一种「近因偏置」，而全局 NoPE 注意力会主动把这个偏置挑选出来当作位置信号使用。具体来说，SWA 在期望意义上近似于一个滑动平均卷积——窗口内相邻位置的输出会共享大量相同的投影值，位置越近共享越多，于是输出的余弦相似度随相对距离平滑衰减，形成一种天然的近因结构。这个结构被写进残差流后，会穿过中间的归一化和 MLP 层传播下去，最终到达全局 NoPE 注意力的 logits。关键在于，NoPE 注意力头在训练中会学到让 query 和 key 的投影矩阵去对齐这个残差流中的近因结构，从而在 logits 上复现出随距离下降的偏置，等价于一种隐式的相对位置编码。作者用滞后交叉矩矩阵来统一刻画这件事：余弦相似度只是各向同性的一个切片，而 NoPE logits 则对应残差流与 query-key 复合投影矩阵的对齐程度，两者其实是同一个相似性结构的不同投影。更妙的是，SWA 的近因偏置尺度由窗口大小决定，与总序列长度无关，所以不会像纯全局 NoPE 那样在长序列上被稀释——后者在均匀注意力假设下，位置 1000 和位置 990 的输出共享 99% 的项，位置信号几乎消失，而 SWA 在窗口内始终维持清晰的衰减轮廓。作者还推导了训练后非均匀注意力的一般情形，证明输出相似性结构是输入结构与注意力自相关的混合，窗口边界依然约束着近因偏置的作用范围。

在实验上，作者训练了 120M 和 350M 两个规模的混合模型，SWA 窗口从 64 到 4096 不等，与全局 NoPE 按 1:1 交错，用 Prolong 数据集训练、TextbookChapters 评估，并与纯全局 NoPE 基线对比。结果显示，残差流中的近因偏置在初始化时就已存在，并随训练不断增强；这种偏置在深度方向上持续存在，且能被全局 NoPE 的注意力 logits 稳定选中。窗口越小，近因偏置越陡峭；而纯全局 NoPE 基线在中等序列长度上就已经失去分辨率。作者还把结论推广到了用 KDA 替代 SWA 的混合架构。这项工作的意义在于，它第一次从理论和实证两方面说明混合架构确实在 NoPE 层隐式编码了相对位置，并且这种编码方式天然具备长度外推的潜力——因为近因偏置的尺度由局部窗口而非序列长度决定。局限也很明显：理论分析主要针对 SWA 的结构性效应，没有完全涵盖内容相关的注意力和 MLP 的复杂计算；实验规模最大到 350M，尚未验证更大模型上的行为；而且这种隐式编码能否真正支撑无限长度外推，还需要更系统的长上下文评测来确认。但无论如何，它给「如何设计能持续外推的位置编码」提供了一个新思路：与其显式加位置编码，不如让局部结构在残差流里自然生成位置信号，再由全局注意力去读取。

### [Correct Answers, Invalid Traces: What Verifiable Grade-School Math Reveals About Chain-of-Thought Traces](https://arxiv.org/abs/2609.38107)
`评分3`

这篇论文要回答的是一个在AI安全与可解释性领域被反复依赖、却极少被直接检验的假设：思维链（CoT）轨迹究竟能不能被当作模型“如何得出答案”的忠实记录。作者指出，当前主流推理模型（如DeepSeek-R1-Zero、Kimi K1.5）的后训练几乎完全依赖结果奖励——只要最终答案对，中间轨迹长什么样都无所谓，过程监督虽被提出却基本没被真正用上。问题在于，人们却习惯性地把这些自然语言轨迹读成模型的推理过程，用来做调试、审计、多智能体行为分析，甚至据此宣称模型学会了推理和规划。可自然语言轨迹几乎无法机械验证，你没法程序化地判断某一步是不是真的从前面推出来的。于是作者转向iGSM这个合成小学数学基准：它由Ye等人设计，原本被用来支持“模型学会了推理与规划”的正面结论，但它的关键优势在于每个问题都携带完整的符号计算结构，包括结构图、依赖图和参考轨迹，因此可以逐句、逐步地对模型生成的轨迹做程序化检查。这就把两个常被混为一谈的问题拆开了：答案对不对，和轨迹是不是该答案的有效推导。作者正是要在“合成数据、固定轨迹语法、干净监督、可形式化验证”这种对模型极其有利的条件下，检验正确答案是否可靠地伴随着有效轨迹。

方法的核心在于利用iGSM的依赖结构做细粒度验证。每个iGSM问题由若干句子陈述若干量，句子顺序随机，所有算术模23；结构图定义实体层级，依赖图则记录哪些量需要哪些量才能算出，其中还有一个必要子图，只包含查询真正依赖的参数。参考轨迹恰好按拓扑序计算必要子图中的参数，而问题中陈述的某些参数可能根本用不到。检查器会解析模型生成的轨迹，验证每个用到的名字是否在前文定义过、每个定义是否恰好使用了依赖图规定的输入、算术是否正确、是否只计算了必要参数、是否按合法顺序进行。这样就能把无效轨迹细分为语法错误、算术错误和语义依赖错误。作者先训练一个“干净模型”，只用有效且最小（即恰好计算必要参数、不引入冗余）的轨迹做微调，然后在分布内和分布外测试。结果发现分布内答案正确率与轨迹有效率几乎重合，但一旦推理深度超出训练分布，两者就解耦了：在最难的实例上，31.6%的正确答案伴随着无效轨迹，其中超过一半通过了所有语法和算术检查，只在语义依赖检查上失败——也就是说，表面看起来完全合理，实际上用错了量或漏掉了依赖。接着作者干预轨迹监督：用有效但非最小的轨迹训练，模型输出也变得非最小；把同一个问题换一个查询量重新提问，模型会暴露出从原查询继承来的计算，说明“最小性”并不能证明模型真的针对当前问题独立选择了所需计算。更强的干预是直接破坏轨迹语义：把不相关问题之间的轨迹互换后训练，模型在分布内仍有82%的答案正确率，尽管它从未生成过一条有效轨迹；把训练轨迹前缀句子中10%的token随机打乱，模型几乎保持干净模型的准确率，分布外也如此，同样没有任何生成轨迹能通过验证，打乱比例更高才会逐渐损害泛化。这些结果说明，轨迹可以帮助模型得出正确答案，却离有效推导很远；而像最小性、连贯性这类看似是推理的特征，完全可能是从训练数据里继承来的，而不是模型自己算出来的。

在结果与意义上，作者反复强调结论比“思维链不重要”要窄得多：无效的生成轨迹并不证明模型内部没有发生有用的推理，实验也没有测量轨迹是否忠实记录了产生答案的实际计算。他们真正证明的是，答案正确性、轨迹有效性、最小性这些属性可以相互分离，而且它们之间的关系在分布偏移下会恶化。这对当前把思维轨迹当作监控和解释接口的做法构成直接挑战：无论是用轨迹检测奖励黑客，还是分析多智能体协调，都默认轨迹能告诉监控者足够多关于模型如何得到答案的信息，而iGSM提供了一个可以精确验证轨迹有效性的受控测试环境，任何关于思维轨迹意义的更强主张都必须先满足这个条件。局限也很明显：iGSM是合成的小学数学任务，算术模23，轨迹语法固定，模型是GPT-2规模，结论能否推广到真实自然语言推理、更大模型和开放任务仍需验证；而且作者没有区分“轨迹无效”是因为模型内部用了别的计算路径却输出了一条看似合理的解释，还是因为模型确实沿着无效路径算出了正确答案。尽管如此，这项工作指出了一个被忽视的风险：在分布内表现良好的轨迹可靠性，可能在输入分布偏移时悄然退化，而监控者未必能察觉，这对AI安全中的思维链监控和解释具有直接的警示意义。

### [LeapQuant: Efficient Linear Attention with Accurate Recurrent State Quantization](https://arxiv.org/abs/2609.38166)
`评分3 · 17 pages, 11 figures`

线性注意力（如 Gated DeltaNet、Kimi Delta Attention）把上下文压缩进固定大小的循环状态，大幅降低了长上下文处理的计算和显存增长，因此被 Qwen、Kimi、GLM 等混合架构广泛采用。但问题在于，每生成一个 token，线性注意力层都要把整个状态矩阵从 HBM 读出来、做一次轻量更新、算出输出、再写回 HBM，而更新和读出的算术量相对搬运的字节数极少，推理吞吐因此被 HBM 带宽卡死；开启前缀缓存后，每个缓存前缀还要各自保留一份状态，显存占用同样可观。最自然的解法是把状态量化成低比特，但朴素做法（每步量化再反量化）会严重掉精度，原因有二：其一，量化误差会循环累积，每次更新都从已量化的状态出发，再量化又引入新的舍入误差，状态在长生成中逐渐偏离 FP32 轨迹；其二，状态中少数行和列存在大幅值离群点，它们撑大了量化范围，迫使大量小值落到很粗的量化格上，进一步放大每次量化的误差。论文用 Qwen3.5-9B 在 64K token 上追踪误差，发现逐步量化下误差随上下文持续增长，即便 BF16 也如此，随机舍入只能把 64K 处的 BF16 误差降低约 3 倍，INT8 反而发散。所以，准确的低比特量化必须同时减少误差被引入的频率和每次量化引入的误差量。

LeapQuant 用两个互补机制分别对付这两个误差源，且完全免训练、无需校准数据。第一个是逐窗口量化：它不再每个 token 都量化状态，而是“跳跃”过一整个窗口，只在窗口末尾量化一次。窗口开始时把循环状态以低精度存好并固定住，窗口内的高精度 token 更新（衰减系数、key 向量、修正向量）被缓存起来，每个输出都由这个固定低精度状态加上缓存更新算出，中间状态通过边界状态和缓存元组展开表达，从不重新量化完整状态；只有到窗口最后一个 token 才把完整更新后的状态物化并量化，作为下一窗口的起点。这样量化频率降低为原来的 1/p，长上下文下状态误差显著下降——实验显示每 16 token 量化一次，64K 处 BF16 误差降低 100 倍、INT8 降低 39 倍。第二个是补偿 token：针对离群点问题，在量化前先拟合一个秩一项去捕获状态中占主导的大幅值结构，把它减掉后只量化残差，从而压窄动态范围。这个秩一项由两个向量构成，形式上与真实 token 的秩一更新完全一致，因此可以直接走解码内核里真实 token 的更新路径，不需要任何模型改动，也不产生输出；实践中用 r≤8 个补偿 token，重构开销能被状态内存读取完全掩盖，内核级额外开销控制在 7% 以内。此外，残差在量化前还会做一次平滑：按 key 行平均绝对值的平方根构造对角缩放，左乘后平衡各行幅值再量化，反量化时再乘回来，这个变换可逆，只有中间的量化引入近似。补偿 token 保留主导低秩结构、平滑处理剩余残差的幅值不均，两者叠加让每次窗口边界量化的误差尽可能小。

在 Qwen3.5-9B、Qwen3.5-35B-A3B、Kimi-Linear-48B-A3B-Instruct 等五个混合线性注意力模型上，用 AIME 2026、GPQA-Diamond、MMLU-Pro、LiveCodeBench v6、GSM8K 评测，LeapQuant 在 8 比特状态量化下精度与 FP32 基线相当，同时把状态内存流量降低 3.4 倍、端到端显存占用最多降低 56%；在 NVIDIA B200、RTX PRO 6000、RTX 5090 上，内核级平均加速 2.05–3.70 倍，端到端推理加速 1.47 倍。它的局限也很明确：补偿 token 的拟合和残差平滑都依赖窗口边界的额外计算，虽然当前规模下开销被隐藏，但窗口长度、补偿 token 数量与精度之间的权衡仍需按模型调；论文对 Qwen3.8-Flash 和 GLM-5.3-Flash 只跑了 8 层版本用于效率测量，未验证完整模型的输出质量；方法针对的是对角衰减加秩一 delta 更新的循环形式，对其他线性注意力变体的适用性还需验证。总体而言，LeapQuant 把“状态量化”从每步一次的高频操作变成窗口级的低频操作，并用低秩补偿把离群点从量化张量中剥离，为线性注意力推理的内存瓶颈提供了一条免训练、可直接落地的路径，也提示后续工作可以沿着窗口结构与低秩补偿的联合设计继续挖掘。

### [WUSH-KV: KV Cache Quantization with Data-Adaptive Transforms](https://arxiv.org/abs/2609.38121)
`评分3`

键值缓存的内存占用和带宽开销随上下文长度与批大小线性增长，这已成为长上下文推理的核心瓶颈。此前的方法大致分两条路线：一条是改进量化器本身，比如 KIVI 按通道量化键、按 token 量化值，KVQuant 在 RoPE 之前量化键并做敏感度加权的非均匀量化，AQUA-KV 用跨层适配器预测缓存内容再量化残差；另一条是在量化前对表示做变换，比如 QuaRot 用随机 Hadamard 变换打散离群值，SpinQuant 学习可合并的正交旋转，FlatQuant 学习 Kronecker 结构的变换，RotateKV 针对 2-bit 场景做分组头旋转。这些变换类方法的关键缺陷在于：它们要么是固定的、与数据无关的旋转，要么只优化重建误差，而没有考虑量化误差究竟如何通过注意力计算传播到最终输出。键上的误差影响的是 query-key 内积，值上的误差影响的是输出投影后的结果，二者的敏感度结构完全不同，用一个统一的、只追求"好量化"的变换无法同时照顾这两条路径。与本文同期的工作 OSCAR 虽然估计了注意力感知的协方差并分别构造键和值的正交变换，但它把变换限制为正交矩阵，无法做各向异性的重缩放，因而在统计特性和下游敏感度之间只能做折中。

WUSH-KV 的核心思路是把 WUSH 变换从权重-激活量化迁移到 KV 缓存量化。WUSH 的出发点是：一个变换好不好，不能只看被量化张量本身的分布，而要看它作为矩阵乘法的一个因子时，误差如何被另一个因子放大。具体来说，对于线性层输出误差，其 Hessian 是权重矩阵与其转置的乘积，而量化张量的 Gram 矩阵刻画了其自身各坐标方向的能量分布。WUSH 用这两个二阶统计量构造一个闭式解的可逆变换，先对 Gram 矩阵做 Cholesky 分解、对 Hessian 做对称特征分解，再组合成一个块对角矩阵，块宽等于量化分组大小，从而在推理时能廉价地施加到激活上。这个构造对两个矩阵的独立正缩放不变，因此不需要额外跟踪归一化因子。在 KV 缓存场景下，WUSH-KV 为每个 KV 头分别构造键变换和值变换：键变换的 Hessian 来自读取该键头的所有查询头，值变换的 Hessian 来自消费该值头的输出投影块。值变换可以离线折叠进值投影和输出投影的权重中，推理时零额外开销；键变换则必须放在 RoPE 之后，因为如果把键变换折叠进投影权重，就要求它与 RoPE 和 RMS 归一化都对易，而对易约束下只剩平凡的符号翻转，无法重新分配坐标幅度。放在 RoPE 之前虽然保留完整自由度，但补偿会依赖缓存位置，每个解码步都要对所有缓存键做旋转补偿，工程上不可接受。因此 WUSH-KV 选择在 RoPE 之后施加完整的 d×d 变换，代价是每个新键和查询需要一次在线变换，但缓存表示保持简单。量化器方面，WUSH-KV 本身与标量量化器解耦，理论分析针对 QuEST 的投影步骤：步长由分组 RMS 决定，重建值取 bin 中心，超出范围的条目被裁剪，裁剪阈值取标准高斯下均方误差最优的常数倍 RMS。在这个加性舍入噪声模型下，作者证明了理想 WUSH 变换在平衡坐标敏感度的变换类中是近最优的。此外，WUSH-KV 对注意力汇和最近若干 token 的缓存条目保留全精度，这与 KIVI、KVQuant 等方法的做法一致。

在实验层面，WUSH-KV 在层重建误差和端到端困惑度上都取得了最低值。受控重建实验使用 QuEST 量化器以隔离变换质量的影响，端到端评估则集成进 SGLang，使用 OSCAR 风格的百分位裁剪仿射量化器。在 2-bit 设置下，WUSH-KV 在所有评估模型和下游任务上都不劣于 OSCAR 变换，在 Qwen3-8B 的四个任务上全面超过 OSCAR，在 4B 和 32B 上也有竞争力。这一结果的意义在于，它表明变换的自由度——从正交扩展到一般可逆——确实能带来实际收益，因为各向异性重缩放可以同时平衡缓存统计和下游敏感度，而正交变换做不到这一点。局限方面，键变换无法折叠进权重意味着每个解码步都有在线变换开销，虽然作者认为这是可接受的工程折中，但在极端长上下文或高并发场景下这部分开销仍需仔细评估；理论近最优性依赖于 QuEST 量化器和加性噪声假设，对于其他量化器是否仍然成立尚不清楚；此外，校准数据的质量和覆盖范围会直接影响变换的效果，分布外输入的鲁棒性有待进一步验证。总体而言，WUSH-KV 把"变换应当感知下游敏感度"这一原则从权重-激活量化推广到了 KV 缓存量化，为后续在更激进的比特宽度下设计数据自适应变换提供了一个有理论支撑的起点。

### [Do LLM Agents Execute the Plans They Declare? From Planning-Mode Declaration to Pattern-Specific Execution](https://arxiv.org/abs/2609.38108)
`评分3 · 51 pages, 8 figures`

这篇论文要解决的是一个在LLM智能体研究中长期被忽视、但实际非常关键的问题：智能体在任务开始时声称自己采用的规划方式，和它真正执行时所用的控制流，往往根本不是一回事。现有的规划器-执行器系统（比如Plan+ReAct）通常让模型先输出一个计划，然后交给一个通用的ReAct循环去执行，但ReAct的本质是每一步都根据当前观察局部反应，它并不强制遵守之前声明的结构。结果是，最终任务成功与否这个单一指标无法区分两种截然不同的失败：一种是智能体选错了规划模式（比如该用搜索却用了固定流程），另一种是它选对了模式却在执行中偏离了计划。作者把这种声明与执行之间的脱节称为“Plan Declaration–Execution Gap”，并指出仅看最终成功率会掩盖这一鸿沟，因为一个智能体可能靠记忆、运气或低效的试错碰巧完成任务，却从未真正执行它承诺的规划结构。更麻烦的是，不同任务和环境对规划模式的需求本就不同——有些任务适合固定流程，有些需要逐步调整，有些需要分解子目标，有些需要探索多条路径——而现有框架通常把规划机制写死在架构里，不把它当作一个可以按任务选择的变量。

核心方法叫Planning-as-Routing，思路是把“规划模式”从隐含行为变成显式声明，再用确定性路由把它绑定到对应的执行器上。具体来说，智能体首先从四种模式中声明一个：Predefined（执行前生成完整计划，之后不再重规划）、Sequential（规划-执行-重规划循环，每步根据观察更新剩余计划）、Hierarchical（编排器把任务分解成子目标，交给专门的工作器执行再汇总）、Search（生成多个候选计划，各自独立执行，再用基于评分标准的裁判选出最优轨迹）。声明之后，一个确定性路由器把任务分发给对应的模式专用执行器，不再经过额外的模型推理。这和Plan+ReAct的关键区别在于：Plan+ReAct只是把计划作为上下文塞给一个扁平的ReAct循环，执行控制流没有变；而Planning-as-Routing让声明的结构直接决定执行的控制流，因此模式是否被遵守可以从轨迹中结构性验证。作者还设计了一个基于规则的执行结构验证器，用来检查Plan+ReAct是否按声明顺序执行了计划步骤，而路由执行因为分发记录本身就保证了顺序保真，不需要额外打分。为了把“执行失败”和“选择失败”分开，论文还做了强制分发分析：对每个基准-模型组合，让所有四种模式都跑遍所有任务，得到一个任务-模式成功矩阵，从而计算出最佳固定模式的成功率、逐任务预言机上限，以及两者之差所代表的“路由余量”。这样就能判断一个智能体的失败到底是因为执行器能力不足，还是因为声明模块选错了模式。

实验结果覆盖四个基准（WebArena、Mind2Web、SWE-bench Verified、ALFWorld）和三个模型家族（Qwen3.6、DeepSeek-V4、Gemma-4），有三个一致发现。第一，通用的Plan+ReAct经常无法保持声明的规划结构，尤其在长计划上，三个基准中只有22%到45%的轨迹保持了结构，而模式专用执行器从构造上就强制了预期结构。第二，规划模式的有效性随环境和模型变化：Search在ALFWorld上最好，Hierarchical在SWE-bench上最好，同一个基准内不同模型的最强模式也可能不同。第三，最大的收益来自执行环节：模式专用执行器把ALFWorld的任务成功率从0.48提升到0.92，把SWE-bench Verified从0.36提升到0.44，相比Plan+ReAct提升显著。但论文也坦承一个尚未解决的瓶颈：当前LLM并不能可靠地为任务选出最强的规划模式，声明策略在每个基准-模型组合上都落后于最佳固定模式；少样本示例可以在部分组合上改善模式选择，带来0.004到0.16的提升，但选择问题依然开放。这项工作的意义在于，它把智能体规划从“能不能生成计划”推进到“声明的规划模式是否被忠实执行、是否适合任务”这一更细的层面，并证明路由机制能大幅缩小执行鸿沟，而如何让模型自主选对模式，仍是未来需要攻克的方向。

### [Thinking Before Thinking: Scaling Agentic Inference Through Meta-Reasoning](https://arxiv.org/abs/2609.38147)
`评分3`

这篇论文要解决的是长程智能体推理中一个被长期忽视却越来越关键的问题：当智能体在一个复杂任务上消耗成百上千次模型调用时，真正稀缺的不再是单步生成能力，而是“下一步该做什么”的控制决策。作者把这种能力称为元认知控制——智能体需要评估自己已经取得了什么进展，并据此决定继续推进哪条路线、信任哪些中间结果、何时止损或收束。过去的主流做法（如 ReAct、Reflexion、Tree-of-Thought 以及各类编码智能体）把控制决策和任务级工作交织在一起，每一步都基于不断膨胀的历史上下文做单次判断。问题在于，随着运行变长，中间产物越来越多，上下文被噪声淹没，控制决策的质量随之下降；一个错误判断的代价远不止多花的那点算力，它可能让一条已经失败的路线贯穿整个运行，或者把已经找到的正确答案丢掉。论文的核心动机就是：控制本身应该是一个独立的、结构化的智能体推理过程，而不是对象级推理的副产品。

为此，作者提出了“智能体元推理”（agentic meta-reasoning），并把它实现为一个推理时 harness。整个系统把角色拆成两类：worker 负责对象级的任务计算，controller 负责决定派发什么工作。关键设计在于 controller 不保存完整历史，而是维护一份紧凑的、自撰写的文本状态，记录运行至今确立了哪些结论、还有什么待办；完整的 worker 输出则以 artifact 形式存入持久记忆，每个 artifact 有稳定标识符，需要时再检索。每个控制周期分四个阶段：Assess 根据上一批 worker 返回的新 artifact 更新状态；Propose 在不看剩余预算的前提下提出若干候选计算，刻意把“生成选项”和“判断可负担性”分开，避免过早砍掉昂贵但有价值的路线；Evaluate 结合剩余预算对候选做定性价值评估，选出最值得做的一个；Dispatch 把选中的提案转成可执行动作，并决定这个 worker 应该看到哪些历史 artifact 作为上下文。这四个阶段各自都是完整的智能体过程，有自己的指令和工具，可以内部多次调用模型。Controller 的模型调用和 worker 共享同一预算，所以额外的“思考”必须自己挣回成本。每次派发时 controller 为 worker 选择的 artifact 上下文会被记录成一条边，整个运行因此形成一张 artifact graph，节点是产物，边表示“后者以前者为上下文产生”。这张图让作者能够按运行实际产出的工作结构来诊断，而不只是看最终分数。相比之前的方法，它的优势在于：控制决策不再被噪声历史拖累，而是基于一份被主动整理过的状态；记忆成为控制动作的作用面，controller 可以读写、可以给 worker 精确划定上下文，从而让后续计算建立在被验证过的前序工作之上，而不是盲目重来。

在实验上，作者在 IMO ProofBench-Advanced、ARC-AGI-2、LongCoT-mini 和 ProgramBench 四个基准上，用 Gemini 3.1 Pro、GPT-5.5 和 Opus 4.8 三个前沿模型做了评测，任务覆盖证明搜索、抽象推理、长程推理和程序重构。在推理基准 100 次模型调用、ProgramBench 1200 次调用的主预算设置下，元推理在全部 12 组匹配比较中都取得更高的点估计，按基准平均提升 3.6 到 4.2 分。最亮眼的是 ProgramBench：用 GPT-5.5 时，元推理把每题测试通过率从 Codex 的 58.0% 提升到 71.5%，也高于同样 worker 和预算下直接控制（Direct Control）的 63.7%；用 Opus 4.8 时达到 67.2%，略高于 Claude Code 的 65.5%。更值得注意的是趋势：随着预算增加，直接控制很快进入平台期，而元推理仍在持续改善，说明把算力花在结构化控制上，在长程任务中比单纯增加采样或延长单条推理链更有回报。artifact graph 的分析进一步显示，元推理在多数设置下更频繁地复用早前工作、更多运行中出现了正确答案的候选，且最终选择环节的增益并不均匀，说明提升既来自“做得更好”，也来自“选得更准”。局限也很明确：控制本身有开销，在预算很小的时候这种开销可能反而拖累表现；Evaluate 阶段目前只是定性的价值判断，并非精确优化或学习出来的价值估计器；此外，worker 作为编码智能体时会读取上下文之外的環境状态并产生随机性，artifact graph 只能记录 controller 显式选择的上下文，无法完全刻画真实依赖。尽管如此，这篇工作指出了一个重要方向：随着智能体运行越来越长，推理时算力的分配问题会从“生成更多”转向“更聪明地控制”，而把控制显式建模为一个独立的智能体推理过程，是让智能体随任务长度和复杂度扩展的关键一步。

## 强化学习 RL

### [Scaling Properties of Same-Family On-Policy Distillation](https://arxiv.org/abs/2609.32722)
`评分4 · HF 190赞`

这篇论文要解决的是大语言模型后训练中一个非常实际的工程问题：强化学习虽然能显著提升模型的推理能力，但如果在每个模型规模上都独立跑一遍 RL，成本会随模型家族规模线性膨胀。于是人们转向同家族内的在线策略蒸馏（On-Policy Distillation, OPD），用一个已经具备任务专长的教师模型，在学生自己采样出的轨迹上提供 token 级监督，把能力“迁移”过去。然而此前的工作几乎只关心 OPD 变体的设计，比如怎么改 token 奖励、怎么改蒸馏目标，却没人系统回答一个更根本的问题：这种能力迁移到底能迁移多少、迁移多快，它和教师、学生的参数量之间是否存在可预测的规律？已有的实证分析只沿 rollout 长度、token 重叠率等局部轴观察训练动态，无法在训练前就估计结果。作者借鉴了 Gao 等人关于奖励模型过优化的研究思路——在 PPO 对学习到的奖励模型优化时，gold reward 的动态可以用相对初始策略的 KL 散度来描述，且系数可由奖励模型规模预测——把 OPD 也视为对“教师诱导的隐式 token 奖励”这一代理目标的优化，用学生相对初始化策略的 token 级反向 KL 散度的平方根 d 作为训练进度的坐标，考察 held-out 准确率（gold score）随 d 的变化，并试图用学生和教师的规模来预测拟合出的系数。核心动机就是：如果这些依赖关系能被写成幂律，那么一次 OPD 运行的结果就可以在训练前被估计，而不是训练后才发现。

方法上的关键洞察在于，作者发现 OPD 的训练动态存在一个普遍且规则的“有效迁移区间”：在这个区间内，gold score 随 d 近似线性上升，而对 25 组教师-学生组合的线性拟合 R² 落在 0.932 到 0.988 之间，斜率跨度从 0.175 到 0.721。这个线性并非巧合，论文给出了局部 KL 几何的解释：沿平滑训练路径，gold score 对参数扰动是一阶变化，而 KL 是二阶变化，因此 G(d) = G(0) + m·d + O(d²)，斜率由更新方向与 gold score 梯度在 Fisher 度量下的对齐程度决定。超过迁移终点 d_transfer 后，动态变得嘈杂且异质，混合了衰减式提升、饱和与回退，且回退时教师诱导的代理分数仍在上升，说明这是隐式奖励过优化而非简单的过度模仿。为了预测峰值和迁移速率，作者没有直接对观测到的峰值位置 d_peak 施加参数化规律，而是分别拟合 G_peak 和斜率 m，并将教师参数量截断到不超过学生参数量，因为实验显示教师规模超过学生后收益饱和甚至反转——比如 0.5B 学生在 3B 教师下峰值 40.8%，换 7B 教师反而降到 39.0%，14B 教师只有 37.7%。更关键的是，作者发现仅用参数量概括教师是不够的，因为未训练到 RL 终点的教师分数会低于其规模趋势，于是把教师剩余误差（由教师 gold score 度量）也作为协变量，拟合乘法形式的幂律：学生规模的作用是移除教师监督所留下的误差中的一个固定比例，这种乘法交互比加法形式拟合误差更低。在教师全部为 RL 终点的网格上，教师规模与教师分数几乎完全共线（r = -0.9999），无法分离两者的指数；作者通过引入 bootstrap 链式 OPD 产生的中间教师（其分数低于规模趋势）打破共线性，将相关性降到 -0.95 和 -0.97，从而识别出所有教师指数，且 bootstrap 区间均不包含零。此外，论文还比较了 Vanilla-OPD 与 Delta-OPD：后者用教师在 RL 过程中获得的策略偏移来构造 token 奖励，在 15 个共享配对中有 15 个产生更大的匹配 KL 局部增益斜率，12 个产生更大的观测峰值增益，优势集中在弱到强方向；而 off-policy 冷启动（先用教师演示做 SFT）会随弱到强能力差距的增大而越来越有害；沿模型家族逐级 bootstrap 弱到强 OPD 也不如直接从最小的 post-RL 专家做直接迁移，尽管中间教师的 gold score 更高。

在结果与意义上，论文在 Qwen2.5 Base 的 0.5B 到 14B 五个规模上、用 GSM8K 与 MATH 混合数据训练教师并评估学生，覆盖 25 组教师-学生组合。核心发现是：在每一个观测到的弱到强配对中，学生的峰值 gold score 都超过教师自身，说明一个紧凑的 RL 专家可以通过 OPD 把能力迁移给大得多的学生；峰值剩余误差和有效迁移速率都服从学生规模、截断教师规模与教师分数的联合幂律，峰值规律在最大的 held-out 规模上外推误差在一个准确点以内；在匹配的教师分数下，更小的教师迁移效果更好，这意味着教师分数本身并不定义其监督价值。同基座 OPD 的峰值在五个规模上都与直接 RL 参考相差不到 0.5 个百分点，其中三个规模还超过了直接 RL。局限也很明显：超过迁移终点后的动态没有共享的函数形式，最小学生的反转仍未被模型解释；参数量是一个混杂变量，隐含了数据规模和训练计算量，因此这些幂律应理解为在 compute-optimal 设定下成立；bootstrap 链式迁移的负面结果也提示，简单地沿家族逐级蒸馏并不是放大弱专家的有效路径。总体而言，这篇工作把 OPD 从“试了才知道”推向“训练前可估计”，为模型家族内的能力迁移提供了第一套可外推的缩放规律，也指出了教师选择不能只看分数、还要看其相对于学生规模的位置这一反直觉但重要的实践含义。

### [SAKI: Maximal-Coupling-Routed Teacher Supervision for On-Policy Distillation](https://arxiv.org/abs/2609.36601)
`评分4 · HF 75赞`

在策略蒸馏（OPD）的核心动机是消除训练与推理之间的状态分布错配：学生模型在自己的生成轨迹上接受教师监督，而不是在固定的或教师生成的前缀上训练。但这一优势本身也埋下了隐患——当学生显著弱于教师时，早期错误会逐步累积，把轨迹推向教师自身策略下概率极低的前缀。教师在这些状态上虽然仍能给出条件分布，但这些分布并非教师强推理能力的代表性行为，导致监督信号与真正需要迁移的能力之间产生偏离。已有的改进方案如TRB（Trust-Region Behavior Blending）通过在每步构造一个向教师靠近、但受学生中心KL信任域约束的中间行为分布来改善被访问状态的分布，然而它保留了每个前缀上相同的反向KL目标。反向KL是学生加权的，学生支持度低的教师偏好token获得的梯度很弱，这意味着在高冲突位置，教师真正想纠正的方向恰恰得不到足够的更新力度。问题因此从“在哪里查询监督”延伸到“在查询到的位置上如何施加监督”这一互补维度。

SAKI的核心洞察在于：当用最大耦合（maximal coupling）来实现TRB的中间行为分布时，采样过程本身会暴露一个天然的监督路由信号。具体来说，在每个解码位置，学生先从自身分布提出一个token，最大耦合以一定概率接受该提议，否则从残差分布中抽取一个修正token。这个接受/修正事件不是外部启发式，而是精确实现目标分布所必需的最小干预——修正概率恰好等于学生分布与引导分布之间的总变差距离，且在信任域约束下被上界为信任域半径平方根的一半。SAKI把这个实现层面的耦合事件直接复用为监督路由器：接受位置上保留标准的采样token反向KL损失，修正位置上则切换到对教师最高概率token的直接监督，即最小化教师Top-1 token的负对数似然。这种设计的精妙之处在于，修正事件的发生本身就意味着学生提议的行为无法被保留、引导策略必须介入，因此在这些位置上施加教师模式的确定性监督是分布意义上最自然的选择。修正token决定后续轨迹前缀的走向，教师Top-1 token决定当前的参数更新方向，同一个耦合过程同时控制了轨迹构造和监督路由，无需引入额外的token选择规则或路由阈值。在工程实现上，由于精确的最大耦合采样需要每步同时获取学生和教师分布，作者采用引擎驻留的投机块验证来摊销教师推理开销，通过精确残差修正和首次拒绝提交/回滚机制，在保持精确引导轨迹分布和耦合语义的前提下，将匹配工作负载下的 rollout 吞吐量提升了4.22倍。

在七个数学推理基准上，SAKI在1.7B和0.6B两个规模的学生模型上都优于匹配的教师引导基线，Mean@8和Pass@8均有提升。消融实验进一步验证了路由机制的必要性：修正触发的监督路由优于等预算的随机放置和按总变差加权的冲突感知放置，说明并非任何在高冲突位置施加额外监督的策略都能奏效，关键在于修正事件本身携带的分布语义——它标识的是在最小干预耦合下学生提议无法被保留的位置。固定前缀分析显示教师对齐具有持续性，且初始学生-教师分歧越大，SAKI相对随机放置的增益越显著。教师模式监督也优于随机教师采样，在1.7B学生上分别高出0.62 Mean@8和1.56 Pass@8，确认了在高冲突位置确定性模式寻求更新的优势。局限方面，方法依赖在线教师分布，精确耦合采样带来的计算开销虽然被投机验证大幅摊销，但仍高于纯学生rollout的OPD；信任域半径的退火调度需要精细设计，修正监督在训练后期随信任域收缩而消失，如何在不同训练阶段保持有效的监督信号仍是开放问题。更广泛地看，SAKI揭示了一个有启发的方向：蒸馏中行为分布的实现机制本身可以携带监督分配的信息，将“如何采样”与“如何监督”统一在同一个概率耦合框架下，这为后续在更一般化的分布匹配目标中复用实现层面的结构信息提供了思路。

### [Dr. OPD: Learning What to Follow for Optimal On-Policy Distillation of Large Language Models](https://arxiv.org/abs/2609.38025)
`评分4`

这篇论文要解决的是在线策略蒸馏（On-Policy Distillation, OPD）中一个被长期忽视但非常关键的问题：教师模型给出的逐 token 监督信号，是否应该被一视同仁地对待。传统 OPD 的做法是让学生模型在自己的生成轨迹上，最小化与教师模型下一 token 分布的 KL 散度，从而获得比只给最终答案奖励的强化学习（如 RLOO、GRPO）更密集的学习信号。但问题在于，教师信号在不同 token 上的价值差异极大：有些 token 上教师纠正的是关键推理错误，直接决定最终答案对错；有些 token 上教师只是偏好不同的措辞，对结果几乎没有影响。Vanilla OPD 默认所有权重为 1，等价于假设每个教师信号同等重要，这显然不合理。更本质地看，蒸馏的终极目标不是让学生分布逼近教师分布，而是提升学生自身的任务表现；最小化与教师的散度只是手段，不是目的。教师信号只告诉我们“教师偏好什么”，并不告诉我们“跟随这个偏好是否能提升学生表现”。因此，论文提出一个核心问题：如何根据每个教师信号对学生最终表现的贡献，自适应地为其分配权重。

Dr. OPD 的核心创新是把“选择 token 权重”形式化为一个双层优化问题：下层是在给定权重函数下，学生通过加权 OPD 训练；上层是选择权重函数，使得训练后学生的期望结果奖励最大。权重被限制在一个正区间内，大于 1 表示更信任教师，小于 1 表示更少信任，等于 1 退化为 vanilla OPD。为了证明加权 OPD 仍然是合法的蒸馏目标，论文定义了加权 KL 散度，并证明只要权重为正，最小化该散度仍然会推动学生匹配教师分布，且当权重恒为 1 时退化为普通 KL。直接求解双层优化不可行，因为每评估一组权重都要完整训练学生，而且权重函数定义在所有上下文-token 对上，是无限维的。论文设计了一个迭代求解器：每一轮先固定权重，对学生做一步加权 OPD 梯度更新；然后根据更新后学生的奖励反馈来更新权重。关键洞察在于，教师修正项 g_t 决定学生概率移动的方向，而“信用” c_t 决定这个移动是否真的提升奖励。c_t 是教师修正向量与奖励梯度的内积：如果为正，说明在该 token 上更跟随教师能提升奖励，应增大权重；如果为负，说明跟随教师反而有害，应减小权重。通过构造奖励的下界代理目标，权重更新可以写成闭式解，无需额外训练一个权重网络。更巧妙的是，计算每个 token 的信用需要两个参数维梯度的内积，代价极高；论文将其转化为两个标量的乘积，并用一次 Jacobian-vector product 同时算出所有 token 的信用，大幅降低计算开销。理论上，论文证明在正则条件下，这种加权更新比 vanilla OPD 更新获得更高的期望奖励。

实验上，Dr. OPD 在数学和代码任务上覆盖了强到弱蒸馏和同尺寸蒸馏两种设定，全面优于所有对比基线。最突出的结果是在强到弱蒸馏中，Qwen3-1.7B 学生相比 vanilla OPD 在数学上平均提升 9.7 个百分点，并且以 35.0 对 34.1 超过了更大的 Qwen3-4B 教师；在同尺寸蒸馏中也超过了经过强化学习训练的教师。这说明“学什么”比“跟谁学”更重要——学生不必盲目模仿教师的每一个 token 偏好，而应学会筛选真正有助于任务表现的信号。局限方面，论文依赖可验证任务提供结果奖励，对开放域任务需要奖励模型，奖励模型的质量会直接影响信用估计；信用估计用当前学生近似替代一步更新后的学生，存在偏差；权重更新只针对采样到的 token，未覆盖整个词表分布；理论保证依赖正则条件和局部 Lipschitz 假设，实际训练中未必严格满足。尽管如此，这项工作把蒸馏从“分布匹配”推进到“性能导向的信号选择”，为 OPD 提供了一个新的优化视角，也提示未来可以探索更准确的信用估计、更通用的奖励来源以及权重函数的结构化参数化。

### [Skill-Space Shooting for Autonomous Robot Policy Improvement](https://arxiv.org/abs/2609.38178)
`评分3`

这篇论文要解决的是机器人在真实物理环境中部署后如何持续自我改进的问题。传统上，机器人策略在初始训练后遇到新物体、场景变化或执行误差时往往表现下降，而仅靠反复尝试并不能带来改进，因为机器人可能不断重复同样的错误。人类提供纠正示范虽然有效，但每遇到新失败就要重新示范，成本随任务数量线性增长，成为扩展瓶颈。强化学习虽能通过奖励驱动探索，但长时序任务中稀疏奖励使物理探索代价过高；交互式模仿学习（如DAgger）虽能在学习者实际访问的状态上获取专家纠正，但仍依赖人类持续提供纠正。近期基于基础模型的智能体系统能将语言推理与可执行技能、程序连接起来，自主组合行为完成任务，但这类系统完成一次任务并不等于教会了任务策略如何克服自身失败——关键在于把这些辅助行为转化为策略可学习的纠正信号。论文的核心洞察是：许多纠正本质上是可复用的短时行为即技能，它们跨任务反复出现，且基础模型能够从场景中推理出该用哪个技能。

方法上，作者提出skill-space shooting，将学习到的技能作为任务策略执行轨迹的候选延续，通过基础模型引导探索纠正，并将成功试验转化为策略改进。整个循环包含三个关键环节。第一是失败检测：任务策略控制机器人直到需要纠正为止，检测器必须同时考虑当前观测和策略即将执行的动作块，因为明显失败往往来不及恢复。具体实现用DINOv2图像特征和编码后的动作token条件化一个流匹配头，预测动作块执行后的机器人状态及一个标量值，成功执行目标为+0.5，失败前一个动作视野开始目标为-0.5，从而在失败临近但仍可纠正时触发。第二是技能选择：一旦低价值触发，就在技能库中搜索纠正性延续，每个技能定义从当前状态尝试的候选行为，基础模型（Gemini 2.5 Pro）接收当前场景、任务指令和可用技能，利用其对物体和任务结构的语义知识判断该尝试哪个技能，比如海绵还在碗里时策略尝试擦拭，模型能识别缺失的抓取并选择对应技能。第三是修复与学习：被选技能从任务策略停止处接管，由于先前错误已改变物体位置或接触状态，技能必须响应策略实际到达的状态，这正是产生有用监督的原因——从干净初始状态的新示范可能永远不会遇到同样的困难失败状态。技能执行后价值模型监控并请求检查，连续c次非负检查或达到M步动作上限后由基础模型判断该阶段是否修复，接受则交还控制给任务策略继续后续阶段，否则重试，每次轨迹最多三次重试。学习时只保留被判定完成轨迹中经技能执行且被接受的修复片段，用任务指令重新标注，排除策略自身动作和被拒绝的试验，形成DAgger式监督，在迭代k时用初始示范加上保留的修复片段更新策略。这样训练不必等待策略首次端到端成功，因为完成的轨迹可以包含只有技能才能执行的阶段。随着策略更新，它会遇到新的失败状态，技能库持续提供新监督，而技能和判断提示固定不变，价值模型校准后也固定，人类输入仅限于初始示范和场景重置。

在四个真实世界任务上，skill-space shooting在连续迭代中提升了无辅助的策略性能，包括从一个初始任务成功率观测为零的策略开始。干预分析表明技能库确实在策略的失败状态提供了有用修复。技能数据共享实验显示，复用已有技能数据能减少将技能适配到新运动原语所需的额外人类教学，甚至促进新任务的改进。局限方面，论文的方法依赖于将任务分解为阶段并为每个阶段指定一个技能，这在实际中可能不够灵活；技能库的初始获取仍依赖人类示范，虽然可以来自先前任务，但从人类视频或自主经验中获取技能留作未来工作；失败检测器需要初始标注片段训练后冻结，可能无法适应策略改进后失败模式的变化；基础模型判断修复是否成功也可能存在误差。总体而言，这篇论文的意义在于将可复用技能确立为纠正性监督的来源，使初始人类教学能够在任务内和跨任务中反复用于自主策略改进，为机器人部署后的持续学习提供了一条减少人类监督、可扩展且可泛化的路径。

### [LEMON-ZEST: Evolution-Informed Tokenization for Efficient Protein Language Modeling](https://arxiv.org/abs/2609.37675)
`评分4 · Accepted to NeurIPS 2026. 9 pages, 4 figures, 3 tables`

蛋白质语言模型近年沿着自然语言处理的路线不断放大参数与数据规模，在序列和结构任务上取得了显著进展，但分词这一环始终被严重低估。人类语言里子词切分是为了压缩词形变化，而蛋白质有一个截然不同的性质：序列可以在进化中大幅漂移，三维折叠却高度保守。标准分词策略——无论是按残基切分还是数据驱动的BPE——都只看到序列表面的统计规律，无法把“哪些片段在进化中被反复保留”这一结构约束编码进去。结果就是模型必须靠海量参数和算力在训练中隐式地重新发现这些保守模式，效率极低。更棘手的是远程同源检测：当两条序列一致性低于30%时，它们可能共享同一折叠，但现有PLM（包括600M到3B参数级别的模型）在这个任务上仍然表现不佳，因为残基级分词把注意力浪费在大量无关的序列噪声上，而真正决定折叠的保守区域没有被显式地表征出来。经典基于MSA的profile方法（如HMMER、HH-suite）虽然能捕捉保守性，却受限于马尔可夫假设，无法建模长程依赖。这就留下了一个明确的空白：能否把进化保守的先验直接注入分词阶段，让模型不必从零学起？

LEMON-ZEST的核心创新正是围绕这一点展开。作者从TEDLH的76万余个HMM profile的共识序列中提取长度至少3个残基、非均聚物的保守片段，称为“zone”，再用MMseqs2在70%一致性下聚类，按跨profile出现频率和长度加权排序，取前31975个簇构成词表ZEST，每个簇共享一个token id——这天然处理了“多序列映射到同一结构”的多对一问题。加上20个标准氨基酸作为回退token和5个特殊token，ZEST的平均token长度约为4个残基，意味着标准1024上下文窗口能容纳约4000个残基，压缩率达4到6倍。但贪心最长匹配会带来一个副作用：较短的保守子模式永远被更长的模式吞掉，导致约139个token在500万条序列上从未被激活。为此作者设计了Trie-Dropout：把词表组织成前缀树，每个位置返回从长到短的所有合法匹配，以概率p_drop随机选择较短匹配而非贪心最长匹配，极端情况下退化为单残基。这既是一种正则化，迫使编码器不依赖表面上的长zone身份，也为推理时的测试时增强提供了基础。模型LEMON本身是一个200M参数的共享编码器，采用pre-norm Transformer、RoPE、SwiGLU和Flash Attention，token嵌入与MLM输出投影绑定。关键设计在于两个头：表示头用单个可学习query做注意力池化，再经瓶颈投影和L2归一化，输出用于层级对比学习的序列嵌入；序列头则把每个token嵌入广播回其残基跨度，加上全局位置嵌入和token内局部偏移嵌入（ALiBi风格），再经MLP还原为20类氨基酸预测。这个序列头的梯度信号至关重要——它惩罚编码过程中局部残基信息的丢失，使共享编码器在粗粒度token上仍保持残基级保真度，而全局位置编码则防止模型把不同链位置上相同的保守motif混为一谈。

在结果层面，LEMON在远程同源检测任务上与600M到3B参数的现有最优模型对比，仅用单张H100训练一周便实现了超越。训练数据为UniRef90的50%（约9000万条序列），微调阶段从TEDLH构建了5970万对蛋白质对，在CATH的Architecture、Topology、Superfamily三个层级上做对比学习，并用CD-HIT严格隔离训练与验证集以防止序列泄漏。评估在SCOP、SCOPe和CATH S20上进行，作者还做了严格的审计：训练与基准之间无完全相同的序列，约10%的基准域与训练序列有70%以上一致性，仅2.5%超过90%，远低于基准评估的一致性阈值；在fold层面80.9%的S20 fold类型出现在训练中，这符合远程同源基准的设计逻辑——它测试的是已知fold的序列远亲，而非全新fold。这一结果的意义在于，它证明了进化信息驱动的分词可以替代大规模的参数扩展：把生物学先验放在输入端，比让模型在训练中隐式学习要高效得多。局限也很明显——ZEST词表依赖于已有MSA和HMM profile的覆盖度，对于缺乏同源信息的孤儿序列或人工设计蛋白，保守zone的提取会受限；Trie-Dropout的概率选择是均匀的，没有考虑不同子模式的结构语义权重；此外模型仅在远程同源检测上验证，能否推广到结构预测、功能注释等任务仍需进一步实验。但方向是清晰的：分词粒度作为PLM设计中一个被长期忽视的维度，值得被重新审视，而进化保守性为这一维度提供了有原则的、可解释的切分依据。

### [RNA Design via Conditioned Flow Matching and Finite-Policy Reinforcement Learning](https://arxiv.org/abs/2609.36885)
`评分4 · 32 pages, figures. Preprint`

这篇论文要解决的是RNA逆折叠问题，即给定目标二级结构，找出能够折叠成该结构的核苷酸序列。现有方法大致分为三类：基于目标特异性搜索的优化方法（如NEMO、SAMFEO）、学习式优化策略（如LEARNA、DRAG）以及条件生成模型（如RNA-Design-LM、GoForth）。这些方法虽然取得了显著进展，但它们都将RNA设计形式化为搜索策略优化或结构条件生成，与自然RNA进化中实际发生的“变异-选择”过程存在本质差异。在自然进化中，序列变异探索不同的核苷酸配置，而配对位点上的补偿性替换能够在突变累积过程中保持碱基配对，随后选择压力偏好那些更好满足结构与功能约束的突变体。现有方法没有显式建模这一过程，导致三个具体问题：其一，序列变异要么被建模为独立决策，要么被建模为严格顺序决策，无法捕捉全序列范围内的协调变异；其二，缺乏一个选择机制来逐步将生成的变体偏向热力学上更有利的折叠；其三，在变异过程中难以保持配对位点的补偿性替换，使得序列变化可能与目标二级结构不一致。

针对上述挑战，作者提出了一个两阶段框架RNA-IFlow和RNA-IFlow-RL。第一阶段RNA-IFlow的核心是结构条件Dirichlet流匹配，它在双向掩码语言模型骨干网络上运行。具体来说，每个核苷酸被表示为其在四类单纯形上的一热向量，作者定义了一条条件Dirichlet概率路径，其中浓度参数α控制向干净核苷酸的集中程度。对于完整序列，使用因子化路径，而双向掩码语言模型根据完整序列状态、路径水平α和目标结构y预测每个位置的干净核苷酸概率，这些后验概率被转换为单纯形切空间上的连续速度场。关键在于，由于速度场是从完整序列状态和共享目标结构预测的，所有核苷酸位置在双向上下文下同时更新，这使得协调的全序列变异得以涌现。在生成结束时，结构感知的终端解码对非配对位点做单位置argmax，对每个目标配对做联合argmax，限制在六种合法碱基配对状态中，从而确保每个目标碱基对都被赋予有效的配对状态。第二阶段RNA-IFlow-RL将学习到的流转化为有限策略，通过三个设计实现热力学选择。流到策略映射将当前离散序列映射到Dirichlet路径的条件均值，并基于结构单元（非配对位点或目标碱基对）构建有限离散转移核，使得转移概率可精确计算。结构保持策略动态进一步约束动作空间：非配对位点有四种状态，配对位点有六种合法配对状态，配对单元的策略通过对两个位置的干净核苷酸后验做温度缩放后联合构建，从而在每一步策略步骤中都保持配对合法性。热力学轨迹细化则对每个目标采样多条轨迹，终端序列根据是否达到最小自由能结构以及是否唯一最小自由能获得奖励，然后计算组归一化优势，并将同一终端优势分配给该轨迹中的每一步转移，使得终端的热力学选择信号能够 refine 整个生成轨迹中的策略决策。训练分两阶段：第一阶段在监督序列-结构对上优化干净核苷酸预测器；第二阶段从训练好的RNA-IFlow初始化策略参数，使用PPO风格的裁剪代理目标优化有限策略，同时加入KL正则化保持监督序列先验和交叉熵正则化保留干净核苷酸监督。推理时，RNA-IFlow通过全局传输演化初始单纯形状态再解码，而RNA-IFlow-RL则直接在合法状态空间上均匀初始化每个结构单元，通过H步RL策略生成离散序列，每个目标用K条独立轨迹实现推理预算。

在实验结果方面，该框架在多个基准测试上取得了领先性能，在Rfam-27上达到85.19%的Pass@1，相比RNA-Design-LM SL+RL的81.48%提升了3.71个百分点。进一步分析揭示了热力学增益、策略动态以及在不同设置下的鲁棒性。这项工作的意义在于将协调变异与热力学选择耦合起来，为RNA设计提供了一个新范式。不过，论文也存在一些局限：两阶段训练流程增加了计算开销，RL阶段的轨迹采样和PPO优化需要大量热力学评估；结构保持策略动态虽然保证了配对合法性，但将配对单元的动作空间限制在六种合法状态中，可能在某些情况下限制了探索能力；此外，方法在Rfam-27等基准上表现优异，但在更长序列或更复杂拓扑结构上的泛化能力尚未充分验证。尽管如此，这项工作清晰地展示了将进化中的变异-选择机制引入RNA设计的形式化建模路径，为后续研究提供了可借鉴的框架和方向。

### [What Makes World Action Models Generalize? An Empirical Study of Test-Time Future Modeling](https://arxiv.org/abs/2609.34981)
`评分3 · HF 88赞`

这篇论文要解决的是世界动作模型（WAM）在推理阶段是否真的需要生成未来视频帧这一争议性问题。WAM 的核心思路是在训练时联合预测未来视觉动态和动作，借助从网络规模视频数据预训练得到的时空先验，把动作学习从稠密的状态-动作模仿转变为一种“逆动力学”问题——即让电机指令去对齐预测出的视觉未来。这种未来建模能力被普遍认为是 WAM 比 VLA 模型更鲁棒、更泛化的根本原因，因为 VLA 的主干主要在海量静态图文对上预训练，擅长理解与推理而非生成，缺乏对时间演化的动态理解。然而，早期 WAM 采用“显式范式”，在每个动作块推理时都要把未来去噪成干净帧，再让动作以这些帧为条件，由于视频 token 数量远多于动作 token，这个去噪过程主导了单块推理成本，严重阻碍高频闭环控制。近期一些工作因此提出“隐式范式”，训练时保留视频监督，推理时直接丢弃未来视频 token，报告称在分布内任务上与显式 WAM 几乎无差异，成本却低得多。于是问题变成：推理时的未来生成到底是不是必要的？论文指出，两种范式各自的证据其实都没错，但隐式 WAM 的“平价”结论只在分布内成立，并不能说明它保留了当初驱动 WAM 的泛化优势。

为了把这个问题讲清楚，作者首先建立了一个三轴泛化评估框架：环境扰动鲁棒性（用 LIBERO-Plus 的七个扰动因子，包括机器人初始状态、相机视角、语言指令、传感器噪声、背景、物体布局和光照）、数据效率（把每任务演示数从 40–50 降到 10 后重新训练并分布内评估）、以及任务泛化（在 LIBERO 的 spatial、object、goal、long 四个套件上做四折交叉验证，每次留出一个套件，并区分“无视频”和“有视频但无动作标签”两种设定）。所有对比都严格匹配主干、训练数据和预算，唯一变量是动作专家能否在推理时访问未来 token 表示，具体实现上只差一个结构化注意力掩码。实验得出两个关键发现：第一，去掉推理时未来建模后，隐式 WAM 在分布内与显式 WAM 持平，但在三个泛化轴上全面落后；第二，把未来视频 token 保持在完全加噪状态、只做一次前向传播所得到的表示，就能恢复大部分泛化差距，根本不需要迭代去噪成干净帧。进一步分析表明，这个差距几乎完全来自去噪的第一步——真正起作用的是“准备”未来，而不是“生成”未来。基于这一洞察，作者提出 Simple-WAM：它保留隐式范式的单次前向传播和推理成本，但把未来视频 token 以加噪状态留在策略上下文中，推理时视频专家只跑一次而非跑完整个调度，训练时则把流时间采样向这个推理点偏移，使训练和推理行为对齐。这样一来，两个阶段都不需要为去噪付出代价，却恢复了推理时的未来条件作用。

在结果层面，Simple-WAM 在八个测量指标中的七个上领先显式范式、在全部八个上领先隐式范式：环境扰动下达到 79.5，而显式和隐式分别为 67.7 和 53.8，同时运行速度是显式范式的 3.8 倍，延迟仅比隐式范式高 1.2 倍。这说明显式与隐式之间的选择并不是通常认为的“泛化与效率的权衡”，而是可以兼得的。论文的意义在于，它把此前分散在不同系统、不同主干和预算下各自宣称的泛化能力，统一到一个受控框架里并排比较，明确指认了推理时未来条件作用对泛化的因果贡献，并给出了一个几乎零额外成本的实现方案。局限方面，研究仍主要基于 LIBERO 仿真基准和有限真实任务，评估轴虽覆盖环境、数据和任务三个维度，但尚未触及更开放的场景、更长时程的推理以及不同视频主干规模下的可扩展性；此外，Simple-WAM 把训练噪声调度向推理点偏移这一做法，其最优偏移量是否随任务和主干变化、是否需要自适应调节，也还没有系统回答。尽管如此，这项工作对 WAM 的高效推理设计具有直接指导意义：未来条件作用应当保留，但迭代去噪可以舍弃，这可能会推动后续 WAM 在架构和训练配方上重新思考“未来”在推理时的角色。

### [VisionHOPE: Visual Backbones as Self-Modifying Learning Systems](https://arxiv.org/abs/2609.33325)
`评分3 · HF 78赞 · 有代码`

这篇论文要解决的核心问题是：视觉骨干网络在自适应能力上的演进已经走到一个瓶颈。从CNN的局部卷积聚合，到ViT的全局自注意力，再到状态空间模型（SSM，如Mamba）的输入依赖状态转移，以及测试时训练（TTT）层在推理时用内层学习器做自监督适配，视觉计算对每个输入的适应性越来越强。但关键在于，这些方法中“如何适配”的规则本身始终是由训练好的骨干网络预先规定好的——SSM的token到状态转移的映射是固定的，TTT虽然让内层学习器在推理时更新，但其表示映射和更新规则仍然由外层参数化。换句话说，模型能改变它记住什么，但不能改变它怎么学。这就引出了论文的核心动机：能否让视觉骨干网络在处理一张图像的过程中，不仅修改记忆内容，还同时修改学习规则本身？直接套用Nested Learning（NL）的自指构造会带来严重的训练不稳定问题，因为记忆系统生成控制自身后续更新的量，形成反馈回路，膨胀的记忆转移会逐步累积并导致训练崩溃。之前的方法没有解决这个稳定性障碍，因此无法将自指学习系统真正落地为通用的视觉骨干。

VisionHOPE的核心创新在于将NL的自指原理实例化为一个稳定的自指嵌套学习模块（SRNL），并围绕它设计了三个关键机制。首先是五记忆耦合系统：内容记忆存储视觉上下文，键和值记忆生成用于更新的键值表示，学习率记忆和保留率记忆分别控制每步的更新步长和记忆保留比例。这五种记忆在每次扫描中随视觉上下文累积而共同演化，每个记忆用自己的当前状态变换值表示来生成自指目标，再通过Delta梯度下降（DGD）的保留递归更新自身。DGD与普通梯度下降的区别在于，它用当前记忆对当前键的响应来修正写入信号，即写入的是残差而非原始值，这使得高度相关的上下文元素能被有效修正。其次是稳定性匹配的步长控制方案：论文推导了自指注入的软上限和对保留记忆转移的谱钳制，证明两者结合能保证每次扫描中记忆动态是非膨胀的，从而解决了直接应用自指更新时的训练不稳定问题。第三是面向二维特征图的四方向扫描与分块并行：将NL的分块公式适配到图像的行和列方向，前向和反向的行主序扫描使用行对齐的分块，列主序扫描使用列对齐的分块，四个方向各自维护独立状态，输出按通道融合。分块机制使得块内token依赖的量可以并行计算，只有状态更新按token顺序累积，从而在保持线性计算复杂度的同时实现高效训练。与TTT方法相比，VisionHOPE的根本区别在于：TTT只让内层学习器适配，而表示映射和更新规则是外层固定的；VisionHOPE则让存储内容、更新表示和学习动态作为一个耦合系统共同演化，真正实现了“学什么”和“怎么学”的协同进化。

在实验结果方面，VisionHOPE在ImageNet-1K分类、COCO目标检测和ADE20K语义分割三个基准任务上都取得了有竞争力的结果，覆盖了从层级式到平铺式的多种骨干架构和不同模型规模。这意味着自指学习系统作为通用视觉骨干的可行性得到了初步验证，而不仅仅是一个理论构想。不过，论文也坦诚了当前的局限：五记忆系统的引入增加了模块的复杂度和参数量，稳定性控制方案虽然证明了非膨胀性，但软上限和谱钳制的具体超参数选择对最终性能的影响尚未做充分的消融分析；此外，四方向扫描虽然覆盖了二维结构，但方向间的融合方式较为简单（通道拼接），是否还有更优的跨方向交互机制值得探索。从更宏观的视角看，这篇工作的意义在于开辟了一条新路径：视觉骨干不再只是一个前向传播的特征提取器，而可以是一个在推理过程中持续修改自身学习规则的自指系统。如果这一范式能在更大规模数据和更多模态上得到验证，它可能会改变我们对视觉骨干“训练后即固定”这一基本假设的理解，推动自适应视觉计算向真正的在线持续学习迈进。

### [Breaking the Uniformity Trap: Scaling Video Diffusion Model via SplitMoE](https://arxiv.org/abs/2609.38140)
`评分3 · Accepted as a Spotlight paper at NeurIPS 2026. Project page:`

视频扩散模型正面临一个棘手的扩展瓶颈：DiT架构虽然能生成高保真视频，但参数规模一旦上去，推理成本就变得难以承受。MoE被寄予厚望，因为它能把总容量和激活计算量解耦——每次前向只激活一小部分专家。然而，现有视频生成模型几乎是照搬语言模型的MoE设计，其中最关键的一个假设就是“负载均衡”：训练时加一个辅助损失，强制所有token均匀地分配到各个专家上，防止某些专家被饿死。这个假设在语言模型里工作得很好，因为离散的语法结构天然把token组织成了可区分的语义单元。但视频token完全不同：相邻patch之间高度相关、空间上连续、语义上长尾分布——背景patch数量庞大且重复，前景物体patch虽然语义重要但数量少。强行让路由器把token均匀撒到专家池里，结果就是同一物体的相邻patch被拆散到不同专家，而大量冗余的背景patch却占据了多个专家的容量。作者把这个现象叫做“均匀性陷阱”，并且用实验量化了它：用现成的语义分割掩码把视频token分组后，标准MoE的语义区分度（不同语义类是否被分到不同专家）和路由主导性（同一语义区域是否被一致地路由到同一专家）都很低，说明路由碎片化严重，直接导致生成视频出现结构扭曲和时间闪烁。

SplitMoE的核心思路是把专家池显式地劈成两个功能不同的分支：语义专家和通用专家。语义专家负责捕捉高层语义抽象，通用专家负责保留残差视觉信息和灵活的生成能力。这个分法不是拍脑袋的——它对应了扩散过程本身从粗到细的去噪逻辑。具体运作上，路由器对每个token独立计算语义亲和度和通用亲和度，用的是sigmoid而不是全局softmax，这意味着一个token可以同时与一个语义专家和一个通用专家高度兼容，而不是被迫在所有专家之间做竞争性选择。然后分别在两个分支内做Top-K选择，比如总共激活8个专家时，选2个语义专家加6个通用专家，激活参数量与标准Top-8 MoE完全对齐，保证性能提升不是靠堆计算量换来的。语义分支的路由不是随便学的，而是用一个“原型引导”机制来锚定：维护一组可学习的原型向量，每个原型对应一个语义专家，原型生活在干净的VAE特征空间里。路由器看到的是DiT的token特征，但它的输出分布要被对齐到“这个token的VAE特征与哪个原型最相似”的软目标上，用KL散度做对齐损失，并且对原型那边做stop-gradient，防止路由器把原型拓扑带偏。原型本身则用pull-push机制优化：pull把原型拉向当前batch和历史上出现过的VAE特征，push让原型之间互相排斥、保持距离，防止多个原型塌缩到背景主导的区域。通用专家那边则沿用DeepSeek-V3的无损负载均衡策略，只更新非梯度的路由偏置，不引入额外的辅助损失。语义专家完全不做显式负载均衡，而是靠语义对齐自然实现自适应平衡。这样一来，语义一致的token自然聚到同一组语义专家上，不同语义区域被推到可区分的专家组，路由碎片化被大幅缓解。

在实验上，作者用Wan 2.2的低噪声checkpoint做上循环，把第15到35层中偶数层的稠密FFN替换成MoE层，每层1个共享专家加100个路由专家（20语义+80通用），总参数27B，每步激活14B，与稠密基线计算量持平。在VBench-2.0等标准基准上，相同激活参数预算下，SplitMoE在收敛速度、路由一致性和生成质量上都超过了标准负载均衡MoE，并且与同量级激活参数的其他基线相比有竞争力。更值得注意的是一个涌现行为：没有任何显式的timestep条件路由约束，SplitMoE在去噪早期高噪声阶段自然地把更多容量分配给语义专家，在后期细节渲染阶段则把更多权重转向通用专家——这与扩散模型从结构到细节的生成顺序完全吻合，反过来验证了语义/通用二分法的合理性。局限方面，目前的分支比例和Top-K分配是手工设定的，原型数量和语义专家的对应关系也依赖超参；原型引导依赖VAE特征的质量，如果VAE本身对某些语义属性编码不好，语义路由也会受影响。但这项工作指出的方向很明确：视频MoE不应该照搬语言模型的均匀性假设，而应该根据模态本身的结构特性来设计路由空间，这为后续构建更大规模的视频世界模型提供了一个可参考的缩放路径。
