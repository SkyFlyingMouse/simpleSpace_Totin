### [When Do We Need On-Policy Distillation? Distilling on Offline Student Rollouts Is Often Better](https://arxiv.org/abs/2610.11291)
`评分4 · HF 17赞`

这篇论文追问的是一个在知识蒸馏实践中被普遍默认、却很少被真正检验的假设：on-policy 采样是否总是有益。On-policy distillation（OPD）的核心卖点在于缓解传统蒸馏中的 exposure bias——训练时学生看到的是教师或固定数据集生成的序列，推理时却要面对自己生成的分布，二者不一致会导致误差累积。OPD 的做法是让学生自己生成 rollout，再让教师在这些学生轨迹的每个 token 上给出稠密的监督信号，从而让训练分布与推理分布对齐。但近期一系列工作暴露出 OPD 的若干病态行为：on-policy rollout 会越生成越长、陷入自我纠错循环、耗尽生成预算却不输出 EOS；轨迹后段的监督信号往往无效甚至有害，截断到短前缀反而够用；一旦学生走上错误的推理方向，后续被误导的续写会引出不可靠的教师监督并浪费算力。这些现象指向一个尖锐的问题：对于任意一对教师和学生，on-policy 采样真的总是更好吗？如果学生和教师本来就差距很大，让学生自由发挥再让教师逐 token 纠正，会不会反而把训练推向教师根本不认同的轨迹？

作者提出的替代方案叫 Semi-OPD，思路极其简单：在训练开始之前，用初始学生模型一次性采样出全部 rollout，之后整个蒸馏过程复用这批固定数据，不再重新生成。注意这里的关键细节——虽然 rollout 是固定的，但目标函数与 OPD 完全一致，学生在每个训练步都会用当前参数重新计算自身对数概率，因此逐 token 的优势值（教师对数概率减去学生对数概率）仍然随参数更新而演化，监督信号并非一成不变。这种设计把数据采集与优化彻底解耦：先集中生成学生 rollout，再让教师跑一遍算出教师对数概率，最后在固定数据集上训练学生，三个阶段各自独立，每个阶段都能占满整个 GPU 集群，而不必像 OPD 那样在并发进行的学生生成、教师服务和训练之间切分资源。与 Lightning OPD 相比，Semi-OPD 省去了在教师 rollout 上做 SFT 的步骤，因为作者直接使用指令微调过的学生模型作为起点，这更贴近真实使用场景，而且实验表明那一步 SFT 反而有负面效果。为了量化教师与学生的初始对齐程度，作者采用 top-K 重叠率：在初始学生 rollout 的每个响应位置上，分别取学生和教师各自概率最高的 K 个 token 构成集合，计算两个集合的交集大小除以 K，再对所有响应 token 做加权平均，K 取 64。这个指标为 1 表示二者 top-K 支撑集完全一致，为 0 表示完全不相交，它成为判断该用 OPD 还是 Semi-OPD 的核心依据。

在覆盖 17 对教师-学生组合、参数量从 1.5B 到 235B、横跨 Qwen3、DeepSeek-R1-Distill 和 Nemotron-Cascade-2 三个模型家族、兼顾思考与非思考模式的实验中，Semi-OPD 在 14 对上优于 OPD，最高提升 13.6% 准确率，训练速度最高提升 11.4 倍，剩余三对也仅落后 0.1% 到 2.6%。更关键的是，Semi-OPD 相对 OPD 的增益与初始 top-K 重叠率呈强负相关（Pearson r = -0.73）：重叠率越低，Semi-OPD 优势越大；OPD 只在教师与学生高度对齐时才真正有用。作者对此的机制解释是，有效蒸馏同时需要两种 on-policyness——对学生而言要避免 exposure bias，对教师而言要保证监督信号落在教师自身推理分布之内。OPD 改善了前者却可能牺牲后者：在低重叠率下，学生 rollout 随上下文变长会越来越偏离教师分布，后段 token 的教师监督变得不可靠，而简单截断又会丢掉后段推理阶段的监督信号，实验证明覆盖完整轨迹的各推理阶段对最终性能很重要。Semi-OPD 用初始学生的 rollout，通常比 on-policy rollout 更短，因此在覆盖完整轨迹的同时更好地保持了相对教师的 on-policyness，本质上是拿一部分学生 on-policyness 去换教师 on-policyness。论文的局限在于，它主要针对数学推理任务和特定模型家族，top-K 重叠率作为选择依据虽然有效但仍是启发式的，阈值如何设定并未给出通用方案；此外它并未提出更强的 OPD 变体，而是呼吁社区在选用教师-学生组合时更加审慎，避免在不匹配的设定下得出关于 OPD 的误导性结论。

### [S-Space: Exploring Spatial Workspace in Multimodal Language Models](https://arxiv.org/abs/2610.13527)
`评分3 · HF 201赞`

多模态大模型在空间推理上的表现一直不理想，尤其在需要视角变换的任务上，模型往往连人类轻松解决的简单问题都会出错。以往研究大多停留在端到端的性能对比，只能看到答案对错，却无法回答一个更根本的问题：模型内部到底有没有形成准确的空间表征，失败究竟出在感知阶段还是推理阶段？这篇论文的核心动机正是要打开这个黑箱。作者借鉴人类视觉认知中“心理工作空间”的概念，提出多模态大模型内部可能也存在一个类似的内部空间工作区，用来存放和操作空间信息。如果能找到这个工作区，就能把“模型看到了什么”和“模型拿这些信息做了什么”分开来诊断，从而定位真正的瓶颈。

作者发现并命名了 S-Space，它是模型中间层隐表示中的一个三维线性子空间，分别对应水平、垂直和距离三个空间轴。识别方法很巧妙：对每个相对空间问题（比如“苹果在杯子的左边还是右边”），作者计算答案对比度（即“右”与“左”的 logit 差）对物体 token 激活的梯度，这个梯度指明了扰动物体表示时最能改变空间判断的方向。由于查询物体和参照物体在空间关系中的角色是对称相反的，作者进一步构造角色反对称的梯度差，并在多种提示模板、物体顺序交换和样本上取平均，从而滤除物体身份、措辞、场景上下文等无关因素的干扰，得到三个稳定的单位方向向量。一旦确定这三个轴，读取空间坐标只需要一次前向传播，把物体 token 的隐表示投影到这三个方向上即可得到连续坐标。这个读出方式不依赖识别时用的空间问答提示，即使模型在回答颜色等非空间问题时，物体 token 的表示中依然能读出准确的空间坐标，说明 S-Space 是模型内在的、持续存在的表示结构，而非特定数据或提示诱导出的假象。因果干预实验进一步证明，编辑 S-Space 中的坐标会显著改变空间判断，却基本不影响颜色等非空间回答，说明模型在生成空间答案时确实因果地使用了这个工作区。

在 SpinBench 视角变换任务上，作者用 S-Space 做感知-计算分解：先从 S-Space 读出物体坐标，再施加与目标视角对应的固定旋转，最后用确定性规则得出答案。结果显示，这种显式变换比模型直接生成答案准确得多，即使加上思维链，模型原生推理仍存在明显错误。更关键的是，当作者把正确的源视角关系作为前提提供给模型时，模型的语言回答依然经常出错，但其 S-Space 表示反而变得更准确，并且基于该表示的读出能达到接近完美的准确率。这揭示了一个核心瓶颈：多模态大模型其实能形成足够准确的空间感知表征，却无法可靠地对这些表征进行视角变换和推理计算。此外，方向词读出还暴露了基本方位与图像相对参照系之间的系统性耦合，这解释了模型在参照系混淆上的常见错误。这项工作的意义在于，它把空间推理失败从笼统的“模型不行”细化到了“感知没问题、计算跟不上”，为后续改进指明了方向——与其继续堆数据提升感知，不如针对性地增强模型对已有空间表征的变换和操作能力。局限方面，S-Space 目前只在中间层识别，水平与垂直轴使用图像平面坐标而未显式解耦深度透视效应，且参照系本身会随上下文和思维链逐步重定向，这些都有待进一步研究。

### [SoftwareGym: Scaling Computer-Use Agent Training with Diverse Synthesized Software Environments](https://arxiv.org/abs/2610.12611)
`评分3 · HF 83赞`

这篇论文要解决的是计算机使用智能体（CUA）训练中一个核心瓶颈：缺乏大规模、多样化且可靠的软件环境。现有方法大致分两条路，但都有明显短板。第一条路是在已有的桌面或移动原生应用里合成任务和轨迹，比如基于 OSWorld、AndroidWorld 这类基准，好处是状态真实、工作流复杂，但把真实应用接入可复现的训练环境成本极高，导致能覆盖的应用种类有限，而且反复在同一批固定软件上训练容易产生应用特定的过拟合，模型可能只是记住了某个应用的界面布局而非学会通用操作。第二条路是构造浏览器托管的软件环境，比如 InfiniteWeb、AutoWebWorld 以及后续的 GUI-GENESIS、ScaleWoB，它们用多页面网站或状态机生成 Web 世界，部署和状态控制都很方便，但共享的浏览器/HTML/DOM 底层限制了交互深度和工作流复杂度，很难模拟原生桌面应用那种多窗口、持久化状态和复杂依赖关系。作者指出，理想的 CUA 训练环境需要同时满足三个条件：界面与交互的多样性以支撑泛化、功能可靠性以产生有效且复杂的轨迹、以及可扩展性以低成本扩大环境池。而这三个条件对应三个挑战：同一软件类别内无约束生成容易收敛到相似布局和交互模式，功能可靠性要求每个指定功能都能通过完整 GUI 工作流被验证，可扩展性则要求把多样性控制和可靠性检查应用到大规模软件池上，这种验证负担是人工开发无法承受的。

SoftwareGym 的核心创新在于用一条全自动的多智能体流水线来合成 GUI 软件环境，把上述三个挑战分别用针对性设计解决。整个流水线分三个阶段。设计阶段从极少量人类输入出发，先由 FunctionDesigner 做功能设计，它用四步工作流把一个软件类型扩展成成熟产品的功能规格：先确定目标用户、核心对象和预期操作，再为每个模块补充领域专业功能（如多条件检索、批量操作、历史管理、输入校验），然后把功能串成完整用户工作流并覆盖跨模块状态变化和失败恢复，最后把每个功能记录成实现与评估契约，契约里明确用户入口、用户动作、预期状态更新、可见 GUI 响应和验收检查点。接着 StyleDesigner 做风格多样化，为同一份功能规格生成多个 Avalonia UI 蓝图，每个蓝图对应不同的产品定位、信息架构、交互模式和视觉身份，并且强制任意两个变体至少在两个布局维度上不同，用归一化布局树的树编辑距离来量化结构差异，如果最小成对距离低于阈值就重新生成最不独特的蓝图，这样保证变体是结构上不同而非仅仅换皮。图标和 SVG 资产也由专门智能体生成，同一语义角色的图标在不同变体间要求结构不同而非仅颜色不同。实现与评估阶段把每个设计包变成可运行应用：Coder 按设计包实现完整 Avalonia 应用并记录功能手册，DevCoder 对照手册审计命令绑定、应用逻辑、持久化、启动行为和文件接口并修复缺失实现；然后 EvalTaskGenerateAgent 从功能手册生成 GUI 测试用例，覆盖控件可达性、导航、对象创建编辑、持久化、检索、设置、对话框和文件工作流，每个用例从明确状态开始、只用文档化功能、定义可见检查点，用例集在首次实现后固定并跨修复轮次复用；GUIAgent 用鼠标键盘执行用例并记录交互轨迹、检查点证据、失败位置和修复建议，功能通过率按通过用例数除以总用例数计算，评估报告和失败轨迹返回给实现阶段进行下一轮修复，直到全部通过或版本预算耗尽。此外还有设计保真度检查，每轮 GUI 评估后计算实现应用与 UI 蓝图之间的归一化视觉保真度分数，低于阈值就触发针对性修复，结构检查也比较实现布局与蓝图，确保修复功能时不偏离预期界面。任务合成阶段只使用通过 GUI 评估验证过的能力：先做功能分析，构建证据支撑的功能树，每个叶子记录任务级能力、支持状态、GUI 入口、约束、可观察状态和评估证据，只有引用了通过用例、检查点或交互步骤的能力才标记为支持，未测试、失败或被阻塞的路径全部排除；然后做难度分级，按已验证能力之间的依赖关系把任务分为简单、普通、困难三级，简单任务单一主要目标，普通任务组合相关对象或操作并带必要依赖，困难任务形成多阶段工作流且每阶段建立下一阶段所需状态，每级还分基于文件的任务和空白状态任务；最后任务生成把每个规划工作流转成自然用户请求和可执行评估规格，用户请求不暴露坐标、详细操作路径、能力标识或评估机制，内部规格记录初始状态、结果标准、过程标准和预期最终状态，确定性验证拒绝不支持的能力、不一致初始状态、不兼容资产和不可达最终状态。这套设计之所以比之前方法更好，关键在于它把多样性控制、功能可靠性验证和可扩展性都做成了自动化流水线的一部分：多样性通过强制布局距离和结构差异来保证，可靠性通过源码级验证加基于检查点的 GUI 评估加迭代修复来保证，只有同时通过源码级和 GUI 验证的应用才进入软件库，而整个流程只需极少人类输入就能批量生成，时间和金钱成本远低于人工开发。

实验结果方面，作者用 Codex CLI 智能体配合 GPT-5.5 在十二个类别上合成了 182 个可运行应用，平均 GUI 任务通过率达到 91.5%，每个应用最多精炼三个版本，v1 的 GUI 测试套件跨轮次固定，全部用例通过就提前停止，评估用 Seed 2.1 Pro 在 Ubuntu 22.04.3 LTS 虚拟机上通过鼠标键盘交互执行，每个用例最多 50 步。用这些环境收集的轨迹训练模型后，在严格域外的 OSWorld 基准上 Pass@3 从 41.39% 提升到 56.97%，提升了 15.58 个百分点，而且训练中完全没有使用任何 OSWorld 的应用、任务或轨迹，说明泛化能力很强。在专门构建的 SoftwareGym-Bench 上，这个 120 任务测试集覆盖同样十二个类别，模型达到 40.0% Pass@3，超过了一些更大的专用计算机使用智能体。消融实验验证了流水线关键组件的有效性。局限方面，论文没有明确列出，但从方法本身可以推断：合成应用基于 Avalonia 框架，可能无法完全覆盖真实桌面软件的复杂性和多样性；GUI 评估依赖固定用例集和最多 50 步交互，可能遗漏长尾失败模式；训练模型在 SoftwareGym-Bench 上 40.0% 的通过率也说明合成环境与真实任务之间仍有差距。不过这项工作的重要意义在于证明了合成软件环境可以作为可扩展且可迁移的监督信号用于 CUA 训练，为突破真实应用集成成本瓶颈提供了一条可行路径，后续如果能把合成环境扩展到更多框架和更复杂的工作流，并进一步缩小合成与真实环境之间的分布差距，这条路线有望成为 CUA 训练数据的主要来源之一。

### [VisionWeave: Weaving Elastic Visual Representations as a Native Capability of MLLMs](https://arxiv.org/abs/2610.07987)
`评分3 · HF 55赞`

多模态大模型当前面临的核心矛盾在于视觉信息的分布极不均匀，但主流做法却把图像切成固定大小的 patch 后编码成等长的密集 token 序列。高分辨率图像和长视频帧数一上来，序列长度就爆炸，显存和计算开销成为 scaling 多模态能力的瓶颈。最直接的解法是下采样，但会丢掉细粒度细节；于是出现了大量 token 剪枝与合并方法，比如 FastV、VisionZip。这些方法的问题在于：它们要么依赖启发式规则，要么在 LLM 内部做剪枝，导致训练和推理之间存在分布错配，而且会丢弃任务相关的信息。论文实测发现，在信息密集的输入和 grounding 任务上，这些方法性能严重退化；同时它们常用的注意力权重提取、LLM 内部剪枝等设计，很难集成进 SGLang、vLLM 这类现代推理引擎，实际加速效果也缺乏充分验证。更根本的是，预设的压缩比例无法适应不同视觉内容——有的区域需要精细细节，有的区域用紧凑表示就够。这就引出了论文的核心动机：让 MLLM 原生地学会「在哪里保留细粒度、在哪里用粗粒度、粗到什么程度」，作者把这种能力称为弹性视觉表示编织。

VisionWeave 的实现由两个核心模块构成。第一个是门控空间池化器，它在 ViT 输出的 patch 特征上，对每个 2×2 邻域做一次可学习的池化，生成一个粗粒度 token，与原本四个细粒度 token 共享同一个 MRoPE 坐标框架，粗 token 的位置通过位置插值放在四个细 token 的几何中心。这个池化器不是简单的平均池化，而是先对四个 patch 特征做 LayerNorm 防止大幅值 token 主导，再通过拼接和可学习偏置构造全局上下文，然后用门控网络逐通道计算四个位置的 softmax 权重，最后经过 value 网络精炼后做门控加权求和。关键设计是门控和 value 网络的最后一层零初始化，使池化器初始退化为归一化后的平均池化，训练起点非常稳定。第二个是粒度路由器，它为每个 4×4 patch 空间块维护一个可学习的 query 状态，用块中心的 MRoPE 坐标初始化，然后依次在 ViT 的第 0、13、27 层做交叉注意力探测——每层先做局部注意力只看本块的 16 个 patch 特征，再做全局注意力开放到整帧，共六组独立参数的注意力块。最后用一个线性头输出两个 logits，决定该块用粗 token 还是保留四个细 token。训练采用三阶段自蒸馏：第一阶段冻结其他部分只训池化器，全部用粗表示，以原生前向为教师做 top-512 词表上的前向 KL 蒸馏；第二阶段只训路由器，用可微的软混合代理——分别对特征的方向和模长做插值，避免范数差异干扰方向混合，同时加一个类似 MoE 的 per-sample 平衡损失，目标粗路由比例设为 0.8；第三阶段在硬路由的混合粒度序列上做自蒸馏，池化器和 LLM 可更新，ViT、native merger 和路由器冻结，路由器头带一个离线校准的粗路由偏置，校准目标是 50% token 节省。整个训练是 off-policy 的，教师和学生共享同一教师 rollout，蒸馏温度 1。这套设计之所以比剪枝方法好，根本原因在于粒度决策是端到端学出来的、内容自适应的，而且粗 token 和细 token 在同一嵌入空间和同一 MRoPE 坐标系里，LLM 不需要面对训练推理不一致的分布。

在 Qwen3.8-27B 上，VisionWeave 在八个 benchmark 上实现了 16.5% 到 55.1% 的 token 节省，平均节省 43.0%，同时保留原生性能的 98.9%。作为对比，FastV 和 VisionZip 在固定 50% 节省目标下只分别保留 88.2% 和 87.5% 的性能。跨不同输入分辨率和视频帧预算的评测也显示，它的效率-质量权衡一致优于输入下采样。部署到 SGLang 推理引擎后，端到端吞吐提升 2.30 倍，平均 TTFT 降低 54.4%，平均 TPOT 降低 60.6%。局限方面，论文的验证主要集中在 Qwen 系列架构上，路由器需要探测 ViT 中间层特征，这对 ViT 的可访问性有要求；三阶段训练虽然只用自蒸馏，但 30K A100 GPU 小时的规模对一般团队仍有门槛；平衡损失中的目标粗路由比例和推理时的阈值都是超参数，需要校准。不过这项工作的意义在于，它第一次把弹性视觉表示编织作为前沿 MLLM 的原生能力通过大规模训练建立起来，并且证明了这种能力可以落地到现代 serving 基础设施上产生真实的吞吐收益。它指向的方向是：下一代多模态基础模型应当根据信息内容本身来调制计算量，而不是靠外部剪枝或固定比例压缩来事后补救。

实验在 ProgramBench 上展开，Program-Env 构建了 1648 个覆盖 C、C++、Go、Rust 的训练环境，每个环境都提供参考可执行文件、运行时沙箱、用法文档和黑盒测试。用这些环境上的轨迹微调 Qwen3.8-27B，测试通过率从 34.87% 提升到 42.84%；再叠加 Program-Agent，基础模型和 SFT 模型分别达到 55.71% 和 56.25%，均超过旗舰模型 Claude Opus 4.7，作者还在相同协议下评估了 DeepSeek-V4-Flash-0731。这些数字说明可验证环境的规模化确实能把编码智能体从"听话的代码编辑器"推向主动发现需求、设计系统的软件工程师。局限也很明显：黑盒测试只覆盖有限输入，通过测试只代表在被测行为上一致而非语义等价，测试覆盖阈值和轮数上限仍是启发式设定，环境构建依赖 Claude Code 这类闭源 harness 的可及性，仓库筛选也偏向有明确构建配置的项目。但无论如何，ProgramGym 把程序复现从"难以训练"变成"可规模化训练"，为社区提供了一个可复用的 gym，其反馈驱动构建环境和角色隔离长程工作流这两条思路，很可能被后续的编码智能体训练工作广泛借鉴。

### [Continually Post-training Small Models via Synthetic Self-distillation](https://arxiv.org/abs/2610.13113)
`评分3 · HF 41赞`

持续后训练面临的根本矛盾在于，模型既要学会新能力，又不能丢掉旧本事，而灾难性遗忘在监督微调场景下尤其严重。近期提出的自蒸馏微调（SDFT）提供了一条优雅的出路：它让模型把训练样本放进上下文，由模型自己生成一份「改写版」答案，再以在线策略蒸馏的方式向这份自生成目标学习。这样做的好处是监督信号天然落在模型自身的分布内，因此比 re-invoke、DFT 这类离线策略方法在习得与保持两个维度上都更好。但问题在于，SDFT 依赖两个前提能力——上下文学习和指令遵循，而这两个能力恰恰是参数量较小的模型最薄弱的环节。论文通过实验发现，SDFT 相对普通 SFT 的增益随学生模型变小而单调衰减，在 0.5B 到 3B 这个对端侧部署、延迟敏感场景至关重要的区间几乎失效。更关键的是，作者先做了归因分析：他们用 Qwen2.5-3B-Instruct 在 23 个数学数据集上微调，发现遗忘程度与策略的分布偏移（用微调前后模型的 KL 散度衡量）呈强负相关（Spearman ρ = -0.85）；在固定语料、只改变目标文本「偏移程度」的对照实验中，高偏移的完整 R1 推理链导致域内遗忘和灾难性遗忘，而低偏移的模型自生成且验证正确的解答反而同时提升数学习得并保住编码能力。这直接说明：持续学习的关键不是数据本身，而是监督目标是否停留在基座模型的分布内。而 SDFT 在小模型上失败，正是因为小模型自己生成的「改写」质量太差——平均准确率跌到 60%，还有 8.2% 的情况直接丢掉思维链，等于用劣质信号在训练自己。

SynthSelf 的核心洞察是：既然 SDFT 的本质是「把外部示范翻译成模型自己会说的话」，那这个翻译工作不必由学生自己完成，可以外包给一个只大一点点、同家族的对齐模型。具体做法是，对每个训练样本，用改写提示让对齐模型贪婪解码出一份既保留原答案语义、又用对齐模型自身措辞重述推理过程的版本，然后对这份改写做拒绝采样，只保留答案与金标一致的样本，构成离线数据集，最后在这个数据集上对学生做标准 SFT。这里有两个设计选择值得深挖。第一，从在线策略转为离线策略，看似退步，实则是为了换取拒绝采样的能力——小模型对监督质量极度敏感，必须先过滤掉错误样本，而在线策略蒸馏无法在训练前做这种筛选。第二，对齐模型的选择被形式化为一个约束优化问题：在保证改写质量（可验证奖励高于基座模型自生成）的前提下，最小化学生模仿该改写时的负对数似然，也就是让学生「学起来最不费力」。论文证明，同家族内放大模型规模恰好同时满足这两个条件——Qwen2.5-7B/14B/32B 相对基座的平均 KL 远低于直接用金标示范训练的基线，而跨家族的更强模型（如 Qwen3.5-27B、Gemma-4-31B）虽然生成质量更高，却因为分布差距太大而无法有效降低 NLL。这就引出一个反直觉的结论：分布匹配比对齐器的绝对能力更重要。最终实现只用比学生大一到两档的同家族模型（如 0.5B 学生配 7B 对齐器），算法本身零额外超参、无需调参，流程就是批量生成改写、拒绝采样过滤、在过滤后数据上做 SFT。

在三个领域（科学、工具使用、医学）加一个四学科科学混合集上，SynthSelf 在 0.5B、1.5B、3B 三个规模上全面取得最佳习得表现，同时在 14 个保持基准上与最强基线持平。与使用完全相同对齐器、仅条件不同的离线和在线策略蒸馏相比，SynthSelf 平均习得提升 5.7 到 16.9 个百分点，证明增益来自「分布内示范注入」而非单纯借用了更大的模型。与提示词匹配的 SDFT 相比，习得提升 18.96 个百分点、保持提升 1.68 个百分点，排除了提示差异的混淆。成本方面，用更小的同家族对齐器替代更大的跨家族教师，对齐阶段 FLOPs 降低 69.9%。消融实验确认拒绝采样与离线策略监督的组合是必要组件。局限也很明显：在医学领域，对齐模型本身已完美掌握训练数据，示范注入变得冗余，SynthSelf 相对普通蒸馏没有显著优势；此外方法仍依赖一个同家族、可获取的更大对齐模型，对完全孤立的小模型场景不适用。但总体而言，这篇工作把「分布内学习是持续后训练的关键」这一经验规律提炼为可操作的设计原则，并证明小模型不必自己教会自己——找一个只大一点点的同门师兄代写示范，反而比请一位更强的外门名师更有效。

### [Work2Skill: Capturing Human GUI Experience for Reusable Agent Skill Induction](https://arxiv.org/abs/2610.12984)

这篇论文要解决的是计算机使用智能体（computer-use agent）在面对陌生软件和组织内部工作流时的能力短板。当前 GUI 智能体在界面定位和通用规划上进步很快，但一旦任务依赖用户或组织特有的流程性知识，它们就抓瞎了——比如用户只说“提交我的报销”，却不会告诉你该进哪个内部门户、该附哪些收据、提交前要核对什么。这类知识不在用户指令里，却是成功执行的关键。人类演示天然是这种知识的直接来源，因为人和智能体共享同一套 GUI 交互空间，演示中的控件、动作序列和可见结果都能指导智能体。但问题在于，演示要能被复用，必须把动作放到上下文中去理解，并把工作流规则和任务特定细节分离开。已有方法要么只靠全屏帧和目标裁剪来解析动作（如 ShowUI-Aloha），要么只用前后截图对比（如 Demo2Tutorial），缺少无障碍树（AX）这类结构化 UI 证据，导致它们只能靠视觉定位去猜控件语义，选定的关键帧还可能漏掉瞬态状态和中间操作；而且不同研究用的演示、任务集和执行协议各不相同，结果里混杂了归纳方法的差异和源经验、评测条件的差异，无法公平比较；此外，典型流水线把动作解析和流程抽象固定成预设阶段，一次性把长录像塞进上下文又会造成上下文压力，固定选一个子集又可能漏掉后面才需要的细节。

Work2Skill 的核心设计分三层。第一层是 WorkRecorder，它把屏幕录像、鼠标键盘事件和可获取的 AX 信息在统一的时间轴上对齐，把带时间戳的事件聚合成点击、拖拽、滚动、快捷键等动作，再把这些动作关联到关键帧。目标元素关联靠指针位置和事件时序，辅以窗口上下文和控件语义来消歧；在 Linux 上通过 AT-SPI 点查询和邻近无障碍事件拿到控件的名称、角色和边界。这样每个动作都能同时看到它的屏幕图像、可用的目标信息和周围视频，从而判断到底发生了什么变化，而不是只靠视觉猜。第二层是 WorkDemo-350，这是首个面向可复用智能体技能归纳的同步多模态人类桌面 GUI 演示数据集，包含 64 个 MyPCBench Bounded Action 任务和 286 个 OSWorld-Verified 子任务，共约 8.48 小时录像，每个演示都经过完整性和任务成功筛选，打包成证据片段，方法可以在相同演示上自行选择检查哪些模态和时间区间。第三层是智能体式技能归纳：一个基于 NexAU 的工具使用智能体，在读取任务定义和技能创作策略后，交替进行证据检查和技能撰写修订。它可用的工具包括文件发现与读取、read_visual_evidence 返回带来源路径标签的选定图像、以及 watch_video 和 extract_video_frames 按时间戳采样视频帧。关键在于，它不是在预设阶段里走流程，而是按需主动获取证据——遇到一个含糊的点击，就去查目标帧确认控件，再查后续视频帧确认结果状态；草稿写出来后如果发现缺少约束或未验证的转移，还能回到证据里补充。技能写成 SKILL.md，带 YAML 元数据，创作策略要求把演示特定的输入泛化成任务相关的描述，保留选择规则、计算、依赖、停止条件、可见的完成检查和有依据的恢复步骤，同时保持可见的 GUI 交互，使得执行时不需要源录像。它比之前方法更好的地方在于：证据检查与技能写作共享同一段对话，检查顺序由智能体根据未解决的问题动态决定，既避免了固定流水线把证据检查锁死在预设阶段，也避免了把整段录像一次性载入上下文带来的压力；同时 AX 证据提供了显式控件语义，弥补了纯视觉定位的歧义。

在结果上，用四个执行模型在相同执行设置下对比，Work2Skill 在 MyPCBench Bounded Action 上比对应的 No Skill 基线平均得分提升 4.67 到 10.54 分，在 OSWorld-Verified 的 286 任务子集上提升 3.11 到 7.50 分，并且在所有评估方法中取得最高分和最高成功率。额外实验还测试了同一应用内需求变化下的复用（MyPCBench Jitter）和两个执行模型之间的迁移，以及证据消融和 Pipeline Prompt 对比，用来考察输入模态和归纳提示设计各自的作用。局限方面，论文没有声称技能归纳阶段能验证技能正确性或任务成功——finalize_extraction 只检查输出结构和必需的工具使用，不检查技能对不对；AX 证据的覆盖取决于录制配置和应用的无障碍支持，并非所有应用都能提供完整的控件语义；归纳过程中候选技能不执行，下游评测结果也不作为修订反馈，所以技能质量的上限受限于演示质量和智能体对证据的解读能力。尽管如此，这项工作的意义在于把“从人类 GUI 演示中归纳可复用技能”这件事从各自为战的零散尝试，推进到了有统一采集基础设施、统一演示数据集和可控下游评测协议的可比较研究范式，并且用主动证据获取的思路替代了固定流水线，为后续在更复杂工作流和跨应用迁移上的技能归纳提供了可复用的基线和数据基础。

### [SoloQ: Calibration-Free Quantization for Diffusion Language Models](https://arxiv.org/abs/2610.07121)
`评分3 · HF 33赞`

扩散语言模型（dLLM）通过双向去噪并行生成多个token，在语言理解与推理上已能与自回归模型竞争，但其推理成本随模型规模和上下文长度急剧膨胀：全序列去噪要反复执行昂贵的前向计算，块扩散模型还额外引入内存密集的KV-cache。权重-激活的低比特量化本可缓解这一压力，但现有dLLM训练后量化方法几乎都依赖校准数据。问题在于，dLLM在解码过程中会反复经历不同的掩码状态和去噪步数，激活分布随之剧烈漂移，量化敏感度也随时间变化，因此用固定校准集拟合出的量化参数很难泛化。论文用实验直接展示了这种脆弱性：把校准数据从WinoGrande换成MMLU，同一套基于旋转或二阶信息的量化方法在不同基准上的准确率就会明显波动。这引出一个更本质的问题——与其去追踪一个不断变化的分布，能否把分布变换成一个可预测的、无需校准就能量化的形式？

SoloQ的核心洞察正是把"适应分布"改为"改造分布"。它利用随机旋转的数学性质：任意归一化向量经Haar随机旋转后，方向信息被抹去，各坐标服从固定的、近似高斯的球面边缘分布，且维度越高近似越准。但直接做稠密随机旋转代价过高，已有的RPBH（随机置换块Hadamard）虽然把复杂度降到O(d log h)，却有两个缺陷：初始置换对异常值敏感，块间能量平衡的保证会随最大坐标增大而失效；置换固定后各Hadamard块独立变换，残余的块间能量失衡无法再分配。SoloQ提出K-RPBH旋转，在RPBH之后插入一个Kronecker形式的跨块Haar正交混合器，把各块对应位置的坐标重新混合，从理论上把块间条件方差拉平到全局平均值，使旋转后的坐标边缘分布更贴近高斯目标，量化误差随之下降，同时仍保持结构化旋转的低开销。在此基础上，SoloQ对权重和激活施加同一K-RPBH基，权重旋转离线完成、激活旋转在线执行，然后分两条路走：SoloQ-C用分布匹配的码本，激活用Lloyd-Max标量量化器、权重用E8P格点量化器，因为权重离线可承受搜索开销而激活需要轻量运行时量化；SoloQ-N则直接落到硬件原生的NVFP4格式，用张量级和16坐标块级的动态缩放。此外，SoloQ还引入一个仅含尺度的偏置校正，以极小开销恢复低比特量化丢失的径向分量。针对块扩散模型，它进一步做"提交时刻"KV-cache量化——只压缩已提交块的持久状态，不扰动正在去噪的活跃块，从而把无校准设计扩展到权重、激活和KV状态三者。

在LLaDA、Dream等全序列dLLM以及Fast-dLLM v2、Nemotron-Labs-Diffusion等块扩散模型上，SoloQ在4比特量化下保持了准确率，并在知识与推理密集型基准上超过基于校准的基线；采用NVFP4时峰值内存最多降低2.61倍，端到端推理最多加速2.24倍。它的意义在于证明了dLLM量化不必依赖校准集，而是可以通过旋转把激活分布规整成可解析预测的形式，这为扩散语言模型的高效部署提供了一条更稳健的路径，也把无校准量化从图像/视频扩散Transformer延伸到了离散文本扩散和持久KV状态。局限方面，论文主要聚焦4比特场景，更低比特（如2比特）下的表现、K-RPBH跨块混合器带来的额外在线开销在极长上下文中的实际影响、以及commit-time KV量化对块扩散生成质量的长期累积误差，都还需要更系统的验证；此外方法依赖Hadamard维度可分解为k×h的结构，对不支持的维度需要padding或退化处理，可能引入额外开销。总体而言，SoloQ把"分布可预测性"确立为dLLM量化的新设计原则，后续工作很可能会沿着更激进的比特宽度和更细粒度的状态感知压缩继续推进。

### [Contextual Correction of Parallel Draftsfor Speculative Decoding](https://arxiv.org/abs/2610.12570)
`评分3 · HF 21赞`

这篇论文要解决的是推测解码（speculative decoding）中并行草稿带来的一个结构性缺陷。推测解码的基本思路是用一个轻量级草稿模型一次性提出多个未来 token，再由目标模型并行验证，从而在不改变输出分布的前提下加速推理。近年出现的扩散式草稿器（如 DFlash）尤其有吸引力：它借助深度注意力骨干网络，在一次前向传播中并行预测整个草稿块，避免了自回归逐 token 生成的串行开销。但并行化是有代价的——草稿块内每个位置的预测都无法看到前面位置实际选出的 token，也就是说块内依赖关系被切断了。自回归草稿器天然具备这种依赖，而并行草稿器没有，于是各个位置单独看都合理的预测拼在一起可能前后矛盾，比如同时给“New York”和“San Diego”高概率的草稿器可能吐出“New Diego”。这种不一致会拉低草稿被验证器接受的比例，进而抵消并行带来的速度收益。已有方法如 DSpark 和 Domino 试图通过引入轻量级顺序模块来恢复块内依赖，但它们都是逐位置递归修正，这个顺序模块的延迟落在每个草稿周期的关键路径上，反而拖慢了整体速度。于是核心问题变成：能否在不重新引入顺序模块的前提下恢复块内依赖？

作者的关键洞察有两个。第一，并行草稿器其实往往已经“猜到”了正确 token，只是没有选中它——在 Qwen3-8B 上，当草稿器的 top-1 预测错误时，有 59% 的位置其 top-16 候选里包含了验证器最终选定的 token；而且越往块的后段，top-16 覆盖率与 top-1 准确率之间的差距越大，从第一个位置的 0.12–0.14 扩大到最后一个位置的 0.38–0.45。这意味着修正的本质不是重新生成 token，而是在草稿器已有的候选集合里重新选择。第二，推测验证有一个强烈的不对称性：验证器只接受一个连续前缀，遇到第一个被拒绝的 token 就停止，所以后面位置的改进只有在前面的位置全部被接受时才有意义。修正策略因此应该优先保证前缀质量，而不是优化整条路径的聚合分数。基于这两点，作者提出 DCOCO（DFlash Contextual Corrector）。它只利用单次 DFlash 前向传播产生的隐藏状态、候选 token 的 id 和 logits，为每个位置保留 top-K 个候选，然后对所有相邻位置之间的候选转移进行并行打分——每个位置对之间要评估 K² 个转移，全部 (B-1)×K² 个分数在一次批量操作中算完，不需要额外的草稿器前向传播。每个候选的表示由它的 token 嵌入和所在位置的隐藏状态融合而成，相邻两个位置还共享一个只依赖槽位的 pair state，转移分数由一个两层 MLP 在候选表示、pair state 和两侧 logits 的拼接上算出，输出层零初始化使得训练开始时修正量为零、退化为原始草稿。训练时草稿器和修正器联合优化，标签是验证器在 teacher-forced 上下文下的 argmax token 对，用指数降权的交叉熵损失。推理时最关键的是“前缀优先贪心选择”：既然验证只认连续前缀，DCOCO 就从左到右逐个位置选择候选，每个位置的选择都以前一个位置已选定的 token 为条件，而不是去最大化整条路径的总分。这样只有选择这一步是顺序的，而所有神经打分仍然是并行的，与 DSpark、Domino 那种逐位置运行的顺序模块有本质区别。

在四个验证器骨干和十个涵盖数学、代码、通用生成的基准上，DCOCO 在每一种配置下都取得了最高平均吞吐，覆盖贪心和随机解码、有无扩展推理的场景，相对原始自回归解码最高加速 6.6 倍，比最强的推测解码基线最高提升 18%。更关键的是它在并发服务下的表现：从 1 到 32 个并发请求，DCOCO 的吞吐始终比 DFlash 高 19%–25%，而顺序修正器（DSpark、Domino）的单周期开销随负载增长，最终在 4–32 并发时甚至跌到不如未修正的 DFlash。作者还单独分析了草稿接受率和修正延迟，并用同一套学习到的候选分数比较了不同选择规则，从而把修正器本身的质量和选择目标的影响分离开来。局限方面，论文没有回避：DCOCO 依赖草稿器 top-K 候选里包含正确 token 这一前提，如果覆盖率不足则修正空间有限；它的修正能力也受限于候选集合，无法生成集合外的新 token；此外前缀优先贪心虽然契合验证结构，但并非全局最优路径，理论上可能存在更优的选择策略。不过总体而言，这项工作指出了一个有价值的方向：恢复块内依赖不一定需要顺序神经模块，把修正转化为对已有候选的并行上下文打分、再用符合验证前缀结构的规则做选择，就能在保持并行优势的同时显著提升接受率，而且这种优势在真实并发服务负载下依然成立，这对推测解码的实际部署有直接意义。

这篇论文要解决的是编码智能体评测中一个越来越尖锐的结构性矛盾：静态基准一旦发布就开始过时。SWE-bench 这类基准把真实 GitHub issue 和对应 gold patch 固定下来，任务和参考答案都来自公开来源，随着模型训练语料不断扩张，这些内容迟早被吸收进训练数据，前沿模型甚至能直接复现 gold patch——OpenAI 已因此停止在 SWE-bench Verified 上报告结果。后续工作尝试补救：SWE-bench-Live、SWE-rebench 持续从 GitHub 收集模型训练截止之后的新任务来延缓泄漏，但任务难度仍受限于人类开发者日常遇到的 issue 分布，刷新只带来"更新"而非"更难"；DyCodeEval 一类方法对任务做扰动以防精确记忆，却保留了原始任务与解法；SWE-Bench Pro 选择直接造更难的基准，但每次替换后的难度依然在发布时被冻结。另一条线索是自动造 bug：早期用预定义或学习到的变异模式注入缺陷，多样性受模式集限制；SWE-smith、BugPilot、Self-play SWE-RL 用 LLM 生成 bug，其中 BugPilot 最接近本文思路——它收集智能体在实现新功能时意外引入的回归作为任务，但这类 bug 必须破坏已有测试才会被保留，解题者跑一遍测试套件就能定位，而且任务在评测前就已固定成集。SwingArena 把竞技场形式引入软件工程，让提交者打补丁、审查者写测试，由 CI 判定胜负，但任务仍取自固定的人类 issue 池，只有 oracle 在评测时生成。核心问题因此被提炼为：能否造出一个"自缩放"的基准——任务和判定标准都在评测时刻才产生，事先不存在任何可泄漏的内容，且难度由参与评测的智能体自身能力决定，随它们变强而水涨船高。

SWE-Duel 的答案是把评测组织成红蓝双方互为出题人与解题人的镜像对抗。每一轮里，红方在真实仓库上分三个上下文隔离的会话造题：会话 A 自主探索仓库、选定目标模块、实现一个新功能，并写出功能规格与功能测试，得到仅含功能的 diff；会话 B 拿到规格和该 diff，在其中埋入一个隐蔽 bug 并写出"触发 bug 的测试"；会话 C 则让同一参与者的全新实例只看到蓝方将来会看到的公开包——仓库、规格、含 bug 的 PR diff、功能测试——去盲修这个 bug。一道题要被接纳，必须同时通过三道可执行门禁：功能测试与仓库原有回归测试在含 bug 的 diff 上全部通过（意味着 bug 不产生任何可见的失败测试，解题者无法靠跑测试发现它，只能读代码找），而密封的 bug 测试恰好失败；同时作者自己的盲修会话能修好它。第二道门禁是关键设计，它把"可解性"编码进了任务准入，排除了无解题；代价是任务难度上限被作者自身的找 bug 能力封顶，这是作者明确承认的取舍。蓝方随后在不知道是否存在 bug 的提示下审查这个 PR，可以改代码甚至重写功能，提交修订 diff；判定采用硬合取——仓库原有测试、功能测试、密封 bug 测试三套全过才算蓝方赢，没有部分分。由于 bug 藏在功能内部，蓝方不能靠回滚 PR 取胜，因为那样功能测试会挂。任务在赛前造好存入任务库，同一红方的所有对手面对同一批题，保证可比性；一轮比赛里双方在同一批仓库上互换红蓝角色，各自出题数不足时缺的题直接记蓝方胜，从而惩罚出题能力弱的参与者。这套协议让一次对决覆盖需求规格、功能实现、测试生成、代码审查、故障定位与程序修复的完整软件工程链条。

在 11 个"模型+harness"组合、15 个仓库、5 种语言、共 1500 轮的锦标赛中，领先者以不同方式取胜：GPT-5.5 配 Codex CLI 以最强解题者身份排名第一，修好了它所审查的 98.3% 的缺陷；Claude Opus 4.8 配 mini-swe-agent 以最强出题者身份排名第二，红方胜率 27.3%，说明"会出题"和"会解题"是两种可分离的能力维度。同一模型家族内，最新版本写出的任务击败固定参考解题者的比例远高于旧版本（42.9% 对 4.0%），为"任务难度随出题能力缩放"提供了初步证据。局限也很清楚：自修复门禁使任务不可能难过作者自己的找 bug 能力，强出题者可能反而造出偏易的题；任务库在赛前固定，虽然对单次锦标赛内的公平性有利，却牺牲了"评测时刻即时生成"的纯粹性；红方胜率整体偏低（最高仅 27.3%）也提示当前出题能力普遍弱于解题能力，竞技场的区分度可能更多来自解题侧。尽管如此，这项工作把基准设计从"造更难的固定题库"转向"让难度成为被测量对象的内生属性"，为编码智能体评测提供了一条不依赖人工标注、不惧数据泄漏、且能随能力增长自动升级的路线，其开源工具链也让社区可以自行发起锦标赛或把新智能体接入现有排行榜。

### [Stateless Language Agents: Scaling Long-Horizon Automated Research](https://arxiv.org/abs/2610.07625)
`评分3 · HF 18赞`

这篇论文要解决的是自动化研究系统在长周期运行中“算力越多、进展未必越大”的真实困境。现有系统大多让 LLM 智能体在长时间会话中反复提出、实现并评估候选方案，但论文通过追踪发现，当预算拉长到数亿甚至十亿 token 级别时，智能体往往陷入三种失败模式：不断重放越来越长的历史对话、多个并行智能体重复做同一件事、以及在 token 持续消耗的同时停止真正有价值的实验。作者把根因归结为两个设计选择：研究状态存放在哪里，以及由谁决定下一步尝试什么。之前的方法把研究历史塞进智能体自己的会话里，导致上下文随运行线性膨胀，既浪费 token 又让模型行为退化；同时，记录下来的发现并不会自动转化为下一步实验，CORAL 在 GPU 内核任务上的一个典型运行中，最后一次有效改进出现在 2.31 亿 token 处，之后 98% 的会话不再调用任何工具却仍在消耗 token，说明单纯扩大推理预算并不能保证搜索持续有效。更麻烦的是，多数评测只用短预算或早已饱和的基准，比如 26 圆填充问题在 500 万 token 时四种方法差距已小于 2.3×10⁻¹⁰，这种评测根本测不出上述失败模式，也掩盖了上下文管理和实验选择这类会随经验累积而放大的设计差异。

针对这两个挑战，论文提出“有状态搜索、无状态智能体”的核心原则，并落地为 SLA 框架。关键洞察是把智能体的“状态”和“上下文”拆开：状态是跨调用持久存在的研究状态，由 harness 持有，包括候选方案、测量结果、失败记录等；上下文是单次调用内智能体看到的内容，每次调用都重新构造，绝不继承上一次的对话。具体机制有两块。第一是 harness 控制的上下文重建：每个 epoch，Advisor 收到的是任务说明、当前全局最优代码与分数、以及 harness 生成的证据摘要，摘要按搜索方向分组呈现近期尝试、结果、Worker 状态和进展，并把“测量到的非改进”与“实现、运行时或正确性导致的不确定失败”区分开，避免把一次执行失败误判为方向已穷尽；每个 Worker 则只看到自己的任务分配、保留的候选方案和紧凑的本地反馈，看不到其他 Worker 的工作区或完整历史。第二是证据驱动的工作分配：Advisor 本身也是无状态的，每个 epoch 从当前证据重新审视并下发具体实验，把并行 Worker 分散到不同方向或集中攻坚某个瓶颈，Worker 在若干本地试验中决定如何实现和精炼分配到的任务，harness 会保留每个 Worker 的局部改进，即使它暂时落后于全局最优，从而给替代方案成熟的时间；当 Advisor 重定向某个 Worker 时，该 Worker 从全局最优重新开始，其首个成功评估的候选成为新的局部基线。这样，Worker 模型可以按任务单独选择，协调与实现分离，Advisor 的 token 开销被压到极低。

在结果上，论文在软件工程、内核优化和算法设计三类任务、最高十亿累计 token 的预算下，与 EvoX、CORAL、SwarmResearch 三个近期框架对比。SLA 在每个任务的全预算最终结果上都最好：在 Anthropic 内核优化任务上，配合 Codex 时三次 SLA 运行全部超过九次基线运行，并以少 93% 的 token 达到最强基线的最终性能，配合 Claude Code 时少 84%；在 FrontierSWE 上平均比各任务最强基线高 4.95 分。消融实验从共享检查点出发，去掉 Advisor 上下文重建、Worker 上下文隔离或 Advisor 分配中的任何一项，都会在每次比较中降低平均进展；去掉 Worker 隔离在 1 亿 token 延续中代价是 5 到 11 个周期，但在完整十亿 token 运行中代价高达 224 个周期，说明短视评测会严重低估组件作用。协调成本方面，Advisor 只占 0.24% 到 0.51% 的 token 和 1.2% 到 2.3% 的模型成本，而 SwarmResearch 的 Shepherd 占 8.4% 到 10.7% 的 token 和 6.1% 到 7.4% 的成本。局限也很明显：SLA 在 FrontierSWE 上四分之一预算时还落后于最强基线，全预算才反超，说明方法排序高度依赖评测视界；最佳 Worker 数量和是否用更便宜模型都因任务而异，没有普适配置。这项工作的意义在于，它用可复现的累计 token 预算和多检查点评测证明，把持久研究状态从智能体对话中剥离出来、让 harness 显式决定每次调用看到什么，是让自动化研究随算力持续产生进展的一条有效路径，同时也提醒社区：短视界评测可能误判研究系统及其组件的真实价值。

### [Recurrent Harness for Agentic Continual Learning](https://arxiv.org/abs/2610.12668)
`评分3 · HF 16赞`

这篇论文要解决的是语言模型智能体在长交互流中持续学习时的一个根本性缺陷：现有的智能体“挽具”（harness，即围绕固定LLM的持久化运行时脚手架）几乎都只依赖前向信息流来演化状态。具体来说，智能体在完成一个实例后，会通过记忆或反思机制把经验写入持久状态，之后在新实例到来时检索这些经验来辅助决策。但问题在于，一旦记忆或反思被写入，它们很少根据后续使用效果被更新。虽然有些方法会做增删改查来维护记忆库的一致性，但这些操作只是让记忆库本身保持整洁，并没有把“这条经验在下游任务中到底有没有用、有没有误导”作为反馈信号纳入。另一些方法则依赖额外的训练集或验证集来优化挽具状态，这在严格的在线流式协议下根本不可用。后果是：在持续分布偏移下，过时的记忆或过度泛化的反思会一直留在状态里，反复误导后续决策。论文举了一个很直观的例子：前一个实例要求降序排列，智能体写下“大数在前”的反思；下一个实例要求升序，这条反思被检索出来导致答错；虽然智能体随后写入了“小数在前”的新反思，但旧的错误反思仍然留在状态中，由于查询有重叠数字，它会在后续实例中再次被检索出来继续造成错误。这说明仅有前向路径的有状态挽具在持续学习中是不完整的。

ReHarness的核心创新是在前向读写之外增加了一条反向修订路径，形成一个循环挽具。具体运作分三步：第一步前向读取，给定当前查询，从挽具状态中检索出最相关的k条反思交给决策智能体，环境给出奖励后形成当前实例的轨迹；第二步反向修订，这是关键所在——在观察到当前轨迹后，一个专门的修订智能体逐一重新审视当前实例所检索到的每条反思，利用该反思的源轨迹以及它在当前实例上的实际效果作为反馈，对反思进行修订。修订的目标是：如果当时用的是修订后的版本，当前实例的错误是否就能避免。修订可能包括补充源轨迹中被遗漏的证据、纠正反思中缺乏支撑的假设、或者细化反思的适用条件。这里有一个重要的约束：当前实例的轨迹只能作为评估和修订的反馈信号，修订后反思中的任何新内容必须扎根于其源轨迹，以防止信息泄漏。用修订后的反思替换原反思、保留未被检索的反思，就得到中间状态。第三步前向写入，记忆智能体基于当前轨迹生成新反思，而修订后的反思作为示范，引导新反思捕捉互补的视角而非重复已有内容。最终状态由中间状态和新反思拼接而成。这样，前向读取、前向写入和反向修订共同构成了一个完整的循环：反馈沿着文本挽具状态向后传播，使得过时或过度泛化的经验能在分布偏移后被及时纠正，而且整个过程不需要实例回放、不需要梯度更新、不需要额外验证集，完全符合严格在线流式协议。

在三个持续学习基准（CL-Bench、MemoryBench、MemoryArena）和三个前沿LLM骨干（Claude Opus 4.8、GPT-5.5、Gemini 3.7 Flash）上，ReHarness一致性地超过了强基线，包括原始上下文基线、结构化记忆与反思方法（Mem0、RBank、DoT、ACE）以及提示优化方法（GEPA-Online），所有提升在统计上显著，且在16个评估任务上表现一致，包括大多数基线相对其无状态骨干出现退化的困难场景。消融实验显示，ReHarness不需要很大的修订集就能超过最强的全历史基线，同时只用了大约三分之一的token。进一步分析表明，ReHarness产生的修订是有源可循且有意义的，能够纠正在分布偏移下过度泛化或过时的反思，同时提升持续学习中的稳定性和可塑性。局限方面，论文没有展开讨论修订智能体本身可能引入的错误、修订频率对计算开销的影响、以及当源轨迹本身质量很低时修订的上限在哪里。但这项工作的意义在于，它把持续学习从“只写不回头”的前向范式推进到了“写了还能根据下游效果回头改”的循环范式，为固定参数LLM的在线自适应提供了一个不依赖梯度、不依赖回放、不依赖验证集的新路径，这对构建真正能在长交互流中自我纠偏的智能体系统是一个方向性的贡献。

### [Task Context Shapes Component Roles in Language Models](https://arxiv.org/abs/2610.13895)
`评分3 · 9 pages, 5 Figs`

大模型在不同任务间复用同一套参数，这早已是共识，但"复用"本身并不解释计算过程如何随任务改变。已有的电路分析工作（如Merullo等人）发现不同任务可以共享注意力头甚至共享相当一部分电路，Todd等人也发现少量注意力头能紧凑地编码上下文中的任务信息。然而这些工作回答的是"哪些组件被共享"，而非"共享组件在不同任务中做的事有何不同"。一个共享头在两个任务中可能面对不同的事实输入、也可能以不同方式影响下游计算，这两种变化此前没有被系统区分和测量。本文借用网络神经科学的视角切入这个问题：大脑中相同脑区参与不同任务时，脑区之间的功能连接（functional connectivity）会随任务改变，这种连接模式的变化本身就能区分任务。类比到语言模型，作者想问的是：当图事实（graph facts，即哪些有向边存在）完全固定、只改变任务指令时，同一批注意力头响应的事实和它们对下游的影响是否会发生系统性重分配？为了干净地分离"任务"这个变量，作者设计了一对任务：Compose path要求判断A→B且B→C是否同时成立（即路径A→B→C是否存在），Read direct edge要求判断A→C这条直接边是否存在。两个任务共享完全相同的图事实和答案映射，只有指令不同，因此任何测量差异都只能归因于任务上下文而非输入内容。

方法上，作者在五个开源模型（Gemma-2-9B-it、Qwen3-14B、Llama-3.1-8B-Instruct以及Falcon-H1的1.5B和7B版本）中选取三个由浅到深的注意力头H1、H2、H3和一个更靠后的残差流位置Res，在最终输入位置测量两种量。第一种是影响力（influence），定义为对源头的输出沿其任务方向施加两个标准差的扰动后，下游位置激活投影的标准化变化量，由于所有中间计算保持活跃，这个量捕捉的是包含间接路径在内的总效应。第二种是重要性（importance），定义为将某位置的完整激活向量替换为参考提示上的均值后，正确答案与备选答案之间logit margin的下降幅度。影响力是六个有符号值（三个头对三个下游位置），重要性是四个值，分别构成影响力轮廓和重要性轮廓，用任务均值之间的夹角来衡量模式变化。关键实验是内部任务编辑：作者用对比激活加法构造一个任务向量，即Read fact 2与Read fact 1在参考提示上的平均激活差，然后将它加到Read fact 1条件下的残差状态上或从Read fact 2条件下减去，从而在不改变书面指令的情况下把模型的内部任务状态切换到另一个任务。这个编辑的巧妙之处在于位移量固定、不随图事实变化，因此可以观察同一组头在"内部任务切换"后响应哪些事实、如何影响下游。作者进一步构造了线性响应图：对每个提示，用H2在正负扰动下的输出差作为输入、H3的输出差作为输出，拟合一个从H2位移到H3响应的线性映射，然后检验这个映射能否预测一个独立的事实干预（替换H2输出为参考运行中的值）对H3的实际影响。核心洞察在于：如果任务上下文确实改变了组件间的功能耦合，那么为当前内部上下文定制的响应图应当比两个上下文的平均图预测得更准。

结果层面，任务切换确实系统性地重分配了影响力。在Falcon-H1-1.5B中，H1对H2的平均影响力从Compose path下的-0.0145变为Read direct edge下的0.00101，对H3的影响力翻倍以上（0.0107到0.0238），而对残差位置的影响力反而下降（0.0446到0.0346）。四个模型中影响力轮廓的任务间旋转角度均显著大于重要性轮廓，Gemma中差值为30.17度（置信区间25.54到34.81），Qwen中为11.98度，说明"怎么影响下游"比"对答案多重要"更敏感于任务变化。事实干预实验显示，当被干预的图事实对当前任务是相关的（即正确答案依赖该事实）时，干预对答案的影响显著更强，Gemma中三个事实的任务选择性分别为13.14、14.14和17.24个logit，Qwen中为36.47、37.57和52.46个logit；下游恢复实验进一步确认这些任务选择性效应确实通过后续残差激活传递。最关键的预测实验里，针对当前条件定制的响应图在Gemma中将均方预测误差降低53.6%，在Qwen中降低5.0%，优于两个条件平均图的基线。条件响应分析还表明，在AND任务中，同一个H2位移在目标边能影响答案时比不能影响时产生更强的H3响应。这些发现的意义在于，它把"共享组件"的讨论从静态的电路归属推进到动态的功能耦合：同一组头在不同任务下既读取不同的事实，也以不同强度向后续层传递信息，这种任务依赖的影响力测量或许能指导更精细的干预策略，比如在改变某一行为的同时保留其他行为。局限也很明显：预测增益在Qwen中仅5%，说明线性响应图远未捕捉全部机制；分析集中在少数手工选取的头上，未覆盖全网络；五个模型虽跨四个家族，但结论的普适性仍需更多架构验证。

### [Can Language Models Learn When to Abstain? Policy Learning and Calibrated Answer Selection](https://arxiv.org/abs/2610.13821)
`评分3 · 17 pages, 2 figures, 10 tables`

这篇论文要解决的是语言模型在事实性问答中“不知道却硬答”的问题。现实场景里，模型对没有把握的问题常常给出看似合理但错误的答案，而一个真正有用的系统应当学会在不确定时主动弃权。然而，传统的评分规则往往只奖励正确答案、对错误和弃权不加区分，这会直接鼓励模型去猜——因为只要有一丝答对的概率，猜就比不答更划算。已有工作表明，对错误施加惩罚可以改变这种激励，让模型更愿意表达不确定性；同时，模型自身的置信度信号也能用来筛选可信答案。但问题在于，如何让弃权变得“有选择性”：一个对所有问题都拒答的模型虽然不犯错，却毫无用处。此前的方法大致分两条路，一条是训练生成答案的模型本身去选择回答还是弃权，另一条是固定生成器、另训一个选择器来判断是否放出答案。但现有证据不足以说明在特定模型和算力预算下哪种干预更有效，也不清楚训练带来的改进能否跨数据集保持，以及模型能否泛化到训练时未见过的置信度阈值。这篇论文正是在Qwen3-14B上系统比较这两条路线，试图回答训练是否真的优于校准后的置信度过滤、模型对未见阈值的响应如何、以及改进能否在TriviaQA和NQ-Open之间迁移。

方法上，论文把“回答还是弃权”建模成一个带阈值的决策问题：系统收到问题和请求的置信度阈值后，要么给出简短答案，要么输出IDK。评分规则设计得很有针对性——答对得分为1减阈值，答错扣掉阈值，弃权得零分，这样当模型自认为答对的概率超过阈值时才值得回答，从而在数学上把弃权变成一个理性的期望效用选择。围绕这个规则，作者比较了两大类干预。第一类是策略学习，用LoRA对Qwen3-14B做强化学习式更新，训练时让模型在不同阈值下练习回答或弃权，并比较了四种受控变体：有的把八个采样响应分成两组计算奖励基线，有的把八個一起比较，有的让每个问题在多个阈值下各练一次，有的则固定用平均阈值0.75来算奖励，以此分别检验组大小、阈值暴露 schedule 和奖励是否依赖阈值的影响。第二类是答案选择，生成器完全不动，只额外训练一个LoRA适配器，输入问题和候选答案，用二元交叉熵学习判断该候选是否精确匹配正确答案，再在独立的校准集上做逻辑回归校准，把学到的logit差映射成概率，超过阈值才放出答案。关键洞察在于把“学习一个更有信息量的打分器”和“对已有分数做概率校准”这两件事拆开：他们既测试原始模型的P(True)分数，也测试对该分数做逻辑校准后的版本，还测试用选择器训练标签去拟合同一个标量分数的控制组，从而证明选择器的增益来自学到了新的问题-候选特征，而不是仅仅重新校准了旧分数。所有校准都在TriviaQA上完成，直接迁移到NQ-Open而不重新拟合，这直接检验了跨数据集的泛化能力。

结果方面，在TriviaQA上，学习到的答案选择器在两个保留阈值（0.65和0.85）平均后，把平均覆盖率从原始校准置信度过滤的20.2%提升到30.9%，同时被评分答案的池化错误率从23.0%降到14.5%（按精确匹配评分），这是一个相当明显的效用提升，并且部分人工复核的审计也支持这一发现。但在NQ-Open上，选择器虽然优于置信度过滤，却仍然低于“总是弃权”的基线，说明跨数据集时可靠弃权的问题并未解决。强化学习的几种变体则没有表现出稳定一致的增益，作者也坦承这些RL比较是不确定的。局限也很清楚：精确匹配评分可能把语义正确但措辞不同的答案判错，虽然做了部分人工审计，但规模有限；校准迁移到新数据集后失去了有限样本保证；选择器本身仍是一个二分类器，无法处理需要推理或多跳的问题。这篇论文的意义在于，它用受控实验把“答案选择”的进展和“可靠弃权”的未解难题区分开来，说明在固定生成器上学习一个选择器是当前预算下更有效的干预，但也警示我们，一个数据集上的成功远不等于跨数据集的可靠 abstention，这对后续研究如何评估和设计弃权机制提出了更务实的要求。

### [AI Models Can Provably Hide Arbitrary Capabilities](https://arxiv.org/abs/2610.13928)
`评分3 · 22 pages, 6 figures, 3 tables. Accepted at NeurIPS 2026`

这篇论文要解决的是AI安全评估中一个根本性的信任问题：我们凭什么相信能力评估的结果？当前的前沿模型部署流程高度依赖“能力 elicitation”——通过提示、微调、工具增强等手段去激发模型的潜在危险能力，尤其是CBRN（化生放核）相关能力，如果激发不出来就认为模型不具备该能力。但作者指出，这个假设在对抗条件下根本不成立。他们构造了一类后门攻击，能够在模型权重中嵌入加密的神经网络，只有在收到秘密触发器时才解密并执行。这意味着一个恶意内部人员或供应链攻击者可以在模型中埋入任意计算能力，而防御方即使拥有完整的白盒权重访问权限、可以任意微调、加噪声、做梯度搜索，在密码学假设下也无法恢复触发器或判断到底嵌入了哪种能力。之前的工作要么只有理论上的不可检测性证明但假设过于简化（比如随机特征模型），要么只有经验性的密码锁定模型但缺乏可证明的保证，而且通常是在训练过程中引入后门，对能嵌入什么电路缺乏精确控制。

核心方法建立在“数字储物柜”（digital locker）这个密码学原语之上：它是一段包含加密数据的程序，没有正确密码在计算上无法解密，即使攻击者能看到完整实现。作者用秘密触发器加密一个神经网络的权重，把生成的储物柜直接嵌入到宿主模型的权重中。每次前向传播时，宿主模型都会尝试解密；只有正确的触发器才能恢复权重并执行隐藏能力。为了让这套机制在现代架构（SwiGLU MLP、RMSNorm）中真正跑起来，他们开发了一个编译框架，把算法写成无分支的直线程序，再用线性阈值门（LTG）构建电路，包括Keccak哈希函数和数字储物柜本身，然后通过程序化设置权重把电路编译进PyTorch模型。关键洞察在于：密码学原语通常不是PAC可学习的，所以不能用梯度下降训练出来，必须靠编译精确植入。他们实现了两种执行方式：单位置执行需要大约n²个残差特征来模拟宽度为n的隐藏层，而逐行自回归变体可以把残差特征降到O(n)，代价是需要O(nd)个暂存位置来执行深度为d的隐藏网络。安全性定义分两个博弈：触发器查找博弈要求任何多项式时间审计者找到能解锁隐藏计算的输入的概率可忽略；载荷隐藏博弈要求审计者区分两个等大小能力的优势不超过二分之一加可忽略项。在数字储物柜安全的假设下，这两个性质都成立。

实验上，他们在一个小型的化学反应预测任务上做了概念验证——判断给定试剂能否生成候选产物，作为CBRN相关能力的代理任务。他们用监督微调（SFT）尝试激发隐藏能力，即使直接在这个任务上训练也失败了；还测试了权重加噪、基于梯度的触发器搜索、以及潜在对抗训练（LAT），这些方法都无法突破。这证明了在密码学保证之外，经验上这些 elicitation 手段也拿它没办法。但作者很诚实地指出了局限：隐藏的只是一个小的二分类反应可行性分类器，开销很大，不是即插即用的攻击；密码电路的存在本身可能被检测到，他们主要保证的是触发器和能力不可提取；而且小规模实验设置限制了直接实用性。真正值得警惕的场景是：一个小的隐藏电路可以增强一个本来就很强的宿主模型，在普通评估时保持休眠，却在特定触发下提供网络滥用、CBRN辅助、欺诈或破坏能力——这个场景还有待验证。论文的意义在于把“安全”和“安保”区分开来：对抗压力下需要最坏情况分析，而不是平均情况假设。他们开源了模型来推动防御研究，并指出这类构造也可能作为优化压力下类似隐藏行为的代理，尽管他们不声称普通训练会产生这种密码学结构。

### [Specialists Learn Faster: Knowledge Organization in Pre-training Shapes Knowledge Update Efficiency](https://arxiv.org/abs/2610.13835)
`评分3 · 25 pages, 12 figures, 11 tables. Project page: https://horiz`

这篇论文要解决的是一个在持续学习与知识更新场景中长期被忽视的问题：模型在预训练阶段接触知识的方式，是否会决定它日后更新知识的速度。以往关于知识编辑和继续预训练的研究，几乎都把注意力放在模型训练完成之后——比如用元学习训练一个编辑器、把更新内容存进外部记忆、或者约束更新范围以免破坏其他知识。这些方法默认预训练已经结束，模型的知识组织方式是一个给定的、不可更改的前提。但作者提出了一个更根本的追问：如果预训练时知识呈现的顺序本身就会塑造模型的内部表示，那么这种组织方式是否已经提前决定了后续更新的难易程度？他们聚焦于具有天然时间顺序的传记类知识，构造了同一批事实、两种排列方式：一种是按时间先后排列（chronological），另一种是完全随机打乱（shuffled）。结果发现，按时间顺序训练的模型变成了“专才”——它只擅长最近接触到的知识，对早期知识表现很差；而随机打乱训练的模型变成了“通才”——它在所有时间段上表现都还不错。直觉上人们会认为通才更容易接受新知识，但论文的发现恰恰相反：专才在学习新事实时需要的更新步数远少于通才。这个反直觉的现象构成了全文的核心动机。

为了解释这一优势，作者从优化动力学的第一性原理出发，推导出一个描述更新成本的“步数定律”。这个定律把更新所需的步数N分解为两个因素的比值：一个是预训练模型在新知识上的初始知识差距D0，即旧值概率与新值概率的对数差；另一个是每步微调能缩小多少这个差距，也就是更新速度，它正比于初始梯度g0的范数。定律的形式很简洁：N大致等于D0除以学习率乘以初始梯度范数再乘以一个校准常数A。关键在于，专才虽然在D0上有时反而更大——也就是说它离新知识更远——但它的初始梯度g0要大得多，足以在更少的步数内跨过这个更大的差距。作者进一步用梯度分析说明，时间顺序训练让模型在参数空间中形成了对近期知识的“陡峭”区域，一旦新知识落在这个区域附近，梯度信号就非常强；而随机打乱训练让模型被迫学会用年份等线索来区分同一事实的不同取值，参数分布更均匀、更“平坦”，因此面对新知识时梯度较弱。基于这个洞察，作者设计了一种预训练数据组织策略：对变化缓慢的历史知识保持稳定呈现，对频繁变化的近期知识采用有利于形成专才的时间顺序，从而同时获得通才的广覆盖和专才的快速更新能力。

在实验层面，作者在GPT-2风格的解码器上进行了三个规模（110M、350M、682M）的预训练，覆盖六种语料组织方式，并分别用LoRA适配器执行覆盖式更新和注入式更新。结果显示，专才比通才少用27%到58%的更新步数，而且这个节省比例随模型规模增大而增加，意味着越强大的通才反而越难被更新。他们推导的步数定律在全部18种实验配置下与观测值的皮尔逊相关系数达到0.91，且不重新校准常数A的情况下还能预测继续预训练后的更新成本以及不同学习率和优化器下的表现。作者也把这一发现推广到了真实世界的预训练模型和现有的知识更新工具上，并验证了其他非时间顺序的知识组织方式同样适用。局限方面，论文目前主要基于合成传记数据，真实世界知识的复杂性和多跳推理场景尚未充分检验；此外，专才在早期时间段上的知识保持能力仍然较弱，如何在不牺牲更新效率的前提下更好地保留历史知识，仍是一个开放问题。这项工作的意义在于把知识更新的研究视角从“训练后如何改”前移到了“训练时如何组织”，提示我们预训练数据的排列方式本身就是一种可以设计的、影响模型可塑性的资源。

### [SpatialASM: Internalizing Active Mentalization for Spatial Reasoning](https://arxiv.org/abs/2610.13832)
`评分3`

当前的大视觉语言模型在静态空间感知任务上表现尚可，但一旦涉及视角变换、跨视角对应以及对未观测区域的推理，就会暴露出一个根本性缺陷：它们只会被动地从给定图像中提取关系，而无法主动判断"应该从哪个新视角去看"以及"从那个视角看过去场景应该是什么样"。论文将这种联合能力命名为主动空间心智化（Active Spatial Mentalization, ASM），包含两个互补技能——视角规划（根据问题和当前观测选择任务相关的视角）和视角想象（在脑中构建从该视角看出去的空间布局）。教模型学会ASM之所以困难，原因在于：现有的大规模空间数据集虽然提供了丰富的问答对，但几乎全是"只给答案"的监督信号，没有任何思维链轨迹来展示"如何选择信息量大的视角"以及"如何想象对应的观测"；而让当前的大视觉语言模型自己去生成这些轨迹又极不可靠，它们经常规划出无用的视角、想象出与场景几何不一致的画面。另一条路是在推理时外挂一个世界模型或空间工具来生成补充观测，但这样做把空间推理绑定在了外部模拟器上，而且大多数方法采用自我中心接口，需要通过一系列以相机为中心的动作才能到达目标视角，每次查询都要多步展开。World2VLM虽然在训练时用了世界模型，但它只监督自我中心的视角关联，不产生任何推理轨迹。

SpatialASM的核心思路是把一个他心中心（allocentric）的新视角生成器当作训练时的空间模拟引擎，而非推理时的工具。具体来说，研究团队先微调一个预训练图像编辑模型（FLUX.2-klein-9B）得到SpatialASM-NVG，让它能够根据一组同一场景的图像以及一个他心中心视角定义——即锚定图像上的像素坐标加上该位置的观察方向——直接渲染出从该视角看出去的画面。这里的关键设计在于"他心中心"：目标视角用位置和方向一步到位地指定，不需要像自我中心接口那样指定一系列相机运动指令，从而避免了多步展开。为了评估渲染视角的几何一致性，论文提出了Geometry Perturbation（GeoP）指标：先用一个前馈三维重建模型从原始图像集重建点云，再把渲染视角加入后重新重建，计算两次点云之间的Chamfer距离。GeoP低说明渲染视角能被重建模型解释为同一场景的另一个合法观测，高则说明渲染视角迫使重建模型改变场景几何，即几何不一致。有了这个模拟引擎和过滤指标，SpatialASM将现有空间问答数据转化为两种互补的监督信号。第一种是显式的ASM推理轨迹用于监督微调：对于模型仅凭原始图像答错的样本，先让模型规划出推理轨迹和若干他心中心视角，由NVG渲染对应视图，然后让模型看着渲染视图重新作答；关键在于最终训练数据中渲染视图被替换为描述想象观测的文本字幕，这样模型学到的是从原始输入图像出发在内部构建空间布局，而不是依赖外部渲染。第二种是自动可验证的视角转换任务用于强化学习（GRPO），通过让模型接触来自不同视角的观测，强化视角描述与观测之间的关联。整个轨迹监督的是完整的"规划-想象-推理"流程，而强化学习任务则专门加强视角条件下的想象能力。

在四个来自Qwen3-VL和Qwen3.5系列的主干模型上，SpatialASM在七个空间基准上取得了平均准确率的提升，增益范围从1.2到3.5个百分点。单基准上最大的提升出现在需要空间心智建模和视角变换的任务上，Spatial457-6d上达到8.7个点，MindCube上达到5.2个点。与此同时，通用视觉问答性能在所有四个主干上与基线的差距都在0.6个点以内，说明空间能力的增强没有以牺牲通用视觉能力为代价。这项工作的意义在于，它提供了一条可扩展的路径来缓解空间思维链监督信号的稀缺问题——通过训练时的空间模拟自动合成ASM轨迹，让模型学会主动进行视角探索和心智场景模拟，而不是在推理时依赖外部模拟器。当然，GeoP本身是一个依赖于重建模型的代理指标而非真实几何度量，其可靠性受限于重建模型的能力；渲染视图的质量也直接影响合成轨迹的质量。此外，当前方法主要针对静态场景的空间推理，对于动态场景或需要物理交互的任务是否同样有效，还有待验证。但总体而言，SpatialASM把"何时何地该想象"这一主动空间心智化能力内化到模型参数中，为空间推理的后训练提供了一个不依赖架构修改、可跨主干迁移的新范式。

## 强化学习 RL

### [DiffusionART: Efficient, Stable and Scalable Reinforcement of Diffusion Models](https://arxiv.org/abs/2610.12572)
`评分4 · HF 229赞`

在线扩散模型强化学习面临一个核心矛盾：反向过程方法如Flow-GRPO直接在采样轨迹上做策略梯度，虽然训练状态来自生成器实际访问的分布，但需要将ODE转化为SDE才能计算似然，而且每个转移的梯度更新只携带该转移自身的采样噪声，却被赋予一个轨迹级别的优势估计——这个优势只被该转移部分决定，导致信用分配极为粗糙，训练效率低下。正向过程方法如DiffusionNFT则反过来，对生成的干净样本做前向加噪，用奖励加权的正负目标回归速度场，完全不需要转移似然，效率很高。但DiffusionNFT的稳定性依赖两个精心设计的稳定器：正负联合训练和一个需要逐任务调节滞后系数的EMA rollout策略。论文首先揭示了一个反直觉的现象：单独使用正分支或负分支都会崩溃，但理论上正负分支的理想引导方向应该是共线的，单独一个理应足够。作者通过理论分析发现，NFT的目标函数隐含地假设模型的采样速度等于其自身端点诱导的理想前向速度，而实际中两者存在差距，这个差距引入了一个隐藏的“前向-反向一致性力”。正分支将速度拉向理想前向速度，负分支将其推离，联合训练只能在样本间部分抵消这个力，因为奖励中心化是在prompt级别做的，并不能保证每个状态处都平衡。更糟的是，随着去噪过程推进，状态揭示的端点质量信息越来越多，这个残余力反而越来越大。另一方面，EMA的稳定作用并非来自off-policy数据，而是来自损失函数中保留的旧策略锚点所提供的“恢复力”——它将当前策略拉回旧策略，从而对抗残余的一致性力。但EMA的滞后系数需要逐任务调参，太小的滞后恢复不足，太大的滞后又拖慢训练。

DiffusionART的核心设计正是针对这两个诊断结果。它借用了正向过程训练的监督速度回归形式，但将更新施加在反向过程rollout实际访问的状态和动作上。具体来说，它首先将每个prompt下的多个样本及其奖励聚合为一个共享的“奖励改进方向”，然后对每个访问到的状态，将其动作回归到由这个共享方向引导的目标上。这个目标中完全不涉及前向速度，因此一致性力在构造上就被彻底消除了，而不是依赖跨样本的抵消。同时，每个状态收到的是一个显式的奖励改进方向，而不是通过似然比传递的标量优势，信用分配更加直接和精确。为了替代EMA的稳定作用，DiffusionART在每次rollout后增加一个带信任域掩码的第二更新步骤：这个更新根据每个状态的漂移程度施加一个自适应的恢复力，漂移越大恢复越强。信任域掩码确保恢复不会过度偏离当前策略，从而在不需要任何EMA调度的情况下实现稳定训练。此外，该方法不要求奖励模型可微分，在每个prompt样本数更少时仍然有效，并且支持成对奖励模型（DiffusionART-Pairwise），进一步拓宽了适用场景。

在实验结果方面，DiffusionART在图像和视频生成任务上都展现出了高效且稳定的训练特性，无需逐任务调参。在SD3.5-M上，它的效率匹配了最强基线，但完全不需要EMA。在HunyuanVideo-13B上，使用视觉质量和运动质量等权重的奖励设置，DiffusionART达到DiffusionNFT和Flow-GRPO-Fast晚期平均奖励水平所需的GPU时间分别减少了12.02倍和11.72倍，同时平均训练奖励分别高出28.8%和53.0%。在图像到视频生成任务中，它以比Flow-GRPO-Fast少4.8倍的GPU时间达到了运动质量6的水平。这些结果表明，通过从构造上消除一致性力并用漂移自适应恢复替代EMA，可以在不牺牲稳定性的前提下大幅提升训练效率。当然，该方法目前主要在rectified-flow模型上验证，对于其他扩散参数化形式的适用性还有待探索；信任域掩码的具体设计对最终性能的影响也需要更系统的消融研究。但总体而言，这篇工作为在线扩散强化学习提供了一个既高效又稳定的训练范式，其核心洞察——一致性力的存在与恢复力作为稳定机制的本质——对后续研究具有重要的指导意义。

### [Inducing Process Supervision from Outcome-Only Reinforcement Learning](https://arxiv.org/abs/2609.36641)
`评分4 · HF 18赞 · 有代码`

过程奖励模型（PRM）本应成为大模型推理与测试时扩展的核心组件，因为它能对推理轨迹逐步给出反馈，从而支持更细粒度的信用分配和搜索剪枝。但训练一个强PRM的代价一直很高：人工标注每一步是否正确虽然可靠，却几乎无法规模化；而主流的蒙特卡洛估计方法虽然省去了人工，却需要为每个中间步骤采样大量后续补全，计算开销巨大，更关键的是它把“步骤质量”定义成“从该步骤出发能否到达正确答案”。这个定义存在根本性偏差——一个错误步骤完全可能因为后续的巧合或模型自身的纠错而最终得到正确答案，因此蒙特卡洛标签会系统性地漂移，无法忠实反映步骤本身的内在正确性。另一条路线是用更强模型蒸馏步骤标签，但这又引入了对更强教师模型的依赖和额外成本。于是问题就变成：能否只用轨迹级的结果标签，低成本地训练出真正具备步骤级判别能力的PRM？

这篇论文的核心洞察是：结果验证本身可以从过程验证中获益，反过来，优化结果验证也能倒逼出过程验证能力。具体来说，当把一个LLM当作结果奖励模型（ORM）使用时，它往往会在给出最终判断之前，先在思维链（CoT）里检查中间步骤是否出错——论文展示了一个例子，Qwen3-4B在思考中识别出某一步有误，进而判定最终答案错误。这说明模型本身已经具备潜在的步骤检查行为，只是没有被显式训练。Tips框架正是利用这一点：训练时，模型被要求先生成一段思维链，再输出每个步骤的标签以及最终的轨迹结果标签；但奖励信号只取决于结果标签是否与真实结果一致，步骤标签完全不参与奖励计算。然后使用GRPO（一种无需critic的PPO风格算法），对同一输入采样一组 rollout，根据结果预测的对错计算组内相对优势，并将这个优势应用到整个生成序列的每一个 token 上，包括思维链、步骤标签和结果标签。直觉上，那些在思维中准确检查了步骤有效性的 rollout，更有可能正确判断最终结果，因而获得更高的相对优势并被强化。论文进一步给出了信息论分析：在验证非平凡（即单次前向表示不足以确定结果）且步骤正确性与最终结果强耦合的条件下，结果预测误差低意味着思维链必须编码关于步骤正确性的信息，从而推导出过程信息的下界。这解释了为什么仅用结果奖励的GRPO能够筛选出过程感知的思维模式，同时也指出了该机制失效的几种情形：输入本身就能决定结果、RL未能有效降低结果误差、步骤与结果耦合松散、或基座模型太弱无法表达忠实推理。

实验覆盖数学推理和LLM智能体任务，横跨Qwen、DeepSeek、LlaMa、SmolLM四个基座家族。在ProcessBench上，Tips-Qwen3-4B-Thinking-2507仅用3.2K条结果标注轨迹就达到85.2 F1，超过了所有被评估的已训练PRM（包括用蒙特卡洛标签、强模型蒸馏或人工步骤标注训练的判别式PRM，以及GenPRM、ThinkPRM等生成式PRM），也超过了GPT-5.4-Instruct和Claude-4.7-Opus等强提示式评判模型，但仍落后于o1-mini。在Best-of-8响应选择任务上，Tips同样提升了GSM8K、MATH、College Math、Minerva和OlympiadBench的选答准确率；在AgentProcessBench上，它也能对多轮智能体轨迹中的助手回复给出步骤标签并取得有竞争力的首错准确率。与最接近的弱监督基线AutoPSV和ImplicitPRM相比，后两者在ProcessBench上仅得45.3和41.5 F1，说明仅从结果标签做隐式过程学习而不显式 verbalize 推理过程，无法可靠定位步骤错误。局限方面，论文自己指出当步骤与结果耦合不强、或基座模型能力不足时，过程监督的诱导效果会显著减弱；此外，训练仍然依赖结果标签，在完全无标注的场景下无法直接应用。总体而言，这项工作把“结果奖励”和“过程监督”之间的单向依赖关系翻转为双向促进，为低成本构建PRM提供了一条不依赖人工步骤标注和蒙特卡洛估计的新路径，也暗示了RL训练中思维链的隐性过程监督价值可能被长期低估。

### [A Privileged Teacher That Only Scores Cannot Search: Critique-Conditioned On-Policy Self-Distillation for Reasoning](https://arxiv.org/abs/2610.13744)
`评分4 · Accepted as an oral at the FLLMPT workshop, NeurIPS 2026`

基于可验证奖励的强化学习虽然能提供可靠的正确性信号，但它的粒度太粗——一个推理轨迹要么对要么错，验证器并不会告诉你中间哪一步决策导致了最终结果。在组相对策略优化这类方法中，当某个问题的所有采样轨迹都失败时，组内相对优势会完全消失，梯度为零，而这些“全错组”恰恰是模型能力边界上最需要学习信号的地方。在线策略自蒸馏被提出来解决稀疏性问题：让同一个模型先作为学生生成轨迹，再作为教师、在上下文中加入参考答案等特权信息后对这条轨迹打分，学生和教师分布之间的差异就提供了每个 token 上的密集信号。但密集不等于有效信用分配。这篇论文直接检验了这个假设：如果信号真的有 corrective credit，它应该在推理出错的位置更大，并且应该压低学生错误 token 的概率。作者在逻辑谜题和竞赛数学的标注错误片段上测试了两种自蒸馏信号——全分布 KL 和 token log-ratio——结果发现它们既不定位错误，也不纠正错误，甚至无法可靠区分同一问题下正确与错误的轨迹。作者认为这个失败是结构性的：定位推理中的错误本身就是一个搜索问题，而一个只负责打分的教师从未被明确要求去执行这个搜索。

核心洞察在于，同一个模型、同样的特权信息，如果被允许生成一段批评而不是仅仅打分，它就能显著更好地定位错误。于是作者提出 critique-conditioned self-distillation：先让模型生成对当前轨迹的批评，批评的形式是逐句引用错误句子并解释原因，然后把这段批评作为特权上下文喂给打分教师，再像之前一样对学生轨迹进行 token 级别的评分。这样，生成过程完成了对错误的搜索，打分过程把找到的错误转化为密集的 token 级信号。作者用匹配的安慰剂批评（来自另一个问题的批评）来控制纯粹由“解决方案形状的前言”引起的分布偏移，并定义了两个探针：localization 信号衡量特权上下文在错误位置引起的分布变化是否比干净区域更大，correction 信号衡量它是否降低了学生实际写出的错误 token 的概率。实验表明，在批评条件下，教师分布的变化集中在错误片段，correction 信号在错误片段内为负，并且概率会向“Wait”“But”“Actually”这类启动回溯的 token 偏移。作者还做了消融，分别检验引用和解释的作用，并测试了不同规模的批评者，包括学生自己批评自己。

在结果层面，论文报告了多个关键数字：在 Knights & Knaves 和 DeepMath 两个任务上，参考条件打分的 error-span Z 在 localization 上接近零甚至为负，在 correction 上也没有达到负值标准；而批评条件则显著改善了这两个指标。在测试时推理中，把批评放入上下文后继续生成，可以解决模型通过采样无法解决的数学问题；在冷启动 GRPO 中，批评为那些可验证奖励完全无法提供优势信号的提示提供了优势信号。论文也指出了局限：批评的质量依赖批评者能力，小模型自批评时定位成功率下降，且批评可能包含不精确的引用或格式错误；此外，当前实验规模有限，尚未在大规模训练中验证该方法能否持续扩展。尽管如此，这篇工作把“密集反馈从何而来”这个问题从损失函数设计推回到了计算本身——定位错误需要生成式搜索，而打分只能把已经找到的错误转化为可蒸馏的信号，这对未来过程监督和自蒸馏方向具有重要的方法论意义。

### [RSI-Anything: Unlocking Recursive Self-Improvement with World Models](https://arxiv.org/abs/2610.13912)
`评分3 · HF 30赞`

递归自我改进的核心目标是让系统把交互经验转化为持久的能力提升，但现有方法面临一个根本性两难：要么依赖昂贵的外部反馈来驱动每一轮改进，要么用世界模型预测替代真实反馈，可一旦策略发生更新，世界模型的预测就可能变得不可靠。问题在于，策略更新会改变候选动作的分布和经验的来源，使得原本训练好的世界模型在新策略下预测失准；反过来，世界模型更新又会改变候选排序和想象轨迹，进而影响策略学习收到的信号。这意味着单独优化策略或单独优化世界模型，都不保证两者组合后的联合表现更好。已有的自训练和偏好优化方法虽然能在单轮内改进策略，但缺乏对“何时该更新哪个组件、更新后是否该保留”的系统性判断机制，导致递归循环要么因外部反馈成本过高而难以持续，要么因预测失准而积累错误。

RSI-Anything 的核心设计是把世界模型嵌入递归循环的每一个关键决策点，并用一套更新与保留协议来管理策略和世界模型的异步演化。它建立在 JEPA-Anything 之上，后者通过正交预测分解将潜在目标拆成互补因子，分别学习专用预测器再重组为完整潜在状态，从而为跨域世界模型构建提供共享基础。在 RSI-Anything 中，世界模型首先用于预测引导的候选选择：策略在给定状态和目标下提出一批候选动作，世界模型对每个候选预测其结果或进行有限步展开，验证器记录有效性、效用分量和不确定性，然后按效用减去不确定性惩罚来排序，只把预算允许的候选送去执行或评估。这样做的好处是在外部反馈有限时，把反馈资源集中在最值得评估的候选上，而不是盲目试错。更关键的是反馈驱动的改进环节：外部反馈被分成策略改进数据和世界模型适配数据两个独立集合，策略可以通过示范学习、偏好学习或工作流搜索来更新，世界模型则用观测到的结果目标来校准预测读出。但更新不是无条件接受的——系统会做组件级检查，评估策略的任务效用或预测器在相关目标上的质量，还会做兼容性检查，判断更新后的策略和世界模型配对后，在候选选择行为上是否真的比旧配对更好。只有通过检查的配对才会被保留，并塑造下一轮的候选生成和学习经验。这种异步更新加配对保留的机制，使得策略和世界模型可以各自演化，但系统整体始终维持一个经过验证的可靠组合，从而把每一轮的经验真正转化为下一轮改进的起点。

实验覆盖了代码修复、GUI 交互、实验室规划和反应优化等多个领域，结果相当有说服力。在代码修复中，固定代码生成器不变，仅把静态验证器换成世界模型预测选择，成功率就从 26.3% 提升到 29.2%，再经过世界模型适配进一步升到 31.2%，而在线测试用量基本持平。GUI 任务完成率提高的同时，平均动作数减少了 39.4%，说明预测引导的选择让交互更高效。实验室规划在连续五个策略版本上把得分从 21.80% 翻倍到 46.01%，展示了递归保留带来的累积改进。反应优化在相同 40 次实验预算下达到 96.15% 的平均最佳产率，显著高于贝叶斯优化的 82.16%。这些结果说明，把世界模型预测与反馈驱动的更新保留机制耦合起来，确实能在有限外部反馈下实现跨域的递归提升。局限也很明显：世界模型的可靠性评估依赖于历史反馈对候选范围的覆盖，如果覆盖不足，系统只能给出“评估不充分”而不是“可靠”的结论，这在高维或全新候选区域可能限制适配触发；兼容性检查虽然能防止劣化配对被保留，但也可能让一些需要多轮才能显现收益的更新被过早拒绝。此外，当前框架的验证主要在相对结构化的任务上，开放环境中状态和动作空间更复杂时，预测器的不确定性估计和配对检查的计算成本会成为新的瓶颈。不过，这项工作把递归自我改进从“单组件迭代”推进到“策略-世界模型联合系统的保留式演化”，为在反馈稀缺条件下构建可持续自我改进的智能体提供了一个可操作的范式。

### [Designing Protein Structures from Natural Language](https://arxiv.org/abs/2610.13917)
`评分5 · 53 pages, 9 figures. Code, data, and model weights: https:// · 有代码`

从头看这篇工作要解决的真实痛点：蛋白质从头设计（de novo design）的核心诉求是生成具备指定结构与功能的蛋白，而现有生成模型（RFdiffusion、Chroma、Proteina 等）虽然能实现条件控制，但每一种属性都需要专门设计一种输入表示——折叠类别用类别标签、二级结构用逐残基的 H/E/L 序列、对称性用对称群参数、结合界面用接触残基列表。这意味着模型能支持的设计目标范围被输入接口本身锁死：你想控制一个训练时没设计过对应表示的新属性，就得重新工程化输入、甚至重训模型。更麻烦的是，当设计者想同时指定多个跨尺度的约束（比如"主要是 α 螺旋折叠、含两个二硫键、且与靶标形成约 15 个界面残基的接触"），这些异构表示很难拼接到一起。文本到图像生成的经验表明自然语言可以充当统一的条件接口，但蛋白质领域此前要么只在推理阶段用文本引导（Chroma 的做法，控制力弱），要么用文本先生成序列再折叠成结构（Pinal、BioMatrix，结构与序列的联合精细控制被割裂）。所以这篇论文的动机很明确：把自然语言变成蛋白质结构生成的一等条件接口，让一个模型通过同一套语言输入覆盖从全局折叠到残基级接触的各类设计目标。

方法上的关键洞察有三层。第一层是数据：作者构建了 Prompteina-Data，把 PDB 实验结构、AlphaFold DB 预测结构和 Teddymer 合成二聚体按单链拆分成约 180 万条目，每条目挖掘最多 59 种注释（折叠类别、紧凑度、二硫键、催化位点、蛋白-蛋白接触等），再用 Qwen3-235B 针对注释子集生成描述性 caption，共 5240 万条，平均每条目 29 条，并用 LLM 裁判验证质量（召回 97.8%、精度 89.8%）。关键是这些 caption 不只是全局功能描述，还带有残基位置信息，因此能构造"文本片段—残基"的对齐标注。第二层是条件注入架构：模型基于预训练的 Complexa 全原子结构生成器，加了两条文本通路——全局属性用 Qwen3-Embedding-8B 的池化嵌入经 adaptive layer normalization 广播到每个残基，残基级属性则让每个残基通过 cross-attention 去 attend Qwen3-8B 的 token 状态，且 cross-attention 放在蛋白 self-attention 之前。消融显示两条通路组合最优。第三层是文本-残基对齐监督：作者把对齐标注表示为残基×token 的二值矩阵，训练一个辅助对齐头预测每对残基-token 的 logit，用带正负样本加权的 sigmoid 损失监督（正样本稀疏，故按负正比加权），思路借鉴文本到图像扩散里的分割掩码 token 级监督。训练分三阶段：先冻结 denoiser 只训新初始化的文本条件参数，再解冻做文本条件持续预训练，最后冻结 denoiser 微调文本投影器、cross-attention 和对齐头。推理时用与 Complexa 相同的随机微分方程采样，配合 classifier-free guidance 调节文本条件强度，冻结的 VAE 解码出全原子结构和氨基酸序列。这套设计之所以更强，是因为它让同一套语言嵌入既能在全局层面调制整个去噪网络，又能在残基层面精确指定哪些位置该形成二硫键或参与界面接触，而对齐头进一步把文本 span 和残基 span 的对应关系显式监督起来，使"文本说到的位置"和"结构生成的位置"真正绑定。

结果层面，结构属性控制上 Prompteina 在 5 组共 18 个任务中领先 15 个，覆盖折叠/拓扑、二级结构、三级结构、全局形状与表面性质、以及折叠类别与二级结构或二硫键计数的组合；在 CATH 类别上接近专用的 Proteina，在 CATH 架构、紧凑度和螺旋计数上超过各属性专用模型，只有在链/片层计数上输给接受逐残基二级结构输入的 RFdiffusion。功能规格生成上，用 ProTrek 对比序列-结构-文本编码器评估 122 个蛋白家族，Prompteina 在最佳 prompt 格式下两项相似度指标均值最高，pLDDT 加权后显著优于 BioMatrix 和 Pinal。结合剂设计上，界面残基数的请求值与实现值的 Spearman 相关达 0.994，说明语言能近乎线性地控制界面大小；在 20 个靶标中至少 13 个超过所有基线，界面置信度比最强基线高 14%；允许迭代 in silico 反馈时，在最难靶标上相对非迭代生成的增益比次优基线大 57%。最有说服力的是湿实验验证：针对 GM2A（此前无报道的 de novo 结合剂，且是先前某次 campaign 中三个无命中靶标之一）设计 89 个候选，表面等离子共振测出 9 个结合剂，最强表观 KD 为 107 nM。局限也很清楚：模型一次只生成一条链，复合物场景需要分别生成再组装；对齐标注依赖正则和 TF-IDF 匹配，能覆盖的注释类型受限于可自动抽取的文本 span；链/片层这类逐残基二级结构控制仍不如专用模型；湿实验只验证了一个靶标，通量有限。但整体意义在于，它把自然语言确立为蛋白质结构生成的有效条件接口，使语言模型智能体可以直接用自然语言把设计规格传给结构生成器，而不必翻译成受限于模型接口的固定输入，这为语言推理与迭代优化深度融入蛋白质设计打开了一条统一通路。

### [Inference-Time Steering Across Scaffolds and Epitopes for Sample-Efficient De Novo Nanobody Design](https://arxiv.org/abs/2610.13844)
`评分4`

纳米抗体从头设计面临的核心瓶颈在于计算资源的浪费。当前基于扩散模型和流匹配的生成方法通常采用“大量生成后筛选”的范式，即先均匀采样大量候选结构，再用昂贵的下游评分器（如结合能计算或界面置信度评估）逐一过滤。问题在于，不同靶标、不同生成配置下的可行候选产出率差异极大，导致大量算力被消耗在评估注定失败的样本上。推理时引导方法如Feynman-Kac引导通过在采样循环中嵌入评分函数来缓解这一问题——它利用Tweedie公式从噪声状态估计去噪后的骨架结构，对高奖励轨迹进行克隆、对低奖励轨迹进行淘汰，从而将采样分布偏向高质量区域，且无需微调生成模型。然而，这类方法仍在一个固定的生成配置内优化：对于纳米抗体而言，框架序列决定了互补决定区的几何构型、稳定性、免疫原性以及生成产出率，而靶标表位和热点残基的选择同样事先未知其可行性。一旦在生成开始前就锁定了框架或表位，就等于把全部预算押注在一个可能根本不产出的条件上。引导本身还会加剧这一问题，因为它把昂贵的评估从生成后移到了生成循环内部，使得错误配置的代价更高。因此，条件选择本质上是一个推理时的预算分配问题，而非单纯的轨迹优化问题。

论文的核心创新在于将条件选择形式化为资源分配，并设计了两种动态分配器。第一种是全局序贯蒙特卡洛方法：不再为K个候选配置各自维护独立的粒子群，而是维护一个统一的、包含N个粒子的联合系统。每个粒子携带一个累积对数权重，在每次引导事件时，粒子的即时奖励增量被加到其历史权重上并在全局归一化。关键之处在于，重采样是在整个粒子群上全局进行的——表现差的粒子被淘汰，表现好的粒子被复制，而复制后的粒子可以跨越条件边界，自动流向更有产出的配置。预算分配不是显式指定的，而是通过粒子在不同条件间的动态迁移自然涌现。第二种是解耦的批式逐次淘汰方法，将条件选择建模为多臂老虎机问题：每个配置作为独立臂被引导，总预算分轮次分配，每轮结束后按终端验证分数的九十分位数排名，确定性地淘汰排名后50%的臂，存活臂均分下一轮预算。这两种方法的关键区别在于：全局SMC依赖循环内的即时奖励做全局重采样，而批式逐次淘汰使用正交的终端验证分数做淘汰决策，因而对循环内奖励欺骗更具鲁棒性。在引导机制层面，论文采用基于ESMFold2预测的界面pTM作为循环内奖励信号，通过BoltzIF生成CDR序列后重折叠复合物来计算，并比较了固定节奏重采样和基于有效样本量低于半数粒子数时触发的自适应重采样两种策略。

在BHRF1和PD-L1两个靶标上的实验表明，自适应全局SMC引导将每GPU小时可设计骨架的产出率提升了近5倍（BHRF1从1.41升至6.82，PD-L1从2.21升至10.81），解耦的批式逐次淘汰也取得了2.4到3.1倍的吞吐量提升，且未牺牲跨独立运行的结构多样性。消融实验进一步揭示了两者的贡献是可叠加的：仅用批式逐次淘汰做分配而不做轨迹引导，产出率已优于基线；但引导加分配的组合同比无引导的分配组产出更多通过验证的设计。然而，论文也暴露了一个关键局限：全局SMC在PD-L1实验中将53%的粒子分配给了8z8v来源的框架，原因是该框架在ESMFold2上得分很高，但最终AF2-M验证通过数为零，说明循环内奖励与终端验证之间存在系统性偏差，即奖励欺骗。批式逐次淘汰由于使用正交的终端验证分数做淘汰决策，能够缓解这一问题，但代价是需要串行多轮评估，在离线验证成本极高的场景下不适用。此外，所有指标均为计算代理，高pTM并不保证体外亲和力或稳定性。这项工作的意义在于将静态的框架和表位约束转化为可优化的动态变量，为生成式分子设计中长期被忽视的条件选择问题提供了一个推理时资源分配的框架，未来方向包括将分配器适配到与湿实验相关的代理指标上。

### [MORAD: Reinforcement Learning with Multi-Objective Rewards for RNA Inverse Design](https://arxiv.org/abs/2610.13305)
`评分4 · 18 pages, 5 figures. Jixin Tang and Ji Guo contributed equal`

结构条件RNA逆向设计要解决的是给定一条目标三维骨架、生成能折叠回该构象的核苷酸序列，但这是一个典型的一对多问题：同一条骨架可兼容多条序列，因此模型需要建模条件序列分布，并同时兼顾结构兼容性与序列可恢复性。此前的方法大致分两条路线：gRNAde、RDesign、RiboDiffusion、RIDE等生成模型提供了较强的初始分布，但只做前向生成，缺乏基于新样本实测属性的后训练闭环；而LEARNA、RIDER、SOLD等强化学习或偏好优化方法，要么为每条目标骨架单独训练一个策略、导致权重无法复用，要么依赖离线偏好数据，无法在线利用折叠预测器、热力学软件等反馈。核心矛盾在于：如何训练一个可跨多条骨架共享的在线RL策略，并让异质、量纲不一的多个设计指标协同驱动更新，而不是只盯着三级结构质量。

MORAD的关键设计分三层。第一层是训练接口：以预训练RIDE为初始化，维护可训练策略、指数滑动平均采样策略和冻结参考三套参数；对每条目标骨架，用滑动平均策略采样一组候选，组内用相对奖励归一化（GRPO式）把不同骨架的难度差异消掉，再转成候选权重，喂给DiffusionNFT风格的前向过程更新——把干净序列加噪后，用正负两个去噪分支的位移把相对奖励变成更新方向，同时用参考项约束不要偏离预训练去噪器太远，β只缩放位移惩罚、不改变奖励信号强度。第二层是奖励构造：不再只用三级结构，而是联合六项测量——GDT-TS、TM-score、RMSD衡量RhoFold+预测结构与目标骨架的吻合，二级结构MCC衡量候选与天然参考的配对一致性，归一化系综缺陷衡量候选热力学系综下与参考配对的期望核苷酸级偏差，再加一个碱基组成偏差项。每项先经带锚点的截断升余弦映射到有界“合意度”，再用加权几何平均聚合，权重为0.25/0.30/0.30/0.05/0.05/0.05。几何平均的好处是：在固定权重下，奖励对最低的那项分数最敏感，从而逼着策略不要牺牲任何一项去换另一项的极端高分；结构三项占85%权重，但三个辅助项仍直接参与候选排序。第三层是数据：527条训练骨架、153条评测骨架，评测集独立构建，包含71条RNA3DB组件和82条RCSB条目，长度15–186 nt，与训练集序列最大相似度中位数仅0.62，避免记忆式泄漏。

在153条评测目标上，MORAD相对预训练RIDE把GDT-TS从0.3300提到0.3827（+16.0%），TM-score从0.2841提到0.3400（+19.7%），RMSD从9.72 Å降到7.92 Å；二级结构配对MCC从0.6110提到0.7295（+19.4%），精确率、召回率、F1全面领先；归一化系综缺陷从0.3906降到0.2830（-27.5%）。与RiboDiffusion、gRNAde、RDesign相比，它在三级结构精度、二级结构配对和热力学质量上全面占优，16项有方向性指标中14项最佳，仅序列恢复率和pLDDT输给RiboDiffusion。值得注意的是，配对指标是用RNAfold和EternaFold测的，而奖励里只用RNAfold打分，说明提升并非单纯过拟合奖励工具。局限也很明显：序列恢复率没有同步提升，说明结构精度与天然序列似然之间存在张力；评测仍以计算预测器为主，缺乏湿实验验证；共享策略虽跨骨架复用，但每条新骨架推理时仍需一次条件采样，且奖励中结构三项必须可用，辅助项缺失时虽可重归一化，但会改变优化目标。总体而言，MORAD把“共享策略+多目标在线RL+前向过程更新”这套组合在RNA逆向设计上跑通了，为后续把更多实验可测属性纳入奖励、以及把该范式迁移到更复杂的RNA功能设计提供了可复用的技术路线。

## 其他

### [Learning Representations to Guide Pixel Diffusion Transformers](https://arxiv.org/abs/2610.12978)
`评分3 · HF 22赞`

这篇论文要回答的问题很具体：在像素扩散 Transformer（pDiT）里，什么样的“表征”才真正对生成有用。作者先做了两组诊断实验，结论都挺反直觉。第一组，他们把 JiT-B/16 的中间层用 REPA 对齐到 DINOv2，对齐层本身的 RMSC、LDS 和线性探测精度都明显变好，说明语义和空间结构确实被注入了；但这些增益在后续层里迅速衰减，网络越接近像素预测，外部注入的语义越被“覆盖”掉。生成结果也印证了这一点：REPA-4 在训练早期加速明显，但大约 160 个 epoch 后被 baseline 反超，最终 FID 是 4.80 对 4.56；把对齐放到更深的第 6、8 层，FID 进一步恶化到 5.38 和 8.33。作者的解释是，pDiT 的逐像素监督几乎可以被局部操作满足，模型没有动力去形成和利用高层表征，这类似 ViT 里的“lazy aggregation”。第二组，他们检验了另一条常见路线——用专门的像素解码器把表征学习和像素合成在结构上分开，比如 PixelDiT、DiP、DeCo。结果发现，这些解码器并没有产出更适合生成的表征，而只是重新分配了语义建模和空间建模的负担：解码器空间建模能力弱，编码器就被迫保留更多空间信息，全局语义反而变弱。代价还不小，PixelDiT 参数量多 55%、FLOPs 多 67%，FID 却只和 vanilla 打平（4.26 对 4.17），DiP 和 DeCo 更是退化到 6.09 和 9.17。两个洞察合起来就是：表征必须既被“正确地形成”，又被“真正地使用”，缺一不可。

Representation Guidance（RG）的设计正是围绕这两点展开，而且刻意保留了朴素的 Transformer 架构，不引入专用像素解码器。整体沿用 DDT 的解耦结构：编码器负责表征学习，解码器负责像素合成，所有 block 仍是 JiT 架构，解码器只通过一个表征 r 与编码器交互，r 以 token-wise adaLN 条件的形式注入。第一个关键模块是编码器输出和解码器输入之间的低维线性瓶颈，它把编码器 token 压到一个紧凑的隐空间再升维回来，作者称之为“隐式潜空间”。这个瓶颈的作用是强制生成相关信息被组织成简洁的表征，而不是让编码器把什么都塞进去。第二个关键模块是引导目标。训练时以 0.1 的概率把 r 置零，此时同一个网络只能依赖类别条件，输出的是无条件速度；把有 r 和无 r 两种情况下的速度差作为“表征诱导的速度偏移”，再把这个偏移加到 flow matching 的目标速度上，并用 stop-gradient 阻断它回传到参考分支。这样一来，模型被显式地推向“更依赖 r”的方向，同时梯度也会穿过 r 回流到编码器，让表征本身在生成目标下被端到端优化。作者在附录里证明，收敛时 RG 会把 r 对预测速度的贡献放大约 1/(2−s) 倍，相当于在训练阶段就把分布朝与 r 一致的低维语义流形上锐化，这和 CFG 在推理阶段锐化分布是不同层面的操作。引导只在 t 大于某个阈值时启用，并先做一段普通 flow matching 预热，因为高噪声阶段的表征不可靠；偏移量用 EMA 网络计算以保证目标稳定。这套机制和自监督里的自蒸馏共享同一个核心思想：表征从模型自身预测导出的目标里 bootstrap 出来，只不过自蒸馏锐化的是 teacher 分布以得到判别性特征，RG 锐化的是沿表征诱导偏移的速度目标，从而逼着表征去编码生成所需的语义和空间结构。

在 ImageNet 256×256 上，RG-XL/16 拿到 FID 1.55，RG-L/16 只用 459M 参数就达到 1.79，明显优于参数量大得多的像素空间模型；512×512 下 FID 为 1.74；扩展到文生图后，GenEval 得 0.89，DPG-Bench 得 87.1。更重要的是它在参数和计算两个维度上都呈现出更优的 scaling 曲线，内部表征的语义和空间组织也明显更清晰。局限方面，论文没有回避：RG 依赖一个低维瓶颈和引导超参，瓶颈维度、RG scale、引导时间区间这些都需要调；引导目标用 EMA 网络计算，带来额外的前向开销；高噪声阶段被排除在引导之外，说明这套机制对表征质量的假设在扩散早期并不成立。此外，诊断实验主要基于 base 规模、200 epoch 的 ImageNet 设定，更大规模、更多模态下这些结论是否依然成立，还需要进一步验证。但它的方向性意义是清楚的：像素扩散要获得好的生成表征，不必不断堆叠更精巧的像素解码器，也不必一味追求更强的外部预训练特征，关键在于让表征在生成目标下被正确地形成，并被生成过程真正地消费。
