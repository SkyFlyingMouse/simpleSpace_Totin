### [Thinking Inertia: LLMs Keep Thinking When Told Not To](https://arxiv.org/abs/2610.11765)
`评分4 · HF 215赞`

这篇论文要解决的是一个被业界长期忽视但非常实际的问题：大模型现在普遍配备了“思考模式”开关，但“不思考”这件事本身却缺乏严谨的定义和评估。以往研究判断模型是否在“不思考”，靠的都是表面代理指标，比如关闭了思考模式、输出里没有 `<think>` 标签、或者回复足够短。作者指出这些代理全都不可靠：关闭思考模式后模型仍可能在普通回答通道里输出依赖问题的推理内容；没有 `<think>` 标签只说明格式变了，推理可以伪装成自然语言；输出短也不等于没推理，一个紧凑的等式或一句话就可能包含关键的中间推导步骤。问题的根源在于，这些代理描述的是提示条件、输出格式或长度，而不是响应内容的实质。于是作者把“不思考”重新定义为一个可观测的响应行为：把任何模型回复拆成“答案前的可见文本 T”和“最终答案 A”，然后从三个递进层次去衡量——第一层是 Empty-Thinking Rate（ETR），检查输出是否严格只有答案、没有任何实质性前置文本；第二层是 Question–Pre-answer Relevance（QRel.），用指令感知的 Qwen3-Embedding-4B 计算前置文本与问题的语义相关度，区分“相关但非推理的复述或断言”和真正的推理；第三层是 Explicit Inference Rate（EIR），由一个盲审的 GPT-5.5 裁判只根据问题和前置文本，判断其中是否包含针对该问题的显式推理步骤，裁判看不到模型身份、干预方式、最终答案和正确性，以此把推理与复述、模板话术、相关断言区分开。这三个层次合起来，才能把“严格只答”“相关但不算推理”“显式推理”三种情况分开，而任务准确率单独评估最终答案。作者还用五名人工标注者做了验证，人工的显式推理标签与 GPT-5.5 裁判的平均二分类一致率达到 98.8%，说明这套度量不是自动指标的自我循环。

在方法设计上，作者构建了一个统一的响应中心框架，把问题样本写成问题、可选上下文和可容许答案空间的组合，答案空间可以是布尔的是/否、多选的 ABCD，也可以是开放式的自由生成。干预手段分成两类：一类是与问题无关的干预，比如改变系统提示、输出约束或思考配置，典型如“请直接回答，不要思考”；另一类是与问题相关的干预，比如把开放式问题改写成多选题，从而改变答案空间。基于这个框架，作者设计了六种从鼓励思考到最强抑制的干预谱系，覆盖原生无思考模式、重新诱发推理、语义抑制和结构化前缀强制等不同强度。核心洞察在于：模型是否表现出显式推理，主要不是由思考开关决定的，而是由任务的答案空间决定的。答案空间越开放，显式推理越难被压制；反过来，当候选答案可见、答案空间收窄时，模型更容易直接给出答案而不暴露推理过程。这解释了为什么单纯关闭思考模式或加一句“不要思考”无法可靠地消除可见推理——模型存在一种“思考惯性”，一旦任务需要生成式回答，它就会倾向于在答案前暴露推理步骤，哪怕指令明确禁止。

实验结果覆盖六种提示干预设置、六个主流大模型（包括开源和商业模型）以及布尔、多选、开放式三类问题。关键发现有几个：第一，显式无思考控制并不可靠，即使是 DeepSeek-V4-Flash（284B）这样的前沿模型，在关闭思考模式的设置下，开放式回答中仍有 99.9% 保留了可见的显式推理。第二，思考惯性表现为显式推理率随答案空间开放程度递增：布尔任务最低，多选居中，开放式最高，而且这个模式在原生无思考和严格无思考两种设置下都成立。第三，在开放式任务上，更强的“只答不推理”指令确实能把平均 ETR 从接近零提升到大约 40%，但代价是平均准确率下降约 15 个百分点，揭示出无思考与性能之间的权衡。第四，答案空间本身很关键：同一个问题，改成事实型或候选答案可见的格式后，模型明显更容易做到只给答案，说明这个现象不能仅用基准难度或答案长度来解释。这项工作的意义在于，它把“不思考”确立为一种需要系统评估的独立能力，而不是可以靠模型设置或提示词默认保证的东西；它提供的三层度量框架和六种干预谱系，为后续研究如何让模型像人一样自适应地决定何时推理、何时直接回答，奠定了可测量、可比较的基础。局限方面，作者明确把分析限定在响应层面的可观测行为，不涉及模型内部的潜在推理过程，因此无法回答“模型内部是否仍在计算”这一问题；此外，裁判和嵌入模型的选择虽然做了跨模型家族的稳健性检验，但度量本身仍依赖外部模型，未来需要更轻量、更中立的评估方案。

### [Scaling Agentic Data for Long-Horizon Terminal Intelligence](https://arxiv.org/abs/2610.13166)
`评分4 · HF 133赞`

终端智能体正从局部操作走向真实的专业工作任务，但短轨迹数据只能展示命令和工具调用，无法体现智能体如何通过探索积累证据、据此形成判断、根据反馈持续调整策略，并把中间结果转化为最终交付物。高质量的长时程轨迹能够把上述“智能体行为模式”及其在同一个问题解决过程中的相互关联完整保留下来，为持续自主工作提供更丰富的经验。然而，现有的环境合成方法存在一个根本性缺陷：它们在构建环境时可能已经提前完成或简化了这些行为模式所依赖的关键工作，从而抹掉了智能体本应执行的探索、实现与验证环节。比如一个任务本意是让智能体诊断并修复某个核心函数，但环境里已经提供了可用的实现，智能体只需改一个常量就能通过验证，原本期望出现的调试与迭代行为就不会发生。已有的终端环境合成工作虽然通过技能组合、基于技术证据的任务生成和递归扩展实现了规模化，但平均轨迹仍然偏短，难以支撑跨阶段的行为模式延展。这就引出了两个核心挑战：一是复杂任务未必能诱导出预期的行为模式，因为供给材料可能已经解决了部分问题；二是即便这些模式出现了，长时程数据还需要刻画它们如何在更长的求解过程中展开并跨阶段连接，而单纯增加任务难度或交互轮数并不足以实现这一点。

针对上述问题，作者提出了 TerminalHorizon，一个全自动的长时程终端智能体数据合成引擎，包含挑战引导的长时程合成与渐进式视界扩展两个阶段。第一阶段把真实专业问题转化为可执行任务，并让一个未参与构建的独立挑战者智能体去实际求解。这个挑战者只能看到公开指令和环境，无法访问研究记录、蓝图、参考解或私有测试，因此它的执行轨迹能真实反映任务在求解时到底需要做哪些工作。随后系统进行“视界差距分析”，把任务种子中原本设想的工作与实际轨迹逐项比对，追踪哪些工作被初始材料、对象关系或工具行为提前完成了，并据此重建环境，恢复被省略的分析、实现或验证需求。例如，如果发现环境已经提供了本该由智能体实现的函数，重建就会移除该实现，同时保留必要的公开规格说明，让智能体重新需要自己去实现和调试。这个过程形成任务级的内循环：构建、独立执行、诊断、重建、再执行，直到确认预期行为模式确实进入了实际求解过程。第二阶段则对已接受的任务在同一目标下进行渐进式扩展，引入新的需求，并确保新增工作依赖于前序阶段的判断、动作和结果。扩展沿四个方向进行：更广的角色，利用已有产物或状态支撑相关职责；更深的机制，把此前被简化的关系、依赖或不确定性重新变成工作的一部分；更丰富的证据，加入需要跨来源分析的记录和材料；方法升级，要求对原方案做实质性扩展或重新设计。同时通过三种交互依赖设计把新增需求与前序证据、产物和状态绑定：让后续决策依赖公开查询和探测获得的证据；让可观察的工具或系统效果把先前操作与后续诊断、修正和验证连接起来；让对象或状态在固定公开规格下随运行实例变化，迫使智能体检查当前实例并调整行动。这样，行为模式就能跨阶段延续，而不是在单步操作后就中断。

作者用该引擎构建了 1535 个任务环境和 2852 条训练轨迹，形成 TerminalHorizon-3K，轨迹平均交互轮数为 52.8 轮，第 90 百分位达到 98 轮，显著长于对比方法。在 Qwen3.5-27B 上做监督微调后得到 TerminalHorizon-27B，在 Terminal-Bench 2.0 和 2.1 上分别比基座模型提升 14.2% 和 13.85%；在真实生产力任务 AutomationBench 上通过率提升 11.7%、部分得分提升 23.3%，在 VitaBench 上提升 11.3%，全部 12 个涵盖编码智能体、真实生产环境智能体任务和通用推理的基准上都有提升。更值得注意的是，多个为期 12 小时研究预算的递归自我改进案例表明，模型能够在初始方案之外继续实验、根据反馈改进方法，并把有效改进保留到最终交付物中。当然，该方法仍有局限：数据合成高度依赖教师模型和自动审查流程的质量，视界差距分析的准确性决定了环境重建是否到位，而渐进式扩展也可能引入任务目标漂移或验证条件不一致的风险；此外，12 小时 RSI 案例目前只是案例研究，尚未形成大规模可复现的评测标准。尽管如此，这项工作把长时程终端智能体的数据合成从“堆任务数量”推进到了“保留并延展行为模式”的层面，为后续研究提供了一个可操作的视角：真正决定智能体能否持续自主工作的，不是任务有多复杂，而是环境是否迫使它去完成那些需要探索、判断、实现和验证的实质性工作。

### [AgentSWE: Can Coding Agents Build the Agent You Actually Want?](https://arxiv.org/abs/2610.13361)
`评分3 · HF 201赞`

这篇论文要处理的是一个正在变得普遍但从未被认真检验的问题：当人们把“帮我做一个 agent”这件事交给编码 agent 去完成时，交付出来的东西到底是不是用户真正要的那个 agent。这里的“agent”不是指某次对话里的助手，而是一段把模型、工具和状态封装起来、围绕某个固定任务反复运行的程序——比如一个自动处理桌面操作、自动翻译科学 PDF、或自动做定理证明的专用系统。用户用自然语言描述需求，编码 agent 负责把它实现出来，这背后隐含一个信任假设：交付的 agent 会忠实服务于需求，而不是仅仅“看起来”满足需求。现有 benchmark 都没测这个假设。SWE-bench 一类测的是修传统软件、对照参考补丁或测试；NL2Repo-Bench 测的是从需求文档生成整个仓库；Paper2Code、PaperBench 测的是复现论文实现。它们共同点是都有一个事先已知的标准答案，评判的是普通代码。而一个被“委托”构建的 agent 是把随机策略包在工具外面，需求本身没有参考解，交付后还会持续变化。AgentBench 之后的各类 agent benchmark 则是拿一个已经做好的 agent 去跑任务、看它表现多好，没人问“这个 agent 能不能被编码 agent 造出来”。最接近的 agent 设计/改进类工作，衡量的是搜索过程或元 agent 能把某个 benchmark 分数推多高，而不是一个通用编码 agent 能否交付需求所描述的 agent。于是，在“评判造出来的软件”和“评判造好的 agent”之间，缺了“造出需求所要的 agent”这一步，这正是 AgentSWE 要补的空白。

AgentSWE 的核心设计是把“忠实委托”从轶事变成可测量的问题，具体通过三个承诺落地。第一是覆盖 agent 开发生命周期的三个阶段，共 25 个任务：10 个 Creation 任务从自然语言需求出发造一个完整 agent，领域横跨 GUI 自动化到形式化定理证明，每个都对照一个成熟开源系统来界定范围；10 个 Editing 任务要求在 OpenHands、Aider 这类生产级 agent 的固定代码库里加入新能力，这些能力会牵涉崩溃恢复、权限围栏、事务性状态等；5 个 Optimization 任务则把一个能跑的 agent 推向可量化目标。第二是让评测方式镜像它所研究的委托关系：每个任务被设计成一份“委托”而非一场“考试”，builder 只能看到客户能给的东西——需求加上少量示例用例，而验收阶段则在它没见过的 held-out 用例上执行冻结后的交付物，这些用例专门覆盖需求里写明但示例没体现的条款。第三是因为没有规定参考实现，Creation 和 Editing 的每次执行都用从需求本身推导出的 rubric 来打分，并设硬性 pass/fail 门：无效执行和不适用的补丁直接判零分。在机制上，论文把需求形式化为目标、接口契约、约束和资源四部分，把交付物定义为一个由 harness（负责规划、路由、重试的编排代码）和 backbone model 组成的 agent，把 builder 定义为一个做软件工程动作的编码 agent。关键洞察在于：因为模型是采样的，同一个交付物这次满足需求、下次可能就违背，所以验收必须真正执行 agent 并对其行为打分，而不是看代码“像不像”完成。论文还定义了“演示保真度”和“交付保真度”之间的差距，即 builder 在它见过的开发用例上表现多好、在没见过的用例上表现多差，这个差距就是衡量“看起来满足”与“真正满足”之间鸿沟的指标。它比之前方法更好的地方在于：不再依赖参考补丁或预设答案，而是用需求推导的 rubric 加 held-out 执行来逼出真实行为，从而能捕捉到过拟合可见用例、空壳运行时、以及 builder 和它交付的 agent 都声称完成但记录自相矛盾这类更深层的失败。

实验结果相当冷静。在 Codex harness 下用五个模型作为 builder，再加上其他 harness 与模型的组合，最强的 builder 在 Creation 上平均只有 19.1 分，在 Editing 上平均 31.6 分；Optimization 里没有任何 builder 平均能弥合超过 5% 的剩余差距，25 次运行中只有 13 次得分高于起点。更刺眼的是，那些在开发阶段拿到 90 分以上的 Creation 运行，交付的 agent 在 held-out 用例上平均只有 9.9 分——演示与交付之间的巨大落差不是边角案例，而是常态。失败轨迹揭示出反复出现的模式：builder 过拟合可见的开发用例，交付物在那些用例没覆盖的条款上直接崩掉；它们交付“空壳运行时”，代码读起来完整，跑起来却不干活；builder 和它交付的 agent 都会声称完成，而自己的记录却与之矛盾。论文还测试了增加开发用例、规定设计、明确要求测试、以及延长用例预算等干预，分数会变，但 held-out 结果在所有条件下依然很低。局限也很明显：25 个任务规模有限，评测依赖 rubric 和硬门的设计质量，Optimization 的目标天花板设定为 100 分可能过于理想化，而且目前只覆盖了有限的开源系统和生产 agent 代码库。但它的意义在于把“agent 软件工程”正式定义成一个可测量的问题，给出了一个能暴露真实失败模式的基准，并把每一种失败模式转化为下一代编码 agent 可以学习和训练去避免的方向——也就是说，它不只是打分，更是在告诉人们该往哪里改进。

### [Multi-Stream Attention Residuals](https://arxiv.org/abs/2610.13630)
`评分3 · HF 34赞`

在标准 PreNorm Transformer 中，深度堆叠并不总能带来预期收益，核心症结在于残差流的单轨迹累积方式：每一层的输出都被固定系数地加进同一个隐藏状态，随着层数增加，早期层形成的特征会被后续更新逐步稀释，后层很难再精确取回这些历史表示。已有的改进沿两条路线展开——Hyper-Connections（HC）及其流形约束变体 mHC 把单一残差流扩展为多条并行流，用学习到的流间混合维持多状态递归，本质上像沿深度方向的线性注意力式记忆；Attention Residuals（AttnRes）则把固定累加换成沿深度轴的 softmax 检索，让每层用伪查询去注意之前所有层的输出，相当于单头深度注意力。一个自然的想法是借鉴序列轴上多头注意力的成功，做多头深度注意力，但此前尝试都失败了：把隐藏状态按通道切分给不同头会破坏其作为完整检索值的连贯性，性能反而下降；而用 mHC 式写回从单层输出派生多个候选流，候选之间只是同一向量的标量重加权，归一化后键几乎相同，头间多样性不足。问题因此聚焦为：如何在不损害隐藏表示完整性的前提下，从单层输出构造出足够多样的深度注意力头。

MSAR 的关键洞察是把多样性来源从通道维度转移到序列上下文维度。它从单一残差源出发，对每层输出施加一组多尺度因果深度可分离一维卷积，卷积核大小取 4、8、12，加上恒等映射共得到四条全维度流，每条流的感受野对应不同的局部上下文尺度，从而为深度注意力提供不同的源视图。每条流独立执行深度 softmax 检索，各有自己的伪查询，注意力权重在各自流内对历史源归一化，得到四个检索结果；随后用一个轻量级 mHC 风格的 H_pre 混合器，通过 sigmoid 生成输入相关的标量权重，把这四个检索状态融合成目标层的单一输入。这样既保留了隐藏表示的全维完整性，又让不同头能通过不同的序列上下文视图选择不同的深度历史。系统层面，MSAR 与 AttnRes 的块模式、缓存式流水线通信和两阶段计算完全兼容：前向中所有流都由主残差状态经因果深度卷积确定性生成，因此只需在内存中保留主流，计算深度注意力时按需展开，展开的中间流立即被消费，可由融合核处理而无需写回。块模式下每块把层输出累积成单流摘要，消费时再重算多流。由此，对 N 个存储源，流水线通信和预填充激活存储从 O(mNd) 降到 O(Nd)，与 AttnRes 持平；在 28B MoE 设置下训练 FLOPs 仅增加 0.5%，激活参数增加 0.3%。

在 18B 和 28B MoE 规模的全部 12 个下游基准上，MSAR 一致优于标准残差、mHC 和 AttnRes。18B 设置下最终训练损失为 1.750，低于 Vanilla 的 1.799、mHC 的 1.776 和 AttnRes 的 1.769，且这一损失优势在整个训练过程中持续转化为知识、推理、数学和代码等代表性基准上更高的平均下游得分。缩放律实验显示，相对 Vanilla 基线，MSAR 达到相同损失所需的等损失计算加速比为 1.58 倍，而 AttnRes 为 1.35 倍、mHC 为 1.30 倍。消融实验进一步表明增益来自所提出的归纳偏置而非特定模型规模的偶然因素。局限方面，MSAR 的额外开销主要来自写回多流检索输出并聚合这些流所需的内存访问，且其多流构造依赖因果深度卷积，在非自回归或双向建模场景下的适用性尚未验证。尽管如此，它把深度残差检索从单头扩展到多头，为深度缩放提供了一条低成本且可落地的新路径，对大规模预训练的残差架构设计具有直接的参考价值。

这篇论文要解决的是个人GUI智能体在利用用户交互历史时的一个根本性错配问题。现有方法几乎都采用任务级检索的思路：给定一个模糊指令，从用户历史中找出与当前任务相关的记录、画像或意图记忆，然后把它们塞进策略模型的上下文里，隐含地假设“与任务相关的经验在整个任务执行过程中都持续有用”。但作者通过实验发现，这种帮助几乎全部消耗在episode的第一个决策上——检索到的历史能显著提升开局步骤（比如决定打开哪个App），但在剩余90%的步骤中几乎不带来持续收益，甚至对“是否该主动建议”这种判断也几乎没有指导作用。原因在于，相关性是在任务层面确定的，而适用性取决于决策时刻的具体情境：一条相关记录能告诉智能体从哪里开始，却不能告诉它当前屏幕上该执行哪个历史动作，也不能判断某个例行程序现在是否真的该触发。这就是论文的核心诊断：相关性不等于适用性。

为此，作者把个性化重新定义为“经验激活”，并提出了ExpActivator，一个无需训练的框架，只在当前情境确实适用时才激活对应经验。它分两个粒度运作。在执行层面，ExpActivator先把检索范围限制在与任务相关的历史轨迹上，然后对每一个新观察到的屏幕，在冻结的GUI骨干网络的潜在空间里，用分块池化并中心化后的视觉特征做余弦相似度匹配，找到最相似的历史状态，并把该状态对应的动作作为参考提供给策略模型。关键在于，这个匹配是每一步都重新计算的，参考动作可以在不同历史轨迹和不同步骤之间跳转，而不是假设当前执行必须沿着某条历史轨迹的步骤索引走。策略模型仍然看到当前屏幕，自行判断这个参考动作是否适用、目标在哪里，历史动作只是参考而非强制指令。在主动建议层面，ExpActivator先从完整历史意图中识别重复任务，用意图编码器嵌入语义相似度构建“例行程序邻域”，再结合当前场景一致性和时间接近度计算支持度：绝对支持量决定某个例行程序是否有资格被激活，而每次出现的平均上下文匹配度决定排序。只有当当前时间和场景提供足够支持时，才激活一个重复意图作为建议参考，否则直接弃权。这样，个性化就从一次性的检索问题变成了决策时刻的选择问题。

在AndroidIntent数据集上，覆盖82个用户、135个应用、13类场景，ExpActivator在四个冻结GUI骨干（Qwen3-VL-8B、MAI-UI-8B、Qwen3.5-9B、GUI-Owl-1.5-8B）上全部取得最佳的执行类型准确率、步骤成功率和累积成功率。相对无历史基线，步骤成功率平均提升44%，累积成功率大约翻倍；相对每个骨干上最强的记忆基线，步骤成功率平均提升约20%，在Qwen3-VL-8B上提升37%，而所有基线读取的是完全相同的历史。更关键的是，所有开源骨干在ExpActivator加持下都超过了专有的QwenVL-Max，累积成功率平均达到其约1.6倍。在主动建议任务上，由于68%的状态是正例，F1无法区分好坏，作者改用平衡准确率和MCC来评估“该不该说话”的判断能力，ExpActivator的平均MCC达到最强基线的约2.3倍，平衡准确率提升24%，每个骨干上精确率都最高，平均84%。消融分析进一步揭示，基线方法在episode开局能把成功率从28.3%提到62.3%，但在剩余7140个动作中没有一个基线能显著超过无历史条件，而ExpActivator在同一批动作上相对无历史提升45%。同时，ExpActivator每步只提供一个动作参考，平均增加144.6个历史token，比基线平均少近五倍，比最经济的HIM-Agent还少近三倍。局限在于，它依赖冻结骨干的视觉特征质量来做状态匹配，如果骨干的视觉表示对某些界面元素不敏感，匹配可能失效；此外，任务级激活的阈值和场景定义需要校准，跨用户或跨设备迁移时可能需要重新调整。但这项工作的意义在于，它把“经验在哪里被激活，而不是在哪里被追加”这个原则清晰地提了出来，并用实验证明，决定个性化收益的不是检索多少历史，而是在每个决策时刻能否从历史中选出真正适用的那一小部分。

### [Returning to Development States: When Full Sandbox Snapshots Help Coding Agents](https://arxiv.org/abs/2610.13841)
`评分3 · 7 pages, 6 figures. Preprint. Not peer reviewed`

这篇论文关注的是编码智能体在长程任务中的失败恢复问题。现实中，一个编码智能体往往在失败前已经做了不少有效工作，比如启动了数据库、配置了服务、写入了运行时状态、安装了依赖、生成了临时文件，甚至让多个进程进入某种协同状态。但传统做法是失败后从零重试，也就是把整个环境重置回初始状态，然后让模型重新来一遍。这种做法的问题在于，它把“机器状态”和“代码差异”混为一谈，默认只要代码仓库还在，进展就没有丢失。然而对于长程编码任务，尤其是涉及多服务、数据库、后台进程、缓存、消息队列、运行时配置的场景，真正的进展往往不在 git diff 里，而在仓库之外的环境状态中。于是 retry-from-scratch 会反复浪费已经完成的探索，把搜索空间重新打开，导致样本效率低、成功率上不去。论文的动机正是：如果中间环境状态本身保留了有意义的进展，那么恢复并分支这些状态，可能比反复从初始状态重启更有效。这其实把失败恢复从“重新生成代码”的问题，重新定义成了“在环境状态空间里做搜索”的问题。

方法上的核心创新是把 Go-Explore 风格的搜索搬到完整 Daytona 快照上。Go-Explore 的关键思想不是让模型从当前策略继续盲目采样，而是先回到一个已知有希望的过去状态，再从那里探索，这样能避免深度强化学习里常见的“遗忘”和“探索崩溃”。论文实现的是对完整沙箱快照的保存、恢复和分支：每当智能体取得一定进展，就保存一个完整快照，这个快照不仅包含代码仓库，还包含文件系统、已安装软件、运行中的服务、数据库内容、环境变量、进程状态等。失败后，系统不是从初始状态重来，而是选择一个之前保存的快照恢复，然后从该状态继续尝试不同动作。这里的关键洞察是，真正决定搜索效率的，是那些无法从单一代码 diff 重建的状态。比如一个服务已经启动并监听端口，数据库已经迁移并填充了数据，某个后台任务已经进入特定阶段，这些状态如果丢掉，仅靠重新应用代码补丁是恢复不了的。论文通过实验发现，更高且更高效的解决率主要来自仓库之外的进展。换句话说，完整快照搜索之所以有效，不是因为它保存了更多代码版本，而是因为它保存了运行时上下文。这个机制让智能体可以在“已经搭好舞台”的状态上继续表演，而不是每次失败都重新搭舞台。相比之前只保存代码或只保存对话历史的方法，完整快照搜索保留了环境因果链，因此分支探索更接近真实开发中的“回滚到某个可用状态再试另一条路”。

在结果层面，论文在 Daytona 沙箱中实现了这套完整快照搜索，并比较了从零重试和从快照恢复分支的效果。关键数字是，完整快照搜索取得了更高且更高效的解决率，而且提升主要来自那些状态无法从单一 diff 重建的任务，也就是涉及数据库、服务和其他运行时状态的长程编码工作。这意味着，对于短小、单文件、纯代码修改的任务，快照搜索的优势可能不明显，因为代码 diff 已经足够恢复进展；但对于多服务、长周期、环境状态复杂的任务，完整快照搜索能显著减少重复劳动，提高搜索效率。论文也客观指出，这种方法有代价：完整快照的存储和恢复成本更高，快照管理策略、分支选择策略、快照粒度都会影响效果，而且如果环境状态本身可以很容易从代码和配置重建，那么快照搜索的收益就会下降。此外，如何自动判断哪个快照值得恢复、如何避免在大量快照中迷失，仍然是开放问题。尽管如此，这篇论文的意义在于它把编码智能体的失败恢复从“重写代码”推进到了“搜索环境状态”，并明确指出长程编码工作的进展往往分布在仓库之外。这对未来智能体系统设计有直接影响：如果想让编码智能体真正处理复杂多服务任务，就不能只盯着代码版本控制，而要把完整运行时状态作为一等公民来保存、恢复和分支。

`评分3 · 18 pages. Project page: https://yeonsungjung.github.io/proje`

个人智能体正越来越多地通过工具调用接入网页和各类应用中的服务，当它们替用户完成看似无害的请求时，跨服务的动作效果会不断累积并相互作用，从而可能产生意料之外甚至有害的后果。要主动发现这类组合性风险，就必须系统性地探索多样化的跨服务路径。然而现有的红队方法存在明显瓶颈：它们要么直接让大模型根据任务和环境描述去“猜”哪些路径可能有害，要么把人类或大模型指定的有害目标拆解成看似无害的动作组合。问题在于，这类生成方式高度依赖大模型在训练中学到的模式，天然偏向于熟悉的工具搭配，导致新颖的跨服务交互被系统性地忽略。当智能体接入的服务越来越多、其中很多组合在训练数据中几乎没有出现过时，这种偏差就更加致命。因此，作者认为需要一种不依赖大模型先验、而是从工具本身的能力和依赖关系出发来系统识别候选路径的方法。

X-AgentRed 的核心创新在于构建了一张名为 HarmFlow 的有向图，并围绕它设计了“采样—实例化—执行反馈—自我进化”的闭环。具体来说，红队智能体先对生态系统中每一个工具进行结构化分析，提取三类属性：该工具能产生的效果（如授予访问权限、创建文档）、这些效果可能引发的潜在危害、以及执行该工具所需的前置条件（如需要已存在的文档、需要特定账户权限）。然后，它逐一判断“工具 A 的效果能否满足工具 B 的前置条件”，若能，就在 A 到 B 之间连一条有向边。这样，复杂的跨服务工具链就被分解为大量简单的两两依赖检查，而图的遍历又能把这些局部依赖重新组合成更长的路径。采样时采用从目标危害工具出发的逆向随机游走：先选定一个与某类危害相关的工具作为终点，再沿着入边一步步向前回溯，直到达到预设的最大路径长度，反转后得到一条候选工具路径，称为“配方”。每个配方再结合危害诱导因素分类体系，被实例化为一个具体场景——一个看似正常的用户请求加上初始环境状态，使得该路径在特定条件下可能导致目标危害。执行这些场景后，如果确实产生了危害，系统就在保持关键危害步骤不变的前提下，用图中相邻的替代工具替换非核心节点，从而在相同漏洞模式下探索更多服务组合；如果路径被阻断，系统则分析阻断步骤上未满足的前置条件，细化图中对应的依赖边，并重建该步骤之前的序列以满足新条件，使执行能够继续推进。这种机制的关键在于：它不依赖大模型去“回忆”哪些工具该搭配，而是让图结构本身引导探索方向，再让真实执行反馈来修正和扩展这张图，从而既能覆盖训练数据中罕见的新颖组合，又能在已发现的脆弱点周围做更深入的搜索。

在实验层面，作者在一个由 30 个服务、914 个工具构成的模拟多服务生态中，对四个前沿智能体模型进行了评估。与 STAC 和 TRACE 两个代表性基线相比，X-AgentRed 的平均有害路径率分别达到其 1.77 倍和 10.36 倍，平均工具覆盖数分别达到 2.99 倍和 1.84 倍，执行的工作流中包含的工具调用数也分别是对手的 2.92 倍和 7.53 倍，说明它不仅能发现更多有害路径，而且探索的广度和深度都显著更高。作者还分析了执行路径的多样性、多轮迭代中的累积发现量，以及反馈驱动的多样化与细化各自的效果。当然，这项工作仍有局限：整个评估在一个固定的模拟生态中完成，每个配置只跑了一次，真实世界中服务的行为、权限模型和状态演化远比模拟器复杂；此外，HarmFlow 图的构建和前置条件的细化都依赖大模型判断，虽然作者人工检查了全部 192 条被标记为有害的轨迹、未发现奖励黑客的证据，但判断质量仍可能影响图的准确性。尽管如此，这项工作的意义在于提出了一种不依赖大模型先验知识、而是从工具依赖结构出发系统探索跨服务风险的新范式，为智能体生态持续扩张背景下的自动化红队提供了可扩展的方向。

### [ReplaySSM: Cache SSM Inputs, Not State](https://arxiv.org/abs/2610.13778)
`评分3 · 11 pages (35 pages counting references and appendix), 6 figu · 有代码`

这篇论文要解决的是状态空间模型（SSM）在实际推理服务中一个被长期忽视却代价高昂的瓶颈：虽然SSM用固定大小的循环状态替代了随序列增长的KV缓存，但传统解码方式每一步都要把整个状态从显存读出来、做一次衰减和秩一更新、算出输出、再写回去，这种"急切"的状态管理带来了三个真实问题。第一，状态读写的数据量很大而计算量极小，算术强度低，属于典型的内存带宽瓶颈；在混合模型里，尽管注意力层的KV缓存流量会随上下文增长，但在批大小256、单张B300上跑Nemotron-3-Super-120B时，SSM状态更新直到约10万token之前都是最大的延迟来源，原因在于SSM层数量是注意力层的五倍，且每层FP32状态每序列就有4MiB。第二，更新后的状态没有廉价的回滚手段，这在投机解码里致命：验证多个草稿token后若后缀被拒，必须把状态恢复到最后一个被接受token处，而状态里没有token历史可以"指"回去，vLLM只能为每个草稿token存一份状态快照，既拖慢本就内存受限的核，又限制了并发，导致投机解码在服务批大小下几乎没收益。第三，把状态量化到低精度后，舍入误差会在每一步重新进入循环更新并随序列累积，最近邻舍入还会引入系统性偏差，随机舍入虽无偏但方差仍会传播，最终扭曲输出分布、损害下游精度。这三个问题共同指向一个反问：为什么我们非要在每一步之后都存一个更新后的状态？

论文的关键洞察是把循环展开来看：当前状态其实等于一个被衰减过的早期检查点加上对最近若干输入的短求和。于是ReplaySSM不再存"状态"，而是把状态表示为一个检查点加上一个有界缓冲区，缓冲区里放最近的SSM输入（对Mamba-2来说每条记录是衰减因子、value和key）。这一表示把"输出计算"和"检查点更新"彻底解耦：在大多数非flush步里，系统只把当前输入追加进缓冲区，然后直接用检查点加缓冲区算出输出，完全不写状态；只有当缓冲区填满时触发一次flush步，才把缓冲的输入折叠进检查点、写回显存并清空缓冲区。这样状态写入只在flush步发生，输出与传统解码在浮点误差范围内一致。这个解耦一举解决了三个难题：非flush步只写很小的输入向量和衰减因子，检查点写入被摊薄到整个窗口，主导性的状态内存流量大约减半；保留最近输入让投机解码的回滚变成一个缓冲区指针移动操作，被拒的草稿token直接丢弃即可，而且因为非flush步只需要输出，验证可以直接从检查点和缓存输入算出结果，无需物化任何中间状态——论文进一步利用矩阵乘法的结合律，把原本要物化 dv×dk 状态的 (v k^T) q 改写成 v (k^T q) 的"仅输出"形式，先算标量 k^T q 再缩放 v，既省FLOPs又能让共享key和query的多个value头复用一次 K^T Q 计算；对GDN这类delta规则模型，草稿修正项之间存在依赖，论文用一个 T×T 的三角求解一次性解出全部T个修正。低精度方面，由于输出计算和循环更新用的是不同角色，可以让低精度检查点负责大多数步的输出、高精度检查点负责跨flush的循环推进，低精度副本的舍入误差永远不会进入后续更新，而且量化从每步一次变成每窗口一次。

在结果上，作者把ReplaySSM实现在vLLM里，覆盖Mamba-2和Gated DeltaNet，在服务批大小256时，对四个混合模型的标准解码相比调优过的vLLM基线加速1.20到1.47倍，在两个120B级MoE模型上吞吐约为vLLM投机解码的1.8倍；分离状态精度相比共享低精度检查点还降低了输出KL散度和下游精度损失。局限方面，论文没有回避窗口大小L的权衡：L越大检查点写入越被摊薄，但每步要加载和应用的缓冲输入也越多，作者统一取L=16，这个超参是否对不同模型和序列长度都最优并未充分展开；投机解码下的flush频率还取决于接受率，接受率越高缓冲区填得越快，flush越频繁，收益会随工作负载波动。此外，这套方法依赖SSM更新能写成外积形式并支持结合律重排，对更一般的循环结构未必直接适用，且实现深度绑定vLLM和特定核。但它的意义在于把"状态管理策略"从理所当然的每步物化，重新定义为一个可设计的表示问题：状态不必是每步写回的张量，而可以是检查点加输入缓冲区的组合，这一视角不仅同时缓解了内存流量、回滚和量化误差三个看似独立的问题，也为混合模型在长思维链和智能体工作负载下的推理效率提供了一条与注意力优化正交的改进路径。

### [Double-Take: Improving Capacity, Binding, and Selectivity In Long-Context Within Bidirectional Memory](https://arxiv.org/abs/2610.13073)
`评分3 · 23 pages, 4 figures, 15 tables`

这篇论文要解决的核心问题是：长上下文模型虽然能处理很长的序列，但“处理过”不等于“记得住、用得上”。作者把这个问题拆成三个彼此独立的能力要求——容量、绑定和选择性。容量指的是固定大小的记忆能同时保留多少条不同的关联而不互相干扰；绑定指的是记忆能否表示两个不同位置之间的关系，而不只是每个位置自身的键值对；选择性指的是当上下文越来越大时，记忆能否优先保留真正重要的结构，而不是把所有内容一视同仁。作者在“大块测试时训练”（Large-Chunk Test-Time Training, LaCT）这个设定下发现了两个具体缺陷：第一，单步写入会把一个块内大量键值对同时叠加进同一个快速权重状态，导致严重的串扰，容量受限；第二，自关联写入只能把位置 i 的键和位置 i 的值配对，根本无法形成跨位置的绑定，也就是说，无论写多少次，记忆里都不会出现“位置 i 和位置 j 有关系”这种项。更糟的是，即使前两个问题解决了，如果所有关联被同等对待，记忆也无法区分哪些结构真正重要。基因组数据把这三个问题变得非常具体：单个核苷酸可能关键，调控伙伴可能相隔几十万甚至上百万碱基，而中间绝大部分序列可能无关。

Double-Take 的核心设计针对这三个缺陷分别下手。首先是多步非钉扎更新来提升容量：DT 不再对每个块只做一次写入，而是从上一块继承的状态出发，做少量几步内层更新，每步用 Muon 的 Newton-Schulz 归一化来正交化更新方向，从而降低 Hebbian 写入带来的键间串扰；关键在于这些更新是“部分”的，DT 不像原始规则那样每步之后做行归一化把状态强行拉向当前写入，而是限制内层步数并把结果直接带到下一块，让旧信息被稀释而不是被覆盖。其次是局部跨位置混合来实现绑定：DT 在查询、键、值三个流上各加一个宽度为 3 的深度可分离因果卷积，这样键流里就显式出现了来自不同位置的项，跨位置关系在写入之前就已经被构造出来，而不是指望记忆自己去推断一个从未呈现给它的关系；这个卷积本身不提供长距离覆盖，它只决定哪些邻近位置被绑在一起，真正把这些关系运送到远处的是持续演进的快速权重状态。最后是双向变化敏感写入来实现选择性：DT 同时看每个位置左侧 512 个位置的摘要和右侧 512 个位置的摘要，把两者的差作为写入目标，当两侧相似时差值接近零，当出现表示转变时差值约等于转变前后的差，这样记忆就优先保留结构变化而非普通内容；读取时也同时保留两个方向的共享分量和方向差异分量，而且正反两个序列是沿 batch 维堆叠并行处理的，不需要额外一次顺序遍历。整个记忆在块内保持因果性：先读上一块积累的状态，再写当前块，当前写入只对后续块可见。

在实验结果上，作者先在受控的联想召回任务里单独检验快速权重记忆：只有容量时端到端召回率停在 0.10 的随机水平，加上绑定后跳到 0.92，说明容量和绑定确实是两个独立且都必要的能力。在基因组任务上，编码器有 8700 万参数、十二个相同块，每块包含深度卷积、滑动窗口注意力、DT 快速权重记忆和逐位置 MLP，嵌入宽度 768，记忆头维度 32，块大小 2048 个 token，在 GRCh38 上以单核苷酸分辨率、32kb 序列做双向掩码语言建模预训练，第 8 和第 9 号染色体留作下游人类评估。滑动窗口注意力每层每侧只覆盖 128 个位置，十二层堆叠后纯注意力感受野约正负 1.5kb，所以超出这个范围的信息必须走快速权重记忆通路。结果是在 32kb 上训练的 DT，在 131kb 上达到 0.927 AUROC，在接近 1Mb 时仍有 0.856，并且从人类到小鼠零样本迁移。局限方面，论文没有声称解决了所有长上下文问题，它的验证主要集中在基因组这一特定领域，读出增益是在验证染色体上选定的固定推理时乘子而非训练参数，公开长上下文模型只作为外部参照而非因果对照，而且宽度为 3 的卷积本身不提供长距离覆盖，长距离能力完全依赖记忆状态的持续演进，这意味着如果记忆写入本身在某些任务上失效，局部混合也救不了。总体而言，这篇工作把“长上下文可用性”从单纯的长度竞赛重新定义为容量、绑定、选择性三个可分别检验的要求，并给出了一套具体、可操作的机制来同时修复它们，对这个方向的影响在于它提供了一种诊断框架：当长上下文模型失效时，可以分别问是记不住、连不上、还是分不清主次。

### [TopoLIA: Topology-Inspired Latent Interaction Attention for Drug Discovery](https://arxiv.org/abs/2610.13006)
`评分3`

这篇论文要解决的是药物发现中蛋白质-配体相互作用建模的核心难题。传统分子对接、自由能扰动等方法虽然可靠，但计算代价高且难以捕捉三维复合物中非欧几里得、不规则、多尺度的几何特征。Transformer 架构虽然在表示学习上取得了巨大成功，但其标准的源-目标注意力机制存在一个根本性瓶颈：注意力权重只决定“传递多少信息”，而每个源节点被变换后的值向量在不同目标之间是共享的，也就是说，源到目标的依赖关系仅通过标量权重体现，信息本身如何随目标不同而变换则完全未被建模。这在异构的生物分子体系中尤为致命，因为一个原子或残基对另一个靶点的影响方式，显然不应等同于它对所有靶点的影响方式。已有的拓扑深度学习工作虽然引入了持续同调、持续谱理论等工具来提取多尺度拓扑和几何特征，但大多把拓扑仅当作特征提取器，而没有让它直接参与神经架构的设计。Copresheaf 拓扑神经网络虽然提出了局部特征空间和可学习的结构映射来中介信息交换，但在高维特征空间直接实现这种交互依赖的变换计算代价极高，且容易引入不必要的灵活性。作者由此提出一个关键假设：生物分子间的信息交换其实可以通过一个远比原始特征空间低维的潜在交互空间来有效中介。

TopoLIA 的核心创新是潜在交互注意力机制，它把信息交换拆成两个互补的方面：交换多少信息，以及信息如何被变换。具体来说，每个源表示先通过一个源相关的变换投影到一个紧凑的潜在交互空间，然后这个潜在表示再通过一个目标相关的变换映射到目标空间，两者的复合就定义了一个经由潜在交互空间的结构化源到目标变换。这样一来，模型无需为每一对源-目标显式参数化一个高维映射，就能实现目标依赖的信息变换，而低维瓶颈本身构成了一种结构化的归纳偏置，既控制了计算成本，又契合了异构生物分子交互的内在低秩特性。在数据表示层面，TopoLIA 引入了持续谱表示来编码三维蛋白质-配体复合物的多尺度拓扑和几何模式，包括原子组成、空间组织、拓扑空腔以及非调和几何变化。训练策略上，模型先在大规模无标注分子结构上进行自监督掩码预训练，随机遮盖一部分多尺度谱 token，让编码器-解码器架构从分子上下文中重建它们，从而学到可迁移的结构表示，再通过微调迁移到下游任务。编码器和解码器都由潜在交互 Transformer 层构成，保留了标准 Transformer 块的整体结构，仅把自注意力替换为潜在交互注意力，因此消融实验可以干净地隔离注意力机制本身的贡献。

在多个基准上，TopoLIA 都取得了当前最优或极具竞争力的结果。评分任务中，CASF-2007 上皮尔逊相关系数达到 0.832，CASF-2013 上为 0.814、均方根误差 1.908 kcal/mol，CASF-2016 上达到 0.861，显著超过 Topoformer 和 PerSpect-ML 等领先架构。在评估跨蛋白家族泛化的 LBA30 和 LBA60 数据集上，TopoLIA 分别取得 0.641 和 0.806 的相关系数，其中 LBA60 上明显优于当前最优的 SableBind。在 PDBbind v.2020 精炼集的十折交叉验证中，TopoLIA 达到 0.811 的相关系数和 1.152 kcal/mol 的均方根误差，远高于 PLAIG 和 GNNSeq 等图神经网络模型。对接任务中，CASF-2013 上 TopoLIA 的成功率达到 88%，超过 AutoDock Vina 的 85% 和 RTMScore 的 80.7%，同时还能保持 0.814 的评分相关系数，而 ChemPLP@GOLD 和 AutoDock Vina 虽然对接成功率尚可，评分相关系数却只有 0.579 和 0.564。消融实验进一步表明，在完全相同的数据表示和 Transformer 架构下，仅把潜在交互注意力换回标准自注意力，三个 CASF 基准上的相关系数就分别从 0.817、0.798、0.857 降到 0.754、0.724、0.819，均方根误差也全面上升，这直接证明了源-目标依赖的特征变换确实带来了实质增益。系统性秩分析还显示，紧凑的潜在维度反而取得最佳性能，支持了低维交互空间作为有效归纳偏置的假设。局限方面，论文目前主要在蛋白质-配体结合这一特定任务上验证，潜在交互空间的维度选择虽然表现出鲁棒性，但最优维度的确定仍依赖经验搜索，且持续谱表示的计算开销在超大体系上可能成为瓶颈。更广泛地看，潜在交互注意力提供了一个通用的结构化源-目标依赖信息交换框架，其适用性不限于生物分子，而可能扩展到任何涉及复杂异构交互的科学与人工智能问题。

### [RetroTAC: Learning Route-Derived Synthetic Accessibility for PROTACs](https://arxiv.org/abs/2610.13639)
`评分3 · 26 pages, 11 figures, code available at: https://github.com/ · 有代码`

PROTAC 这类靶向蛋白降解嵌合体在药物发现中开辟了传统抑制剂难以触及的空间，但其分子量大、由弹头、连接子和 E3 配体三部分模块化拼接而成的结构，使得合成可行性成为实际瓶颈。生成模型可以极快地枚举虚拟降解剂，但合成路线评估的速度远远跟不上，于是研究者长期依赖快速合成可及性打分来做过滤。问题在于，现有打分大多是在类小分子药物的化学空间里开发的：基于片段频率的启发式、基于反应语料库的模型、以及基于逆合成规划器成功与否的分类器，它们普遍带有尺寸惩罚，并且其片段词表和反应语料并不能正确刻画 PROTAC 这种"由少数模块化片段拼接而成"的分子。结果是这些分数会高估 PROTAC 的合成难度，把模块拼接误判为复杂度的累赘。虽有 DeepPSA 和 FSscore 两个专门面向 PROTAC 的尝试，但前者是专有数据上的二分类器，后者只用了数十对专家标注，都不足以支撑大规模虚拟筛选。而真正给出丰富证据的逆合成规划工具虽然能提供步数、收敛性、具体转化和起始砌块，却计算代价高昂，且结果强烈依赖于规划器、反应模板、库存、搜索预算和随机种子，无法直接嵌入生成式流水线或虚拟筛选。

这篇工作的关键洞察是把"路线评估"重新表述为"单分子性质预测"：训练时用外部逆合成工具为每个 PROTAC 生成路线并据此定义标签，但推理时模型只吃分子结构，不再调用规划器。其路线衍生分数由两个人类可解释的项构成。第一项是路线深度，即最长线性序列，衡量所有分支到达可购买砌块前需要多少步顺序反应，它随深度线性衰减到零。第二项是平衡项，针对每个双分子反应步骤，比较被连接的两个片段的重原子数，取较小者与较大者的比值，再在整条路线上平均。这个设计的精妙之处在于，它能把"用小块基团逐步修饰一个大中间体"和"把体量相当的模块拼接起来"区分开来——后者才是 PROTAC 合成的典型模式，而单纯的长度惩罚无法区分二者。分数只读取路线拓扑和重原子计数，不需要第二个反应模型，是同类路线分数中最轻量的。数据方面，作者从 PROTAC-DB、PROTACpedia 和 TPDdb 收集标准化了 21,189 个 PROTAC，用 ShallowTree 在 eMolecules 库存、最大深度 12、单分子 30 分钟超时的设置下成功解析了约 92.4%（17,802 个），最终得到 18,076 个带标签分子，其中约 10% 通过自适应 Butina 聚类隔离为留出集，开发集内部又按弹头的 Bemis-Murcko 骨架分组做交叉验证以防泄漏。模型层面比较了 XGBoost、多层感知机和 Chemprop 图神经网络三种骨干，输入分别是 Morgan 指纹加 RDKit 描述符或直接分子图，并用 Ash 等人的重复交叉验证框架做 25 组配对评估，再用 AutoRank 做统计检验。最终 RetroTAC 是一个 Caruana 贪心选择集成，从 75 个交叉验证模型中挑出 13 个 GNN、7 个 MLP 和 7 个 XGB，输出均值预测和作为不确定度的成员标准差。

结果上，路线衍生分数与现有合成可及性指标的相关性很弱甚至反相关，例如与 SA score 的 Spearman 相关是负 0.37，与 SCScore 是负 0.14，说明这些为小分子药物设计的指标确实无法迁移到 PROTAC 空间。交叉验证中 GNN 表现最好，R² 为 0.509、RMSE 为 0.142，显著优于 MLP 和 XGB；在 2,232 个留出分子上重训后 GNN 的 R² 达到 0.615。集成进一步提升，Caruana 集成在 1,854 个评估分子上取得 RMSE 0.132、R² 0.647，Spearman 相关 0.72。最具说服力的是前瞻性验证：作者用 RetroTAC 对约 130 万个未见过的枚举 PROTAC 打分，按不确定度中位数分成自信与不确定两池，各取最高和最低分的 400 个分子，再用 ShallowTree 实际规划路线并打分。高预测分候选的平均路线衍生可合成性达到 0.73，而低分候选只有 0.31；在测试搜索设置下，前者有 98.75% 能被完全解析，后者仅 51.00%。这证明该代理模型确实能快速、有效地从海量虚拟库中优先挑出可合成性高的候选。局限也很明确：该分数只刻画路线深度和模块平衡，并不捕捉反应可行性、选择性和产率；分数为 0 的边界情况既可能是真实困难，也可能只是规划器超时或达到深度上限；集成的不确定度与绝对误差只有约 0.33 的弱相关，只能算弱校准的误差估计。尽管如此，RetroTAC 的意义在于把分子筛选与可解释的路线特征连接起来，让显式规划只留给被选中的候选，为 PROTAC 虚拟库的高通量优先级排序提供了一个实用且透明的工具。

### [GroundingPI: A Grounding Foundation Model towards Physical Intelligence with Visual Primitives](https://arxiv.org/abs/2609.39601)
`评分3 · HF 246赞`

视觉语言动作模型和世界动作模型正越来越多地建立在通用视觉语言骨干或视频生成骨干之上，但这些骨干并非为物理交互所需的精确感知而优化。当机器人面对一张杂乱的桌面时，它需要先找到杯子和杯柄在哪里，才能决定怎么抓、怎么移——也就是说，先确定“在哪里行动”，再决定“如何行动”。然而通用VLM在密集场景和微小物体上的 grounding 能力存在明显短板，Qwen3.5 系列在这些场景中表现吃力，即便是 GPT-6 Astra 也留有提升空间。更关键的是，下游动作学习本身数据就稀缺，如果感知还得靠动作数据来“顺带学”，那有限的监督信号就被迫同时承担感知和动作两项任务，效率极低。已有的补救方案，比如 π₀ 到 π₀.₅ 在策略中增加边界框预测，或引入辅助感知模块和额外学习目标，本质上都是把感知当作任务特定的代理信号或中间表示，依赖额外标注、难以跨场景规模化。作者因此提出一个更根本的问题：能不能先训练一个强大的、感知原生的 grounding 基础模型，让下游策略直接建立在它之上，而不是从任务代理中“恢复”感知能力？

GroundingPI 的核心设计思路，是把多种感知任务统一为语言条件下的结构化生成问题。它采用 4B 参数规模，视觉端用 MoonViT-V2 编码器，语言端用 Qwen3-4B 解码器，中间通过一个可学习的投影器把相邻 2×2 的视觉特征聚合后映射到语言嵌入空间。关键创新在于共享词表：语义标签、协议标记和 1000 个量化坐标 token 共用同一套输出词表，点、框等视觉基元都被表示为量化坐标序列，模型以自回归方式逐 token 生成变长响应。这样一来，grounding、referring、pointing、OCR、GUI 和布局 grounding、视觉提示等任务全部统一到同一个接口下，查询类别不存在时直接输出 None。训练分三阶段：先做多模态与空间预训练，冻结双骨干只对齐投影器，再联合更新全部模块；然后做监督微调，用教师强制让坐标与视觉位置对齐，先全模块更新、后冻结视觉侧精调语言侧；最后用 GRPO 做强化后训练，对每个图像-查询对采样 8 条自回归响应，grounding 任务用集合级奖励衡量覆盖度（基于参考的最大 IoU 匹配加类别验证），再用严格奖励综合多阈值 F1、定位、格式、计数和排序分数并惩罚重复和过大框，两者标准化后按 0.7 和 0.3 加权；OCR 任务则用匈牙利一对一匹配评估文本和几何，经格式门控和输出惩罚合成单一奖励。这套设计让模型直接优化定位精度、目标覆盖和文本-几何一致性，而不是只靠下一 token 预测的交叉熵来间接学坐标。

在 34 个 grounding 基准、11 类感知能力上对 44 个基线进行评估，GroundingPI 平均达到 73.68%，超过参数量更大的 GPT-6 Astra 的 71.54%，建立了新的最优结果。作为下游视觉骨干，它在机器人操作和自动驾驶上都带来显著提升：在 RoboTwin 2.0 上，四个分布外设置中全部优于所评估的主流骨干，相对最强基线最高提升 24.8%；在 RoboCasa-GR1 上，只用 50% 演示数据训练的 GroundingPI 就超过了用 75% 数据训练的基线；在 nuScenes 上作为视觉骨干达到 0.296 米的平均开环 L2 误差。消融分析进一步显示，预训练规模和数据组成都很关键，密集 grounding 对自动驾驶和机器人操作都有实质性收益，而 OCR 可能成为感知学习的催化剂。局限方面，论文的设计洞察主要面向 System-1 风格的执行感知，尚未与前沿模型的高层推理和规划深度整合；视觉基元能否进一步支撑“物理提示”——即用点、框、结构配合语言来指定目标、位置和交互结构——仍是一个开放方向。但总体而言，这些结果支持把 grounding 作为感知基础，并把专门的感知预训练视为物理智能基础模型的一条有前景的路线。

### [GroundAnything: Reconciling Parallel Decoding with Precise Visual Grounding at Flash Speed](https://arxiv.org/abs/2609.39600)
`评分3 · HF 71赞`

这篇论文要解决的核心问题是自回归视觉定位模型在密集场景下的解码效率瓶颈。传统方法如Pix2Seq、Florence-2、Rex-Omni等把目标框、关键点、OCR文本等空间预测序列化成一条从左到右的token链，用next-token prediction逐个生成。这种做法的根本矛盾在于：图像和查询对物体位置、类别、空间关系的约束是联合的、双向的，并不存在一个内在的“先出左上角坐标、再出右下角坐标、再出类别标签”的因果顺序。但自回归解码强制引入了这种顺序，导致两个后果：一是延迟随输出长度线性增长，密集场景下框数量多、坐标token多，推理时间急剧膨胀；二是每个token只能看到已生成的前缀，无法利用后续token的信息来修正前面的预测，容易出现坐标漂移或类别与位置不匹配。LocateAnything用多token预测（MTP）把每个框当作原子单元并行解码来缓解延迟，但它本质上仍是自回归框架下的加速技巧，没有改变因果顺序的约束，且只针对框解码这一种输出形式。扩散VLM虽然在多模态理解、GUI定位、文档OCR等方向有探索，但要么是领域专用的，要么没有解决统一结构化输出下保持精确定位的问题。所以这篇论文的动机很明确：能不能用一种天然支持并行、双向 refinement 的解码范式，在保持甚至提升定位精度的同时，把速度拉到实用级别。

GroundAnything的核心洞察是把视觉定位重新定义为“结构化视觉证据提取”——物体、位置、空间关系由图像和查询联合约束，但它们的依赖关系不构成一个固有的从左到右生成顺序。基于这个视角，论文采用块状掩码扩散（blockwise masked diffusion）作为解码范式。具体来说，模型把响应序列切成K个连续的块，每个块内部用双向注意力并行恢复所有token，块与块之间保持因果依赖，已完成块的KV cache可以复用。这样既保留了语义顺序（比如轨迹的时间顺序），又允许每个块内的空间假设同时涌现、通过迭代去噪联合精炼。模型架构上，GroundAnything是一个4B参数的扩散定位基础模型，视觉编码器用MoonViT-V2，投影层做2×2空间聚合加两层MLP，语言解码器用Qwen3-4B。输出接口共享一套词表，包含语义标签、协议标记和1000个量化坐标token，缺失类别用None占位。训练流程分四步：先做定位预训练，数据来自公开数据集和自建数据引擎（多教师标注在字段级融合、任务特定验证、迭代训练统一专家）；然后从预训练的AR模型GroundAnything-VLM做AR-to-diffusion转换，保留骨干和词表，只加一个mask token，联合优化掩码扩散损失和自回归损失，块大小B=32；接着做监督微调；最后用GRPO做强化后训练，奖励设计上框定位结合集合完整性和严格定位，OCR用标注感知的文本-几何一致性，pointing综合位置、数量、标签和格式，优势函数在组内标准化后加权求和。推理时默认用熵引导解码：对每个掩码位置计算未修改token分布的熵，只提交熵低于阈值τ的位置，如果都没有就强制提交熵最低的那个以保证进度，已提交token固定，再用一次因果前向构建该块的cache，不需要AR验证。这个设计的关键在于，扩散的并行去噪让模型可以在一个块内同时看到所有位置假设，利用共享的视觉证据和部分恢复的结构来相互修正，而不是像AR那样只能依赖已生成的前缀。可选的自推测解码模式则把扩散草稿和因果验证结合，线性解码每轮两次网络前向、2B个query token，二次解码在初始化后把验证和提议生成融合进一次前向、用B(B+1)个query token，接受最长匹配前缀。

在30个定位基准上，GroundAnything-VLM在同类规模模型中建立了新的总体最优，平均72.42%，与GPT-6 Astra的71.35%相当。纯扩散解码的GroundAnything用熵引导模式平均61.75%，超过了之前同规模的最优53.32%（基于MTP的LocateAnything），且速度超过GroundAnything-VLM两倍以上。自推测模式在COCO上达到4.51倍加速，F1mIoU仅下降0.74个百分点。基础设施层面用SGLang、CUDA Graph和选择性FP8进一步优化，验证了并行解码在实际部署中的加速效果。局限方面，纯扩散解码在绝对精度上仍低于AR变体，说明并行去噪在极精细定位上还有提升空间；自推测模式虽然更快更准，但混合了AR验证，不算纯扩散解码；数据引擎的标注质量对最终性能影响很大，迭代标注的成本和可扩展性没有充分讨论。这篇论文的意义在于，它第一次在统一的多任务视觉定位上证明了扩散解码可以同时做到广覆盖、高精度和实用速度，打破了“并行解码必然牺牲定位精度”的固有认知，为延迟敏感的实时视觉系统提供了一条可落地的技术路线。

### [EmbodiedCLBench: Evaluating Continual Learning for Self-Evolving Embodied Agents](https://arxiv.org/abs/2610.13021)
`评分3 · HF 66赞`

这篇论文要解决的核心问题是：现有持续学习研究几乎全部停留在非具身环境里，比如知识密集型问答、网页自动化、操作系统操作或纯文本模拟世界，这些场景虽然能测出模型是否记住了过去的经验，却完全绕开了具身智能最本质的挑战——空间约束、物理可行性、动作序列的因果后果。与此同时，具身智能领域已有的基准测试覆盖了场景感知、视觉导航、机器人操作和长程规划，但它们的设计目标从来不是持续学习，而是单任务或零样本泛化能力。结果就是，我们既不知道一个自进化具身智能体能否把过去在简单任务里学到的技能真正迁移到新任务上，也没有一套可复现、可量化、能控制变量地衡量这种迁移能力的评测协议。更麻烦的是，直接在真实仿真器里做在线评测会带来巨大的计算开销和不可复现性，而现有具身基准又往往被大模型训练数据污染过，导致测出来的“泛化”可能只是记忆。所以这篇论文的动机非常明确：必须造一个专门为具身持续学习设计的基准，它要能控制任务复杂度、能离线并行评测、还要尽量避开数据污染。

它的核心洞察是把“持续学习”这个抽象概念操作化为“组合泛化”。具体来说，作者不直接问“智能体有没有记住经验”，而是问：如果智能体先在基础任务里学会了若干原子动作和技能元素，它能不能把这些元素重新组合起来，解决从未见过的、更复杂的进阶任务？这个设计的关键在于，基础任务在这里扮演的是“测试时学习数据”的角色，而不是训练数据——智能体在评测时先做基础任务积累经验，然后立刻用这些经验去挑战进阶任务。为了把这个思路落地，作者选了TongSim作为仿真平台，因为它有丰富的家居物体和可执行动作，组合空间足够大，而且尚未被广泛用作大模型训练数据，能降低污染风险。任务被分成三层：原子动作是单次物体交互，基础任务由少量原子动作组成一个实用的家居操作，进阶任务则组合多个基础任务类别的元素。每个任务都被离线构造成一张状态转移图，图节点是环境状态，边是可执行动作，这样评测就变成了在图上做多轮决策：智能体每步看到当前状态图像和一组候选动作，候选动作分为最优、次优和无效三类，选完后确定性地转移到下一状态，直到到达目标或耗尽步数预算。这种图结构的好处是评测完全离线、可并行、可复现，而且能通过图的分支和深度精确控制任务复杂度。在评测协议上，作者设置了三种条件：零样本直接做进阶任务、上下文学习把基础任务的完整交互轨迹保留在上下文里、以及技能学习让智能体把经验写成Markdown技能摘要再用于进阶任务。这样就能区分“经验以原始轨迹形式存在”和“经验被压缩成可复用技能”两种迁移机制。

实验在268个任务上展开，其中168个基础任务、100个进阶任务，基础任务的最短路径是6步，进阶任务是12步，进阶任务的原子动作来自2到4个基础任务类别。评测覆盖了OpenClaw、Claude Code、Codex等多种智能体外壳，以及ICL和技能学习两种学习方式。结果有几个非常值得注意的发现：首先，零样本条件下进阶任务几乎做不出来，但只要有相关基础任务的经验，成功率就大幅提升，这直接验证了简单任务经验可以迁移到更难的新任务上。其次，这种提升幅度随着任务复杂度增加保持稳定，说明持续学习能力对任务难度不敏感。第三，也是最反直觉的一点，提升并不随学习样本数量增加而扩大——单个基础任务就能带来显著提升，再给更多样本反而没有一致的进一步改善，说明当前智能体无法从额外经验中提取出有意义的新信息。第四，过去经验改善了决策行为，智能体倾向于选择更有意义的动作，无效动作明显减少。这篇工作的意义在于，它第一次把持续学习评测从数字世界拉进了具身仿真，用组合泛化作为可操作、可量化的原则，揭示了当前自进化智能体的一个根本局限：它们能从少量经验中获益，但无法有效扩展这种获益。局限也很明显，评测目前基于离线图，虽然保证了可复现性，但牺牲了在线交互中可能出现的动态反馈和物理不确定性；任务规模虽然覆盖了家居场景，但距离真实世界的开放性和噪声还有很大差距。不过，这个基准为后续设计真正能“从经验中持续进化”的具身智能体提供了一个清晰的起点和一套可复用的评测基础设施。

### [When VLMs Destroy What They Know: Spatial Representations Fall Below Lexical Priors](https://arxiv.org/abs/2610.13910)
`评分3`

这篇论文要追问的是一个比“模型答没答对”更底层的问题：视觉语言模型内部到底有没有编码空间关系。此前大量工作（如 Yuksekgonul 等 2023、Hsieh 等 2023）已经发现 CLIP 这类模型在关系型表达上表现得像词袋模型，在组合性和语序敏感任务上频繁翻车，但这些研究几乎都停留在“看输出”的层面——模型预测错了，我们就说它不行。问题在于，输出正确不等于内部真的表征了关系，输出错误也不等于内部完全没编码关系。作者指出，一个模型可能靠语言先验或表面统计线索蒙对答案，也可能内部明明编码了信息却在最终聚合时丢失。于是他们提出一个更根本的判据：概念稳定性，即当且仅当改变一个底层概念、其余全部固定时，内部表征是否朝可预测、可解码的方向变化。为此他们构建了 CASP-VL 基准和 EICS 指标，并把 VLM 的表征和一个纯词袋基线作对比，这个基线只利用词的身份信息、不含任何上下文编码，从而能回答“模型有没有保住自己输入里本来就有的词汇信息”这一关键问题。

方法上的核心设计有两块。CASP-VL 基于 Visual Genome 的场景图构建，关键在于它干预的是场景图而不是直接改句子，从而保证每个三元组里严格只有一个概念被改动：要么是属性翻转（红变蓝），要么是空间谓词翻转（on 变 beneath），然后用模板把前五个关系渲染成句子。这样得到的“原句—扰动句”对构成反事实描述，图像本身不动，所以扰动句是对同一张图的另一种描述。EICS 则是一个评估不变的概念稳定性指标：它只在原始句子上训练一个逻辑回归探针，标签是原始概念，然后拿这个探针去预测对应扰动句子的新标签，看它有多大概率给出被干预后的新概念。EICS 在随机水平处为零，越高说明表征越可靠地跟随概念变化。作者还把这个流程套在归一化的词频向量上，得到词袋基线，用来衡量“仅凭词身份能拿到多少信息”。实验在 CLIP ViT-B/32 上取所有 13 层的 [EOS] 池化隐状态，并用 SigLIP 和 LLaVA 验证泛化性。结果非常刺眼：颜色概念在 L12 的 EICS 达到 +0.312，是词袋基线的 94%，说明颜色信息基本被保住了；而空间关系的 EICS 在所有层都很低，峰值仅 +0.097，L12 只有 +0.070，不到词袋基线 +0.372 的五分之一。更关键的是，作者进一步定位了失败发生的位置：在谓词自身的 token 上，关系是可以被识别出来的，但一旦句子被聚合成全局表示——无论是通过 [EOS] 还是平均池化——这个信息就丢失了。也就是说，模型并非“看不见”关系词，而是没有把这个局部可识别的信息保留到下游决策所用的那个表征里。这个发现之所以重要，是因为它揭示了一种输出评估完全看不到的系统性失败：模型输入里有、局部也编码了，但最终用于判断的表示里没有。

在结果层面，这种空间表征的崩塌跨架构成立。在统一协议下，没有任何一个被测模型的空间 EICS 接近词袋基线 +0.359：CLIP ViT-B/32 是 +0.066，ViT-L/14 是 +0.053，SigLIP 是 +0.038，LLaVA 是 +0.115，而 LLaVA 的谓词 token 本身对两个概念的 EICS 都至少 +0.86，再次印证“局部有、聚合后丢”。作者还用论元顺序交换做了更严格的检验：把“猫在垫子上”换成“垫子在猫上”，词的多重集完全不变，词袋模型按构造只能到 0.500，而 CLIP 的 [EOS] 探针能显著区分两者，说明结构信息确实在某个层面存在，只是没被保留到池化表示中。论文的意义在于把“组合性失败”从行为层面推进到表征层面，指出问题不是模型缺乏空间知识，而是聚合机制系统性地压制了空间信号，使其甚至低于纯词汇先验。局限也很明确：LLaVA 上颜色与空间的差距不显著，作者没有强行宣称普适的颜色—空间鸿沟；部分单向反义词翻转无法被探针预测而被排除；不同分析使用了不同的数据子集，虽然都来自 Visual Genome 但彼此不混用。对方向的影响是，它提示后续工作不能只靠输出准确率来评估组合性，而应引入表征级诊断，并且把改进重点放在如何让池化或聚合步骤保留局部已编码的结构信息，而不是一味增加训练数据或堆叠场景图监督。

### [MC-EvoBench: Auditing Experience-Driven Self-Improvement in Minecraft Agents](https://arxiv.org/abs/2610.13829)
`评分3 · 39 pages, 6 figures · 有代码`

这篇论文要解决的是具身智能体“递归自我改进”中一个被普遍忽视的归因难题：智能体从自身交互历史中获得的经验，究竟有没有转化成一种可复用、可迁移、能跨越不同世界和后续任务的能力？现实中，保存一段记忆或记录一个成功的最终动作，并不能证明智能体真的习得了某种能力——后续任务表现变好，完全可能是因为它把上一轮的工具留在了物品栏里、世界状态被自己改过、出生点更有利，或者仅仅是在源任务上多花了交互步数。更麻烦的是，在Minecraft这类具身环境里，任务往往有严格的前置依赖链，早期采集木材或 crafting 失败会让后面的能力根本无从被观测到，于是“没提升”可能只是“没跑到那一步”。已有的基准各有侧重：MCU覆盖多样任务和自动验证，LifelongAgentBench、EvoAgentBench、PAST-Bench研究跨任务学习、迁移和持久状态，但它们要么不涉及具身环境中的物理状态混淆，要么没有把“源任务暴露量”和“目标世界重置”严格对齐，因此无法干净地把“能力变化”从“资源残留”“源暴露不均”“早期执行失败”中剥离出来。MC-EvoBench 的核心动机就是：要宣称经验驱动了改进，必须在目标世界重置、只允许声明的智能体产物跨越源-目标边界、并且用匹配的无关源和打乱源作为对照的条件下，仍然观察到行为上的提升。

方法上的关键洞察是把“经验驱动的自我改进”重新定义为一个可审计的归因问题，而不是一个单纯的分数比较。论文把智能体形式化为策略、持久状态和更新规则三部分，并把持久状态与世界状态严格分离：世界状态包括物品栏、工具、资源、位置、地形和世界改动，持久状态则可以是记忆、提示、回放数据、检查点或模型更新。源阶段结束后，评估器记录并冻结持久状态，然后重置目标世界和物品栏，只允许那个被声明的智能体产物进入目标阶段，源阶段的资源、位置、世界编辑、路线信息和成功标记一律不得跨界。为了把任务依赖和可观测的资源流动显式化，论文构建了一个任务-状态图，包含80个任务、111个状态节点和369条带类型边，组织成19条链，其中12条主评估链和7条校准/探针链；边分为严格执行边（requires、produces、consumes）以及仅表示可能能力链接的enables和abstracts_to，后者不被当作迁移证据。每个阶段都有环境验证器检查运行证据，并给出三个互补指标：TSR衡量计划阶段通过比例且未到达的阶段仍留在分母中，WGP衡量严格执行图中被验证进展支持的加权边比例，VMP追踪链结束前观测到的合格物品或工具里程碑，从而捕捉部分进展而非只看最终完成。配对协议设置四种目标条件——无先验、相关经验、无关经验、打乱的相关经验——并在每个探针家族内匹配环境步数预算和五个种子，同时单独记录规划器调用和token消耗，因为相等的环境暴露不等于相等的计算量。三个探针家族分别是木材种类 crafting、木制工具迁移和石制工具迁移，每个家族中相关链和目标链共享依赖模式但最终产物不同，每阶段上限450步，早期终止后重启新回合直到家族预算用完。这套设计之所以比之前的方法更好，是因为它把“内部状态变了”和“能力真的迁移了”区分开：只有目标世界重置后、在匹配对照下仍然出现的行为变化，才被算作经验驱动的能力增益。

实验结果显示，在直接能力矩阵上，基于控制器的执行明显优于依赖规划器的变体：STEVE-1、仅控制器的JARVIS-1和Optimus-1变体平均TSR/WGP/VMP分别达到8.4/6.4/25.5、7.5/5.5/25.0和8.1/6.1/25.4，在核心进展和目录迁移分区上优势最大，因为这些分区需要多个依赖动作；无操作基线和GPT规划的JARVIS-1则停留在执行地板，证明基准确实把主动任务求解和背景行为分开了。但在配对迁移探针上，相关经验没有带来稳定增益：它既没有改善任何一个工具探针，木材种类上的微小提升也完全依赖单个种子，所有置信区间都包含零；阶段审计进一步表明，早期木材采集和 crafting 瓶颈经常让后续能力根本未被观测到。论文的局限也很明确：它目前只覆盖前向迁移，参考方法在匹配控制下没有展示出稳定迁移，长链中的早期执行瓶颈会掩盖后期能力，而且探针家族和任务目录虽然固定但规模有限。不过它的意义在于把具身递归自我改进从“存了记忆就算进步”推进到“必须在重置世界和匹配对照下审计出可归因的能力变化”，并指出未来的RSI方法必须先清掉这些执行瓶颈，否则任何增益宣称都缺乏说服力。
