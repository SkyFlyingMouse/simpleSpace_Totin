## 大模型 LLM

### [Hierarchical Continuous Diffusion Language Models](https://arxiv.org/abs/2610.02193)
`评分4`

离散扩散语言模型一直被看作自回归生成之外最有吸引力的替代路线，因为它天然支持双向推理和全局约束满足——每一步可以并行解码多个 token，而不是像自回归那样从左到右一次性锁死。但这条路有个结构性瓶颈：并行解码时，每个位置都是从自己的边缘分布里独立采样出来的，联合分布被近似成边缘分布的乘积，token 之间的统计依赖被直接切断。这在语法、逻辑、物理约束紧密耦合的任务上恰恰最致命。连续扩散语言模型试图绕开这个问题，做法是对一个所有 token 共享的连续状态做去噪，这样并行解码的 token 都依赖同一个隐变量，而不是各自为政。可它的问题是对称的：去噪器只看得到连续状态，训练目标里没有任何一项涉及 token，直到最后一步解码之前，整个轨迹和合法的 token 配置之间没有任何约束。rounding 和 self-conditioning 虽然把模型自己估计的 token 反馈回去当输入，但那个估计既不是模型的变量，也不在目标函数里，所以并没有真正解决问题。两类方法的缺陷正好互补：并行 token 需要一个共享状态来依赖，连续隐变量需要一个离散配置来锚定。

HC-DLM 的核心洞察就是把这两个互补的需求直接焊在一起，构造一条两层级的反向链。整条链里唯一持续存在的状态是连续隐变量轨迹，token 不再是独立的生成链，而是在每个反向步骤中从当前隐变量里通过一个 readout 分布读出来，再经过离散前向核重新加噪，作为下一步隐变量转移的条件反馈回去。这个设计的关键在于：token 状态是生成模型的变量，拥有自己的前向核，所以它和之前那种“把估计值当输入喂回去”的做法有本质区别。在生成模型里，第 t 步的 token 只通过第 t 步的隐变量依赖过去，因此 token 本身不携带跨步的转移链，每个位置在每一步都会被重新读出，始终可修正。作者把这种组织方式称为层级耦合，它同时决定了训练和采样：训练目标来自对这条两层轨迹的变分下界，推导时利用连续和离散前向腐蚀过程相互独立这一事实，把 ELBO 拆成可解释的重建项、先验匹配项、边界项和去噪项，其中离散 token 预测子项在形式上与类别离散扩散的 KL 完全一致，相当于在保留离散扩散监督的同时，额外加了一路连续去噪信号。实际训练时，连续部分用 Conditional Flow Matching 实现，token 预测器采用 x0 预测参数化，先从噪声状态得到干净隐变量估计，再映射到干净 token 分布，这样中间层的 noisy-token KL 就被一个干净 token 的交叉熵控制住。推理时从标准高斯和离散先验出发，每一步先用去噪器在 token scaffold 条件下估计干净隐变量并推进连续状态，再用 token 预测器读出干净 token，最后通过已知前向核重新加噪得到下一步的 token 状态，如此交替直到最后一步输出结果。

在 Sudoku、Countdown 和 LM1B 三个任务上，HC-DLM 在相同模型规模下同时超过了离散扩散和连续扩散基线，Sudoku 和 Countdown 上拼图准确率更高，LM1B 上生成困惑度更好。消融实验进一步说明，连续隐变量和 token 反馈缺一不可，去掉任何一个都会让性能明显掉下来，这直接验证了层级耦合不是装饰性的设计，而是性能来源本身。当然，这篇工作也有它的边界：方法引入了一个额外的编码器和一条两层轨迹，训练和推理的计算开销比纯离散扩散更高，ELBO 的紧致程度、编码器熵项权重的敏感性、以及在更大规模语言建模上的可扩展性，都还需要进一步验证。但它的意义在于指出了一个清晰的方向——离散扩散的 token 依赖瓶颈和连续扩散的锚定缺失，并不是两个独立的问题，而是同一个结构缺陷的两面，用一个层级化的连续隐变量作为唯一持久状态、让 token 每步读出并反馈，可以在不牺牲前向过程可解性的前提下把两者同时补上。这对后续做并行解码、约束满足和双向推理的扩散语言模型，提供了一条有原则可循的路线。

### [Finetuning with Sampling: SFT Learns Better Than You Think](https://arxiv.org/abs/2610.02140)
`评分4`

这篇论文要解决的是后训练阶段一个长期存在的两难困境：如何让前沿大模型获得全新能力，同时又不破坏它已有的能力。当前主流做法分两条路，监督微调（SFT）和强化学习（RL）。业界普遍认为RL泛化更强、遗忘更少，因为它是在策略上（on-policy）学习的——模型用自己的采样结果来更新参数，更新方向被约束在离原始分布不远的范围内。而SFT是离策略的（off-policy），它直接拟合专家数据，梯度更新可能又大又不稳定，导致在新任务上泛化差、在旧任务上灾难性遗忘。但RL也有致命短板：它依赖模型自己通过反复采样找到成功轨迹，如果模型对某道难题根本生成不出正确答案，奖励就没有方差，学习信号为零，这些难题在训练中被白白丢弃。而SFT恰恰能从离策略的专家数据中获取丰富监督信号，不需要模型自己会做。所以作者的核心动机是：能不能既保留SFT利用专家特权信息的能力，又让它享受到on-policy学习带来的泛化和抗遗忘优势？他们的答案是——不改学习算法，改数据分布。

核心创新在于一个叫“投影采样”（projection sampling）的MCMC算法，它把离策略的专家轨迹逐步“拉近”到基座模型的分布上，然后再拿这些被改造过的数据去做标准SFT。具体来说，作者首先形式化了一个目标：在所有“与专家轨迹语义等价”的轨迹集合上，找到一个离基座模型分布最近的分布，这在信息论里叫“信息投影”。这个目标分布其实就是基座模型在等价轨迹集合上的条件分布——既保留了专家数据的信息内容，又是基座模型最容易“消化”的形式。问题在于这个分布无法直接采样，因为基座模型对难题的等价轨迹概率极低。于是作者用Metropolis-Hastings算法来近似采样：从专家轨迹出发，用一个“保信息”的提议分布（比如对轨迹做局部改写但保证语义等价）生成候选，再根据基座模型对候选的似然比来决定接受还是拒绝。关键洞察在于，作者证明了在等价类内部运行MH等价于在全体轨迹上运行MH但目标分布换成基座模型本身，这样接受率的计算就变得可行。更重要的是，他们证明了每跑一步MCMC，数据生成分布与基座模型之间的KL散度就单调递减——也就是说，采样步数越多，数据就越“on-policy”。最终，这些被采样改造过的轨迹既携带了专家数据中的正确答案信息，又落在基座模型高概率区域附近，SFT在这种数据上更新时梯度更稳定、偏移更小，从而在获得新能力的同时不大幅偏离原有分布。

实验结果覆盖了科学技能习得、数学推理和开放式专业知识等任务，SFT配合投影采样在泛化到新任务和保留旧能力两个维度上都超过了强on-policy基线，包括RL和自蒸馏方法（如OPSD）。论文强调这些提升不是靠“锐化”基座模型已有的分布，而是真正学到了新东西——微调后的模型展现出强分布性能，说明它不是在原地打转。局限方面，MCMC采样本身有计算开销，每一步都需要评估基座模型对候选轨迹的似然，而且“语义等价”的判定依赖任务相关的等价关系定义，在开放式任务中可能需要LLM评分器来近似，这会引入噪声。此外，收敛速度和混合时间在实践中是否足够快，论文没有给出大规模模型上的详尽分析。但这项工作的意义在于提出了一个更高层的视角：采样可以作为一种“模型原生算子”来塑造数据的可学习性，而不仅仅是生成或推理的工具。这意味着后训练流程中，数据端的分布工程可能和算法端的损失设计同等重要，甚至更关键——SFT远比人们以为的更强，前提是你喂给它的数据被适当地“投影”过。

### [KaliBench: A Fine-Grained Benchmark for Cybersecurity Tool Use on Kali Linux with Runtime-Free Verifiable Rewards](https://arxiv.org/abs/2610.02206)
`评分3 · Accepted at NeurIPS 2026 Evaluations and Datasets Track. Pro · 有代码`

大语言模型正越来越多地被用于网络安全工作流，从交互式助手到自主代理都有涉及，但现有评测要么停留在知识问答层面（如SecEval、CyberMetric、SecBench等通过选择题或结构化问答考察概念理解），要么走向端到端的代理任务评测（如CyBench、NYU-CTF Bench用CTF挑战衡量综合表现），却始终没有直接测量模型能否为真实网络安全工具生成可执行的命令行指令。这个空白之所以关键，是因为安全运营高度依赖庞大而异构的命令行工具链——Kali Linux就预装了超过两千个安全工具包，分析师必须把"扫描这个子网的SMB配置错误"这类高层意图翻译成Nmap、Metasploit、Volatility等工具精确的CLI调用。而CLI是极其严苛的：参数顺序、标志拼写、别名误用或工具理解偏差，任何一处小错都会导致执行失败。与通用函数调用评测（如BFCL、ToolSandbox、StableToolBench）不同，那些基准假设工具有JSON schema明确定义功能和参数，而网络安全工具是"无schema"的——在典型部署中把成百上千个工具的模式塞进提示词并不现实，模型必须自行推断工具与参数，并生成语法正确、可执行的命令。这正是KaliBench要回答的核心问题：当前LLM能否可靠地把自然语言安全请求翻译成精确可执行的CLI命令？

KaliBench的核心设计围绕"细粒度、可验证、无需运行时"三个关键词展开。数据构建采用"手稿锚定"流水线：从Kali Linux官方仓库中提取2372个工具的结构化Markdown文档，解析出长短选项和别名，并用Qwen3-Max为每个工具生成10到13条自然语言查询与命令对，同时标注工具名、别名感知的可选参数键值对以及有序的位置参数，初始产出2.7万条数据。由于幻觉严重——人工抽查发现超过50%的生成命令含有虚构或拼错的选项（比如把--silence写成--silent）——作者设计了三阶段人机回环验证：先用LLM作为验证器，对照工具手稿检查每个标志和参数是否有文档支持、命令是否忠实实现查询意图，这一轮就过滤掉53.8%；再把通过的命令放进预装kali-linux-everything镜像的Docker沙箱中真实执行，记录stdout、stderr、退出码和超时，基于规则剔除那些因工具或参数无效而报错的样本，又去掉11.95%；最后针对最强模型在"提示"设置下仍失败的案例做人工复核，发现另有4.9%存在CLI选项畸形、遗漏查询明确要求的参数或参数语义错配等问题。经过SemHash语义去重（以查询、工具名、真值命令为语义单元，余弦相似度超过0.90即聚类保留代表样本），最终得到8504条高质量查询-命令对，覆盖1642个工具、23个能力维度和5个安全阶段，其中5000条作为评测集（覆盖全部工具）、3504条作为训练集（覆盖962个工具）。评测时模型在三种设置下生成命令：无限制（只给查询）、受限（额外给20个候选工具名，含正确工具）、提示（再给候选工具的官方文档，近似schema式函数调用）。评分用Python的shlex做词法解析而不执行命令，因为数据集已显式记录真值工具名、别名感知的可选参数和有序位置参数，所以可以确定性地逐组件打分：工具准确率、可选参数F1、位置参数F1、总得分以及只有工具和全部参数完全匹配才为1的精确正确率。这种确定性结构还带来一个关键副产品——无需运行时执行即可计算可验证奖励，因为命令的正确性完全由结构匹配决定，这使得强化学习训练可以大规模扩展而不必反复启动沙箱。

在实验结果上，作者评测了24种通用和安全领域的开放权重模型配置，发现在无限制设置下没有任何开放权重模型能超过42%的精确命令准确率，说明在没有工具提示的情况下准确使用CLI安全工具极其困难，而参数构造而非工具选择才是主要瓶颈。更值得注意的是，利用KaliBench的确定性信号做可验证奖励，对8B模型进行监督微调和带可验证奖励的强化学习后，其在三种评测模式下的平均总得分提升了7.5个百分点，性能可与685B的MoE模型相媲美。这揭示了一个重要含义：网络安全CLI工具使用的能力瓶颈未必在于模型规模，而在于是否有细粒度、可验证的监督信号来教会模型参数构造的精确性。当然，KaliBench也有其局限：数据生成依赖Qwen3-Max，可能继承其偏差；沙箱验证中参数是合成的（地址、设备、路径可能不存在），基于规则的过滤未必能捕捉所有语义错误；评测集虽覆盖全部1642个工具但每工具样本数有限；提示设置下提供文档虽近似schema调用，但与真实部署中模型需自行检索文档仍有差距。尽管如此，KaliBench作为首个面向无schema网络安全CLI工具调用的细粒度基准，把评测从"模型知道什么"推进到"模型能否精确执行"，并通过运行时无关的可验证奖励打通了从评测到训练的闭环，为这一方向提供了可复现、可扩展的基础设施。

### [Every Ablation Is a Dose: Counterweights and the Semblance of Self-Repair](https://arxiv.org/abs/2610.02173)
`评分3`

这篇论文要解决的是机制可解释性中一个长期困扰研究者的真实问题：消融实验的因果推断被“自修复”现象污染。所谓自修复，是指当你删除模型中某个组件后，下游组件会调整自身行为，使模型表现部分恢复，导致你低估被删组件的重要性，甚至错误归因它的功能。此前的研究，如备份名称移动器、Hydra效应、抗擦除神经元，都是通过先消融再观察哪些组件发生变化来发现的，但这种方法只能看到单个删除点上的效果，无法区分一个组件是“被激活”还是“按比例响应输入位移”。最系统的研究甚至得出结论说自修复是噪声性的，不太可能有单一机制。论文作者认为这个结论是错的，自修复其实有唯一机制：补偿是一种在消融前就已经存在的固定增益。传统消融方法只是在一条坐标轴上的未校准点，而这条轴代表的是反事实对比的带符号强度。

论文的核心创新在于把干预从离散的“删或留”变成连续的“剂量”，并引入嵌套反事实干预来观测下游方向的响应。具体来说，作者定义了一个核心方向c，它承载了模型对真/假判断的类别信号。对于一对反事实提示（比如一个真陈述和一个假陈述），核心方向的激活可以分解为中点m（共享上下文）和对比Δ（类别差异信号）。任何对核心的钳制值v都可以用单个标量λ参数化：λ=+1表示保持干净激活，λ=-1表示换成反类激活，λ=0表示停在类别中性中点。这样，所有传统消融（置零、置均值、重采样）都只是这条轴上的某个特定λ点。然后，作者在同一个剂量世界里测量下游方向r的贡献：先对核心施加剂量λ，再在扰动后的模型中，把r的系数替换成它在配对提示上的自然值，看判决边际被抹去多少。这个估计量是总效应，因为两次前向传播都在同一个剂量世界中进行，核心位移带来的共同偏移会相互抵消。关键发现是，在自然激活窗口|λ|≤1内，下游方向r对判决的贡献与剂量λ呈仿射关系：E_r(λ)=own_r+γ_r λ。斜率γ_r是一个固定系数，无论有没有消融都持续影响模型，它的符号决定这个方向是“配重”（γ_r<0，即反对核心信号）还是“继电器”（γ_r>0，即放大核心信号）。这个斜率可以从静态检查点中核心的写入向量与r的读取权重的对齐程度预先估计出来，说明它不是实验设计的伪影，而是网络权重的内在属性。

在结果方面，作者在四个不同家族的指令微调模型（Gemma、Qwen、LLaMA、Mistral）上，用一个零样本事实判决任务（真/假陈述）进行了验证。他们从权重中命名了一个包含81个下游方向的基准集，这些方向在未嵌入层上具有可读的真/假词元极点。结果发现，核心能触及的81个方向中有68个在两种拟合下都可靠地偏离零斜率，其中52个是配重，16个是继电器。在GPT-2 Small的IOI电路上，干预能触及的10个头中有7个遵循该定律，且全部是配重。用三个剂量点（λ=+1,0,-1）拟合的直线，能预测未见的中间剂量（λ=±1/2），样本外R²在0.65到0.91之间。这意味着，看似自修复的现象，其实只是配重在对比信号从核心涌现时执行其常规操作。局限在于，该定律只在|λ|≤1的流形窗口内成立，超过完全反转后响应会饱和；基准集的选择依赖于可读极点，可能不覆盖所有类型的补偿；重归一化只能解释最多4.5%的招募。这项工作的意义在于，它把自修复从一种模糊的、噪声性的现象，转变为一种可预测、可从权重中预先计算的确定性耦合，从而让消融实验的因果推断重新变得可靠，也为理解模型内部的反事实信息流提供了新的定量工具。

### [AutoCompact: Learning When to Compact Context in Long-Horizon Coding Agents](https://arxiv.org/abs/2610.02163)
`评分3`

这篇论文要解决的是长程编程智能体在仓库级软件工程任务中的上下文管理问题。这类智能体需要通过代码检查、搜索、编辑和测试等多轮交互来解决复杂问题，随着任务推进，早期探索产生的假设、失败尝试和冗长的工具输出会逐渐过时，继续保留完整历史会让上下文被大量无关细节占据，而下一阶段真正需要的只是一个紧凑的工作状态——已得出的结论、相关代码与工作区状态、以及剩余待执行的动作。因此，有效的上下文管理要求智能体自主决定三件事：何时压缩、保留什么信息、以及如何从压缩后的状态继续执行。现有方法只解决了部分问题：以CompactionRL为代表的长度触发方法只在剩余上下文预算低于固定阈值时才压缩，把压缩绑定到上下文长度而非任务进展，导致过时探索不断累积，且压缩可能发生在某个尚未解决的阶段中途，而此时证据仍然需要；以SelfCompact的推理时评分标准和SWE-Compressor的离线插入压缩调用为代表的前瞻式方法虽然让智能体自己决定何时压缩，但仅决定时机并不够——工作状态可能遗漏或错误表达关键信息，即便状态正确，智能体也可能不遵循它，重新访问已完成的探索或忽略既定的下一步动作。评分标准方法不提供训练信号，离线插入方法则保留了插入调用之后的原始动作，两者都无法解决这些失败模式。

AutoCompact的核心创新在于把压缩决策作为策略的一部分来训练，让智能体同时学会何时压缩、保留什么以及如何继续。具体做法分两阶段：首先在数据收集阶段，让基础智能体在编程任务上运行，用一个评判模型（GPT-5.5-Codex）在线审查其压缩决策、生成的摘要以及压缩后的动作，评判模型依据预定义的标注协议判断三类决策是否合格——触发纠正检查当前时机是否适合压缩（当前阶段已充分解决才应压缩，中间证据仍需要时应继续探索），工作状态纠正检查生成的“# Auto Context Summary”是否准确保留了后续执行所需的信息，继续纠正检查压缩后的首批动作是否遵循了工作状态而非重访已完成的探索。关键在于，纠正发生在执行之前：当评判模型判定某个输出不合格时，它会写出修正后的输出，环境执行的是修正版本而非原始版本，策略随后从这个被修正的历史继续生成动作，因此每个纠正都会塑造轨迹的后续部分，这与事后标注有本质区别。收集到的1052条经过评判修正的轨迹用于监督微调，其中24%监督压缩触发、53%监督工作状态构建、23%监督压缩后继续，使AutoCompact-SFT同时学会普通编程行为和三种压缩行为。随后进入第二阶段，从SFT检查点出发，在SWE-Gym上用组相对策略优化（GRPO）做端到端多轮强化学习，每个 rollout 根据最终补丁是否通过任务测试获得二值结果奖励，GRPO在组内把结果转化为相对优势，为轨迹中所有模型生成的 token 提供统一学习信号——包括普通编程动作、调用compact()的决策、生成的上下文摘要以及压缩后的继续执行，因此压缩不需要单独的辅助目标或专门的奖励塑形。由于每次compact()都会重写上下文，一条含压缩的轨迹不再构成前缀单调增长的单一序列，论文按上下文前缀被重写的位置把轨迹切分成多个段，段内每个模型轮次的条件前缀只增不减，所有段共享同一优势值，策略损失在批次内按 token 级别对所有段取平均，不使用KL惩罚或熵奖励，二值结果奖励是编程和压缩的唯一训练信号。

在SWE-bench Verified和SWE-PolyBench Verified上，AutoCompact分别达到39.6%和24.5%的通过率，相对基础模型绝对提升9.2%和5.0%。与基线相比：长度触发的Fixed Compaction反而比基础模型低1.6%和0.9%，说明在受限上下文设置下长度触发压缩有性能代价；CompactionRL通过RL比Fixed Compaction提升3.9%和1.2%，但相对基础模型的增益仍然有限；在256K长上下文设置下，所有前瞻式方法（SelfCompact、SWE-Compressor和AutoCompact变体）都优于基础模型，说明即使完整历史能放进上下文，前瞻式上下文管理仍有帮助。AutoCompact-SFT比SWE-Compressor高1.2%和1.6%，两者使用相同基础模型、脚手架和可比训练数据，差异在于在线评判修正让修正后的输出（包括压缩后的动作）真正被执行，而SWE-Compressor只是把压缩调用插入已完成的轨迹并保留其原始后续动作。结果奖励RL在SFT基础上再提升7.4%和2.8%。在成本效率方面，从每任务0.10美元到4.00美元的六个推理预算下，训练后的策略在所有预算上都一致优于基础模型，RL相对SFT在低预算下增益尤其明显；同一训练检查点在执行压缩与忽略压缩两种条件下的对比显示，压缩在紧张推理预算下特别有益。局限方面，论文的方法依赖评判模型在线修正数据收集，训练数据规模为1052条轨迹、379个SWE-rebench任务，评判模型本身的能力和标注协议质量会影响监督信号；RL阶段使用二值结果奖励，对压缩质量的细粒度反馈有限，且训练和评估集中在特定基准和Qwen3-Coder-30B-A3B-Instruct模型上，跨模型和跨任务域的泛化性尚未验证。总体而言，这项工作表明上下文压缩不应仅被视为防止溢出的被动手段，而应作为智能体策略中可学习的一部分，通过让压缩决策、摘要构建和后续执行共同接受任务结果的监督，智能体能够在长程编程任务中更高效地利用上下文预算，这一思路对更广泛的LLM智能体长程决策场景具有参考意义。

### [From Knowledge Access to Source Learning: Developing Source-Specific Competence](https://arxiv.org/abs/2610.02150)
`评分3 · Website: https://sourcelearn.github.io/ Code: https://github · 有代码`

这篇论文要解决的核心问题是：当LLM智能体反复依赖同一个外部权威知识源（比如一套API文档、一个代码仓库、一份文档集）来完成一系列知识密集型任务时，现有方法并没有真正利用"反复使用同一来源"这件事来提升对来源本身的理解。目前的主流做法分两条线：一条是检索增强和结构化表示（如RAPTOR的层次摘要、GraphRAG的图结构、HippoRAG的联想检索等），它们优化的是"怎么在查询时把源内容取出来、组织好"；另一条是智能体记忆系统（如A-MEM、AriGraph、ReMe等），它们保留的是从过往交互中积累的经验知识。这两条线优化的是不同的对象——前者服务于单次查询时对外部知识的调用，后者保存的是从交互中蒸馏出的可复用信息——但都没有把"对来源本身的理解"当作一个可以持续学习、逐步精炼的对象。结果就是：即使有持久化索引或结构化表示，可复用的理解仍然可能是碎片化的，每来一个新任务都需要重新拼接；而任务经验虽然被保存下来，却容易变成"记住了这道题的答案"而非"更懂这个来源"。论文把这一空白定义为"来源学习"（source learning）：能否通过反复学习和使用，逐步积累关于来源本身的可复用能力，而不是把每次使用都当作一次孤立的访问事件。

SourceLearn的方法设计围绕一个核心洞察展开：学习信号决定"该重新审视什么"，但持久化的知识必须从权威来源重新构建，而不能直接把观察结果或任务答案写进记忆。系统维护一个显式的、可修改的"来源模型"，以实体为单位组织可复用的理解——包括重要属性、机制、适用条件、流程、例外、实体间关系等——同时保留跨实体的高层结构。这个模型刻意不复制源的全部内容，而是保持紧凑，把容易检索的底层细节留给原始来源。构建分两个互补机制。自导向来源学习采用"检查—研习—巩固"循环：先以当前模型为条件重新阅读每个实体的源内容，问的不是"这段说了什么"而是"当前表示还解释不了什么"，比如某个机制只被部分表示、某条规则的适用条件仍是隐式的、某个跨实体引用尚未整合；然后一个自适应规划器根据当前模型、累积观察和历史，选择少量"深化"（深入某个实体的未解方面）或"连接"（联合研究两个实体间可能存在的依赖）动作，每个动作生成一个临时研习问题来指导检索和重读；所有观察先累积、不直接改模型，直到研习结束后统一通过"有据重构"机制提交——即只有被源证据支持、且不丢失已有支持含义的更新才会被写入。这形成了"多读一次写"的模式，避免边看边改导致的碎片化和错误固化。任务导向来源学习则从下游任务中提取两类信号：失败案例揭示局部表示缺陷（某任务需要的源知识在模型中缺失），重复出现的任务模式揭示更广的表示偏好（源知识应该以什么形式组织才便于使用）。同样地，任务只用来诊断"哪里不够好"，具体的持久化更新仍然回到权威来源重新构建。推理时，来源模型按任务相关性激活不超过预算的token量，与直接从源检索的任务特定证据一起提供给求解器，两者互补：前者提供积累的可复用理解，后者保证精确的源证据可及。

实验在五个基准、三种LLM后端上进行，覆盖文档问答、代码问答、工具使用和交互式环境，SourceLearn在15个设置中拿下13个最佳，相对Hybrid RAG最高提升22.6个点，整体上显著优于任务局部检索、静态来源表示和基于经验的记忆基线，且自导向和任务导向两种学习各自都带来增益。局限方面，论文没有详细讨论来源模型在源本身发生更新或版本变化时如何高效迁移，也没有分析当源规模极大时实体划分和区域构建的代价，以及"有据重构"在源证据存在歧义时如何裁决。但这项工作的方向性意义比较明确：它把"对来源的理解"从检索和记忆的附属品提升为一个独立的、可持续学习的目标，提出了一个可操作的表征（来源模型）和两条互补的学习路径，并且坚持"源始终是事实权威、学习信号只做导航"这一原则，为同一来源上长期运行的智能体提供了一种超越"反复检索+经验堆叠"的累积式改进范式。

### [Argo-Bench: Evaluating Data Agents on Enterprise-Scale Workflows](https://arxiv.org/abs/2610.02122)
`评分3 · 41 pages, 4 figures, 18 tables. Code: https://github.com/Tex · 有代码`

Argo-Bench 要解决的核心问题是：现有的数据智能体评测基准已经严重偏离真实企业数据工作流。Spider 2.0-Snow 的得分从发布时的 23.8% 飙升到 96.7%，BIRD 也达到 82.4%，看起来 text-to-SQL 快被解决了，但这些基准存在三个致命缺陷。第一，它们跑在拼凑的公开数据集上，Spider 2.0-Snow 的 547 道题散落在 152 个数据库上，超过三分之一的数据库只被一道题用到，三分之二的表是日期、地理或版本分片的副本，而真实企业仓库里同一个业务事件可能横跨十张以上的表，各模块之间的数字必须对得上。第二，它们不是端到端的，很多高价值的企业数据科学任务根本没法用 SQL 完成，比如拟合需求预测、训练欺诈模型、优化配送调度，这些需要统计、机器学习和优化库，而且发现问题的目的是做决策，决策的优劣要看投资回报，一个高兑换率的促销如果大部分订单本来就会发生，那它可能是亏钱的，SQL 的 gold answer 根本区分不了这种决策质量。第三，它们不可验证，最近一次审计发现 Spider 2.0-Snow 发布的 gold query 有 62.8% 是错的，BIRD Mini-Dev 有 52.8% 是错的，修正 BIRD 的错误后智能体的排行榜名次最多变动九位，更麻烦的是很多最有价值的企业任务答案根本不在数据里，没被发现的欺诈不会留下标签，被否决的决策的后果永远不会被观测到。真实企业把财务规划、预测和欺诈检测所需的记录放在 Oracle EBS、SAP S/4HANA 这类 ERP 系统里，但这些系统同时持有公司的总账、工资单和客户记录，访问受到严格限制，所以 ERP 数据在基准测试中几乎从未被探索过，偶尔释放也要匿名化，而匿名化会破坏答案所依赖的关系结构，BEAVER 的早期版本就出现了主键违反唯一性约束、gold query 为 null 的问题。

Argo-Bench 的核心洞察是：与其在真实数据上标注答案，不如模拟一个业务世界，用模拟器的隐状态作为 ground truth 来评分。它模拟了 2024 年纽约市的一个外卖平台，这是一个三方市场，经济学数据每月向市政府披露。模拟器基于 34 个公开数据集和报告构建，每个数据集贡献一个机制，比如 Uber 和 Lyft 的行程数据提供两个区域之间在特定时段的驾驶时间，MenuStat 提供连锁餐厅的菜单。这些数据源扮演三种角色：身份捐赠者提供纽约市真实实体的公开记录，比如 45,834 家餐厅、107 万个地址、260 个出租车区域，直接进入世界；形状捐赠者提供在其他地方、其他人、其他年份测得的分布；锚点则是已发布的总量，世界被校准去复现但从不从中采样记录。选择纽约外卖是因为其经济学数据异常详尽，平台必须向 DCWP 报告月度订单、消费者支出、商户费用、配送员收入和工时，DCWP 每季度发布，DoorDash 和 Grubhub 的 10-K 文件提供了平台资产负债表的形状。最终世界包含 8100 万订单，约占 DCWP 报告的 2024 年 1.48 亿配送量的 55%，340 万活跃客户，每单经济学在 16 个季度比较中有 13 个落在 DCWP 数字的 5% 以内。2024 年被选中是因为有一个真实的外生冲击：纽约市从 2023 年 12 月开始对 app 餐厅配送员执行每小时 17.96 美元的最低工资，2024 年 4 月 1 日提高到 19.56 美元，模拟器用一个在 4 月 1 日激活的新配送员调度器来建模平台的响应，之后配送员薪酬比锚点高 6% 到 9%。模拟器还植入了公开证据显示的外卖平台主要欺诈模式：配送员取餐后偷餐、伪造 GPS、用机器人抢单、出租账号，客户端有新手账号薅促销、盗卡进行账户接管和 bust-out，商户端有空壳店、与配送员或常客合谋退款、付款被改到其他银行账户。每种模式都根据真实卡欺诈的可分离程度以及诚实客户共享设备、地址或卡片的频率来校准，因为后者决定了检测器的精度。模拟器的最后一步把世界投影到 Oracle EBS 12.2 的 analytics export 中，仓库有 235 张表、75 亿行，每张标准表和列都存在于 Oracle EBS 12.2 Vision 实例的数据字典中，但平均只携带 Vision 对应表 52% 的列，省略的是未使用的 flexfield 以及 shipping、inventory、外币、预扣税等功能，这些列在这个业务中本来就是空的。仓库刻意不包含数据漂移或不一致，比如废弃表与活跃表重叠、跨表数字对不上，虽然顾问认为这是与客户系统最大的差异，但作者选择保留这个差异以保持 ground truth 无歧义，因为如果遗留表与活跃表冲突，正确答案就取决于未文档化的约定。任务设计上，210 个任务分布在五个业务领域：信任与安全、FP&A、市场、会计、增长。每个任务有四个部分：prompt 以利益相关者的口吻陈述问题，scope 设定智能体可见的最后一个月，expectations 列出评分器要求的 filings，answer key 在任何运行前冻结，来自隐表的 SQL 或模拟器自己的标签。智能体不返回查询，而是通过沙箱中的 Python 库向 mission-control 接口提交 action，比如封禁欺诈账户、分配配送员激励预算、发放补发工资。评分器知道隐状态，所以可以按决策的后果评分：封禁列表按它阻止的欺诈损失评分，包括平台从未检测到的欺诈损失，减去错误封禁客户带来的收入损失；预测按加权区间评分在结果前固定的参考预测设定的尺度上评分，所以提交真实的中位数和区间是最优策略；预算分配按模拟器实现的可达节省份额评分。

在 14 个前沿和开放权重模型上评估，最强的 Claude Opus 5.5 只解决了 34.8% 的任务，平均 59.5 分，14 个模型中有 9 个平均低于 35 分。模型经常分析错误的量或优化错误的目标。这个结果的意义在于，它揭示了当前数据智能体在真实企业工作流中的巨大差距，而这个差距被 text-to-SQL 基准的高分掩盖了。Argo-Bench 的贡献包括：一个合成的大规模公开 ERP 数据集，235 张相互约束的表、8100 万订单、340 万活跃客户、75 亿行，一个订单会解析为调度决策、配送员薪酬、商户付款和平衡的总账日记账；一个按行动后果而非查询正确性评分的评分器，使用模拟器隐状态作为 ground truth；以及 210 个任务的基准和 14 个模型的评估。局限方面，仓库刻意不包含真实数据仓库中常见的数据漂移和不一致，这虽然保持了 ground truth 无歧义，但也意味着智能体不需要处理遗留表冲突、未文档化约定、语义层和机构知识这些真实企业环境中的核心挑战。此外，仓库没有外币交易，只有 43 个资产负债表账户。论文使用第二个私有种子的世界进行评分，公开释放的仓库在 Hugging Face 上以 CC BY 4.0 发布，任务、参考智能体、工具服务器和沙箱以 Apache License 2.0 发布，排行榜只在私有世界上评分，所以分数不能通过记忆公开仓库获得。这个方向的影响可能是推动智能体从理解、导航到在真实数据环境中行动，而不是停留在查询生成上。

### [Where-OPD: Spatially Guided On-Policy Self-Distillation of MLLMs with Synthetic Scenes](https://arxiv.org/abs/2610.02117)
`评分3 · 有代码`

这篇论文要解决的核心问题是：多模态大模型（MLLM）在需要精细视觉感知的任务上表现不够好，而现有的基于在线策略自蒸馏（On-Policy Self-Distillation, OPSD）的改进方案存在明显的适用性瓶颈。OPSD 的基本思路是让学生模型自己生成推理轨迹，然后由一个拥有“特权信息”的教师模型在这些学生实际访问过的状态上提供逐 token 的监督信号，教师通常是学生本身的冻结副本或 EMA 副本，因此推理时不需要外部教师。此前将 OPSD 用于 MLLM 的工作——如 Vision-OPD 和 Imagine-OPD——主要采取的策略是给教师提供更好的视觉输入，比如问题相关区域的裁剪图或放大视图，而学生只能看到原图。这种“教师看得更清楚”的不对称设计在细粒度定位任务上确实有效，比如 Vision-OPD 在 V* 上给 Qwen3.5-4B 带来了 8.90 分的提升、在 ZoomBench 上提升了 14.56 分，但问题在于这种增益并不均匀：同一个方法在 CountQA 上反而掉了 10.73 分。原因在于，裁剪或缩放本质上改变了教师看到的图像内容，它教会学生的是“如果看得更清就能答对”，但学生推理时并没有这种增强视图，而且很多视觉任务——计数、文档阅读、图表理解——需要的不是看得更清，而是知道该看哪里、如何把分散在图像各处的证据整合起来。此外，这些方法依赖人工标注的 grounding 数据或外部更强的教师模型来生成裁剪区域，扩展成本高。

Where-OPD 的关键洞察是：与其告诉教师“你应该看到什么”，不如告诉教师“相关证据在哪里”。具体来说，教师和学生在训练时接收完全相同的图像和问题，但教师额外获得一段文本形式的空间 grounding 提示，这段提示明确指出问题相关的视觉元素及其在图像中的位置。比如对于“图中有多少辆汽车”这样的问题，提示会列出每个匹配目标的位置坐标并给出计数。学生则只能从图像和问题出发，学习复现教师在这种空间引导下产生的行为。为了大规模获取这种提示而不依赖人工标注或外部模型，作者采用程序化生成的合成场景：在 1024×1024 的画布上放置 12 到 40 个不重叠的彩色几何形状（七种形状、十二种颜色），每个场景的物体身份、属性和坐标在生成时就是已知的，因此可以自动构造出问题、答案和空间提示的完整训练三元组。训练目标是最小化学生分布与教师分布之间的广义 Jensen-Shannon 散度，教师分布被视为固定目标，梯度只流过学生；计算上只在学生概率最高的 100 个 token 上计算散度并附加尾部概率项，教师在整个训练过程中保持冻结。推理时提示被完全移除，学生只看到图像和问题。这种方法之所以比之前的方法更好，是因为它不改变教师看到的视觉内容，而是教会学生一种可迁移的注意力分配策略——即如何在图像中定位和整合多个相关区域——这种策略不依赖于特定的视觉增强，因此能够泛化到合成场景之外的真实任务。

实验在三个 MLLM 上进行：Qwen3.5-4B、Qwen3.5-9B 和 Qwen3-VL-4B。在任务特定基准上，Qwen3.5-4B 在 ChartQA 和 EvoChart 上分别提升了 7.20 和 10.11 分，CountQA 和 OCRBench 分别提升 2.53 和 1.93 分。更关键的是跨域迁移效果：尽管后训练只用了合成场景，在 CVBench、V*、HR-Bench 4K、HR-Bench 8K、ZoomBench、MME-RealWorld 和 BLINK 这七个真实世界感知基准上的平均性能，三个模型分别提升了 3.23、1.07 和 1.29 分。这说明空间 grounding 的特权信息诱导出的不只是对合成任务的拟合，而是一种更通用的视觉证据定位与整合能力。局限方面，当前方法仅在计数任务上验证了训练信号的生成，合成场景的视觉复杂度远低于真实图像，且教师始终冻结在初始 checkpoint，没有探索 EMA 更新教师是否能带来进一步增益；此外，空间提示以文本坐标形式给出，对于需要密集空间推理的任务（如空间关系判断、多跳视觉推理）是否同样有效尚不清楚。尽管如此，这项工作开辟了一个有意义的方向：特权信息不一定要是更好的感知输入，也可以是对感知结果的显式空间描述，而程序化生成的合成数据足以支撑这种信号的规模化生产，并实现从合成到真实的显著迁移。

### [Scalable, Transferable Meta-network for Data Selection Requires a Different Loss (and Why the Obvious Choice is Problematic)](https://arxiv.org/abs/2610.02092)
`评分3`

这篇论文要解决的是大语言模型训练中的数据选择问题：面对海量且异质的语料，如何自动挑出真正有助于模型泛化的训练样本。已有的启发式打分方法（如熵、指令跟随难度、可约损失、与目标领域的距离等）各有信号但无法动态适应新场景，也难以组合成更强的排序机制。元学习式数据选择（MTS）提供了更原则化的替代方案，它把每个训练样本的权重当作可学习变量，通过验证集损失来反向指导权重更新，本质是一个双层优化问题。但MTS落地时卡在两个瓶颈上：一是可扩展性，精确超梯度需要对内层优化展开，即使只展开一步并用有限差分近似，每更新一次数据权重也要对模型参数做三次反向传播，Calian等人用64块v5 TPU才展开8步，普通学术实验室根本承受不起；ScaleBiO把反向次数降到两次，SEAL进一步降到一次但带来明显性能损失。二是泛化性，逐样本权重对未见数据毫无泛化能力，逐领域权重又太粗，无法刻画同一领域内样本质量的差异。一个直觉上很自然的想法是训练一个元网络，输入样本、输出权重，从而在小数据上训练、在大语料上推理。但此前所有尝试——包括Calian等人超大规模实验——都没有报告出对未见数据的泛化，作者自己的实验也发现直接这样训练会导致优化不稳定和泛化极差。

作者把失败原因追溯到现有MTS训练目标的两个性质。第一是竞争性权重压制：把ScaleBiO的目标对每个数据权重求梯度后可以看到，样本在伪标签高于当前加权均值时被上调、低于时被下调，而随着高伪标签样本权重上升，加权均值也被推高，形成赢者通吃的分配，大多数权重被压向零，元网络逐渐丧失区分好坏数据的能力。第二是持续偏好易学特征：该损失让网络只抓住那些与训练标签强相关但容易提取的特征，忽略更难但更可迁移的特征，从而陷入捷径学习，分布偏移下相关性减弱或反转时泛化就崩掉。针对这两点，作者提出TESS框架，核心是把ScaleBiO的目标换成一个简单的均方误差目标，称为Pointwise Value Matching（PVM）。具体做法是：先用均匀权重分别训练两个LLM，一个只在训练集上训练得到θ_U，另一个在验证集加训练集上训练得到θ_W；然后冻结这两个模型，对每个训练样本计算它在两个模型下的损失差Δ_i，即θ_U下的损失减去θ_W下的损失，这个差值越大说明该样本在验证引导模型下获得的损失下降越多、与目标验证目标越相关；最后把这个Δ_i当作伪标签，用均方误差监督元网络去拟合它。与原来的ScaleBiO损失相比，PVM不再做那种竞争性的归一化比较，而是让每个样本独立地回归到自己的效用值，因此不会出现权重被集体压向零的情况，也不会过度聚焦于容易拟合的特征，从而抑制捷径学习、促进泛化。在工程上，TESS采用顺序训练而非ScaleBiO的联合训练，三个模型分阶段优化，元网络和预训练LLM可以使用各自独立的优化调度，训练好的元网络直接对候选池中的未见样本打分，无需再优化，峰值内存比ScaleBiO降低超过20%。

实验在LLM安全和定向指令微调两个任务上展开，覆盖三种迁移设定：跨数据集迁移、小模型到大模型迁移、子集到全语料迁移。结果显示TESS在所有这些设定下都展现出显著优于基线的方法的泛化能力，而此前没有任何MTS工作报告过对未见数据的泛化，这是该方向首次实现这一目标。局限方面，论文的理分析主要针对TESS的顺序训练设定，虽然作者观察到ScaleBiO联合训练下也有类似的定性动态，但严格的理论保证尚未覆盖联合训练情形；此外PVM依赖两个LLM的损失差作为伪标签，这个信号的质量本身受限于验证集与训练集的分布关系以及两个模型的训练充分程度。意义上看，这篇工作把MTS从“逐样本或逐领域调权重”推进到“训练一个可迁移的打分网络”，并且指出失败根源不在元网络架构本身，而在损失函数的选择——这为后续在更大规模、更多任务上做可迁移数据选择提供了一个简洁且可扩展的基线，也提醒社区：直接把现有双层目标套到共享网络上并不可行，损失设计才是关键。

### [TACO: Ternary Absolute-max Column-wise One-sparse Optimizer for LLM Fine-Tuning](https://arxiv.org/abs/2610.02199)
`评分3 · 24 pages, 7 figures, 10 tables. Code available at https://gi · 有代码`

这篇论文要解决的核心问题是大语言模型全参数微调时优化器状态带来的显存瓶颈。以13B模型为例，BF16权重本身约占26GB，但AdamW的两个FP32动量缓冲区就要再吃掉约104GB，加上梯度约26GB，在考虑激活值和临时工作区之前就已经逼近156GB，这意味着AdamW的持久优化器状态大约是BF16参数内存的4倍，直接把能在单卡上微调的模型规模卡死了。已有的省内存路线各有代价：AdamW8bit和FlashAdamW用量化压缩优化器状态，Adafactor用行列因子分解近似二阶矩，GaLore和APOLLO把梯度投影到低秩子空间，但这些方法要么仍然保留稠密状态、要么引入近似误差；零阶方法虽然能把内存压到接近推理水平，却需要额外的前向评估来估计更新方向，在分布式训练或大batch场景下计算和通信开销反而上升。Muon走了一条不同的路，它把二维权重当作矩阵，保留一个动量矩阵并做正交化来近似谱几何下的最速下降方向，优化器内存比AdamW小，但状态仍是稠密的，而且从AdamW预训练的模型切换到Muon微调时会出现“优化器不匹配”导致的性能退化。所以问题就变成：能不能在保留一阶梯度信息和有竞争力的墙钟效率的前提下，把持久优化器状态内存压到几乎可以忽略？

TACO的关键洞察在于换一个算子范数几何，让最速下降方向本身就具有极端稀疏的结构。Muon用的是归一化2到2谱范数，对应的更新方向是梯度矩阵的极分解U V转置，虽然比AdamW省内存但状态稠密。TACO则把输入和输出空间都装备归一化的1范数，在这个1到1算子范数下，约束按列解耦，每一列独立地在一个L1球的极点上花掉自己的预算，也就是选该列中绝对值最大的那个梯度坐标的符号。这样一来，一个m乘n的更新矩阵最多只有n个非零元，而且这个稀疏性不是事后对梯度做Top-1裁剪强加出来的，而是局部最速下降问题的精确闭式解，m/n这个因子也不是额外的逐层缩放超参数，而是维度归一化的直接产物。但实际训练中minibatch梯度会让每列选中的坐标在不同step之间跳来跳去，如果老老实实维护稠密的梯度历史来稳定选择，内存优势就没了。TACO的做法是每列只保留一小撮低精度的动态“heavy hitter”梯度分量，用FP8稀疏梯度历史加即时梯度处理来稳定坐标选择，把持久状态从O(mn)降到O(n)，同时保留一阶梯度和列方向Top-1更新。理论方面，作者证明了vanilla TACO在标准光滑性假设下以O(ε⁻²)迭代次数到达ε稳定点，并且在一个固定输入的简化设定下证明了TACO与Adam代理共享相同的continuation几何和极限解，而Muon的谱几何则诱导出不同的continuation路径，这从几何角度解释了为什么TACO不会像Muon那样在AdamW预训练模型上出现优化器不匹配，同时还满足标准μP谱缩放。

实验层面，TACO在OPT-13B上把持久优化器状态相对AdamW8bit减少了174倍，从27.7GB降到0.16GB，峰值训练内存减少2.9倍，从80.6GB降到27.5GB，而精度和运行时间与AdamW8bit相当。更关键的是，TACO让30B到32B参数模型的全参数微调能在单张80GB H100上跑起来，比如OPT-30B在SST-2上峰值显存62.5GB、RTE上64.7GB、BoolQ上68.1GB，而Adam在这张卡上根本放不下这个模型。跨模型家族的迁移也在OPT、Qwen3、Pythia、Llama和Mistral上得到了验证。局限方面，TACO的收敛保证是针对vanilla版本在光滑假设下给出的，实际使用的FP8稀疏梯度历史加即时处理的实用版本并没有被同一个定理直接覆盖；每列只选一个坐标虽然内存极省，但在梯度信号本身就很稠密或者列内多个坐标同等重要的任务上，这种极端稀疏的更新是否总能匹配AdamW的最终精度还需要更多任务来检验；另外论文的对比主要集中在微调场景，从零预训练时TACO的表现尚未充分探索。总体而言，TACO的意义在于它把优化器内存问题从“压缩已有状态”转向“设计一种其精确最速下降方向本身就极度稀疏的几何”，并且通过continuation几何分析把优化器选择与预训练-微调匹配问题联系了起来，这可能会启发后续工作去探索更多算子范数几何下的稀疏优化器，以及把优化器几何纳入预训练阶段来消除微调时的几何不匹配。

### [The Missing Primitive: Diagnosing and Repairing Mathematical Reasoning in Large Language Models](https://arxiv.org/abs/2610.02191)
`评分3 · 27 pages`

大模型在数学推理上的表现越来越亮眼，甚至能对研究级难题给出像样的解答，但一个根本问题始终悬而未决：模型到底是真的理解了问题背后的数学结构，还是只是碰巧把答案“算”对了？现有评测几乎只看最终答案正确率或形式化证明能否通过验证，这种结果导向的指标掩盖了一个关键区分——模型是发现了让问题可解的核心结构，还是仅仅在执行一条推导链。论文指出，这两者可以完全脱节：模型可能通过似是而非的推理得到正确答案，也可能识别出高层的证明思路却在低层技术执行上翻车。随着模型生成的证明越来越长，一长串合法步骤虽然能保证正确性，却让底层的数学结构变得难以辨认，Terence Tao 也警告过，只优化形式正确性会产出大量正确但晦涩的证明，数学理解却没有相应增长。因此，作者提出需要一种超越结果验证的诊断方式，去暴露那些组织论证的“承重”想法——为什么这样做有效、哪些组件是本质的、什么可以被推广或复用。

为此，论文形式化了一个叫“数学原语”（Mathematical Primitive）的概念：它是揭示问题为何可解的那个本质性概念观察，捕捉问题与解法共享的潜在数学结构，比如不变量、定理条件、某种表示、归约或重述。原语必须简洁、针对具体问题、具有解释力，它不是例行计算、泛泛建议或完整证明。围绕这一概念，作者构建了 Prim 基准，把数学推理拆成四个互补维度：Discovery（只给问题，看模型能否独立发现原语）、Generation（零样本思维链直接解题，看最终答案精确匹配）、Digestion（给完整正确解法，看模型能否从中提取原语）、Execution（把原语喂给模型，看它能否据此解出问题）。数据来自 HLE-Verified 的 Gold 和 Revision 子集，随机抽 200 题，由 GPT-5.4-High 生成初始原语标注，再经三位数学研究生背景的专家独立审核，剔除 18 道不合格题，最终留下 182 题。原语评分不是简单的文本匹配，而是从三个角度打分：是否构成合法原语、是否识别出本质结构、是否解释了该结构如何使解法成为可能，并且按 Recast、Witness、Argument 三种原语家族分别处理，以容纳不同形式的数学结构。

诊断结果揭示了几个关键发现。首先，相似的解题正确率可以掩盖截然不同的能力画像——两个模型最终答案得分接近，但在 Discovery、Digestion、Execution 上的表现可能天差地别，说明只看准确率会严重误判模型的真实数学理解水平。其次，一旦把正确的原语显式提供给模型，Execution 维度会释放出大量潜在能力，也就是说模型其实“会做”，只是自己找不到那个关键结构。最重要的结论是，独立的 Discovery 才是数学推理的主导瓶颈：模型在给定解法后能较好地提取原语（Digestion），在给定原语后也能较好地执行（Execution），但让它仅凭问题自己发现原语时表现最差。进一步的后训练分析表明，受限于 Discovery 的失败恰恰是最容易被修复的，但现有方法在修复这些问题的同时，容易在模型本来就能解对的问题上造成退步。基于这些发现，作者提出 Absorb，一个“原语特权”的自蒸馏框架：训练时把数学原语作为特权信息，通过一个有界的覆盖机制，选择性地把原语引导的推理过程迁移进学生模型，使得模型在推理时不再需要原语输入，也能内化这种结构化的推理方式。实验显示，Absorb 在多个模型规模和多个高难度数学推理基准上，平均性能一致提升 2.42 到 4.48 个百分点。当然，论文的局限也很明显：基准规模只有 182 题，原语标注依赖专家和强模型生成，评分虽有多维设计但仍带有一定主观性，Absorb 的增益幅度虽然稳定但不算巨大，且“有界覆盖”机制在更大规模训练下的行为还有待验证。不过，这项工作把“结构理解”从模糊的哲学讨论变成了可操作、可评测、可修复的对象，为后续研究提供了一个清晰的诊断框架和改进方向，可能会推动数学推理评测从只看答案正确率转向同时考察发现、消化与执行等分离能力。

### [Trust the Direction, Search the Step: Zero-and-First-Order Methods for LLM Fine-Tuning](https://arxiv.org/abs/2610.02190)
`评分3 · Accepted to 40th Conference on Neural Information Processing · 有代码`

这篇论文要解决的是大语言模型微调里一个非常具体但代价高昂的问题：步长（学习率）怎么选。现代微调几乎都依赖 AdamW、Muon 这类一阶优化器，它们靠反向传播得到的梯度来决定参数更新的方向，方向本身通常相当可靠；但沿着这个方向究竟该走多远，却往往交给学习率调度、经验规则或大量超参搜索来决定。这个标量选择极其敏感：步长太小，当前 minibatch 里的信息没被充分利用，收敛慢；步长太大，又可能让训练震荡甚至发散。已有的做法要么是固定步长加调度，要么是完整线搜索——前者依赖调参且对局部几何变化不鲁棒，后者需要在同一方向上反复评估目标函数，对 LLM 来说计算上不可接受。零阶方法虽然只用前向评估、省去反向传播，但在高维参数空间里用随机方向做有限差分估计梯度，方差极大、噪声严重，单独拿来微调 LLM 并不现实。论文的关键观察是：一旦方向已经由一阶优化器确定，高维问题就退化成一维的“沿这条线走多远”的问题，此时少量零阶评估反而变得非常有信息量。于是作者提出 ZFO 框架，把“选方向”和“选步长”彻底解耦：方向仍然信任一阶优化器，步长则用零阶探测来定。

ZFO 的具体运作方式是这样的：在每个迭代步，基础优化器（如 AdamW）先算出更新方向，并把它归一化成一维搜索方向 z；标准一阶更新相当于在这条线上走一个由学习率决定的固定距离。ZFO 不直接采用这个距离，而是把当前 minibatch 固定住，在同一批数据上沿 z 方向做两次对称扰动评估，也就是在正负 epsilon 处各算一次前向损失。由于 minibatch 不变，这两次额外评估只需要重新打分，不需要重新采样数据或收集新反馈，成本远低于完整线搜索。结合反向传播已经给出的方向导数，以及这两次探测，ZFO 就能估计出沿该方向的一阶、二阶甚至三阶导数信息，进而构造局部模型：既可以用二阶或三阶泰勒多项式，也可以用二阶或三阶帕德有理逼近。然后在这个局部模型上，于一个受控区间内最大化，选出曲率感知的步长。这个区间上界是基准步长的 beta 倍，beta 等于 1 时就退化为标准一阶更新，大于 1 则允许模型考虑更长的步。帕德模型如果出现极点或系数病态，就回退到二次泰勒步，避免有理外推在奇点附近爆炸。相比 GeN 那种固定的广义牛顿步规则，ZFO 把固定预算下的方向步长选择抽象成一个局部建模问题，GeN 只是其中某个二次特例；ZFO 的四个实例共享同一次反向传播和同两次前向探测，却能从同样的信息里恢复出二阶和三阶方向信息，支持更丰富的模型族。理论上，作者证明了在共享样本和公共随机数下，有限差分曲率估计会以高概率集中到总体曲率附近；在固定 batch 和方向后，最大化局部模型得到的步长在搜索区间内接近最优；进一步还给出了全局收敛保证，说明 ZFO 会收敛到一个稳定点邻域，邻域大小由累积的步长选择误差控制。

实验上，论文在受控低维问题和多个 LLM 微调任务、多种语言模型与数据集上评估了 ZFO，并与固定步长的一阶基线以及零阶基线比较。结果显示，ZFO 在多数基准上能匹配或超过这些基线，而且对初始学习率的选择明显更鲁棒——这意味着它减少了对精细调参的依赖。提升幅度和具体偏好哪种局部模型取决于目标任务，说明没有单一模型在所有情况下占优。局限也很清楚：ZFO 仍然依赖一个可信的一阶方向，如果基础优化器给出的方向本身很差，沿该方向的步长搜索再精细也救不回来；两次额外前向评估虽然比完整线搜索便宜，但在超大模型上仍有不可忽略的开销；理论保证主要针对固定方向下的局部分析和收敛到邻域，而不是全局最优；帕德模型虽然加了回退保护，但在极端非凸或噪声很大的目标上，局部模型与实际目标之间的偏差仍可能影响步长质量。尽管如此，这篇工作的意义在于它指出了一个被忽视的折中点：不必在“完全信任一阶梯度加固定学习率”和“用零阶方法替代梯度”之间二选一，而是可以让一阶方法负责它擅长的方向选择，让零阶评估负责它擅长的一维曲率探测。这种解耦思路为 LLM 微调中的自适应步长提供了一个轻量、可分析、可扩展的框架，也可能影响未来优化器设计中方向与步长如何分工的思考方式。

### [Decoding Looped Transformers Better for (Almost) Free](https://arxiv.org/abs/2610.02185)
`评分3 · 32 pages, 19 figures`

循环Transformer的核心卖点是用固定参数反复执行同一个块来换取“深度换参数”的效率，推理时每个循环迭代都会产出一个可以解码出下一个token的中间隐状态，但标准解码只取最后一次迭代的输出，把前面所有中间状态全扔了。这篇论文要解决的就是这个浪费：既然循环结构天然提供了同一前缀在不同计算量下的多个预测，那能不能把这些“弱预测”利用起来提升最终解码质量？之前做对比解码的方法要么需要额外训一个小模型当弱参考，要么得人为扰动上下文或截取中间层，成本和复杂度都不低；而循环Transformer的中间状态天然与最终状态共享同一套参数、同一个表示空间、同一个输出头，不需要任何辅助模型或额外训练就能构造出对齐的弱-强预测对，这正是之前方法没有利用起来的结构性红利。

LoopCD的核心思路非常直接：把第一次循环迭代的隐状态当作弱参考，把最后一次迭代的隐状态当作强预测，然后沿着“从弱到强”的方向做外推，让最终token选择更偏向强预测所代表的方向。具体有两种落地方式。LoopCD-Logits是在logit空间做对比：分别把第一次和最后一次的隐状态过coda层和语言模型头得到两组logits，然后用强logits减去弱logits乘以一个引导系数ω，多出来的计算量仅仅是多跑一次输出投影。LoopCD-Hidden则更省，直接在隐状态空间把弱参考和强状态做线性组合，再让组合后的状态过一次coda和输出头，这样输出通路的计算量完全不变，零额外开销。引导强度ω可以设成固定值，也可以用一种基于预测不确定性的自适应策略：看最终预测中最高和次高两个token概率的差距，差距越小说明模型越犹豫，就加大引导力度，差距大就减小引导，这个规则不需要算全词表的熵，非常轻量。值得注意的是，自适应策略只用在LoopCD-Logits上，因为LoopCD-Hidden要用自适应的话得额外跑一次输出通路来获取不确定性，那就破坏了零开销的设计。

实验覆盖了Ouro、Huginn、Parcae和Looped-Qwen3四个循环Transformer家族，任务横跨数学推理、代码生成和多项选择。在完整循环深度下，LoopCD-Logits把Ouro-2.6B-Thinking在AIME 2024上的pass@1从61.88%拉到73.33%，LoopCD-Hidden则把Huginn在HumanEval上的pass@1从22.56%提到31.71%，多项选择七个基准的平均分也是全面上涨。更有意思的是，这些增益大到可以把循环迭代次数砍半——在只跑一半迭代的情况下，LoopCD引导后的模型仍然能追平甚至超过全深度无引导的基线，前向FLOPs省了22.5%到48.2%。论文还深入分析了为什么有效：循环轨迹的早期迭代和最终预测之间的分歧越大，引导带来的增益就越高，而第一次迭代作为参考效果最好，因为后期迭代已经收敛到和最终状态几乎一样，没什么可对比的了。局限方面，LoopCD-Hidden在Huginn上因为初始隐状态来自高斯噪声，需要跳过前几步“燃烧期”才能当参考，说明隐藏空间对比对表示质量更敏感；另外自适应强度目前只在logit空间可用，隐藏空间的自适应方案还没解决。总体来看，这篇工作把循环Transformer的中间计算从“被丢弃的副产物”变成了“免费的引导信号”，在不增加参数、不重新训练的前提下同时提升了精度和推理效率，对循环架构的实际部署价值很直接。

### [From Gradients to Capabilities: Understanding Multi-Teacher On-Policy Distillation](https://arxiv.org/abs/2610.02179)
`评分3`

这篇论文研究的是多教师在线策略蒸馏（MOPD）中的一个核心但长期被忽视的问题：当我们把多个用强化学习训练出来的领域专家（数学、代码、指令跟随、科学）蒸馏进同一个学生模型时，教师信号究竟是如何变成学生参数变化的，以及为什么强教师并不必然带来学生能力的全面整合。作者以 Qwen3-1.7B 为主实验对象，四个教师都是从学生同一初始化出发用 RL 训练得到的，另外还用 SmolLM3-3B 做诊断性验证。之前的方法主要卡在几个模糊地带：损失平均规则（全局 token 平均、领域 token 平均、领域响应平均）到底如何隐式地给不同领域和不同长度的响应分配权重，这一点没有被拆解清楚；采样 token 的策略梯度损失和 top-k 词表截断的 KL 损失之间，到底哪种监督更接近全词表梯度、又是否真的能转化为任务分数，已有工作报告的结论甚至互相矛盾；此外，参数层面的分析往往只看到 BF16 权重变化稀疏，却忽略了 FP32 主权重其实发生了广泛变化，也没区分优化器历史（尤其是 Adam 一阶动量）和当前梯度各自贡献了多少。作者的核心动机就是把这些环节拆开，从梯度、优化器更新到任务学习曲线逐层追踪，回答“监督选择如何影响参数更新和最终能力”这个问题。

方法上的关键洞察可以分成三条线。第一条线是损失平均的隐式加权机制。作者指出，全局 token 平均会让长响应领域（比如数学，响应长度约是指令跟随的三倍）获得更大的损失权重，而领域 token 平均虽然固定了领域权重，却仍然在领域内部按长度加权响应；只有领域响应平均才真正做到领域内响应等权。他们用一个协方差恒等式说明，领域 token 平均的领域内梯度等于响应等权平均梯度加上一个协方差项，这个协方差项衡量的是长响应是否系统性地具有不同方向的梯度，因此 Open-MOPD 那种 token 份额校正只是恢复了领域 token 平均，并没有消除领域内的长度加权。第二条线是优化器和数值精度对教师信号的掩盖。作者发现，即使不同教师当前的原始梯度几乎正交，经过 Adam 一阶动量混合后，参数更新方向的余弦相似度仍然高达 0.83；而不同平均规则之间的更新方向余弦更是达到 0.96。更关键的是，BF16 舍入把 FP32 主权重中约 97% 的变化隐藏掉了，只有 7% 到 11% 的 BF16 权重看起来发生了变化，这让人误以为参数变化很稀疏。他们还发现，即使当前梯度为零，Adam 的动量也能让约 0.14% 的 BF16 权重发生变化，说明观察到的参数变化很大程度上反映的是优化器历史和舍入，而不是当前教师监督的直接影响。第三条线是词表截断与梯度保真度的关系。作者提出了一种 top-64 交集 KL 损失，只取学生和教师各自 top-64 词表的交集，并在交集内重新归一化概率。在 Qwen 上，这个交集平均保留了超过 99.9% 的学生总概率，其梯度方向与全词表 KL 梯度高度接近，余弦相似度超过 0.999。但有趣的是，这种更精确的梯度近似并没有稳定地带来更好的任务表现：在响应平均下，top-64 交集 KL 让数学准确率比采样 token 策略梯度高 2.6 个百分点，但在全局 token 平均下反而低 2.1 个百分点。这说明梯度保真度本身不是任务增益的充分预测器，响应加权规则会改变哪些任务从更宽的词表监督中受益。

结果层面，作者在四个任务上做了完整的训练对比。在 PG 损失下，无动量的 SGD 在三种平均规则下都取得了比 Adam 更高的四任务平均分（领域响应平均：39.94 对 38.91；领域 token 平均：39.46 对 38.63；全局 token 平均：39.26 对 38.79），这暗示 Adam 的动量可能保留了早期响应偏好的方向，延迟了对当前教师信号的适应。不同平均规则之间的四任务平均分差异其实很小，在 Adam 加 PG 损失下只有 0.28 个百分点，在 top-64 交集 KL 下只有 0.06 个百分点，但具体任务的分数变化可以很大，比如全局 token 平均相对领域响应平均让数学高 3.0 个百分点、科学低 2.1 个百分点。词表监督方面，top-64 交集 KL 与 PG 在 BF16 权重变化比例上几乎相同，说明监督广度本身不决定参数变化比例。论文也坦诚了局限：实验只覆盖有限模型家族和规模，结论在更大规模上可能不同；top-64 交集在 SmolLM3-3B 上虽然平均保留 97% 以上的学生概率，但仍有 8.42% 的加权前缀保留不足 90%，梯度相对误差在训练后可达 2.16% 到 24.54%。未来方向包括探索更小的 Adam 一阶动量系数是否有助于适应教师信号，以及梯度裁剪和 Adam 二阶动量在 MOPD 中的具体作用。总体而言，这篇工作把“多教师蒸馏如何变成能力”这个问题从黑箱推到了可测量的梯度、更新和任务曲线层面，提醒研究者在选择响应加权、词表监督和优化器设置时必须联合考虑目标任务和训练预算，而不是孤立地追求更精确的梯度近似或更均衡的领域权重。

### [VISTA: A Visual Harness for Reasoning in an Interactive World](https://arxiv.org/abs/2610.02200)
`评分3 · Tech report. An early version of this manuscript was in a bl`

这篇论文要解决的核心问题是：现有的多模态模型在交互式视觉环境中进行长时程推理时，能力被严重束缚住了。以 ARC-AGI-3 这个交互式视觉游戏基准为例，它要求智能体在完全陌生的世界里通过不断试错来发现规则和目标，而此前的主流做法是把环境状态转成文本或结构化表示，再让语言模型去推理，甚至进一步用程序合成的方式构建可执行的世界模型。这种路线的问题在于，它把丰富的视觉信息强行压扁成符号，一旦环境变得视觉复杂，用显式程序去刻画状态、转移动态和目标条件就会越来越吃力。另一条路线是直接用视觉语言模型，但现有 VLM 通常把每张图一次性编码成视觉表示，这些表示未必保留后续推理真正需要的细节，而且随着上下文增长，早期观察会被丢弃或被文本摘要替代，模型自己也无法控制哪些信息被保留。更根本的困难是：在编码那一刻，模型并不知道未来哪条视觉线索会变得关键，因此一次性编码天然是「有损」且「时机错配」的。

VISTA 的关键洞察是：与其让模型在编码阶段就决定什么信息重要，不如把原始观察完整保存下来，让模型在推理过程中按需主动回看。它由三个组件构成。第一是视觉观察，模型直接接收环境渲染出的图像，保留物体的外观和空间关系，从而能利用预训练的视觉先验。第二是无损视觉记忆，环境返回的每一帧，包括动作之间的中间动画帧，都以原始形式按回合和帧号索引存储，不依赖模型当前上下文里还剩什么。第三是视觉检视，模型可以主动调用工具在空间和时间两个维度上检索：空间上可以请求任意矩形区域的放大视图，看清全图里难以分辨的细节；时间上可以调取任意早期回合的多帧，比较状态、回放某个动作如何通过中间帧展开。此外还有 read_pixels 工具读取选定区域的精确像素值。这套机制本质上给了模型一个显式的注意力机制，让它自己决定看哪些帧、看哪些区域。整个 harness 是纯机械的，不含任何训练模型，只负责执行工具调用、返回图像或像素值、报错。每个回合内模型可以多次与 harness 交互，用自由语言推理、预测动作结果、更新两个笔记文件（GUIDE.md 记录跨关卡的游戏理解，WORKING.md 作为当前状态的草稿纸），最后调用 play 执行动作。上下文接近上限时，模型写一份交接摘要并在新上下文中继续，而笔记、视觉记忆和动作历史都保留。消融实验很能说明问题：从官方文本网格基线 13.33 分起步，换成渲染图像升到 47.32，放宽动作和时间限制到 51.66，加入持续对话和原生压缩到 65.82，加入两个笔记文件到 70.05，而加入无损视觉记忆和模型自主检视直接跳到 94.10，最后加上精确像素读取达到 99.00。这说明真正带来质变的是「可回看的无损记忆 + 主动检视」，而不是单纯的视觉输入或提示工程。

在结果上，VISTA 搭配 Claude Opus 5.0 在 ARC-AGI-3 全部 25 个公开游戏上取得 RHAE 满分 100.00，总共用 7302 个动作，比首次游玩的人类基线 17135 个动作少 57.4%；搭配 GPT-5.6 Sol 也完成全部 25 个游戏，RHAE 为 99.00。作为对比，同一模型在官方基线实现下只有 40.68 和 13.33。据作者所知，这是首个不依赖程序合成就达到完美或接近完美性能的纯视觉系统。它还能以极小适配迁移到 GameWorld 的 34 个浏览器游戏、AI GameStore 的 10 个游戏和 BabyVision 的 39 个视觉追踪问题，GPT-5.6 Sol 加 VISTA 大幅超过同模型加最小 harness 的基线，并在 GameWorld 上超过新手人类基线、在 AI GameStore 上超过人类中位数。消融还显示，用文本网格替代图像性能相当但动作略多，且 token 消耗从每游戏 3070 万暴涨到 7190 万，因为一个 64×64 网格约需 4000 token，而 512×512 图像只需约 308 个图像 token。上下文从 200K 降到 100K 只损失 0.4 分却省一半 token，说明 harness 在短上下文下依然有效。局限方面，VISTA 仍依赖闭源大模型后端，成本较高，780K 上下文下每游戏消耗 1.057 亿 token；它也没有从根本上解决模型自身视觉推理能力的上限，而是通过外部记忆和检视工具把能力「托」出来。其意义在于指出了一条与程序合成正交的路线：视觉 harness 设计本身就是一个重要的研究方向，通过让模型主动重组视觉输入，可以在不训练新模型的前提下释放多模态模型在复杂交互环境中的长时程推理潜力。

## 强化学习 RL

### [CARM: Cancellation-Aware Response Masking for LLM Reinforcement Learning](https://arxiv.org/abs/2610.02039)
`评分3 · 28 pages, 11 figures, 5 tables`

在大模型强化学习后训练的实际系统中，采样与训练往往并不严格同步：小批量更新会让存储的回复逐渐变旧，actor 与 learner 之间的延迟会推迟样本使用，而高吞吐的 rollout 引擎与训练后端在批处理、数值精度和底层算子实现上也存在差异。这些因素共同导致生成回复的 rollout 策略与正在被优化的当前策略之间产生概率失配，也就是所谓的 off-policy 问题。PPO 和 GRPO 通过 token 级裁剪来约束更新幅度，但裁剪只改变单个 token 对损失的贡献方式，并不能保证每个当前策略与 rollout 策略的概率比都落在指定区间内，也无法决定整条回复是否应该参与更新。序列级掩码正是为后一个问题设计的：它用一个汇总整条回复失配程度的分数来决定是否保留该回复。此前常用的做法是几何平均掩码，即对 token 概率比取长度归一化的几何平均，在 log 空间里等价于对带符号的 token log-ratio 求平均，DeepSeek-V3.2 的 off-policy 序列掩码就采用了这种带符号聚合。问题在于，正负 log-ratio 会相互抵消：比如两个 token 的比值分别是 10 和 0.1，几何平均仍然是 1，看起来完美对齐，但实际上每个 token 的概率都变化了十倍。这种抵消会让大量双向漂移被掩盖，使得掩码误保留那些表面一致、实则严重失配的回复。

CARM 的核心洞察非常直接：既然带符号平均会抵消，那就先取绝对值再平均。具体来说，它对每个 token 的 log-ratio 取绝对值，然后在整个回复上求平均，得到平均 log-ratio 幅度，并据此设定阈值来决定是否保留该回复。这个改动看似简单，却改变了度量的性质：GeoMean 衡量的是平均带符号 log-ratio 的大小，而 CARM 衡量的是 log-ratio 幅度的平均，前者是净位移，后者是双向漂移的总量。CARM 还给出了阈值一个直接的 token 级解释：论文证明，任何被 CARM 接受的回复都满足一个联合界，同时约束了落在指定比例带之外的 token 比例以及这些越界 token 超出边界的平均 log 距离。换句话说，阈值不再只是一个抽象的过滤参数，而是对应着“允许多大比例的 token 越界、以及越界多严重”的预算。这个界对非对称区间也成立，而 PPO/GRPO 常用的裁剪区间 0.8 到 1.28 正好可以作为一个参考带：在阈值 1.02 下，任何被接受的序列中越界 token 比例不超过 8.88%，阈值 1.04 下不超过 17.58%。此外，论文还证明了 CARM 的接受集是 GeoMean 接受集的子集：在相同阈值下，CARM 至少会拒绝同样多的回复，因为它对每个回复的分数都不小于 GeoMean。在真实 rollout 的 1024 条回复上，CARM 与 GeoMean 的过滤决策确实出现了明显分歧，其中 195 条被 GeoMean 接受但被 CARM 拒绝，而一条典型被误保留的回复中，平均绝对 log-ratio 是带符号平均绝对值的 9.79 倍，且最大单 token 贡献只占绝对 log-ratio 总量的 0.43%，说明这种差异并非由某个极端 token 驱动，而是普遍存在的双向漂移。

在数学推理和代码生成任务上，CARM 都取得了稳定的提升。数学方面，在 Qwen3.5-4B 和 Qwen3.5-9B 上使用 DAPO Math 训练，并在 AIME 2024/2025/2026 和 BeyondAIME 上以 16 条回复评估，CARM 在四个数据集上的平均 mean@16 最高比 GeoMean 提升 3.13 个百分点；三年 AIME 平均从 69.17% 提升到 70.42%（4B），从 74.03% 提升到 77.50%（9B），后者在三个年份上分别都更好。BeyondAIME 上，4B 从 38.88% 提升到 42.56%，9B 从 47.06% 提升到 49.19%。代码方面，在 TACO 训练集上训练 Qwen3.5-9B，并在 TACO 测试集、LiveCodeBench-v6、HumanEval+ 和 MBPP+ 上评估，CARM 的平均 pass@1 比最强基线提升 2.88 个百分点。论文也客观指出了一些局限：CARM 给出的是对采样 token 比值的确定性界，而不是对完整条件策略 KL 散度的界；阈值分析显示过滤率相近时准确率可以不同，且过滤更多回复并不总是更好，说明掩码的选择行为并非单调。此外，CARM 目前只处理序列级保留与否，不改变 token 级代理损失本身，也不涉及优势条件的区分。尽管如此，这项工作的意义在于它把序列级掩码从“净位移”视角转向“双向漂移”视角，并给出了可证明的 token 级解释，为 LLM 强化学习中的 off-policy 控制提供了一个理论扎实且易于实现的新选项。

### [FERPO: Forward Entropy-Regularized Policy Optimization](https://arxiv.org/abs/2610.02198)
`评分3 · Code: https://github.com/Atarilab/FERPO · 有代码`

在连续控制的大规模并行在线强化学习里，REPPO 这类当前最优方法依赖一个学到的软动作价值评论家，并通过对评论家关于动作求导来做策略改进，也就是所谓的 pathwise 梯度更新。问题在于，评论家的训练目标始终是拟合回报数值，而策略更新真正需要的却是动作维度上的导数精度，这两件事并不等价：价值预测得准，不代表它对动作的梯度方向也准。已有工作已经观察到，学到的动作梯度与基于 rollout 的估计在方向上一致性很差，评论家梯度误差会系统性地偏置策略改进；而在 on-policy 设定下，这种有偏梯度还会和不断变化的数据分布相互作用，把训练推向不稳定。换句话说，之前方法的瓶颈不是“评论家不够准”，而是“用错了评论家的信息”——把一个只被监督过数值的函数拿来当导数用，天然缺乏保障。

FERPO 的关键洞察是：与其对评论家求导，不如只用评论家的数值来构造一个显式的目标动作分布，再让策略去拟合它。具体来说，作者从带熵正则和 KL 信任域约束的策略改进目标出发，在不受参数化策略族限制的条件下，对每个状态解析地求出最优目标密度，它是一个 Boltzmann 形式与 rollout 策略的几何混合：既偏向高价值动作，又通过 KL 项被拉回 rollout 策略附近，其中信任域乘子 λ 越大更新越保守。得到这个显式目标后，FERPO 不再做传统的 reverse-KL 投影，而是改用 forward-KL 去拟合它，因为 forward-KL 倾向于覆盖目标分布的多个高价值模态，而不是塌缩到其中某一个，这天然有利于探索。由于目标密度里含有难以直接采样的归一化项，作者用自归一化重要性采样来估计这个 forward-KL 损失：从冻结的 rollout 策略里抽 K 个候选动作，用评论家数值和 rollout 对数概率算出重要性权重，并在更新 actor 时把这些权重视为常数，只对策略对数密度求导，从而完全绕开了对评论家的动作求导。另一个精巧之处是乘子的自适应机制：温度 τ 沿用 SAC 式的自动熵调节，而信任域乘子 λ 不是直接控 KL，而是控重要性权重的归一化有效样本量，当权重过度集中、ESS 低于目标时就增大 λ 把权重压平。作者还给出了一个命题，说明在种群层面 ESS 下界可以推出目标分布与 rollout 策略之间 KL 的上界，从而把权重集中度的控制与信任域控制联系起来，这也解释了为什么这套机制能让重要性采样保持数值稳定。

实验在 MuJoCo Playground 和 ManiSkill 两个连续控制基准上展开，FERPO 相比 REPPO 等基线取得了有竞争力的回报，并在样本效率上有明显提升，计算基准还显示其 actor 更新速度比 REPPO 更快，消融实验则分别验证了 forward-KL、ESS 调节和缓存 actor 更新等组件的贡献，作者还给出了一个基于一步模拟的状态价值扩展，在 AcrobotSwingupSparse 上结果可观。需要客观看待的是，FERPO 并没有摆脱对评论家数值准确性的依赖，它只是不再要求动作导数准确；同时它依赖从 rollout 策略采样的候选动作对目标分布有足够覆盖，当目标分布模态远离 rollout 策略时，重要性权重的方差仍可能成为隐患，而 ESS 调节本质上是一种软约束，并不能提供 worst-case 的信任域保证。尽管如此，这篇工作的意义在于指出了一条被忽视的设计空间：策略改进未必需要可微的评论家，把评论家当作“打分器”而非“梯度源”，再用显式目标和 forward-KL 拟合来完成更新，这可能为大规模并行 on-policy 学习提供一条更稳健、也更容易扩展的路线。

### [Generative modeling of intrinsically disordered protein regions by reinforcing sparse autoencoder features](https://arxiv.org/abs/2610.02189)

内在无序区域（IDR）在转录调控、信号转导和亚细胞定位等细胞过程中扮演核心角色，但它们的理性设计一直很困难。基于结构的设计方法依赖明确的折叠结构，对IDR天然不适用；而现有的蛋白质语言模型（PLM）虽然能生成新序列，却是在全长蛋白质序列上训练的，其生成先验严重偏向折叠结构域——这意味着模型学到的统计规律主要来自有序区域，对IDR特有的序列特征（如低复杂度、电荷分隔、重复模体）建模不足。另一方面，即使有了IDR专用的生成模型，如何精确控制生成序列中功能相关的序列模式仍是难题。现有的强化学习方法虽然可以用计算oracle或实验数据微调PLM，但它们并不显式地识别或控制序列层面的功能模式；而稀疏自编码器（SAE）虽然能把PLM的内部表示分解为与可解释序列模式对应的特征，但如何让生成序列同时激活多个指定特征，此前没有可靠方案。激活引导（activation steering）尝试沿特征方向加偏置，但多个方向叠加时并不能保证所有目标特征都被激活。这篇论文正是针对这两个缺口：一是缺乏IDR专用的生成先验，二是缺乏对可解释功能特征组合的显式控制手段。

论文的核心贡献分为两部分。第一，作者构建了IDiom-DB数据集，从AlphaFold数据库中基于低pLDDT值（阈值70，窗口化判定）提取了5400万条预测的IDR序列，经过90%序列相似性聚类、过滤短于30残基或位于超长蛋白中的片段等步骤，保留了IDR及其在宿主蛋白中的位置信息。在此基础上训练了IDiom——一个仅解码器的自回归Transformer，提供19M、85M和302M三种规模，使用1024 token上下文，每个氨基酸残基一个token。训练时采用fill-in-the-middle目标，将IDR的N端和C端侧翼上下文置于IDR前后，50%的序列带上下文、50%不带，从而使模型既能无提示生成IDR，也能在给定侧翼序列的条件下生成。第二，作者提出了RL-SAE（带稀疏自编码器特征的强化学习）。具体做法是：先在IDiom第18层（共24层）的残差流激活上训练一个Top-k SAE（k=32，16384个潜在特征），且只用IDR残基位置的激活，使学到的字典专注于无序区域的序列特征。然后，对于每个功能标注的序列集（如核仁定位、转录激活域等），计算每个SAE特征在正例集与负例集中的对数几率比（LOR），取排名前N的特征作为目标集。RL-SAE的奖励函数直接定义为生成序列中激活的目标特征比例，同时对序列长度和氨基酸组成熵施加二次惩罚，以匹配目标长度和自然IDR的平均熵。优化使用组相对策略优化（GRPO），并以KL正则约束相对基础模型的偏离。关键洞察在于：SAE特征提供了可解释的、与功能相关的序列模式作为显式设计目标，而强化学习直接优化“激活了多少目标特征”这一稀疏匹配奖励，避免了激活引导中多方向叠加导致的特征覆盖不全问题。与监督微调相比，RL-SAE不需要正例序列作为训练目标，而是通过奖励信号灵活组合多个特征。

在实验上，作者选取了八种IDR设计任务：六种亚细胞区室关联（核仁、染色体、核斑、应激颗粒、P小体、核孔复合物）和两种转录调控功能（激活域和抑制域）。评估指标包括ProtGPS（区室关联）、DeepLoc 2.1（亚细胞定位）、PADDLE（转录激活）以及已知的共抑制因子招募模体。结果显示，RL-SAE生成的序列平均激活了30个目标特征中的90%，而激活引导仅激活24%。在预测的亚细胞定位和转录活性上，RL-SAE也优于激活引导和监督微调，并且能够将不同生物功能相关的特征组合到同一序列中。此外，作者发现许多富集特征对应着经典的IDR序列语法，如核孔序列中的FG/GLFG重复、核斑中的RS重复、激活域中的酸性暴露模式以及抑制域中的SUMO化模体，说明SAE特征确实捕捉到了可解释的功能序列模式。局限方面，论文主要依赖计算预测器（如ProtGPS、PADDLE）而非湿实验验证，生成序列的实际生物学功能仍需实验确认；SAE特征的可解释性虽然强于原始神经元，但仍有部分特征难以对应到明确的序列语法；RL-SAE的计算成本较高，需要为每个任务单独训练策略。尽管如此，这项工作展示了通过可解释特征进行组合式IDR设计的可行性，RL-SAE框架原则上可推广到其他蛋白质设计场景，只要存在可解释的特征作为设计目标。

### [pCoMole: Pareto-Constrained Molecule Editing with Discrete Flows](https://arxiv.org/abs/2610.01663)
`评分4 · Published at NeurIPS 2026. (Proceedings of the 40th Conferen`

生物分子治疗药物的开发很少从零开始，通常是在已知序列基础上做靶向编辑，在满足硬性生化与可制造性约束的同时改善多个性能指标。这里存在一个真实且棘手的问题：现有生成方法无法在离散、变长的生物序列空间里同时做到多目标优化、硬可行性保证和序列编辑这三件事。比如 RayGun 通过把变长蛋白序列编码到固定维度嵌入空间再以更短长度解码来实现模板引导的缩小，能做大片段插入缺失并大致保持结构，但它不是为通用多目标编辑设计的；SCISOR 把缩小建模为离散扩散过程，通过反转一个只做插入的加噪过程来学习删除规划，在删除效应预测和基序保持上达到最优，但它同样不联合优化多个可开发性或功能目标，也不提供偏好驱动的权衡控制。更广泛的约束多目标分子优化方法（进化搜索、强化学习）可以逼近帕累托前沿，但通常依赖反复的在线 oracle 评估，不适合在大规模变长离散空间中对已有分子做离线编辑。离散扩散和离散流匹配虽已成为强大的序列生成器，其引导机制也能控制目标和约束，但多数可控离散生成器聚焦从头生成，且只单独处理约束满足或偏好控制，不支持带插入删除的迭代序列编辑。Edit Flows 虽然把离散流匹配扩展到通过局部插入、删除、替换来做随机序列编辑，但尚未被发展为面向生物分子设计的约束感知多目标编辑框架。pCoMole 正是为填补这一空白而提出的。

pCoMole 的核心思路是在一个预训练好的 Edit Flow 之上施加偏好引导，同时强制终端可行性。它首先定义一个可行性门控的终端分布：用增广 Tchebycheff 效用对候选序列排序，该效用对帕累托支配关系严格单调，因此会鼓励跨多个目标同时改进，而不是塌缩到单一指标；再通过一个逆温度参数把可行性编码进去，对不可行终端赋予零偏好质量，从而得到偏好倾斜的目标终端分布。关键洞察在于，这个倾斜分布可以通过底层编辑过程的 Doob-h 变换来精确实现——定义一个调和函数，即在当前状态和时刻下对终端偏好值的条件期望，然后用它去重加权基础 Edit Flow 的转移速率。这样做的好处是保留了基础过程局部的编辑结构（插入、删除、替换），同时把采样导向高偏好且可行的终端。理论上可以证明，当调和函数可精确计算时，引导后的连续时间马尔可夫链的终端分布恰好等于那个偏好倾斜分布，且改变权重向量就能探索不同的帕累托权衡。实际中调和函数在大编辑空间里无法精确求解，pCoMole 用短蒙特卡洛 rollout 来近似：从当前状态出发，用基础速率模拟若干条到时间终点的续写轨迹，用这些轨迹的终端偏好值平均来估计调和函数。为了控制计算量，它采用两阶段近似——先按基础速率采样若干候选下一状态，再对每个候选跑少量 rollout 估计其续写价值，然后按“局部提议概率乘以估计调和值”的规则在候选间做归一化选择。此外还维护一个当前最优可行终端作为兜底，并用廉价筛选先剪掉即时标量化得分不升的候选，只把 rollout 预算分配给有下游改进证据的候选。这套机制之所以比之前的方法更好，是因为它把多目标偏好、硬可行性、变长离散编辑统一在一个有理论保证的引导框架里，而不是像进化或强化学习那样依赖在线 oracle，也不是像已有离散生成器那样只做从头生成或只处理单一约束。

实验在三个缩小基准上验证了 pCoMole：GFP 缩小（设计更短荧光蛋白但不牺牲荧光相关目标）、Cas9 缩小（缩短蛋白长度同时保持 PAM 特异性）、以及肽模拟物结合剂压缩（把长肽结合剂压成短肽模拟物并优化七个药物相关性质且满足硬约束）。对比对象包括 RayGun 和 SCISOR 等最先进的缩小与编辑方法，pCoMole 在可行性和权衡控制上都有提升。湿实验方面，两个由 pCoMole 设计的 229 残基 eGFP 变体在 BL21 细胞中经 488 纳米荧光成像仍保留清晰的绿色荧光，它们分别做了 10 个删除外加一到两个替换。这些结果说明，在离散变长生物序列空间里做约束感知、帕累托对齐的编辑是可行的，并且设计出的缩短蛋白能保留功能。局限也很明显：方法依赖预训练 Edit Flow 的质量和覆盖范围，短 rollout 近似在预算有限时可能错过可行终端，调和函数估计的方差会随序列长度和编辑空间增大而上升，而且目前只在缩小任务上做了系统验证，对需要增长或更复杂编辑模式的任务是否同样有效还不清楚。尽管如此，pCoMole 把 Doob-h 引导、增广 Tchebycheff 效用和离散流匹配编辑结合起来，为离线、约束感知的多目标生物分子序列编辑提供了一个有理论支撑且实验可验证的新范式，对该方向后续研究很可能产生推动作用。

### [Fold'EM: Direct atomic structure inference from Cryo-EM particles](https://arxiv.org/abs/2610.01358)
`评分4`

单颗粒冷冻电镜（cryo-EM）已经成为解析生物大分子结构的主流手段，但它的传统计算流程存在一个根本性的瓶颈：必须先对成千上万张信噪比极低的粒子图像进行对齐和平均，重建出三维静电势密度图，然后再把原子模型拟合进这张密度图里。问题在于，密度重建的样本复杂度极高，需要大量粒子才能达到足以支撑模型搭建的分辨率，这直接导致结构解析成本高、通量低。更棘手的是结构异质性的样本：把不同构象的粒子混在一起平均会模糊结构特征，而把它们拆分成更均一的子集又会让每个状态可用的粒子数进一步减少，低丰度或瞬态构象往往因此被淹没、被丢弃，或者根本无法独立重建。与此同时，AlphaFold 这类蛋白质结构预测模型已经从序列和进化数据中学习到了极强的结构先验，近期也有工作用实验数据去引导这些生成模型，但它们在 cryo-EM 场景下几乎都作用在已经重建好的密度图上，也就是在粒子挑选、对齐、平均完成之后才引入先验，因此仍然摆脱不了对大量粒子的依赖。这篇论文要问的就是：能不能把结构先验直接下沉到粒子层面，绕开高分辨率中间重建，直接从稀疏的粒子图像推断原子结构？

Fold'EM 的核心做法是把结构确定重新表述为一个联合推断问题：既要推断一组原子结构（用 AlphaFold3 的 Pairformer 中间隐状态来参数化），又要推断每张粒子图像对应的姿态和构象类别分配，目标函数是粒子级似然与序列条件结构先验的联合最大化。关键的技术洞察在于它优化的是 Pairformer 中间层的表示，而不是像已有方法那样去优化终端嵌入或者直接在坐标空间里引导扩散轨迹。由于 Pairformer 的每个 block 都保持张量形状不变，中间状态和终端状态处在同一个表示空间里，把实验梯度回传到中间层、再让剩余的 Pairformer block 把它变换到终端条件空间，等价于在终端空间里做了一次由 Jacobian 乘积所定义的预条件优化——也就是说，扰动被限制在预训练模型自己学到的、与序列和当前状态相关的几何方向上，对结构生成器敏感的方向被放大，不敏感的方向被抑制。作者进一步证明，在中间层放一个各向同性的高斯锚点，经过最后几个 block 的线性化后，会变成终端表示上一个序列依赖的各向异性松弛，这比把终端表示当作自由变量、施加各向同性先验要合理得多，也正是这种重参数化让实验引导的强度大幅提升。另一个统计层面的动机是：当姿态和构象分配不确定时，粒子根本无法被压缩成单一的充分密度统计量，把粒子塌缩成共识密度会丢掉推断这些隐变量所需的信息；而且即便姿态已知，粒子级拟合也只在与成像算子和噪声协方差所定义的实验特定度量下才等价于密度拟合，标准的密度空间 L2 目标一般并不能复现粒子似然。针对未知姿态的情形，作者提出 ab initio Fold'EM，在结构推断与姿态/类别推断之间交替优化，并引入受 RECOVAR 启发的残差子空间估计器 B-RECOVAR 来提供更稳健的粒子分配和置信度，用于在异质数据中优先采信可靠分配。

在实验结果上，已知姿态的设定下，Fold'EM 在实验和合成数据集上都能用不到传统密度重建所需粒子数的百分之一恢复出准确原子结构，在 EMPIAR 的均一实验数据上甚至只需约千分之一的粒子就能达到可比的傅里叶壳层相关和原子 RMSD；未知姿态的 ab initio 设定下，它用约百分之三的粒子达到与 deposited 重建相当的结构精度，在异质数据中用约百分之五的粒子就能分辨出不同的构象状态，而且不需要为每个状态单独重建密度图再搭模型。在连续异质体系中，作者还发现粒子空间里构象状态的组织方式会反映在 AlphaFold 的嵌入空间里，意味着实验观测到的构象结构被保留在了学习到的表示中，因此可以用少量优化过的锚点状态来表示一条连续轨迹。局限方面，论文目前假设除姿态和类别外的成像参数（如 CTF）已知，连续异质性也只在嵌入空间做了初步验证，B-RECOVAR 这类组件在极低信噪比或极端稀疏条件下的稳健性还有待更系统的检验。但总体而言，这项工作把结构先验的引入时机从"重建之后"提前到了"粒子层面"，为低样本条件下的结构解析和直接从粒子图像表征低丰度构象态开辟了一条新路径，也提示了一个更一般的思路：与其让实验数据去适配一个通用的密度重建流程，不如让强大的生成式结构先验在推断阶段就与原始测量耦合起来。

### [Higher-Order Molecular Grammars for Generative and Foundation Models in Chemistry](https://arxiv.org/abs/2610.02186)

分子表示一直是计算化学与药物设计的核心问题，因为它直接决定了模型能否高效、精确地导航巨大的化学空间。然而，现有主流的序列表示（如SMILES、SELFIES）和图表示（如基于消息传递的GNN）都存在一个根本性缺陷：它们无法显式编码高阶拓扑结构，也就是涉及两个以上原子或子结构的多体关系。环系、官能团、药效团这类化学上极为重要的单元本质上都是高阶的——环系统约束分子形状和取代基取向，官能团通过极性、氢键和酸性决定相互作用位点，它们共同把原子级连接性桥接到介观尺度的化学组织，进而决定反应性、代谢稳定性和与靶点的结合行为。但SMILES把高阶结构隐含在括号和数字的语法里，容易生成非法分子；分子图虽然直接编码原子和键，却受限于Weisfeiler-Lehman检验的表达上界，深层网络还面临过平滑和过挤压问题，更重要的是它把环和官能团这些高阶单元拆解成了成对边，丢失了多体关系的整体性。已有的高阶表示方法（如超图、单纯复形、胞腔复形）虽然能显式建模多体关系，但通常依赖关联矩阵编码，生成时必须保证不同拓扑维度之间的关联关系互相一致——比如边-面关联矩阵中生成了一个面，但节点-边关联矩阵中缺少其边界边，结构就非法了。这种一致性约束使得在高阶结构上做生成极其困难，因为可能的关联关系空间随分子尺寸组合爆炸。碎片类方法（如JT-VAE、HierVAE、各种图语法）试图用片段作为高阶单元来缓解问题，但它们要么把片段间关系隐含在字符串语法中，要么面临规则表达力与复用性之间的两难：上下文特定的片段导致稀疏长尾的规则词表，通用片段又削弱了化学上有意义的模体语义。归结起来，序列和图编码把高阶拓扑留作隐含，碎片方法不显式编码层级结构，关联矩阵编码又让可扩展生成变得困难——这就是这篇论文要解决的的核心权衡。

HGR的核心洞察是：与其在高阶关联矩阵上直接生成，不如把高阶拓扑无损地序列化成一串产生式规则，从而让标准序列模型（如Transformer）可以直接处理。具体做法分两步。第一步是“提升”：从分子图出发，用一个从数据中挖掘的模体词表，把频繁出现的子图收缩成组合复形中的胞腔。组合复形是一个统一了图、超图、单纯复形和胞腔复形的形式化框架，其中的胞腔按层级排列，叶节点对应原子级微结构，内部节点对应介观尺度的高阶模体。为了保证可逆性，每个产生式规则不仅记录被提升的模体，还记录一个有序锚接口——即该模体所有外部邻居和边界键的固定排序。这个接口在解码时固定了边界对应关系，使得原始组合复形和分子图可以被精确重建。但模体锚点多了会产生规则爆炸，所以作者设计了两种提升方案：MIG通过最佳优先模体扩展来抑制锚点增殖，RSG则进一步引入环系感知的合并策略，专门稳定环状分子的提升过程，缓解复杂环连接导致的规则膨胀。第二步是“语法归纳与推导”：对提升后的组合复形做自底向上的收缩，每一步把一个胞腔收缩成一个新的非终结符，并记录对应的展开规则。由于子子树总是先于父节点被处理，最终得到的序列天然编码了“原子如何组成模体、模体如何组装成完整分子”的层级推导树。所有分子库中结构相同的收缩被赋予同一个产生式规则，因此归纳过程只收集不同的规则构成共享规则库。解码时反向应用这些规则即可无损重建。这里的关键技术细节是：产生式规则的token用置换不变的结构描述符初始化，使得规则嵌入能反映拓扑相似性，并能泛化到未见过的规则。这样一来，HGR字符串既保留了高阶拓扑的层级和连接信息，又完全兼容成熟的序列架构，避免了在高阶关联矩阵上生成时那种组合爆炸和一致性维护的代价。此外，作者还构建了RingDiv基准（118万分子，含RingDiv300k拓扑平衡子集）和环多样性指数RDI，专门缓解现有生成基准对简单环系的偏好。

在分子生成任务上，基于HGR的模型（HGR-VAE和HGR-LDF）在五个生成基准上全部取得FCD第一名，并且由于语法约束，生成有效性按构造就是100%——这是唯一同时做到100%有效性和领先分布对齐的方法。在表示学习上，HGR-FM在MoleculeNet的七个基准上，在探测和全微调两种迁移协议下都取得了最高平均AUC，分别比最强基线高出8.3和3.3个AUC点。消融实验进一步表明，这些增益来自对层级高阶拓扑的显式编码，而非仅仅来自序列建模本身，说明高阶结构确实构成了有用的归纳偏置。局限方面，HGR依赖从数据中挖掘的模体词表，词表覆盖范围会影响对全新化学空间的泛化能力；提升和解析过程虽然比关联矩阵生成高效，但仍需要预处理步骤，对超大规模分子库的扩展性有待进一步验证；此外，RSG在环系上表现更优，但对非环状的高阶模体（如某些非环连接子组合）是否同样高效，论文没有充分展开。总体而言，这项工作为分子表示提供了一个新的思路：把高阶拓扑从“需要显式矩阵编码的负担”转化为“可以序列化的语法结构”，从而在保持拓扑表达力的同时获得序列模型的全部工程便利。如果这一范式能被更广泛地验证和扩展，它可能会影响未来分子基础模型的设计——不再在序列、图和高阶结构之间做非此即彼的选择，而是通过语法归纳把三者统一到一个可解码的表示框架中。

### [CipherGenome: Homomorphic Inference for Genomic Mixture-of-Experts](https://arxiv.org/abs/2609.35883)

基因组基础模型正快速走向稀疏混合专家（MoE）架构，但随之而来的是一个尖锐的部署矛盾：15.1B 参数的 GenomeOcean-MoE 中，95.8% 的参数和 85.7% 的每 token 线性浮点运算都集中在专家层，持有患者或菌株序列的实验室和医院根本没有足够显存来本地服务这些专家。一个自然的出路是把序列发送到租用的 GPU 服务器或协作推理集群上，但这直接暴露了基因组数据——基因组是永久性的、可识别个人及其亲属的敏感信息。论文首先量化了这种暴露的严重程度：一个只托管单个专家的服务器，在其收到的激活上训练一个小型解码器，就能以 99.8% 的 top-1 准确率还原第 0 层的输入核苷酸；更隐蔽的是，MoE 的路由选择模式本身构成第二条泄露通道，仅凭每个专家的路由计数就能在 16 个分类单元中以 54.9% 的准确率识别源生物体，而随机猜测只有 6.25%。此前的方法在这个场景下都卡住了：CKKS 等非交互式同态方案必须用高次多项式逼近 softmax 和门控非线性，还要反复自举，开销巨大；两方协议虽然用交互替代了逼近，但需要第二个具备服务器级算力的参与方和大量通信；已有的 MoE 专用协议针对的是私有权重而非私有输入，与本文的威胁模型根本不同。

CipherGenome 的核心洞察在于，基因组 MoE 场景允许一个远比通用同态推理更简单且精确的设计，它建立在三个结构性事实之上。第一，专家权重是公开的——模型所有者发布权重，因此只需要隐藏输入，不需要保护权重。第二，一个专家本质上是两个线性映射夹着一个门控非线性，而这两个线性映射承载了模型几乎全部参数。第三，一个公开整数矩阵与一个 LWE 密文的乘积本身就是一个整数矩阵乘积，只要把密文拆成字节，现成的 GPU int8 张量核心就能精确计算它。具体运作方式是这样的：一个瘦客户端运行专家之外的 4% 模型（嵌入、注意力、路由器），把路由到每个专家的 token 在 module-LWE 下加密，所有 slot 共享一个由 32 字节种子经 ChaCha20 扩展出的公开掩码 A，每个 slot 使用独立的新鲜三元秘密 s_j，只把种子和 B 部分发给托管该专家的服务器。服务器用一个精确的整数 GEMM 乘以自己的权重，再把结果切换到较小的模数后返回。客户端解密后，在 float64 中精确计算 SwiGLU 的 SiLU 和门控乘积，折入路由权重，再用全新的秘密重新加密，提交给下投影。这里的关键在于：非线性从未离开客户端，所以完全不需要多项式逼近或自举；每个密文都使用新鲜秘密，所以即使所有服务器合谋汇集各自的视图，安全性依然成立。为了让整数计算不回绕，论文证明了逐 token 缩放的无回绕命题：令 β 为整数权重最大行范数并随模型公布，若 token x_t 以 Δ_t = 2^{Q-2}/(β‖x_t‖₂) 编码，则每一行的乘积绝对值严格小于 2^{Q-1}，W·M 在模 q 下可精确恢复（仅差 LWE 噪声项 W·e）。权重按输出行量化为 int16 并拆成两个平衡 int8 肢，[A|B] 拆成平衡的 base-256 数字，所有肢-数字乘积由一次 torch._int_mm 调用完成，融合的 Triton 尾函数负责移位、求和、模 2^Q 归约和模数切换。在 Q=48 时 int16 权重只需 11 个 int8 GEMM 单元，int8 在 Q=40 时 5 个，int4 在 Q=32 时 4 个，每种配置都与 FP64 参考逐位一致。部署优化同样关键：公开提示利用了 W·A 与输入无关这一事实，客户端一次性取回所有 W·A，在线任务只携带 B 和 W·B，这是 SimplePIR 思想在专家上的应用，秘密仍然每任务新鲜；线路压缩把 token 列按 16 而非完整 256 槽环块发送，A 和 B 切换到不同位宽，上行 B 的低位被舍入掉；逐层填充把每层所有专家填充到该层最大计数，使编排器每层只能看到一个数字，把路由泄露从 54.9% 压到 8.9%；HE 兼容量化支持 int8 和 int4 专家，行缩放解密后应用，AWQ 输入缩放折入客户端明文，服务器仍然只看到纯整数矩阵。

在 12 个完整细菌基因组（跨越四个门）的 72 个 1024 token 窗口上，用三个种子评估，结果相当有说服力。加密相对于精确推理是非劣的：int16 权重、Q=48、Q'=24 时，CipherGenome 到 fp32 模型的 KL 散度为每 token 0.0032 nats，而精确 fp64 专家是 0.0030，标准 bf16 推理是 0.0033；主要终点——加密新增的 KL——为 2.54×10⁻⁴，95% 置信区间上界 3.95×10⁻⁴，低于预注册的 5×10⁻⁴ 非劣边界，且与 bf16 的差异置信区间包含零，top-1 一致率 94.3% 对 94.4%。一个已知坏配置（int8 权重上 Q'=16）以 2.79×10⁻² 的 KL 增量失败，证明终点确实能检测真实退化。误差溯源显示，几乎全部残余散度来自 bf16 注意力导致的路由翻转而非加密本身：用 gold routing 时，精确和加密专家到 fp32 的 KL 都降到 4.0×10⁻⁴，两者仅差 2.2×10⁻⁶。安全方面，攻击者被赋予最强单专家位置，在明文任务上第 0 层还原 99.8% 的 token，第 6 到 23 层还原 42% 到 74%；而在 CipherGenome 任务上，所有十个（层，专家）单元的准确率都落在多数类基线 0.19% 到 1.20%，预注册终点通过，而故意破坏密码学的阳性对照（重用秘密或零秘密）恢复到 98.8%，说明攻击本身有效。系统层面，可复用公开提示把端到端延迟降低 3.54 倍，线路压缩把流量减少 6.8 倍，每个专家每 token 的服务器端成本比 CKKS 基线低六个数量级以上。局限也很明确：完整性对抗恶意服务器和权重保护不在范围内，客户端仍需承担非专家部分的计算和所有非线性求值，且当前评估限于细菌基因组和 1024 token 窗口，更长的上下文、真核基因组和更复杂的路由模式是否保持同等保真度尚未验证。但这项工作的方向性影响是清晰的——它表明对于公开权重的 MoE 模型，只要把信任边界画在专家的线性映射上，利用张量核心的精确整数运算和客户端侧的非线性求值，就可以在不需要任何多项式逼近或自举的前提下实现实用的同态推理，这为基因组基础模型在隐私敏感场景下的外包部署提供了一条可落地的路径。

### [GenomeOcean Anywhere: Private WebGPU Inference for Genome MoEs](https://arxiv.org/abs/2609.35882)
`评分3 · Preprint. 18 pages`

基因组基础模型在真实使用场景中面临一个核心矛盾：最有价值的地方恰恰是序列产生的地方——野外实验室、诊所、环境采样现场，但这些地方往往只有普通硬件，而且DNA数据本身高度敏感、不宜外传。然而当前最大的基因组模型动辄需要数据中心级加速器和约30GB显存，同时要求把私有序列发送给模型拥有者，这两点对目标用户都不可接受。已有的浏览器推理工作（如WebLLM）能把几亿到几十亿参数的稠密模型跑在单个标签页里，分布式推理系统（如Petals）能把大模型按层切分到志愿者机器上，MoE服务系统则在数据中心内部做专家放置优化——但没有任何一个系统同时回答三个关键问题：浏览器内核加量化加网络传输之后，基因组模型的似然度是否还准？专家分布在大范围广域网上时，延迟由什么决定、能否预测？以及最棘手的——志愿者从它收到的专家输入中到底能推断出什么？作者指出，把token分散到不同专家并不能自动带来隐私，因为拆分推理攻击已经反复证明中间激活可以被反演出原始输入，而DNA片段恰恰是基因组组装可以直接重建的对象。论文用GenomeOcean-MoE（8专家、top-2路由、24层、15.1B参数）作为具体载体，把这三个问题从猜测变成可测量的工程事实。

系统的核心设计是把一次前向传播拆成"可信协调者"和"不可信浏览器工人"两部分。协调者持有嵌入、注意力、归一化、路由器、输出头以及KV缓存，只占0.63B参数；每层由路由器决定每个token走哪两个专家，按专家分组后通过WebSocket发给托管该专家的浏览器页面。浏览器端用手写WGSL内核实现SwiGLU专家前向，支持BF16、Q8_0、Q4_0权重并在寄存器内反量化、FP32累加，小批量走矩阵-向量内核、大批量走64×64分块内核，实测达到19–20 TFLOP/s，与PyTorch FP32的最大相对误差仅2.4×10⁻⁶。关键创新在隐私层：作者没有直接把专家输入发给工人，而是采用实数域Lagrange编码计算。具体来说，把输入分成K个数据块并加入T个随机填充块，用Chebyshev节点作为插值点，每个工人收到的是这些块的一个线性组合（即编码份额）。由于专家中的线性映射W作用在编码份额上，得到的是多项式W·u(z)在各自求值点的取值，协调者只要收到任意K+T个结果就能通过Lagrange插值恢复出W·X。SwiGLU的非线性无法用低次多项式表示，所以作者把专家拆成两轮线性计算：第一轮工人返回W₁S和W₃S，协调者解码后自己算SiLU门控；第二轮把中间结果h重新加填充编码，工人返回W₂S'，协调者再解码。填充噪声取自高斯分布，尺度与校准数据上专家输入的逐维RMS成正比，这样每个份额对输入构成一个高斯信道，理论上限制了至多T个合谋工人能获取的信息量。此外，路由本身也是信息泄露源，因此系统提供三档隐藏模式：routed只发被选中的行，dense对全部八个专家都做第一轮，full连第二轮也对全部专家做，使请求形状与路由无关，协调者丢弃未选中专家的输出。

实验结果从保真度、性能和隐私三个维度给出了量化结论。保真度方面，浏览器路径在Q4_K_M、Q6_K、Q8_0各量化级别下与原生llama.cpp的NLL差异一致，误差预算由量化选择而非浏览器决定；分布式路径在BF16下与参考模型的KL为0.00364 nats/token，恰好等于两个正确BF16实现之间的噪声底线，99.85%–99.91%的专家输出与PyTorch FP32逐位相同。性能方面，一个未拟合的延迟模型在48种模拟广域网条件下对解码时间的预测中位误差仅0.74%，并能正确判断何时层流水线优于专家并行；复制机制让工人崩溃对输出不可见。隐私方面，明文专家输入的攻击者能从每一层的单个向量恢复token，一个工人仅凭300个无序token就能以92%准确率识别源基因组；而启用编码专家后，针对份额训练的自适应攻击者退化到最频繁token基线，单个工人每次前向传播对每个token的信息量被限制在1比特以下，同时保真度代价仍低于BF16噪声底线。在Chrome中，编码解码速度为每token 220–376毫秒，取决于路由隐藏程度。局限也很明显：编码计算引入了两轮通信和插值开销，220–376毫秒/token的交互速度对长序列生成仍然偏慢；高斯填充的隐私保证是统计性的而非密码学意义上的完美隐私；系统目前只在单一H100节点上模拟广域网，真实跨洲志愿者网络的异构性和波动性尚未验证。但这项工作首次把Lagrange编码计算应用到Transformer MoE的专家层，并用学习型攻击者量化了实际隐私增益，为"模型跑在数据产生的地方、且不信任任何单一设备"这一方向提供了可复现的工程基线。

### [GenoTrace: Inheritable Watermarks for Genome Foundation Model Distillation](https://arxiv.org/abs/2609.35881)
`评分3 · Preprint. 33 pages`

基因组基础模型正把合成DNA变成一种可复用的下游训练资源，但随之而来的问题是：当一个较小的学生模型通过蒸馏从教师模型那里学到生成能力后，它并不会主动暴露自己究竟受过哪些合成序列的影响。这不同于检测某条序列是否直接由教师生成，也不同于识别被复制的模型检查点——证据必须挺过一次完整的学习步骤，而学生模型可以有不同的架构和参数量。已有的文本水印继承研究（如Sander等人）证明了教师输出分布中的密钥偏置可以被学生部分学到，但基因组数据带来了额外的结构性麻烦：所有模型共享A、T、C、G四字母表，却可能使用完全不同的分词词表，子词token与密码子并不对齐。一个在token空间容易学习的水印，很可能同时改变编码结构或序列多样性。因此真正的设计问题不是“如何把水印偏置调得更强”，而是“如何在基因组token之间分配这个偏置”。

GenoTrace的核心做法是在教师采样阶段引入两个与密钥无关的调制因子，再与传统的绿名单偏置相乘。第一个是位置因子，衡量一个token中有多大比例的核苷酸落在密码子第三位（即摆动位）；第二个是使用因子，衡量token内部完整密码子中有多大比例属于特定生物体偏好的密码子集合（基于Kazusa密码子使用表，取每个同义密码子家族中位于中上水平及以上的密码子）。这两个因子的乘积调制一个由密钥和前序token决定的伪随机绿名单偏置，教师logit被加上这个偏置后采样，学生则在生成的序列上做标准的下一token预测训练，训练完成后评估路径中完全移除水印处理器。审计时，审计方用教师的tokenizer和密钥重建绿名单，对学生输出中观察到的token转移计算z分数。关键洞察在于：位置因子和生物使用因子都是软性偏置而非硬性约束——比如一个包含一个偏好密码子和一个非偏好密码子的token，使用权重是二分之一而不是被排除；一个长token的位置权重趋近三分之一，而二元位置权重只要出现任何第三位就是1。这种token级别的分数化设计使得水印信号可以嵌入到可变长度的子词token中，而不需要改变教师架构或学生目标函数。实现上，作者预计算了一个词表大小乘以三的查找表，把核苷酸级别的偏好映射到token级别，每次生成时只需根据当前阅读框相位取出对应列，与绿名单掩码逐元素相乘后加到logits上。教师侧的偏置强度δ控制绿概率的提升幅度，但学生继承率还取决于训练语料、模型容量和解码方式，必须实验测量。

在GenomeOcean-500M到100M的三种子主实验中，联合分数加权配置（δ=8，使用大肠杆菌密码子表）达到了平均审计分数17.88和94.5%的检测率（阈值z>2.326），而干净的普通KGW基线只有3.99和92.3%——注意平均分数的大幅提升与检测率的小幅提升是两回事，前者反映信号强度，后者反映有多少输出越过阈值。更关键的是抗编辑能力：在密钥感知的token替换攻击下，联合配置保留了49.0%的检测率，而可用的单种子普通水印基线直接降到0%；在同时针对密码子位置和使用机制的核苷酸编辑组合下，仍保留47.0%。不过这种优势并非无条件：联合分数加权在δ=4时经过token替换后只保留10.7%，二元联合加权在δ=8时保留47.2%，说明因子选择和强度必须一起考虑。扩展实验在五种生物条件数据集和最高40倍的教师-学生规模比下都观察到了继承信号，但作者明确承认局限：所有结论限于共享tokenizer的蒸馏和所测试的编辑流程，检测分数不等于经过校准的溯源判决，计算序列质量指标（GC含量、密码子适应指数、k-mer多样性、ORF覆盖、ESMFold和BLAST分析）与检测强度之间存在不同的操作点，生物功能是否保留需要独立验证。这项工作为基因组模型蒸馏提供了一种实用的token级水印构造，并首次系统性地展示了基因组结构——密码子简并性和物种使用偏好——如何塑造可继承的水印信号。

### [BarcodeMAE+: Rethinking Masked Pretraining and Global Representations for DNA Barcode Foundation Models](https://arxiv.org/abs/2609.35877)
`评分3`

DNA 条形码的基础模型长期依赖掩码语言建模（MLM）做预训练，但标准 MLM 有一个被忽视的结构性缺陷：训练时输入里塞满了 [MASK] 占位符，推理时却完全不存在，这种训练-推理分布错位迫使编码器把一部分表征能力浪费在处理这些下游根本用不到的 [MASK] 嵌入上。更麻烦的是，BERT 式模型在文本领域的经验已经表明，token 重建困惑度的改善并不必然带来下游冻结探针性能的提升，因为编码器表征被直接耦合到了重建损失上。而在生物多样性信息学里，基础模型最常见的用法恰恰是当冻结特征提取器——KNN 物种识别、零样本物种聚类，都不做任务微调，所以表征质量本身比重建精度更关键。此外，[CLS] 这类全局序列表征在 DNA 条形码里到底有没有用、该怎么训练，此前几乎没有系统研究，标准 MLM 的重建损失只作用于被掩码的 token 位置，对 [CLS] 没有任何显式监督，光把它拼到输入前面并不能保证它学到有信息量的序列级嵌入。

BarcodeMAE+ 的核心设计有两条主线。第一条是架构层面的 MAE-LM 改造：编码器只吃未被掩码的核苷酸 token，被遮住的位置直接从输入里删掉，位置编码通过跳过被掩码的索引来保持剩余 token 的原始相对位置；解码器则重新插入 [MASK] 占位符，并接收编码器对可见位置的输出，只让解码器去承担重建任务。这样一来编码器永远见不到 [MASK] 嵌入，全部容量都用于建模真实核苷酸序列，下游又只用编码器，训练与推理的输入分布彻底对齐。第二条是全局表征的显式训练：在编码器输入前拼接一个可学习的 [CLS] token，让它通过多头自注意力聚合全序列信息，然后在预训练阶段给它挂一个辅助分类头，用属级标签做监督——选属是因为它是两个数据集里标注最稠密的最细粒度层级，且与下游评测的粒度一致。作者比较了三种辅助目标：把两条序列的 CLS 表征拼接后过 MLP 做同属二分类、用余弦距离的 triplet margin loss（含 batch-hard 与随机两种在线挖掘策略）、以及直接在 CLS 上做属级交叉熵分类。辅助头只在预训练时存在，之后丢弃，且只作用于有属级标签的序列，其余序列仍贡献重建损失。作者还试了 Jumbo CLS——把全局 token 加宽 J 倍并配一个跨层共享参数的宽前馈网络——但并没有比标准 CLS 更好。这套设计之所以更强，关键在于它把「学表征」和「做重建」解耦：编码器不再为 [MASK] 分心，而全局表征则通过显式的分类信号被塑造成对物种/属判别真正有用的形式，而不是指望它从重建损失里间接涌现。

在 BIOSCAN-5M（节肢动物 COI）和 UNITE+INSD（真菌 ITS）两个条形码区域上，编码器-解码器的 MAE-LM 在十种模型配置中几乎全部优于匹配的纯编码器版本，包括每个区域的最优配置。全局 [CLS] 带来的增益非常显著：在 BIOSCAN-5M 上，不加辅助目标时 [CLS] 准确率只有 47.53%，加上交叉熵属分类后跳到 80.65%。最优辅助目标还随生物区域变化——BIOSCAN-5M 上交叉熵最好，UNITE+INSD 上则是成对同属分类最好，在 Yeast 上达到 73.19%、Filamentous Fungi 上达到 63.07%。用冻结编码器表征，BarcodeMAE+ 在 BIOSCAN-5M 上超过了已发表的 DNA 基础模型基线，在 UNITE+INSD 上取得了所评估基线中最高的 Yeast 准确率。作者还发现把 KNN 的均匀投票换成相似度加权的 softmax 投票后，准确率在邻居数 k 从 1 增到 50 的过程中明显更稳定，均匀投票在大 k 时会显著退化。局限方面，辅助目标的最优选择依赖生物域，说明目前还没有一个跨区域通用的全局表征训练方案，Jumbo CLS 的负结果也暗示单纯增加全局 token 容量并非出路；此外两个数据集都处于部分标注状态（BIOSCAN-5M 仅 15.9% 有属级标注，UNITE+INSD 仅 7% 有物种级标注），监督信号的稀疏性仍是潜在瓶颈。总体而言，这项工作把「编码器-解码器掩码预训练 + 显式训练的全局表征」确立为 DNA 条形码基础模型的强设计选择，同时指出全局表征的最优监督目标需要按生物域定制，为后续跨区域统一建模留下了明确的问题。
