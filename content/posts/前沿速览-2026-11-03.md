### [R^2Orch: Recursive Self-Improvement for Agent Orchestration via Self-Play within a Skill-Internalization Loop](https://arxiv.org/abs/2610.22740)
`评分4 · HF 89赞 · 有代码`

这篇论文要解决的是智能体编排器（orchestrator）如何自我改进的问题。现有做法有三条主要路线：从任务反馈中学习工作流与规划的“学习型编排”、通过反复循环自我改进记忆/代码/答案/任务的“自改进智能体”、以及把程序性知识以技能形式交给策略的“技能脚手架”。但这三条线各自卡在三个具体痛点上。第一是手工设计的课程：学习型编排和技能内化都在人预先收集的任务池上训练，而自博弈虽然自己选任务，求解器却一直带着检索到的技能，导致“选什么任务”和“撤什么技能”互不通信，课程无法随技能变化而自适应。第二是优势坍缩：GRPO 这类基于组的强化学习靠同一任务多次 rollout 的结果差异来算优势，一旦所有 rollout 都得到相同结果（全对或全错），优势就变成零，梯度消失；自博弈把任务维持在求解器当前能力边界上、且技能一直在上下文里，所以一旦撤掉某个技能，它支撑的那些任务就滑向全错，优势坍缩立刻回来。第三是不可靠的评估信号：训练期脚手架按一个混合了任务选择和技能效果的成功率来淡出指导，技能库则凭每个技能一个噪声很大的分数决定保留还是淘汰，结果技能库会漂移，直到注入某个技能反而比不注入还差。这三个问题环环相扣——课程不感知技能、技能评估不感知任务分布、评估噪声又反过来污染课程，所以需要一个新的范式把“选任务”和“撤技能”放进同一个循环里互相提供信号。

R²Orch 的核心是一个嵌套的双环结构：内环是自博弈，让编排器（称为 Director）在 Proposer 选出的任务上变得更强；外环则改进“内环如何改进”这件事本身，具体手段是随着某个技能不再有用就把它撤掉。两个环通过两条通道耦合：向下的通道是“递归可学习性”（Recursive Learnability），它给 Proposer 的奖励是——在把候选技能扣掉之后的上下文里，任务的多次 rollout 是否仍然持续产生不同结果。这里的关键洞察来自对近端策略步的解析：一步 KL 正则化的策略更新对成功率带来的增益，在一阶近似下正比于该任务结果方差 p(1−p)，也就是说任务的可学习性本质上就是它结果分布的曲率；而真正值得追求的不是带技能时的曲率，而是撤掉候选技能后仍然存在的曲率，因为那才是能被内化进参数、不依赖脚手架的进步。于是每个 rollout 组被随机分成“隐藏部分”和“可见部分”，隐藏部分读的是扣掉候选技能的上下文，Proposer 的奖励就直接在这个隐藏部分上做经验贝叶斯估计，坍缩时（全对或全错）奖励归零并加惩罚，若只有可见部分有进步则打折，这样 Proposer 会主动去挑那些“撤了技能还学得动”的任务，而不是去挑已经坍缩的任务再过滤掉。向上的通道是“技能撤回”（Skill Withdrawal）：因为隐藏部分是随机分配的，每个 rollout 组就构成一个随机化区组实验，隐藏部分与可见部分均值之差是技能效应的无偏 Neyman 估计量，把这些对比按技能累积起来形成贝叶斯 bootstrap 后验，再用 Thompson 采样优先检验最接近撤回的技能，撤回与准入都做成贝叶斯决策——撤回的损失是技能的正效应、保留的损失是一个小常数 ε，准入则用非对称的零一损失加一个风险阈值 α，从而保证每次撤回在它被测试过的任务上后验期望损失不超过 ε。两个环由此闭合成一个循环：失败被蒸馏成技能，技能被内化进参数，撤回又让 Proposer 去暴露新的失败，Director 于是朝“零技能部署”移动。训练上，Director 用 GRPO 的组相对估计量，但由于随机上下文把大部分概率质量放在扣掉候选技能的集合上，多数更新其实已经在训练“没有该技能”的 Director，中心化优势后等价于留一法基线；两个策略按双时间尺度随机逼近运行，内环快、外环慢，外环每步改写内环的目标函数。论文还给出了一个分解：零技能成功率等于起始成功率加上各轮内环增益、减去各轮外环撤回代价，递归可学习性负责把内环增益做大，技能撤回负责把每轮撤回代价压小。

实验在十二个数据集上覆盖问答、数学、代码和交互式任务，R²Orch 在每一个基准上都优于所有基线，还能在不重新训练的情况下迁移到另外六种 Worker 骨干上，并且在零技能测试时保持精度——这直接验证了“技能被真正内化进参数而非留在上下文里”这一目标。关键数字方面，摘要在正文中只给了“十二个数据集全部领先”“六个骨干免重训迁移”“零技能不掉点”这三条定性加半定量的结论，具体提升幅度需看正文表格。客观地说，局限也清楚：方法依赖一个可靠的验证器来给出二值正确性，开放域任务里这本身就是难题；随机化区组估计要求同一任务能被多次 rollout 且技能检索可复现，任务级方差大时后验需要更多记录才能做出可信撤回；贝叶斯决策的 ε 和 α 是人为设定的风险参数，不同任务分布下需要调；双时间尺度的收敛保证建立在图决定结果等假设上，真实多智能体执行中的随机性可能削弱理论保证。但它的意义在于把“课程学习”和“技能内化”从两个各自带噪声的独立模块，变成了一个共享同一组 rollout 的闭环控制问题——选任务的目标函数直接由“撤掉技能后还学不学得动”定义，撤技能的判据直接来自同一组随机化 rollout 的无偏对比，不需要额外采样，这在思路上为编排器的递归自我改进提供了一个可操作、可分析的模板。

### [Latent Reasoning in Continuous Space for Unified Multimodal Models](https://arxiv.org/abs/2610.42149)
`评分4 · HF 25赞`

这篇论文要解决的是统一多模态模型（UMM）在图像生成任务上无法有效利用语言链式推理的问题。现有做法是在离散 token 空间里做推理，再把推理结果喂给图像生成模块，但作者指出这里存在根本性的模态错配：推理发生在离散 token 空间，而图像生成发生在连续隐空间。离散的推理链难以编码图像合成所需的稠密、空间定位的信息，导致推理退化成表层的 prompt 改写，只在很窄的场景下有效。这直接表现为：即便增加推理预算，UMM 也看不到 LLM 那种平滑的 test-time scaling 收益。作者据此提出核心主张——要让推理真正发挥作用，推理本身必须搬到连续空间里做。

方法上，LARC 构建在 Coconut 式的隐推理思路上，但把它扩展到多模态生成，并引入强化学习。关键设计是把推理轨迹组织成语言段与连续隐步交替的序列：模型在语言模式下正常采样文本 token，遇到特殊 token 后切换到隐模式，直接把最后一层 transformer 的隐状态作为下一步的输入嵌入，绕过文本解码，从而保留内部表示的丰富语义；若干步后再切回语言模式，直到输出结束符，整条隐状态轨迹通过 cross-attention 被图像模块读取并生成目标图像。训练分两阶段。第一阶段是课程式 SFT：一开始完全禁用隐步、只训纯文本推理链，然后逐阶段激活前 k 个隐步，让每个新引入的隐步都建立在已稳定的前缀之上，阶段切换时降低学习率；损失由文本段的 next-token 预测损失和图像上的 flow-matching 损失组成，隐步本身没有显式监督目标，梯度直接穿过它们回传，让模型自己学出有用的表示。这一步同时注入了受控的随机性，解决了 Coconut 式推理是确定性的、无法做策略梯度 rollout 的问题。第二阶段是自演化 RL：核心是信息增益奖励，它衡量加入某条隐推理轨迹后，冻结的参考模型（即 Stage 1 后的模型）对目标图像的预测密度提升了多少，本质上是在最大化隐轨迹与目标图像在给定上下文下的条件互信息，无信息时奖励为零；由于图像模块拿不到显式对数似然，作者用共享噪声下两次条件 flow-matching 损失的配对差值来估计这个奖励。此外还加了一个防止隐步塌缩的步间余弦相似度正则，保证轨迹多样性。优化用 GRPO，从组内 rollout 估计优势，不需要额外的价值模型。

实验在 BAGEL 上实例化，用 FLUX-Reason、WEAVE、ScaleEdit 采样的 100 万条交错样本训练。在 GenEval 上比 BAGEL 提升 7 个百分点达到 SOTA，属性绑定子项提升 15 个百分点；DPG-Bench 从 85.07 升到 90.04，OneIG-Bench 比 Uni-CoT 高 7.6 个绝对点；图像编辑上 LC-T 提升约 10%，PSNR 从 24.3 升到 25.7、LPIPS 从 0.069 降到 0.049；在 MME、MMB、MIRA 等理解类基准上也全面超过 BAGEL 和 Uni-CoT，MIRA 从 7.5 升到 11.7，说明连续隐推理对需要多步中间推断的视觉推理同样有益。更重要的是，在 budget forcing 下把隐推理计算量翻倍，三个 T2I 基准都呈现单调提升，这是据作者所知首个展现出清晰 test-time scaling 的推理增强 UMM。局限方面，方法依赖一个冻结参考模型来定义信息增益奖励，奖励信号的质量受参考模型能力约束；课程 SFT 需要预先构造带步边界的 CoT 数据，数据分布仍有影响；隐步数量与切换时机由模型自己决定，可控性和可解释性相比显式文本链更弱。但整体上，它把「推理必须与生成同处连续空间」这一判断做成了可训练、可扩展的框架，为 UMM 的推理增强指出了一条不同于离散 CoT 的路线。

### [Subquadratic Attention with a Hierarchical Tree-Structured Indexer](https://arxiv.org/abs/2610.42112)
`评分4 · 43 pages`

这篇论文要解决的是 Transformer 注意力机制在长上下文场景下的根本瓶颈：标准注意力在 prefill 阶段的计算开销随序列长度呈二次方增长，在 decode 阶段每生成一个新 token 都要重新读取整个 KV cache，内存带宽和存储成本随序列长度线性上升，这直接限制了 LLM 能处理的有效上下文长度。已有的绕行方案各有硬伤：滑动窗口注意力和状态空间模型用固定大小的状态替代完整 KV cache，虽然把 prefill 降到线性、decode 降到常数，但固定状态在长上下文下必然饱和、性能退化；混合方法把固定状态混合器和全注意力交错堆叠，大部分层便宜了，但少数全注意力层在足够长的上下文下仍然主导总开销；GQA、MLA 这类头压缩方法受限于头数，压缩率有理论上限；KV 驱逐和序列压缩方法理论上压缩率可以很大，但实践中很脆弱，核心原因是无法事先或平均意义上判断某个 token 是否有用。细粒度稀疏注意力（如 DSA、MSA）让每个 query 自己检索 top-K 的 KV 对，全注意力只在这 K 个对上做所以成本恒定，而且每个 query 独立选子集比所有 query 共享压缩表示精度更高，但它把成本转移到了 indexer 上——在接近 1M token 的上下文下，这类层 60% 到 90% 的时间仍然花在索引上，indexer 本身还是二次方的。chunk 稀疏方法试图压缩 indexer 本身、按块稀疏选择，但大多只做单层 chunking，仍然只拿到常数因子加速，且经验上不稳定。论文由此提炼出两个必须同时满足的性质：一是 query 相关的稀疏性，不同 query 需要的信息差异很大；二是活跃状态大小要增长但必须是次线性的——固定状态必然饱和，全注意力线性增长但高度冗余，因为每个新 token 的预测信息量是递减的。关键的经验观察是：在自然语言数据上，全局注意力层中 top-p 子集（注意力概率累计达到 p 的最小 key 集合）的大小随上下文长度呈次线性幂律增长，这暗示了可压缩性；但同时对未来多个 query 取 top-p 子集的并集，随着 query 数增加并集会覆盖几乎整个 cache，说明不能永久驱逐 KV，必须保留完整 cache 但为每个 query 检索不同子集。这两点合起来指向一个几何树结构的层级索引器：粗粒度摘要引导 query 走向有希望的 key 组，不相关的组整组丢弃、无需逐项比较，从而把检索工作量压到次线性。

ZHA 的具体做法是先在 KV cache 上递归构建一棵 key 摘要树，每个节点压缩下一层中一段连续 chunk 的 key（底层是原始 key，上层是子摘要）。压缩的核心洞察是：一个 chunk 对某个 query 的未归一化注意力质量的对数（即缩放后注意力分数的 log-sum-exp）是 query 的凸函数，可以用一组切平面做分段仿射逼近，取这些切平面的最大值来近似。每个切平面由一个参考 query 定义，切平面的参数——压缩 key 和偏置——可以通过在该参考 query 下对 chunk 内 key 做注意力加权、并测量注意力权重的熵来廉价算出。也就是说，树的每个节点存储的是若干组（压缩 key，偏置），对应若干参考 query；这些参考 query 就是整个方法唯一的可学习参数，树构建本身没有可学的东西。构建时机上，decode 时每积累满一个 chunk 的 key 就立刻算出其摘要挂到第一层，每 C² 步挂到第二层，依此类推，摊销到整个序列上树构建的额外延迟约 1% 或更低。路由时，query 从树顶往下走，在每一层用自己与各节点压缩 key 的内积加上偏置来打分，选出 top-p 比例的节点展开到下一层，直到叶子层得到稀疏的原始 key 子集，再只在这个子集上做全注意力。这里的关键是 p 的选择和逐层收缩：每层只保留 top-p 比例的候选，候选数按几何级数递减，因此路由的总比较次数加上最终注意力的成本随序列长度呈次二次方（但仍超线性）增长。由于只训练参考 query、不改基础模型任何权重，ZHA 可以用很短的 KL 蒸馏阶段套到预训练模型上，论文报告只需几十亿 token 的 warmup 就能匹配基座模型性能，且兼容不同的位置编码（包括部分 RoPE 和 NoPE）、门控结构以及 GQA、MLA、CCA 等头结构。论文还特别测试了树的几何形状鲁棒性，包括深达 6 层的极深树，发现性能对树几何不敏感——这一点很重要，因为深树意味着每层候选收缩更激进、路由更便宜，如果深树不掉点，就可以用更深的树换更低的计算量。值得注意的是，作者也诚实指出幂律 top-p 结构并非普遍成立，依赖位置编码：用部分 RoPE 的模型表现出稳健的幂律，而用 NoPE 的模型 top-p 缩放没那么好的幂律性，但 ZHA 在其上仍然表现可比。

实验上，论文把 ZHA 应用到最大 35B 参数的预训练模型，在数学推理、agentic coding 和长上下文检索等挑战性评测上几乎观察不到性能退化，同时用 roofline 性能模型做了外推分析：在与稠密注意力和 MSA 的对比中，一个 p=0.75 的高效几何配置下，ZHA 与 MSA 的交叉点大约在 0.5M token 上下文，超过 1M token 后 ZHA 显著优于竞争方法，并且理论上在数千万到数十亿 token 的极端序列上仍保持渐近次二次方缩放（前提是 top-p 要随长度仔细缩放），有潜力把有效上下文窗口扩展到数亿甚至数十亿 token。局限方面，首先是幂律可压缩性依赖数据和位置编码，NoPE 模型上不如部分 RoPE 模型稳健，说明方法的前提不是无条件成立的；其次，树构建虽然摊销成本低，但需要维护缓冲和逐层摘要，工程实现比标准注意力复杂；第三，性能优势目前主要来自 roofline 模型的外推和稀疏度经验测量，真实超长上下文（百万级以上）的端到端实测覆盖有限，top-p 随长度如何缩放才能既保持精度又保持次二次方复杂度，仍是一个需要小心调参的开放问题；第四，参考 query 的数量和分布作为唯一可学参数，其容量是否足以覆盖足够宽的 query 分布、在分布外任务上是否仍然可靠，论文没有给出完整的压力测试。总体而言，这篇工作的意义在于它把"注意力天然稀疏但稀疏模式随 query 变化"这一经验事实，转化成了一个可训练、可套用到现有模型、且复杂度分析上真正突破常数因子瓶颈的层级检索架构，为长上下文注意力指出了一条从"压缩状态"转向"次线性增长的层级索引"的路线。

### [Does Scaling Toward AGI Depend on What System-1 Lets System-2 Execute?](https://arxiv.org/abs/2610.39497)
`评分3 · HF 53赞`

这篇论文要解决的核心问题是：当前通往AGI的主流路径几乎全部押注在扩大System-2上——更大的模型、更多的数据与算力、更长的推理链、更多的智能体——但这条路的边际收益正在系统性衰减。作者从三个层面论证了为什么“堆交互量”不再有效。第一，数据积累的前沿正在关闭：人类生成的文本存量有限且高质量数据更加稀缺，合成数据虽然能部分补充，但可合成的交互空间是组合爆炸式的，真正的问题是哪些合成交互值得付出成本；而在科学发现、机器人、临床与工业等场景中，交互本身就是一次实验、一次作动或一次测量，其节奏由物理过程决定，算力再多也无法加速一个化学反应。第二，无向交互的边际回报在数学上就是消失的：在幂律缩放律下，多执行一次无条件交互带来的性能增量随累计算力增长而趋于零，因为这条曲线描述的是在固定景观上用无差别交互行进的结果，而改变“执行哪些交互”可以移动曲线本身。第三，两个具体场景让浪费变得可量化：在RLVR中，GRPO对每个prompt采样一组回答并计算组内相对优势，当所有回答拿到相同奖励时所有优势归零，该prompt完全退化，消耗了G次rollout却不产生任何策略梯度信号，而这样的退化prompt在池子里占了相当比例；在物理场景中，rollout无法自由并行且消耗真实时间，高维任务空间里“评估哪些任务”与“评估多少任务”同等重要。作者进一步提出“超级鹦鹉假说”：从模仿人类文本，到人类可读的推理链，再到以自编码表征自我进化，每个阶段中系统学习所用的材料越来越多由AI自身生产，而每一次自生成交互都是用系统自己的算力支付的，因此系统必须在执行之前就具备对交互价值的内判断——这正是System-2无法独自完成的事，因为评估一次交互的价值必须比执行它便宜得多。

为此作者提出“条件交互”作为System-1与System-2的协同设计接口，其核心是一个“预测—门控—执行—更新”的闭环。System-1被定义为轻量、语义感知的预测器，输入是一个候选交互（prompt、任务配置、查询或工具调用）及其上下文，输出是一个效用分数而非解答，其成本远小于执行成本；System-2是资源密集的执行者，只在System-1认证通过的候选上被调用。关键在于这个环是双向的：System-1塑造System-2所接收的数据与算力，而System-2的执行结果反过来成为System-1的监督信号，二者必须一起设计、一起缩放，而不是把一个过滤器螺栓固定在一个已完成的执行器上。作者用AlphaZero作类比：其棋力并非仅来自更深的搜索，而是策略价值网络与树搜索互相训练的结果。在理论层面，作者给出了两个关键结论：在理想筛选且执行成本相等的条件下，执行算力可下降接近1/ρ_u的因子，其中ρ_u是效用相关交互的密度（成本不等时按成本加权），而预测误差、探索和分布漂移会削减这一节省；选择遗憾被预测器误差与效用间隔所界定。这引出了全文的中心假设：ρ_u是一个可测量的缩放效率坐标，而“有信息的算力”比总算力更能描述缩放行为。作者特别区分了池分数与执行分数：池分数ρ_u(θ_t)是当前策略状态下候选分布的性质，由学习动力学产生，任何门控都无法改变它；执行分数则是实际付费的交互中有信息的那部分占比，无条件训练下二者相等，而完美门控把执行分数推到一。条件交互提升的是执行分数，因此在固定参数、数据与算力下，更多预算倾向于买到效用相关的交互。作者还强调ρ_u依赖于策略状态、不是一个可以自由调节的轴，并且所有结论都相对于一个声明的效用函数而言——非零GRPO优势的prompt密度、超过适应风险阈值的任务密度、答案随算力提升的查询密度是不同的量，不可互换。在架构选择上，作者区分了静态级联与自适应协同设计：静态级联（如被开发者称为“System One”的商业模型Jev）训练一次、只在推理层路由、不接收System-2的回传信号，而条件交互要求两个系统在训练、测试时推理、自适应决策和智能体工具使用中全程耦合。

在结果与意义上，作者给出的是理论界与可测量的效率主张而非大规模实验数字：理想筛选下执行算力下降接近1/ρ_u，选择遗憾由预测器误差和效用间隔界定，并论证按预测效用定向交互可以收紧算力、数据与模型复杂度之间的帕累托前沿——更少的rollout和梯度同时降低算力与数据消耗，把每个任务只路由到它所需的System-2模型则削减每任务激活的容量，部署时训练期门控降成本、测试期门控以更低延迟提升服务质量，二者共同提高单位成本的任务成功率。作者也明确划定了局限：该原则不能替代探索，当预测器不确定时它不适用；适用范围被有意限制在存在可靠效用预测器的情形；ρ_u依赖于策略状态且随系统改进而衰减，这一衰减可能解释部分递减回报和缩放指数，但这是假设而非已证实的定律；静态级联产品只能说明商业上对快速结构化判断模型的兴趣，不足以证明全行业收敛。其真正影响在于提出了一种 claim 分层：前提是未来数字与机器人系统可能更多受交互效率而非参数或数据限制，立场是应当协同设计廉价的System-1与昂贵的System-2并以“执行前估值”耦合，假设是ρ_u是资源转化为能力效率的重要决定因素，预测是ρ_u随系统改进而衰减、缩放律用有信息的算力描述比用总算力描述更好。换言之，这篇论文的贡献不是一个新的SOTA模型，而是把“该不该执行这次交互”从一个工程启发式提升为一个可形式化、可度量、可纳入缩放律的效率坐标，并指出通往AGI的下一阶段可能来自两个系统的协同设计而非单独放大System-2。

### [Apriel Voice 27B Preview: An Open Model for Speech, Reasoning, and Tool Use](https://arxiv.org/abs/2610.40738)

这篇论文要解决的是语音助手真正落地时的核心矛盾：用户对着设备说一段话，往往夹杂着截图、需要纠正的标识符、还要让助手去执行开票之类的操作，最终目标是“把事办成”，而不只是把话听写对。传统三段式级联方案把 ASR、LLM、TTS 串起来，转录一旦出错或丢失语气、约束条件，后面的推理就跟着崩；而且级联各模块独立优化，对话历史、工具返回结果很难在组件间无损传递。另一类做法是让语音模型只负责对话、把推理和工具调用甩给后端模型，这同样割裂了“听懂—想清楚—动手做”的链条。已有的语音条件模型（如 Ultravox、SLAM-ASR）证明了把声学特征投影进 LLM 嵌入空间可行，但它们的评测多集中在识别和翻译，没有系统回答“同一个骨干在语音输入下还能不能可靠推理、遵循指令、完成多轮任务”。更麻烦的是，对一个已经 post-train 过的多模态大模型做语音适配，很容易把原有的文本和图像能力冲掉——这正是本文要正面处理的保留性问题。

方法上的关键洞察是：不要把语音当成一个新任务去另起炉灶，而是把语音当作已有推理骨干的一个新输入接口，同时用在线蒸馏把“原来的自己”请回来当老师。具体分两阶段。第一阶段冻结 Whisper large-v3-turbo 编码器和整个 Gemma 4 26B-A4B 骨干（MoE，总参约 26B、每 token 激活约 4B），只训练一个约 4772 万参数的投影器：把编码器输出的 1280 维声学帧按 8 帧堆叠成 10240 维，经无偏线性层升到 4096、SwiGLU 门控压到 2048、再投影到 2816 维解码器空间，然后用这些投影特征替换输入序列中预留的音频位置，多段音频可以和文本交错插入。这一阶段用多语言转写、翻译和“续写”任务（共约 1817 万样本、两轮各 3.2 万小时音频）让冻结的解码器学会“读懂”声学表示，关键是续写任务——它逼着投影器传递的不只是音素信息，而是足以支撑生成的内容。第二阶段解冻投影器和语言骨干（含 MoE 路由），编码器和视觉塔保持冻结，用约 6.15 万小时音频加文本跑三轮。这里的核心设计是“按来源分配监督信号”：目标回答、推理链和工具调用行为用交叉熵（CE）直接教；而在选定的语音任务和文本回放数据上，额外用前向 KL 散度（FKL）让学生模型的预测分布对齐一个冻结的原始 checkpoint（即教师），教师只在训练时存在、推理时移除。FKL 的作用不只是“防遗忘”——它同时被用在语音任务上，把教师在文本条件下的行为迁移到语音条件下，相当于告诉模型“同样的请求，用耳朵听和用眼睛看，你应该给出同样的判断”。配套的工程实现也值得注意：教师模型本地部署、教师与学生的计算重叠调度、融合的全词表 CE/FKL 核函数，以及支持这种混合负载的协调式 checkpoint，使得在线蒸馏的开销可控。对话数据是自动构造的：先合成文本形式的多轮交互（含工具调用与返回结果），再用参考音色一致的 TTS 把用户轮次中的选定片段转成语音，支持整轮说话、只读问题保留上下文为文本、多段分离朗读等策略，并做转换保真度校验，从而让模型见到“口语请求 + 文本上下文 + 工具结果”这种真实分布。

结果方面，在 thinking 模式下 Apriel Voice 在 Big Bench Audio 上拿到 98.90、Speech-BFCL 81.13、τ-Voice 任务成功率 65.51%，平均延迟 1.91 秒；英文 EVA 准确率 51.27%、体验 pass@1 74.13%。这些数字说明语音输入下的推理与工具调用能力已经接近可用的语音 agent 水平，且是开源模型里少见的把“听懂、想明白、动手做”放在同一骨干上并给出完整评测的尝试。局限也很实在：语音合成是外挂的独立模块，端到端延迟和自然度受制于外部 TTS；视觉能力虽然在第二阶段冻结了视觉塔，但解码器本身被更新，图像保留只能靠实测（论文也明确说需要经验测量），并非结构性保证；对话数据是合成加自动转换，合成任务的正确性和目标答案的可靠性没有被校验，可能引入噪声；τ-Voice 65.51% 的成功率离“可靠办事”仍有距离，复杂多步工具链上的鲁棒性有待验证。总体而言，这篇工作的意义在于给出了一套可复现的“给已 post-train 的多模态 LLM 加语音接口而不丢能力”的配方——分阶段适配、按来源混合 CE 与 FKL、自动构造语音对话、以及把在线蒸馏工程化——对这个方向而言，它把语音 agent 的评测从“识别准不准”推进到了“任务成不成”，也为后续在更大规模上做语音-推理-行动一体化提供了可借鉴的训练范式。

### [CEPO: A General Framework for Improving Prompt Optimization in Multi-Agent Systems](https://arxiv.org/abs/2610.34722)
`评分3 · HF 20赞`

这篇论文要解决的是多智能体系统里提示词优化的结构性问题。在多智能体系统中，每个智能体既要完成自己的专门任务，又要在系统层面与其他智能体协调配合，这两件事本来是纠缠在一起的。现有的提示优化方法，无论是联合优化各个智能体的提示，还是像 MASPO 那样把下游交互和协调失败的信息纳入优化信号，本质上都只在优化每个智能体各自的提示词，而系统级的协调规则和智能体级的执行指令被耦合在同一段提示里。这就导致一个根本性困难：当你想要修改一条共享的协调规则时，比如“智能体之间应该如何共享发现、如何标记分歧”，这条规则散落在多个职责不同的智能体提示中，你必须让这些提示发生一致性的改动，否则协调逻辑就会在不同智能体之间产生冲突。而现有的优化器并没有区分“这段提示里哪部分在管协调、哪部分在管执行”，它只能把整段提示当作一个搜索目标，反馈信号也是系统级的最终表现，于是协调规则的修改很容易被执行细节的噪声淹没，或者改了一处协调逻辑却破坏了另一个智能体的执行指令。作者把这个问题凝练成一个核心追问：能否通过提示的结构设计和优化引导，让现有的提示优化器在多智能体场景下真正发挥作用。

CEPO 的核心洞察是把“协调”和“执行”拆成两个独立的优化目标，而不是继续混在每个智能体的提示里。具体做法有两层。第一层是协调者-执行者提示分解：引入一个所有智能体共享的协调者提示，专门定义系统级的协作规则，比如智能体之间如何传递发现、如何标记证据冲突、后续阶段如何衔接；同时每个智能体保留自己的执行者提示，专门规定它如何完成被分配的任务。每次调用某个智能体时，实际生效的提示是把共享协调者提示前置拼接到该智能体的执行者提示上。这样一来，更新协调者提示就是一次改动、全局一致地作用于所有智能体，而更新某个执行者提示只影响那一个智能体的局部行为，两者在参数层面彻底解耦。第二层是角色对齐优化：给底层优化器提供两套不同的元指令，一套专门引导协调者提示朝着团队级协作方向改进，关注跨智能体沟通、冲突证据处理和共享推理规范；另一套专门引导执行者提示朝着该智能体任务执行方向改进，关注任务范围界定、证据使用和具体操作流程。关键在于，这两层提示仍然用同一个系统级验证目标来挑选，元指令只是提供不同方向的更新引导，并不定义两个独立的数值目标。整个框架不自己实现搜索算法，而是把提示结构和优化引导交给现有的优化器去执行搜索，因此具有通用性。默认的优化流程是先固定初始执行者提示、用协调元指令优化协调者提示若干轮，再固定选定的协调者提示、用执行元指令优化用户指定的执行者子集，这个先协调后执行的调度在消融中被证明效果最好，但作者强调调度只是实现选择，框架的本质是分解加角色对齐。

实验覆盖四个领域共十一个基准：文档理解用了 MMLongBench-Doc、LongDocURL 以及 PaperTab、PaperText、FetaTab，数学推理用了 AQuA、MATH-500、AGIEval-MATH，代码生成用了 HumanEval-ET 和 MBPP，视频理解用了 LongTVQA+。作者把 CEPO 套在四个现有优化器上——PE2、OPRO、ProTeGi 和 MASPO——在对应设置下全部取得一致提升。以文档理解为例，PE2 加 CEPO 让 MDocAgent 和 DocAgent 在五个基准上每一个都涨，平均分别提升 4.3 和 2.7 个百分点，其中 DocAgent 在 MMLongBench-Doc 上从 59.5 涨到 67.4，提升 7.9 个百分点。在 MDocAgent 上的控制实验还显示，CEPO 改善了优化预算的效率，并且性能随智能体数量增加呈现出更好的扩展性；组件消融、优化引导互换实验和定性提示分析都支持“分离协调与执行、并让引导与角色对齐”这两个设计确实在起作用。局限方面，论文的默认调度和超参数（比如协调与执行各优化几轮、优化哪些执行者）是在文档系统上做的消融选择，换到其他多智能体拓扑是否同样最优并未充分验证；协调者提示的初始版本由 GPT-5-mini 根据系统描述生成，这一步引入了对生成模型质量的依赖；此外实验主要验证的是“套在现有优化器上能稳定涨点”，对于协调规则本身能被优化到什么程度、是否存在协调者提示与执行者提示之间的负迁移，论文没有给出理论层面的刻画。总体来看，这篇工作的意义在于它把多智能体提示优化从“优化每个智能体的提示”推进到“按角色结构化地优化提示”，提供了一个与优化器无关的通用外壳，后续工作可以在这个分解框架上继续研究更优的调度策略和跨角色的信用分配问题。

### [When Requirements Interact: Scaling Long-Horizon Coding via Interdependent Specifications](https://arxiv.org/abs/2610.40256)

这篇论文瞄准的是真实软件开发中一个被现有基准系统性忽视的维度：任务规格之间的相互依赖。作者先做了一项实证分析，发现当前从 issue 和 pull request 挖掘出来的可执行任务在规格密度和结构多样性上都严重不足——它们通常只强调主要开发目标，而把接口兼容性、状态一致性、错误处理这类约束留在空白处。这带来的后果是，用这类数据训练出来的 coding agent 在真实仓库里经常翻车，因为它们从未被要求同时满足多个彼此牵制的约束。更麻烦的是，合成这类任务本身有两个坑：一是单纯往任务里堆规格，很容易把任务退化成一张可以逐条打勾的清单，模型只要孤立地满足每一条就能拿高分，根本不需要跨需求做联合推理；二是验证这种耦合规格极其困难，需求之间的微妙交互让测试要么漏掉隐藏缺陷、放行不完整的实现，要么过度绑定某一种实现方式、把合法的替代方案判死。论文的核心动机就是：要真正训练出长程编码能力，必须造出规格之间相互约束、且验证器足够可靠的任务，而这需要一个可扩展的合成流水线。

方法上的关键洞察在于把"加性规格"和"互依规格"明确区分开。作者用设计变量的可行空间来刻画这一点：加性任务的可选空间可以分解成各需求独立选择的笛卡尔积，模型可以贪心地逐个解决；而互依规格则刻意打破这种可分解性，使得为满足某一个需求所做的选择会严格限制另一个需求的可选方案，从而逼着 solver 必须全局联合推理。CodeSpecWeave 的合成流程从真实开发者留下的规格种子出发——他们从开源仓库的 commit 历史、issue 讨论和 PR 中挖掘，过滤掉闲聊和裸代码片段后去重，得到横跨六种自然语言的十万余条候选规格单元，再压缩成一份带示例、定义和边界指引的规格参考。合成 agent 在这个参考和"构造互依规格"的提示下探索代码库，刻意把互补的需求锚定到同一组状态转移或同一个核心组件上，比如把输入校验、事务回滚和对既有读者的向后兼容绑在一起，使得单独满足任何一条仍然违反整体契约。它迭代地同时起草任务请求、细粒度规格和测试用例，测试与规格是多对多的灵活映射，并且直接在仓库里跑测试、根据运行时反馈修正。第二道关卡是验证与修复：作者发现自动审查在 3067 个候选任务里识别出 2267 个（73.9%）存在对齐缺陷，说明复杂规格下可靠测试生成极难，而且这些缺陷只有真正跑起来才暴露。于是他们用多个独立编码模型多次尝试，收集候选补丁和执行轨迹，筛出成功率混合的任务（既有挑战性又可解），再由 review agent 检查完整的（请求、测试、补丁、轨迹）四元组：违反多条需求的运行暴露缺失的检查，而合法运行却失败则说明测试施加了不该有的限制。发现假阳性或假阴性的任务交给 repair agent 依据审查结论和轨迹修改请求或验证器，修完还要重新过执行检查、新 solver 试跑和对齐审查才能入库。最终在 14905 个初始任务中，难度过滤留下 3275 个，审查通过 766 个，整条流水线共产出 4670 个训练任务、覆盖 2865 个仓库。

实验结果分两块。基准侧，CodeSpecWeave-Bench 含 100 个任务、1044 条规格，平均每任务 10.44 条，覆盖七类需求；GPT-5.4 到 GPT-6 Astra、Claude Opus 5、Kimi K3、Qwen3.8-Max、MiMo 系列等前沿 agent 的通过率落在 44.0% 到 74.0% 之间，最强的 GPT-6 Astra 也有 26% 失败，说明基准区分度好且仍有明显提升空间。一个有意思的发现是成功率与输出长度负相关：GPT-6 Astra 以最低的平均输出（17.2k token）拿到最高通过率，Codex 内四个 GPT 模型通过率随输出长度单调下降，Claude Opus 5 比 Qwen3.8-Max 高 6.1 个百分点却少用约 47% 的 token，暗示在处理互依规格时多出来的长度多半是无效试错。失败模式主要有两类：补丁针对某条规格写了代码和测试，但行为只在部分输入边界或执行路径上满足它；以及满足了某条需求却违反了约束同一状态的另一条需求。训练侧，他们在两个 310B 总参、15B 激活的 MoE 模型上做 RL，与 SWE-PI（三万条任务的 SWE 数据混合）和 MiMo Coding 对比，CodeSpecWeave 在两个骨干上平均分最高（50.15% 和 67.60%），在 DeepSWE-v1.1 上提升尤其显著（25.30% 和 62.98%），而其他数据集在那里收益有限甚至负迁移，同时在 SWE-bench Verified 和 Pro 上保持竞争力。行为分析显示训练后模型思考 token 分别增至 4.8 倍和 3.0 倍，改动文件和行数明显增多，从局部补丁转向跨文件重构，而且这种扩张是有验证支撑的：每条轨迹的编辑—测试循环从 3.48 升到 4.34、从 2.96 升到 4.90，持续两轮以上循环的轨迹占比超过 70%。按规格数量分组，9–11 条和 12–31 条组增益最大（10.2–12.5 个百分点），七类规格上增益也较均衡（9.5–14.9 点）。局限方面，论文没有系统报告合成流水线的计算成本和多模型试跑带来的开销，验证仍依赖 review agent 的判断、并非形式化保证，基准只有 100 个任务规模偏小，且训练只在 MiMo 系列上验证、跨模型家族的泛化性未知。但它的意义在于把"规格互依性"从一个模糊的直觉变成了可操作的设计原则和可扩展的数据生产方法，并用 RL 结果证明这种数据能实打实地把 agent 从局部打补丁推向跨文件、带反复验证的系统性工程行为。

### [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)
`评分3 · HF 6赞`

这篇论文要解决的是智能体记忆系统的设计优化问题。当一个智能体需要长期辅助用户时，它必须从对话、邮件、文档等积累的历史记录中存取信息，而存储粒度、检索策略、上下文组装方式这些设计选择直接决定了记忆系统的效果。问题在于，不同用户的历史在内容、模态和组织结构上差异巨大，对某个用户有效的记忆设计换一个人可能就不灵了，因此需要针对具体用户历史来自适应地优化记忆设计。已有的方法如 MemEvolve、ALMA、M* 依赖下游任务反馈来优化记忆设计，但个人记忆场景中日常交互往往没有明确的成功或失败信号可供利用。人工标注问答对可以充当这种监督信号，但为每一份新历史手工构造问题、参考答案和支持证据成本极高。于是论文提出的核心问题是：能否直接用未标注的用户历史本身来引导记忆设计的优化？已有工作如 MemBuilder 用合成 QA 作为奖励训练记忆构建策略，MemMA 用 QA 探针修复已存储的记忆，但它们都不是把历史衍生的 QA 当作评估和改进记忆系统设计的反馈信号。论文指出关键难点在于：用于设计优化的参考答案决定了候选设计如何被评估，而源证据则帮助诊断失败响应，如果答案缺乏证据支撑或证据与答案不匹配，就会误导设计选择和后续修订。

MemSteer 的核心思路是把无标注用户历史转化为带有源证据锚定的 QA-证据监督数据。具体做法分三步。第一步是图引导的素材准备：把每个用户的历史组织成一张源记录图，节点保留原始文本、标识符和来源提供的结构元数据，边连接同一对话中的记录、相邻文档章节、显式互相引用的记录以及词汇重叠度足够高的记录；从种子节点做基于路径的扩展，采样出一个连通子图，其记录构成一个受上下文预算约束的素材包，并带有源跨度引用，用于识别联合支撑事实和证据记录。第二步是证据锚定的答案规划与问题生成：给定素材包，一个基于 LLM 的规划器构造出答案计划，明确问题应该问什么、参考答案是什么、哪些支撑事实对应哪些源跨度引用、每条被选证据记录贡献了什么以及需要什么操作来组合这些事实；结构一致性和来源覆盖度不过关的答案计划会在问题生成前被程序化检查拒绝；通过检查的计划连同素材包一起交给问题生成器产出独立问题。第三步是源锚定验证：先用 LLM 审查员做语义审计，分别评估答案支撑度和问题-计划一致性，并对每条事实的源支撑和每条证据记录的声称贡献做独立判断，全部通过才进入下一步；然后做盲答案恢复，只给问题、答案类型和素材包中的源记录，让一个 LLM 盲读者给出带源引用的答案，只有当读者声明问题可回答、答案经类型特定归一化后与参考答案精确匹配、且引用覆盖所有被选证据记录时才通过。通过验证的 QA-证据标注被划分为不相交的训练集和验证集，训练集用于生成修订提案，验证集用于选择记忆设计。在监督信号的基础上，论文开发了 MemSteer-Opt 优化器：把存储、检索、上下文构建的选择表示为一个记忆设计，在固定回答模型、指令提示和上下文预算的前提下，用验证集二值准确率评估设计；对训练集中的错误响应，利用证据标注做失败诊断——如果所需源记录和引用段落已完整出现在最终答案上下文中，则标记为回答失败；如果缺失证据对应的记录在当前记忆系统中不可恢复，则标记为存储失败，若可恢复则标记为检索失败；然后按失败类别分层采样，把问题、参考答案、标注源证据、当前系统响应和诊断结果连同当前设计与修订历史一起输入给基于 LLM 的设计提议器，由它提出修订设计及理由，在验证集上评估后只在准确率提升时才接受替换，接受后重新在训练集上运行以刷新失败诊断和采样反馈进入下一轮。这套机制之所以比之前的方法更好，关键在于它不需要人工标注就能为任意新用户历史生成可验证的监督信号，而且证据标注不仅用于评分，还直接支撑了失败归因，使修订提案能精准指向存储、检索还是上下文构建环节。

实验在 ATM-Bench 和 RHELM 两个基准上展开。ATM-Bench 包含约四年的个人记录，共 11,034 条邮件、图像和视频，主集 1,013 题、困难多跳集 31 题；RHELM 覆盖十个角色的 21,142 条交互记录，分有外部数据和无外部数据两种设定。基线 Base-BM25 是一个记录级检索-阅读系统，用原始问题做 BM25 检索并按排名在固定上下文预算内组装内容。MemSteer-Opt 从 Base-BM25 出发跑 20 轮反思进化，ATM-Bench 上用 DeepSeek-V4-Flash 做回答、评判和设计提议，RHELM 上按官方协议用 GPT-4.1-mini。结果显示，相比 Base-BM25，MemSteer-Opt 在 ATM-Bench 上 Question Score 提升 13.4 分（从 54.9 到 68.3），困难多跳集从 8.2 提升到 29.1，证据召回率也有增益；RHELM 上无外部数据时准确率提升 4.1 分，有外部数据时提升 6.6 分。与使用官方标注 QA 的优化相比，MemSteer 生成的监督具有竞争力，而且官方 QA 方案用了 1,013 题中的 600 题和 1,305 题中的 788 题做训练和验证且这些题仍留在评估集中，而 MemSteer 完全不使用评估集题目做训练。此外，把生成的 QA 提供给 M* 和 MemEvolve 两个已有优化器后，它们在 ATM-Bench 上也能获得提升，说明监督信号跨优化框架有效；新用户实验还表明可以用目标历史生成的监督持续优化设计。局限方面，论文的方法依赖 LLM 做规划、审查和盲读，验证流程虽然严格但仍有漏网之鱼的可能，失败诊断的粒度受限于证据标注的质量，且优化过程需要多轮迭代和反复重建记忆，计算开销不小；另外监督信号的质量与源记录图的结构化程度相关，对结构混乱或跨模态关联弱的历史可能效果打折。总体而言，这篇工作开辟了一条不依赖人工标注、把用户历史本身转化为记忆设计优化监督的路径，对个性化智能体记忆系统的自动化适配有直接推动作用。

### [Asynchronous Flow Map Language Models](https://arxiv.org/abs/2610.42018)
`评分3 · Code available at: https://github.com/david3684/async-fmlm · 有代码`

这篇论文要解决的核心问题是：在语言模型里，token 的预测顺序对生成质量有实质影响，而自回归模型和掩码扩散模型都能利用多步迭代来体现这种顺序——先确定的 token 会为后续 token 的预测提供条件信息。但并行语言模型、尤其是一步生成（单次前向就吐出全部 token）的模型，根本没有"步骤"这个维度来承载顺序，所有计算都压在隐空间里完成，如何把顺序信息注入进去此前并不清楚。已有的流映射语言模型（FMLM）通过压缩连续流语言模型的采样轨迹实现一步生成，但它用的是同步流——所有 token 共享同一个时间标度、齐头并进地去噪，因此天然无法表达"某些位置先确定、某些位置后确定"这种异步结构。虽然异步扩散模型早已存在（如按从左到右、滑动窗口或算法求解顺序安排各位置的噪声水平），但它们的少步蒸馏基本局限于预设的固定调度，或者只能在第一步从若干预设调度中选一个，无法处理完全由模型状态自适应决定的、依赖全部中间输出的学习型调度。此外，一些在生成过程中动态"定稿"token 的采样器依赖随机更新或重新加噪，破坏了流映射蒸馏所需的确定性轨迹。这些缺口正是本文的出发点。

方法上的关键洞察是把"顺序"编码进每个 token 各自的时间变量里，再把这个异步流整体蒸馏成流映射。具体来说，作者为每个位置 i 引入独立的 tokenwise time τ^i，用异步插值把噪声和数据按各位置不同的进度混合；生成过程不再是单一标量时间从 0 走到 1，而是在 L 维单位立方体里从全零向量走到全一向量，这条路径由调度器 ω 决定，它根据当前 token 状态和 tokenwise times 给出各位置的推进速率。作者证明了两件事：一是这种耦合了 token 状态与 tokenwise times 的动力学确实构成合法的概率流（异步流），能正确从噪声分布输运到数据分布；二是它的解算子——异步流映射 F_{s,t}——满足半群一致性（从 s 直接跳到 t 等于经 u 分两段跳），于是可以用自蒸馏来学习：用两时间点的去噪器参数化平均速度，让模型预测从 (s, z_s) 跳到 t 时 token 和 tokenwise times 各自的平均变化率，训练目标是最小化与"先跳到中间时刻 u 再由停止梯度版本继续跳"之间的一致性损失。为了让调度器可以在训练后再选，作者还引入与调度无关的去噪器训练：借助 diffusion forcing 的思路，让各位置的 tokenwise times 独立采样，从而学到以 (τ, 当前插值状态) 为输入的去噪器，推理时再套上任意调度器（预设的或由去噪器预测驱动的学习型调度，后者是掩码扩散模型中各种 unmasking 准则的连续类比）。这样做的妙处在于：蒸馏后的单步模型在前向计算中同时输出 token 预测和 tokenwise times 的推进，等于把"谁先谁后"的顺序效应内化进了隐计算，而不是靠外部多步迭代来体现。相比之前只能在预设调度上做蒸馏、或只能第一步选调度的工作，aFMLM 能处理完全学习型、依赖全部中间状态的调度，且保持了确定性轨迹，使流映射蒸馏在原理上成立。

实验上，作者在数独求解和面向 GSM8K 数学应用题的代码生成两个任务上评估一步生成，aFMLM 均取得了新的 state-of-the-art 一步性能，说明把异步顺序蒸馏进单次前向确实能带来实质收益；论文还分析了一步行模型的隐计算，佐证其确实把顺序与调度的影响吸收进了前向过程。需要客观看待的局限是：当调度器依赖模型状态（学习型调度）时，去噪器与调度耦合后的速度近似不再精确，理论上不再保证精确恢复数据分布，只能寄望于调度为不完美去噪器提供更简单的子问题来提升质量；异步流映射的唯一解只在满足条件的区间上成立，蒸馏目标依赖半群一致性这一自洽约束而非真实轨迹监督；此外评估集中在数独和 GSM8K 代码这类结构性强、顺序敏感的任务上，向更开放的自然语言生成推广的效果尚待验证。尽管如此，这篇工作把"预测顺序"从多步迭代的专属优势拓展到了一步并行生成，为流映射类模型的顺序建模提供了一个可蒸馏、可学习调度的通用框架，对少步/一步语言生成方向有明确的推动作用。

### [Completeness and Cost of Retrieval Structures for Multi-Tool Requests in LLM Agents](https://arxiv.org/abs/2610.41905)
`评分3 · 17 pages, 3 figures, 9 tables`

这篇论文要解决的是 LLM 智能体在多工具请求下的工具检索完整性问题。现实中的请求往往需要调用多个工具，而且工具之间常有依赖关系——一个调用的输出（比如某个 ID 或凭证）是另一个调用的输入。只要检索器漏掉其中任何一个必需工具，智能体就无法完成整个任务。然而现有的工具检索器几乎都是围绕单工具查询来构建和评测的，聚合指标掩盖了多工具场景的真实表现。作者在 ToolRet 全部 7,961 条查询上做了动机分析，发现 completeness@10 在单目标查询上是 0.58 到 0.67，但在四目标及以上的查询上骤降到 0.08 到 0.17；更关键的是，检索器在单目标查询上的排名顺序在多目标查询上会发生反转——比如 bge-base 在单目标上最好或并列最好，但在两到三目标查询上被查询分解方法和 COLT 的 released retriever 反超。这说明聚合分数把两种截然不同的机制混在一起，单目标占多数使得聚合 completeness 对多工具性能几乎没有指导意义。此外，之前针对多工具检索提出的各类结构（扁平检索、LLM 查询分解、LLM 导航层次、server-then-tool 匹配、依赖图、训练过的集合级检索器）各自在不同数据、不同基线上评测，彼此之间缺乏可比的、控制变量的横向对比，也没有人系统测量过每种结构在检索时到底花多少 LLM 调用、token 和延迟。

方法上的核心是控制变量下的六类结构横向对比，作者在 AppWorld（345 条带专家依赖标注的查询，每条至少需要两个 API，必需集合大小 2 到 12，中位数 6）和 MCP-Bench（103 个任务、257 个真实 MCP 工具，其中 97 个需要多工具）两个多工具测试床上各跑一个或两个代表性实现。共享组件尽量固定：扁平稠密、分解、server-then-tool 和图方法统一用 bge-base-en-v1.5 做嵌入，所有 LLM 步骤统一用 DeepSeek-V3.2、温度 0。具体来说，扁平方法用 BM25 和稠密嵌入直接对工具描述打分；分解方法用一次 LLM 调用把请求拆成子请求、各自检索后轮询合并；层次方法用 AnyTool 的官方 agent 在类别—工具—API 层级上导航，只跑搜索阶段；server-then-tool 用 MCP-Zero 的匹配逻辑，让 LLM 为每个所需工具写一个指明服务器域和操作的请求，再匹配 top 服务器和工具；依赖图用 Graph-of-Skills 的默认构建，包括索引期 LLM 验证的语义边，查询期不做 LLM 调用；集合级方法用 COLT，在每个测试床上用其官方配置重新训练（AppWorld 用 90 条训练查询、57 条开发查询选 checkpoint；MCP-Bench 用按服务器数分层的五折交叉验证），并复现了作者在 ToolBench 上的 G2 结果以确认代码正确。关键洞察在于：多工具请求的难点不是单个工具的相关性排序，而是“集合完整性”——要么整个必需集合都进 top-k，要么任务就失败；而不同结构在补全这个集合时走的是完全不同的路径，花的资源也完全不同，因此必须同时测量完整性和检索时成本，并把每个不完整查询的失败归因到“漏了目标 API”“漏了前置生产者 API”还是“排在 cutoff 之下一点”。

结果上，在 k=16 时，未在测试床上训练且每查询至多一次 LLM 调用的结构中，没有一个能在 AppWorld 上完成超过 10% 的查询；扁平词法/稠密、查询分解、server-then-tool 和依赖图在 AppWorld 上最多 9.6%、在 MCP-Bench 上最多 36%。两种结构表现更好但代价不同：COLT 用 75 到 90 条域内标注查询训练后，在 AppWorld 达到 0.328、MCP-Bench 达到 0.583，查询时零 LLM 调用；AnyTool 的 LLM 导航层次无需训练，达到 0.301 和 0.398，但每查询中位数要 31 到 38 次 LLM 调用、约 300 秒。两者在 AppWorld 上统计不可区分，COLT 在 MCP-Bench 上领先。失败模式也截然不同：COLT 漏掉的工具中 58% 排在 17 到 50 名之间，属于“差一点进 cutoff”；AnyTool 通常能找到请求点名的 API，却漏掉生产其输入的前置 API，这是它 241 个不完整查询中 162 个的主因；扁平、图方法和简化版 HYSET 则大多连目标 API 本身都没找到。下游验证用官方 AppWorld agent 跑了 60 个任务：检索集合完整时 21/21 成功，不完整时只有 2/39 成功，而直接给 gold API 集合能让那 39 个不完整任务中的 26 个成功——说明完整性确实是任务成功的瓶颈，且检索器的差距主要在于没把正确工具塞进 top-k 而非工具本身不可用。局限方面，MCP-Bench 的必需集合来自生成器计划、是参考集而非唯一 gold 集；COLT 需要域内标注查询，跨工具池迁移能力未验证；AnyTool 的延迟和调用成本在真实部署中可能不可接受；依赖图在 MCP-Bench 上因工具不声明输出 schema 而无法形成确定性生产者—消费者边，只能靠 LLM 补边。这项工作的意义在于把“多工具检索”从单工具聚合指标中剥离出来，给出了一个可复用的评测框架（completeness@k 加检索时成本加失败归因），并明确指出训练过的集合级检索器与 LLM 导航层次是两条各有代价的可行路线，为后续在完整性与成本之间做权衡提供了实证基础。

### [Latent Sparse Attention: Towards Subquadratic Ultra-Long Context Attention](https://arxiv.org/abs/2610.42147)
`评分3`

这篇论文要解决的是超长上下文（尤其是百万 token 以上）下注意力计算成本爆炸的真实问题。当前 agentic 工作流越来越多地转向长程任务，比如开放式科学研究和软件工程，模型上下文越长往往表现越好，前沿模型已经把窗口推到 1M token 甚至更远。但在这种规模下，标准全注意力在 prefill 阶段是 token 数的平方级开销，decode 阶段每步也线性增长，成本不可接受。稀疏注意力是主流缓解方案：每个 query 只对一部分 key 做注意力，由专门的 indexer 选出子集。问题在于，现有 indexer 仍然要为每个 query 给所有前置 key 或 key 块打分，prefill 依旧是平方级、decode 依旧是线性级，只是常数小一些。论文给出的实测很说明问题：在 10M token 时，一个稀疏注意力层 98% 的 prefill 时间花在 indexing 上；如果 indexer 是“免费”的，稀疏注意力还能再快 58 倍（prefill）和 8.9 倍（decode）。也就是说，超长上下文下稀疏注意力的瓶颈已经从注意力本身转移到了“找 key”这件事上。已有的改进，比如把每四个 key 压成一个再打分、先块级后 token 级、跨层复用选择结果，都只是把 indexer 成本除以一个常数，每个 query 的工作量仍随上下文线性增长；而基于语义聚类的方法要么只在推理时使用、无需训练，要么只在小规模（如 16k token）上验证过，没有一个在百万级以上被系统评估。

LSA 的核心洞察是：既然按内容聚类可以把“找 key”从扫描所有 key 变成搜索少量簇中心，那就把 key 在一个可学习的隐空间里做层次化聚类，让 query 去给簇打分而不是给每个 key 打分。具体流程分两步。第一步是语义聚类：index key 先做 L2 归一化，然后每 n_pool 个连续 key 求和池化成一个 pool key，降低聚类规模；接着在一个 cluster block（固定数量的连续 key）内，用 Ward 方法自底向上合并 pool key 成桶，每个桶维护其 key 之和，归一化后就是簇中心，合并准则是最小化桶内 key 到中心的平方距离增量，合并到固定桶数为止，并限制单桶最大 key 数。桶中心和位置索引表存进 bucket cache，体量只有 KV cache 的一小部分。第二步是语义搜索：query 同样 L2 归一化后，与各桶的单位范数中心做点积打分，这样不同大小的桶可以在同一尺度上比较，选出 top-p 个桶后按分数从高到低展开成具体 key，直到凑满 k 个长程 key；此外每个 query 还固定关注 n_sink 个 sink key 和最近一个 cluster block 的窗口 key，窗口恰好覆盖尚未聚类的 key，避免遗漏。Flat 变体只有一层桶，每个 query 仍要扫所有桶中心，是线性开销；Tree 变体把桶再逐层合并成节点桶，用 beam search 逐层下降，每层只对候选节点桶中心打分并保留 top-p_l，下一层候选是保留节点的子节点加上该层尚未合并的开放桶，于是每个 query 只打 O(log T) 个中心，prefill 的 indexer 成本降到 O(T log T)，真正实现次平方。训练上有两条路：D-LSA 面向预训练模型，冻结主干，每层额外学一对降维的 key/query 投影（把多头 query 求和成单个 index query，使所有头共享一份 key 索引列表），用前向 KL 散度把冻结层在可选 key 上的头平均注意力蒸馏到 LSA 打分上，温度参数用于锐化 softmax 以匹配模型原本尖锐的注意力分布；投影也可以不训练，直接取该层 key 的前若干主方向，称为 D-LSA Training-Free。N-LSA 则从零开始只用 next-token prediction 损失训练，聚类空间由注意力自身的 key 学出来，不需要蒸馏目标。

实验上，论文在 Qwen-3.8-27B 和 GLM-5.3-Flash 上把上下文推到远超其标称窗口的 10M token，在 RULER 和自建的 PaperTrail（跨未见科学论文找事实并建立联系）上评估。10M token 时，D-LSA 在 GLM-5.3-Flash 上把单层注意力的 prefill 加速 22.7 倍、decode 加速 4.6 倍，在 Qwen-3.8-27B 上分别是 72.4 倍和 42.5 倍，同时多种任务上精度与原始稀疏注意力（或全注意力）接近；N-LSA 在 128k token 下达到全注意力精度，单层训练加速 1.6 倍。工程侧还集成进 SGLang 并支持上下文并行，给出 H200 和 B300 的 GPU kernel 并开源。局限也很明显：Tree 搜索的次平方保证依赖层次结构和 beam 宽度等超参，聚类一旦完成桶就不再变化，对分布漂移的适应性有限；D-LSA 的蒸馏目标来自冻结模型在可选 key 上的注意力，蒸馏阶段是逐 key 打分而非聚类，与推理时的聚类搜索存在训练-推理不一致；评估虽推到 10M，但任务覆盖仍以长上下文检索和科学理解为主，对需要精细全局推理的任务是否保持精度还需更多验证。总体而言，这篇工作把超长上下文稀疏注意力的优化焦点从“注意力算得多快”转向“索引找得多快”，用可学习的语义层次结构把 indexer 从线性扫描变成对数级搜索，为百万级乃至千万级上下文的实用化提供了一个有工程落地支撑的方向。

## 强化学习 RL

### [On the Origin and Evolution of Training-Inference Mismatch in LLM Reinforcement Learning](https://arxiv.org/abs/2610.40945)
`评分4 · HF 8赞`

这篇论文要解决的是大模型强化学习里一个很实际但长期被含糊处理的问题：训练-推理不匹配（training-inference mismatch）。在标准的 on-policy RL 设定里，我们假设训练用的回复是从当前策略采样出来的，但工程实现上采样和训练是两套系统——vLLM 之类的推理引擎负责采样，FSDP 之类的训练器负责算梯度，两者的 token 概率分布并不一致。这个不一致有两个来源：一是引擎数值层面的差异（不同 kernel、不同精度，比如 FP8 量化采样器会把差距拉大），二是异步采样带来的权重陈旧（采样器还停留在上一次同步的权重上，训练器已经往前走了若干步）。用 q 采样、用 p 算梯度，训练数据就是 off-policy 的。之前的工作提出了三类修正手段：截断重要性采样（用 p/q 的截断比值给每个 token 加权）、score centering（在每个前缀处减去采样器的平均 score，去掉 drift 项）、以及 PPO 的 ratio clipping。但问题是这些修正的效果强烈依赖于不匹配的来源——实验里 score centering 在量化采样器下稳定、在陈旧采样器下却落后于重要性采样，而 PPO 能扛住陈旧却在量化下崩溃。作者追问的核心问题是：到底是什么属性决定了一个不匹配源需要哪种修正？他们的关键观察是，在单个前缀处，未截断的重要性比值和 centering 都能消掉 drift，所以差异不在 drift 本身，而在于每种修正消掉 drift 之后留下的残余，以及这个残余在训练过程中如何演化。

方法上的核心创新是把采样 token 的误差做了一次精确分解。作者引入第三个对数概率——在采样器权重 θ_old 上用训练器的数值算出的 log-prob——这样就能把 δ_t = log p_θ − log q 精确拆成两项：政策滞后（policy lag，训练器权重和采样器权重之间的差异）和数值差异（numerical discrepancy，引擎数值造成的差异）。这个分解本质上是对重要性比值做因子分解，把训练-推理差异和政策陈旧性分开。分解之后他们分别追踪两项在训练中的行为：数值差异在训练中近似恒定，所以它给更新带来一个几乎固定的偏置，centering 在每个前缀处减去采样器平均 score 就能消掉它的主导偏置；而政策滞后是训练器自己的更新产生的——它留下的残余偏置进入下一次更新，下一次更新又制造出更大的滞后，形成一个反馈回路。重要性加权只能在滞后比值仍然集中的范围内切断这个回路，一旦有效样本量（ESS）跌到一半以下就失效——在 Qwen3-1.7B 上，比值的重尾让这个临界点出现在第 11 步，比高斯预测早了 3 步，重要性采样就在这一步脱离了噪声底。基于这套分析，作者提出了 discrepancy-lag correction（DLC）：对数值差异做 centering，对滞后比值做基于采样器权重的裁剪，并在 ESS 跌破一半时重新同步采样器权重。换句话说，DLC 的核心洞察是——数值差异是静态的、可以用 centering 消偏置；政策滞后是动态的、会自我放大的，必须用裁剪限制其单步影响、用重同步打断反馈回路，两种修正不能互换。

实验结果方面，作者在 Qwen3-0.6B 和 Qwen3-1.7B 上用 Countdown 任务（奖励 ±1，学习率 1e-2，40 步训练，每种配置跑三次）验证了分析。在量化采样器下，重要性采样和 score centering（单独或组合）都停留在噪声底附近，而朴素策略梯度冲到噪声底的 13 倍，score centering 的测试准确率 46.5% 与 on-policy 持平。在陈旧采样器下，score centering 冲到 32 倍噪声底、准确率跌到 12.2%，而重要性采样加 centering 保持在 2.1 倍、准确率 32.0%。DLC 在陈旧采样器下把与 on-policy 训练的 KL 偏差控制在噪声底的两倍以内，而且它的重同步机制防止了单独使用裁剪时仍然会出现的崩溃——这种崩溃是逐 token 修正无法阻止的，而且用采样器前缀上测的 KL 也检测不到。局限方面，实验规模偏小（0.6B 和 1.7B、40 步、单一任务 Countdown），重同步的触发阈值（ESS 一半）虽然有机理解释但仍是经验性的，更大模型、更长训练、更多任务类型下这套分解和修正是否依然成立还需要验证。不过这篇工作的意义在于它把“训练-推理不匹配”从一个笼统的工程噪声变成了一个有结构的、可分解的对象，并且明确指出不同来源需要不同修正、不能指望一种方法通吃，这对异步 RL 系统的设计有直接的指导价值。

### [CRoS: Causality Reward on Scrambled CoTs Improves Accuracy and Reasoning Faithfulness](https://arxiv.org/abs/2610.42054)
`评分4 · 17 pages, 3 figures, 14 tables. Project page: https://xxiaoy`

这篇论文要解决的核心问题是RLVR训练中结果奖励与推理链脱节的根本缺陷。当前标准的RLVR流程是模型生成一段思维链再给出最终答案，训练信号只检查答案对不对，但答案正确并不代表思维链真的在推理中起了作用——模型可能先蒙出答案再用思维链去“圆”一个事后解释，或者干脆走捷径绕过了推理。这种脱节导致两个后果：一是模型在难题上表现差，因为没有真正学会依赖推理；二是思维链不可信，无法用来监控模型的决策过程。为了量化思维链到底有没有因果贡献，已有工作提出了若干因果性指标，思路都是扰动思维链再看答案变不变，具体分两类：截断式（删掉部分推理步骤看答案概率变化）和注入错误式（往步骤里塞错误看答案是否被带偏）。但这两类扰动都有一个致命的混淆因素——它们在改变步骤结构的同时也改变了每一步的内容信息，截断删掉了表面线索，注入错误引入了虚假信息。于是高分可能只反映模型对信息变化的敏感度，而非真正的因果依赖。更糟的是，作者发现把这些指标当奖励信号用会诱发不良行为：模型学会生成信息量更低的思维链、探索和自查行为减少，因为奖励信号被混淆因素带偏了。这就引出了论文的核心问题：能不能只扰动思维链的顺序而不动每一步的内容，从而干净地测量因果性并给出更好的奖励信号？

CRoS的关键洞察正是“只乱序、不改内容”。具体做法是：把模型输出按换行切分成若干推理步骤（不追求精确的步骤边界，只要保证语义单元完整即可），然后对步骤序列做随机排列，生成多个打乱顺序的思维链版本。为了保证乱得够彻底，只保留与原顺序的Kendall秩相关系数低于阈值的排列。接着用一个冻结的参考模型（即RL训练前的初始策略，避免引入外部模型的信息）分别计算原始答案在原始顺序思维链和打乱顺序思维链下的平均token对数概率，两者之差就是CRoS分数——打乱后原答案概率下降越多，说明原始思维链对答案的因果贡献越强。这个设计的巧妙之处在于：每一步的信息内容完全保留，唯一被破坏的是步骤之间的顺序依赖关系，因此分数下降只能归因于模型确实依赖了步骤间的逻辑顺序来推导答案，而不是对信息增减的敏感。在训练阶段，CRoS作为辅助奖励与结果奖励结合使用，基于GRPO框架：对同一问题采样的多个回答中，只有答案正确的那些才参与CRoS排名，按CRoS分数在组内升序排名映射到负一到正的奖励区间，错误回答的因果奖励置零，再叠加格式奖励。用排名而非原始分数是为了消除不同问题间对数概率差值的尺度差异，保证奖励信号稳定。这样，两个答案都对的回答会因为思维链因果贡献不同而获得不同奖励，模型被明确推动去生成真正驱动答案的推理链。

在Reasoning Gym上用Gemma-3-4B-IT训练（AIW逻辑集和Survo游戏集），CRoS在多个维度上超过了结果奖励和四种已有因果指标（Early Answering、Adding Mistakes、CIR、SR）。域外泛化上，五个未见过的逻辑与游戏数据集平均准确率46.8%，最强因果基线43.8%，纯结果奖励41.8%；域内泛化在默认难度与最强基线持平（34.5%），但在中高难度上开始拉开差距（33.5%对33.0%，31.5%对31.0%），说明难题上优势更明显——这符合直觉，因为难题更需要真正依赖思维链。思维链质量用CoT-Pass@K衡量（要求答案和推理过程都正确，推理正确性由DeepSeek-R1-0528-Qwen3-8B判定），CRoS在K从1到128上一致优于基线，平均43.4%对41.4%；在Pass@K上，64次采样时CRoS达到88.3%，高于结果奖励的85.4%甚至高于基座模型的86.9%。思维链忠实性用提示承认分数衡量，CRoS为34.0%，最强基线仅20.2%，且行为观察显示CRoS训练的模型会更明确地承认提示的影响，而基线模型可能不承认提示还给出错误计算。局限方面，论文只在4B模型上做了主实验（12B仅在附录中验证泛化），计算约束下未覆盖更大规模；步骤切分依赖换行符，对不按行分步的思维链格式可能不够稳健；Kendall阈值和排列数量等超参的影响也未充分展开。但这项工作的意义在于指出了一个干净的方向：因果性奖励的设计应该控制混淆变量，仅扰动结构而非内容，这不仅能提升答案准确率，还能同时改善推理质量和忠实性，为RLVR中“奖励什么”的问题提供了一个更精确的答案。

### [CaPtain: A Pipeline for Post-Training Code-as-Policy Robot Agents](https://arxiv.org/abs/2610.40799)

这篇论文要解决的真实问题是：能否用训练语言模型智能体的标准配方——先用监督微调学会接口、再用多轮强化学习精进行为——把一个小型开源视觉语言模型训练成独立的代码即策略机器人智能体，而不依赖闭源前沿模型或预训练VLA。现有CaP智能体基本绕开了训练：一类直接提示闭源前沿模型，每回合调用成本高昂、无法针对新机器人微调、也无法跑在机载算力上；另一类把操作本身外包给冻结的VLA或高层技能（如grasp、place），代码只决定调用哪个技能，而技能决定怎么抓、怎么接近、怎么放，智能体因此被技能训练数据所限，RL最多学会技能排序。小型开源VLM直接控制机器人则完全失败——Qwen3.5-4B在其测试环境中零成功率，少数训练尝试也主要靠SFT或单轮纯文本RL。缺失的是一套完整的SFT加RL配方，让小型开源VLM通过底层原语完成操作，且每个操作决策都由策略自己做出。在底层做这件事比在技能层更难，原因在于没有语义技能兜底后，策略必须自己决定抓哪里、从哪个方向接近、何时闭合夹爪，这些决策分散在每回合数十个请求中，多数请求只做感知或验证；多轮RL必须为这些请求分配信用，而它们的物理效果往往在数轮之后才显现，最终只有一个回合末的结果被观测到。纯结果RL给每个请求相同信用，语言模型评论家则只能从文本和图像间接推断物理进展。

CaPtain的核心洞察来自机器人学习相对语言智能体的一个不对称性：训练在仿真中进行，精确的物体位姿、抓取状态和子目标进展都是已知的，尽管部署时策略只能看相机。于是作者构建了CaPtain-Harness，一个可移植的执行环境，只暴露22个底层原语——感知类（observe返回头部与腕部RGB-D、segment用SAM 3做文本提示分割、point用Molmo2做指向、mark_point把模型自选像素反投影、track_target）、测量类（物体几何中心、范围、偏航角及到目标的偏移，接触与释放几何检查）、运动类（move_to接受绝对末端位姿或单条夹爪指令、hold、recover沿上条轨迹有界回退、release）以及只读的可达性与时序检查、机器人状态与位姿运算，没有任何grasp/place技能、没有VLA。每次move_to被转成直线笛卡尔运动，解逆运动学、查自碰撞、在每个控制子步监控力，首次接触即停，除非请求容忍负载的操作模式；由于每个接近向量、抓取位姿和夹爪指令都显式写在Python里，完整操作策略都暴露给语言模型后训练。每次机器人调用后，harness追加一条结构化文本回执，报告实际发生了什么——运动则给出停止原因、执行距离、峰值力、夹爪开合前后值，感知则给出检测身份、度量位置及到目标的偏移，每格还可附最多四张相机图像。训练分两步：先在harness内用GPT-6 Astra生成的合成轨迹做SFT，严格按部署时看到的多轮格式渲染；再做多轮RL，关键创新是仿真器评论家——它读取策略永远看不到的特权物理状态，把每个请求的信用定义为其对预测成功概率的改变量，在固定时间索引上测量，因此只感知或验证的请求信用接近零，信用集中到抓取和放置上。这一机制把SAO的流式RL表述与非对称actor-critic训练结合：评论家只在训练时使用，测试时策略仅靠相机图像和回执行动。上下文管理也做了工程处理——工具输出截断到固定token预算、每格最多20行回执、只保留最近12张图像，接近上下文上限时逐轮压缩，保留初始任务上下文和最近轮次原文，被删轮次替换为列出所执行命令的简短提示并警告场景可能已变；由于智能体变量活在Python会话而非提示里，检测结果、位姿和辅助函数在压缩后依然存活，且压缩在RL rollout和测试时行为一致，保证策略训练时见到的输入就是部署时见到的。

### [Locality-Controlled Out-of-Distribution Guidance for Robust Regulatory DNA Sequence Design](https://arxiv.org/abs/2610.41736)
`评分4 · Accepted to NeurIPS 2026 · 有代码`

这篇论文要解决的是调控DNA序列设计中的一个真实痛点：现有方法在优化目标属性（比如基因表达活性）时，往往在单一指标上看起来很强，但一旦把评估拆成属性、新颖性和合理性三个维度，就会发现它们其实是在“作弊”。作者指出，之前的做法把生成引导当成一个标量幅度问题——调一个引导强度系数，全局地推着序列往高分走。可调控DNA的语法是空间非均匀的：功能基序（motif）占据的位置对扰动极其敏感，稍微改动就破坏功能；而基序之间的背景区域则相对宽松，可以承受更多探索。全局引导不分位置地施加压力，结果要么把基序推离功能流形导致活性假高、湿实验复现不了，要么只是在复制训练分布、毫无新颖性。单轴评估掩盖了两种典型的奖励黑客行为：预测器特异的基序集中化，以及全局的序列组成漂移。所以问题不是“引导得不够强”，而是“引导打错了地方”。

LocoGen的核心创新就是把引导从幅度问题重新表述为局部性问题。它包含两个关键模块。第一个是掩码分离器：用一个可学习的软掩码把每条序列拆成不变部分和环境部分，训练时要求不变部分单独就足以预测活性，并且通过V-REx（方差风险外推）约束这个预测在不同子群体间表现一致——子群体标签是用冻结的环境编码器做k-means聚类自动推断的，不需要人工标注。这样学出来的掩码倾向于圈出真正承载功能的基序位置，同时用稀疏性和全变差平滑正则保证掩码连续成块。第二个模块是采样时的局部OOD控制：在冻结的MDLM（掩码离散扩散语言模型）骨干上做推理时引导，但只对掩码标记为“环境”的背景位置施加OOD阻尼，基序位置完全保护不动。具体来说，反向去掩码过程中，每个位置被填成某个核苷酸的概率由骨干模型的预测加上一个引导项决定，而引导项里的OOD控制系数只作用于环境位置。这相当于给采样过程加了一个结构先验：告诉模型“你可以在哪里探索、哪里不许动”。因为骨干不重新训练，换目标属性时也不需要重新微调，只需要换外部评分网络，这是相比DRAKES那类奖励微调方法的实际优势。

在HepG2、K562和SK-N-SH三个细胞系上，LocoGen达到了此前没有基线能同时满足的区域——作者称之为属性、新颖性、合理性三维空间中的“空角落”：两个活性读出都高、新颖性高、组成偏差低。对比的对象包括奖励微调的DRAKES、连续扩散的DRaFT、以及SVDD等采样选择方法，这些方法在单轴看不错，但分解评估后都暴露出权衡。论文的局限也值得注意：掩码分离器的质量依赖训练数据的子群体结构，k-means的环境数是个超参；方法建立在离散扩散MDLM上，换成连续扩散或自回归骨干是否同样有效还没验证；湿实验验证的规模也有限。但它的意义在于提出了一个诊断框架——三轴分解评估——揭示了单轴评估看不见的奖励黑客，并且示范了把“在哪里引导”作为一等公民来设计采样算法，这对调控序列设计乃至更广泛的生物序列生成都有方法论上的启发。

### [Localizing predictive concepts encoded in neural representations via hierarchical testing](https://arxiv.org/abs/2610.41046)
`评分3`

这篇论文要解决的核心问题是：在基因组深度学习模型（比如从DNA序列预测染色质可及性的卷积网络）中，如何以统计上可靠的方式定位出哪些网络单元真正编码了与预测目标相关的调控概念（如转录因子结合motif）。这件事之所以重要，是因为这类模型被广泛用于变异效应预测，而要让使用者信任预测结果，就必须确认预测变化是由正确的调控概念驱动的，而不是模型学到了虚假关联。现有方法分成两类，各有硬伤。一类是探索性方法，如TCAV、ACE、CRAFT，它们对单元做排序和可视化，让人工判断哪些单元"看起来"相关，但完全不提供统计置信度——一个单元可能纯属偶然地显得与预测高度相关，没有群体层面的错误控制就无法排除这种可能。另一类是测试型方法，但都只解决了问题的一部分：Bykov等人检验单个单元的激活在概念正负样本间是否有差异，却把各单元独立处理、不做多重检验校正，名义p值0.05直接使用；Teneggi和Sulam虽然做了多重检验校正，但只在一小撮预先指定的概念上做条件独立性检验，既不回答"哪一层里哪些单元或单元簇携带预测信息"，也无法在大量候选之间控制错误。真正能对嵌套的、高度相关的变量簇做错误控制的是分层检验框架（Meinshausen 2008；Mandozzi和Bühlmann 2016），但它原本是为线性模型的系数设计的，而网络单元之间强相关、没有现成的层次结构、也缺乏既定的假设和检验统计量，所以不能直接搬用。论文的切入点在于：分层检验的错误控制其实只依赖两个条件——层次结构在看数据之前就固定好，以及每个节点有一个有效的p值（Goeman和Solari 2010），因此线性模型可以被替换成条件独立性检验，这就为把分层检验搬到网络内部打开了门。

CUTTIE的核心设计可以拆成四步。第一步是给每个单元打分：对激活值，取该单元在序列所有位置上响应的最大值，这个定义与网络用何种池化无关；对Concept Relevance Propagation（CRP）的相关性分数，则把输出端的相关性逐层回传到目标层再沿序列求和，每个类别各得一个分数，因此激活刻画的是"单元检测到了什么"，CRP分数还额外反映"下游网络如何利用这个单元做该类别的预测"。当分数按类别给出时，论文对每个单元的分数做跨类别中心化，扣掉所有类别共享的成分，因为那部分不携带类别间差异的信息；响应向量也同样中心化。第二步是建树：在独立的聚类样本上，用完全连接聚类（complete linkage）按单元分数间相关系数的绝对值距离把每层单元组织成一棵二叉树，根节点是整层、叶节点是单个单元。选完全连接是为了保证树低处的簇只包含彼此强相关的单元——这类单元在条件检验下很难被单独检出，但作为一个整体仍然可以被检测到，这是提升检验功效的关键设计。第三步是自顶向下的分层检验：对每个节点簇，检验在给定该层其余单元分数的条件下，簇内单元的分数是否与（中心化后的）响应条件独立，用的检验是广义协方差度量（GCM），它把响应和簇内分数分别对簇外分数做回归（可用post-lasso等灵活方法），再检验残差之间是否相关。GCM的好处是只要求回归能足够好地估计条件均值，不需要条件采样，且天然支持向量值响应和单元间强相关。遍历规则是：根节点在α水平检验，只有当父节点被拒绝时才继续检验子节点，于是单个单元实际上是在α/M_l的水平上被检验，中间簇的水平介于两者之间，整个树的family-wise error rate被控制在α。这里有个微妙但重要的点：树只要是在推断样本之外独立构建的，无论怎么聚类都不破坏FWER控制，聚类只影响功效和可解释性；而且训练样本和聚类样本可以来自任意分布，只有推断样本必须来自目标分布P_XY，FWER控制在给定模型和树的条件下成立。第四步是解释：对被拒绝簇中的单元，用条件归因图揭示它们编码的具体motif，从而把统计上的"显著"翻译成生物学上可读的概念。

在结果层面，论文先在一个有已知真值的受控模拟中验证了流程能正确找出概念影响目标的那些簇，然后把方法应用到斑马鱼胚胎跨细胞类型预测DNA活性的序列到活性模型上。CUTTIE识别出的非冗余单元对特定细胞类型的DNA活性具有预测性，下游分析显示这些单元对应已知的调控motif，而且从归因图恢复出的motif与文献报道中该motif活跃的细胞类型一致——这说明模型确实依赖这些单元来区分细胞类型，而不只是碰巧相关。论文的贡献可以概括为三点：一是提出了在神经网络层内以FWER控制定位预测信息的分层检验流程，同时适用于激活和CRP分数，并刻画了固定训练网络下每个节点所检验的假设；二是给出了适合向量值响应和单元强相关的条件独立性检验方案；三是在有真值的模拟和真实基因组任务上都做了验证。客观地说，局限也很明显：GCM的有效性依赖回归对条件均值的估计质量，高维或极端非线性下这一前提未必满足；检验的功效要求残差在期望上相关，若真实依赖关系被簇外单元完全解释则可能检不出；方法目前只在基因组场景做了实证，其他领域的普适性还有待检验；此外聚类树的质量虽不影响错误控制，却直接影响能否定位到具体单元而非停在较粗的簇上。尽管如此，这项工作把形式化的分层错误控制与概念级归因首次结合在神经网络中，为"可信地解释模型到底学到了什么"提供了一个有统计保证的实用工具，对变异效应预测等下游应用的意义尤为直接。

### [D2ML: Models for Direct-to-Biology Small Molecule Screening](https://arxiv.org/abs/2610.41070)
`评分3 · NeurIPS 2026 Workshop on AI for Drug Discovery (AI4DD)`

这篇论文要解决的是药物发现早期阶段分子性质预测模型在数据稀缺、分布偏移和噪声干扰下失效的真实问题。传统的小分子发现流程分为两步：先用高通量筛选或DNA编码库在广阔化学空间中找初步命中，再通过反复合成类似物做局部构效关系优化，这导致活性数据呈现“路灯效应”——活性化合物集中在容易通过局部搜索获得的相似系列中，而非因为它们是唯一可能的活性分子。更麻烦的是，化学性质景观本身存在“活性悬崖”：化学空间上邻近的分子活性可能天差地别，模型在训练分布之外性能急剧下降。直接到生物学（D2B）策略通过纳克级高通量化学合成结合粗反应混合物的生物测试，能在几天内合成并测试超过一万个新化合物，大幅扩展了数据规模，但代价是测试的是未纯化的粗产物，真实浓度未知，且测定按单点初筛、粗剂量响应、微克级纯化合成三个保真度递增的阶段级联进行，每个阶段的数据噪声结构和信息含量完全不同。之前的方法要么只用高保真但极稀疏的纯化数据训练，浪费了海量粗测数据；要么简单地把所有阶段数据混在一起回归，没有针对每个阶段的信息特点设计预测目标和损失函数。论文的核心问题就是：粗测阶段的结构化噪声到底会淹没数据量带来的收益，还是说只要模型设计得当，跨阶段共享监督信息能显著提升稀疏阶段的预测能力？

方法上的关键洞察在于为每个测定阶段量身定制预测目标和损失函数，而不是让所有阶段共享同一个回归目标。单点初筛阶段预测的是活性概率（分类问题），因为单浓度高浓度下的信号只能作为粗粒度活性证据；粗剂量响应阶段不预测绝对效价，而是预测跨靶点的对数效价比值——这是因为粗产物中目标分子的确切浓度未知，但同一粗反应孔的材料在多个靶点上测试时，浓度不确定性是共享的，做比值时恰好抵消，从而在绝对效价不可靠的情况下仍能保留选择性信息；微克级纯化阶段才预测绝对对数IC50。模型架构上，单任务版本为每个阶段训练独立网络，多任务版本则共享分子骨干网络（统一使用Morgan指纹作为表示），但每个阶段有独立的输出头和损失函数，并且做了阶段间的损失归一化和加权，防止原始损失量级差异主导共享目标。这里的关键技术细节是：粗剂量响应的比值监督使得模型能在浓度不确定下学习选择性，而多任务共享骨干让数据量最大的单点阶段（两万一千余分子）学到的表示迁移到数据量极小的纯化阶段（仅一百一十四分子），从而缓解稀疏阶段的过拟合。此外，剂量响应曲线用贝叶斯四参数Hill模型拟合，每个测量值附带后验不确定性和非活性概率，只有非活性概率低于阈值的测量才用于效价训练，这进一步净化了监督信号。

结果方面，在ROS1激酶抑制剂发现项目的数据上，多任务深度模型在所有阶段都优于单任务模型：单点阶段AUROC从0.890提升到0.892（差异很小），但粗剂量响应和纯化阶段的提升显著，纯化阶段留出集上Spearman相关系数达到0.443，前瞻集上达到0.175，而线性回归基线在留出集上看似不错（ρ=0.624）却在前瞻集上完全崩溃（ρ低至无法泛化），说明仅靠数据量而不设计阶段特定损失是不够的。前瞻性验证中，用单任务模型在约一亿个可合成虚拟库中筛选，经过单点活性、粗剂量响应选择性、纯化选择性、纯化效价四层过滤后合成测试了84个新化合物，最佳化合物达到233倍ROS1对TRKB选择性且ROS1 IC50为14.7 nM，而训练集中选择性最好的化合物仅为79倍选择性和20.3 nM效价，且新化合物与训练集最优化学型的Tanimoto相似度仅0.529，说明提升并非来自局部修饰而是模型引导的远距离化学空间探索。局限在于多任务模型尚未做前瞻验证（前瞻实验用的是单任务模型），纯化阶段数据仅一百余分子导致前瞻集相关性偏弱（ρ=0.175），粗剂量响应选择性估计依赖“粗混合物中其他组分不贡献靶点特异性活性”的假设，且模型容量与数据量的匹配关系仍需进一步探索。这项工作的意义在于证明了D2B级联数据中结构化噪声不必被抛弃，通过匹配预测目标与各阶段信息结构并共享表示，可以在高保真数据极度稀缺时仍获得可用的预测模型，为模型引导的D2B发现循环提供了可操作的建模范式。
