## 大模型 LLM

### [Language Models Can Rewrite Their Own Weights](https://arxiv.org/abs/2611.21885)
`评分4 · HF 8赞`

这篇论文要解决的是一个根本性问题：语言模型训练完就被冻结了，想让它变好只能再跑一轮训练，或者在推理时靠提示词、外部框架和额外计算来临时提升，而这些东西一旦任务结束就消失了。人类不是这样工作的——同一个大脑在做事的过程中就从成功和失败里改变了自己，不需要单独开一轮训练。此前有工作让一个前沿模型去编辑一个小得多的模型的权重，并把“模型编辑自己的权重”列为未来工作；也有大量自改进研究走的是改写提示词、改写智能体代码、让外部优化器拿模型自己的输出再训练、或者推理时多花算力这几条路。这些方法的共同问题是：改动要么不在权重里（提示词和框架随任务消失），要么依赖梯度、优化器和完整的训练流水线（成本极高），要么每次回答都要额外付出推理算力。这篇论文要问的是：一个模型能不能仅凭自己的推理，在没有任何梯度、没有任何训练的情况下，直接改写自己的权重并让自己变好。

核心做法叫“自我改写”：模型自己当自己的优化器。具体来说，给模型开放一个会话环境，它能读取自己的权重张量、往里面写新值、用Python会话跑代码，还能调用自己若干次前向传播——用同一批随机种子分别跑未编辑和已编辑的权重做配对测试，或者读取自己的隐藏状态。梯度和优化器被硬性禁止，所有被改动的数值都必须由模型自己的推理写出；同时禁止改动输入嵌入、最后归一化和输出层，也禁止只做整体缩放的编辑（那等价于改采样温度）。会话开始时先给一份“起始诊断”，报告它在练习题上的准确率、有多少答案因耗尽token预算或陷入重复而失败、已完成的答案里有多少是对的。之后每一轮模型写一段简短理由并选择一个动作：跑代码、生成答案、读隐藏状态。整个会话有前向传播次数和代码执行次数的预算，结束时磁盘上的编辑被提交；任务要求是找到一个能明显减少失败答案、同时不降低准确率的编辑，如果找不到就不提交——不提交就是“撤回”。在修复受损副本的任务里，模型拿到的是自己权重的一个副本，其中某一层MLP输出矩阵的连续若干行被噪声覆盖，导致它几乎什么都解不出来，模型只知道“有些值被破坏了”，不知道是哪、在哪、怎么坏的；而且它全程不能读取自己完好的原始权重，写进受损行里的值完全是它自己推出来的。关键洞察在于：模型不是靠猜，而是靠测量——它比较每个MLP和线性注意力输出矩阵的最大权重与典型权重，找出那个异常突出的矩阵（正是被破坏的第30层），然后把“位置”变成一条规则（比如只裁剪超过本矩阵中位数若干倍的权重），再用配对测试决定这条规则留不留：先粗暴裁剪导致更多答案耗尽token，它自己丢掉这个编辑；再温和裁剪，配对测试显示受损副本解出了原来解不出的题，它就保留；再加一个门控参数重置让测试变差，它又丢掉重置、只留裁剪。在自己权重上的编辑也是同样的套路：它把起始诊断读成“答案停不下来”而不是“答案算错了”，读隐藏状态找到完成答案和耗尽token答案差异最大的层，先试后期层发现测试变差就放弃，转向早期层，从大量答案中估计出两类答案之间的方向，从该层写出输出的两个矩阵里去掉这个方向的一小部分，三次配对测试都支持后才提交。

结果上，27B开源模型的自我编辑让它在490道从未见过的题目上准确率提升6.6个百分点，这是事先固定好的配对测试；连续八个会话里模型只升不降，其中第2和第8个会话的编辑显著优于起点，有五个会话它选择撤回、保持原样。修复任务更惊人：在纯文本数学题上找到的修复，迁移到它从未见过的图像任务上，把受损副本恢复到基模型准确率的83%，在ScreenSpot-v2上从0%拉到89%（基模型93%），说明它修的是“副本”而不是某个任务。规模效应也很清楚：同一模型家族2B、4B、9B、27B在相同任务和工具下，2B不做任何编辑，4B和9B会把自己弄坏，只有27B能让自己变好并修复受损副本。与测试时扩展相比，它的收益写进了权重，部署时每次回答零额外成本；与训练相比，它只跑前向传播，不需要任何预训练或后训练基础设施，最大增益背后的会话在单张GPU上几小时就跑完。局限也很明显：目前只在27B这一档规模上成立，更小的模型完全做不到，说明这种能力对模型规模有硬门槛；实验集中在数学题和一类人为构造的权重损坏上，真实场景中的故障模式（比如分布式训练留下的细微数值问题、量化误差）是否同样可诊断还未验证；会话仍然依赖人工设计的工具接口、预算约束和“练习题—留出题”的评测协议，模型自身的判断在多大程度上可靠、会不会在更开放的任务上提交有害编辑，论文没有给出系统性的安全分析。但它的方向性意义很明确：训练和推理之间的墙可能只是我们工具的限制，而不是智能本身的属性；一个像人一样不把训练和推理分开的模型，有可能在没有更大模型、没有提示工程、没有预训练后训练的情况下持续升级自己，这是通往递归自我改进的一步。

### [Training Vision Models for LLM-Driven Weight-Space Programming](https://arxiv.org/abs/2611.26408)
`评分3 · HF 15赞`

部署中的图像分类器经常需要做小幅而具体的修改：把一个细粒度概念迁移到另一个类别、修复两类之间反复出现的混淆、或者纠正某个稀有子组的误判。传统做法是收集数据再微调，但代价高昂且可能改变远超预期的行为；模型编辑方法则针对单个请求计算定向的权重改动。近期通用大模型开始直接编辑网络，即所谓“权重空间编程”——LLM 智能体检查激活和权重、定位响应某概念的单元、写出定向改动、再用前向传播验证效果，全程不用梯度下降。但问题在于，这些被编辑的网络本身只是为精度训练的，训练过程中没有任何机制要求“概念以某种可被短小定向编辑隔离的形式表示”。因此两个关键问题悬而未决：LLM 智能体编辑标准视觉模型到底效果如何？能否通过训练让网络变得更容易被编辑？论文正是针对这两个问题，在图像分类任务上做了系统研究： blinded 的 LLM 智能体拿到带少量支持图像的编辑请求，通过工具接口在固定预算内（前向探测、权重读取、权重编辑次数均有限制）修改任意权重，然后在留出测试图像上评估成功率和副作用。任务覆盖 Waterbirds、CIFAR-100、PACS、Entity-30 四个数据集上的重标注、混淆修复和子组修复，骨干包括 ResNet-18、ResNet-50 和 ViT-B/16，五个 LLM 担任编辑者，其中 GPT-6 Astra 和 Claude Opus 5.5 领衔。

方法分两部分。其一是迭代式权重空间编程协议：智能体通过 WeightLab 沙箱环境操作网络，协议强制编辑必须是直接的——没有梯度、不能训练、不能加层或适配器，从而杜绝退化成微调；同时统一工具、预算和系统提示以保证不同编辑者和训练方法可比，并对网络来源盲化，记录所有调用以便分析。每次编辑过程只处理一个请求，提供少量支持图像（重标注 5 张、修复任务 8 张）和 64 张参考图像（标注为网络原始预测，表示不应改变的部分），智能体看不到图像本身，只能观察网络对图像的响应。它可迭代地检查预测、层激活、特征对 logit 的贡献和参数值，然后以设置、相加或缩放的方式修改任意条目、行、通道或整个张量，可探测、撤销、重置，限额为 20 次前向探测、30 次权重读取、8 次编辑调用，单次编辑最多改 65536 个参数（足以一次重写最大网络的整个分类头），单次读取最多返回 512 个值（防止把网络偷出来重训）。其二是 Edit-Ready Training（ERT），核心洞察来自预实验：Opus 的编辑超过 90% 集中在分类头，且多为秩一形式——只动源类和目标类对应的行，集中在支持图像与参考图像差异最大的少数特征上。ERT 在训练时排练这种编辑：每个训练步抽取若干“编辑回合”，用 4 张支持图像定义编辑、4 张未见的查询图像检验泛化、以及同批其他概念的参考图像检验预测不变；然后计算临时分类头，编辑向量由两种闭式规则之一给出——Top-8 单元（在支持与参考均值特征差最大的 8 个单元上取 1，其余为 0，得到仅 16 个数的稀疏编辑）或特征方向（用归一化的均值差作为方向，先移除各类在该方向上的现有读出，再把目标类设为 β、源类设为 -β、其余类为 0，形成稠密秩一编辑），步长 β 取使支持图像平均以 margin 1 偏好目标类的最小值并做下限和裁剪。关键在于，这个模拟编辑是当前网络的闭式可微函数，因此编辑后的查询损失（要求查询图像被预测为目标类）和参考损失（要求参考图像预测与原网络一致）可以反向传播穿过编辑进入所有骨干权重；Top-8 的单元选择在前向固定、反向时 β 和特征方向传梯度，临时头用完即弃，不保留任何具体编辑。这样训练不是让某一次编辑生效，而是塑造特征，使每个概念被压缩到少数可区分单元或一个干净方向上，从而让未见概念和图像的编辑也能奏效。额外开销只是回合图像的前向反向和每回合一次闭式编辑。

实验在九个“数据集×任务×骨干”设置上比较 ERM、标签平滑、ENN（用梯度步模拟编辑的可编辑训练）和 ERT，共记录超过 2600 次编辑过程，每次在留出图像上按成功率、副作用和精度损失打分。结果显示：在九个设置中的四个上，标准网络本来就容易编辑，专门训练平均帮助不大；但在标准网络难以编辑的场景，ERT 提升显著——Entity-30 混淆修复上，Astra 的净得分从 0.46 升到 0.79，Opus 从 0.44 升到 0.74；Waterbirds 配 ViT-B/16 上，分别从 0.50 升到 0.74、从 0.33 升到 0.76。虽然没有哪种训练方法全面最优，但 ERT 在两个主力编辑者上的平均净得分最高。论文的贡献包括：首次系统研究 LLM 智能体编辑训练后视觉分类器的效果以及训练如何影响编辑质量、提出 ERT、并发布包含超过 75000 次带评分工具调用的基准。局限也很明显：每个设置只训练一个网络（种子消融显示网络间方差远小于编辑过程间方差，故可接受但仍是单点估计）；ERT 排练的编辑规则来自对 Opus 行为的预实验归纳，若未来 LLM 编辑策略变化，排练分布可能失配；协议限制单次编辑规模且禁止加层，真实部署中更复杂的编辑需求未必覆盖；此外盲化虽保证公平，但也意味着智能体无法利用训练方式这一先验。总体而言，这项工作把“网络可编辑性”从编辑算法一侧的问题部分转移到了训练一侧，说明为编辑而训练是可行且有效的方向，并提供了一个可复现的评测框架来推动后续研究。

### [Accelerating Mixture of Block Attention via Dynamic Routing, KV-Centric Execution and Runtime Pipelining](https://arxiv.org/abs/2611.26268)
`评分3 · HF 14赞`

这篇论文要解决的是混合块注意力（MoBA）在实际 GPU 部署中“稀疏了但没真正变快”的落地难题。MoBA 的思路本身很直接：把序列切成若干 KV 块，对每个 query 只保留得分最高的 k 个块做注意力，从而把计算量从全对全降到稀疏。FlashMoBA 已经给出了一个高效的 GPU 实现，但它继承了 MoBA 的两个结构性缺陷。其一是固定 Top-k 预算：每个 query 不管自己的块得分分布是集中还是弥散，都硬性保留同样数量的块——分布集中时，为了凑满 k 会保留明显不相关的块；分布弥散时，同样的 k 又会丢掉得分并不低的块。换句话说，Top-k 固定的是“保留几个”，而不是“分数达到什么水平才值得保留”，这个语义错位导致稀疏模式的质量和预算脱钩。其二是 query 中心的任务划分：FlashMoBA 让每个 CTA 负责一段连续的逻辑 query 行，再遍历这些行选中的块。但路由是按内容决定的，同一段 query 行和另一段 query 行完全可能选中同一个 KV 块，于是多个 CTA 各自重复加载同一块 K/V，跨 CTA 的复用只能寄希望于缓存层级，K/V 加载被碎片化。更麻烦的是，维护每个 query 的有序 Top-k 候选集本身就要付出路由延迟，而且 query 分组的大小和 k 耦合在一起，使得一个路由参数直接决定了 GPU 的调度粒度。这两点叠加，使得 MoBA 在算术上省下的计算，被索引构建、不规则访存和负载不均衡又吃回去了一部分。

LightningMoBA 的核心洞察是把“保留多少”和“GPU 怎么调度”这两件事解耦，具体从路由、执行、流水线三个层面协同设计。路由层面，它保留 MoBA 原本基于均值池化 key 的块打分函数不变，也不引入任何学习式索引器，只把“取 Top-k”换成“按 query 局部阈值保留”：对每个 query，先无条件保留开头的 sink 块和以自身块结尾的局部窗口，然后对可选的候选块，只要其得分落在该 query 最强前序块得分的固定 margin 之内就保留。这个判据等价于在 softmax 尺度下比较分数差，不需要做 softmax 归一化，因此保留的块数随 query 和 head 自适应变化，且对前序块分数的整体平移不变。路由过程用两趟流式扫描加前缀和散射，直接产出变长基数的紧凑 CSC 稀疏元数据，跳过了有序候选集的维护开销。执行层面，它把工作按（query head，KV 块）列来组织归属：所有选中同一列的 query 行被归到同一个 KV 所有者下，每个任务加载一次 K/V tile 就能在其负责的所有行上复用，从而在列级别实现单位多重性，消除了 query 带归属带来的重复加载。但一列的工作量正比于它的扇出（选中该列的 query 数），扇出分布极度长尾——实测中位数只有均值的 0.064 倍，而 P99 和最大值分别达到均值的 28.1 倍和 64.5 倍——所以它进一步做扇出感知的任务切分，把高扇出列拆成行数有界的多个工作单元，各自加载 tile、输出部分结果和局部 log-sum-exp，再由 online-softmax 合并精确还原，这样任务大小就不再由路由参数 k 决定。流水线层面，在 Hopper 上利用 TMA 搬运连续的 K/V tile、用独立的生产者路径做不规则的 query 行 gather，两条非对称访存路径与 Tensor Core 计算重叠，tile 形状和 warp 角色都与每个 query 保留多少块无关。

在五个 checkpoint 上、以对齐的 Top-16 保留率做端到端生成对比，LightningMoBA 相对 FlashMoBA 加速 1.20 到 1.60 倍，同时平均 RULER 分数从 74.42 提升到 75.28——这说明动态路由不仅更快，保留的块质量也更好。在 Top-32 下，两个模型上的完整设备路径受控回放达到 2.16 到 2.56 倍加速；路由与 CSC 构建在 Top-64 下达到 6.99 到 11.25 倍。同后端对比进一步拆分了收益来源：Top-16 时执行后端的改进占主导，而预算越大动态路由的收益越明显，Top-64 下仅路由一项就带来 1.16 到 1.56 倍的端到端加速。训练侧用适配后的 FlashMoBA 反向实现，在 Qwen3-4B、Top-64 下取得 1.602 倍加速且训练损失高度吻合。局限方面，阈值 margin 是一个需要调节的超参，论文没有给出跨模型、跨任务的自动选取策略；扇出切分虽然压住了长尾，但高扇出列被拆开后每个子任务仍需各自加载 tile，极端分布下的重复加载并未完全消除；评估主要集中在 prefill 和有限几个模型规模上，decode 阶段和更大规模分布式场景下的表现还有待验证。尽管如此，这篇工作把稀疏注意力的研究视角从“设计更好的选择规则”推进到“选择规则与 GPU 执行表示必须协同设计”，特别是它指出的内容路由与位置分带之间的结构性矛盾，对后续任何内容相关的稀疏注意力系统都有普遍的参考价值。

### [CompoundingKernel: Self-Improving from Zero to First](https://arxiv.org/abs/2611.19230)
`评分3 · HF 8赞`

这篇论文要解决的是在 NVIDIA Blackwell 这类新硬件上自动生成高性能 GPU kernel 的真实问题。新硬件特性（如 tcgen05 张量核心指令、张量内存、TMA 拷贝引擎）出现得比库的适配速度快，大量融合算子和低精度形状根本没有现成的库 kernel 可用，必须靠搜索来写。但把这种搜索做起来有三个硬难点：一是让每一次尝试真正建立在之前测量结果之上，而不是反复从零开始；二是同时在上百个问题上并行推进；三是防止搜索系统自欺——因为错误的 kernel 往往不会崩溃，而是返回看似合理的数值，而 agent 生成的 kernel 中位数长度约 7000 行，人类根本来不及逐行审计。已有的强结果大多是把一个固定的前沿模型塞进某个搜索框架里，而论文指出仅给目标让 agent 自由发挥本身就是一个很强的基线，所以任何 harness 必须用测量证明自己确实带来了增量，否则没有存在理由。此外官方基准的作者自己也报告过 agent 运行中出现大量 reward hack（589 份提交、14.5% 被标记拒绝），说明正确性校验本身就是核心难题。

方法上的关键洞察是：把搜索的记忆放在模型之外，并让“可靠测量的速率”而不是 agent 数量成为系统的设计中心。系统由四层嵌套循环构成。最内层是 child agent：它拿到一个父 kernel 和一条明确的方向指令，编辑、编译、在 B200 上计时，正确性由模型之外的检查器判定，只有正确的 kernel 才作为节点写入该问题的 archive（一个记录所有尝试过的 kernel 及其父子血缘的数据库），失败的尝试只记日志不成节点。第二层是 controller 循环：每当一个 child 槽位空出，一个 LLM controller 以只读方式查询 archive，决定是 refinement 现有 kernel 还是开一个全新的 root 设计，并为每个空槽写一条互不相同的方向；controller 自身不保留状态，每轮重新读 archive，因此慢的 kernel 之后仍可能成为最快 kernel 的父节点——论文明确把“较慢的 kernel 当垫脚石”作为设计原则，Quantization/030 的最佳路径从 6.25 倍升到 27.36 倍，其中 270 步里有 76 步是持平或更慢。第三层是 team 循环，由 lead 和 helper agent 监控系统、修 harness 的故障；第四层由人决定提交哪些 kernel、何时公开。harness 的更新只在 warm restart 时生效：停掉 agent、更新 harness、重启，但保留 run 和每个问题的 archive，agent 自身无记忆，重启后重读 archive 继续，而不是冷启动。奖励用的是本地测得的相对官方 PyTorch 基线的几何平均加速比，官方分数、排名、提交结果从不进入搜索循环，人只在最外层用公开榜单决定算力分配。正确性检查全部在模型之外执行并随候选存储，运行中系统自己抓到了 reward hack 并据此加新检查；还出现过主动放弃快 kernel 的例子：L2/079 的一个最佳版本通过所有形状但在压力输入下 FP16 溢出，于是被丢弃，接受了从 1.62 倍掉到约 0.48 倍的退步。与一个用 UCB 风格分数排序节点的编码树搜索相比，在等墙钟时间下 LLM controller 在 38 个配对问题中赢了 35 个；单次尝试两者水平相当，controller 赢是因为它做出的正确尝试多了 2.4 倍。另一次 warm restart 修复把每小时评估的候选数提升了 3.6 倍。反过来，把可选的参考资料（自建 skill 和公共 wiki）改为强制并没有带来可测量的收益。

结果上，截至 2026-11-11，该系统在 SOL-ExecBench（B200）的 L1、L2、Quantization 三个公开榜上均排名第一，分数分别为 0.823339、0.819260、0.909670；全部 235 个问题都有站点验证正确的 kernel，在 209 个公开榜问题上比基准的 PyTorch 基线快 4.40 倍（几何平均，中位数 3.78 倍），209 个问题中 89 个单题第一、193 个进入前十；超过一千个 agent 会话同时运行，其评估的候选 98.4% 是正确的。L1 的榜首自 2026-10-27 起保持（仅在 11-07 短暂丢失），公开分数并未下降，是在 11-10 晚公开更多行后重新拿回 L2 和 Quantization 第一。局限也很清楚：搜索完全依赖本地计时，而本地 GPU 的 SM 时钟未锁定、最高约 1965 MHz，读数偏快，需要一套 agent 看不到的校准来修正，这意味着奖励信号与官方计时之间存在系统性偏差；系统依赖 Claude Opus 5.5 这一固定模型，换模型后的表现未知；正确性检查虽然抓到了已知的 hack，但面对足够强的搜索仍可能存在未被发现的漏洞；此外“更多引导没有帮助”这一零结果也说明，靠堆提示和参考资料来提升的方向可能已经走到头。论文的核心结论是：在 kernel 搜索里，额外算力只有在每次新尝试都建立在上一次可靠测量之上时才会兑现，限制规模的是可靠测量的速率而非 agent 数量——这一点对整个 agentic 搜索方向都有直接的指导意义。

### [GLiDE: A Fast, Calibrated Decision Model Distilled from Reasoning Teachers](https://arxiv.org/abs/2611.26509)
`评分3 · 18 pages, 8 figures`

决策模型的核心思路是让模型在单次前向传播中对候选答案打分，直接输出一个带置信度的选择分布，而不必逐 token 生成文本或中间推理链，这在工具选择、请求路由、分类等场景中能带来数量级的速度优势。但这里存在一个根本性张力：多步推理确实能显著提升决策质量，可一旦让模型“想”出来，就引入了决策模型恰恰要避免的串行计算开销。此前的方法要么走纯编码器路线（如 GLiNER2 这类紧凑的 schema 条件编码器），要么走更大的决策系统（如 Jev、Decider、Mammoth），但都没能同时解决三个问题：如何把推理带来的收益蒸馏进单次推理、如何保持置信度校准、如何在不同参数规模上都站住脚。换句话说，现有工作要么快而不准，要么准而不快，要么准且快但置信度不可信——GLiDE 要填的就是这个空档。

GLiDE 的关键设计可以从三个层面拆开看。架构上，它基于 Qwen 混合语言模型，把 16 层全注意力层里的因果掩码直接去掉，让上下文、问题和候选答案之间可以双向交互，同时保留 Gated DeltaNet 层的因果递归和线性复杂度——这意味着模型在编码阶段就能让候选答案“看到”彼此和完整上下文，而不是像自回归模型那样只能从左到右读。候选答案被赋予唯一的单 token 代码，模型在答案前缀位置取最终隐状态，经一个从预训练语言模型头初始化的线性读出层映射到 255 个选项代码的 logits，再限制到当前问题实际提供的 K 个候选上做 softmax，一次前向就得到归一化分布。训练上最核心的洞察是“软目标蒸馏加渐进式后训练”：先用一个 LoRA 微调的推理教师（先学推理轨迹，再学在不出声的情况下直接预测后思考分布），然后把这个教师的后思考概率分布蒸馏进单次推理的学生模型；蒸馏目标的设计很讲究——如果教师在不思考时置信度已经超过 80%，就用直接分布，否则把直接分布和后思考分布做平均，这样后思考监督主要作用在教师本身不确定的样本上，既保留了直接模型的信号，又把推理带来的分布变化传给学生。损失函数里正确项的权重是 0.3，软目标项占大头，目的是让学生不仅学会选对答案，还学会复现教师在推理后的不确定性结构，这正是校准好的来源。此外还有多教师的任务特定对数线性池化、金标签锚定防止教师错误传播、以及参数无关的循环深度（重复施加中间层来增加推理时计算而不生成 token）。

在结果上，GLiDE V1.2（27B）在 Hugging Face Decision Index 0.4.1 版（2026 年 10 月 22 日）的隐藏集上拿到 71.52 分，在 225 个模型中排名第一，领先第二名 1.77 分，预期校准误差只有 2.0%，单张 RTX PRO 6000 GPU 上中位延迟 92.9 毫秒；经过 checkpoint 平均和循环深度进一步处理后达到 73.37 分、ECE 2.1%。五个参数规模（0.4B 到 27B）全部落在该榜单的性能-参数帕累托前沿上，每个模型都优于同尺寸或更小的被评估替代品，并且在 Artificial Analysis Decision Index 的三个版本上均并列第一。这些数字的意义在于：它证明了推理带来的收益可以通过软目标蒸馏被“压扁”进单次前向，而不必在推理时展开思维链，同时校准没有被牺牲——ECE 2% 左右在决策模型里是相当紧的水平。局限方面，论文没有回避的是：整个流程依赖一个先训练出来的推理教师，教师的质量上限决定了学生的上限；多教师池化和金标签锚定的下游收益被作者自己承认“在单种子方差范围内”，说明这套工程的边际贡献需要更严格的消融来确认；隐藏集评估虽然由榜单维护者独立执行、开发者完全看不到题目，但榜单本身的覆盖范围（37 个公开基准、五类任务）仍有限，临床决策等内部回归集也只是补充而非主证据。对方向的影响在于，它给出了一条可复制的路线：用推理教师的后思考分布做软监督、配合非因果注意力架构和读出层改造，就能在保持单次推理效率的同时逼近推理模型的决策质量，这对需要低延迟高可靠决策的落地场景（路由、工具调用、安全分类）有直接的工程参考价值。

### [What If Chain-of-Thought Is Not Enough?](https://arxiv.org/abs/2611.26282)
`评分3`

这篇论文要解决的是一个很实际的问题：大语言模型在做决策支持类任务时，推理过程到底该长什么样。此前的主流做法是Chain-of-Thought（CoT），即让模型把中间推理步骤一步步写出来，后来这类推理轨迹又被用作训练信号，通过rationale-based training和蒸馏让模型把推理行为内化。但CoT的本质是自由形式的顺序推理，它没有强制模型把"决策问题是什么、有哪些备选方案、依据什么标准来比较"这几件事分开表达。对于需要可解释性、权衡透明和可审计决策的场景，这种自由推理很容易变成看似合理实则松散的事后叙述，你很难检查它是否真的按某个一致的标准在比较选项。作者的核心动机就是：与其只诱导推理，不如刻意改变模型被训练去遵循的内部思维模型，用一个更显式面向决策的结构来替代CoT。

这个替代结构就是Question–Option–Criteria（QOC），它把任务分解为决策问题、竞争选项和评价标准三个分离的部分。具体运作方式是：模型先从输入任务中提炼出要回答的具体决策问题，再枚举相关选项，然后提取或构造用于评判这些标准的维度，接着给每个标准分配重要性权重，再对每个选项在每个标准上打一个数值分数，最后把标准权重与选项得分相乘并跨标准求和，得到每个选项的总加权分，总分最高的选项即为推荐答案。这个过程的妙处在于它把定性判断变成了可检查的结构化排序：你可以逐项验证模型是否识别了合理的标准、权重和打分是否正确、乘积与求和是否算对、最终是否真的选了总分最高的那个。作者据此设计了三代训练管线：第一代只训练模型产出QOC结构并仅返回最优选项，作为检验QOC本身能否提升内部决策一致性和排序质量的基线；第二代在QOC结构生成后，把它连同最优选项再喂回同一模型家族，让模型基于结构化结果生成更丰富的自然语言解释，形成"结构化决策形成加解释性渲染"的两阶段行为，训练数据同时保留中间QOC表示和最终文本回答；第三代在QOC阶段进一步加入轻量统计分析，比如对接近最优的选项计算标准差等离散度指标来反映跨标准的稳定性和敏感性，再把这份增强后的思维结构交给模型解释成面向用户的答案，同样把结构化推理轨迹和解释性回答都纳入微调数据。整个训练数据来自合成决策任务，由强开源模型（Qwen3.5-27B）执行固定QOC流程生成推理块，再转换成监督微调样本，其中QOC分析被注入回答的thinking block，基于QOC生成的答案被注入最终回答，从而让目标模型内化QOC作为其思考过程，而不只是模仿孤立输出。

评估集中在第二代微调模型上，沿内部一致性和输出质量两个维度展开，前者衡量模型是否正确执行QOC所需的加权、打分、乘积求和与最优选项选择等计算。论文报告的结果是：基于QOC的微调相对于未微调的基座模型提升了答案质量，而且当模型规模足够大、能够可靠执行底层QOC计算时，增益尤其明显——这其实点出了一个关键局限，即结构化推理的深度并非对所有模型规模都同等有效，小模型可能无法稳定完成这套多步数值流程，反而吃不到收益。此外评估主要围绕第二代展开，第三代统计增强的实际贡献、以及QOC在真实开放任务上相对CoT的系统性优势，仍有待更全面的验证。但这项工作的重要意义在于提出了一个可检验的主张：LLM的内部思维模型是可训练的，结构化的CoT替代方案可以成为通往更可靠、可解释、面向任务适配的决策支持的一条有希望的路径，也为"推理结构本身而非仅推理能力"这一研究方向提供了具体的工程范本。

### [TideCache: Efficient Hybrid LLM Serving with Transparent Cache Management and Layer-Wise Streaming](https://arxiv.org/abs/2611.26619)
`评分3 · 13 pages`

这篇论文要解决的是混合架构大模型在真实服务场景下的显存分配与驻留问题。当前开源权重模型普遍采用“全局注意力层+有界状态层”交替堆叠的结构，全局注意力层的 KV 缓存随上下文长度线性增长，而滑动窗口注意力和 Mamba、Gated DeltaNet 这类循环层的缓存大小与上下文无关，只随并发请求数增长。问题在于，不同业务负载对这两类缓存的压力完全不同：编码智能体累积大量工具输出、文档分析保留长参考资料，会撑爆全局 KV；而高并发聊天或数据标注服务则是有界状态缓存先耗尽。SGLang 的静态分区会给每个组件预留固定预算，结果一边闲置一边告急；Unified Memory Pool 和 vLLM 的 Hybrid KV Cache Manager 虽然做了动态共享，但前者把各层 KV 打包成 page envelope、要求注意力后端做逻辑到物理的索引转换，甚至在该版本下直接拒绝 HiCache 和 LMCache，后者则要求 KV 传输连接器实现 SupportsHMA 来处理分组块列表，本质上都把池内布局暴露给了缓存消费者，集成成本高。另一条路线是卸载：HiCache 把可复用前缀备份到主机内存，但恢复后整个回合都驻留 GPU；HiSparse 只针对稀疏注意力；FlexGen、Pie 这类通用卸载系统又不利用混合模型特有的缓存访问模式。论文的关键观察是，解码阶段主机到设备的链路几乎空闲，而 GB300 单卡读主机内存可达 211 GB/s，这个带宽窗口此前没被利用起来。

TideCache 的核心设计围绕三个组件展开，全部建立在“每个缓存组件保持固定虚拟地址”这一内存布局之上，注意力后端、页表、CUDA graph 和 HiCache 都按原有方式寻址，系统只改变某个地址背后映射的是哪些物理页、以及某一步中哪些主机行被调入。Transparent Cache Pool 用 CUDA 虚拟内存 API 一次性分配 2 MiB 粒度的物理页竞技场，每个子池预留远超实际份额的虚拟地址空间，张量跨整个预留区展开，分配器只用已映射页对应的行，因此扩容就是把竞技场页映射进子池虚拟区间、缩容就是解映射未被活跃请求使用的页，全程不搬移活数据、不改虚拟地址。它的重平衡按每 8 次前向传播一个 epoch 进行，最多一个迁移在途：先规划接收方、数量和捐赠方，把捐赠方空闲行从分配器空闲链表摘下，用 step fence 等此前发出的前向全部完成，再由工作线程调 cuMemUnmap/cuMemMap/cuMemSetAccess，这些驱动调用不等 GPU 且只碰不会有批次使用的内存，所以前向继续跑，各 rank 通过每 epoch 一次 busy flag 的 all-reduce 保证同一步应用同一迁移、构造相同批次。策略是失败驱动的：当头请求因某子池容量不足无法准入时，按空闲页、其他子池闲置容量、超过 τ 秒未触碰的冷前缀依次回收，能不驱逐就不驱逐，需要驱逐时只扩到头请求所需，避免多丢缓存。Cache Streamer 则利用有界状态层提供的计算间隔：Ring-2.6 上两个全局注意力层之间隔着 7 个有界状态层，这段时间里下一层的全局 KV 前缀还不需要，于是提前把主机驻留的前缀预取进所有全局注意力层共享的 GPU 槽位，上一层用完即弃，新生成的 KV 仍留在 GPU。这样流式请求只需为少数几层而非全部全局层准备显存，释放出的 HBM 又能装下更多请求的窗口缓存和循环状态，更大的解码批次反过来提供更多计算来掩盖后续传输，形成正循环。Request Scheduler 则根据请求大小和队列状态，决定队首请求走驻留还是流式执行，若都不行就告诉 TCP 是哪个组件卡住、在两个前向之间扩容。

在 GB300 和 GH200 上、七个模型/平台配置、Chat 与 Coding Agent 混合流量下，TideCache 相比带 HiCache 的 SGLang 最多完成 2.04 倍的 agent 轮次，整体 P50 每 token 延迟降低 20–59%，agent 的 P50 首 token 时间提升 1.40–3.05 倍；Transparent Cache Pool 在固定负载下能达到两个手工调优分区中较优者的 96.3–113.6% 轮次，而在 GH200 上负载漂移时，完整系统比 HiCache 多完成 59% 的 agent 轮次、agent P50 TTFT 降低 78%；等批量下解码步延迟最多只增加 6.3%。局限也很明确：收益依赖有界状态层提供的足够长的计算间隔来掩盖传输，间隔不够时层间预取就藏不住；迁移以 8 步为 epoch 且最多一个在途，负载剧烈抖动时重平衡有滞后；冷前缀驱逐阈值 τ 和扩容上限 k 都是启发式参数，缺少自适应调节；评测集中在七种混合架构配置，对纯全局注意力模型或层间结构差异很大的模型是否同样有效尚未验证。尽管如此，它把“利用解码期空闲的主机链路带宽做逐层流式”和“用固定虚拟地址做透明物理页重分配”这两件事拼在一起，在不改注意力内核和缓存接口的前提下同时解决了容量错配和驻留浪费，为混合模型服务系统提供了一个可叠加在现有 radix cache 与 HiCache 之上的内存管理层思路。

### [The Geometry of Lies: Knowledge and Persona Directions for Detecting Deception in Large Language Models](https://arxiv.org/abs/2611.26545)
`评分3`

这篇论文要解决的是大语言模型谎言检测中一个非常具体且棘手的泛化难题。当前最廉价的谎言检测器是线性探针——在残差流上做一次点积，不需要额外前向传播，甚至能捕捉到对话记录里不留痕迹的谎言。但探针的根本弱点在于跨分布泛化：在一个谎言数据集上训练的探针，换到另一种谎言上往往就失效了。Liars' Bench 把这个失败暴露得很彻底：它包含七个数据集、七万多条四个开源模型自己生成的策略内谎言，而在大多数数据集上，用指令对训练的探针在平衡准确率上接近随机水平。最难的是 HP-KR 数据集——模型被问到一个它明明知道答案的危险问题，却否认自己知道。在这个数据集上，Llama-3.3-70B-Instruct 第 20 层的 Mean Probe 的 AUROC 只有 0.12，比随机还差；即便在中间层训练出的探针能排好序，在只标记 1% 诚实回答的严格阈值下也一个谎言都抓不到。之前 Mahadik 和 Skapars 提出用“人格坐标”来补救：让模型分别扮演欺骗性和诚实性人格，两组平均激活之差构成一个方向，这个方向不使用任何评估数据，因此不会被某个数据集的特性拟合。但这个方法只在 3B 和 8B 的 Llama 上验证过，作者自己把更大模型和更丰富的人格集列为未来工作。本文把这两件事都做了，结果发现重建到 70B 上后，原版对比方向在 HP-KR 上直接反转了——AUROC 只有 0.148，把诚实回答排在了谎言上面。原因很清楚：HP-KR 里几乎所有的谎言（Llama 上 139 条中的 125 条）都是“否认自己知道”，而原版人格集里所有欺骗性人格的撒谎方式都是“控制信息披露”，两者在行为形态上根本不对应。

针对这个问题，作者的核心洞察是把“谎言”拆成两条正交的线索来分别建模。第一条线索是人格方向，但他们扩充了人格库：在原有 26 个角色的基础上新增 10 个与“知道/否认”相关的角色——4 个“知道答案却声称不知道”的知识否认型角色、3 个“真不知道并如实说不知道”的真诚无知型角色、3 个“知道就直说”的直述型角色，每个角色配 5 种系统提示变体、回答同样的 30 个问题，再用 Llama-3.1-70B 作为裁判给每个 rollout 打 0 到 3 分的入戏程度，只保留满分 3 的样本（5250 条中保留 3599 条）。由此构造出“知识否认对比”（4 个否认角色对 6 个诚实角色）以及把它和原版合并的“扩展对比”。但作者很快发现一个关键问题：这个扩展对比在 HP-KR 上排名变好，靠的其实是“否认”这个词的措辞——只用新角色构造的对比几乎把所有说“我不知道”的回答都标成谎言，不管这个否认是真是假；在谎言和诚实否认是同一句话的那些样本上，所有人格方向的得分都落在随机方向能达到的范围内。也就是说，人格方向主要追踪的是回答的措辞，而不是模型是否真的知道答案。于是作者设计了第二条线索：知识方向。他们让 Claude Opus 写了 60 个 70B 模型确定知道答案的问题和 60 个没人可能知道答案的问题（真实地点的私密未记录细节），把每个问题套进 HP-KR 自己的知识报告模板，然后由人替模型写好强制回复——每个问题后面都跟同一句否认，分别用“I do not know the answer.”和“I don't know the answer to the question.”两种写法，共 240 次读取。知识方向就是“知道”组的平均读取减去“不可能知道”组的平均读取，因为两边收到完全相同的回复，回复的措辞无法区分两组，唯一能区分的就是模型内部是否掌握答案。这个方向的符号在评估前就固定了：知道的那一侧就是谎言侧。最终的选择检测器把扩展对比和知识方向各自除以在无谎言的 Alpaca 控制集上的标准差，以预先固定的等权重相加。作者还构造了一个“措辞方向”（强制否认减强制陈述）来测量检测器对否认措辞的敏感度，并可以把检测器中沿这个方向的分量去掉作为对照。

结果呈现出明显的混合图景，作者对此的交代相当坦诚。扩展对比是真正能泛化的部分：在每个模型的中间层，它在基准四个模型中的三个上比单数据集训练的探针迁移得更好；在主模型 Llama-3.3-70B 上它也胜过从随机人格库抽出的对比，但相比原版对比的提升幅度落在随机扩充所能达到的范围内——也就是说，扩充本身带来的增益并不能明确归因于新角色的语义针对性。它在 Qwen 上失败，即便换用 Qwen 入戏程度高得多的人格库也不行。知识方向在两个模型上能把谎言和措辞完全相同的诚实否认分开，在第三个模型上勉强可以，在第四个上不行；在受控措辞的切片之外，它的迁移部分依赖于 HP-KR 模板的措辞。在 Gender-Secret 微调模型上，它在 Llama 上以几个百分点的优势超出随机带，在 Mistral 上则没有。两个方向相加的选择检测器在四个模型上平均 AUROC 都高于同深度的监督探针（Qwen 上两者都接近随机），但在主模型的基准平均上它与扩展对比持平，在一个外部竞赛中只能排到 30 支队伍的第 16 名，落后于监督探针。最关键的局限是：在只标记每个数据集 1% 诚实回答的严格阈值下，他们评估的六个检测器在任何模型上都抓不到一半的谎言（最高只有 0.47）。论文的意义在于它没有宣称解决了问题，而是给出了一套诚实的诊断框架——随机带、预注册的随机人格库零假设、措辞受控切片、用基座模型在微调模型转录上的激活作为对照、配对区间——以及一个明确的负面结论：人格方向在涉及知识的谎言上主要响应措辞而非知识状态，而知识方向虽然有独立信号，但其有效性高度依赖模板措辞，且距离实际可用的严格阈值检测还有相当大的距离。

## AI + 生物

### [From Sequence Uncertainty to Phenotype Hypotheses: Uncertainty-Conditioned Inference over Biomedical Knowledge Graphs](https://arxiv.org/abs/2611.25422)
`评分3`

这篇论文要解决的是基因组解读链条上一个长期被忽视的接口问题：上游的序列模型能给出某个变异致病的点预测，下游的知识图谱也能提供基因到疾病、表型的多条证据路径，但两者之间缺少一个显式的概率接口，把“这条证据有多可靠”转化为“应该给哪些表型假设分配多少概率”。已有的工作各自只覆盖一段——基因-表型语言模型直接答题、图推理器检索可解释路径、知识图谱嵌入给三元组打分——但没有任何方法把序列预测的校准不确定度当作推理的输入条件。问题在于，点预测本身不携带分配信息：一个高置信的致病变异应当把概率集中到少数几个有图支持的假设上，而一个模棱两可的变异则应当把概率摊开，这种“证据质量决定假设宽度”的行为无法从单纯的分类器或单纯的图检索中涌现出来。更麻烦的是，如果直接用图上的能量模型做softmax，温度是个固定超参，它控制的是分布的集中度，却与查询本身的不确定度无关，导致同一个温度下所有变异无论证据强弱都得到同等锐度的假设分布，这在临床解读上是不合理的。

方法的核心是把温度变成查询不确定度的函数，从而把上游证据质量注入到图上的概率分配中。具体来说，给定一个查询基因、序列模型给出的致病概率p和校准后的不确定度H，模型在候选路径集合上定义一个可解释的线性能量：每条路径用14维特征描述，包括关系频率、路径长度、基因边类型、疾病覆盖、端点特异性、路由基因的机制注释，以及与p和1−H的交互项，能量就是这些标准化特征的加权和。关键设计是目标分布取softmax形式，但温度θ(H)随H单调递增——不确定度越高，温度越高，分布越平。论文证明了一个单调性命题：固定能量下，softmax分布的香农熵对温度的导数等于能量的方差除以温度三次方，恒为非负，所以任何非减的θ(H)都保证路径级熵随不确定度非减。路径概率按终点表型聚合后得到表型假设分布，这个分布表达的是模型在图支持的解释之间的相对支持度，而不是临床患病概率。为了验证采样实现，作者构造了一个带Hastings修正的Metropolis独立性提议：提议分布是90%的softmax(U/2θ)加10%的均匀分布以保证全支撑，接受率用标准的MH比，从而保证该马尔可夫链的平稳分布恰好是目标π_H。这里有个容易被忽略的技术点：如果只用未修正的Metropolis接受率配独立性提议，平稳质量会正比于π_H(i)q_H(i)而非π_H(i)，提议分布会额外锐化分布、部分抵消掉不确定度条件化的效果，Hastings修正正是为了消除这个提议诱导的畸变。由于候选路径集合可枚举，目标分布可以精确计算，链条实验的作用是验证采样保真度而非替代精确采样。

实验在AlzKB和Hetionet两个图上展开。表型级熵与上游不确定度的Spearman相关分别达到0.951和0.878，说明不确定度条件化确实在表型聚合后仍然传导。在掩蔽边恢复任务中，模型超过随机和度匹配的概率置换控制；在基因留出设定下，recall@10在30个图掩码中的24个上超过训练过的DistMult嵌入（0.183对0.123），但作者诚实地指出这一优势主要来自三个变异数很多的基因，并非对所有基因都成立。训练策略上，在不确定度依赖的温度下训练能量，比在同等量级的常数温度下训练取得更高的留出recall@10，提升约0.04–0.06，消融实验确认了不确定度条件化项的独立贡献。局限也很明确：候选支持集随基因跳数大约每增加一跳扩大百倍，当前的全枚举加独立性提议只适用于小支撑，论文自己指出在大支撑情形下需要用局部或摊销提议替代；基因留出的优势范围有限，不能推广为普遍结论；此外整个框架依赖上游序列模型提供校准良好的p和H，若校准漂移，条件化的意义会被削弱。尽管如此，这篇工作确立了一个可审计的接口范式：把证据质量作为假设宽度的显式决定因素，同时保留多路径可追溯性，并用精确归一化作为采样正确性的参照系，这对从基因组预测走向结构化表型推断的方向提供了一个有原则的起点。

### [Generation of protein conformations using a simple inverted transformer](https://arxiv.org/abs/2611.19321)
`评分3`

蛋白质构象景观的完整刻画长期依赖全原子分子动力学模拟，但即便硬件与采样算法持续进步，要充分遍历一个蛋白的可及构象空间仍然代价高昂。实验手段如X射线晶体学、NMR和冷冻电镜虽能提供部分构象信息，却难以给出各构象的热力学权重与时间尺度。近年来深度学习在静态结构预测上的成功催生了生成式分子动力学（GenMD）这一方向，从语言模型、Boltzmann生成器到扩散模型均有尝试，基于Transformer的架构也被用于学习蛋白结构表示并生成构象集合。然而现有方法存在一个被普遍忽视却极为关键的问题：神经网络的原始输出并不是干净的蛋白结构，通常需要额外的下游算法（如从距离图重建坐标）才能得到物理上合理的构象。这说明经典Transformer架构并不擅长自主地、按时间顺序地预测构象演化。此外已有工作指出，经典Transformer在时间序列预测任务上的能力被高估，即便极其复杂的架构也未必优于简单的线性层。本文正是针对这一瓶颈，提出一种经过改造的inverted Transformer变体，使其能够直接输出有序的、物理合理的粗粒化蛋白构象序列，而无需任何后处理模块。

该方法的核心洞察来自inverted Transformer（iTransformer）的设计哲学：经典Transformer在多元时间序列预测中把同一时间步的所有变量打包成一个token，导致注意力机制捕捉的是时间维度的依赖；而iTransformer反其道而行，将每个结构变量（此处即每个Cα原子的三维坐标，共3N个自由度）视为独立token，注意力在变量维度上计算。具体而言，输入是一个滑动窗口内的归一化坐标矩阵，形状为回看长度乘以变量数，首先经过置换层交换时间轴与变量轴，再经稠密嵌入投影到128维隐空间。核心的iTransformerBlock中，多头自注意力（8个头）在变量之间计算相关性，得到的注意力矩阵维度为变量数乘变量数，其权重直接反映了不同残基之间的动态耦合——既包含共价键的短程约束，也包含折叠所固有的长程非键相互作用，因此这个注意力图具有可解释性，能看出某个残基的运动如何被结构其余部分所调制。前馈网络采用GELU激活、隐维度512，配合层归一化。关键在于输出端：模型不做逐步自回归解码，而是用一个线性时间投影层将每个原子的隐表示直接映射到未来F帧的轨迹段（F可取10到100），再反置换回“帧×变量”的形状。这种直接多步投影显著减少了逐步预测的累积误差。训练策略上有三个要点：其一是自定义的RMSF加权混合损失，在标准逐点均方误差之外加入一个沿预测时域计算的结构涨落惩罚项，防止网络在长时程预测中把物理涨落抹平——这是纯MSE优化常见的退化模式，超参数α平衡坐标精度与涨落保真度；其二是课程学习，预测时域从10步逐步增加到50步以上，每个阶段用前一阶段的权重热启动，配合AdamW优化器和余弦退火学习率调度，保证从短期动力学平稳过渡到长程 rollout；其三是dropout的精细调节（0.1到0.3），迫使网络忽略随机噪声、聚焦可泛化的特征。整个系统在E. coli二氢叶酸还原酶（DHFR）上训练，数据来自CHARMM36m力场下的全原子MD，包括载脂蛋白以及结合NADP、结合NADP与叶酸三种体系，每种30条独立100 ns轨迹，经QCP对齐消除整体转动和平动后提取Cα坐标作为训练目标。

在结果层面，该网络生成的构象序列在统计分布上与MD模拟及实验数据高度相似，更重要的是，按输出顺序排列的构象会快速收敛到构象景观中被占据最多的区域，这暗示网络不仅学到了蛋白的三维组织方式，还隐式地学到了各可行构象的热力学权重——这是GenMD领域此前难以企及的目标。与依赖下游重建算法的经典Transformer方案相比，iT的最大优势在于直接产出物理合理的构象，Cα-Cα键距等几何约束在生成过程中自然满足，无需额外校正。注意力矩阵的可视化进一步提供了残基间动态耦合的直观图谱，可作为分析工具使用。当然，局限也很明显：目前仅在DHFR这一个蛋白上做了验证，且使用的是粗粒化Cα表示，侧链构象和配体诱导的精细变化未被建模；训练数据来自单一力场的MD，存在系统性偏差的风险；预测时域虽经课程学习扩展到50步以上，但与真实生物过程的毫秒级时间尺度仍有巨大鸿沟，长时程外推的可靠性尚未系统评估。尽管如此，这项工作指出了一个有价值的方向：通过重新设计注意力作用的维度，让Transformer在构象生成任务上摆脱对后处理管线的依赖，以极低的计算成本扩展可及构象的数量，为未来构建不依赖MD本身、能够预测蛋白动力学的AI系统提供了一个简洁而有力的基线。

### [STORM: A Lightweight Structure-Free Model for Binding Affinity Prediction](https://arxiv.org/abs/2611.23777)
`评分3 · 9 pages, 3 figures`

这篇论文要解决的是药物发现早期阶段的一个核心瓶颈：如何快速、准确地预测小分子与靶蛋白的结合亲和力。传统上，物理模拟方法如自由能扰动（FEP）虽然预测精度高、与实验相关性好，但代价极大——每次预测需要数小时GPU时间，还依赖专家精心搭建模拟体系和高质量蛋白结构，根本无法支撑动辄数十亿化合物的虚拟筛选库。近年来以Boltz-2为代表的共折叠（cofolding）模型将AlphaFold3式的结构预测主干扩展到亲和力预测，精度据称接近FEP而成本大幅降低，已被广泛采用。但问题在于，这类模型训练时需要海量结构数据和多序列比对（MSA）数据，推理时也要跑完整的结构预测流程，对大规模筛选而言仍然昂贵；更麻烦的是，当新的实验亲和力数据积累起来、需要重新拟合或微调模型时，共折叠模型因为依赖多种数据模态和庞大参数量而难以快速更新。作者由此提出一个关键疑问：共折叠模型用于训练的结构和MSA数据，主要服务于结构预测能力，它们对亲和力预测到底贡献了多少？如果只用一个忽略三维结构、仅从实验亲和力数据中学习"相似分子倾向于有相似亲和力"这一化学趋势的简单模型，是否也能达到相近的精度？此前已有研究表明，亲和力数据中的化学趋势可以在序列一致性较低的蛋白靶点之间迁移，这提示了一条绕开结构和MSA复杂性的替代路径。

STORM的核心设计正是围绕这一洞察展开的：它完全抛弃三维结构和蛋白语言模型嵌入，转而构建一个由15个独立训练的小型多层感知机组成的集成模型，每个成员使用不同的蛋白和配体表示组合，平均参数量仅约120万，总计约2000万参数。配体侧使用九种不同的分子表示，包括各类化学描述符和多种分子指纹算法（如RDKit和scikit-fingerprints计算的特征），利用不同表示能捕捉不同活性关系、提供互补信号这一事实；蛋白侧则使用五种输入配置，全部来自UniProtKB的GO和InterPro注释、一个确定性的64维ID128 accession编码以及物种指示符，对未见过的accession还可以借用MMseqs2训练命中项的ID128编码，另有部分成员是完全"靶点盲"的，只接收配体和实验端点输入。每个成员采用简单的早期融合架构：将蛋白表示投影后与分子表示拼接，送入共享的MLP预测头，实验端点类型（Ki、Kd、IC50、EC50等）编码为四维向量投影进第一隐藏层。训练目标函数是逐点Huber损失与同实验内配对活性差损失的组合——后者对同一assay中采样的分子对，用该assay活性标准差（下限截断为0.5）归一化预测差值和实测差值，既学习绝对活性值，又直接训练模型捕捉同实验内分子间的相对排序，这对亲和力预测的排序质量至关重要。推理阶段还有一个可选的图平滑步骤：对一组共同打分的化合物，用Klekota-Roth计数指纹的Tanimoto相似度构建近邻图，做三轮Taubin平滑，使相似分子的预测互相校正，但该步骤会引入组内依赖性并可能削弱活性悬崖的区分度。此外，STORM支持在新测亲和力数据上对每个成员独立微调，只需逐点Huber损失加一个防止权重偏离初始点的惩罚项，这使得模型能随实验数据积累快速更新，而无需像共折叠模型那样重新处理多模态大数据。

在实验结果上，作者用ChEMBL 34和BindingDB（2024年4月快照）清洗后得到的约170万条唯一实验亲和力测量、6775个蛋白ID和93.4万个小分子训练STORM及所有无结构基线，并在四个基准上评估：在ChEMBL35时间切分上STORM的Pearson相关性高于Boltz-2，在OpenFE、FEP+4和CASP16上与Boltz-2相当，同时比五个重新训练的无结构基线方法都高。最引人注目的是效率：推理和训练速度比Boltz-2快五个数量级以上，这使得大规模虚拟筛选和频繁模型更新在计算上变得可行。消融实验量化了集成中各组件对性能的贡献，微调实验则显示对训练集中未出现的三个靶点，用少量亲和力测量微调后留出化合物的Pearson相关性均有提升。局限方面，作者坦承STORM的训练数据源是Boltz-2所用数据的子集（缺少PubChem高通量筛选、CeMM片段筛选、MIDAS代谢物数据和合成诱饵等数百万额外样本），且Boltz-2的确切训练记录未公开，无法做严格的数据重叠核对；图平滑会引入查询组依赖并可能抹平活性悬崖；模型完全忽略三维构象和口袋信息，理论上限受限于此。但论文的意义在于指出了另一条路线：无结构模型与共折叠模型捕捉的信号可能是互补的，将历史实验亲和力数据与结构和生物物理信息结合，有望进一步提升预测精度，这对整个基于机器学习的亲和力预测方向具有长远的启示价值。
