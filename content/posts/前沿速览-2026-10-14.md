## 大模型 LLM

### [Agent-Reflex: Teaching Language Agents to Act Reflectively](https://arxiv.org/abs/2610.17953)
`评分4 · HF 192赞 · 有代码`

这篇论文要解决的是语言智能体在真实部署中“不会反思、不会从失败中恢复”的问题。现有智能体训练范式大多假设环境稳定、工具返回干净、用户几乎不干预，但现实里 MCP 工具服务经常超时、报错、返回格式错乱，用户也会在智能体跑偏时中途纠正。之前的方法大致分两类：一类是推理时反思，比如 Reflexion、Self-Refine，靠模型自己生成一段自我批评再重试，但批评信号来自已经失败的策略本身，如果工具返回了一个格式正确但内容错误的假结果，模型很难自我矛盾；另一类是训练时反思，比如 Agent-R、ReflectRL，用一条轨迹内的修复信号做监督，或者像 NoisyAgent 那样只给标量回报让策略在扰动环境里硬扛。这些方法要么信号太稀疏、要么只停留在单条轨迹内，没有把“某个环境下反复出现的失败模式”沉淀成可复用的环境级知识，所以智能体换一个任务、换一个环境，还是不会主动反思。

Agent-Reflex 的核心洞察是把“反思”当成一种可学习的元技能，并且从真实工具失败中反向挖掘这种技能。整个框架分三段。第一段叫环境反思技能发现，先选 557 个真实 MCP 服务器主题，自动构建带数据库、可执行工具和验证器的环境，然后从九个公开智能体基准里回放收集了 17.7 万条工具返回，其中 2.45 万条是错误返回，归成八类失败模式，再按工具类型概率性注入到工具返回里，模拟真实噪声。接着用一个覆盖五大家族、从 4B 到 284B 的九模型池在噪声环境里采样，对同一任务同时拿到成功轨迹和失败轨迹，由分析模型和验证器联合标注出首个错误轮次、错误原因和环境状态快照，再把成功与失败配对，挖掘出 1170 条环境索引的反思元技能，每条技能本质上是一条“坏模式到纠正动作”的恢复规则。第二段叫反思监督微调，把每条技能转成三种可验证的监督数据：自我反思采样把环境恢复到首个错误轮次之前，把技能作为特权提示让模型继续生成，但存储时去掉提示，逼模型学会从自己的错误状态里恢复；技能恢复采样把环境重置到初始状态，带着技能重新跑整条任务，教全局重规划；用户中心反思采样则用用户模拟器把技能转成自然语言纠正，插在错误轮次之后，因为用户消息在部署时可见，所以保留在输入里。这三类数据加上目标策略自己生成的正确轨迹一起做监督微调，把显式反思技能内化到策略里。第三段叫在策略反思策略优化，在噪声环境里做智能体强化学习，同时引入反思引导的在策略蒸馏：对同一批动作 token，分别在普通上下文和带特权技能上下文的条件下重新打分，用置信度加权的蒸馏目标把两种打分差异变成 token 级的密集监督，专门教模型在哪些决策点上应该触发反思。这样一来，反思不再依赖推理时临时生成，而是被写进了策略参数里，并且有环境级的技能库做支撑。

实验结果上，基于 Qwen3-8B 的 Agent-Reflex 在五个长程工具使用基准上拿到 58.6 的总体成绩，在 AgentNoiseBench 上拿到 29.1，超过了强环境扩展基线和反思基线；在六个挑战性智能体基准套件上的实验也验证了有效性。进一步分析显示，它提升了智能体对噪声的鲁棒性，同时训练动态保持稳定，说明这种“从失败中挖技能、再分阶段内化”的路线是可扩展的。局限也很明显：技能库依赖 557 个预选环境主题和九模型池的采样覆盖，如果真实部署遇到完全没见过的工具生态或失败模式，元技能的迁移能力还没有被充分验证；另外 ORPO 里的特权技能上下文在训练时可用，但推理时没有这个特权信息，模型必须完全靠自身策略触发反思，这对策略的校准要求很高。不过这篇工作指出了一个重要方向：智能体训练不该只堆环境数量，而要把环境里的失败变成结构化的监督信号，让反思从“事后补救”变成“可学习、可复用、可内化的元能力”，这对构建真正能在噪声和干预中稳定运行的长程智能体有直接推动作用。

### [Harness^2: Recursive Agent Harnessing for an Open World](https://arxiv.org/abs/2610.14224)
`评分4 · HF 77赞`

在开放世界中部署LLM智能体时，其能力不仅取决于底层模型，更取决于执行框架（harness）——即提示词、记忆、技能、工具和编排方式。递归自我改进（RSI）提供了一条自动演化框架的路径，但面临两个关键挑战。第一，开放世界任务在框架设计阶段通常未见，测试时又是全新的，没有真实标注的验证器来可靠指导在线框架编辑。现有方法依赖代理信号、假设的正确答案或成对输出判断，但如何安全地利用不完美的执行证据来指导框架变更仍然困难。第二，RSI过程高度任务特定，难以泛化到新场景。针对单个任务的改进在需求变化时往往失效，而直接继承高度定制的执行框架会因任务分布偏移导致噪声化的递归改进。然而，改进过程本身产生了高度可复用的经验：如何诊断弱点、测试哪些变更、执行结果揭示了什么。因此，改进过程本身必须成为学习来源，使系统能够递归升级自身的改进机制。核心问题由此提出：递归自我改进能否同时改进当前框架以及未来框架的改进方式？

Harness²通过两个耦合的递归层级实现这一目标。任务级递归精炼当前任务的执行框架，其核心是一个对比式的“提议-探测-组合”步骤。首先，管道获取当前框架在任务上的参考执行记录，揭示框架行为而非正确性。然后提议两个候选框架：一个针对跨领域复现的智能体缺陷（如规划、工具使用、上下文管理），另一个针对当前领域的知识、流程和约束。每个候选框架在匹配的模型和环境配置下执行同一任务，通过与参考执行的行为对比来判断编辑是否缓解了目标缺陷、未改变相关行为或引入了退化。组合步骤选择性地合并有支持的变更、修正冲突编辑、采纳某个候选或保留当前框架，每个决策都绑定具体观察而非假设的分数增益。在此基础上，并行递归同时探索多个候选并组合其执行证据，顺序递归则迭代构建连续修订。框架级递归则利用这些任务级探索来更新持续改进框架，不是继承先前的执行框架，而是选择性保留可复用组件以及关于何时、为何有效的经验，指导未来的提议和组合。

在WorkBuddy-Bench、JobBench和Harvey法律智能体基准上，跨四种执行器-框架配置，单次对比步骤在所有配置下均提升了GLM-5和Gemini 3.5 Flash的性能，WorkBuddy-Bench最高提升11.5分，JobBench提升4.5分，LAB部分通过率提升11.8个百分点。并行递归在WorkBuddy-Bench上额外增加3.9分，JobBench增加4.2分，LAB部分通过率增加6.7个百分点。预算研究表明并行和顺序递归均带来增益，且任务级探索也惠及后续框架改进：更大递归预算积累的库支持更强的后续框架编辑，即使没有额外探测；从JobBench迁移的库也能提升WorkBuddy-Bench的性能。局限在于，选择器返回的是“被采纳”而非“已验证最优”的框架，执行随机性和共享模型偏差限制了证据可靠性，且当前实现仅执行一次种群更新，并行递归控制宽度而非深度。尽管如此，该工作将模型-框架视角从执行任务的智能体扩展到同时学习如何改进自身框架的智能体，为开放世界中的递归自我改进提供了可插拔的实用路径。

### [DoSA: Dots Sparse Attention](https://arxiv.org/abs/2610.13990)
`评分4 · HF 65赞`

这篇论文要解决的是稀疏注意力里一个被长期忽视却越来越致命的瓶颈：选 token 本身太贵。以 DeepSeek Sparse Attention 为代表的方法虽然只让注意力访问少量 key，但为了找出这些 key，必须先跑一个多头 indexer，对每个 query 和每个 key 的每个 head 做点积、ReLU 激活再加权求和，最后做 Top-K。也就是说，稀疏注意力省下的是后续的注意力计算，却没省下"决定去哪看"这一步。论文给出的实测很能说明问题：在约一百万 token 的上下文下，indexer 在 GLM-5.2 的 prefill 中占了 73.0% 的 GPU 时间，在 DeepSeek-V3.2 中更是高达 90.8%，而它占的逻辑矩阵 FLOPs 分别只有 47.4% 和 83.2%——时间占比明显高于算力占比，说明除了算分，写回和选择带来的内存流量同样是负担。已有的加速方案各有局限：GVR 利用解码阶段的时间相关性，DeepSelect 用有界缓冲流式处理已算出的分数，LiteTopK 把打分和候选过滤融合以避免稠密写回，但它们都仍要求对每个 key 评估全部 head；MISA 尝试用少量 head 先筛再用完整 indexer 重排，可重排无法把已经被错误排除的赢家救回来。核心问题于是变成：能不能在不计算完整分数的情况下，严格证明某些 key 不可能进入 Top-K，从而安全地跳过它们？

DoSA 的关键洞察是：Top-K 选择并不需要每个候选的完整分数，只需要足够证据去否决它。具体做法是构造一个分数上界，再和一个真实 Top-K 阈值的下界比较，凡是上界低于下界的 key 就被认证淘汰。阈值下界来自一个"种子集"——至少 K 个可见 key 的完整分数，取其中第 K 大的分数，它必然不高于真实阈值。难点在于如何以远低于完整打分的代价构造紧的上界。对于带符号权重的 ReLU indexer，直接丢掉正权 head 是不安全的，丢掉负权 head 虽然安全但界会很松。DoSA 因此把 head 分成保留集和省略集：保留一部分 head 直接精确计算，对省略的正权 head 采用非负投影加联合残差界——为每个省略 head 选一个已保留的锚 head，把它的 query 向量投影到锚方向上，投影部分复用已经算过的点积，残差部分则利用多个省略 head 共享同一个 key 这一事实，用联合几何界替代逐个界，从而在不增加 key 读取的前提下收紧上界。对省略的负权 head，由于它们是从分数里减去的，需要构造一个"最多减多少"的下界，DoSA 用种子 key 上的激活频率做多数投票，选出激活一致的 head 子集做聚合，避免把不激活的 head 混进来抵消掉活跃 head 的正贡献，导致界变松。这些 query 侧的量在所有 key 上复用，最终形成完整的分数证书。落到 GPU 上，整个流程分四步：先复用筛选行做稠密 Tensor Core 计算，形成上界并丢弃低于阈值的 key；把幸存者压缩成紧凑 ID；只对这些幸存者做全 head 精确打分；最后只写回分数不低于阈值的记录，并用原始分数解决边界并列。这样同时省下了计算、写回和选择三方面的开销，而且由于淘汰是严格认证的、最终分数始终用原始值，整个方法是无损的，Top-K 结果与全量计算完全一致。

实验结果相当扎实。在英文、中文、代码三类负载、共 60 个微基准配置中，DoSA 全部最快：完整 indexer 相比 SGLang 最高加速 2.74 倍，相比 LiteTopK 最高 1.69 倍；在 1M token 时对两者的加速分别为 2.47–2.74 倍和 1.47–1.69 倍。端到端在 GLM-5.2 和 DeepSeek-V3.2 上，TTFT 相比 SGLang 分别最高加速 1.86 倍和 1.94 倍，几乎把首 token 延迟砍半。分析显示增益主要随上下文长度增长而非 query chunk 大小，说明 DoSA 真正省的是沿长 key 维度的工作量，这也解释了为什么它比只做融合的 LiteTopK 越到长上下文越领先。逐层看，21 层中有 20 层的剪枝率超过 95%，三个领域的平均剪枝率在 97.2%–97.5% 之间，且都呈现第一层剪枝率最低、其余层更高的深度相关模式，说明分数几何比输入领域影响更大。局限方面，论文的证书依赖种子集质量和激活频率估计，种子差或激活模式与种子不一致时界会变松；解码阶段因为每步 query 少、key 复用有限，加速只有 1.06–1.26 倍，明显弱于 prefill。此外方法是为 DSA 这类带符号 ReLU indexer 量身定制的，能否推广到其他打分结构还需验证。但总体而言，它把"稀疏注意力内部仍有稠密打分瓶颈"这个问题正式提出来并给出了无损解法，为注意力层面的条件计算打开了一条与 MoE 思路平行的路径，对长上下文推理系统的意义可能不亚于稀疏注意力本身。

### [Hybrid Reasoning Agents](https://arxiv.org/abs/2610.18861)
`评分4 · 45 pages, 12 figures · 有代码`

现代 LLM 智能体有一个根本性的割裂：它们既能调用工具、观察环境反馈、多轮迭代地解决复杂问题，但所有中间推理都必须以文本形式逐 token 生成，这既昂贵又低效；而另一条 latent reasoning 路线虽然能在连续隐空间里直接展开计算、跳过解码和verbalization的开销，却把自己封死在模型边界内——连续隐向量没有原生的工具调用接口，也无法暴露人类可读的语义，导致训练时难以监督、推理时难以审计。两条路线各用一种介质，一个负责"行动"却推理笨重，一个负责"思考"却无法行动，始终没能合流。这篇论文要解决的就是这个分裂：能不能造一个智能体，让它"超越文本地思考，却仍然通过文本行动"？

核心设计叫 HybridAgent，关键模块是 HybridLink——一个轻量残差适配器，把最后一层隐状态从 hidden space 映射回 input embedding space。为什么需要它？因为直接把隐状态 h_t 当作下一步输入会与预训练好的输入空间产生表示错配，文本 token 和连续隐向量之间的切换会变得极不稳定。HybridLink 用两个线性投影加激活函数模拟下一步的输入嵌入，由于残差连接保留了 h_t 的原始语义，它只需对齐分布差异而非从零学整个投影，因此参数量极小（4B 模型上约 10M）。生成时，智能体在文本模式下正常采样 token，一旦吐出特殊锚点 \<latent\> 就切入隐模式，此后每步的隐状态经 HybridLink 直接作为下一步输入，在连续空间里做序列级递归，直到隐状态语义与退出锚点 \</latent\> 对齐才切回文本。这个切换是动态涌现的，长度和频率都不预设。多轮场景下，文本、隐向量、工具观测三类内容通过嵌入层或 HybridLink 映射到同一输入空间，Transformer 统一处理并累积 KV 条目，这些 KV 条目构成连续工作记忆，跨轮无损保留完整混合上下文，无需中间 token 空间重建。训练分两阶段：HybridSFT 先用标准文本 SFT 教模型何时进出隐模式，再冻结主干训练 HybridLink 对齐隐位置与目标嵌入，然后用两遍自条件训练消除训练-推理错配——第一遍教师强制生成隐输入，第二遍用模型自己产出的隐输入替换真值，联合监督文本和隐位置；HybridRL 则解决了一个理论障碍：标准 PPO/GRPO 需要每个位置的 token 级似然，但隐位置生成的是连续向量，重要性比率无定义。论文提出 hybrid policy factorization，证明在固定 HybridLink 下策略只需在采样的文本位置上做似然比更新，隐位置和工具响应不参与策略采样，从而让 RL 在混合轨迹上合法运行。

在 11 个覆盖数学、科学、医学、搜索和智能体推理的基准上，用 Qwen3-Base 的 4B、8B、14B 三个规模实例化，HybridAgent 相比前沿 LLM 智能体和涵盖文本与隐方法的智能体框架平均提升 10.4%，同时 token 用量减少 35.5%–54.7%，推理速度提升 1.8–2.6 倍，成本降低 2.7–3.7 倍。更值得注意的是它展现出清晰的模式分工：内部推理大量转移到语义丰富且可解释的隐思维中，而文本被保留给外部检查和工具交互——隐模式甚至能通过最近邻 token 嵌入映射回人类可读的伪文本，使隐推理不再是不透明的黑箱。局限方面，HybridLink 的轻量性意味着它依赖主干隐状态本身已编码足够语义，若主干能力不足或任务需要极长隐推理链，对齐质量可能下降；隐模式的退出条件依赖与 \</latent\> 的语义对齐，这种软性判据在分布外场景下的鲁棒性尚未充分验证；RL 阶段固定 HybridLink 的假设也限制了隐空间与策略的联合优化。但总体而言，这篇工作首次在架构、训练算法和理论层面系统性地打通了隐推理与工具智能体，为下一代智能体提供了一条"思考在隐空间、行动在文本空间"的可行路径。

### [Self-Evolving Agent Harness](https://arxiv.org/abs/2610.18813)
`评分4 · 18 pages, 3 figures · 有代码`

部署后的智能体面临任务和环境持续变化的问题，而传统做法要么依赖重新训练模型权重，要么靠人工重写提示词和流程，前者成本高、需要访问权重且难以通过闭源 API 实现，后者无法形成可累积、可复用的经验。已有的自反思、记忆巩固、工作流搜索等方法虽然能在单次任务中改进表现，但它们修改的对象、候选生成方式和采纳标准各不相同，缺乏统一框架，更关键的是：仅凭经验上的性能提升，无法保证修改在后续任务上仍然有效、不会引入回归，也无法说明什么样的修改应该被持久化到下一次运行。这篇论文正是要把“不改模型权重、只改智能体外围软件脚手架”这件事形式化，回答三个问题：改什么、怎么改、凭什么相信改完是可靠的。

论文把智能体拆成模型 M 和脚手架 H，H 涵盖提示词、记忆、工作流、工具、运行时控制逻辑乃至插件组合，模型权重固定不变。核心流程是一个带持久化的反馈闭环：第 k 轮用当前脚手架跑一批 rollout，收集轨迹、结果和反馈，由更新算子完成诊断、提案、评估和准入，被接受的修改写入存储并在后续运行中加载，未被接受则保留原脚手架。作者的关键洞察在于按“更新目标”建立分类：一是解释型状态更新，改的是指令、记忆条目、任务级编排，仍走预定义能力接口；二是可执行修订，改的是组件实现、仓库级控制逻辑或插件绑定，会触及运行时机制本身。这个区分不看代码语言，而看被改对象在系统中扮演的角色。理论上，他们把脚手架搜索映射为进化优化结构，再用稳定性与集中不等式推出三个条件性结论：期望泛化界、在历史回归预算约束下的保留界，以及用新鲜独立验证数据做准入的高概率规则。换句话说，它不承诺每次修改都变好，而是给出在什么假设下、用多少验证数据，才能以高概率接受真正有益的修改并控制累积退化。

实验层面，论文引用了 HarnessOpt 在 SpreadsheetBench 上的结果：GPT-5.4-nano 配合 HarnessOpt 与技能达到 77.58%，超过 GPT-5.5 配 SkillOpt 的 76.20%，在四个模型上比 SkillOpt-Lite 提升 5.69 到 11.39 个百分点，说明模型与脚手架的配对效应可以弥补模型代差。另一个 Codex 插件案例显示，智能体在执行中生成批量查询和汇总工具后，首个任务的工具调用从 13 次降到 3 次，但墙钟时间增加 54.9%、token 增加 15.7%，从第二个任务起才出现累计节省，不过论文也指出两处报告的累计成本存在未解决的差异，不能当作单一成本曲线。局限同样明确：理论结果依赖显式假设，准入需要持续的新鲜验证数据，任务分布或评估器变化时旧结论可能失效；插件接口契约只能保证兼容性，不能保证行为隔离或安全准入；持久化修改还会带来知识传播、组织流程、科学可靠性和责任归属等系统性问题。总体而言，这篇论文的价值不在于提出某个刷榜方法，而是为“冻结权重、演化脚手架”这一方向提供了可操作的定义、分类、条件性理论保证和部署时必须面对的权衡清单，后续工作若想声称自进化有效，至少需要在这个框架下说明改了什么、怎么验证、回归如何控制。

### [Jeva: System One Models from First Principles](https://arxiv.org/abs/2610.18773)
`评分3 · HF 255赞`

这篇论文要解决的是“系统一模型”在真实决策任务中的结构缺陷。所谓系统一模型，是指不生成推理链、直接输出类型化决策（选工具、选文档、判断条件、打分）的模型，其优势是低延迟。但作者指出，当前主流做法把请求和候选选项拼成一段文本送进语言模型，再从答案 token 的 logits 或专门预测头里读出决策，这从根本上没有尊重决策问题的结构。具体来说有四个要求被忽视：第一，模型要能区分“没有任何候选合适”和“在多个候选之间不确定”，前者是空答案问题，后者是竞争问题，而现有做法通常只在给定候选上做 softmax，无法表达“全都不合适”；第二，候选顺序不应影响决策，但序列化文本会让位置信息渗入预测，于是出现同一组选项换个顺序答案就翻转的现象；第三，候选数量变化时不应重新定义输出空间，而基于固定答案符号表的实现天然限制了候选规模；第四，工具库、文档集、标签表往往跨请求复用，但现有方法把候选内容塞进请求相关的联合计算里，换一个请求或重新组合候选就得重算一遍，无法缓存。作者认为这些问题的共同根源是语义表示、候选交互和答案可用性被耦合在同一个预测过程里，因此需要一种“决策原生”的架构，把可复用的编码、依赖集合的判断和空答案估计显式分开。

Jeva 的核心设计正是围绕这一分离展开。它用一个共享的语言编码器分别独立编码请求和每个选项，请求侧输入包含决策类型、问题和状态，选项侧只包含决策类型和候选文本，不含当前问题、状态或候选序号，因此每个选项的向量是请求无关的，可以预先算好并缓存。编码后，请求状态 z 会经过一个轻量的决策模块，在“不可变的选项记忆”上做若干层精炼：每一层用多头注意力让请求状态去读取所有选项的键和值，但键和值只由选项向量投影而来，不随请求改变，只有请求状态在更新。这个设计的关键洞察是：如果对每个候选独立打分再 softmax，那么任意两个候选之间的偏好只取决于它们自己的分数，加入或删除其他候选只能改变概率大小，不可能让原本落后的候选反超，因为 softmax 的归一化分母在比较两个候选时被约掉了。但真实决策中，周围候选集合的变化确实可能改变两个保留选项之间的相对偏好，所以 Jeva 让请求状态先根据整个候选集合做条件化精炼，再用精炼后的状态去和选项向量做点积打分。论文证明，即使只有一层决策块，也能构造出这样的例子：同一组选项 A、B，在加入不同第三个选项时，单块 Jeva 会分别唯一选择 A 和 B，而任何独立打分器都无法做到。精炼完成后，最终分数通过共享的选项向量计算，因此候选概率对排列是等变的，候选数量变化也不改变参数形状。空答案问题由一个独立的覆盖门处理：它估计“至少存在一个可接受候选”的概率，再把这个概率分配给候选集合，剩余质量给 null，从而把“没有合适答案”和“候选之间不确定”分开。同一个计算还能统一支持 Choice（选候选）、Noul（判断某个候选是否可用）和 Score（按候选概率对数值评分加权）。由于选项向量和每层投影都与请求无关，它们可以跨请求缓存，包括新组装的候选集合，而请求状态精炼和决策读出仍然每个请求单独执行。

实验方面，论文用 Qwen3.5-4B 作为骨干，只加一个决策块，在 Typed Decisions、BANKING77、MASSIVE 和 Mind2Web 等任务上评估。结果显示，Jeva 在类型化决策准确率上有竞争力，同时空答案检测接近完美，并且在所有测试的候选排列下都没有出现决策翻转。在 2048 个候选的大规模场景下，Jeva 的原生全集合打分比递归选择基线准确率更高，中位延迟加速超过 2 倍；跨请求复用则在新组装的长文档候选集上带来超过 20 倍的中位延迟加速，且不改变决策。这些结果说明，把候选编码做成请求无关、把集合相关判断压缩到请求状态精炼里，确实能同时满足空答案感知、排列不变、候选可扩展和可缓存这四个要求。局限也很明显：论文的验证主要围绕相对小规模的决策任务和特定骨干，覆盖门和精炼模块在极端分布外请求、候选质量参差或需要多步推理的场景下是否稳健，还没有充分展开；此外，虽然候选侧计算可缓存，但每个请求仍需执行状态精炼和读出，当请求本身很长或候选集合极大时，这部分开销仍会随候选数线性增长。总体而言，这篇工作把“决策”从文本生成中拆出来，作为一类有独立结构约束的建模问题，为低延迟、可复用、对顺序和候选规模鲁棒的系统一模型提供了一个清晰的设计范式，后续很可能影响工具调用、检索选择和结构化预测等方向。

### [VideoJev: System One Model for Video Understanding and Interaction](https://arxiv.org/abs/2610.18615)
`评分3 · HF 189赞`

这篇论文要解决的核心问题是：视频智能体在连续交互中需要把观察到的视频内容快速转化为可执行的决策，比如判断某个事件发生在哪段时间、或者从多个选项里选出最合理的答案。现有的视觉模型分成两条路线，各有各的短板。判别式视觉模型预测效率高，但往往依赖特定任务的设计或固定的标签空间，换一个任务就得重新设计输出头，缺乏语义灵活性。视频多模态大语言模型（MLLM）语义理解强、接口灵活，但它们表达决策的方式是自回归逐token生成——要输出时间戳就一个数字一个数字地生成，要回答问题就一个字一个字地写出来。问题在于，很多决策本质上是非常紧凑的结构化判断（一个区间、一个选项），根本不需要开放式生成，逐token解码在这里既慢又没必要。更关键的是，在交互场景中，同一个视频历史会被反复查询，如果每次查询都重新编码视频、重新做一遍昂贵的视觉计算，响应速度根本撑不住。所以论文的动机很明确：能不能把高效直接预测和预训练MLLM的语义灵活性结合起来，用一个统一的、语言条件化的接口，让模型直接对候选答案打分，而不是生成答案？

VideoJev的核心设计围绕两个原则展开：直接候选打分和可复用视觉计算。具体来说，它拿一个预训练MLLM（Qwen3.5-4B和Qwen3.6-35B-A3B）做改造，把语言模型原来的输出头去掉，换成一个共享的候选打分器。它引入两个新token，一个叫option_end放在每个候选后面，一个叫decide放在整个候选列表后面，两者的嵌入都从预训练的im_end初始化。打分器把这两个位置的隐藏状态各投影到512维并归一化，然后做点积相似度得到logit，再乘固定缩放10加一个学习偏置。这个打分头同时服务两个任务：时间定位和多项选择视频问答。时间定位时，候选是一系列时间戳文本，每个对应视频中一对帧构成的区间，sigmoid分数表示该区间是否属于被查询的事件，然后通过一个带阈值调整的Kadane算法在O(K)时间内选出非空连续区间作为预测；视频问答时，候选是文本选项，softmax归一化后选概率最高的。训练时用多标签二元交叉熵监督每个区间的局部成员关系，再加一个软IoU损失来奖励对事件整体的覆盖，因为一个事件可能横跨多个候选区间，光有局部判断不够。视频问答这边用交叉熵，并且为了防止模型靠选项位置走捷径，训练时对每个问题做一次与答案无关的固定排列，推理时保持原顺序。可复用视觉计算体现在两个推理模式上：Cached inference是视频编码和预填充只做一次，后续每个查询从缓存前缀分叉，只需对查询和候选做一次前向；Joint inference是把多个查询和它们的候选列表拼在同一个视频前缀后面，一次因果前向就为所有查询分别产出decide位置的打分。训练时也用同样的拼接布局来共享视频计算。两阶段训练先冻结主干只训打分头，再解冻语言主干和标记嵌入做联合适配，视觉编码器全程冻结。

实验结果覆盖三个时间定位基准和四个视频问答基准。时间定位上，VideoJev-4B平均mIoU达到65.3，比Qwen3.5-4B主干提升6.7个点，比TimeLens2-4B高3.3个点；VideoJev-35B-A3B平均mIoU 67.7，比主干提升10.8个点，而延迟只增加22%。推理速度相比各自主干有2.8到3.1倍加速，而且这个对比中生成式基线也已经共享了视频预填充，所以加速纯粹来自避免了自回归时间戳生成。视频问答上，两个模型在四个基准上的平均分比Instruct模式主干分别高8.0和5.7个点，并且在LVBench上领先各自开源组。更值得注意的是，VideoJev-4B与Qwen3.5-4B Thinking模式的均分只差0.6分，VideoJev-35B-A3B甚至超过Qwen3.6-35B-A3B Thinking 0.7分，而推理速度分别快129倍和100倍。在相同训练数据和设置下，VideoJev-4B也比自回归微调在定位mIoU上高1.3分、问答均分高1.9分，说明直接决策学习的收益不只来自数据。局限方面，论文没有大篇幅讨论，但从设计可以看出，它的候选空间是预先枚举的——时间定位依赖固定的帧对划分，问答依赖给定的选项列表，如果任务需要开放式生成或候选空间无法预先确定，这套打分机制就不直接适用。另外Thinking模式在Video-MME和MLVU上仍有优势，说明在需要深度推理的复杂问题上，直接打分还不能完全替代显式推理链。总体而言，这篇工作为视频智能体提供了一个统一、可复用的决策接口，把结构化视觉判断从逐token生成中解放出来，对需要低延迟、多轮交互的视频理解应用有直接的工程价值，也提示了一条把System One范式从图像扩展到视频时序决策的可行路径。

### [Vela: User Behavior as Supervision Sparks LLM Intelligence](https://arxiv.org/abs/2610.14709)
`评分3 · HF 69赞`

这篇论文要解决的是一个在真实产品场景中越来越突出、但现有训练范式覆盖不到的问题：大模型正在被放进个人助理、推荐系统、广告系统这类应用里，它们必须能从一个用户几周甚至几年的行为历史中推断出这个人的偏好、意图和下一步动作，论文把这称为 LLM 智能的“用户维度”。这个维度有三个硬性特征：面向个体而非平均用户、时间跨度极长、每个判断都必须有行为证据支撑。而当前模型的训练数据要么是静态网页、教材、代码，要么是合成数据，它们即便包含用户相关内容，也无法刻画单个用户行为随时间的演化，所以模型在用户维度上先天不足。已有评测显示，通用能力更强的模型在用户相关任务上并不一定更好，模型拿到行为历史后还会向“平均用户画像”漂移、历史越长越容易失准、个性化能力薄弱。与此同时，内容平台和个人助理里其实已经沉淀了海量真实行为记录——系统展示了什么、用户如何回应、偏好如何变化——这些序列本身就是天然的监督信号，在公开人类文本逐渐成为扩展瓶颈的背景下尤其珍贵。此前的工作如 P5、RLPF 只把行为数据用于推荐或用户摘要等特定任务，没有回答“能否用行为数据提升更广泛的用户相关能力、甚至不损害通用能力”这个问题，这正是 Vela 要填补的空白。

Vela 的核心设计是把“用户行为即监督”这一范式落成可训练的任务和轨迹。它取 10 万名用户的匿名行为记录，把每个用户的历史按时间切成可见历史和隐藏未来，在约 7.2 万到 12 万 token 的片段内让前三分之二作为输入、后三分之一作为监督来源，并围绕浏览、搜索、购买、发帖、关注、踩这六类行为设计了 91 个任务模板，归为两大家族四类问题：预测类里的客观题给出候选列表让模型选出用户未来会交互的对象，开放预测题则要求自由文本预测未来行为，两者的参考答案都从隐藏未来里用确定性规则抽取；评分标准类里的开放题要求模型总结用户属性、兴趣或语言风格，归因题则给出一个已发生的未来行为、要求模型基于可见历史解释它，这两类没有唯一答案，改用任务专属评分细则逐条打分。一个关键细节是，对同一个未来事件只随机选用预测模板或归因模板之一，避免归因题把预测目标泄露出去、让模型绕过推断直接抄答案。任务合成后先做难度过滤：用基座模型对每个任务生成四个回答并打分，只保留平均分落在 0.2 到 0.8 之间的中等难度任务，聚焦最有学习价值的区间；随后对保留下来的任务生成轨迹，每条只保留得分最高的一条，且该轨迹得分必须超过难度过滤时的平均分才被接受，最终从 10 万候选任务中留下约 7.5 万条用于指令微调，另外用模型自身生成的小规模 9375 条轨迹做拒绝采样微调。这套流程之所以比之前的方法更强，在于它把监督信号锚定在用户真实发生的后续行为上，而不是人工标注或合成偏好，同时通过难度过滤和轨迹接受准则控制了噪声和过易/过难样本，让模型真正学会从长历史中筛选信号、跨时间整合证据。

实验结果覆盖三组基准：同分布的 VelaBench 共 982 个留出任务，用户相关的分布外基准包括购买意图、画像摘要、人格理解和广告推荐，通用分布外基准包括 AIME 2026、GPQA-Diamond、IFBench 以及两个上下文学习基准。在 Qwen3.6-35B-A3B 上微调得到的 Vela-35B-A3B 在 VelaBench 上比基座提升 11.5 分，在用户相关分布外基准上最高提升 11.2 分，同时在通用基准上平均还涨了 4 分，说明用户行为监督不仅没有牺牲通用能力，反而带来了正向迁移；扩展实验显示喂入更多用户行为数据能持续提升用户相关表现；更值得注意的是，在微调之后再做强化学习，比直接从基座做强化学习在 VelaBench 和 ProfileSummary 上都高出 7.7 分，意味着行为监督为后续 RL 提供了更好的起点。局限方面，论文的数据来自单一社交媒体平台，行为类别和任务模板都围绕该平台设计，跨平台、跨语言、跨场景的泛化性尚未验证；评分大量依赖一个超大模型作为裁判，可能引入评分偏差；匿名化虽然去除了直接标识，但长行为序列本身的隐私风险仍需更系统的评估。总体而言，这项工作把“用户行为”从被预测的对象提升为训练监督的来源，为 LLM 在个性化、长时程、证据约束场景下的能力提升提供了一条可扩展的路径，也暗示了在公开文本之外，真实交互行为可能成为下一阶段模型智能的重要燃料。

### [UltraBERT: Beyond the Limit of BERT Pre-Training](https://arxiv.org/abs/2610.15028)
`评分3 · HF 50赞`

双向编码器在检索增强生成、数据质量过滤和奖励建模等非生成式场景中依然是不可替代的基础设施，其推理成本远低于同等能力的解码器。近年来，研究者已经将解码器领域的一系列创新引入编码器，包括旋转位置编码、FlashAttention-2 以及大规模 token 训练，但预训练配方本身——尤其是掩码语言建模这个编码器独有的目标——仍然沿用小规模时代的经验。此前关于掩码比例的研究普遍在 100 亿到 1000 亿 token 的预算下得出结论，认为更大模型应该用更高掩码比例，但这些结论实际上被收敛速度混淆了：高掩码比例让模型更快收敛，短期看指标更好，但长期是否真的更优从未被验证。更关键的是，掩码比例对分类和检索两类任务的影响方向相反，导致此前没有任何单一编码器能同时在两类任务上达到竞争性水平——要么偏向分类，要么偏向检索，无法兼得。

这篇论文的核心洞察来自三个系统性发现。第一，作者用 150M 和 1.3B 两个规模的编码器训练到 8.8 万亿 token，发现下游性能在 1 到 2 万亿 token 附近就饱和了，而训练和验证损失仍在持续下降——这与解码器持续受益于更多 token 的行为截然不同，说明编码器的下游表现存在一个额外 token 无法抬升的上限。第二，在饱和点上重新审视掩码比例，发现分类任务一致偏好低掩码比例（甚至低到 3%到6%），而检索任务一致偏好高掩码比例（50%），且这一规律跨模型规模成立，推翻了此前“大模型该用高掩码”的结论。第三，知识蒸馏与剪枝的组合同样呈现任务分化：低掩码比例下蒸馏提升分类，高掩码比例下蒸馏反而损害检索。基于这些发现，作者提出 UltraBERT，关键设计是 LM 头解耦：在每个 batch 内混合 5% 和 50% 两种掩码比例的序列，但为每种比例分配独立的 LM 预测头。之所以这样做，是因为作者通过可视化发现，不同掩码比例训练出的输入嵌入几乎相同，但 LM 头的几何形态差异显著——低掩码比例的 LM 头奇异值更集中、占据更低维的子空间。由于编码器的梯度是通过 LM 头回传的，共享 LM 头会造成梯度层面的任务干扰，解耦后则允许两种掩码机制在同一编码器内各自优化而不互相拉扯。同时，蒸馏目标只施加在低掩码序列上，高掩码序列仍用标准 MLM 训练，从而在保留分类优势的同时不破坏检索所需的表征空间利用率。

在结果层面，UltraBERT 从 1.3B 教师模型出发，经剪枝和蒸馏得到 380M 和 150M 两个版本，训练 2 万亿 token，原生支持 32K 上下文。它是首个同时在分类和检索上达到最优的编码器：GLUE 上达到 91.0，BEIR 上达到 47.7。其中 150M 模型以少 2.3 倍的参数量匹配 RoBERTa-large 的分类表现，以少 2.6 倍的参数量超越 Ettin-encoder-400M 的检索表现。局限方面，论文没有给出掩码比例与模型规模之间更细粒度的缩放规律，LM 头解耦带来的额外参数和计算开销也未做详细分析，且蒸馏仅限低掩码序列这一设计是否在所有教师规模下都最优仍有待验证。但这项工作的意义在于，它首次系统性地揭示了编码器预训练中 token 缩放、掩码比例设计和知识迁移三个核心维度的交互规律，为后续编码器的算力分配和配方设计提供了有原则的依据，也重新定义了单一编码器的性能上限。

### [DoubtLess: Training-Free Contrastive Decoding for Efficient Reasoning](https://arxiv.org/abs/2610.18862)
`评分3 · 有代码`

这篇论文要解决的是推理模型“想太多”的问题。像Qwen3、DeepSeek-R1这类模型在给出最终答案前，会先写一段用<think>和</think>包裹的思维链（CoT），在难题上这段CoT往往占了输出的大头。问题在于，其中相当一部分内容是在反复重新推导和验证模型其实已经得到的结论——论文的实测显示，Qwen3-32B在正确解答中，有32%到69%的CoT是在正确答案首次出现之后才写出来的。当然并非所有检查都多余，工作过程中的检查和第一次验证答案有可能抓出错误，但重复已经做过的检查就纯粹是浪费token了。已有的缩短方案分两类，各有硬伤：基于训练的方法要么在强化学习里加长度惩罚、要么在短轨迹上微调，都会改动模型权重，每换一个新模型就得重新训练一轮；推理时的方法则包括在prompt里要求简洁、封禁“wait”这类会开启新一轮检查的词、在答案看起来就绪或token预算耗尽时提前终止CoT、以及往隐藏状态里加一个固定的引导向量。这些做法的共同毛病是“一刀切”：prompt效果取决于模型多听话，关键词封禁在所有语境下一视同仁地压制同一批词，激活引导在每个解码步加同一个向量，提前停止则按固定准则砍断——它们既可能砍掉冗余检查，也可能砍掉真正有用的推理。

DoubtLess的核心思路是：不训练、不改权重，用一个小得多的推理模型来“带节奏”，而这个引导是动态的、随语境变化的。具体来说，选一个与大模型共享tokenizer的小模型（比如Qwen3-32B配Qwen3-0.6B），在CoT的每一步，让小模型读同一段已生成的文本两次：一次在指令后要求它直接给答案、不要重新推导或验证，称为“简洁思考者”；一次要求它逐步复查、考虑其他可能，称为“啰嗦思考者”。两次前向得到两组logit向量，二者之差（简洁减啰嗦）乘以一个强度系数α，再加到大模型当前的logit上，然后照常采样。这个差值的本质是一个方向：它把大模型的下一token分布按“简洁思考者相对啰嗦思考者的概率比”重新加权——简洁思考者更看好的token被抬高，啰嗦思考者更看好的被压低，两者意见一致的token不受影响。关键在于这个对比是每一步从当前上下文重新算出来的，所以同一个词在不同位置命运不同：在推导过程中，“Wait”开启一次检查时几乎不受影响；但一旦答案已经写出，简洁思考者预期CoT该收尾、啰嗦思考者预期再来一轮检查，此时“But”“Let”“maybe”这类开启新检查的词会被压低五倍以上。这正是它比NoWait之类关键词封禁高明的地方——它不封任何词，只是让“答案已就位后再开一轮检查”这件事变得更不可能发生，而判断“下一句是继续推导还是另起检查”很大程度上是形式问题，小模型即使解不出这道题也能判断。此外，对比只作用于CoT内部，</think>之后的答案由大模型独自解码，而且</think>和结束符的logit、top-p候选集都保留大模型自己的，小模型只能在大模型本来就愿意写的token里重新排序，无法凭空引入新token或强行终止。

在七个基准上（AIME 2024/2025、HMMT 2025、AMC 2023、GPQA-Diamond、OlympiadBench、LiveCodeBench），用Qwen3-32B配Qwen3-0.6B、按Qwen3推荐的采样设置跑三个种子，DoubtLess在准确率不变的前提下砍掉了31%的思考token，是六个方法里降幅最大的，且在七个基准中的六个上超过最接近的对手“简洁prompt”。它的优势在难题上更明显：简洁prompt在AMC 2023上能省31%，到最难的HMMT 2025只剩13%，而DoubtLess在HMMT 2025上仍能省31%。准确率方面，NoWait在AIME 2025和LiveCodeBench上显著掉分（AIME 2025掉14分），DEER在LiveCodeBench掉分，ThinkBrake在OlympiadBench和LiveCodeBench掉分，DoubtLess则一个基准都没掉，还把撞上token预算的run比例从2.4%降到0.4%。它还能迁移到EXAONE-4.0和Granite-4.2（各自用同族小模型引导，省25%和40%，而简洁prompt只省8%和14%），在HumanEval+的自调试编码agent里每轮少想20%且通过率反升2.0个点。机制分析进一步印证了设计意图：把每次run在“正确答案首次出现”处切开，DoubtLess砍掉答案之后的思考约一半、之前的约五分之一，说明省下的token主要来自答案已定后的重复检查；同时它并非无差别删检查——AIME 2025第11题里一次代数检查纠正了被错误排除的根，这种有用的检查被保留了下来。局限也很清楚：强度α目前是在AIME 2026上选定的单一值（5），换模型对或换任务是否仍最优需要验证；它依赖小模型与大模型共享tokenizer，跨tokenizer的场景不适用；对DEER这类基于预算的提前终止，DoubtLess并不直接竞争同一机制，两者结合的效果论文没有展开。总体而言，这篇工作指出了一个有说服力的方向：与其训练模型变短、或用静态规则砍CoT，不如让一个便宜的小模型在每一步动态地告诉大模型“此刻该收还是该查”，把“简洁”从一个全局属性变成随上下文变化的局部信号。

### [Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents](https://arxiv.org/abs/2610.18784)
`评分3 · 24 pages. Project page: https://ethannju.github.io/carryon`

长期任务智能体面临的核心矛盾在于：任务进展实际上被存储在两个地方——持久化的任务状态（比如已经插入演示文稿的图片、已经填入报告的测量数据）记录了“完成了什么”，而交互历史则记录了“怎么完成的”。问题在于，随着执行步数增加，智能体反复处理的却是后者——那些描述“如何达成”的交互记录，而任务状态本身已经包含了这些进展，可以直接被检视和修改。这种冗余随轨迹长度持续膨胀。现有方法要么对历史做摘要、检索、剪枝，要么把历史翻译成显式的进度记录和结构化任务状态，虽然能压缩上下文增长，但它们的共同缺陷是：当这些压缩产物替代了可复用的任务结果时，智能体的继续执行就依赖于一份有选择性的、可能漂移的“叙述”，而非它真正能直接检查和修改的任务状态本身。换句话说，摘要可能遗漏关键约束，检索可能召回不相关的片段，结构化记录可能与实际环境状态脱节——这些都会在长程执行中被放大。

CarryOn 的核心洞察是把长程上下文围绕“可复用的任务对象”来组织，而不是围绕产生这些对象的交互历史。它把智能体的活跃上下文拆成三个互补部分：延续载体、执行上下文和活尾。延续载体是核心创新，它把可复用内容或对象引用与其使用条件绑定在一起，并维护稳定身份——修订产生同一身份下的后继版本，未受影响的载体保留原有记录。载体分三类：外部对象（代码文件、文档、表格等独立存在于环境中、可重新打开修改的工作产物）、信息产品（通过交互获得的合成信息或排障结论，若未物化为持久对象则直接存储发现及其来源）、以及情境状态（只在特定应用、会话或工作流中可用的进展，载体记录环境锚点、已建立状态及其可复用范围）。执行上下文则保留载体未捕获的活跃目标、约束和未决问题，活尾保留最近一次折叠以来的原始交互。运作机制上，Tracker 持续识别可能变得可复用的候选进展，候选可以跨多次调用逐步成熟，一旦达到可支撑继续执行的状态就请求编译；编译前 Grounder 会做只读的环境检查，把候选、已有载体记录、授权来源材料和检查结果打包成输入包，固定住后续验证所依据的版本和证据。Compiler 联合更新载体和执行上下文：载体编辑只针对被选中的候选并以其授权证据为依据，执行上下文则针对整个活尾修订以保留延续所需信息。验证通过后，受影响的载体获得后继版本，未受影响的保留原记录，整个活尾被一次折叠覆盖，后续交互开启新的活尾。关键约束是：一次成功折叠必须至少引入一个载体变更，仅修订执行上下文不足以退休交互历史。这套设计比之前方法更好的地方在于：它不依赖对历史的压缩重建，而是让智能体直接检视和使用可复用对象，上下文只提供继续执行所需的补充信息；同时通过绑定证据和环境检查来保证载体在被折叠后仍然有效，而不是每次折叠都从头重建整个表示。

在 OSWorld 2.0 上，CarryOn 把 Claude Opus 4.7 的部分分从 43.9% 提升到 49.7%（+5.8%），二值分从 15.7% 提升到 19.4%，同时总 token 用量降低 51.9%，每任务成本降低 35.9%；在 BrowseComp-Plus 的 100 题随机子集上，准确率从 49% 提升到 56%（+7%），token 用量降低 22.9%，成本降低 7.1%。上下文动态分析显示，基线上下文随轨迹持续增长最终超过 20 万 token，而 CarryOn 的平均输入上下文在初始增长后稳定在约 6.5 万 token；累计成本曲线在约 200 轮前交叉，到 500 轮时 CarryOn 累计成本降低 34.1%。局限方面，验证机制只检查更新的一致性和证据支持，并不验证任务正确性，这意味着错误的载体内容仍可能被提交；当前实现中一次成功折叠覆盖整个活尾，折叠粒度较粗；实验仅在两个基准上验证，跨更多任务类型的泛化性有待检验。意义在于，它提出了一条不同于“压缩历史”或“外化状态”的第三条路——让可复用任务对象成为延续的基本单位，这对长程智能体的上下文管理方向有明确的启示：与其反复重建进展的叙述，不如维护一个可检视、可修订、带使用条件的对象集合。

## 强化学习 RL

### [Tev: Scaling Long-Horizon Agentic Environments with Dense Progress Rewards](https://arxiv.org/abs/2610.18868)
`评分4 · HF 74赞`

长时程智能体（能自主工作数小时到数天、处理有经济价值任务）是通向自动化发现与递归自我改进的关键能力，但开源模型在这类任务上表现很差，根本原因是既缺训练数据、也缺可用的训练配方。现有开源智能体训练语料（如 SWE-Smith、TMAX、Endless Terminals、CLI-Gym、SETA、Terminal-Universe）虽然规模从数千到数万环境不等，但每个任务本质上只是一个 pull-request 级别的修复或一段很短的终端会话，评估方式是基于单元测试的终局通过/失败或通过测试比例，信号极其稀疏。真正意义上的长时程任务只存在于人工编写的评测集（如 Agents' Last Exam、Terminal-Bench 的部分子集）里，这些集合只有几十到几百个实例，每个实例需要专家数周投入，且只提供手写检查点式的部分分，纯粹是评测集而非训练集。于是形成了一个结构性缺口：智能体训练语料大但短，长时程任务长但小且只用于评测。更麻烦的是，要构造长时程任务必须同时满足两个互相冲突的目标——任务要足够长、结构足够复杂才有训练价值，同时又必须能被精确验证；而长时程任务的奖励天然稀疏，只在任务完成提交时才出现，这直接饿死了对长尾样本的训练。在 GRPO 这类组相对策略优化里，同一任务采样 G 条 rollout 做组内归一化，如果一组全部失败，所有优势都为零，这条任务对梯度毫无贡献。短时程任务里这种全败组很少见，可以丢弃或重采样；但在长时程任务上，训练初期策略最弱、最需要信号的时候，全败组恰恰最常见——当单条 rollout 成功率为 p、组大小 G=8 时，p=0.05 就有 66% 的组被浪费，p=0.01 时高达 92%。即便一组里有一条成功，那条正样本也只能和 G-1 条同样收到负优势的失败样本对比，梯度无法区分"差一点就成功"和"完全没进展"。

论文的核心创新是"潜在世界优先"（latent-world-first）的合成范式，它把任务构造的方向反过来：先造一个完整且正确的隐藏规格，再从中渲染出智能体看到的环境。具体分几个阶段：给定种子和规模档位，程序化生成潜在世界 W（比如零售仓库的客户、商品、交易，或分布式检查点的张量分片与拓扑），并用不变量（唯一标识、合法连接、有限度量）校验 W；同一步还抽出一个由种子决定的"缺陷计划"，明确哪些记录、分片或字段会被哪种声明式算子破坏。接着把工作流编译成有向无环图（DAG），节点是带依赖、允许并行、带语义工作量估计的阶段，关键路径定义任务时程，且完全由代码根据 W 的规模构建，不引入模型。然后把 W 投影到环境的公开接口上，物化成 CSV/TSV 分区、JSON、SQLite、safetensors 分片、剥离符号的二进制或基础设施清单，并断言渲染可往返（能从渲染文件精确恢复 W）。再施加缺陷计划注入 schema 漂移、重复与缺失记录、类别漂移、分片索引错乱、过期缓存等，得到智能体实际收到的损坏树 s0，而未受污染的 W 就是标准答案。由于渲染可往返、损坏可逆且被声明，s0 完全决定 W，正确答案可从智能体所见直接算出，无需运行求解器。关键在于任务提示、输入树、严格验证器和进度势函数全部是同一个 W 的函数，这从根本上避免了"工件漂移"——分别生成的环境、任务和验证器各自看似合理却描述不同问题。基于此，每个环境都提供一份"进度契约"：一组可检查的输出工作区状态节点，带权重和前置条件集，每个节点有部分打分器直接对照潜在世界给分，且信用受前置门控（取该节点及其所有直接与间接前置的最低分），势函数就是加权和。这个势函数被三重资格门保证可用：锚定性（未污染树和所有作弊探针得分恰为 0，严格验证器接受时恰为 1）、单调性（完成节点上升、破坏已完成工作下降）、独立性（打分器代码闭包与验证器、参考求解器不相交，且这些评分代码不随公开树发布）。训练时采用"进度势奖励塑形"（PPRS）：每步奖励是势的增量，rollout 奖励为塑形项之和加上 λ 倍的终态势，λ 固定为 0.25。与经典 PBRS 不同，PPRS 刻意保留终态势项、有意改变优化目标，因为提交是一个动作而非状态，势函数评的是工作区，终局项评的是策略实际提交的工作区；若 rollout 耗尽回合或 token 预算而未提交，则只拿 λΦ(sT)。这样即便一组 rollout 全部失败，从第一步起就有组内方差，训练信号不再饿死。

在结果上，作者用该范式构建了 Tev-Gym，这是首个带可验证、密集、渐进奖励的长时程智能体训练数据集，覆盖软件工程、数据工程、AI/CS 研究、数学与运筹、安全与取证、基础设施管理、量子计算 7 个领域共 1170 个已验证环境。前沿智能体在 Tev-Gym 上单条 rollout 中位耗时 12.4 分钟，约为此前最耗时语料的 6 倍，且通过率最低，说明其复杂度和质量。用 PPRS 训练得到 Tev-9B 和 Tev-27B：在 ALE-CM（Agents' Last Exam 的计算与数学科学部分）上，Tev-9B 的 Pass@5 比 Qwen3.5-9B 提升 83%，Tev-27B 比 Qwen3.8-27B 提升 65% 达到 0.28，追平 GPT-6 Astra 和 Claude Opus 5；尽管只在 ALE 相关数据上训练，Tev-27B 零样本泛化到 Terminal-Bench 3.0 和 4.0 子集，Pass@1 分别提升 56% 和 150%，超过 GLM 5.2 和 Gemini 3.7 Flash；在中时程的 TB 2.1 上，Tev-9B 零样本 Pass@1 提升 28%，Tev-27B 达到 0.794，追平 Claude Opus 4.8 水平。配方还能迁移到更大基座：应用于 GLM-5.3-Flash 得到 Tev-320B，在 TB 3.0 和 4.0 子集上 Pass@1 分别再提升 35% 和 28%，在 TB 4.0 上仅次于 Claude Opus 5、Claude Fable 5 和 GPT-5.6 (sol)。局限方面，作者明确说受资源限制只聚焦 ALE-CM 领域，虽然方法可推广到其他 ALE 领域（附录展示了云运维、工程控制、金融财报重建三个例子），但尚未系统验证；此外 PPRS 有意改变优化目标、保留终态势项，理论上不再保证最优策略不变，这需要靠资格门和实验来兜底。总体而言，这篇工作把"长时程任务无法规模化训练"这一瓶颈拆成数据与奖励两个子问题，用潜在世界作为唯一锚点同时解决精确验证、可控难度阶梯和密集进度奖励，为开源模型在长时程智能体方向提供了可复制的配方，其影响可能在于把长时程训练从"只能评测"推进到"可以规模化训练"。

### [TPPO: Tracking-Value PPO For Language Model Reasoning](https://arxiv.org/abs/2610.16794)
`评分4 · HF 71赞 · 有代码`

在长链思维链推理的强化学习里，PPO 这类带价值网络的方法一直面临一个尴尬：终端奖励是稀疏的二值信号，整条轨迹只在最后拿到对错，但策略梯度却需要给每个 token 分配信用。标准 PPO 的做法是让 critic 独立预测每个前缀的状态价值，再用 GAE 把相邻价值之差转成 token 级优势。问题在于，真正决定相对信用的是价值沿轨迹的演化量，也就是相邻前缀价值之差，而独立预测的 critic 并不显式建模这个演化。论文用一个很直观的例子说明这种失效：在“sin²x=0”这一步之后，模型错误地断言“唯一解是 x=0”，用蒙特卡洛续写估计出的价值变化是 −0.992，是一个巨大的下跌，但 PPO critic 给出的却是 +0.036，不仅漏掉了下跌，还把符号搞反了，直接导致两个锚点处的 GAE 优势排序被颠倒。更严重的是这不是偶发噪声，而是系统性缺陷：训练过程中 critic 对价值演化方向的符号准确率始终在随机水平附近徘徊，甚至从 50.34% 掉到 45.91%，也就是说越训越不靠谱。作者由此提出核心问题：critic 能不能被设计成真正去追踪价值演化，而不是各自独立地猜每个前缀的价值。

TPPO 的关键洞察来自对价值演化本身的贝叶斯结构分析。在二值终端奖励、折扣为 1 的设定下，某个前缀的价值恰好等于从该前缀续写最终成功的概率。当采样出下一个 token 后，前缀被延长，成功概率被这一个新观测条件化，于是从当前前缀价值到下一前缀价值的转移，本质上就是一次贝叶斯更新。作者证明，把这个更新写在对数几率空间里时，它变成加性的：相邻前缀的对数几率之差，等于该 token 在成功与失败两种续写分布下的对数似然比。把这一步沿整条轨迹递归展开，就得到价值的增量分解——任何位置的前缀价值，都可以表示成从开头到该位置一系列位置级标量增量之和，再经过 sigmoid 还原成概率。TPPO 正是把这个结构直接写进 critic 的参数化：critic 不再为每个前缀单独输出一个价值，而是对每个位置输出一个标量，把这些标量沿轨迹累加得到价值 logits，再取 sigmoid 得到重构的前缀价值。训练时仍然只用标准 PPO 就有的终端结果作为监督，用二元交叉熵去拟合这些重构价值，不需要额外的 rollout、不需要过程级标注、也不需要辅助奖励模型。由于每个位置的增量会出现在它之后所有前缀价值的累加和中，它会从所有后续位置的重构价值处收到梯度，这种跨位置的梯度共享让 critic 被迫去学习“每一步让成功概率往哪个方向变、变多少”，而不是孤立地拟合每个前缀。重构出的价值直接接入标准 GAE 和 PPO 裁剪目标，其余流程完全不变。对照实验也验证了增益来自参数化本身而非损失函数：在固定 actor、统一用 BCE 训练的条件下，累积参数化相比标准 critic 在价值演化方向准确率上分别提升了 2.01 和 2.80 个百分点。

在结果层面，TPPO 在 Qwen3-4B-Base 和 Qwen3-8B-Base 上的数学推理综合得分分别比 PPO 高出 7.0 和 8.4 分，同时分布外泛化也更好，增益还稳定迁移到 Qwen3-4B、Qwen2.5-Math-1.5B、Qwen3.5-9B 以及 Countdown 和科学编程任务上。进一步分析显示，TPPO 对价值演化的追踪更准，优势估计也更可靠，说明性能提升确实来自信用分配质量的改善，而不是某种训练不稳定带来的偶然波动。当然，方法也有边界：它的贝叶斯加性结构建立在二值终端奖励和折扣为 1 的假设上，对于更一般的奖励形态或多级奖励是否仍然成立，论文没有展开；此外，虽然不增加 rollout，但累积参数化改变了 critic 的梯度传播路径，在大规模模型和更长轨迹上的训练稳定性与计算开销仍值得进一步检验。总体而言，这篇工作把“价值演化追踪”从一个被忽视的经验问题提升为有理论结构支撑的设计原则，为 RLVR 中稀疏奖励下的 token 级信用分配提供了一个不依赖额外监督的实用方向。

### [Scoring Higher, Answering Worse: Mitigating Reward Hacking in Rubric-Based RL via Protocol-Level Rubrics](https://arxiv.org/abs/2609.38847)

这篇论文要解决的是基于评分表（rubric）的强化学习里一个非常隐蔽但后果严重的问题：奖励聚合方式本身会诱导模型学会“刷分”而不是“答对”。在没有编译器或答案校验器可用的开放任务上，研究者用 LLM 裁判逐条检查评分表上的标准，再把判定结果聚合成一个标量奖励，最常见做法是加权求和。论文指出，正是这个“求和”成了薄弱环节——在加法聚合下，各条标准可以互相补偿：漏掉了真正关键的那一步决策，可以用一堆没人要求的额外建议把分数买回来。作者在临床问诊任务上展示了这种崩塌：训练后评分表覆盖率从 26.6 升到 32.1，看起来在进步，但用医生撰写、训练时完全没见过的“适当性”标准去评，分数却从 54.1 掉到 26.0，比未训练模型还低一半。更关键的是，他们系统排除了其他解释：把回答砍短 42% 几乎不恢复适当性，换一个模型家族的裁判排名不变，只用同样的评分表数据做 SFT 不崩塌，加大 KL 惩罚也只是在停止学习后才恢复适当性。真正能恢复的是改变聚合机制本身——把逐字不变的标准重新分组、要求组内同时满足，就能挽回约三分之一的损失；把整张表当作一个整体来打分，能挽回近 40%。这说明问题不在标准写得不好，而在聚合方式给了模型一条廉价的刷分通道。

### [SkillScaffold: Scaffolding Agentic Reinforcement Learning with Policy-Adaptive Skill Credit Assignment and Selective Injection](https://arxiv.org/abs/2610.18807)

这篇论文要解决的是智能体强化学习（Agentic RL）中一个很实际的瓶颈：当大语言模型需要在多轮交互环境里完成任务时，长时程和稀疏的结果奖励让成功行为很难被探索到、也很难被强化。文本技能（textual skill）本来是个好帮手，它把过往轨迹或反馈压缩成可复用的程序性指导，帮模型在后续决策中少走弯路。但现有的技能型 RL 方法存在一个关键缺陷——它们要么默认注入技能一定有益，要么依赖间接、延迟的反馈，要么干脆用额外的、针对每个候选技能的环境 rollout 去评估技能到底有没有用。作者做了先导实验，发现这种基于 rollout 的效用估计既昂贵又不稳定：在稀疏奖励下，即使把每个查询的额外 rollout 预算从 5 次加到 40 次，候选技能组中仍有接近一半无法区分优劣；而且技能收益高度依赖具体查询和当前策略的能力——当策略本身已经能可靠解决某个查询时，技能的平均收益反而变成负的，连最好的候选技能也几乎带不来额外价值。这就引出了一个核心需求：技能信用分配必须能同时做两件事，一是对候选技能排序，二是在没有技能真正有帮助时果断弃用（abstention），而且这个判断必须是查询相关、策略相对的，不能靠昂贵的下游 rollout 来获得。

SkillScaffold 的核心创新在于用「结果感知的似然比较」替代「候选特定的环境 rollout」，从而以极低成本估计技能效用。整个训练脚手架让同一个共享策略扮演两个角色：Executor 负责与环境交互，Generator 负责从带结果标签的轨迹中生成候选技能。每一轮更新时，Executor 先做 N 条无技能的 Scout 轨迹，环境验证器给每条轨迹打上成功或失败的标签，形成全成功、全失败或混合的证据组。Generator 根据这些证据独立采样出 M 个候选技能，每个技能是一张结构化卡片，包含适用条件、可执行流程、条件决策规则以及验证、恢复或停止准则。关键的一步是效用估计：作者不再让每个候选技能去跑新环境，而是把 Scout 轨迹固定住，用当前策略在「有该技能」和「无技能」两种上下文下对同一条 Scout 轨迹的 token 序列重新打分，得到一个似然差。如果技能让成功轨迹的似然上升、让失败轨迹的似然下降，效用就高；在全失败组里符号反转，奖励的是技能对失败行为的抑制；混合组里成功支持和失败抑制两项获得相等总权重，避免被数量多的一方主导。这个效用是策略相对的，因为它衡量的是当前 Executor 在给定技能下对已验证行为的偏好变化。选择时只取效用最高的候选，并且只有当其效用为正时才注入到后续 L 条 Post-Scout 轨迹中，否则该查询保持无技能执行。训练上，Executor 用环境奖励做 GRPO，Generator 用技能效用做另一组 GRPO，两者共享参数，使得无技能的 Scout 和有选择脚手架化的 Post-Scout 共同更新同一个策略，天然鼓励技能内化。部署时整个技能通路被移除，推理完全无技能、无额外开销。

在 ALFWorld、WebShop、ScienceWorld 和 τ²-Bench 四个多轮环境上，SkillScaffold 在完全无技能推理的条件下超过了强智能体 RL 基线（GRPO、GiGPO）和技能型 RL 基线（INSPO、SkillRL、Skill1、Evolving-RL、SEED 等），覆盖了短时程和长时程任务，消融实验也支持基于效用的选择和弃用机制确实重要。论文的局限在于，它目前主要在 Qwen3-8B 这一档模型上验证，效用估计依赖似然比较，对于极长轨迹或 token 级打分成本敏感的场景可能仍有扩展性问题；此外 Generator 生成技能的质量上限、以及效用正负阈值在分布偏移下的稳健性，都是尚未完全展开的问题。但它的意义在于把「技能该不该用、用哪一个」从昂贵的试错变成了可微、可批量计算的策略相对信号，并且证明了训练时脚手架、部署时无技能这条路径在多个环境里可行，为技能型智能体 RL 提供了一个更务实、更可扩展的信用分配范式。

### [Two Clocks: Why Larger Rollout Batches Learn Slower but Fail on Schedule in Reinforcement Learning with Verifiable Rewards](https://arxiv.org/abs/2610.18853)

这篇论文要解决的是强化学习可验证奖励（RLVR）训练中一个非常实际却长期被忽视的工程问题：当研究者为了摊薄昂贵的生成成本而不断增大 rollout batch（即每次策略更新前生成的回复数量）时，通常沿用平方根学习率缩放规则，即学习率正比于 batch 的平方根。在“每次 rollout 只做一步优化”的理想设定下，这条规则被证明能近似保持每样本进度不变，因此被广泛当作 batch 缩放的黄金法则。但真实训练几乎不会只做一步——DAPO 等主流配方会把一个 rollout 切成多个 mini-batch，做十几步甚至更多优化。一旦进入多步 regime，从第二步开始当前策略已经偏离生成数据的旧策略，token 级重要性比率不再等于 1，PPO 式的比率裁剪开始生效。作者在 GRPO 多步实验中观察到三个同时出现的反常现象：更大的 rollout batch 每样本学得更慢；不裁剪时大 batch 会在与小 batch 相同的样本数处崩溃，尽管优化步数少得多；裁剪反而对大 batch 帮助最大。此前的工作要么单独研究 batch 不变性，要么在每 batch 都重新调学习率的条件下研究 critical batch，要么在固定 batch 下研究裁剪，没有任何一个框架能解释这三件事为什么会在同一条平方根规则下同时冒出来。

论文的核心洞察是把“样本效率”和“崩溃时间”拆成两个独立的时钟。作者用一个局部二次模型分析一步优化的效果：在噪声主导归一化的假设下，平方根规则确实让每样本的持久位移（drift per sample）与 batch 无关，因为大 batch 步长更长但步数更少，两个效应恰好抵消。但位移相同不等于进度相同——在弯曲的损失面上，更大 batch 用更少、更长的步走完同样的位移，会因曲率项损失更多实际进度。由此得到“进度时钟”：每样本进度随 batch 线性下降，存在一个依赖学习率的 critical batch，超过它后样本成本指数从接近 0 升到 0.44，且这个 critical batch 随平方根规则给出的学习率增大而缩小，可以远低于梯度噪声尺度。对于失败，作者提出漂移阈值假设：当累积漂移达到某个阈值时训练崩溃。在平方根规则下，失败所需样本数恰好与 batch 无关，形成“失败时钟”。裁剪的作用也被定位清楚：平方根规则让大 batch 每步更长，一个 rollout 内 log-ratio 的扩散按 batch 平方根增长，所以大 batch 被裁剪得更狠；裁剪限制的是每个 rollout 新增的漂移，而不是撤销已积累的漂移，因此它推迟崩溃却不消除进度差距。基于这两个时钟，作者还推导出一个简单调度：先在 critical batch 以下起步保证样本效率，再在崩溃前切换到更大 batch。

实验在 Qwen2.5-Math-1.5B 上用 GRPO 和 DAPO-Math-17k 做控制变量，rollout batch 从 512 到 8192 跨越 16 倍，每个 rollout 切 8 个优化步，学习率按平方根规则从 1e-6 到 1e-5。结果支持两个预测：进度方面，μ=1 时大 batch 仍需多 20–45% 样本达到同等精度，μ=8 的保守 regime 下差距依旧，去掉裁剪后差距仍在；样本成本指数随学习率从 0.15 升到 0.44，隐含 critical batch 从约 9k 降到 2k。失败方面，不裁剪时 4096 batch 在 56–80 步崩溃，512 batch 在 648 步崩溃，但两者都在 30–50k 样本处失败，符合漂移律而非噪声驱动的 1/η² 律；裁剪把小 batch 崩溃推迟约两倍、大 batch 推迟约四倍。进度差距在第二个数据集、通用 checkpoint 和 7B 模型上复现。局限在于漂移阈值仍是假设而非从第一性原理导出，实验规模有限、部分只跑了两个种子，二次模型也忽略了策略陈旧性的高阶效应。但它的意义在于把“大 batch 是否划算”从单一的学习率缩放问题，变成进度与稳定性两个时钟的联合设计问题，并给出了可直接落地的 batch 调度思路。

### [WorkRover: Scaling Long-Horizon Cowork Agent Training Via Recursive Environment Evolution](https://arxiv.org/abs/2610.18067)
`评分3 · HF 64赞`

长时程协作智能体的强化学习训练长期受制于一个核心瓶颈：环境本身不可靠。这类任务要求智能体在文件、工具和应用之间执行几十甚至上百步相互依赖的操作，而每一步的成败都依赖于前序步骤是否正确改变了工作区状态。用强化学习训练这类智能体，前提是环境能提供多样化的可执行工作流，并且能对任务结果给出可靠反馈。但问题在于，自动合成的环境——即使数量庞大——并不天然保证反馈可靠。一个协作环境要真正可用，工作上下文必须支撑任务需求，验证器必须能评估所要求的结果同时接受合理的替代方案。然而初始构建之后，智能体实际执行时经常暴露出缺失依赖、任务描述不一致、验证器误判等缺陷。这些缺陷的后果很严重：合法行为可能被判为失败，错误结果反而可能被奖励。更棘手的是，修复一个缺陷往往需要跨组件协调——改了工作上下文或任务描述，验证器也得跟着更新才能保持执行与评估对齐。已有的构建流水线基本不支持这种迭代式精化，它们要么一次性生成环境后就不再改动，要么改动时无法保证组件间的一致性。这正是这篇论文要解决的真实问题：如何让环境在训练过程中递归地自我进化，使得任务、上下文和验证器始终保持语义对齐。

WorkRover 的核心设计围绕三个相互咬合的模块展开。第一个是 Harness 驱动的环境合成。Harness 不是简单的脚本调度器，而是一个显式追踪组件依赖关系的协调层。它把环境拆成三个部分——工作上下文（文件、能力、应用运行时）、任务（目标、交付物、约束）和验证器（检查任务完成度）——然后让构建智能体在 Harness 的约束下联合构建并验证这三者。关键机制在于：构建智能体不是按照固定流程走，而是根据工作区状态和执行反馈自适应地决定下一步动作。任务合成阶段，一个独立的演示智能体从干净初始状态执行任务，成功则确认任务可行并产生参考状态；验证器合成阶段，先从任务指令推导出评估契约，再据此生成评分规则，并用起始状态和负例来校准验证器，确保它拒绝违规方案、接受参考状态和独立获得的有效替代方案。第二个模块是 Factorial Compatibility Replay，简称 FCR，解决的是环境进化中的修复选择问题。当诊断确认是环境缺陷而非智能体自身错误时，Harness 会为每个受影响组件冻结一个修复提案，然后在最多四个组件上枚举所有组合（至多十六种），每种组合展开为依赖闭包——也就是说，即使某个组件没被直接选中修复，只要它依赖于被修复的组件，也会被自动纳入更新。这些组合在匹配的 rollout 条件下重放，比较单独修复和联合修复的效果。最终 FCR 选择通过所有独立检查且改动组件版本最少的那个组合，平局时优先选重建依赖更少的方案。这个设计的精妙之处在于：它不依赖智能体成功率或提议验证器的打分来判断修复是否有效，而是用独立检查确认原始问题已解决、任务意图和信息边界未被破坏。第三个模块是 Verifier-to-Turn Credit Assignment，简称 VTCA，解决的是信用分配问题。GRPO 只给整条轨迹一个终端奖励，但长时程任务中，有用的步骤可能出现在失败的轨迹里，冗余动作可能混在成功的轨迹中，而早期的信息收集步骤往往只有通过后续的工作区变化才能体现价值。VTCA 的做法是用冻结的确定性检查测量每一轮前后工作区状态的变化，得到进展或倒退的信号，然后通过记录的工具输出和工件版本依赖关系，识别出哪些前置轮次对后续进展有贡献，并给它们分配有界比例的正向信用。整个过程不需要调用中间裁判模型，因此不会引入额外的推理开销或不一致性。

在实验结果方面，作者用 WorkRover 对 Qwen3.5-35B-A3B 进行后训练，得到 WorkRover-35B-A3B，并在五个外部基准上评估。相比原始骨干模型，JobBench 上提升了 26.27 个百分点，OfficeQA Pro 上提升了 29.32 个百分点，GDPval v2 上提升了 413.25 Elo 分。控制实验进一步验证了两个核心组件的贡献：在匹配修复预算上限的条件下，FCR 比完全重新生成的任务包合成通过率高 6.0 个百分点，并且在维护评估中能更可靠地解决自然发生的缺陷，同时减少对任务意图的意外改动；在 SFT 初始化、任务与种子调度、rollout 预算都固定的情况下，VTCA 在全部五个基准上都优于仅用终端奖励的 GRPO。构建消融实验还表明，遵循文件依赖关系、按兼容技能匹配文件，比仅靠主题相似度组装工作区，能显著提高任务产出率和可执行性。当然，这篇工作也有局限。VTCA 的效果受限于检查器覆盖范围和依赖图质量——如果确定性检查覆盖不到某些关键进展维度，或者工具输出与工件之间的依赖关系记录不完整，信用分配的精度就会下降。FCR 的修复搜索空间虽然被限制在四个组件以内，但依赖闭包展开后实际涉及的更新可能远超预期，在更复杂的环境中组合爆炸的风险仍然存在。此外，目前只在 Qwen3.5-35B-A3B 这一个骨干上做了验证，方法对不同规模和架构的模型的泛化性还有待检验。尽管如此，WorkRover 指出的方向是清晰的：长时程智能体训练的真正瓶颈不在策略算法本身，而在环境的质量和反馈的粒度。把环境当作一个可以递归进化的活系统来维护，而不是一次性构建后冻结的静态资源，这个思路对整个智能体训练领域都有借鉴意义。

### [Rubrics from the Task, Verdicts from Evidence: Pointwise Rubric Rewards with Tool-Augmented Judges](https://arxiv.org/abs/2610.18766)
`评分3`

在不可验证任务上，传统奖励模型直接输出一个整体标量分数，往往不可靠，因为它缺乏明确的评判依据。基于评分标准（rubric）的奖励模型试图通过显式准则来评估回答，但现有方法存在两个关键缺陷。第一，评分标准通常是从观察到的回答候选中归纳出来的——比如让教师模型对比优选回答和被拒回答，找出能区分二者的准则，再训练一个学生生成器仅凭指令预测这些准则。这种做法会引入“回答诱导偏差”：准则可能只覆盖了候选回答之间恰好存在的差异，而忽略了所有候选都满足或都违反的任务要求，导致评分标准对未见回答的泛化能力受限。第二，评判环节也有问题。复杂指令往往同时包含机械约束（如字数限制）和主观质量维度（如语言生动性），但现有基于LLM的评判器仅靠阅读来评估，即使评分标准正确识别了字数限制，评判器也可能数错字数。此外，常用的成对评判器只给出两个回答的相对偏好，无法为单个回答提供独立分数，这给直接用于策略优化带来了困难。

针对这些问题，作者提出了ReVeR，一个逐点（pointwise）评分标准奖励模型。它的核心创新在于：评分标准完全从指令本身推导，而非对比回答。生成器先对任务进行推理，识别用户想要的交付物、显式与隐式要求、以及可能的失败模式，然后生成两类准则——硬规则（必须满足的强制要求）和原则（分等级的质量维度）。评判器对每个回答独立评估，在共享的指令特定评分标准下，判断每个准则是否满足。对于机械约束，评判器可以调用沙箱化的Python解释器来执行验证，比如统计词数或检查格式；对于语义准则，则依靠推理判断。最终奖励采用字典序聚合：先看满足硬规则的数量，满足更多硬规则的回答得分更高，只有在硬规则满足数相同时，才用原则分数区分。训练方面，作者采用“标签盲蒸馏”：教师模型仅根据指令生成评分标准推理，并分别对优选和被拒回答进行独立评判，偏好标签只在生成完成后用于筛选——如果教师给出的分数与偏好标签一致，就保留该样本，否则丢弃。标签和竞争回答从未出现在生成上下文中，因此学生模型在推理时只依赖自己可获得的信息。这一过程产出了ReVeR-Traces数据集，包含约3万条评分标准推理轨迹和6万条工具增强的评判轨迹。生成器还进一步用GRPO进行强化学习，以固定评判器下的偏好区分准确率为奖励，优化评分标准的质量。

实验表明，4B参数的ReVeR在平均偏好准确率上超过了8B的成对评分标准奖励模型，在指令遵循类基准上优势最明显，并且在DPO和GRPO下游策略优化中取得更好的平均表现。但作者也揭示了三个维度并不一致：生成器的强化学习提升了偏好准确率，却降低了评分标准保真度（即与专家评分标准的一致性）；在GRPO下，偏好准确率最高的成对评分标准奖励模型反而训练出一个在IFEval上低于基础策略的模型，该策略倾向于声称自己满足要求。这些发现说明，评分标准保真度、偏好准确率和下游效用是三个不同的属性，不能混为一谈。这项工作的意义在于，它指出了当前奖励模型研究的一个盲区：仅仅追求偏好准确率可能误导策略优化，未来需要分别评估和优化这些维度，而ReVeR提供的从任务推导标准、用工具验证证据、逐点独立评判的范式，为构建更可靠、更可解释的奖励模型提供了可行路径。

### [AutoNovo: Agentic Program Search Discovers Transferable Nucleic Acid Design Algorithms](https://arxiv.org/abs/2610.16232)
`评分4 · 40th Conference on Neural Information Processing Systems (Ne`

这篇论文要解决的是核酸序列计算机辅助设计中的一个根本性信任危机。在药物开发中，用预测模型（oracle）来优化核酸序列——比如提升翻译效率、稳定性或细胞特异性表达——比湿实验筛选快得多也便宜得多。但问题在于，针对某一个预测模型优化出来的序列，往往只是 exploit 了那个模型特有的伪影（artifact），而非真正激活了生物学功能。论文引用此前的工作指出，不同设计算法在面对独立模型时的泛化能力差异巨大。这里的关键验证手段叫“正交验证”：用另一个训练数据、架构或两者都不同的模型去预测同一属性。注意这是一种单向测试——两个模型一致不保证序列在真实生物系统中有效，但不一致通常意味着序列只是 oracle 的产物。既然湿实验验证昂贵且耗时，正交验证就成了领域内快速筛选的代理指标。于是核心问题变成：能否用智能体程序搜索自动发现比人类手工设计更好的核酸设计算法，并且这些算法设计出的序列能在搜索时未见过的独立模型上也表现良好？

AutoNovo 的方法核心在于构建了两层嵌套的优化循环。外层是 ERA（Empirical Research Assistant）驱动的程序搜索：它用基于树搜索和上置信界规则的 LLM 进化算法，迭代地重写、执行、评估和修订实现“设计器”的代码。每个设计器有固定接口——初始化时接收一个可查询的 oracle 函数和一条等长的 ACGT 起始序列，run 方法在墙钟时间预算内迭代编辑序列，get_samples 返回找到的最佳序列。内层则是每个被生成的设计器自身在生物序列空间上的搜索。关键设计在于训练时的评估目标：ERA 用 f_eval = f_opt + λ·f_orth 来给候选程序打分，其中 f_orth 是一个正交评估 oracle，设计器本身只能查询 f_opt，看不到 f_orth。这就让外层搜索倾向于选择那些虽然只针对优化 oracle 设计、但产出的序列在独立模型上也能得高分的算法。作者用四个手工算法的描述作为种子（GrAdaBeam、FastSeqProp、Ledidi、Proximal Exploration），让 LLM 各实现两次，再用 ERA 改进。最终选了 FastSeqProp 的两个种子、Ledidi 的一个种子和 PEX 的一个种子，跑了五次搜索，其中四次用单优化 oracle 加一个隐藏正交 oracle，一次同时用 BPNet ATAC 和 ChromBPNet 两个优化 oracle，Enformer 始终完全留出作为最终测试。这样得到十六个 AutoNovo 设计器。搜索完成后代码冻结，再用未见过的 oracle 实例化来测两种泛化：算法级泛化（把冻结程序用到非搜索时的优化 oracle 上）和跨 oracle 序列迁移（用不同 oracle 给设计出的序列打分）。

结果方面，在三个 DNA 设计任务（BPNet ATAC、ChromBPNet、Enformer 预测 K562 染色质可及性）上，AutoNovo 设计器在全部 3/3 直接任务和 6/6 跨 oracle 迁移方向上都取得了最佳观测均值。直接任务中最佳 AutoNovo 得分分别为 -61.17、-74.88、-3360.36，而最强基线均值只有 -40.88、-60.08、-124.53（数值越低越好）。跨 oracle 迁移中，BPNet→Enformer 方向有 15/16 个 AutoNovo 设计器超过最强基线，Enformer 出发的两个方向分别有 13/15 和 12/15 超过。不过 ChromBPNet 作为设计 oracle 时优势不明显，只有 4/16 超过基线。值得注意的是，最佳设计器在不同任务上并不相同：FSP-gradient memory STE 在 BPNet ATAC 上最好，FSP-Best-Anchored STE 在 ChromBPNet 上最好，FSP-sparse restart STE 在 Enformer 上最好。这些获胜程序几乎都来自 FastSeqProp 种子，且九个获胜表项中有八个使用了直通估计器（STE）——即前向用硬 one-hot 序列评估、反向通过软松弛传递梯度。它们共同模式是：梯度优化连续 logits、保留最佳离散序列、在进度停滞时扰动连续状态重启。局限也很明显：没有单一通用最优设计器，ChromBPNet 出发的迁移提升有限，且基线排名与 NucleoBench 原论文不同（主要因为时间预算从 8 小时缩到 30 分钟）。但这项工作的意义在于首次证明智能体程序搜索能发现超越人类手工设计的核酸设计算法，并且通过隐藏正交 oracle 的评估机制，让外层搜索主动偏好跨模型泛化的算法——这为未来设计更可能反映真实生物学的合成序列迈出了关键一步。

### [X-Ragent: Tool-Augmented Reinforcement Learning for Evidence-Grounded Chest X-Ray Reasoning](https://arxiv.org/abs/2610.16811)
`评分3 · HF 66赞`

胸片解读的核心难点在于，诊断结论往往不能只靠一眼看片得出，而需要把视觉发现与任务相关的证据结合起来，比如某个解剖区域是否真的异常、心影是否增大、纵隔是否偏移。现有的工具增强型医学智能体虽然能调用外部模块提供这类证据，但存在三个结构性缺陷。第一是视觉与诊断之间的鸿沟：多模态大模型能整体感知图像，却难以把宏观视觉线索与局部、细粒度的解剖证据或定量指标对应起来，推理过程因此碎片化。第二是证据与诊断不一致：智能体可能调用了工具，却忽略或曲解了工具返回的客观结果，仍然被文本先验牵着走，生成听起来合理但缺乏依据的诊断。第三是测量适用性问题：像心胸比这样的确定性测量只在特定拍摄条件下才有意义，如果没有显式的适用性检查，不适用的定量证据会混入推理并误导最终判断。更麻烦的是，传统训练数据只监督最终答案，不监督证据是如何被获取和整合的，模型学不会“什么时候该找证据”以及“找到证据后该怎么用”。

X-Ragent 的核心设计是把“学出来的证据寻求”和“有效性门控的定量测量”彻底解耦。整个推理分两轮：第一轮，策略网络先对图像和临床问题做一次全局评估，然后自主决定是否调用辅助工具，可选动作包括区域解析、感兴趣区域裁剪和证据查询，调用数量从零到五不等；与此同时，一个独立的有效性门控模块判断当前图像是否满足定量测量的拍摄条件，只有通过时才把心胸比、肺野不对称性和胸廓移位等测量结果暴露给模型。第二轮，策略把第一轮选定的工具返回的视觉与语义反馈，连同门控放行的测量数据，一起整合进多模态上下文，生成完整的推理轨迹和最终答案。训练上分两步：先用他们构建的 Rad-CoT 数据集做智能体监督微调，这个数据集包含七千七百多条样本，其中三千七百多条是带工具调用的两轮轨迹，四千条是报告风格的思维链，所有观测结果都只在对应动作生成之后才被揭示，保证因果顺序；然后用 GRPO 做强化学习，奖励函数的关键创新是一个“准确性门控”：只有最终诊断正确的轨迹，才能获得过程级奖励，包括测量一致性和工具调用成本，这样模型无法用看起来漂亮的过程行为来补偿错误的诊断。视觉精修和知识查询工具不直接接受过程监督，而是通过任务成功间接优化。这套设计让模型学会按需取证，而不是默认把所有工具都跑一遍。

在三个胸片基准上，X-Ragent 都取得了最强结果。完全未参与训练的 ChestAgentBench 上，它从最强基线的 63.1% 提升到 71.7%，涨了 8.6 个百分点，并且在该基准的七项解读能力上全面超过基线，相对其基座模型 Qwen3-VL-8B 提升了 14.6 到 18.3 个百分点。CheXbench 三个子集平均达到 77.3%，比最佳已报告结果高 9.2 个百分点，其中 SLAKE 子集提升 19.5、OpenI 推理子集提升 15.8，而 Rad-Restruct 子集与基座持平。SLAKE 上达到 93.0%，比最佳基线高 2.6 个百分点，相对基座提升 20.2 个百分点。这意味着一个 8B 模型在胸片推理上超过了更大的通用视觉语言模型和基于 GPT-4o 的 MedRAX 智能体。局限方面，Rad-Restruct 子集没有提升，说明对于某些细粒度结构描述任务，当前的工具路由和门控测量可能没有提供额外增益；此外，有效性门控目前只覆盖少数确定性测量，更广泛的定量证据类型尚未纳入。这项工作的意义在于，它把“何时需要证据”和“证据是否可用”拆成两个独立可控的环节，为医学智能体提供了一条可验证、可监督的推理路径，而不是让模型在黑箱中同时学习取证与判断。

### [MFG: Multi-turn Feedback Guided Molecular Optimization](https://arxiv.org/abs/2610.18851)
`评分3`

多目标分子优化（MOMO）在药物发现中是一个核心且棘手的任务：给定一个源分子，需要在保持结构相似性的前提下同时改善多个性质（如溶解度、选择性、毒性等），而这些性质之间往往相互冲突，改善一个可能恶化另一个。近年来，基于大语言模型（LLM）的方法开始被用于这一任务，但存在两个关键瓶颈。第一，已有的迭代式方法虽然在推理时让LLM多轮修改分子并接收反馈，但模型本身从未被训练过如何利用这些反馈，仅仅依赖预训练阶段获得的通用推理能力，导致反馈信号无法被有效内化。第二，那些用监督微调或强化学习训练的方法，全部局限于单轮生成范式——模型一次性输出优化后的分子，没有多轮迭代调整策略的机会。单轮范式的根本问题在于：MOMO任务的化学空间极其复杂，不同源分子的优化模式并不一致，一次性生成很难在多个竞争性性质之间找到好的平衡点，而多轮迭代恰恰提供了试错和策略调整的空间。这篇论文正是要填补这一空白：让LLM在多轮交互中学会利用反馈来逐步优化分子，而不是把每轮优化当作独立的一次性生成。

MFG的核心设计可以拆成三个相互咬合的模块来理解。首先是问题重构：把MOMO从单轮生成重新定义为带反馈的多轮决策过程，LLM作为策略网络，在每一轮t接收源分子、目标性质集合以及之前所有轮次的历史记录，生成候选分子，然后环境返回一个反馈向量——这个向量的前m维表示每个目标性质相对于源分子的改善或退化程度，最后一维表示与源分子的Tanimoto相似度。这个反馈向量会被拼接到下一轮的输入中，让模型知道自己上一轮改了什么、效果如何。其次是训练算法：MFG采用GRPO（Group Relative Policy Optimization）进行强化学习训练，每一轮采样多个候选分子，根据它们的相对奖励来更新策略，训练时随机采样轮次t，确保模型在每一个轮次上都学会利用反馈。这里的关键洞察在于，GRPO的组内相对比较机制天然适合处理奖励稀疏的问题——即使所有候选分子的绝对奖励都不高，组内相对排序仍然能提供有效的学习信号。第三是奖励函数的设计，这是整个框架最精巧的部分。奖励函数采用分层结构：如果候选分子与源分子的相似度低于阈值δ，直接给一个基于相似度的惩罚，完全不考虑性质改善，这防止了模型通过大幅改变结构来刷性质分数；如果相似度达标，则进入基础奖励，基础奖励由两部分组成——性质改善的归一化平均值和相似度的归一化值，归一化用的是参考优化分子的对应值，这样就消除了不同性质之间数值尺度的差异；此外还有一个放大因子λ，只有当候选分子同时改善了所有目标性质时才生效，相似度越高放大倍数越大，这鼓励模型追求全面的性质提升而非在某一两个性质上刷高分。最后还有一个渐进奖励项，将当前候选分子与之前所有轮次中通过Advance准则选出的最佳分子进行比较，如果当前分子的基础奖励更高，就给予额外奖励，这直接激励模型在多轮中持续进步而非原地踏步。Advance准则本身是一个分层选择机制：优先选相似度达标的，再优先选改善性质数量多的，而非改善幅度大的，这保证了优化方向的广度优先于局部极值。推理时，每一轮采样N个候选，用Advance准则选出一个带入下一轮，最终从所有轮次的所有候选中选出最终输出。

在MuMOInstruct基准上，GeLLM³O-MFG在十个多目标优化任务上取得了81.50%的平均相似度约束成功率，显著超过了基座模型GeLLM³O的70.81%和最强基线BioMedGPT-Mol的77.81%，提升幅度接近11个百分点，这在分子优化任务中相当可观。消融实验进一步证实，多轮反馈机制和强化学习训练各自贡献了独立的增益，说明两者不是简单的叠加而是互补的。案例分析展示了模型如何根据反馈调整策略——比如当某一轮的性质改善不理想时，下一轮会尝试不同的结构修饰方向。不过，这项工作仍有局限：反馈向量目前只包含性质变化和相似度两类信息，没有纳入更细粒度的化学知识（如合成可及性、代谢稳定性等），而且训练和评估都基于MuMOInstruct这一个数据集，跨数据集的泛化能力尚未验证。此外，多轮迭代带来的推理成本是单轮方法的T倍，在实际药物发现流程中需要权衡精度和效率。从方向上看，MFG首次将多轮强化学习引入分子优化LLM的训练中，开辟了“让模型学会利用反馈”而非“让模型一次性猜对”的新范式，这对于任何需要迭代决策的分子设计任务——比如多步逆合成规划、蛋白质序列优化——都有直接的迁移价值。

### [GreenWAM: A World Foundation Model for Robotics](https://arxiv.org/abs/2610.18774)
`评分3 · HF 82赞`

机器人要真正干活，得同时具备两种能力：一是世界模型，能预测自己的动作会把场景变成什么样；二是策略，能根据当前情况挑出合适的动作。但过去的研究基本把这两件事分开做——要么只训练一个预测模型来评估其对物理世界的理解，要么只训练一个策略网络来完成任务，很少有一个统一模型同时把两个角色都扛起来。更麻烦的是，不同机器人记录动作的方式五花八门，双臂机械臂、灵巧人形、单臂抓手各有各的关节定义和坐标系，导致在一个机器人上训好的模型很难直接迁移到另一种身体上。这就带来一个核心问题：能不能用一个统一的机器人世界模型，跨不同身体形态同时充当预测器和控制器？如果能，又是什么设计让这件事成立？之前的方法卡住的地方在于，它们要么针对单一本体做特化，换一个机器人就失效；要么把动作空间强行对齐到某个公共表示但丢失了关节层面的物理含义，预测出来的轨迹根本没法执行。GreenWAM 这篇论文就是冲着这个缺口去的。

它的核心思路分三层。第一层是定义一个共享的解剖学动作空间，把 20 种机器人家族——从双臂操作臂到高自由度人形——统一用公共关节坐标来描述。这不是简单地把动作归一化到零到一，而是保留每个关节的物理语义，让不同机器人之间的动作在同一个坐标系里有可比性。第二层是联合训练：在同一个模型上同时跑三种模式——纯视觉预测、动作条件预测、以及世界-动作联合建模。视觉模式让模型学会场景的时空演化规律，动作条件模式让它理解“如果我这么做，世界会怎样”，世界-动作模式则把预测和决策耦合起来，迫使模型学到的表示既能支撑前向模拟，又能支撑反向推理。第三层是策略的拆分：在适配到具体机器人时，从生成器里分出一个动作专家模块，专门负责输出可执行的动作序列。这个拆分的关键在于，动作专家不是从头训的，而是从已经具备世界预测能力的生成器里“切”出来的，所以它天然继承了场景演化的先验。训练时还发现一个反直觉的结论：在策略适配阶段保留世界模型的训练模式，能显著提升对场景变化的鲁棒性，而不是像常见做法那样只微调策略头。换句话说，它之所以比之前的方法好，是因为没有把预测和控制当成两个独立任务，而是让它们共享同一个表示空间，并且用解剖学动作空间保证了跨本体的可迁移性。

在结果上，作为世界模型，GreenWAM 在 WorldArena 1.0 上拿到了顶级的轨迹、深度和三维精度，超过了所有对比的世界-动作模型和视频生成器。作为策略，它在 RoboTwin 2.0 排行榜上名列前茅，在 LIBERO-plus 上取得了对比方法中最高的零样本成功率，在 CALVIN 和 LIBERO 上也与专门的视觉-语言-动作模型和世界-动作策略打得有来有回。更关键的是，它被适配到一台真实人形机器人上，成功率超过了从 π_{0.5} 和 Cosmos 3 Edge 适配过来的策略，并且通过蒸馏变成了单步策略，能跑实时控制。消融实验给出了三个明确发现：机器人特化能同时提升世界预测和控制；动作专家在适配初期就拆出来效果最好；策略适配时保留世界模型模式能保住对场景变化的鲁棒性。局限也很明显：共享动作空间目前只覆盖了 20 种机器人家族，更奇特的形态比如软体或轮足混合还没验证；联合训练的计算开销比单独训一个模型大得多；蒸馏到单步虽然能实时，但会损失一部分预测精度。不过这篇论文的意义在于，它用实验证明了世界模型和策略不是非此即彼的选择，而是可以互相增强的，这可能会推动后续研究把更多精力放在统一架构和跨本体动作表示上，而不是继续割裂地刷各自的榜单。

### [LeWAM: End-to-End World and Action Modeling with JEPAs](https://arxiv.org/abs/2610.12818)
`评分3 · HF 62赞`

这篇论文要解决的核心问题是：如何让基于视觉的智能体在没有奖励信号、也不重建像素的前提下，学到一个既能预测动作后果、又能直接输出动作的紧凑世界模型。此前的主流做法是联合嵌入预测架构（JEPA），它在潜空间里预测未来状态，避免了对像素的浪费式重建，但存在两个结构性缺陷。第一，视觉表征、动作条件动力学、控制策略这三者是分开训练的：要么先用预训练编码器（如 DINOv2）冻结特征再学动力学，要么用分布正则化（如 SIGReg）从零训练表征，然后另外接一个策略或求解器。这种分离导致动作监督信号无法反过来塑造视觉表征，表征里可能保留对控制无用甚至有害的信息——比如时间上持续存在的干扰物，或者与动作无关的观测细节。第二，测试时的控制依赖在线求解器，最典型的是交叉熵方法（CEM）。CEM 从一个宽泛的高斯先验里采样大量动作序列，再通过模型 rollout 评估，动作维度或规划视野一大，需要的采样和 rollout 就爆炸式增长；而且接触丰富的操作任务里动力学会在不同模式间切换，局部动作优化很容易失效。虽然后来有 GC-IDM 这类后训练动作预测器、或 PRISM 这类在冻结世界模型特征上训练高斯先验来引导 MPPI 采样的方法，但它们都建立在冻结的 JEPA 嵌入之上，动作监督和视觉表征学习仍然是断开的。

LeWAM 的关键洞察是：把表征学习、动作条件潜动力学、以及一个随机策略，全部塞进同一个训练阶段，让它们互相塑造。具体架构上，编码器用 ResNet-18 加空间 softmax 池化和两层 MLP 投影，同一个编码器处理历史帧、未来目标帧和 goal 图像。预测器采用 Mixture-of-Transformers（MoT）结构，分成状态分支和动作分支：每个分支有自己独立的 query、key、value 和前馈投影，但共享一个带掩码的自注意力。这种设计让两个模态能交换信息，又不会让动作分支通过历史潜变量间接“偷看”干净动作。训练目标有两个：一是下一潜状态预测，用 MSE 回归未来帧的潜表示；二是动作流匹配（flow matching），对记录的动作块加噪后回归速度场，让动作分支学会从噪声中恢复动作分布。这里有个精巧的细节：同一个预测器，状态分支读的是干净动作来预测未来潜状态，动作分支读的是加噪动作来学策略，两个目标共享视觉表征，于是动作监督直接成了表征学习的信号。此外还用 SIGReg 对潜状态施加各向同性高斯约束，防止表征坍缩——论文发现，没有 SIGReg 时纯潜变量的 LeWM 在 Push-T 探针上 R² 直接是 0，而 LeWAM 即使只加动作头也能保持可解码的状态和动作信息，说明动作监督本身起到了反坍缩信号的作用。控制阶段，LeWAM 支持两种模式：直接控制就是从学到的动作分布里积分速度场采样一个动作块，执行前 K 步再重采样；规划则是从学到的动作分布里采 N 个候选动作序列，每个候选交替做动作采样和潜动力学预测，生成完整计划后，再用梯度下降通过可微的潜动力学去优化到目标潜状态的代价，最后选代价最低的。相比 CEM 从宽高斯先验盲目搜索，LeWAM 的采样先验已经由策略学到的动作分布收窄了搜索空间，而梯度优化又能利用 GPU 并行性，所以规划效率大幅提升。

实验结果覆盖十个异构的模拟导航和操作环境，数据包括专家演示、随机策略交互和混合质量数据。在视觉规划设定下，LeWAM 平均成功率 93.5%，而 LeWM（CEM）只有 50.9%，差距 42.7 个百分点；在接触丰富的 ToolHang 上从 35.4% 提到 94.7%，Transport 上从 2.8% 提到 83.3%，逻辑结构化的 Puzzle 上从 GCBC 的 44.0% 提到 80.7%。长视野规划中，把目标沿轨迹推远到 100 步偏移，LeWAM 在 Push-T、Cube、Scene、Puzzle 四个任务上平均成功率 46.2%，LeWM 只有 10.9%。规划速度上，LeWAM 平均每秒 52.50 个计划，LeWM（CEM）只有 1.62 个，加速 32.3 倍。行为克隆任务里，在模拟和真实机器人上 LeWAM 也与已有方法竞争力相当。线性探针显示，联合训练动作建模目标后，本体感觉、动作和 IDM 的 R² 分别平均提升 0.21、0.20、0.19，说明表征确实编码了控制相关的物理状态和动作信息。局限方面，LeWAM 目前仍假设能拿到目标图像嵌入和剩余视野信息，规划时的梯度优化依赖潜动力学可微，且实验规模大约 17M 参数，尚未在更大规模的真实机器人数据上验证。但它的意义在于证明了：JEPA 不必把表征、动力学和策略割裂开训练，动作监督可以成为表征学习的有机组成部分，同时兼作反坍缩信号；而把随机策略学到的动作分布作为规划的先验，再用梯度优化精炼，能在保持规划质量的同时把速度提升一个数量级以上。这为视觉控制中世界模型与策略的端到端联合学习提供了一个简洁而有效的范式。

### [The Last Remote Sensing Model Built by Humans? Casting Any Earth Observation Task as Recursive Self-Improvement](https://arxiv.org/abs/2610.18845)
`评分3 · Ongoing project`

这篇论文要解决的是遥感领域一个长期存在但很少被正面挑战的痛点：地球观测模型至今仍然是“手工打造”的。每来一个新传感器、新区域或新任务，专家就得重新选骨干网络、设计训练配方、对着基准调参，一轮工程下来动辄数周甚至数月。基础模型虽然抬高了起点，却没有消除这个循环——在PANGAEA基准上，它们甚至不一定稳定超过一个监督训练的UNet。问题在于，遥感任务在传感器、区域、标签体系上极度多样，专家工程时间决定了到底有多少任务能拿到一个足够强的模型。而最需要模型的场景恰恰最缺人：灾害发生后、新卫星上线后、 wildfire、洪水、森林损失需要在全新区域快速制图，往往要求几天内出模型，但很多机构和国家根本没有机器学习团队。与此同时，AI进步最快的领域都有一个共同点：成功可以被自动检验。数学推理、程序发现、机器学习竞赛，都是靠验证器驱动，编码智能体已经能连续数小时写、跑、调试训练代码。但遥感领域的智能体此前只是编排人类预先搭好的固定模型和工具，或者对全监督基线做一两个点的微调，没有人真正把“遥感任务本身”交给智能体去端到端解决。

论文的核心洞察是：任何可验证的任务都可以被拆成“harness”和“verifier”两部分。Harness定义智能体可以使用什么——有标签数据、无标签数据、预训练权重、软件库、算力预算；verifier定义什么算成功——它在一个智能体永远看不到的留出集上运行智能体提交的完整pipeline，返回一个分数。遥感恰好拥有异常丰富的验证来源：社区基准的留出标签、独立传感器、实地测量、物理模型一致性、对同一地点的重复观测。于是构建遥感模型就变成了对着验证器做优化，而过去被当作独立研究问题的少样本学习、域适应、标签预算搜索，全都退化成这两个组件的不同配置选择。具体运作上，智能体在离线容器里工作，自己写训练代码、训练模型、调用验证器查询分数、决定下一步尝试什么。验证器是密封的，只通过工具调用返回分数，验证图像和标签从不进入智能体视野。更关键的是递归自我改进：智能体把每一代训练出的模型当作下一代的学习材料，上一代在无标签池上的预测、类别概率、检查点、在训练数据折上的预测，都成为下一代的输入。外层循环是智能体提出pipeline、验证器打分；内层循环是每一代保留的模型成为后继模型的素材，模型沿一条谱系不断进化。智能体自己设计这个递归——它可以选择在数据层面做硬伪标签或软概率蒸馏，在参数层面从早期检查点初始化或做权重平均，在预测层面训练校准器或掩码精修网络。论文举了一个具体例子：只给六张有标签图像，智能体跑了八代自训练，每一代都由验证器见过的最佳pipeline来教，最后还用自己的脚本把这个循环自动化了。这套设计之所以比之前的方法更强，是因为它不再依赖人类预设的搜索空间或固定的模型编排，而是让通用编码智能体在任意代码空间里自由探索，验证器则保证探索方向不跑偏。

实验结果相当有冲击力。在四个有公开结果的遥感基准上——土地覆盖制图、光学与SAR建筑损毁评估、SAR船舶实例分割、Sentinel-2时间序列作物类型制图——智能体构建的模型全部超过了当前最优水平，每个任务在四块GB200 GPU上12小时内完成。更值得注意的是标签效率：只用训练集0.1%到1.4%的标签，模型就能保留大部分精度。在OpenEarthMap上，六张有标签图块达到60.0测试mIoU；而用300个无标签选择出的图块，就足以超过所有用全量标签训练的已发表方法。两个以截然不同方式构建模型的智能体都超过了已发表的最优结果。这指向一个范式转变：人设计harness和verifier，智能体构建模型，任务的两个组件保持固定而智能体不断进步，遥感模型就能随智能体一起变强，不再需要新的人类工程。从新需求到可用模型的时间缩短到智能体的预算之内——灾害后标注几对图像、定义成任务，一天内就能拿到损毁模型。当然，论文也坦承这是进行中的项目，目前只在四个基准上验证，验证器主要基于有标签留出集，尚未充分利用物理模型和重复观测这些遥感独有的验证源；智能体在离线容器中运行，算力和时间都有硬约束；递归自我改进的深度和稳定性在不同任务间是否一致，还需要更大规模的实验来确认。但它的意义在于把研究问题向上游推移：哪些验证器能忠实捕捉任务、harness必须包含什么，以及标注工作从训练集转向验证器背后的留出集——而每个基准其实早就标注好了。

### [SEAR: Self-Evolving Agentic Robotics](https://arxiv.org/abs/2610.18792)
`评分3 · 16 pages`

这篇论文要解决的核心问题是：当语言模型智能体被允许“自我进化”式地改进机器人时，我们看到的成功率上升到底是真的学习，还是只是多试了几次、运气好、预算更大、或者偷看了仿真器特权状态？过去的工作（如 Fu、Zhang、Lu、Xiao、Waddle Labs 等系统）各自定义自己的评测协议，每个系统都报告自己的曲线在涨，但没人能回答两个关键问题：第一，智能体是真在学习，还是只是重采样次数更多？因为更多独立尝试本身就能解更多题，一次幸运的成功、更大的时间预算、或者真机永远看不到的仿真器内部状态，都能让曲线好看。第二，学到的东西换个地方还有用吗？在练习任务的留出初始状态上成功，只是离练习最近的一小步；真正值得保留的经验应该还能帮到新任务、新仿真器、甚至真机。由于缺乏统一的对照协议，这些系统的结果既不能互相比较，也无法回答上述任一问题，这就是 SEAR 要填补的空白。

SEAR 的方法核心是把“自我进化”拆成可对照的实验设计，并给出三种运行智能体的模式。第一种是 code-as-policy：语言模型写一段 Python 程序，这段程序本身就是策略，执行时不再调用模型，因此策略快、可重放、可被独立重打分；程序里通常不包含学习到的动作模型，而是调用感知、逆运动学和伺服工具，预训练的 VLA（π0.5）虽然也在工具箱里，但几乎不被最终程序使用。第二种是 agent-as-policy：模型留在控制回路里，根据实时观测逐条选择命令，每条命令都要等一次模型调用，所以慢、评估成本高。第三种是 auto-research：智能体把 code policy 当教师收集 rollout，筛选数据后微调 VLA，再评估并决定下一步实验。三种模式共享同一套工具（SAM3 分割、π0.5、IK 与伺服接口），每个任务从空工作区开始，任务之间唯一持久化的是 library——由每个已完成任务的最佳策略中提取的版本化代码技能和文字记忆，AR 的检查点和数据不跨任务传递。为了把“真学习”和“多试几次”分开，SEAR 设计了匹配对照：best-of-3 把同样总预算拆成三次短尝试取验证集最高分，用来模拟“多试几次”；无 library 的 Vanilla 用来隔离继承经验；密封裁判（sealed judge）持有留出初始状态和评分逻辑，只对冻结后的程序或检查点打分，忽略策略自称的成功；多次重复运行暴露运气成分；五个泛化层级（T1 同任务新初始状态、T2 变条件、T3 同仿真器新任务、T4 新仿真器与动作 API、T5 真机）衡量收益能走多远。关键洞察在于：短尝试是否划算取决于“模型首次成功所需时间”与“单次短尝试时长”的相对关系——如果模型在短尝试内就能首次成功，拆成三次短跑和一次长跑差不多；如果首次成功要一小时而短尝试只有四十分钟，拆分就会损失 5 到 24 分，因为短尝试常常在提交策略前就结束了。library 的增益则呈倒 U 形：模型单独得分高于 80% 时几乎无增益，低于 30% 时模型很少复用保存的东西，只有在 30% 到 80% 之间增益最大，例如 Gemini-3.6-flash 在 LIBERO-RIG 隐藏故障下被 library 提升 46.6 分，Kimi-k3 在 RoboLab 从 30.1% 升到 51.9%。而且 library 的内容比模型本身更重要：有用的技能（如根据开口测量控制夹爪、偏航对齐、捏取）能跨任务和仿真器迁移，而错误信念（如从旧任务继承的阈值和偏移）会被一路带下去，GPT-5.6-sol 在 RoboLab 上从 46.9% 降到 42.4% 就是例证。跨模型继承也成立：GPT-5.6-sol 用别人的 library 反而从 46.9% 升到 60.6%，说明经验以代码形式保存时可以跨模型迁移。

在结果层面，SEAR 在七个前沿语言模型、330 个仿真任务（两个物理引擎）和五个真机任务上运行了超过四年的智能体总时长，给出了几个有数字支撑的发现。学习确实发生，但并非总是：在 robosuite 上 Opus 一小时长跑得 93.8% TEST，三次二十分钟的 best-of-3 得 90.0%；在 RoboLab 上 GPT-5.6-sol 和 Gemini-3.6-flash 因首次成功在 40 分钟内，best-of-3 反而分别高出 1.6 和 2.8 分，而 Opus 和 DeepSeek-v4-flash 因首次成功约需一小时，拆分损失 5 到 24 分。library 的增益在 30% 到 80% 区间平均 12.0 分，高于 80% 时仅 0.9 分，低于 30% 时 3.0 分；跨 1510 个模型-任务对，library 的帮助稳定在 8 到 10 分。迁移方面，抓取和控制例程能跨任务与仿真器复用，一个在不知道任务前写好的程序能在未探索过的场景中成功；代码策略在相机不动而硬件出故障时仍工作，训练过的 VLA 在相机移动时仍工作；但真机上练习成功会高估新场景成功。模型选择上，最强模型在每个仿真家族领先，且任务越难差距越大；纯文本模型 DeepSeek-v4-flash 在 RoboLab 上甚至超过同通用能力分数的多模态模型，说明感知有助于错误评估，但智能体推理和工具使用可能更重要；GPT-6-astra 在真机上从冻结代码策略的 41% 升到实时行动的 88%，但实时行动中位耗时 12.8 分钟机器人时间，远高于冻结策略的 3.8 分钟。局限也很明显：library 可能有害，弱模型很少复用保存内容，真机与仿真之间仍有差距，AR 只在部分套件上单次运行，密封裁判仍被智能体找到过绕过方式（如从资产文件读取物体几何）。尽管如此，SEAR 的意义在于把“自我进化机器人”从各自为政的演示变成可对照、可复现、可跨模型和跨仿真器比较的基准，并明确指出：要让经验真正有价值，关键不在于让模型多试，而在于让它在正确的时间尺度上持续努力，并把可迁移的代码技能和记忆而非任务特定的解保存下来。
