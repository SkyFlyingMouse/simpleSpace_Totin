## 大模型 LLM

### [Look Only When Needed: Certificate-Guided Visual Routing for Efficient Diffusion VLMs](https://arxiv.org/abs/2610.36671)
`评分3 · HF 98赞`

这篇论文要解决的是扩散视觉语言模型（DVLM）在推理时算力浪费的真实问题。以 LLaDA-V 为代表的扩散 VLM 采用双向注意力，无法像自回归模型那样直接用精确的 KV 缓存，因此标准解码在每一个去噪步都要把整个多模态序列重新过一遍前向。而视觉 token 在这些基准上占输入的 89% 到 97%，也就是说绝大部分解码算力都在反复处理同一张没变过的图，一次去掉视觉 token 的前向只需要完整前向 3% 到 10% 的开销。已有的加速路线各有盲点：视觉 token 剪枝（如 RedVTP、ZOO-Prune、D3ToM）确实减少了每次前向处理的 token 数，但被剪掉的信息就永久丢了，而且剩下的图仍然每一步都要过；中间状态缓存（如 Fast-dLLM 的块级近似 KV 缓存）复用的是计算而非判断"这一步到底要不要看图"；解码调度方法（如 KLASS、Prophet）则专注于一步多解掩码 token、减少步数，同样没有回答图像访问的必要性问题。作者的关键动机来自一个直接测量：沿 LLaDA-V 的标准解码轨迹，在每一步同时跑一次带图的完整前向和一次去掉视觉 token 但保留位置 ID 的纯文本前向，结果发现被选中解掩码的位置里有 83.4% 在两次前向中给出相同的 top-1 预测，最终 token 中有 85.0% 在解掩码之前就已经以 top-1 形式出现过；平均只有 22.8% 的步会因去掉图像而改变解掩码决策，且这个比例在不同基准间从 MMBench 的 7.9% 波动到 DocVQA 的 43.8%，依赖图像的步还倾向于聚集在解码早期而非周期性出现。这说明固定调度很难贴合真实轨迹，必须做输入相关、步相关的自适应判断。

LOWN 的核心设计是把标准解码中一次完整前向同时承担的两个决策拆开：这一步要不要看图，以及这一步能推进多少 token。它维护一个"锚"（anchor），即最近一次带图完整前向在仍被掩码的位置上留下的 top-1 预测和置信度。每一步先跑一次廉价的纯文本前向，按锚置信度从高到低扫描掩码位置，若某位置的纯文本预测与锚一致，该位置就被"认证"（certified）；一旦遇到第一个不一致，认证前缀就此截断。这个一致性检验很巧妙：两次预测的差异既来自是否看到图像，也来自所依据的响应状态已经变化，因此一致同时近似了两个条件——这个 token 不需要图像，且锚在状态变化后仍然有效，从而避免了依赖绝对置信度阈值。认证前缀的长度直接决定步的类型：若前缀长度不少于基线每步解掩码的 k 个 token，这一步就跳过完整前向，把整个前缀按锚预测全部解掩码——注意这可能多于 k 个，正是这种"整段接受"让纯文本步能比基线推进得更远、总步数更少；若前缀不足 k，说明锚已无法认证足够 token，则触发一次完整前向，用新预测替换整个锚，并按"不一致优先"顺序解掩码 k 个位置（纯文本与完整预测不同的位置排前面，其余按完整置信度排序）。两个分支都至少解掩码 k 个 token，因此 LOWN 的步数不会超过基线的 T 步。方法完全免训练、免调阈值，只保留预测结果而不触碰模型参数或注意力模式，因此天然能与剪枝、KV 缓存正交组合：剪枝降低每次完整前向的成本，LOWN 降低完整前向发生的频率，成本公式上分别对应乘性的 π 和 f 因子。作者也诚实指出锚会随响应演化而"变旧"、认证错误随年龄增长，所以每次完整前向都整体替换锚以保证认证针对最新预测。

实验在 LLaDA-V 和 LaViDa 两个骨干、十个基准（MathVista、ScienceQA、ChartQA、MME、MMBench、DocVQA、GQA、LLaVA-Bench、CapArena、DeCapBench）上展开，并额外在 VidLaDA-8B 的视频基准 EgoSchema 和 MLVU 上验证迁移性。独立运行时 LOWN 在平均 0.353 倍解码 FLOPs 下保留了基线 99.6% 的分数，十个基准中有八个在同等或更低算力预算下优于 RedVTP、ZOO-Prune、KLASS、D3ToM 等加速方法；若把超过基线的四个基准截断在 100% 以防其增益掩盖别处损失，仍有 98.6%。与 KV 缓存或视觉剪枝组合可再削减伙伴方法 1.8 到 2.5 倍的 FLOPs，配合 KV 缓存时端到端解码速度比原模型快 5.6 到 7.0 倍。消融显示视觉路由单独就能在 ScienceQA 和 CapArena 上超过基线，不一致优先的解掩码顺序进一步把 ChartQA 和 DeCapBench 抬到基线之上，十个基准中七个因此提分；对认证可靠性的测量则表明，用一步旧的锚做认证时，新鲜完整前向会推翻 4.1% 到 11.0% 的已认证 token，而 LOWN 实际运行中纯文本步解掩码的 token 只有 2.2% 到 4.7% 被推翻，说明认证误差可控。局限方面，方法的收益高度依赖纯文本前向相对完整前向的成本比 ρ，视觉 token 占比越低（如视频或长 prompt 场景）收益就越小；认证本质上是一种启发式近似，锚老化在响应剧烈变化的轨迹上仍可能带来质量损失；此外它只决定"何时看图"，不减少单次完整前向内部的成本，因此与剪枝、缓存是互补而非替代关系。总体而言，这篇工作把"图像访问的必要性"从被忽视的隐变量提升为可在线检验的决策对象，用预测一致性这一零成本信号同时控制路由与解掩码节奏，为扩散 VLM 的高效推理提供了一个与现有加速手段正交的新维度。

### [Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities](https://arxiv.org/abs/2610.39301)
`评分3 · HF 67赞`

这篇论文要解决的是多模态智能体在真实场景中“读材料”的成本与可审计性问题。当前 LLM 智能体越来越多地需要处理文档、图像、音频和视频，但让驱动智能体的主模型直接消费这些原始输入代价很高：每次回看材料都要重新编码长序列的视觉和声学 token，而且从原始像素或波形得出的答案本身无法说明它依据的是哪个区域或哪段时间。多模态解析的思路是把每种输入一次性转换成结构化的文本记录，既说明“有什么”，也说明“在哪里/什么时候”，这样任何 LLM（包括纯文本模型）都能读取并追溯证据。但现有解析器只覆盖了部分输入类型：文档解析在标准页面上已经很强，但化学结构、乐谱这类符号内容仍主要依赖领域专用模型；多模态模型大多面向描述和问答而非带定位的结构化输出，跨图像、音频、视频的解析直到最近才有专门基准。结果是不同输入类型由不同模型、不同输出格式分别服务，而它们的目标输出其实是同一种东西——以空间或时间为锚点的结构化记录。要造出统一解析器面临两个挑战：其一是跨模态联合感知，现有全模态模型（包括 Logics-Parsing-Omni）把视觉编码器和音频编码器分开预训练，导致各模态孤立编码、语言模型只能从分离表示中推断跨模态关系，两个编码器各自独立索引时间、同一瞬间的画面和声音在感知层不共享时间位置，且每个新模态都要再加一座塔；其二是跨任务联合优化，同一个模型要在十个输出字段各异的任务上同时优化内容准确性、时空定位和 schema 合法性，SFT 只在参考前缀上训练、从不接触模型自己推理时产生的前缀，而带可验证奖励的强化学习虽然用模型自己的输出训练，却需要难以在异质标准间定义的标量奖励、只给序列级反馈。

方法上的核心创新可以概括为“一个编码器、一个 schema”。编码器方面，Youtu-Omni-Encoder 用单个共享 Transformer 取代视觉和音频两座塔，并且从预训练语言模型初始化以强化文本读取能力；只有输入 stem 和输出 projector 是模态专属的，占编码器参数很小一部分，绝大部分感知参数跨模态共享。图像和视频帧按原生分辨率切 patch、经一个线性映射变成 token，音频转 log-mel 后经几层带步长卷积降采样再线性映射，得到固定 token 率；共享 Transformer 用标准 pre-norm 块（RMSNorm、SwiGLU、GQA、QK-Norm），双向注意力，RoPE 从逐 token 旋转角矩阵施加而非读单一位置表，这正是轴分解位置编码得以表达的前提。位置编码把旋转预算切成 T、H、W 三段近似等长的连续区段，每段有自己的逆频率表并按自身宽度归一化，使每个轴都覆盖完整频率范围；视觉 token 的 t 取自帧索引、(h,w) 取自 patch 位置，音频 token 的 t 取自时间偏移、h=w=0，于是两种模态写入同一个 T 段、在同一时间尺度上表达时间位置，模态身份交给特征本身区分。共享时间线只让位置可比，融合才让二者真正交互：视频可以走独立路线（每帧、每段音频各自成注意力窗口）或融合路线（按时间顺序打包，在若干融合层里让一帧关注同一瞬间的声音），融合层把打包事件按“一帧或多帧加其后、下一帧之前的音频块”切成组，每组一个注意力窗口，组内视觉和音频按与音频 token 率挂钩的共同时间尺度推进，从而在感知内部完成跨模态融合与时间对齐，只把跨窗口依赖留给语言模型；由于窗口只由累积长度向量指定，融合是逐层选择，同一份打包特征同时携带融合与非融合两套分段，旋转注意力分数只依赖查询与键的偏移、查询不会遇到其他窗口的键，所以两套分段给同一 token 不同时间原点也无害。schema 方面，OmniSchema 把十个任务（图像上的文档、化学结构、乐谱、图表、流程图、几何图形、自然图像，音频解析，以及自然视频和文本丰富视频解析）的输出统一为 JSON：必有 modality、带定位的单元列表（图像为 bounding box 归一化到 0–1000 的 element，音频视频为带起止时间戳的 segment，语音段还带一致的说话人标识）和 global_description，另有 subtype、reading_order、structured_report 等按任务可选字段，每个单元的内容字段承载该区域或区间提取的信息（文本、OTSL 表格、SMILES、ABC 记谱、Mermaid 图、ASR 文本等）。因为所有输出都遵循同一 schema，每个 token 都能被识别为内容或结构，于是同一个基于 token 角色的目标可以跨任务使用。后训练流程是 SFT 加 schema 路由的 RLVR 之后接一个自演化的 OSAD：不用序列级奖励，而是在模型自己的 rollout 上取 token 级目标，目标由一份冻结的、额外以参考解析为条件的自身副本提供，每轮结束后训练好的学生成为下一轮教师，解析器与其监督共同演化，既不需要手工设计奖励也不需要单独训练教师。

结果上，单个 5B 参数 checkpoint 同时服务十个解析任务：在 OmniDocBench v1.6 上拿到 96.96 的总体分数，为当前最优；在 OmniParsingBench 上以 75.08 的平均分领先所有开放权重模型，超过 Logics-Parsing-Omni 的 72.26，优势集中在音频和视频；图表解析总体得分 95.02 为对比系统中最高，化学结构精确指纹匹配率 Tani@1.0 达 54.2、高于 DeepSeek-OCR 2 的 49.6，排版乐谱字符错误率 22.73，与专用模型 LEGATO 原论文报告的 23.30 相当，同时远好于通用系统。这些结果说明一个编码器加一个 schema 既能支撑广泛的多模态解析，又能保留专用模型的精度。局限方面，论文自己也指出新增模态虽只需新 stem 和 projector、不必再建一座带独立预训练谱系的塔，但共享权重仍须在新输入上训练；融合只在短音频-视觉窗口内于感知层完成，跨窗口依赖仍交给语言模型；视频走融合路线的概率从第二阶段起被设为小于 1，说明两条路线需并存以保证推理可用。更宏观的影响是，它把解析定位为非文本输入与语言模型推理之间的感知层，用统一 schema 让输出可追溯、可引用，为智能体“读、定位、引证”证据提供了可审计的基础设施，也提示跨模态感知参数的共享与 token 角色驱动的自演化监督是多模态解析值得继续推进的方向。

### [Read, Allocate, Route: Role-Coupled Tokenization for Pixel-Space Generative Transformers](https://arxiv.org/abs/2610.40647)
`评分3 · HF 36赞`

这篇论文要解决的是像素空间生成 Transformer 的一个根本性算力瓶颈。当前主流的像素空间生成模型（如 JiT）直接在像素上做扩散/流匹配，省去了预训练自编码器及其压缩瓶颈，但代价是必须把全分辨率图像表示成 Transformer token。问题在于，绝大多数像素空间 Transformer 采用"一个图像 patch 对应一个 token"的范式，于是 patch 网格同时决定了三件事：模型读什么、每个 token 预测什么、以及有多少 token 参与全局注意力。这导致输出细节和通信成本被死死绑在一起——想要更细的细节就得缩小 patch，而 patch 缩小会让 token 数按平方增长，全局注意力的二次项随之爆炸（例如 256×256 图像上 patch 从 16×16 降到 8×8，token 数从 256 涨到 1024，稠密注意力的二次项增大 16 倍）。已有方法从不同角度绕这个成本：JiT 让所有 patch token 都走全局序列；多尺度系统把细节挪到额外阶段或 detailer head；高效注意力用窗口、少量全局 token 或学习到的稀疏模式压缩序列；Spectral Forcing 引入频率结构但只用来过滤噪声输入，token 仍是空间 patch。这些方法的共同前提没变——输出细节始终绑定在空间 patch 网格上，即使通信被压缩或限制，token 的"身份"仍由它所在的位置决定，而不是由它产出什么决定。论文的关键观察正是：更细的细节并不必然需要成比例更多的全局通信。在频域里，低频结构承载图像的整体组织、受益于长程交换，而高频细节基本是局部的；一个承载粗结构的 token 值得和全图交换信息，一个承载细节的 token 则基本不需要。但现有设计里 token 通信什么是由它坐在哪里决定的，不是由它产出什么决定的——能否让 token 的输出角色反过来决定它该如何通信？

SpecSlot 的核心设计就是把"输出角色"显式化，并用它来控制通信，整体围绕 Read、Allocate、Route 三个操作组织。Read 阶段在空间 anchor 网格上采集输入证据：用共享投影把每个 s×s 输入单元映射成 anchor 向量，接一个零初始化的残差深度可分离 3×3 卷积（input mixer）让相邻单元先交换证据，再用共享 1×1 投影把每个 anchor 向量扩展成 K 个 slot 隐状态，加上二维 anchor 位置和可学习的 slot 位置。注意一个 anchor 向量播种全部 K 个 slot，角色来自 slot 位置、输出头和路由，而非输入。Allocate 阶段解决"谁产出什么"：把输出窗口（边长 L=2s）的 DCT-II 系数按径向频率 u²+v² 排序后等分成 K 组，每个 slot 固定拥有第 k 组、即每通道 E=L²/K 个系数，各组互不重叠、恰好覆盖整个网格，每个系数只被预测一次；共享仿射头从 slot 最终隐状态预测其拥有的系数——共享头是刻意的，定义归属的是 slot 索引而非各频带参数。解码时不做独立窗口逆变换（否则相邻窗口在共享边缘上会不一致、产生块状接缝），而是用 50% 重叠 DCT 框架的合成半部：逆 DCT、平方根周期 Hann 窗、归一化 overlap-add，相邻窗口共享一半像素，归一化 overlap-add 抑制跨窗口不连续，且分析与合成用同一窗、Λ 归一化重叠、裁剪满足 QP=I，因此对匹配的分析系数能精确重建。此外还有一个 anchor 对齐的空间修正头：slot k 在像素空间写自己 anchor 单元的确定性行主序 K_h×K_w 平铺中的第 k 块（K=4、s=16 时即四个 8×8 象限），这些投影是 slot 专属且零初始化的，训练从纯谱模型起步，只增加输出参数、不增加 token 状态或注意力边——径向归属只作用于谱基，空间项是无频率分配的像素读出。Route 阶段解决"谁需要全局通信"：若让所有 slot 都进全局注意力，全局二次成本会随 K 增长，正好把刚拆掉的耦合又装回去。谱角色提示了更便宜的切分——最低径向组持有受益于跨 anchor 交换的粗结构，越高的组越局部，且其信号在流中最早压过噪声。于是 slot 0（最低径向组的拥有者）作为 carrier，是唯一进入全局阶段的 slot，全部 K 个 slot 再在各自 anchor 内做局部混合；全局块与局部块交替，carrier 把全局信息带回 anchor、又把局部细节带进下一个全局阶段。具体是 GGLL 调度（两个全局块、两个局部块）重复三次，共六个全局块和六个局部块、维度相同；类别上下文只出现在全局组。在 ImageNet-256、s=16、K=4 时，全局序列只有 W+C=288 个 token 而非 WK+C=1056 个，全局二次项随 W 而非 WK 增长。这套表示暴露了两个独立的分配变量：W 控制空间 anchor 密度，K 控制每个 anchor 的谱细分，总 slot 数随 WK 增长但全局序列只含 W 个 carrier，固定 token 预算可以在"更密的空间 anchor"和"更细的谱角色"之间显式分配，从而把 tokenization 从单一 patch 尺寸选择变成一个明确的质量—算力分配问题。

实验上，论文在 ImageNet-256 和 ImageNet-512 上训练类别条件模型，并在文本到图像生成上验证。ImageNet-256 上，SpecSlot 在 FLOPs 匹配的 JiT 对照下取得可比的最终 FID，但收敛更快；ImageNet-512 上，W256/K4 配置比 FLOPs 匹配的 JiT-CM 对照把 FID 降低 2.84，同时 GFLOPs 还少 3.9%，并且以低 38.2% 的成本逼近 JiT-B/16 仅差 0.69 FID；文本到图像上，SpecSlot 在 DPG-Bench 上以低 40.6% 的前向成本超过 JiT-B/8 达 1.06。值得注意的是，更大的输出窗口覆盖更多像素而全局序列保持不变，且相对 JiT-CM 的提升更大，这与"anchor 内部分配"的机制一致——细节可以在不扩大全局序列的前提下细分。客观来看，这套方法仍有其边界：它依赖 DCT 径向分组这一固定先验（要求 K 整除 L²），谱角色到通信资格的映射是人工设定的而非学出来的，空间修正头虽零初始化但引入了额外输出参数；此外论文的验证集中在类别条件和文本到图像两类任务、ImageNet 与 DPG-Bench 两个基准上，更大规模、更高分辨率以及视频等模态上的可扩展性尚未充分展开。尽管如此，它的意义在于把"输出细节"与"全局通信长度"这两个此前被 patch 网格强行捆绑的量真正解耦，把 tokenization 重新表述为一个显式的质量—算力分配问题，为像素空间生成 Transformer 提供了一条不依赖额外自编码器或额外细节头、在单一骨干内完成分配的新路径。

### [VibeGame: Prompt-to-Game Development with AI-Native Engine and Self-Evolving Adversarial Agent Team](https://arxiv.org/abs/2610.33106)
`评分3 · HF 22赞`

这篇论文要解决的是如何让大语言模型智能体真正端到端地完成一个可玩的游戏项目，而不是只生成一段能跑的代码。游戏开发的难点在于它要求代码、场景、美术资源、动画、物理系统和配置参数之间保持高度一致，任何一个局部修改都可能破坏其他部分的隐含依赖关系。此前的工作大致分两条路线，但都卡在关键环节上：世界模型类方法（如 Genie）能直接从视频生成交互体验，却不产出可编辑的源代码，无法构建、版本管理和迭代修改；而把 LLM 接入商业引擎（如面向 Unreal 的 DreamGarden）的做法，项目状态散落在图形界面和二进制资产里，智能体无法稳定地检查和修改。近期 AutoUE、OpenGame 等系统虽然用智能体做端到端生成，GameCraft-Bench 也提供了带资产库的评测设定，但它们大多把运行时检查留到最终评测阶段，或者只验证游戏能否构建和启动。然而大量游戏缺陷只有在实际游玩中才会暴露——玩家输入、物理、动画和游戏逻辑交互时出现的问题，静态检查根本发现不了。更麻烦的是，修复一个产物往往会在相互依赖的代码、场景、资产之间引入新的不一致。因此作者认为需要三种紧耦合的能力：一是智能体可操作的项目状态表示，能显式暴露脚本、场景、资产、动画、物理和配置之间的结构与依赖，因为仅靠直接读写文件无法阻止看似局部的编辑破坏别处的隐藏关系；二是基于交互的验证能力，由于游戏执行速度远快于智能体的推理速度，必须提供可暂停、可单步推进、可检查的可控执行；三是保留已验证的开发经验，让可复用的项目结构、功能和协作流程指导后续工作，同时把未经验证或项目特定的内容隔离出去。

VibeGame 的核心设计正是围绕这三点展开。首先是 AI 原生游戏引擎，作者把它定义为具备三个属性的引擎：GUI 无关，即整个项目以纯文本文件表示，智能体可直接读写，而不是依赖引擎专有标识符或需要图形编辑器的二进制文件；运行时可达，即智能体可以通过代码暂停、单步、观察和干预运行中的游戏，把异步的实时系统变成可同步验证的过程；源码可用，即引擎的完整未编译源码被复制进项目目录，智能体可以查阅确切的 API、假设和实现细节，而不必依赖可能滞后于版本变更的文档。具体实现上，引擎基于 Phaser 构建，但 Phaser 对项目组织几乎没有约束，容易导致智能体生成的项目碎片化，因此作者把每个游戏表示为一组场景，场景配置存放在类型检查的 JSON 文件中，每个场景是节点的层级结构，节点把视觉外观、碰撞几何、行为脚本和配置显式声明在 JSON 字段里，而不是藏在构造函数中，跨场景共享的节点存为独立定义文件并在运行时实例化。这种场景—节点—资产的层级让每个产物有明确位置、跨文件依赖显式化，schema 校验能在执行前发现缺失资产等无效引用。运行时接口则提供帧同步的程序化控制：暂停与恢复、推进指定帧数、读写节点位置和速度等运行时属性、注入“按下跳跃”这类语义动作、以及截图，智能体可以按自己的节奏做逐帧检查、脚本化测试序列或启发式机器人实时游玩。在此接口之上是八角色的对抗式智能体团队，包括编排者、设计师、美术、架构师、程序员、审计员、玩家和评审员，通过角色专属提示和执行钩子定义职责，用持久化项目产物保存决策并在团队间传递。开发分三阶段：意图对齐阶段，设计师依据游戏设计原则把“做一个空洞骑士风格的 Boss 战”这类请求扩展成完整的游戏设计文档，美术并行生成概念图确立视觉方向，经用户确认后成为下游开发和评估的共同基准；并行开发阶段，代码由架构师、程序员、审计员、玩家组成的流水线完成，编排者先分解出并行组件、从自进化仓库检索相关骨架模块和契约作为先验、准备定义各组件范围和验收标准的需求文档，架构师规划实现策略与验证流程，程序员实现，审计员用引擎的一致性检查工具做静态审查并对照设计规格，玩家通过运行时接口在帧同步控制下实际运行游戏并用视觉模型判断渲染结果是否符合预期，只有同时通过静态审计和运行时试玩才算完成；美术工作流则由美术智能体调用图像生成模型产出初稿，再做去背景、尺寸归一化等后处理并注册到引擎。所有子任务完成后，独立评审员作为最终质量门，从功能、视觉质量和可玩性三个维度评估完整项目，不合格就给出具体理由，编排者将其转化为新的修复任务，形成构建—评审循环直到满足全部验收标准。最后是免训练的自进化机制：对每个被接受的项目，系统把可复用经验蒸馏为三种形式——骨架是某类游戏的可运行项目模板，剥离项目特定美术资产但保留代码架构、调参数值、视觉比例、场景流和运行时结构，还附带错误笔记（总结反复出现的失败及其已验证修复）和美术包（记录该类型的资产生成提示词与后处理惯例）；模块是可挂到任意节点上的自包含行为脚本，实现跨游戏类型可复用的功能，并可包含自检逻辑，把此前观察到的运行时失败转化为启动前执行的静态校验规则；契约则是把通用团队工作流适配到某类反复出现的功能或开发模式的文档，规定各角色的输入、输出、依赖和验证标准，例如地图契约定义设计师如何指定地图需求、程序员如何在项目文件中表示地图、美术如何提供所需资产、审计员和玩家如何验证结果。后续项目会适配并重新验证这些经验，而不是盲目复用。

实验方面，作者从 GameCraft-Bench 的 15 种游戏类型中各随机抽取两个任务共 30 个作为测试集，仅改动引擎、输入设定和一段简短的演示录制提示，保留游戏描述和评估标准不变。在 P2G 设定下（智能体自行生成美术），VibeGame 在相同底层模型下持续优于多种智能体框架，包括 GPT-6.1-Sol，且这些对比方法无论处于 P2G 还是 PA2G 设定都被击败。消融实验显示，去掉 AI 原生引擎或去掉对抗式评审角色都会显著降低总分，说明结构化项目表示和实现与审查分离的设计都是性能的关键来源；此外，用更强模型通过自进化蒸馏出的经验可以迁移到较弱模型上带来提升，这验证了经验复用机制的有效性。局限方面，论文目前只覆盖 2D 游戏和 Phaser 生态，30 个任务的评测规模也相对有限，自进化产物的质量依赖于被接受项目的质量，若评审环节放过了有缺陷的项目，错误经验可能被固化进骨架和契约中；此外视觉评估依赖视觉模型，其判断可靠性本身也是变量。尽管如此，这项工作把“提示到游戏”从单次代码生成推进到包含运行时验证和经验积累的完整开发闭环，为智能体在复杂多产物软件系统上的工程化协作提供了一个可复用的范式。

`评分3 · HF 20赞`

这篇论文要解决的核心问题是：现有的代码智能体评测基准无法真实反映"人机协同设计"场景下的能力。真实用户在编码会话中提出的修改请求往往是复合性的——可能同时附带图片、音频、视频或文档，要求修改布局、交互和应用状态，而且这些需求彼此耦合、相互依赖。比如论文举的运动剪辑编辑器例子：用户要求同时限制片段数量和时长、在缩放时保持时间轴对齐、并且在删除或拆分片段后重新启用插入操作，这些需求牵一发而动全身。而此前的方法各有盲区：Design2Code、WebSight-Test 这类做的是截图到代码的参考重建，IWR-Bench 扩展到交互视频但仍是重建范式；DesignBench 从版本历史里抽取相邻版本对做前后截图对比，MT-Web2Code 通过污染参考页合成修复轨迹，WebCompass 围绕预定义的编辑操作构造任务——它们要么依赖金标准代码或目标截图作为监督，要么只覆盖单一、预定义的编辑类型，无法刻画从真实生产会话中提取的、跨界面与行为的多需求复合修订。更关键的是，论文发现执行方式本身会显著改变评测结果：在同样的 150 个 WebCompass-edit 任务上，把 qwen3.7-plus 从单次生成切换到智能体式执行（可迭代调用工具），平均分级特征完成率从 73.6% 跃升到 95.1%，opus-4-8 在智能体执行下更是达到 99.4%——21.5 个百分点的差距说明，如果不把评测放在带工具访问的迭代执行条件下，测出来的分数根本不能代表真实能力。因此需要一个从真实用户会话中恢复、带可运行起始状态、无参考监督、且在智能体执行框架下评测的基准。

方法上的关键设计可以拆成数据构造和评测协议两块。数据侧，论文从 26,314 个真实编码会话的 39,325 条生产查询出发，去重后保留 37,463 条候选，每条锚定到一个目标编辑轮次及其仓库、上下文和附件。为了让"起始状态"真正可运行，他们从会话日志、仓库归档或 HTML 打包中重建应用，并通过依赖解析、构建、容器启动和 Playwright 渲染四道关卡验证，无法恢复的服务型任务直接剔除，修复过的应用也要过同一道门。候选请求经过归一化（打包附件、澄清措辞）、硬过滤（去掉环境阻塞、不可操作、非编辑类请求），再按结构难度、可验证性和历史失败信号（如用户反复改写、回滚）排序，最后合并成有界的会话区间，由专家撰写隐藏的验收标准。最终形成 273 个任务、2,331 条专家标准，分两条轨道：多模态编辑（ME，100 个任务）针对局部视觉、结构、内容修改，附件分布为无附件 20、图片 4、视频 27、音频 32、文档 17，平均每任务 5.5 条标准；仓库编辑（RE，173 个任务）从可运行的多文件前端仓库出发，要求跨组件、路由、状态、数据流的协同修改，平均每任务 10.3 条标准，且 173 个任务中有 166 个需要多种编辑类型叠加。评测侧的核心创新是"先判后驳"协议：一个固定的智能体式评估器依据源码 diff、渲染页面和 Playwright 轨迹，对每条隐藏标准给出 Pass/Partial/Fail；随后一个独立的 LLM 验证器专门挑战 Pass 和 Partial 判定，检查是否存在桩代码、硬编码输出、不可达入口、变输入下失效、需求错配等问题；最后还有强制证据审计——视觉类主张必须有成功渲染和截图，交互类主张必须有录制的浏览器操作日志，证据缺失直接在聚合前中止评测。这套设计之所以比之前的方法更可靠，是因为它把"源码里存在"和"用户能实际触达并操作"严格区分开，用独立验证器压制评估器的自我偏好，并用无金标准代码、无目标截图的参考无关方式，让基线应用本身成为判断修改是否达成的锚点。评分上同时报告严格完成率（全部标准 Pass 才算）、分级完成率（Partial 记 0.5）和全通过率，并按任务等权归一化，避免长标准列表主导均值。

结果方面，论文在共享的智能体执行框架下评测了十个模型端点：最强端点平均每任务通过 69.9% 的标准，但只有 26.4% 的任务做到全部标准满足——这个 43.5 个百分点的落差正是论文想强调的核心现象：大量局部需求被覆盖，与完整交付之间存在巨大鸿沟。模型排名在 ME 和 RE 两条轨道间会发生变化，而所有十个端点在涉及三到四种变更类型的仓库编辑上，标准完成率都低于只涉及一到两种变更类型的任务，说明变更广度是当前智能体的系统性短板。局限也很明显：任务虽然源自真实会话，但评测时请求是固定的，不模拟执行过程中的进一步用户反馈；"先判后驳"虽用独立验证器和强制审计提升了正例可信度，却无法消除判断错误本身；低分案例的失败归因依赖可独立渲染的基线和并行可解性探针，对无法恢复服务的任务覆盖有限。不过这项工作的意义在于，它把"部分满足"与"完整成功"的差距摆到了台面上，并提供了一个可审计、可追溯、跨局部多模态编辑与仓库级协同修改的统一测试床，这对推动智能体从"能改对几处"走向"能交付一个完整可用的修订"是有实际牵引力的。

### [IntReal: A Real-World Dataset and Benchmark for Multimodal Interleaved Generation](https://arxiv.org/abs/2610.38425)
`评分3 · HF 15赞`

这篇论文要解决的是多模态交错生成（multimodal interleaved generation）缺乏专门数据集和细粒度评测的问题。所谓交错生成，就是让模型像人类写百科、故事书或教程那样，把文字和图片按自然顺序交替产出，而不是单独生成一段文字或一张图。虽然统一多模态模型（UMM）已经能同时生成文本和图像，但交错生成长期被当作模型统一化的副产品，没有被当作一个独立的生成任务来对待。卡点有两个：一是数据层面，MMC4、OBELICS、OmniCorpus 这类大规模交错数据集是为多模态理解而非生成收集的，缺少面向生成的质量控制；CoMM 虽然汇总了交错数据源，但没有按真实世界场景的分类体系来组织采集，导致任务空间刻画不清。二是评测层面，现有基准多依赖 VLM 对长交错回复做整体打分，这种粗粒度评估与刻画复杂生成能力所需的细粒度诊断天然错位；ISG-Bench 虽然把回复拆成四个结构层级，但这种拆分并不对应不同的能力维度，而且所有层级都只用同一个 VLM 评判，某些维度所需的专门能力（比如图像美学质量）它并不具备。因此作者认为，这个方向缺的是一个在原则性分类体系下构建的高质量生成数据集，以及一套能按能力维度可靠诊断的评测协议。

方法上的核心创新分数据与评测两条线。数据侧，作者先从网页和视频等自然交错内容中归纳出四类真实场景：规划（如 WikiVoyage 的行程，文字给约束、图片展示时空变化）、知识（如 Wikipedia，文字讲概念、图片做视觉锚定）、教程（如下厨房，文字给步骤、图片展示中间状态与时间过渡）、故事（如动画剧本，文字推进叙事、图片构建角色与场景），并据此从七个可公开采集的来源构建百万级原始语料。清洗管线是渐进式的：先用元数据过滤掉异常宽高比、低分辨率和不支持格式的图片；再用专门视觉模型做表征级过滤，包括用 RALI 做图像质量评估、在专家标注数据上微调 SigLIP2 来检测水印和人脸、用 DINOv3 做序列内近重复去重；接着用 Qwen3.5-397B-A17B 生成图像描述并润色周边文本，原则是原文优先于生成描述以保事实真实性；最后用同一 LLM 按类别生成 prompt 和推理过程，把每个样本转成可直接微调 UMM 的结构化交错数据。由于长交错样本中任何一段有缺陷就整条剔除，最终只有约 10% 的样本被保留，得到含 538K 图像的 IntReal-100K，并做了类别均衡采样。评测侧的关键洞察是"由粗到细"：整体评测让模型从零生成完整交错回复，考察开放式能力；细粒度评测则固定真实交错上下文、只让模型生成下一张图，从而做受控诊断。七个指标分别由专门的专家模型承担——文本丰富度和文本逻辑性用 LLM 做成对排序与事实一致性判断，图像美学用 IQA 模型，图像多样性用相邻生成图的 DINO 特征相似度来捕捉"连续几张图过于相似、没反映上下文推进"这一常见失败模式，数量合规用真实样本的图片数作为图预算来考察指令遵循，上下文保真度用 VLM 校验生成图是否满足评测集构建时从先前上下文推导出的视觉评分细则，主体一致性则用生成图与同位置参考图的 DINO 相似度衡量故事角色或食材等关键主体是否保持。评测集本身是半自动构建的：先用 LLM 评文本质量、RALI 评图像质量、再用上下文感知的自验证策略（模型先不看目标图、仅从前文推导该图应描绘什么，再拿目标图对照）筛跨模态一致性，然后人工剔除不合格样本，按类别分层抽样得到每类 150 共 600 个样本；作者刻意控制规模，因为粗到细协议下每个模型就要生成六千多张交错图，再扩大会显著推高多模型族的评测成本而收益不成比例。

实验上，作者评测了四族 UMM：Bagel（官方微调脚本可用但原检查点不支持交错生成，只报微调后结果）、Emu3.5（原生支持交错推理但不开放微调，只评原模型）、SenseNova-U1（8B-MoT 与 A3B-MoT 两个变体，前者用专门优化的 Interleaved 检查点做基线和微调）、以及闭源的 NanoBanana2。评测套件本身先做了三项验证：七个指标两两最大绝对 Spearman 相关不超过 0.42，说明维度间冗余低、确实在测不同能力；自动评测与人类判断一致率达 83.3%；不同专家评估器之间 Spearman 相关高于 0.9，说明结果稳定。基准测试显示没有单一模型在所有维度上占优，开源模型中 Emu3.5 文本逻辑性最强，而 U1-8B-MoT 在数量合规和上下文保真度上明显更好，能力呈现互补而非全面碾压。后训练实验给出两个更有意思的结论：在 IntReal-100K 上做 SFT 能提升 SenseNova-U1 的文本生成，却会损害图像生成的某些方面，复现了 UMM 中文本与图像优化之间的经典张力；而针对交错上下文下的下一图生成施加 Flow-GRPO 强化学习、并把上述指标当作奖励信号，不仅把退化的图像生成能力拉了回来，还在所评开源 UMM 中拿到 IntReal 评测套件的最高总分。这直接支撑了论文的核心主张：只训练单一生成模态也能改善交错生成，交错生成可以从模态特定的优化中获益，而不必在每个阶段都做文本-图像的联合训练，从而把优化空间从"对交错序列做联合 SFT"扩展到了更广的范围。局限方面，评测集只有 600 个样本、每个模型需生成六千余张图，规模受成本约束；Subject Consistency 只在教程和故事两类上计算，因为知识与规划不要求跨图主体一致；闭源模型无法判断其交错能力是原生还是智能体流水线拼出来的；Anole、Show-o2 因上下文长度受限被排除，LLaDA2.0-Uni 因缺少公开实现被排除，说明这套基准目前对长上下文和可复现实现有隐性门槛。尽管如此，IntReal 把"交错生成"从统一模型的副产品提升为有分类体系、有数据、有可诊断评测的独立任务，并用"单模态训练可迁移到交错生成"这一发现为后续优化路径提供了新方向。

### [Glance: The Generator Is Its Own Reranker](https://arxiv.org/abs/2610.40454)
`评分3 · HF 11赞`

这篇论文要解决的是检索增强生成系统里一个很实际的工程冗余问题：重排器和生成器通常是两个独立模型，交叉编码器要为每个查询-段落对单独做一次前向编码，基于大模型的重排器虽然质量更高但代价更大，而无论哪种方案，都意味着要额外常驻一个模型、并且候选段落要在重排阶段被处理一遍、选中之后又要在生成器里再被处理一遍。作者提出的核心疑问很直接：生成器反正都要读这些段落，能不能让它用一份共享的计算顺便把候选段落都判了？之前的方法卡在几个地方：交叉编码器逐对编码，无法复用段落间的共享上下文；逐点式大模型重排（比如用 yes/no logits 打分）要为每个段落单独跑一次完整前向，k 个候选就是 k 次预填充；列表式重排虽然一次看所有候选，但只能输出一个排列或依赖首 token 的 logits，无法给出每个段落独立的、经过训练的相关性判断；而 Self-RAG 这类让生成器自我评判的方法，也是每个段落单独过一次。换句话说，现有方案要么牺牲共享计算，要么牺牲逐段打分的粒度，要么需要额外模型驻留。

Glance 的关键设计是把重排变成生成器主干上的一次共享预填充加多条短探针分支。具体来说，它给冻结的 9B 主干挂一个 rank-16 的 LoRA 决策适配器和一个 256 维的指针头，把 k 个候选段落拼成一个共享状态前缀（packed_all 格式：依次放 Passage 1 到 Passage k），然后从这份缓存的末尾分出 k 条互不关注的短分支，每条分支只问一句“第 i 段是否包含能回答或支持该查询的信息”，约 30 个 token，一次批量续写就得到 k 个逐段的相关性分数——每个段落只被预填充一次，而不是 k 次。指针头的作用是把每条分支在决策位置上的隐状态与该分支中选项位置的隐状态做比较，输出一个 softmax，因此不需要生成任何文本，一次决策就是一次预填充。这里的技术难点在于主干是 Gated DeltaNet 线性注意力与全注意力 3:1 交错的混合架构：全注意力层可以用掩码隔离分支，但线性注意力层在整个序列上只携带一个循环状态，所以 Kev 运行时的做法是在共享状态末尾为每一层复制一份缓存（注意力层的 KV、DeltaNet 层的卷积窗口加循环状态），每条分支从这份精确副本继续，训练和推理走同一条路径，保证状态每条记录只算一次。主流程在选出 top-n 后会用关闭适配器的权重重新预填充选中的段落再生成，原因是 DeltaNet 状态按顺序汇总整个前缀、无法任意拼接各段落的缓存，而且状态缓存是在适配器开启时算的；论文另外给出 Glance-Activated 变体，适配器只在探针 token 上激活、段落编码用基础权重，于是生成可以直接从原始候选缓存继续，代价是输掉的段落仍留在缓存里。训练上只训 LoRA 和指针头，从已有的通用决策适配器出发，在 4000 条 MS MARCO 查询上（每条一个正例加 7–19 个 BM25 硬负例，packed_all 格式，每个探针一个二分类标签）跑一个 epoch、500 步优化，单张 B200 上 39 分钟、峰值 21 GiB，完全没碰 BEIR 或 HotpotQA 数据。

结果上，零样本（只用通用决策适配器、未做任何检索训练）时 packed_all 在 SciFact 上拿到 0.715 nDCG@10，接近同一模型 20 次独立逐段调用的 0.729 和交叉编码器的 0.721，但比逐段调用快 3.6 倍；在 NFCorpus 上 0.341 反而高于交叉编码器的 0.326 和逐段调用的 0.323，作者推测原因是每个探针能看到全部段落、可以横向比较邻居，而孤立打分做不到。经过 39 分钟 MS MARCO 微调后，SciFact 到 0.741、NFCorpus 到 0.345，分别比 bge-reranker-v2-m3 高 0.020 和 0.019；再花 14 分钟在 20–80 段的长上下文记录上训练，两个数据集还各涨到 0.749 和 0.346。扩展性实验里，训练过的适配器在 k 增大时质量不降反升：k=100（约 21.6k token 一次预填充）时 0.682，比交叉编码器同候选集的 0.637 高；k=200（43.4k token，走分块路径）时 0.717 对 0.659，高 0.058。端到端在 HotpotQA 300 题上，虽然交叉编码器召回的金标段落更多（R@2 0.863 对 0.762），但同一生成器从 Glance 选出的 top-3 作答 F1 更高；用训练后适配器时，在适配器关闭、同一基础生成器的受控条件下，Glance 选出的上下文把答案 F1 从 0.684 提到 0.729，提升 0.045，配对 bootstrap 95% 置信区间 [0.014, 0.076]，这个比较干净地隔离了“选不同证据”本身的效果。局限也很明确：交叉编码器每查询仍快得多（31–60 毫秒），当前实现里每条探针分支都复制一份共享状态的注意力缓存，显存随 k 乘上下文长度增长（k=100 时 56 GiB），跨查询批处理反而降低吞吐，作者指出用块掩码让所有分支共享一份缓存可以把显存变成线性、从而支撑 128k token 的共享预填充，但留作未来工作；评测只覆盖两个检索数据集、一个 QA 数据集和一个主干家族，BEIR 上的差异未做显著性检验，n≈300 时 0.02 以内的差距只能当参考；训练标签是段落相关性而非答案效用，所以“生成器选自己好用的证据”这一解释虽有端到端证据支持，但还不能证明模型学到了答案质量。总体而言，这篇工作展示了一条去掉独立重排器主干、用一份常驻权重同时承担生成、通用决策和重排的可行路径，每个额外决策技能只增加约 0.1 GiB 显存，模式切换不改权重、进出适配器只需毫秒级且输出逐位一致，对 RAG 系统的部署形态有直接的工程启示。

### [AskStream: When and What to Ask Proactively under Uncertainty in Streaming Video Understanding](https://arxiv.org/abs/2610.38678)
`评分3 · HF 10赞`

这篇论文要解决的是流式视频理解中主动交互范式的根本缺陷。现有的主动范式（如ProactiveVideoQA、ProReady-QA等）虽然把模型从被动回答者推进到能自主决定“何时回答”的主动代理，但它们都隐含了一个强假设：回答问题所需的信息完整地存在于视频流中，迟早会出现，因此模型只需在“等待”和“回答”之间二选一。现实场景却常常不满足这个假设——信息可能因为视频本身（关键证据被遮挡、视角不对、缺少个性化概念）而不完整，也可能因为用户（问题歧义、前提错误、偏好未知或过时）而不完整。在这种不确定性下，只允许“等待或回答”的范式会导致两种失败：模型要么无限等待一个永远不会到来的证据，要么在信息缺失时强行作答，产生严重幻觉。作者通过实验量化了这一点：提供正确证据能把准确率从42.3%提升到62.3%，而不匹配的证据几乎无益，说明主动获取缺失信息确实能降低模型不确定性。因此论文主张把主动交互重新定义为三种动作——等待、提问、回答，让模型在回答前主动索取缺失信息，并指出现有工作（如ClearVQA、ProactiveBench）只覆盖静态图像、不区分不确定性来源，流式视频下的主动提问仍是空白。

方法上的核心创新可以拆成三个相互支撑的部分。其一是任务建模：把AskStream形式化为部分可观测马尔可夫决策过程，隐状态正是视频流或用户流中缺失的信息，模型每个决策点只能依据已观测视频、用户查询和历史交互，在WAIT、ASK、ANSWER三个动作中选择，且每秒允许一次动作选择、每轮最多一次ASK和一次ANSWER。其二是精细的时间窗标注体系，这是让“何时问”可评估的关键：论文把事件定义为从当前查询到下一查询之间的区间，并区分两种时序类型——Type I是“先等后问”，初始观测不足以识别不确定性，模型必须先等待相关证据出现才能发问，此时ASK必须落在ANSWER窗口内才有效，ASK的发出动态地终结了等待区间；Type II是“先问后等”，初始观测已能识别不确定性，模型应在标注的ASK窗口内发问，然后等待证据出现再回答，此时等待区间的起点由ASK动作动态决定而非人工标注。其三是评价指标Ask-F1，它联合衡量ASK和ANSWER在时间与内容两个维度上的正确性：只有当ASK内容正确且落在有效窗口内才计为一次正确ASK，再结合回答的时序得分与内容正确性做综合，避免了以往只看时间戳或只看答案的片面评估。配套地，作者构建了StreamHarness分层记忆框架，保留近期帧、压缩早期观测，以更真实地模拟流式场景，并在多选和开放式两种设定下评测。这套设计之所以优于此前方法，是因为它第一次把“信息不确定性”作为一等公民建模，并用双类型时间窗和联合指标把“何时问、问什么、何时答”三者解耦又统一地纳入监督与评估。

实验结果揭示了当前模型的巨大短板。在包含438个视频、1401个问题、覆盖视频不确定性与用户不确定性共四类任务八个子任务、三种时间窗总时长分别达33.92/30.47/12.00小时的AskStream上，即便是最强的离线模型GPT-5.6-Sol也只拿到52.18%的Ask-F1，而最强的具备主动能力的流式模型仅7.22%，离线与流式之间存在鸿沟。错误分析显示“过早ASK”和“错误ASK”是两类最常见错误，而如果给模型提供关于“何时问”和“问什么”的oracle信息，Ask-F1能提升43.83个百分点，直接证明主动提问是当前模型的主要瓶颈。局限也很明显：基准规模相对有限（438视频），标注依赖人工与GPT-5.6 Sol生成选项后再人工校验，成本高且覆盖面受限；StreamHarness只是评测侧的近似，真实部署中的记忆压缩与延迟问题未充分探讨；模型侧的方法创新几乎缺席，论文主要贡献在基准与范式定义，如何训练模型真正学会三动作决策仍是开放问题。尽管如此，这篇工作把主动交互从“等待/回答”的二元框架推进到包含“提问”的三元框架，并给出了可复现的基准、指标和记忆框架，为流式视频理解中“不确定性驱动的主动信息寻求”这一方向奠定了问题定义与评测基础，后续若能在训练范式和更大规模数据上跟进，很可能成为该子领域的重要参照。

### [EditAgent: Rethinking Agentic Image Editing](https://arxiv.org/abs/2610.39664)
`评分3 · HF 10赞`

这篇论文要解决的是"智能体式图像编辑"在真实复杂指令下频繁失败的问题。现实中用户的请求往往不是单一操作，而是像"把我移到画面左侧、拉宽镜头露出更多海滩、去掉身后走路的人、再调成日落氛围"这样由多个子任务组成的复合指令，现有的通用编辑模型倾向于完成其中一部分而悄悄丢掉其余部分。此前的智能体编辑系统（如基于规划-编辑-评判循环的方法）会把请求拆成步骤逐步执行，但当某一步失败时，它们基本只是用同一套狭窄的工具、同一个"肉眼打分"的评判器反复重试、精修或回滚。作者指出这类智能体被两个空间所限制：一是动作空间，即智能体能做什么；二是观察空间，即它的评判器能看到什么。为了量化这两个瓶颈，他们构建了一个由专业 Photoshop 修图师盲标的诊断基准，覆盖 30 种编辑类型、共 600 个候选集。结果很说明问题：通用编辑器在 42.7% 的集合中给不出任何可用结果，尤其在几何、色调与增强类编辑上失败严重，而专用方法能挽回其中 175 个失败案例；同时没有任何一个评判器（包括经过偏好微调的奖励模型）在所有编辑组上都最准。这直接否定了"多试几次就行"的直觉——问题不在采样次数，而在工具多样性和评判器可见的信息。

方法上的核心创新就是把这两个空间同时撑大。动作空间方面，EditAgent 不再只依赖一个通用编辑器，而是为每个步骤做路由，把候选分发给通用编辑器与一系列专用方法——包括基于 SAM 2.1 掩码的局部编辑与重上色、用 OSOR 做物体移除、专用模型做物体移动、分割加合成的缩放、全局与局部光度算子、风格滤镜与神经风格迁移、翻转旋转与摆正、以及裁剪加超分实现放大和向外绘实现缩小等。观察空间方面，它给每个候选附加一份"验证记录"，里面包含变化图、编辑区域的局部特写、测得的颜色与几何量，以及程序化检查的结果，让评判器清楚哪些属性已被代码验证、哪些还需视觉判断。关键运作方式是：所有候选都从同一张源图并行生成，评判器在一次 listwise 调用中把所有候选连同记录一起比较，接受一个或给出反馈重试。这里有个重要洞察——顺序精修在图像编辑中会累积误差，因为每一轮都在改自己的输出，早期小错误会传播到后续；而并行搜索始终从源图出发，保持对原图的忠实。实验显示专业修图师在 78.5% 的非平局比较中更偏好并行搜索，且评判调用次数不超过顺序精修的一半。另一个反直觉的发现是：配上验证记录后，现成的 VLM 评判器无需微调就能超过专门微调的奖励模型，说明"评判器看到什么"比"它怎么被训练"更重要。在诊断基准上，listwise 比较把 Qwen3.8-27B 的准确率从 71.6% 提到 73.6%，但单独比较反而在光度与增强组下降（因为正确结果变化很小），加入验证记录后这两组分别恢复到 64.4% 和 80.3%，总体达到 81.3%，比最强的 EditScore-72B 高 6.5 个点；七个现成 VLM 评判器全部提升 6.3 到 9.3 个点，且全部超过四个微调奖励模型。系统还包含跨轮次的历史检查机制：每轮结束后把原图、此前各轮结果和当前图一起给 VLM，询问早先的请求是否仍然成立，若确信被违反则执行一次修复轮，且仅当该步评判器接受时才采纳。

实验结果上，EditAgent 分别以 Qwen-Image-Edit-2511 和 FLUX.2-klein-9B 为骨干，在 EdiVal（572 个三轮会话）、Complex-Edit（8496 个不同复杂度样本）和 ComplexBench-Edit（763 个组合式指令样本）三个基准上均优于单独使用这两个骨干编辑器。此外，由于它只接受经过验证的编辑，还能充当数据引擎：用它筛选出的 25.7K 条被接受的会话去微调编辑器，效果超过直接用基础编辑器 FLUX.2-klein-9B 生成的数据训练出的模型。局限方面，论文的验证记录依赖一组预定义的检查项和专用工具池，动作空间的扩展仍受限于这些方法能覆盖的编辑类型，遇到池外的新操作可能仍然无解；历史检查依赖 VLM 判断"早先请求是否仍成立"，本身也可能出错；并行搜索虽然省评判调用，但每步要并行生成多个候选，图像生成的总算力开销并不低。意义上，这篇工作把智能体图像编辑的瓶颈从"多试几次"重新定位到"工具多样性与评判器可见信息"这两个结构性维度，并证明了现成 VLM 加结构化证据可以取代昂贵的专用奖励模型，对后续智能体编辑系统的设计取向和训练数据生产方式都有直接的启发。

### [On the Fundamental Limits of Prefill-Based Decoding Length Prediction](https://arxiv.org/abs/2610.40541)

这篇论文要解决的是大模型推理调度中的一个关键前置问题：在解码开始之前，仅凭prefill阶段的隐藏状态预测这条请求会解码出多少token。这个预测值对批调度、PD分离和资源预留都极其重要，因为解码阶段主导了端到端延迟和能耗。已有工作沿着两条路线推进：早期方法在表层特征上训练外部代理模型，近期方法则复用目标LLM自身的内部激活，比如用中间层embedding做调度、在逐层隐藏状态上搭图卷积回归器，以及EGTP用下一token分布的熵做softmax加权来池化隐藏状态，并在新提出的ForeLen基准上报告了最高29.16%的MAE下降。但作者指出了一个被忽视的公平性问题：已发表的数字彼此不可比——同一个预测器架构在ForeLen长序列划分上配Qwen2.5-7B能到MAE约80，换到ShareGPT配Qwen3-32B就退化到150以上，在RL采样数据上更是超过260。根本原因不在预测器设计，而在于自回归解码本身的随机性：当一条query的解码长度方差很大时，长度本身就是一个随机变量，任何只看prefill信息的预测器都不可能以高精度猜中某一次具体采样的确定长度。之前的方法卡就卡在把预测器质量和任务难度混为一谈，用一个确定性的回归目标去拟合一个本质上随机的东西，却没有先厘清哪部分误差是任何方法都消不掉的。

论文的核心洞察是把解码过程建模成一个带非恒定风险的停时过程，并由此推出解码长度的渐近正态性。关键的一步是跳出了token级别的视角：一条长回答不是一长串独立决策，而是由句子、列表项、从句或推理步骤这些“段”拼接而成，段与段之间存在更新结构。作者假设在给定prompt后，回答被分成M个段，段长在给定M时独立同分布，而M本身是段级延续过程的一个停时计数，其方差随均值平方增长。在这个仅有的统计假设下，用Berry–Esseen型界可以证明解码长度Y在段数趋于无穷时服从正态分布，并给出显式的误差项。这个正态极限直接导出了三个可检验的推论：其一是仿射方差律，即每条prompt的标准差与均值成线性关系，斜率恰好等于段数的变异系数；其二是聚合指数，标准差与均值之比有一个由段数波动决定的下界，等价于说一条回答大约只有(μ/σ)²个“有效停止机会”；其三是残差的偏度形状应当呈现高斯–几何混合的特征。有了这个正态律，就能对任何只看prefill的预测器给出下界：在给定σ(x)的条件下，最优预测就是条件均值μ(x)，此时MAE的下界是σ乘以根号下2/π，通过率的上界由正态CDF在容差区间上的质量给出，而且这两个极值都是唯一取到的。换句话说，一旦某条prompt的σ超过某个阈值，比如要让acc@100达到90%就必须σ不超过61个token，那么无论预测器多大、训练数据多少，高精度都是不可能的。论文进一步把超额风险精确分解成系统项和模型项：预测器与下界的差距至多等于它到oracle均值的距离，而由于训练标签是单次采样而非均值，回归目标本身带着方差为σ²的噪声，这会在有限样本下拖慢学习，正好解释了实验中观察到的残余差距。此外，在仿射律下，绝对MAE会随数据长度尺度无界增长，而相对误差趋于一个由生成过程决定的、与架构无关的常数，这为“应该报告相对误差指标”提供了形式化依据。为了从有限次解码中估计σ，论文算出在95%置信度下要把σ估到10%以内需要每条prompt约193次解码，因此实验统一用200次。

实证部分在ShareGPT的300条prompt上用Qwen3-32B、按其推荐的采样配置（温度0.6、top-k 20、top-p 0.95）各解码200次来验证。其中2条prompt是完全确定的，σ为零，其余298条参与统计。结果相当支持理论：每条prompt的MAE与高斯理论值σ根号下2/π的偏差在1.9%以内，分布中心质量与正态预测相差不超过两个百分点；残差的偏离方向也正是理论预言的——中位标准化偏度+0.27（70.8%的prompt右偏）、超额峰度+0.35，这些正是采样噪声修正项所预测的形态。σ对μ的仿射关系在六个模型上都成立，但系数差异很大：Qwen3-4B-Instruct的斜率仅0.1068，而关闭思考模式的同款模型升到0.2029；DeepSeek-R1蒸馏思考版则是低斜率0.1156配异常大的截距147.6，反映出思维链生成即便最终答案很短也自带探索性随机。按斜率约等于段数变异系数来读，这些数字意味着一条ShareGPT的长回答大约只相当于25到90个有效独立的停止机会。在固定模型、数据和采样条件后，论文横向比较了MLP回归、EGTP式熵池化、FiLM条件化、软标签分类和MoE路由等一大类预测器设计，发现它们全部收敛到接近理论下界的相似性能，这直接印证了“系统误差主导模型误差”的论断。局限也很清楚：正态律是渐近结果，短回答或σ接近零的prompt上理论界会偏松；段结构假设虽然刻意做得很粗，但仍是一个统计假设，在高度结构化或强约束的输出（如严格格式的JSON）上段长独立性可能不成立；σ的估计需要每条prompt约200次解码，这在真实调度场景中不可得，论文的界更像是离线评估和基准设计的工具而非在线可用的预测器。对方向的影响在于，它把“预测解码长度”从一个模型容量竞赛重新定位为一个受生成过程内在随机性约束的估计问题，并据此主张基准测试应固定模型、数据和采样参数，同时报告相对误差与绝对误差——否则ForeLen这类榜单测到的更多是任务难度而非预测器质量。

离散扩散模型近年来在文本、代码等生成任务上受到关注，但其采样效率长期受制于需要多步随机跳转的特性。连续扩散模型之所以能加速采样，关键在于概率流ODE的存在——它用一个确定性常微分方程复现扩散模型各时间边缘分布，从而支撑一致性蒸馏等少步采样技术。然而离散状态空间上是否存在类似构造，此前并无肯定答案。已有离散采样方法大多依赖随机转移核（如tau-leaping或基于rate matrix的采样），每一步都要按概率跳转，轨迹不可微、不可确定预测，因此难以直接套用连续扩散里的蒸馏与加速范式；同时离散状态无法定义梯度，也让一致性训练缺少可用的确定性路径。这篇论文正是要回答：离散扩散能否也写出一个保持边缘分布的确定性"流"，从而把连续扩散的加速工具箱迁移过来。

作者给出的答案是"指数残差流"（ERFs）。核心洞察是把每个token、每个位置的离散状态额外配上一个连续残差变量，相当于给离散符号挂一个"倒计时时钟"。这个残差按分段定义的ODE确定性演化，其向量场由当前离散状态以及原扩散模型的前向、后向rate matrix共同决定；当某个残差衰减到零时，对应位置的离散状态发生一次跳变，残差随即重置并继续演化。也就是说，离散跳变不再是随机抽样，而是被连续残差的穿越事件确定性地触发，整条轨迹由初始残差与ODE唯一决定。作者证明了这一构造精确保持原扩散模型的边缘分布，并给出了可实现的离散化采样器，分别针对masked diffusion和uniform diffusion做了特化。相比随机跳转采样，ERF的轨迹是确定性的、可复现的，因而天然支持一致性蒸馏——可以训练一个网络直接把任意中间状态映射回流终点，实现少步甚至单步生成。

实验上，作者在代码与文本生成等多个基准上对比了先前的离散扩散采样方法，报告了经验性提升，说明确定性轨迹确实能转化为更少步数下的更高质量样本。需要客观看待的是，ERF的向量场依赖前向与后向rate matrix，对一般离散扩散需额外计算或近似这些量，分段ODE的数值离散也引入步长与事件检测的精度问题，残差重置附近的处理可能影响稳定性；此外方法目前主要特化到masked与uniform两类扩散，向更一般的离散转移结构推广仍需验证。尽管如此，它首次为离散扩散建立了与概率流ODE对应的确定性表述，把连续扩散的加速与蒸馏范式系统地引入离散生成，为后续少步离散扩散采样与一致性训练提供了可延展的理论与实践基础。

### [Pre-Crime for Agents, at the Last Second: Probing When a Recruited Agent Gives In](https://arxiv.org/abs/2610.40588)
`评分3 · 49 pages, 11 figures. Code: https://github.com/leonidas1712/ · 有代码`

这篇论文瞄准的是一个多智能体系统里被此前防御手段系统性忽视的真实威胁场景：当多个AI智能体共享频道、工具和凭证时，一个智能体可能被同伴智能体公开地、多轮次地施压，去违反自己运营者设定的规则（比如泄露一个部署令牌），而现有防御几乎都建立在“检查输出”这一层——要么在工具调用执行前拦截可疑动作，要么在模型输出流式生成时截停。问题在于，这类泄露往往不走工具调用，而是以普通聊天消息的形式直接发到共享团队频道，论文的统计显示Qwen3-32B的泄露中大多数直接进了共享频道，44%就是智能体回合结束时的普通回复，工具调用过滤器根本看不见；同时请求来自队友、是公开的而非藏在数据里的注入，压力可以持续二十轮逐步累积，每一轮单看都无害，规则又常常是运营者自定义的（如“这个凭证不许外传”），基于固定危害类别的守护模型覆盖不到。更根本的是，仅靠输出过滤在原理上就不可靠：改写和翻译能绕过逐字匹配，在可逆编码下输出端审查是不可能的，而编码后的外泄在激活里仍然可读。于是作者提出一个“提前一秒钟的犯罪预防”式问题：能不能在智能体即将屈服、但还没写出任何东西之前就发出预警？

方法上的核心洞察是：把预警点从输出端前移到每次模型调用生成之前的内部表示上。具体做法是在目标智能体的残差流上训练一个线性探针（逻辑回归），读取该次调用最后一个输入token处的激活，因此打分发生在模型开始写任何内容之前；在gpt-oss-20b上还额外用一个推理探针，对本次调用私有推理的每个token打分取最大值，同样早于公开输出。为了公平比较，作者构建了六个职场场景的招募基准（保护对象分别是部署令牌、保留价、容量数字、发布阈值、交接备注和集成码），每个场景都有控制组（同伴只问普通任务细节、从不索要秘密），且控制组和单独运行组从不泄露，从而把泄露归因于同伴的请求；评测时只对目标首次读取受保护文件之后、直到首次泄露的那次调用为止的调用打分，并定义了三个由近及远的标签：这次调用是否泄露、本轮或下一轮是否泄露、整个回合是否最终会泄露。关键的方法论细节是：由于泄露倾向集中在早期轮次，单纯按轮次打分会虚高，所以他们只在同一场景、同一轮次内部比较泄露调用与非泄露调用再加权平均，任何只依赖场景和轮次的打分器都只能得到0.5。对比基线包括零样本文本监控器（Jev，读掩码后的对话并输出“是”的概率）、在完全相同标注调用上训练的TF-IDF加逻辑回归词袋分类器，以及若干读取推理文本的监控器。

结果方面，在留出的Qwen3-32B测试回合上，阈值设为只对5%的良性调用报警时，探针抓到了82%的泄露调用，而同报警率下零样本文本监控器只有26%；在gpt-oss-20b上推理探针达到AUROC 0.91。但作者诚实地指出，在相同调用上训练的词袋分类器成绩接近探针，说明大部分增益来自“用了标注数据训练”而非“用了激活”，激活最多只带来很小的额外优势。局限也很明确：预警是短程的，对“本轮或下一轮是否泄露”只有中等准确率，对“整个回合最终是否会泄露”很弱；探针实际上更多是在读“即将发生的披露”而不是“违规”，因此也会对运营者允许的披露报警；而且一旦对任何警报都中止，会停掉大多数良性回合，加一道文本复核也解决不了。尽管如此，这项工作的意义在于把多智能体共谋防御的战场从“输出之后”推到了“生成之前”，并给出了一个可复现的基准、严格的同轮次比较协议和对报警成本的量化分析，为未来在蜂群式智能体扩散中抢在招募蔓延之前干预提供了技术起点。

## 强化学习 RL

### [Online Dense Reinforcement Learning with Planning-Grounding Agent for UI Navigation on Live IOS Apps](https://arxiv.org/abs/2610.39264)
`评分3 · HF 9赞`

这篇论文要解决的是UI导航智能体的实用化落地问题：前沿视觉语言模型虽然导航能力强，但推理成本高到每个任务要花好几美元，日常使用完全不现实；而小模型通过监督微调或离线强化学习训练后，往往只是记住了静态轨迹，执行脆弱、出错后无法恢复。作者把现有方法的症结拆得很清楚：SFT只在成功轨迹上做模仿学习，模型学到的是"沿着已经走对的路走下一步"，几乎没见过错误状态长什么样，更没学过出错后怎么办，因此泛化差、错误恢复能力弱；已有的RL方法要么退化成单步RL、奖励与黄金轨迹的相似度，本质上还是SFT那套局限，要么只在轨迹终点给一个终端奖励，信号极其稀疏——智能体哪怕中间做对了很多步、只差最后一步没完成，也拿不到任何正向反馈，学习效率低下。此外，现有GUI智能体系统普遍采用GRPO这类组相对方法，根本不训练价值函数，也就无法做步级的信用分配，密集信号即使存在也只能被聚合成轨迹级回报或重复状态的分组平均，无法真正被利用起来。

方法上的核心创新可以分三层来讲。第一层是架构解耦：作者没有训练一个端到端模型同时做规划和定位，而是拆成Planning Agent和UI Grounding Model两个专门组件。Grounding本质上是把"点哪里"这个意图映射到屏幕坐标的确定性空间定位问题，用SFT就能训得很好，所以直接冻结；Planning则是开放式的——要理解目标、跟踪已完成动作、适应UI动态变化、从意外状态中恢复，这才值得投入昂贵的RL。Planning Agent输入任务指令、当前截图、历史步骤计划及其推理、以及上一步的剩余计划，输出带思维链的当前步骤计划和长期计划，当前步骤计划再交给Grounding模型转成具体动作原语和坐标；动作空间里还包含Ask_User原语，用于任务描述不充分时向用户澄清偏好。第二层是奖励设计：用LLM-as-a-Judge同时给出密集奖励和终端奖励，密集奖励逐步评估是否取得了有意义的进展、并惩罚幻觉和无产出的循环，终端奖励评估整体任务是否完成。这里有个关键陷阱——如果直接优化步级密集奖励，智能体会故意拖长轨迹来薅奖励，所以作者设计了非对称折扣：密集奖励按折扣累加，终端奖励不打折，以此平衡局部过程监督和最终任务完成。第三层是GiGPPO：标准PPO用步级GAE做优势估计，但critic在稀疏或噪声奖励下不稳定；GiGPPO让价值估计额外利用并发轨迹中视觉相似状态的奖励信号来做邻居条件化的价值估计，相当于把跨轨迹的相似状态信息路由进一个学习到的价值函数里——这一点和GiGPO不同，后者是靠精确重复状态的平均回报构造步级基线，而在真实iOS应用里状态几乎不会精确重现，这种基线会退化成单点、失去意义。训练基础设施上，作者用云托管iOS虚拟机和快照回滚机制支撑了512条并发轨迹，每个设备独立跑智能体-环境循环，episode结束靠回滚快照而非销毁会话，重启延迟压到约10秒，这也是首次在真实iOS设备上大规模训练UI导航智能体。

实验结果方面，作者在UINavBench、iOSWorld和AndroidWorld上做了评测。最亮眼的数字是8B的在线RL智能体在分布外泛化到Android环境时，成功率比SFT基线提升了近七倍，这说明它学到的是可迁移的导航策略而非死记iOS特定轨迹；在真实iOS应用的UINavBench上，它超过了Qwen3.8-27B和Gemini-3.5-Flash，与Gemini-3.1-Pro打平；密集奖励配方和GiGPPO都被验证能加速训练收敛。客观地说，局限也还在：Grounding模型是冻结的，规划器的上限受制于定位模块的质量；LLM-as-a-Judge作为奖励源本身有噪声和偏差风险，论文没有深入讨论judge与真实成功率的对齐程度；训练完全依赖云托管iOS设备和快照机制，工程门槛和成本不低，其他团队复现难度较大；Ask_User这类交互原语在真实用户场景下的体验影响也缺乏评估。但方向上，这篇工作把"解耦规划与定位、把RL预算花在开放式推理上、用密集加终端双通道奖励配合步级价值函数做信用分配"这条路线在真实移动端跑通了，对UI智能体从实验室走向低成本日常部署是有实质推动的。

## AI + 生物

### [TRACER, a time-to-event EHR foundation model for disease detection across health systems](https://arxiv.org/abs/2610.40536)
`评分3`

这篇论文要解决的是电子健康记录（EHR）基础模型在真实临床筛查场景中“看起来很强、用起来不够”的问题。以往基于EHR的基础模型（无论是编码器式还是解码器式Transformer）大多用AUROC、C-index这类全局排序指标来评估，这些指标把所有阈值上的排序质量压缩成一个数，适合比较不同表征的好坏，却回答不了临床最关心的两个问题：在假阳性率被压到实际可承受的水平时，模型到底能捞回多少未来会发病的病人？被标记为高风险的人里又有多少真的会发病？对罕见病而言这个问题尤其尖锐——论文引用的一项回顾性研究显示，42个罕见病病例发现算法的中位特异度高达99.9966%，但调整后的中位阳性预测值只有3.1%，也就是说极高特异度并不自动换来可用的PPV。此外，既往工作很少在“既没参与预训练、也没参与下游模型训练”的完全外部医疗系统中，跨多种疾病、多个预测时间跨度联合评估检测率和误报负担；而只用一年期的表现也无法说明更长跨度的可用性。还有一个容易被忽视的统计陷阱：随访不完整时，把失访病人直接排除或当作“无病”都会引入偏倚，需要生存分析里的右删失处理框架来正确估计风险。正是在这些缺口上，TRACER把“时间到事件”（time-to-event, TTE）建模和EHR基础模型结合起来，试图把评估从“排序好不好”推进到“在临床能容忍的误报率下能发现多少病例”。

方法上的关键设计可以拆成三层。第一层是预训练：TRACER是一个解码器式（decoder-based）Transformer，在加州大学四个医疗系统超过450万病人的纵向结构化EHR序列上做自回归式的“预测下一个临床编码”预训练，从而学到病人就诊序列中的时序模式；这与编码器式模型“重建被遮蔽的编码”的目标不同，解码器式目标更贴近“根据历史预测未来事件”的推理方式。第二层是生存头：预训练完成后主干冻结不变，只在域内留出病人上训练DeepHit生存头，把模型输出的病人表征映射为随时间变化的发病风险分布，从而天然支持多个预测时间点（1年、2年、5年，癌症另加6个月）并正确处理右删失随访——这是它相对普通二分类预测头的核心优势，因为二分类只能给出某个固定窗口内的“是/否”，而TTE框架直接建模事件发生时间的分布。第三层也是最关键的评估思路转变：论文不再只报AUROC和C-index，而是在每个队列内部单独估计阈值，使特异度分别达到90%、95%、99%，然后在这些工作点上计算敏感度、PPV、相对基线发病率的富集倍数（fold enrichment）以及每万名病人中的病例产出（case yield），并用逆概率删失加权（IPCW）来校正不完整随访。这样做的洞察在于：全局指标衡量的是“排序能力”，而固定特异度下的敏感度和PPV衡量的是“临床可操作性”，两者可以脱节——一个模型AUROC很高，但在95%特异度下可能漏掉一半以上的未来病例；反过来，两个模型全局指标接近，在低假阳性工作点上的表现却可能差很多。论文还训练了一个编码器式版本在相同预训练数据和模型规模下做对照，以检验架构选择本身的影响。

结果层面，TRACER在完全外部的UC5和UC6两个医疗系统（合计超过200万病人，既未参与预训练也未参与下游头训练）上评估了16种新发疾病。整体区分度基本保持：域内C-index范围0.624–0.879，UC5为0.617–0.870，UC6为0.651–0.880，域内与两个外部系统中较差者的中位下降仅0.041。但真正有信息量的是低假阳性工作点上的表现：以心衰为例，域内一年期AUROC为0.87，在95%特异度下敏感度只有44.2%，意味着超过一半的未来心衰病例在这个阈值下漏掉；把特异度从90%提到99%时，阿尔茨海默病的敏感度从70.6%降到25.5%，心衰从63.7%降到15.1%，说明“压低误报”的代价在不同疾病间差异巨大。外部迁移也不是整齐划一的：在104个“疾病-时间跨度×外部系统”比较中，56.7%的外部敏感度低于域内，中位下降1.9个百分点；慢性肾病基本持平（域内46.8%，外部48.7%/48.4%），而心衰明显下滑（44.2%降到36.9%/33.6%），且五年期心衰AUROC只从0.862降到0.836，敏感度却从42.4%掉到32.1%——这正是全局指标掩盖临床可用性损失的典型例子。PPV方面，高血压在95%特异度、一年期下外部PPV为26.5–36.0%，相对基线发病率富集3.4–3.9倍，每万名评分病人产出166.6–253.5个未来病例；慢性肾病富集最高达8.0–8.5倍。论文也坦承局限：外部敏感度下降说明跨系统迁移并不免费，罕见癌种在95%特异度下敏感度最低仅约15%，99%特异度下更是低至个位数百分比，筛查价值有限；此外阈值是在各队列内重新估计的，实际部署时阈值选择本身需要目标人群数据。其意义在于把EHR基础模型的评估标准从“排序好不好”推向“在临床能承受的误报率下能发现多少、要复核多少人”，并证明这种评估必须在未参与开发的医疗系统中做，否则全局指标的稳定性会给出过于乐观的印象。

### [Intrinsic Distribution Matching](https://arxiv.org/abs/2610.39633)
`评分3 · HF 19赞 · 有代码`

这篇论文要解决的是少步数甚至单步文本到图像生成中的一个核心矛盾：当网络评估次数被压缩到一两次时，生成器几乎没有机会在采样过程中逐步修正细节，因此必须一次性把提示词里指定的内容准确渲染出来。长文本渲染是这个问题最严苛的试金石——画面里要同时保证大量字符清晰可辨、拼写正确，还要维持整体图像的连贯性，任何细节丢失都会直接暴露。此前的主流方案是分布匹配蒸馏（DMD），它利用参考分布和当前生成分布之间的分数差来引导生成器更新：预训练教师模型提供参考分数，另有一个辅助的假分数网络估计生成分布的分数，两者之差告诉样本该往哪个方向移动才能降低模型与参考的密度比。但问题在于，这个假分数网络本身需要跟着生成器不断变化而持续训练，估计误差和有限训练步数会导致学到的分数监督并不精确；后续工作如 TwinFlow 和 APEX 改用生成器内部拆分的速度分支来估计分数差，省掉了独立的假分数网络，但模型分数依然是被学习出来的，统计层面的偏差仍然存在。作者由此提出一个关键问题：既然分数差已经包含了完整的分布信息，能不能额外加一个显式的统计量约束来弥补学习型分数估计的不足？

论文的核心洞察来自对 DMD 背后反向 KL 分数场的分解。作者把任意光滑正密度函数的分数精确拆成两部分：一个是与均值和协方差匹配的高斯分数，另一个是剩余的非高斯残差。这个分解说明，分数场里有一部分信息完全由一阶和二阶矩决定，是可以用显式约束直接盯住的；而残差部分则承载了更高阶的形状信息，单靠矩匹配无法确定完整分布。因此 IDM 的设计思路不是用矩匹配替代 DMD，而是在保留完整 DMD 修正的同时，额外加一个特征空间的矩损失。具体来说，DMD 部分沿用 APEX 的内部双分支构造，通过取负条件向量把同一个生成器分成参考分支和模型分支，两者在同一输入点的速度差给出分数差的估计，再把这个修正同时用于监督速度预测和干净样本端点预测，两种回归形式按时间步加权组合。矩损失这一侧则复用生成器的指数滑动平均（EMA）副本作为共享特征提取器：同一批噪声分别经过当前生成器和 EMA 副本，得到两组特征，然后匹配它们的均值和逐坐标标准差。这个设计的关键在于不需要外部特征编码器、不需要判别器、也不需要额外的分数网络，两个训练信号全部来自生成器自身及其 EMA 副本。消融实验专门对比了用 EMA 特征和用外部 DINOv2 编码器提取特征的效果，发现在报告的五项指标上两者竞争力相当，说明生成器自身特征空间已经足够承载有用的统计监督。

实验在 Z-Image-Turbo 6B 和 Qwen-Image 20B 两个骨干上分别做了全参数微调和 LoRA 微调，重点评测 LongText-Bench 的中英文长文本渲染。在两次网络评估的预算下，IDM 在 Z-Image-Turbo 上取得中文 94.25%、英文 90.20% 的成绩，相比 Z-Image-Turbo++ 分别提升 2.63 和 0.32 个百分点，是同等预算下对比方法中最高的。消融实验确认了额外矩损失带来的增益，也验证了 EMA 特征替代外部编码器的可行性。不过论文的局限也比较明显：矩约束只覆盖均值和逐坐标标准差，协方差结构并未显式匹配，残差部分的高阶信息仍然依赖 DMD 的学习型分数估计来间接捕捉；实验主要集中在长文本渲染这一任务上，方法在其他细粒度条件生成场景（如复杂空间关系、多物体属性绑定）上的泛化性尚未充分验证；此外 20B 模型上的提升幅度和训练成本之间的权衡也需要更多数据来评估。从方向上看，这篇工作提供了一个有说服力的思路：把分布匹配的梯度场做解析分解，识别出哪些统计量可以被显式约束，再用生成器自身的特征空间去实现这种约束，从而在不引入额外网络的前提下给学习型分数监督补上一个统计锚点。这个“分解—识别—显式约束”的框架有可能被推广到其他蒸馏目标和特征空间的设计中。
