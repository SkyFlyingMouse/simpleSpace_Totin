## 大模型 LLM

### [DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression](https://arxiv.org/abs/2609.19969)
`评分4 · HF 56赞`

这篇论文要解决的核心问题，是长程智能体（long-horizon agent）场景下 KV cache 带来的存储与带宽瓶颈。随着 agent 任务越来越"输入密集"（input-heavy），上下文动辄几十万甚至上百万 token，虽然此前的稀疏注意力工作（如 DeepSeek-V4 的 CSA+HCA 混合架构）已经大幅降低了长序列的计算开销，但 prefill 依然昂贵，更关键的是 KV cache 本身要占用大量 HBM 和 SSD 容量，并在缓存迁移、加载时消耗 I/O 与互联带宽。DeepSeek-V4 的结构是"全局注意力分支 + 局部滑动窗口注意力（SWA）"：全局分支维护全局 KV（主 KV 加 indexer K），SWA 维护局部 KV。SWA 的 KV 存储量由窗口大小决定、与序列长度无关，所以序列一长，全局 KV 就成了运行时 KV 占用的主导项，受 HBM 容量约束；而为前缀复用而持久化的 KV（persistent KV）则受 SSD 和主机内存约束。计算、存储、带宽三者叠加，直接限制了服务吞吐、推高部署成本，成为长上下文 agent 大规模落地的首要障碍。因此，进一步压缩 KV cache 占用，是降低长上下文服务成本的关键。

核心创新可以拆成架构、精度、部署三个层面。架构层面，作者提出 CSA2（Compressed Sparse Attention 2），对全局 KV（主 KV 和 indexer K）以及 Top-K 索引做跨层复用，并设置三种静态分配的模式：Full 模式生成全局 KV 并做索引；Reindex 模式复用前面层的全局 KV，但用自己的 indexer Q 对共享的 indexer K 重新打分、选出新的 Top-K 索引；Reuse 模式则连全局 KV 和 Top-K 索引一起复用，直接做稀疏注意力。三种模式下每层仍保留自己的全局 Q 和 SWA KV，被共享的只是重复的全局 KV 与 indexer K，从而直接砍掉冗余存储；同时模型放弃了 V4 的 CSA-HCA 混合结构，改为纯 CSA2。精度层面，训练时就使用 FP4 的全局 KV cache，性能损失很小。部署层面，作者提出 SWA Bounded Replay：V4 原本为了精确重建 SWA KV，需要重放最近 L×n_win 个 token（L 是层数），代价很高，于是 V4 用混合策略在"持久化 SWA KV"和"重算"之间权衡；而 V4.1-Flash 只重放最近 n_win 个 token 来近似重建 SWA KV，实验显示性能退化可忽略，从而可以完全不把 SWA KV 持久化到 SSD，只付出少量 prefill 重算。此外还有 Causal Encoder-Decoder（CED）架构，解码器的全局 KV 由编码器最终隐状态投影而来，使 prefill 每 token 只激活 8B 参数、decode 激活 16B，prefill 计算量近乎减半，对输入密集的 agent 负载特别划算；配套还有 Single-Pass mHC（配合 Mega-mHC 内核，激活内存流量减半）、Engram 条件记忆模块、DSpark 半自回归草稿加置信度调度的推测解码等。正是这些设计叠加，使单 token decode FLOPs 几乎不随上下文增长——从 4K 扩到 1M（256 倍），decode FLOPs 只增加约四分之一。

结果上，V4.1-Flash 拥有 552B 骨干参数、196B Engram 参数，支持百万 token 上下文，全局 KV cache 占用降到每 token 约 890 字节，约为 DeepSeek-V4-Flash 的四分之一；借助 SWA Bounded Replay，持久化 KV 占用进一步降到约八分之一，而性能反而更好。预训练用了 45T token 的多模态语料，稀疏注意力从零开始在 64K 序列上训练、不做 dense warmup。Base 模型在世界知识、推理和编码上追平 DeepSeek-V4-Pro-Base，在留出评测上还有 5%–10% 提升，而总参数只有三分之一、激活参数只有四分之一。后训练没有算法创新，沿用 SFT→RL→OPD 的标准范式，全部改动集中在数据管线（大规模自动合成任务、环境构建、DSec 大规模 agent 运行、可控推理努力度）。评测显示推理能力可比 Kimi-K3 和 DeepSeek-V4-Pro，在 Terminal-Bench 2.1、DeepSWE v1.1、AutomationBench 等标准 agent 基准上追平闭源前沿模型，多模态视觉推理和专业图表解读超过 Kimi-K3，可完成 95% 以上的真实任务。局限也很明确：在需要专家级领域知识的科学型 agent 任务（如 Terminal-Bench 4.0）上，与巨型模型仍有差距，多模态整体上也落后于顶级闭源系统。总体而言，这篇工作的意义在于证明了"能力提升"和"推理效率提升、部署成本下降"可以同时实现，把长程 agent 大规模部署的成本门槛显著拉低，并为后续架构、预训练、后训练的联合 scaling 提供了新起点。

### [LimiX-2: A Contextual Mechanism Network Towards General Structured-Data Intelligence](https://arxiv.org/abs/2609.17488)
`评分3 · HF 165赞`

LimiX-2 要解决的是结构化数据（表格数据）缺乏通用基础模型的困境。当前表格预测的主流方法——梯度提升树、专用深度网络、自动集成流水线——在单个数据集上表现强劲，但每个新任务都需要独立训练和模型选择，知识无法跨任务复用。已有的表格基础模型（如 TabPFN、TabICL、TabFM）走的是 Prior-Data Fitted Networks 路线，在合成任务上预训练，用上下文学习直接近似 p(y|x, D_context)，即给定查询特征和带标签的上下文集，预测指定目标列的后验分布。这条路线的问题在于：每个任务内，直接监督只盯着单一目标列，模型从未被显式要求建模所有变量之间的联合分布。这意味着变量之间的依赖结构、缺失值之间的相互推断、以及更广泛的“从已知证据推断未知量”的能力，都没有被当作预训练目标来优化，而是被压缩进了一个目标导向的预测接口里，导致模型在需要跨变量推理的任务上能力受限。

LimiX-2 的核心创新是 Contextual Mechanism Networks（CMN）范式，把建模重心从“指定目标的预测”转向“变量间预测依赖体系的联合建模”。具体来说，它不再只学 p(y|x, D_context)，而是学 p(x, y|D_context)，即数据生成过程背后的、依赖于上下文的联合结构表示。实现这一点的预训练目标是 Context-Conditional Masked Modeling（CCMM）：每个预训练 episode 把表格切成不相交的上下文行集和查询行集，查询行中一部分特征列被掩码，模型同时做两件事——从观测到的查询特征和上下文预测被掩码的特征值，以及从同样的条件信息预测查询目标。这样，变量间的推断成为显式的预训练目标，而不是附带能力。架构上，LimiX-2 延续了 cell-level 表示（每个单元格单独编码，不把整行压成一个向量），但做了几处关键改动：嵌入维度从 192 提升到 256；引入低秩 Discriminative Feature Encoding，用 s=d/4 维的列身份码经变换后加到特征表示上，既区分列身份又避免模型记住列索引的偶然顺序；主干仍是双轴 Transformer，但特征路径和任务路径不再共享计算——样本轴注意力中特征和目标的 Q/K/V 映射不共享，特征轴注意力是非对称的（特征表示可以关注目标和其它特征，目标表示只能关注特征），FFN 也替换为特征和目标各自独立的 SwiGLU；目标表示从 LimiX 的单个任务嵌入扩展为 K=4 个任务嵌入槽，每个维度 d，再拼接后送入注意力。回归头也改了：不再用 MSE，而是把目标范围分成 5000 个有序 bin，预测每个 bin 的概率，再以 bin 中心值加权求和得到回归值。这些设计让同一个预训练模型无需参数更新就能同时支持分类、回归、缺失值插补和因果发现。

在 TabArena、TALENT、BCCO 三个覆盖广泛样本量、特征维度、类别数、类别-数值特征比、缺失率和样本特征比的基准上，LimiX-2 同时超越了数据集专用模型和当前的表格基础模型，尤其值得注意的是它在参数量只有 TabFM 四分之一的情况下仍然胜出。在因果骨架恢复任务上，它的特征注意力编码了直接因果关系，表现优于其它表格基础模型、基于树的特征重要性方法和专用因果发现方法。局限方面，论文没有展开讨论，但从设计可以推断：预训练完全依赖结构因果模型生成的合成数据，合成引擎对图结构、函数机制和观测过程的覆盖范围直接决定了模型的能力边界，真实数据中可能存在的、合成引擎未能覆盖的机制类型仍是潜在风险；此外，cell-level 表示在行数和列数极大时带来的计算开销、以及 5000 个 bin 的回归头在高维输出或极端值场景下的表现，都是尚未充分验证的问题。这项工作的意义在于，它把表格基础模型的预训练目标从“单目标预测”推进到“联合分布的条件建模”，并展示了这种范式转换能同时带来预测性能提升和因果结构涌现，为结构化数据的通用智能提供了一条区别于语言模型和世界模型的独立路径。

### [SoL-Pi: Recursively Scaling Auto-Research Loops for Efficient Agent Harness](https://arxiv.org/abs/2609.20519)
`评分3 · HF 45赞`

这篇论文要解决的是编码智能体在长时间无人值守运行时的 token 效率问题。当智能体从受监督的代码补全转向全天候自主探索，它的工作不再是孤立的一次性预测，而是由推理、工具调用和反馈构成的长轨迹，token 消耗随之成为递归自我改进能否规模化的首要瓶颈。已有的效率工作大多集中在降低单 token 成本，比如更快的注意力核、服务基础设施优化、量化压缩，或者换用更便宜的模型；而这篇论文选择了一条正交路径：优化模型与环境之间的智能体 harness（即承载工具调用、上下文管理、验证、委派、恢复和终止逻辑的那层编排代码）。问题在于 harness 优化本身极难：工具使用、上下文管理、验证和委派高度耦合，局部有益的改动可能把成本转移到执行后期或引发下游失败，传统上依赖人工检查长轨迹、归纳失败模式再手写代码修改，成本高且难以跨任务、跨环境扩展。已有的自动化尝试如 Meta-Harness 搜索可执行 harness 程序、RHI 迭代精炼 prompt 级智能体循环，都被发现容易过拟合搜索时用的任务，在留出任务上收益边际，因此作者强调必须把搜索反馈与最终评估严格隔离。

SoL-Pi 的核心思路是把 harness 改进本身当作一个受 RSI 启发的自动研究过程，用 AI 优化器迭代改进 harness，并且刻意设计成「宽到深」的漏斗结构。搜索从 152 个候选方向出发，分属上下文、进度、工具、委派、prompt 与策略、改进与评估六个提案家族，先由 Oracle Analysis 检查基础 harness 的执行轨迹找出可避免的开销，再让每个方向在独立的、一次性的搜索谱系中运行：每个实验复制一份共享技能模板，设定参数跑完即弃，只保留候选机制和证据，丢弃改过的编排代码。这种隔离让失败不会跨候选传播，宽度靠更多独立循环，深度靠循环内的反复精炼——实现者按明确的完成标准修改候选，独立审查者检查后才进入评估，审查失败则触发修订，每轮还可能产生多条探索轨迹，由多个分析器分别检查重复动作、上下文膨胀、大观测或稀疏诊断信号，再由 reducer 汇总成候选级摘要指导下一轮提案。候选要过两道顺序门：所有能力指标必须留在预先声明的容差内，且至少改善一个声明的效率指标，通过者再按非支配关系保留。最终存活下来四个机制：Action Fusion 把文件编辑和随后的测试/构建命令合并成一次工具请求、一次观测返回，省掉中间模型往返；Online Context Compact 以计划步骤完成为边界，用已完成步骤间的实际请求数估算剩余请求，再用当前上下文增长速度封顶，并通过比较预计节省的输入 token 与重写 prompt cache 的额外成本来决定是否压缩，越到后期还要求更大的节省余量；ObservationPack 把超过 10 KiB 的大工具输出本地归档，前两次 provider 请求仍全量发送，从第三次起替换为稳定句柄、原始大小和头尾完整行的短摘录，需要时可按句柄取回精确分页；Evidence-Preserving Reducer 针对至少 4 KiB 的构建和测试日志，先归档原始输出，再让低成本模型抽取关键证据生成紧凑回执，由确定性验证器检查回执的 schema、源哈希、退出状态、精确引用和大小，验证失败或疑似凭据泄露或没有尺寸缩减就回退到原始日志，且它在 ObservationPack 投影模型上下文之前处理工具结果，ObservationPack 识别到回执标记就跳过，从而保住已验证的证据。这四个机制分别作用于动作执行、上下文管理、观测存储和委派阅读，互补地削减重复工作，同时保留后续决策所需的信息。

在结果上，SoL-Pi 在 EdgeBench 的 51 个公开任务上，用 GPT-5.6 Sol 和 Opus 5 都达到了与 Pi 相当的性能：效率配置点只用 1.10B token，比 Pi 少 49.0%，保留 Pi 平均分的 93.7%（42.0 对 44.8），token 成本低 33.2%；性能配置点在 GPT-5.6 Sol 下把平均分从 44.8 提到 47.2，提升 5.3%，同时 token 流量还降了 6.1%，token 效率提升 9.8%。跨后端迁移时，用 GPT-5.6 Sol 开发出的 SoL-Pi 不做任何再搜索或适配直接用到 Opus 5 上，仍保留 Pi 平均分的 94.3%，token 流量降 44.7%，API 成本降 33.5%。在 Terminal-Bench 4 的 63 个纯 CPU 任务上，SoL-Pi 解出 15 个而 Codex 和 Pi 各解出 18 个，但总模型成本比 Pi 低 26.3%（211.12 对 286.45 美元），每个解出任务成本低 11.6%；在 IMO 2026 的 Lean 4 形式化验证上，SoL-Pi 通过 6 题中的 3 题，每个通过题成本 20.90 美元，低于 Codex 的 22.89 和 Pi 的 25.32。局限也很明显：SoL-Pi 在 Terminal-Bench 4 上解出的任务数少于基线，说明效率提升并非没有能力代价，效率配置点也只保留了 Pi 约 94% 的分数；搜索规模约 150 个方向、500 个环境、3000 多次运行和 6 万多次交互，作者自己也强调这些数字只描述搜索范围，不构成缩放定律；跨后端迁移目前只有 Opus 5 一个未见的 LLM 后端作为初步证据。但它的意义在于展示了一条路径：RSI 的持久价值可能不在于让模型自己改权重，而在于让搜索过程跨公开环境规模化，发现可复用、可迁移的 harness 级效率机制，并且这种改进不需要额外模型训练，能与基础设施和模型层面的优化叠加。

### [An Empirical Study of Harness Design for Coding Agents](https://arxiv.org/abs/2609.20804)
`评分3 · HF 37赞`

这篇论文要解决的核心问题是：编码智能体（coding agent）的表现究竟在多大程度上由“外壳”（harness）决定，而外壳中各个组件又各自贡献了什么。此前的研究大多把整个 harness 当作一个黑盒来评测，比如 Cao 等人发现 Claude-Opus-4.5 在 OpenHands 上表现最好，而 Claude-Sonnet-4.5 却在 SWE-Agent 上最优，这种跨 harness 的比较虽然揭示了模型与外壳之间存在偏好差异，却无法说明性能差异到底来自规划机制、工具设计、上下文管理，还是它们与模型能力的交互。换句话说，两个完整 agent 之间的差距被多种机制混杂在一起，研究者既不知道哪个组件真正有用，也不知道这种有用性是否依赖于模型规模、任务类型和资源预算。已有的组件级研究虽然触及了架构选择，但没有在长程编码任务上同时刻画实现层面的规划、工作区动作接口和上下文管理策略，也没有在显式的上下文窗口扫描和同家族模型规模轴上做联合分析。因此，论文提出的研究问题是：harness 组件是普遍有效，还是其效果取决于模型能力、任务类型和资源预算？

为了回答这个问题，作者从零构建了一个轻量级 harness，固定 ReAct 执行循环，只变化三个组件：规划、动作空间和上下文管理。规划组件维护一份显式的任务计划，模型通过 update_plan 工具更新，后续轮次把计划追加到输入中但不存入对话历史，从而估计的是“持久规划脚手架”的效果而非一般推理策略。动作空间有两种：预定义工具集（read_file、write_file、edit_file、list_files、glob_files、grep_text、web_fetch、bash）或仅 bash 接口；预定义工具带有类型化参数、读写前检查、文件状态跟踪和编辑后自动诊断，而 bash-only 则把这些都去掉，因此比较的是完整动作接口的效果而非单纯工具数量。上下文管理是最精细的部分，包含三个可组合机制：省略（elision，用短桩替换陈旧工具观测）、召回（recall，把被省略内容存入外部文件并通过 recall_event 按需读回）、摘要（summarization，用同一个模型的无工具调用把旧消息折叠成运行摘要）。它们由软阈值 B1 和硬阈值 B2 控制：历史超过 B1 时先省略臃肿的工具观测，仍超过 B2 时再对最旧的中段事件做摘要，而系统提示、初始任务描述和最近至少两轮的窗口始终保持原样。由此定义五个策略：T0 不做管理、超窗即报错终止；T1 只做省略；T2 在省略基础上加召回；T3 只做摘要；T4 是省略加召回加摘要的分阶段策略，先省略后摘要。这种模块化设计使得模型、任务、执行循环和未消融组件都被固定，从而能估计每个干预的条件效应。关键洞察在于：上下文管理的收益主要来自防止上下文溢出导致的提前终止，而非提升单步推理质量；分阶段先省略再摘要能在控制峰值上下文的同时减少对摘要调用的依赖；而让省略可恢复的召回机制虽然理论上更安全，实际却很少被模型调用，也没有带来准确率提升。

实验在 SWE-Bench Verified（500 个真实 GitHub issue）和 Terminal-Bench 2.1（89 个端到端终端任务）上进行，使用 Nemotron-3 的 30B、120B、550B 三个规模作为同家族能力轴，外加 Mistral-Medium-3.5-128B 做跨家族验证，共 176 个匹配设置。主要发现是：上下文管理的价值随窗口预算收紧而增大，在 32k 时 managed 与 T0 的成功率差距最大，随窗口扩大到 128k 逐渐缩小，因为大部分收益来自避免溢出失败而非改变 agent 行为；T4 在五种策略中效率最高，平均成功率与其他管理策略相当，但峰值上下文更低、摘要调用更少，而召回机制几乎不被使用且不带来准确率增益；规划的作用随模型能力变化，对弱模型它是准确率脚手架，能让轨迹存活到尝试编辑，对强模型它主要减少编辑后冗余验证，降低成本而准确率变化很小；预定义工具对 bash 能力弱的模型提升明显，而 bash 能力强的模型用纯 bash 接口反而成本大幅降低，尤其在命令行中心任务上。轨迹级分析进一步解释了这些效应：上下文管理延长了执行轨迹但不显著改变 agent 行为，规划改变的是轨迹在哪里停止，动作空间改变的是代码写入的粒度。论文的局限在于只覆盖了四个模型和两个基准，规划与动作空间的消融仅在 T4/128k 下进行，且预定义工具的比较混合了工具可用性、接口指令、状态跟踪和验证支持等多个因素，无法完全分离。尽管如此，这项工作为模型感知和预算感知的 harness 设计提供了可迁移的诊断方法，并给出了一个模块化框架来评测未来的 harness 组件。

### [When EOS Tokens Disagree: Understanding Length Inflation in On-Policy Distillation](https://arxiv.org/abs/2609.20511)
`评分3 · HF 28赞`

在策略蒸馏（OPD）用学生模型自己的采样轨迹、由教师模型提供逐 token 的稠密监督，是近年来把强后训练能力迁移到小模型上的实用手段。但多个研究都观察到学生回答会越训越长，甚至大量 rollout 直接耗尽生成长度预算，出现重复、冗余、截断等退化现象。这篇论文聚焦的就是这个“长度膨胀”问题。作者在 Qwen3、Llama、Gemma 三个模型家族上复现了同样的现象：学生常常早就给出了正确答案，却不停下来，继续生成重复后缀。已有的解释包括 reverse-KL 蒸馏的目标层效应、rollout 退化、训练不稳定等，但本文指出一个更直接、也更容易被诊断的成因——基座学生与后训练教师之间的“终止 token 不匹配”。关键在于，学生和教师可能用不同的 EOS token 来表达“该停了”这同一个语义决策。这种不匹配不仅出现在两者声明的停止集合不同时，更隐蔽的是：即使声明的停止集合完全一致，两个模型也可能把学到的停止概率放在集合内不同的 token 上。由于 OPD 中教师只对“学生实际采样出来的 token”打分，如果学生采样的是自己偏好的 EOS，而教师此刻正倾向于另一个 EOS，那么这个学生 EOS 就会收到负的蒸馏信号，被反复压制；与此同时，教师偏好的那个 EOS 因为学生几乎不采样（Qwen3 中概率低到约 10 的负 11 次方），又得不到有效的直接监督。结果是学生的终止行为被削弱，而教师的终止形式又没被可靠迁移过来，长度自然就膨胀了。

作者先验证了一个直觉性的修法：把教师认可的终止 token 也注册进 rollout 的停止集合（Fix 1）。但实验显示，仅对齐解码停止集合几乎和 vanilla OPD 一样，长度和截断率照涨不误。原因在于，解码器视为等价的停止事件，在蒸馏目标里仍被当作彼此不同的动作来监督，改动解码接口既不会改变 token 级的蒸馏信号，也不会让学生更可能采样到那个教师偏好的 EOS。于是论文提出三种在“概率层面”对齐终止语义的修正。Fix 2 是教师侧 EOS 映射：把教师在所有终止等价 token 上的概率质量合并映射到学生原生支持的那个规范 EOS 上，学生分布不动，rollout 只在规范 EOS 上终止，从而把教师的停止信号转移到学生本来就支持的 token 上。Fix 3 是语义 EOS 类：不选某个具体表面 token，而是把所有终止等价 token 视为同一个语义动作“stop”的不同实现，对教师和学生都先把 EOS 集合内的概率求和成“总停止概率”，采样到任一 EOS 就替换成统一的 stop 动作，再套用标准的采样 token OPD 更新，这样 EOS 样本通过总停止概率被监督，非 EOS token 保持不变。Fix 4 是规范单 EOS 动作空间：既把教师 EOS 质量映射到规范 token，又把学生采样分布中其他 EOS token 移除并重新归一化，actor 的 log 概率也用同一套归一化分布，rollout 只在规范 EOS 上终止，从而构造出一个无论词表里有多少终止等价 token、都只有单一规范终止动作的一致动作空间。消融实验显示，Fix 1 仍贴近 vanilla OPD，而 Fix 2、3、4 表现相近，都把长度和截断率拉回到接近教师参考线的水平，学生原生 EOS 的概率也不再崩塌。作者还特别指出，即便做全词表的 reverse-KL，在 softmax 参数化下梯度仍被学生自身 token 概率加权，学生概率极低的教师偏好 EOS 依然只能得到微弱的恢复信号，所以问题不纯粹是单 token 采样的锅，而是概率加权与终止语义未对齐共同造成的。

在结果层面，论文在单轮数学推理任务上、用 DAPO-Math-17K 训练，主实验对是 Qwen3-1.7B-Base 学生配 Qwen3-4B 非思考模式教师，并在 Llama-3.2-3B Base/Instruct 和 Gemma-3-4B PT/IT 上验证了语义 EOS 聚合的普适性。评价用 Avg@16，在 AMC23、AIME24、AIME25 上取平均，同时跟踪训练中的平均响应长度和截断率（触及生成长度预算的 rollout 比例），并直接比较学生与教师在 rollout 末位置上的单 token 终止概率和总停止质量。语义 EOS 聚合在三个模型家族上都显著缓解了由不匹配引发的长度膨胀，长度与截断率明显更接近教师参考。但论文也诚实地指出，终止对齐并非万能药：借助 K2-Horizon 从预训练、中训练、监督微调到最终后训练的中间 checkpoint 做分阶段分析后发现，学到的终止偏好会在训练过程中大幅漂移，而且在 OPD 后期会出现一种独立于 EOS 不匹配的、在对齐之后依然存在的长度膨胀——此时教师偏好的终止形式已经迁移过来了，响应长度却又一次上升、终止概率再次塌陷，说明还有别的机制在支配 OPD 的长度动态。此外，prompt 模板的选择也会进一步调节响应长度和测得性能，构成报告结果时的额外变异来源。总体而言，这篇工作把“终止 token 不匹配”确立为 OPD 长度膨胀的一个主要且易于诊断的来源，给出了可操作的修正方案和实现，同时也划出了边界：它解释了相当一部分现象，但不是全部，OPD 长度动态仍有待进一步拆解。

### [dQwen3.5: Hybrid-Attention Diffusion Language Models](https://arxiv.org/abs/2609.20751)
`评分3`

这篇论文要解决的核心问题是：如何把已经预训练好的自回归语言模型高效地改造成扩散语言模型，尤其是当这个自回归模型的骨干网络不再是传统的全注意力Transformer，而是注意力层与RNN层交替堆叠的混合架构时，改造还能不能做、值不值得做。背景是这样的：扩散语言模型通过迭代地“去掩码”来生成文本，可以并行解码、不按从左到右的顺序生成，最近一些模型已经能和自回归模型掰手腕，但从零训练一个扩散语言模型极其昂贵，达到同等规模自回归模型的效果可能要多吃一个数量级的token。于是大家转向“改造”路线：拿一个预训练好的自回归模型，把它的因果注意力改成双向注意力，再用扩散目标继续训练，成本低得多。可问题在于，近来自回归模型本身也在演进，像Qwen3.5这类新架构已经把大部分层换成了门控DeltaNet这样的循环层，只保留少数注意力层，形成“混合骨干”。循环层天生是因果的——它从左到右扫描序列、把前缀压缩进一个固定大小的循环状态，因果性写在递推结构里，不像注意力那样改个掩码就能双向化。这就造成一个尴尬局面：扩散语言模型最引以为傲的“任意顺序生成”能力，似乎和混合骨干里占多数的因果循环层根本冲突。之前几乎所有改造工作都从全注意力模型出发，没人认真验证过混合骨干能不能改造成像样的扩散语言模型，这篇论文就是要填这个空白。

作者的关键洞察是：这种“冲突”可能被夸大了。自然语言本身就是从左到右产生和阅读的，预测一个token所需的信息高度集中在它前面紧邻的上下文里，远距离信息只是选择性地起作用；而且已有的全注意力扩散语言模型，哪怕是从零训练的LLaDA，在推理时也表现出全局从左到右的解码趋势。换句话说，循环层的因果偏置未必是扩散语言模型的敌人，反而可能和双向化的注意力层形成互补——注意力层负责让每个位置拿到未来上下文，循环层保留语言固有的顺序结构。基于这个判断，作者的做法非常直接：只把Qwen3.5里的注意力层双向化（去掉因果掩码），循环层原封不动保持因果，然后按标准改造流程继续训练。具体来说，注意力层只占整个序列处理栈的25%（小模型6/24层，大模型8/32层），所以真正被双向化的只是少数，多数层仍然是因果的。其他改造细节沿用已有实践：在序列前加一个BOS token并把读出位置偏移一位，让位置k的隐状态去预测位置k+1的token，这样既保留了预训练自回归模型的下一token对齐方式，又允许输入本身包含掩码token；另外复用三个未使用的特殊token id分别充当掩码、填充和BOS，避免改动嵌入表。训练数据是Nemotron预训练数据里抽出的14个子集的固定混合，按token占比50%代码、35%通用文本、15%数学，序列打包到4096长度，用时间重加权的掩码扩散目标训练，全局batch为512条序列。作者在0.8B、2B、4B、9B四个规模上做了改造，得到dQwen3.5系列，同时还用同样的配方改造了Qwen3-1.7B作为全注意力对照组，其1.41B的非嵌入非输出头主干参数和Qwen3.5-2B的1.37B主干非常接近，构成最干净的对比。

结果层面，最核心的发现是混合骨干不仅没有拖后腿，反而adaptation更快：在主干规模匹配的对比中，dQwen3.5-2B达到相同训练损失所需的内容token数只有全注意力对照组的大约一半（中位数2.21倍差距），也就是说保留因果循环层多数派让模型更快适应扩散目标。在解码行为上，dQwen3.5-9B和从零训练的全注意力LLaDA-8B很像：全局上从左到右生成，但相邻位置经常乱序解码。作者用两个指标量化这一点，局部自回归性衡量相邻位置（如k和k+1）的左到右顺序，全局自回归性衡量所有位置对的顺序，随机顺序和严格自回归分别得0.5和1.0；四个规模的dQwen3.5局部自回归性都在0.64左右，落在其他扩散语言模型0.58到0.66的区间内，全局自回归性则高达0.88到0.97。在并行解码上，dQwen3.5-9B在HumanEval上从1倍速以上的每一个加速档都领先同等主干的扩散语言模型。下游基准方面，1.4B主干规模上，dQwen3.5-2B用50B token在7个基准中的6个上超过了用200B token的CoDA；6.5到7B主干规模上，dQwen3.5-9B用50B token在7个基准中的4个上拿到最高分，对手包括用了580B token的Dream-7B、322B token的Dream-Coder-7B和2.3T token的LLaDA-8B。有意思的是，更长的adaptation并非 uniformly 更好：从50B加到100B，0.8B规模上7个基准有5个提升，但9B规模上只有1个提升。局限也很明显：所有run结束时损失仍在下降，但作者没有训到收敛，而且已有工作发现更长的自回归到扩散改造反而可能损害下游表现；训练损失也不能当作能力的通用标尺，4B和9B的损失曲线几乎重叠，下游却分得很开。此外，作者只改造了基座模型、没有做后训练，后训练对下游表现影响巨大且高度依赖配方，被作者有意划为另一个问题。这项工作的意义在于，它第一次系统性地证明混合注意力-循环骨干可以成为扩散语言模型的有效起点，而且因果循环层占多数不仅不是障碍，反而可能通过保留语言固有的顺序偏置来加速adaptation，这为在最新一代自回归架构上低成本构建扩散语言模型打开了一条现实路径，也提示社区重新审视“扩散语言模型必须完全双向”这一隐含假设。

### [On-Demand Attention: Language Models Know When to Recall](https://arxiv.org/abs/2609.20734)
`评分3 · 28 pages, 5 figures`

这篇论文要解决的是长上下文推理中一个非常实际的效率瓶颈：自回归解码时，标准全注意力每一步都要读取不断增长的全部历史 KV 缓存，但真正需要远处信息的步骤其实只是少数。作者首先通过实验揭示了一个关键现象——预训练模型在解码过程中形成的隐状态，本身就携带了“当前这一步是否值得做全局注意力”的预测信号，而且这个信号在全局注意力被计算之前就已经存在。这直接挑战了此前动态注意力方法的主流思路：那些方法要么把局部/全局的分配决策塞进训练目标里联合学习，要么依赖额外的启发式规则，前者需要改动预训练权重、破坏模型已有的能力，后者则无法根据生成内容的实际需求灵活调整。更麻烦的是，在线解码时你既不知道参考的下一个 token，也还没算出当前步的全局注意力结果，所以任何“事后判断”都来不及。作者的出发点就是：既然模型自己的解码状态已经隐含了这个判断依据，那就只需要训练一个极轻量的模块把它读出来，完全不动预训练权重，同时保留完整历史 KV 缓存以备随时召回。

具体来说，ODA 的核心是一个叫 recall head 的轻量预测头，它只做一件事：在每一步先做一次局部注意力计算，然后根据三个当前可得的输入——当前输入 token 的嵌入、局部计算后的最终归一化隐状态、以及上一步传下来的隐状态——输出一个标量分数，用来预测“如果这一步改用全局注意力，相对于局部注意力能带来多少预测质量的提升”。训练时，作者用成对的局部和全局前向计算来构造监督信号：同一个历史状态下分别跑局部和全局，比较两者对同一个参考下一 token 的负对数似然降低量，这个差值就是全局注意力的真实收益。为了让 recall head 学会在收益和成本之间权衡，作者引入了一个惩罚项，把调用全局注意力的计算代价折算到预测损失的尺度上，再用带符号的对数变换压缩大收益的数值范围，最后用 Huber 回归训练。推理时，每一步先跑局部，如果 recall head 给出的分数超过阈值（默认是零），就用同一个 pre-step 历史重新跑一次全局注意力，否则直接接受局部结果；被选中的隐状态继续往下传，对应的当前步 KV 也追加到缓存里。这样做的巧妙之处在于，局部和全局共享同一份已提交的历史，重算只改变当前步的候选输出，之前所有位置的信息始终保留在 KV 缓存中，不会因为连续走局部而丢失。计算上，局部注意力的每步开销是常数级，全局是随历史长度线性增长，累积到整个因果序列后局部是线性、全局是平方级，所以在固定召回率下上下文越长节省越明显。作者还在 vLLM 里实现了 GPU 端的条件执行，把局部计算、recall 决策和条件性的全局重算放在同一个执行流里，减少路由带来的同步开销。

实验结果相当有说服力。在 Qwen3-1.7B 上，RULER16K 任务中 ODA 只用了 41.6% 的全局调用就拿到 81.17 分，而纯局部只有 19.23 分，纯全局是 81.94 分，相当于恢复了 98.8% 的性能差距；LongBench v1 上以 70.6% 的全局调用率拿到 36.82 分，对比纯全局的 37.94 分，恢复了 92.2% 的差距。更关键的是，作者用随机全局调用做了对照：在五个 RULER16K 任务上，随机策略以几乎相同的调用率只能拿到 32.79 分，而 ODA 拿到 88.96 分，说明“什么时候召回”本身比“召回多少次”重要得多。效率方面，在 128K 输入、1K 输出、12.5% 全局调用率的设定下，ODA 把主要解码操作的 FLOPs 降到纯全局的 24.26%，减少约 76%，在 A100 上单请求吞吐从 75.54 tokens/s 提升到 149.52 tokens/s，接近两倍。不过局限也很明显：在 4K 短上下文下 ODA 反而比纯全局慢 15.8%，因为省下的全局读取抵不过局部尝试和条件执行的开销；另外每个模型都需要单独训练 recall head，论文没有验证跨模型迁移能力；英文段落检索任务上仍比纯全局低 10.33 分，说明某些需要精确远距离信息的场景下召回决策还不够准。总体来看，这篇工作指出了一个有前景的方向：预训练模型自身就具备判断“何时需要回忆”的能力，不需要重新训练整个模型，只需要一个轻量读出器就能把长上下文推理的效率大幅提升，而且这种按需分配的思路可以和混合注意力架构互补，为后续在更大规模模型和更复杂推理任务上的应用留下了空间。

## 强化学习 RL

### [RetireOPD: Self-Retiring On-Policy Distillation for Agentic Reinforcement Learning](https://arxiv.org/abs/2609.20784)
`评分4 · HF 15赞`

多轮智能体用强化学习训练时，一条完整轨迹往往只拿到一个标量奖励，中间几十步决策没有任何细粒度监督，这让信用分配变得极其困难。一个自然的补救思路是引入同策略蒸馏（OPD）：让一个拥有特权信息的“教师”在学生自己采样出的轨迹上，逐 token 地给出密集监督，把技能内化进学生参数里，推理时学生就不再需要这些上下文。但论文指出，这套范式建立在两个从未被验证的假设上。第一，教师因为看到了特权上下文（比如检索到的任务技能）就一定比学生强——作者在 ALFWorld 和 WebShop 上发现并非如此：在共享参数的 OPSD 设置下，带技能条件的分支并不稳定地优于它所监督的无技能学生，因为共享参数主要被无技能的学生目标优化，策略从未真正学会“使用”技能上下文，即便换成 7B 模型、把同样的技能塞进提示词，ALFWorld 成功率也只有 23.4%。第二，教师监督的收益被默认为贯穿训练始终——但实验显示，学生与教师之间的分布差异先缩小后重新扩大，一旦学生把技能诱发的行为内化完毕，奖励优化就会偏向教师不会采取的动作，两个梯度开始正面冲突，继续匹配教师只会把学生锁在教师的能力天花板上。作者用一阶分析说明：差异停滞不前，恰恰意味着两个目标在局部梯度上已经对立。于是核心问题变成两个：该向哪个教师学，以及该学到什么时候为止。现有方法要么用预先设定的退火权重，要么在固定步数从蒸馏切到 RL，完全不观察教师是否还有用；而在线决策只存在于 per-prompt 或 per-token 这种更细的粒度上，没人真正“撤掉”教师。更麻烦的是，差异停止下降的临界点在不同模型和任务上从第 50 步漂移到第 90 步，任何固定日程都必然在某些设置下撤得太早、另一些撤得太晚。

RetireOPD 的设计正是围绕这两个失败模式展开，分三步走。第一步是教师构建：把教师从学生中解耦出来，用同一底座模型初始化一个独立的、带技能条件的教师，并直接用环境奖励对它做 GRPO 优化，得到一个真正“会用技能”的 skilled teacher，然后冻结它。这一步的关键洞察是，特权信息本身不等于行为优势，必须先用奖励把信息优势转化为行为优势，蒸馏才有一个可靠的目标。第二步是联合训练：学生不接触技能上下文，在它自己生成的轨迹上同时接受 GRPO 的环境奖励和来自冻结教师的密集监督，教师只在学生访问到的前缀上给出分布，不额外生成轨迹。蒸馏项用的是反向 KL，但完整词表求和开销太大，于是采用采样 token 近似——因为 token 本就采自学生策略，用学生和教师在同一个 token 上的对数概率差就能得到反向 KL 的单样本蒙特卡洛估计，几乎不增加成本。第三步是自适应退休，也是全文最核心的机制。作者把训练切成固定长度的监控窗口，在每个窗口里统计教师与学生逐 token 对数概率差的平均变化量，得到一个“对齐进展”指标：如果它仍为负，说明差距还在缩小，教师还有东西可教；一旦它变为非负，说明对齐停滞甚至反弹，两个目标已经冲突。但只看这个信号还不够，因为学生可能还很弱、只是暂时波动，所以再加一个相对胜任度条件：学生的成功率要达到教师成功率的某个比例（默认 0.9），并且学生表现要在连续两个窗口上平均以抑制抖动。只有两个条件同时满足，才触发退休，此后完全移除 OPD，只用 GRPO 继续训练。这个设计的精妙之处在于，它把“教师是否还有用”这个判断从人为日程变成了可从训练信号本身读出的量——差异停滞对应梯度对立，相对成功率对应技能是否已内化，两者结合既避免了学生尚弱时的过早退休，也避免了教师已成为天花板时的过晚退休，而且退休后不再需要教师前向传播，还省了算力。

在 Qwen2.5-1.5B、3B、7B 三个规模上，RetireOPD 在 ALFWorld 和 WebShop 两个交互式智能体基准上都取得了最好成绩。ALFWorld 上相对 GRPO 的提升为 14.1 到 18.8 个百分点，其中 3B 模型达到 93.8% 对 75.0%；WebShop 上准确率提升 11.8 到 19.0 个百分点，1.5B 模型从 56.8% 提到 75.8%。它同时稳定超过 GiGPO 这类更强的 RL 基线，并且在所有设置下都超过了自己的技能条件教师——这一点尤其值得注意，说明学生并非简单模仿教师，而是在教师退休后借助奖励优化突破了教师的上限。与 GRPO+OPSD 的对比进一步验证了“教师必须先被训练”的论断：仅靠特权上下文并不能提供可靠的监督目标。局限方面，方法引入了若干超参（监控窗口长度、胜任度阈值、停滞阈值），虽然默认值在三个规模两个任务上一致有效，但其跨任务鲁棒性仍需更广的验证；此外它依赖一个可检索的技能库作为特权信息，在缺乏高质量技能来源的领域可能受限；退休判据基于成功率与分布差异这类标量统计，在奖励极其稀疏或成功率长期为零的任务上，相对胜任度可能迟迟无法满足，导致教师难以退休。总体而言，这篇工作把“特权信息蒸馏”从一种静态配方推进到动态自适应过程，明确指出教师监督只是临时脚手架，并给出了一个可操作的、从训练信号本身读取退休时机的判据，这对智能体 RL 中如何融合稀疏奖励与密集监督这一核心问题提供了一个有说服力的新视角。

### [Don't Mask the Environment: Observation Supervision Changes How Agents Explore Under RL](https://arxiv.org/abs/2609.20715)
`评分3 · 29 pages, 9 figures, 11 tables`

标准智能体监督微调（SFT）有一个看似自然却从未被严格检验的惯例：一条轨迹里，智能体发出的动作（命令、推理）被当作预测目标来训练，而环境返回的观测（终端输出）虽然被放进上下文，却被排除在损失函数之外。这个做法背后的假设是——读取环境反馈对决策有用，但学会预测环境反馈本身没有价值。论文直接挑战了这一假设：既然部署时策略只生成动作、不生成观测，那训练时让模型去预测它永远不会输出的 token，到底有没有用？作者指出，这个假设之所以长期未被检验，是因为过去人们只关注 SFT 本身的benchmark表现，而忽略了 SFT 其实是后续强化学习（RL）的初始化。如果 SFT 的目标函数会系统性地塑造策略的初始分布、进而影响 RL 能探索到什么，那么"掩掉观测"这个看似无害的工程习惯就可能付出隐性代价。论文的核心动机正是：在 SFT 只作为 RL 起点的设定下，重新审视观测掩码是否最优。

论文提出的 ActObs 改动极其简单——只是把损失掩码从"仅动作 token"扩展为"动作 token + 观测 token"，不增加任何数据、参数、序列长度或前向传播。关键在于它带来的学习信号变化：在观测位置，模型被训练去预测"给定历史上下文和刚执行的动作，环境会返回什么"，这迫使模型显式地表征动作与后果之间的因果关系。这样一来，每条轨迹同时充当了模仿学习样本和状态转移样本，两个目标共享同一套参数，因此对"动作→后果"的建模会反过来塑造用于选择下一步动作的表示。作为对照，作者还设计了 Obs→Act 的时序控制组（先纯观测 SFT 再纯动作 SFT），以及 ECHO（在 GRPO 阶段加入下一观测预测损失），以区分"联合监督"和"仅仅暴露观测"的效果。机制分析揭示了一个关键现象：动作梯度和观测梯度在训练初期方向一致，但很快变得近乎正交，这意味着仅优化动作损失无法近似观测损失的方向。ActionSFT 在拟合动作目标的同时留下了一个巨大的观测梯度残差，导致其预测环境反馈的能力甚至低于基座模型——这是一种"单侧专业化"的退化。ActObs 通过联合优化两个目标，保留了模型对动作后果的预测能力，从而为下游 RL 提供了一个分布更完整、更少被动作模仿过度锐化的初始化。

在结果层面，三种 SFT 检查点在 Terminal-Bench 2.0 上的表现几乎相同，但经过完全相同的 GRPO 训练后出现显著分化。在 Qwen3-4B 上，ActObs→GRPO 在 pass@1、pass@4、pass@8、pass@16 上分别领先 ActionSFT→GRPO 1.6、1.4、1.5、1.1 个百分点，相对优势从 29% 递减到 6%；在 8B 上，ActObs 在 pass@1 略逊，但从 pass@4 开始反超，到 pass@16 时领先 3.4 个百分点（相对 14%），并多解决了 3 个不同任务。更值得注意的是跨域迁移：在 aider-polyglot 的 225 个多语言代码编辑任务上（SFT 和 RL 均未见过），4B ActObs→GRPO 在 pass@1 上领先 4.2 个百分点（相对 43%），而它的 SFT 检查点在该基准上其实弱于对照组——说明优势完全来自 RL 阶段被更好初始化后的探索能力。机制上，ActObs 在 GRPO 过程中维持了更高的训练熵和最终自熵，同时端点策略与 SFT 初始化的 KL 距离更小，即用更少的策略位移保留了更宽的探索空间；而简单调高 ActionSFT 的推理温度无法复现这一优势，说明差距来自学习到的分布本身而非采样随机性。局限方面，论文尚未在更大规模模型或更异构的 agent 任务上验证，观测监督的权重 λ 也需要针对任务调节（λ=1 并非普适最优），且当观测本身噪声极大或不可预测时，强制预测观测可能反而引入有害梯度。但这项工作至少清楚表明：SFT 的目标函数选择不只是影响初始性能，它决定了 RL 能从什么分布出发、能探索多远——这对所有"先 SFT 再 RL"的 agent 训练流程都具有直接的实践含义。

### [Score Centering Stabilizes Off-policy Reinforcement Learning](https://arxiv.org/abs/2609.20807)
`评分3`

大模型强化学习的一个核心工程痛点是训练引擎与推理引擎之间的数值不一致，即训练-推理失配（TIM）。理论上，采样和计算梯度应当基于同一个策略，但实际中推理引擎为了吞吐会使用量化、不同的浮点归约顺序、连续批处理与异步更新，导致采样分布q与训练分布p存在微小但持续的偏差。此前主流的补救方案几乎都基于重要性采样：用p与q的概率比作为乘性权重来修正梯度。然而重要性比在稀有token上会爆炸，方差极大，因此实践中不得不裁剪或掩蔽比值，这又引入了偏差，等于把失配问题从方差转移成了偏差。作者指出，这些方法之所以治标不治本，是因为没有抓住TIM下不稳定的真正根源——一个随每步训练累积的持续偏置项，他们称之为“漂移”。

论文的关键洞察来自对策略梯度期望的分解。在恒定奖励下，同策略时每个前缀处的期望得分恰好为零，因为得分函数对完整词表求和等于零。但在TIM下，token由采样器q产生而得分由训练器p计算，期望得分不再为零，于是梯度中出现了一个漂移项：它等于期望得分乘以期望奖励，方向恰好是交叉熵损失对训练器的负梯度，也就是说，策略梯度在每一步都悄悄地把训练器蒸馏向采样器。由于采样器是训练器的一个有偏副本（量化或陈旧），训练器又被同步回采样器，误差便形成正反馈循环不断放大。组归一化能缩小漂移但无法消除，因为漂移发生在前缀级别而非整条轨迹级别。Score Centering的做法极其直接：既然同策略时期望得分为零，那就人为把它减掉——对每个前缀，从实际得分中减去采样器分布下的期望得分，得到一个中心化得分。这个修正项是加性的、确定性的，只依赖前缀而不依赖具体采样出的token，因此不引入额外方差，也不需要裁剪。期望更新中漂移被精确抵消，剩下的协方差项与同策略更新只差在测度分布上。由于它和重要性采样在数学上正交，两者可以叠加使用。实现上无需存储完整词表分布，只需记录采样器top-128的logprob，尾部用训练器分布按尾部质量重标定来近似。

实验覆盖了从0.6B到30B参数的模型，任务包括Qwen3-0.6B上的Countdown和Qwen3-30B-A3B-Base在INTELLECT-2数学子集上的训练。在量化导致的TIM下，仅用Score Centering就匹配或超越了基于重要性采样的方法，且失配越严重优势越明显；在陈旧rollout的实验中，Score Centering与重要性采样的组合又优于纯重要性采样基线。这意味着它不仅能独立作为一种轻量级稳定器，还能作为现有方法的正交增强。局限方面，论文的漂移分析主要针对在线正奖励场景，离线负奖励的不稳定性被明确排除在外；top-k近似尾部建模在极端长尾分布下可能不够精确；此外方法假设可以高效获取采样器在每步的top-k logprob，这对某些推理框架的日志接口提出了额外要求。总体而言，这篇工作把TIM下的RL不稳定从“方差问题”重新定位为“偏差累积问题”，并给出了一个几乎零额外计算开销的加性修正，对异步RL训练、量化推理和长上下文agent等场景具有直接的工程价值，也可能启发后续工作从漂移消除而非比值裁剪的角度重新设计稳定化机制。

## 其他

### [JEPA-Anything: Learning Predictive Models across Different Worlds](https://arxiv.org/abs/2609.20800)
`评分3 · HF 23赞 · 有代码`

这篇论文要解决的核心问题是：世界模型（world model）能否用一种统一的预测学习原则，跨越视觉、生物、临床、控制、分子动力学、物理场、天气这些差异极大的领域？现有方法的主要瓶颈在于，虽然JEPA（联合嵌入预测架构）提供了通用的潜空间预测机制——上下文编码器总结已观测信息，目标编码器定义待预测状态，预测器在表示空间里完成映射——但标准JEPA把整个目标状态压缩成单一嵌入向量、走单一预测通路。当目标里同时包含局部与全局结构、多实体、多尺度变化时，这种“单体式”目标会让容易预测或高方差的方向主导优化，多个潜维度学到相似角色，而较弱的预测结构收到互相冲突的梯度。换句话说，潜世界状态的设计变成了一个“预测容量如何分配”的问题：接口可以固定，但状态本身需要被组织成多个互补成分。论文正是要回答：能否用同一个潜世界模型接口，通过多因子分解来组织不同领域里结构迥异的预测状态？

方法上的关键创新是“正交预测因子分解”（Orthogonal Predictive Factorization, OPF）。它把目标表示分解成K个互补因子：先用K个可学习的投影矩阵把停梯度的目标嵌入切成K个r维子空间（满足K×r等于总维度d），每个因子配一个专属预测器，从共享的上下文表示（必要时加上目标描述符，比如位置、时间戳、实体身份）预测对应因子。训练时对每个因子做直接回归，同时施加两类正交约束：每个投影器内部的列近似标准正交，不同投影器之间占据近似正交的子空间，防止多个因子重复编码同一方向。合成完整状态时，用分析映射的Moore–Penrose伪逆把各因子预测拼回d维潜状态；当投影严格正交时，伪逆退化为转置，合成就是各因子投影的加权和。论文还证明了：在零惩罚极限下，正交因子构成目标空间的正交直和，信息无损；若没有跨因子正交约束，投影矩阵可能秩亏或条件数任意大，合成不稳定。此外，因子活跃度正则项维持每个投影目标坐标在样本间的方差，在线编码器方差项则直接给可训练编码器提供抗坍缩梯度。整个OPF损失是加性的，与各领域原有的基础损失结合，适配器负责观测几何，OPF负责预测容量组织，下游任务从在线编码器状态或合成状态读取。

实验覆盖七个领域，包括10个匹配动力学任务、超过1000个临床事件预测、四个分子系统的100步滚动。与匹配的JEPA基线相比，JEPA-Anything在全部10个动力学任务上提升报告指标，在Interventional Pong上将单干预预测误差降低34.8%；在四个分子系统中，一步和100步误差均为对比方法中最低。更有说服力的是，因子坐标不只是预测工具，还能作为可复用的诊断接口：一个由因子命名的生物干预在细胞共培养、患者来源类器官、肿瘤片段和小鼠中获得了实验支持；潜轨道模式恢复了开普勒标度律，拟合斜率为-1.4991。局限方面，论文没有声称OPF能自动发现语义因子，因子身份仍从可预测性中涌现而非预定义；因子数量和宽度需要按实例的预测复杂度配置，超参数选择仍依赖领域知识；跨领域实验虽然广泛，但每个领域的适配器和评估协议仍需定制，距离“一个模型直接吃原始多模态数据”还有距离。总体而言，这项工作把世界建模从单一潜向量预测推进到可分解、可合成、可诊断的因子化预测状态，为跨异质系统的统一预测学习提供了一个有实验支撑的候选原则。
